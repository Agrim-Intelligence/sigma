## Detailed design

Build a capability/evidence foundation first, then a deterministic evaluation plane, then live-authority preparation and P1 observability. The foundation is deliberately decomposed: B4-1 is only the cross-platform resource/output preflight; B4-2 is only the immutable Git object reader; B4-3 is only Python route discovery; B4-4 is only shell/executable boundary discovery; B4-5 joins those typed records into the static inventory and decision/evidence inputs; and B4-6 is the separately recoverable scale fixture harness. B4-2 accepts a user revision only by resolving it once to a full commit SHA and tree SHA, records both, and scans that immutable tree—not `HEAD` again, the index, or the worktree. It recursively enumerates NUL-delimited entries through `git ls-tree -r -z -l <tree>` and streams each declared blob through `git cat-file --batch`; the parsed batch header must exactly agree with the declared object ID, blob type, and byte count. A malformed or abbreviated revision, missing tree/blob, malformed NUL record/header, invalid path UTF-8, non-regular Git mode, invalid blob UTF-8, or over-budget blob is an explicit refusal with the pinned SHA, path, and reason. Only modes `100644` and `100755` are admitted; symbolic links, gitlinks, and every other mode refuse. Staged, untracked, and conflicted worktree bytes are deliberately irrelevant because the reader never reads them; a control proves a changed/conflicted index cannot alter a result for the same pinned tree, while a nested-file fixture proves the recursive command rather than a root-only listing.

Before any blob decode, B4-1 derives and enforces a numeric usable-memory and output ceiling; B4-2 and B4-6 consume that measured preflight rather than supplying it later. On Linux cgroup v2 it resolves the calling process's cgroup path and walks every ancestor to the mounted hierarchy root; for each finite `memory.max`, it takes `memory.max - memory.current`, then takes the minimum over all finite ancestors and `/proc/meminfo:MemAvailable`. The `memory.max=max` sentinel is an explicitly unlimited ancestor, not a parse error; a malformed, negative, or overdrawn finite ancestor refuses. cgroup v1's hierarchical usage accounting is not sufficiently precise for a safety budget, so B4-1 detects it and refuses `cgroup-v1-memory-availability-unsupported` rather than estimating from `memory.usage_in_bytes`. On macOS it calls Mach's in-process `host_statistics64(HOST_VM_INFO64)` plus `vm_kernel_page_size` through a checked binding and uses only free plus inactive pages—never `speculative_count`, because it is already included in free pages; a missing/invalid binding refuses. On Windows it calls `GlobalMemoryStatusEx` for `ullAvailPhys`. A finite POSIX `RLIMIT_AS` is an additional constraint only after subtracting current virtual address space—Linux obtains it from `/proc/self/statm`, Darwin from `task_info(TASK_VM_INFO)`; if a finite limit lacks a current-address-space source, the gesture refuses. Any malformed, non-positive, or internally inconsistent finite source refuses loudly; Windows and macOS use their native source rather than pretending to be Linux. Usable bytes equal the smallest applicable available value less an explicit validated reserve fraction (required to be strictly between zero and one and recorded with the run); per-blob decode, worker count, and emitted-record/output byte caps are each calculated from that usable value and the observed encoded record size, never from a laptop-size constant. B4-1 preflights only its own bounded output sink: `statvfs` on POSIX or `GetDiskFreeSpaceExW` on Windows must report enough for that calculated output; B4-6 separately preflights its factor-specific fixture metadata and owned workspace. A missing numeric value or insufficient space refuses. Isolated red/green controls cover a finite near-full parent below an unlimited child, `memory.max=max`, malformed/overdrawn cgroup values, the v1 refusal, finite `RLIMIT_AS` below current virtual space, missing virtual-space evidence, output-budget exhaustion, the Mach-binding refusal, and each platform-specific availability failure. The receipt records every selected ancestor/source, arithmetic, reserve fraction, OS/cgroup mode, and refusal details so it is reproducible and testable.

B4-6 owns scale evidence, separately from the B4-5 production inventory gesture. Its documented gesture is `inventory-scale <.sdlc-root option> <absolute-root/.sdlc> --goal <active-child-goal-id> --source-commit <full-sha> --factor 1|10|100 --repeats <positive-integer>`, run from the repository's main worktree. Before the goal becomes a state-file component or branch input, it computes `goal_stem = work.stem(goal)`, explicitly refuses an empty stem or any control character, and applies the shared `state.unsafe_goal_reason(goal_stem)` gate; any separator, traversal, colon, empty, control, or other rejected value stops before a path or ref is formed. It derives the sole main-worktree anchor from that `.sdlc` root option: its parent must be the caller's canonical Git top-level, and that top-level's canonical `git-dir` and `git-common-dir` device/inode must be identical. A linked-worktree caller, different checkout, or a root whose Git dir is not its common dir refuses before reading a work record. It derives `expected_branch = work.settings(config)["branch_prefix"] + goal_stem`, validates it with hardened `git check-ref-format --branch`, then forms `expected_ref = "refs/heads/" + expected_branch`, matching `work.py`'s configurable safe-ref rule; only `expected_ref` is compared with `symbolic-ref` and porcelain's fully qualified branch field.

The `.sdlc/state/work/<goal_stem>.json` path is only an untrusted candidate. From the descriptor-pinned main anchor, B4-6 runs hardened `git worktree list --porcelain -z`, feature-probes `-z`, and uses a bytes-only NUL-record parser; it refuses malformed/duplicate fields and any control character in a registered path before doing path comparison. Every other Git path output is likewise byte-validated to contain no control character. It requires exactly one registered target whose canonical device/inode matches the candidate; whose target and main anchor report the same canonical common-directory device/inode; whose `HEAD` and porcelain branch record equal `expected_ref`; and whose target descriptor is pinned and rechecked before fixture creation. A missing/stale/forged record, newline-path record, detached or wrong branch, invalid custom prefix/ref, empty/control/separator/traversal goal, unrelated common directory, a path outside the registered target, or the root checkout itself refuses before creating a directory. Controls copy the documented gesture from the root, use empty/control/separator/traversal goal values, forge the work record to name another repository, register a newline-path worktree, configure a non-default safe branch prefix, and invoke from a linked child with a forged root record; each bad binding must prove no write, while an intact custom-prefix child resolves green with its short `expected_branch` and fully qualified `expected_ref`. Only then does B4-6 write its manifest and use B4-1's preflight plus its own calculated factor-specific tree-metadata/output/owned-workspace requirement to build an isolated fixture below that registered child worktree. B4-2 and B4-6 share the existing hardened read-only Git invocation pattern in `tools/readiness/decide.py`, strengthened for this contract: every Git read strips inherited `GIT_*`, disables system/global config and replacement objects, sets `GIT_NO_LAZY_FETCH=1` and `GIT_TERMINAL_PROMPT=0`, pins every transport protocol to `never`, and invokes the explicit global `git --no-lazy-fetch` flag. Startup runs that flag under the same scrubbed environment and refuses before scanning when unsupported; it is not enough to inherit an environment variable from an older Git. It refuses an object absent from the local object database. B4-2's partial-clone control derives from `tests/test_readiness_decide.py`'s `blob:none` fixture: a missing promised blob must leave the missing-object set and transport receipt unchanged while the reader refuses. B4-6 applies the same control before it copies a source blob; a new fixture bare repository has no promisor remote. A capability control makes `--no-lazy-fetch` unavailable and observes the documented startup refusal. This prevents a permitted `cat-file` read from silently fetching or spawning `git-upload-pack`.

On POSIX, B4-6 fixture directories live only below a newly created private, current-UID, mode-0700 base inside the goal worktree—not the shared system temporary directory. The recovery/deletion implementation retains an open descriptor for that base and uses descriptor-relative, no-follow `openat`/`fstatat`/`unlinkat` traversal (or an equally strong platform primitive); it never validates a path and later recursively deletes it by pathname. Each child has an owned prefix, random run ID, exact marker token, creator UID, and an expiry lease calculated from the validated run deadline and recorded in the receipt. At startup it removes only an expired child proven by descriptor-relative checks to be a regular owned directory beneath that held base descriptor. A normal path removes the same descriptor-anchored child in `finally`. On Windows, B4-6 refuses before making a fixture until a handle-relative, reparse-point-safe deletion primitive is supplied; it does not claim a weak path-based cleanup guarantee. Controls simulate an expiry sweep after SIGKILL/crash, a concurrent rename/symlink swap, foreign/mismatched/nonexpired directories, cleanup failure, and the Windows unsupported result; the contained control must go red under each own-clause break.

Fixture construction may use only local Git plumbing in the owned bare repository, but it is not allowed to inherit Git write state. Its runner removes every inherited `GIT_*` variable, uses the same disabled system/global configuration and protocol pins as the reader, and passes descriptors for the actual fixture child, bare repository root, repository `objects`, and repository `common` directories to each child. It creates each directory with descriptor-relative, no-follow operations first, opens and retains the actual target descriptor, then names `GIT_DIR`, `GIT_OBJECT_DIRECTORY`, `GIT_COMMON_DIR`, and any index/worktree location as the direct `/proc/self/fd/<actual-target-fd>` or `/dev/fd/<actual-target-fd>` mapping—not a `<base-fd>/<child>/...` path. Every Git child inherits those descriptors, and unavailable direct descriptor mappings or a post-open device/inode mismatch refuses before a Git write. It sets `GIT_ALTERNATE_OBJECT_DIRECTORIES` explicitly empty, descriptor-checks that `objects/info/alternates` is absent before and after every plumbing command, and refuses/discards the fixture if an alternate appears; no command can borrow an ambient object store.
