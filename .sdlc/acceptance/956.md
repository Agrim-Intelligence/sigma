## Done when
- [ ] An assertion-failing planned test whose pytest report block carries a `Captured stdout`/`Captured stderr`/`Captured log` section is still recorded as an assertion red by `red_green.py`; a test proving this is seen red against the pre-fix code.
- [ ] When only some failing tests in a run have captured output, every assertion-failing node is still attributed — one logging red no longer disables attribution for the whole run.
- [ ] A non-assertion failure (e.g. an ImportError, a fixture/setup error, or a non-assertion exception) is still NOT recorded as an assertion red, with or without captured output (negative control test).
- [ ] Text inside a captured-output section (e.g. a logged line containing `AssertionError` or `assert`) cannot create a false assertion attribution for a node that did not fail an assertion.
- [ ] #414's guarantee is preserved: a long (>100 character) node id failing an assertion is still attributed independent of terminal width, and the existing red_green tests stay green.
- [ ] The full suite (`python -m pytest tests/ -rs -q`) passes.
