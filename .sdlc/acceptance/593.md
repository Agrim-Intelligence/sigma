## Done when
- [ ] A launcher (a small stdlib Python script, location chosen to match how the harness expects to be handed it: read `evals/bench/bench.py`, its tests and `docs/bench/`) that, for one run, starts the arm's `claude -p` command in a fresh isolated profile: fresh `HOME`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME` and `TMPDIR`, no inherited credentials beyond the single variable or file the owner names (state exactly which and why), the plugin loaded only from the clean export the harness provides, and the command's whole process group killed at the deadline.
- [ ] It hashes the real profile's plugin surface (`~/.claude/plugins`, `~/.claude/settings.json`, `~/.codex/config.toml`, `~/.codex/plugins`) before and after each run and exits non-zero if anything changed; it never writes outside its scratch directory and the run's output file.
- [ ] Hermetic tests with a fake `claude` executable on PATH prove: isolation of the four environment variables, the real-profile hash guard (planted change in a TEMP home, never the real one, goes red), the deadline kill, a refusal to run when the scratch directory is inside the repository or inside the hidden-test root, and no credentials leaking beyond the named one. Each guard is seen red.
- [ ] A README next to it states what it does and does NOT guarantee (it cannot prove what the host CLI reads from other places, for example the OS keychain or system-wide config; say so), the exact first-run command for the owner, a tiny dry-run mode that starts the fake or `--version` only, and the cost expectations from `docs/launch/evidence/cost-calibration.md` (measured per-run figures only; say plainly the benchmark pilot is unmeasured).
