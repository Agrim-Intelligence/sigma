## Done when
- [ ] `docs/bench/preregistration.md` replaces the go threshold with a rule chosen for the 15-task paired binary design, written before any run, with the change in the deviations log (date, reason, what it replaces).
- [ ] The rule is an exact test on discordant pairs (for example an exact one-sided binomial test conditional on the number of discordant tasks, with a stated margin expressed in whole tasks), not a bootstrap percentile bound. State the hypotheses, the margin in tasks and in points, the alpha, and the decision (go, no-go, inconclusive).
- [ ] The document includes the rule's exact operating characteristics, computed by a script committed with the change: the probability of GO under a small set of stated scenarios (for example equal true pass rates, Sigma truly better by a stated amount, Sigma truly worse by a stated amount) for 15 tasks and for the 12 to 18 task range, and the number of discordant tasks each outcome needs. If no rule gives acceptable error rates at this size, say so plainly and state what claim the result can still support.
- [ ] An inconclusive outcome is defined and is never reported as a win. The exact allowed claim wording is restated for the new rule, and the duplicated clause in the existing claim sentence is fixed. The document states that the predecessor is no longer an arm, so no launch claim compares against it.
- [ ] The margin and alpha are listed as owner decisions in the document with the recommended values and their consequences; the document does not pretend they were settled by statistics alone.
- [ ] `tests/test_bench_preregistration.py` and any test or doc that cites the old threshold are updated, run on the gesture the docs give, and seen red against the old text. The operating-characteristics script has a test that fails if its published numbers drift.
- [ ] No benchmark task is run and no money is spent.
