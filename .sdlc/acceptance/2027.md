## Done when
- [ ] `loop.py next` and `next-batch` print the bare token `HANDOFF` on stdout, with a stderr reason naming the context and the threshold, once the session's recorded context reaches the threshold; no goal is claimed after it.
- [ ] The threshold is `handoff.after_context_tokens` when set, else a documented multiple of the session's first-pick context, capped at a fraction of the host-reported window; a resumed session with a huge first-pick baseline still trips under the cap (test seen red without the cap).
- [ ] The context check still runs when `after_goals` is 0 and no `max_iterations` is set; `handoff.enabled: false` turns both triggers off; with the meter unavailable only the goal count applies.
- [ ] The meter is read once per `next`/`next-batch` invocation, outside the session lock, and passed to every `_session_count_stop` call.
- [ ] The config template, `docs/configuration.md`, the doctor handoff row, the enforcement table and the running-the-loop "Context bounded across goals" row describe the context trigger, and their sync tests pass.
