## Done when
- [ ] AC-1: WHEN a run claims a goal with `ledger.enabled` true and `.sdlc/ledger` not a worktree, THE loop SHALL create the worktree from origin through the `sync.py init` path, publish the claim, and leave the code checkout's HEAD, index and status unchanged. The step is bounded in time and fails open.
- [ ] AC-2: THE loop SHALL publish at the claim, at each lease renewal and at the outcome (done, parked, failed, release) without a watcher daemon. IF a push is refused or times out, THEN the run SHALL continue and SHALL print that the entry was NOT published.
- [ ] AC-3: WHILE a run holds a claim, THE loop SHALL write a `lease-renew` entry at goal boundaries, at most once per a third of the lease TTL. THE ledger reader SHALL extend the lease only for a renewal by the holder (the same actor, a compatible run and the same host). This closes #616.
- [ ] AC-4: WHEN several clones under one login publish at once, THE origin ledger SHALL hold every entry each one wrote, with retries bounded in count and time. Shown with real git, red first.
- [ ] AC-5: IN a Claude Code cloud session, THE writer's host token SHALL be unique per container, and a laptop's token SHALL be unchanged.
- [ ] AC-6: IF a stale claim's writer is on another machine, THEN `_auto_reclaim_stale_claims` SHALL release it only once a fresh read of origin's ledger branch confirms it is still expired. IF that read fails, THEN it SHALL NOT release.
- [ ] AC-7: The claim, renew and outcome path works under `SIGMA_GH_GRAPHQL=off` with every GraphQL call refused.
