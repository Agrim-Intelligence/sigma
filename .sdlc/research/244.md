# #244 research — flaky tests/test_risk_detect.py under xdist: root cause found

## Reproduced (before the fix)

Stress harness (outside the suite): `pytest tests/test_risk_detect.py -n 8`, repeated, with 12
(or 2x6) background `while :; do :; done` busy loops on a 12-core Mac, Homebrew bash 5.3.15, git 2.55.

| run | script | red / runs |
|---|---|---|
| base1 | original | 6/40 |
| traced (xtrace + fd 9) | original | 5/30 |
| base2 (same session as fix, A/B) | original | 6/40 |
| **total before** | | **17/110 (15.5%)** |

The failures were split between `test_detects_each_category` and
`test_content_line_that_renders_as_a_diff_header_never_leaks_untracked`. The `.why` from one run:

```
script rc=0
stdout='{"schema":"risk-detect/v1","matched":[],"hits":[]}\n'
stderr=''
git status --porcelain=v1 --untracked-files=all -> rc=0 stdout='?? notes.txt\n'
git ls-files --others --exclude-standard -> rc=0 stdout='notes.txt\n'
```

The fixture had landed and git saw the file, but the content scan returned nothing.

## Layer isolation

1. The xtrace of a failing run (`PS4` with `$EPOCHREALTIME`, `BASH_XTRACEFD`) shows the
   content-scan subshell (`++`) starting `LC_ALL=C grep -Iq . -- <first untracked file>`. The trace
   then stops: no `|| continue` and no `printf 'diff --git'`. The main shell's `read -r hline` sees
   EOF at the same point.
2. Logging each command's exit status showed `grep` rc 0 for every file. The pipeline's
   `PIPESTATUS` was `139 0` in 13 of 450 script runs: **the `emit_combined_diff` subshell died of
   SIGSEGV**. The script is FAIL-OPEN and discards errors, so the result was valid, empty JSON.
3. `~/Library/Logs/DiagnosticReports/bash-*.ips`: all 26 bash crash reports from today show one
   stack: `dispose_temporary_env -> dispose_used_env_vars -> sv_locale -> set_locale_var ->
   reset_locale_vars -> libintl_setlocale -> CFLocaleCopyPreferredLanguages -> CFPreferences ->
   os_log_type_enabled -> _os_log_preferences_refresh` (EXC_BAD_ACCESS).

## Root cause

`otool -L /opt/homebrew/bin/bash` shows that it links libintl (gettext) and CoreFoundation. On
every locale-variable assignment, bash calls `setlocale()`. A per-command temporary assignment
counts: it is applied before the command and restored in `dispose_temporary_env` after it.
libintl's `setlocale` then queries CoreFoundation for the preferred languages (LANG is unset in
this environment). CoreFoundation is not fork-safe. The content-scan subshell is a forked bash
that is never exec'd (a process substitution), and it ran that assignment/restore twice per
untracked file. Under CPU load it sometimes crashed in the os_log preferences refresh.

Why the symptoms looked the way they did:
- The name scan has no locale prefix, so file-name matches survived.
- Only the two tests whose asserted category comes only from untracked-file content went red.
  In every other fixture, a path glob matches too.
- Load makes it more likely, and the crash is nondeterministic, so tests run alone looked green.
- It is not an xdist, tmp-dir, index.lock, fsmonitor or untracked-cache race. None of those were
  involved: the fixture's git view was correct in every `.why`.

Rejected hypotheses (checked): internal timeouts (none in the script), global excludes (the
`_assert_untracked` precondition passed), exported shell functions (`env` has no BASH_FUNC),
GIT_*/LC_* env leaks (only `GIT_EDITOR` is set), fsmonitor/untrackedCache (not configured).

## Scope and siblings

The same pattern (`| LC_ALL=C sort` in pipeline elements and command/process substitutions) is in
`skills/sigma-align/scripts/alignment-collect.sh` (6 sites) and
`skills/sigma-loop/scripts/discovery-scan.sh` (1 site). No crash has been observed there (every
report shows the dispose stack of the procsub `grep`), but those sites are not safe by
construction. That work is out of scope here and is flagged as a follow-up task.

Linux/glibc: setlocale is fork-safe, so the fix is a no-op there, and the control holds on every
OS. Windows: the suite does not run this file (the Windows CI job runs only
`tests/test_windows_real.py`).
