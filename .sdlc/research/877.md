## Shape of the record (`sigma.regression-run/v1`, `evals/regression/record.py`)
Top level: `schema`, `goal`, `run` (the run directory's basename, so the fixture builder must use a fixed dir name), `caveats` (two fixed strings: call-existence and "journal and action log are off by default"), `phases`, `streams`. No timestamps and no absolute paths (strings are scrubbed to their last segment); output is `sort_keys` with indent 2, byte-identical across builds.

`phases[]` entries: `phase`, `evidence: "call-existence"`, `start_present`, `end_present`, `attempts`, `tokens_in`, `tokens_out`, `cost_cents`, `notes`. They come from JOURNAL rows (`kind` phase start/end and spend), ordered by `PHASE_ORDER` (goal, research, plan, plan_review, implement, review, retro).

`streams` has exactly nine keys, each with `source` and `present` (plus `reason` when absent): `plan`, `research` (`bytes`, `sha256`); `plan_review_verdict` (`verdict`, `route`, `plan_hash`, `verified`, `gate_file_present`; present only when an action-log `verdict` row with `phase=plan_review` exists); `verify` (`exit`, `verify_state`, `at`, `head`, `test_first_passed`); `journal` (`files`, `lines`, `skipped_malformed`, `kinds`); `action_log` (`rows` filtered to `actionlog.INTERNAL_KINDS`, `dropped_non_internal`, `skipped_malformed`); `review_evidence` (`review_posted[]` of `pr`, `head_sha`, `verdict`, `evidence_id`; `marker_in_store` true/false/None); `commit_order` (`main[]`, `goal_branches{}`, `goal_branches_present`); `tokens` (`by_phase`).

INTERNAL kinds (`skills/sigma-loop/scripts/actionlog.py`): claimed, worktree_start, verify_run, recorded, gate, merge_armed, merged, decompose_check, released, agent_reclaimed, phase, verdict, phase_waived. Agent-writable kinds (file, model_choice, agent_dispatch, agent_done, note, and others) never reach `action_log.rows`.

Key consequence for check.py: a process property reads `streams.action_log.rows` (kinds `phase`, `verdict`, `gate`, `recorded`, `merged`). The "reject a property naming an agent-writable kind" rule should validate against the same `INTERNAL_KINDS` object. Import it through `record._load_scripts("actionlog")`, never a copy; a copy would let the set drift.

## What the three mutations remove (D-8 proposal, owner-confirmable)
Each is a copy of `run-green.json` with exactly one thing deleted, must exit 1 and name its property:
1. Plan-review verdict dropped: remove the `verdict`/`phase=plan_review` row from `streams.action_log.rows` and set `streams.plan_review_verdict.present` false (verdict null). Property: plan-review verdict recorded.
2. One phase end dropped: remove one `phases[]` end (`end_present` false, `attempts` 0) AND the matching `kind=phase,state=end` row from the action log. Both, because the process property reads INTERNAL rows only; a mutation touching the journal side alone would not fail a log-based property.
3. Review marker dropped: `streams.review_evidence.marker_in_store` false and `review_posted` emptied (`present` false). Property: review evidence marker present (the review_posted event and the marker).
Edge: a hard property whose stream is absent must exit 1 (acceptance item 1), so mutation 1 and 3 may exit 1 via NOT EVALUABLE rather than FAIL; decide in the plan which is intended and assert the printed word.

## Property list sketch
- outcome: goal merged (`merged` row), main commit order contains the goal branch commits, verify exit 0.
- process: all six `REQUIRED` phases (`phase_gate.py`) have an end row; plan_review verdict recorded and approved; review evidence marker present.
- cost: tokens and `cost_cents` present for the measured phases (NOT EVALUABLE when `tokens.present` false).
- quality: `verify.test_first_passed`, plan and research present with sha.
- safety: no agent-kind rows in the record; no absolute paths; caveats present.
Hard vs soft needs a field in properties.json (`hard: true`); D-5 resolution: list a retro-phase-end property in process rather than a retro writer.

## Risks
- Process properties evaluated against the journal-derived `phases[]` rather than INTERNAL action-log rows would break AC-2 and make mutation 2 unobservable; read log rows.
- A property naming an agent kind must be REJECTED by the checker (config error, exit non-zero, distinct from FAIL); test it with a real agent kind from `actionlog`.
- Fixture rot and drift: record.py field renames would silently invalidate the fixture; the regenerate-and-compare test covers it.
- `run` field and any path-like string in fixtures: committed output must be deterministic and carry no absolute path (scrubbing exists, but a regeneration from a differently named temp dir changes `run`).
- Exit-code contract: 0 all PASS, 1 any FAIL or absent hard stream; a malformed record or property file should be a refusal (2) so it is not confused with a regression. NOT EVALUABLE on a soft property must not by itself exit 1.
- Call-existence caveat: PASS on a phase end proves only that `phase_report.py end` ran. Property names and output should not overclaim.
- Scalability: O(properties x rows), linear; record held in memory, same ceiling as record.py. Not measured here.
- Slice 4 (driver) will feed a real record to check.py; property names chosen now are a contract for it.
