# Research: #400 — private host paths in launch exposure evidence

Date: 2026-10-01

## Measured state

- The shipped exposure scanner's `history` mode intentionally walks every reachable blob; it
  therefore reports two historical `.sdlc` records that contain owner-specific paths.  A source
  history rewrite would also have to rewrite every remote branch/tag and is outside this goal's
  safe, non-destructive scope.
- The current tracked scan reports five `absolute-home-path` findings.  They are detector,
  documentation, or hermetic-test literals, each on a distinct tracked blob.  They must remain
  detectable if their file content changes.
- #397 creates a fresh public tree with one initial commit and runs the exposure scanner on that
  tree.  It does not publish this repository's history.  Thus, retaining the private source
  repository's historical records is not a justification for suppressing them; a public export
  must instead exclude the historical `.sdlc` records by the owner-approved export policy and
  allow only exact reviewed fixture blobs.

## Gap

`docs/launch/exposure-allowlist.json` currently keys an allowance only by `(path, rule)`.  That
would suppress a later, different blob at the same path, including a real path accidentally added
to a fixture file.  It cannot be used to distinguish the known current fixture from historical
content at the same path.

## Direction

Add an optional Git blob identifier to allowlist entries.  An entry with `blob` suppresses only
the exact `(path, rule, blob)` triple and becomes stale when that blob disappears.  Preserve the
existing three-field entries for compatibility.  Record the five currently reviewed
`absolute-home-path` fixture blobs with explicit public-export reasons.  Do not weaken `history`
mode: it remains red for historical source-repository records, which is the signal the fresh-tree
export must not carry them forward.

## Constraints

- No source-history rewrite, branch deletion, tag deletion, or force push is authorized by this
  goal; those operations are destructive and require an owner-run public-release decision.
- Evidence and tests must never print a matched value.
- The documented gesture is `python3 tools/readiness/exposure_scan.py tracked . --json <outside-or-scratch-output>`.

## Repair cycle 2 — #277 leak-gate residuals

The #277 leak gate in the integration tree identified three current tracked source locations that
were not part of the prior blob-scoped scanner's reviewed fixture set: one owner-encoded segment
left in a rendered evidence preview and two literal home-path test inputs.  The gate reports
locations only, not values.  These are source-content defects, not a reason to broaden an
allowlist: the preview can use an opaque redaction token, and the hermetic fixtures can construct
the same runtime value without carrying a forbidden literal in shipped source.  Because the
leak-gate implementation is awaiting #277, its documented red/green proof will run in an isolated
`sdlc/277` checkout with this repair applied; no scanner behavior is modified by this goal.
