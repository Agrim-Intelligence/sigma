# Research — #267

Dependency #258 is closed and present. Its `work.plan_copies` selects the published plan and
`review_context.plan_sha256` owns exact-byte identity; the new gate will reuse both and will not
change the independent plan-review gate or its default.

Current witness rows contain test id, source hash, kind, second-resolution timestamp and detail.
`loop._witness_verdict` writes rows after a failed configured command; `_failed_ids` extracts
pytest summary ids, but `classify` is applied to the entire output, so mixed failures can wrongly
credit a non-assertion failure. Existing `witness.verdict` only checks kind/hash, not chronology.
Mutation witnesses come from diff-revert/mutation controls. No current PR gate reads them.

Contrary to the issue premise, there is no plan Tests-section parser in this checkout. The
supposedly shared scoped resolution uses committed Git diffs, omitting uncommitted TDD tests;
flake also has a separate diff path. A shared plan selector resolver is therefore necessary.
Plan selectors will take precedence in flake/witness paths, with old diff fallback retained for
legacy advisory runs. A dedicated observed pytest run of the planned nodes will bind actual
per-node red/passed results to current hashes; a configured command returning zero alone cannot
prove those tests passed. Collection errors, skipped tests, unrelated ids, mixed error classes,
missing reports, and stale/changed hashes must not satisfy the gate.

The PR path already has plan/research/acceptance gates before push. Add the witness gate there,
with a nonzero CLI refusal. A nonempty explicit `--no-tests` reason bypasses only this new gate;
it must appear verbatim in created and existing PR bodies. It does not disable verify or plan
review. Bootstrap drivers that intentionally change only text will name this exception explicitly.

Bounded work: the plan protocol accepts at most the existing flake scope limit (25 selectors).
Collection and execution use one explicit pytest scope, no background processes or external
network. Existing witness journals remain the durable history; PR scans stream through one goal's
file and retains matching ids only, O(history + scope), rather than loading all goal histories.
At 10x/100x requested tests, work is linear until the explicit selector ceiling refuses; a file
selector can still collect many nodes, so that file's test cost remains visible and unbounded by
wall-clock prediction. Timings will be measured before any performance claim. This change adds
no daemon, host resource quota, or process-pause mechanism.

Crash/recovery: a partial witness line is ignored and cannot grant credit; missing/malformed proof
refuses before push. Restore/re-run the same red control then green verify when evidence is lost.
A test edit requires fresh red evidence. A changed plan requires green verification against its
new exact bytes and the independent #258 approval where enabled. A failed PR-body update reports
failure; retrying the same exception does not append duplicate text. Local evidence is not
cryptographic attestation against an agent that deliberately forges files; it prevents accidental
or opportunistic reuse of unrelated/stale evidence and says what was actually observed.
