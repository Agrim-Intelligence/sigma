# Research 2086: a killed merge runner reads as a bare FAILED

Lane: small (one function in `loop.py`, one reference file, docs, one test file). Blast radius:

- `skills/sigma-loop/scripts/loop.py` `_wait_call`: the `failed` branch for `merge` prints `FAILED ...` and a stderr
  line that says "do not re-run blindly". A dead runner pid reaches it through `run_receipt.classify`
  (`runner pid N gone`). The branch reads no GitHub state.
- `work.pr_landing_state(sdlc_dir, rec)` already does ONE REST read of `pulls/<n>` and answers merged, open, closed or
  unknown; `merge_with_receipt` is what writes the receipt whose pid dies; `gate()` only READS while it polls (the
  pending-check loop is `PENDING_ATTEMPTS` re-reads, `PENDING_INTERVAL` apart, sleeping between them).
- `loop.py agent-start` writes the agent marker with a bare PID; a restarted worker has a new PID, so the old marker
  names a dead process until the orchestrator re-registers.
- Docs that must follow: `skills/sigma-loop/references/landing.md` (the `wait-call` bullet and the merge paragraph),
  `skills/sigma-goal/references/land.md`, `docs/cloud-sessions.md`, `CHANGELOG.md`.
- Existing tests that touch the branch: `tests/test_long_call_receipts.py` (`test_wait_call_exit_1_on_dead_pid...`
  plants a merge receipt with a dead pid and asserts exit 1 plus "landing.md" and "re-run" in the output).
  `tests/test_goal_land.py` holds the one stateful REST fake the landing gestures run against.

Not in scope: proposal item 3 (bind the agent marker to a session id) is a design change; it is written up as a
follow-up note on the issue, not built.

Not measured: no real cloud container, no real GitHub; every GitHub answer in the tests is a fake.
