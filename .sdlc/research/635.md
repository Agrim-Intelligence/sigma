# Research: #635 review gate honours sigma: comments from any commenter

Reader: `work.py` `_comment_directive` (only caller: `review_gate`). It runs `gh pr view N --json comments,author`, scans each comment with `_line_directive`, and tracks only whether the commenter login equals the PR author. `gh pr view --json comments` already returns `authorAssociation` per comment (OWNER, MEMBER, COLLABORATOR, CONTRIBUTOR, FIRST_TIME_CONTRIBUTOR, FIRST_TIMER, MANNEQUIN, NONE), so no extra API call is needed. Writer: `post_review` posts the loop's own markers through the operator's gh token (an OWNER/MEMBER/COLLABORATOR account), so trusted-only reading does not break the loop.
Existing design: self-authored `sigma:approve` is deliberately honoured (solo-account repos cannot use GitHub's own approve); #821 only makes it loud. That stays.
Blast radius: work.py `_comment_directive`/`review_gate`; fixtures in tests/test_work.py `_review`, tests/test_merge_reconcile.py `_merge_runner`, tests/test_public_bootstrap_control.py fake gh; docs: docs/enforcement.md (generated from skills/sigma-doctor/scripts/enforcement_table.py), README review-gate section, config.json.tmpl `_require_review*`, doctor.py text.
Ceilings: MEMBER is any org member, which can be broader than write access; the gate is not a substitute for branch protection. Out of scope, noted: an unreadable `reviewDecision` still fails open (existing, documented).
