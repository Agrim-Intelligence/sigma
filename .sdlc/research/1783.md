## Exact Mermaid subset to support (decision D-4 / D-6, structural only)
- Fence: line matching ```` ^```mermaid\s*$ ```` opens, ```` ^```\s*$ ```` closes; an unclosed fence is a finding at its opening line. Blocks recorded with start line and enclosing level-2 heading.
- First non-blank, non-`%%` line's first token must be one of: `flowchart`/`graph` (optional direction `TB|TD|BT|RL|LR`), `sequenceDiagram`, `stateDiagram-v2`, `erDiagram`, `classDiagram`. `C4Context|C4Container|C4Component|C4Dynamic|C4Deployment` -> finding "unsupported (experimental, not rendered everywhere)". Anything else, and an empty block -> finding.
- Balance, per line: `[ ]`, `( )`, `{ }`, and `"` quote parity, counted outside quoted strings; unbalanced -> finding naming the line. `subgraph` / `end` must pair across the block (a stray `end` or unclosed `subgraph` is a finding); `end` is matched as a whole word at line start only so a label "Legend" is not one.
- Per-line cap 4,096 characters (longer is a finding, line skipped by the bracket pass); no backtracking-prone regexes (anchor + character classes only, or a manual scan).
- Container extraction (flowchart/graph only, under `Building blocks`, first mermaid block): node `id["Name [Tech]"]`, `id("…")`, `id{{"…"}}`, `id(["…"])`; name = label text before the LAST `[...]` pair inside the quotes; tech missing -> finding "no technology". `Person` / `External system` bracket -> exempt. Match to the first table under `Technology inventory`, column 1, trim + casefold, **exact equality** (no substring). Context diagram under `Context and scope`: keyword + balance only. Edge lines (`-->`, `-.->`, `==>`, `<-->`, `|label|`) are not nodes; ids used before a bracketed definition are not containers.
- Not supported and stated in the doc: Mermaid C4 syntax, `%%{init}%%` directives (treated as comment lines), `click`/`classDef`/`style` lines (ignored, balance still checked), multi-line labels, markdown-string labels.
