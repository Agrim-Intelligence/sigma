# #240 Research — coexistence of Sigma and the plugin under its previous name

`<old>` below is the previous name; it is never spelled whole in a shipped file (it is a guarded
private name, `tests/test_no_private_names.py`), and code spells it only through
`legacy.RETIRED` (built from fragments, #239).

## What both plugins share on one repository

Measured by reading the previous name's latest 1.4.x release (read only, nothing written):

- **Watcher lock files are identical.** Its `watch_daemon.py` uses `state/watch.pid`,
  `state/watch.heartbeat` (via `sync.heartbeat_path`) and the `state/watch.decide.lock` directory
  mutex, byte-for-byte the same protocol as Sigma's (`watch_daemon.paths`). So two watchers on one
  `.sdlc` are ALREADY impossible at the process level: whichever plugin's watcher starts second
  reads "already running (pid N)" and exits 0. The defect is not a double watcher; it is that the
  hand-off is SILENT — a Sigma trigger seeing the old plugin's live watcher says nothing, and that
  watcher keeps writing old spellings.
- **Its loop, session-start hook and `_ensure_watcher` are the same shape** (a detached
  `watch_daemon.py` spawn from every loop trigger). With both plugins enabled, both hook sets fire
  in one Claude Code session, and both loops can claim goals and write registry/ledger state.
- **The old plugin cannot read Sigma's schema ids** (`docs/upgrading.md`), so any Sigma write to
  `features/` reads as empty to it. That is the data-integrity risk the issue names.
- **The old plugin writes no ownership marker.** Detection must therefore come from Sigma's side
  alone: host plugin inventories, hook registrations, the live watcher's identity, and old-spelled
  state (`legacy.is_legacy_schema`).

## Where "installed / enabled" is knowable, per host

- **Claude Code**: `enabledPlugins` in `~/.claude/settings.json` (user), `<repo>/.claude/settings.json`
  (project) and `<repo>/.claude/settings.local.json` (local); precedence local > project > user.
  `~/.claude/plugins/installed_plugins.json` lists installs per scope (shape already read by
  `doctor._install_scopes`). `CLAUDE_CONFIG_DIR` relocates `~/.claude` (doctor already honours it).
  Hooks registered by hand live under `hooks` in the same settings files.
- **Codex**: `$CODEX_HOME/config.toml` (default `~/.codex`) holds `[plugins."<name>@<mkt>"]` tables
  with `enabled = true` (shape observed on a real install). Python 3.10 has no `tomllib`, so a
  line reader is used; `codex plugin list --json` exists but is a CLI spawn, not spent on every
  write surface.
- **Cursor**: no hooks and no plugin inventory; the adapter is committed text (`.cursor/rules/*.mdc`).
  An old-name rule there is an adapter signal, not a running process.
- An old-name Codex block in `AGENTS.md` is likewise committed text (replaced by
  `sdlc_init.py --codex` / `migrate.py`).

## Surfaces and their current behaviour

| Surface | Writes shared state / starts processes | Today |
|---|---|---|
| `hooks/session_start.sh` | no (injects context) | nothing detects the other plugin |
| `watch_daemon.py` | yes (ledger publish, pid lock) | exits 0 "already running" silently if the other's watcher holds the lock; starts normally otherwise |
| `loop.py _ensure_watcher` | spawns the watcher | fail-open spawn |
| `loop.py start` | yes (session registry, run state) | no detection |
| `sdlc_init.py` | yes (scaffold) | no detection |
| `migrate.py --apply` | yes | refuses while any watcher runs (cannot tell whose) |
| `doctor.py check` | no | no coexistence row |
| `log.py`, `status.py` | no | nothing |

## Constraints

- Host-agnostic: the load-bearing checks live in Python on the write surfaces; the hook only
  accelerates (Cursor has no hooks).
- Refuse loudly with the next step, never a silent half-guarantee; one explicit documented
  override (no derivation).
- No new background process, no network, no CLI spawn on the hot path; bounded file reads.
- Parallel goal #229 edits `sdlc_init.main` and `doctor.check`: keep those edits to one small block.
- Test hermeticity: the developer machine this runs on has the old plugin enabled user-wide, so
  scans must honour `CLAUDE_CONFIG_DIR` / `CODEX_HOME` and the suite pins both to empty dirs.

## Scale

Per call: at most 3 settings JSONs + 1 installed_plugins JSON + 1 TOML + up to 200 state JSON
headers (capped) + 1 pid probe. Constant in repo size beyond the cap. Measured: 1.5 ms median,
2.3 ms max over 20 warm runs against a real 3,717-file `.sdlc` (macOS laptop, Python 3.12).
