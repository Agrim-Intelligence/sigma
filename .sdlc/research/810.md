**Goal**: #810 (epic #804/#876, unit regression-eval) · **Lane**: large (per design; see rationale: the remaining deliverable is medium, split) · **Date**: 2026-10-17

## Goal in one paragraph
Make `evals/regression/live.py` the only place the regression eval may start a paid model run: refuses loudly (`REFUSED [code]`, exit 2, empty stdout, a NOT RUN row) unless opted in with credential + dollar cap; books the belt in a spend ledger before launch; never logs the credential; invokes the operator launcher as a subprocess without touching `evals/bench/`. **Key finding: design slices 1 and 2 have already landed in the worktree base** (slice 1 = #884 refusal ladder + NOT RUN rows + redaction, `evals/regression/live.py`, 347 lines; slice 2 = #886 spend ledger, `evals/regression/spend_ledger.py`, 609 lines; tests `tests/test_regression_live.py` 40 test fns, `tests/test_regression_ledger.py`). What remains of #810 is slices 3 and 4 (plus gated slice 5). Worktree is clean at `8ae89660`.

## write_surface.py: exactly what `check` does and the append-mode blind spot
`python3 tools/readiness/write_surface.py check . docs/launch/write-surface.json` (`tools/readiness/write_surface.py:459 main`, `ratchet :431`): scans every git-tracked `.py`/`.sh` outside `tests/` (`_paths :423`), AST-walks each call (`_rules_for_call :323`), and keys findings by `(path, enclosing function, rule)` with a count. It fails on: a new key not in the inventory ("new write site"), an inventory key no longer found ("stale entry"), a count mismatch, a missing/invalid field (risk in low|medium|high, count int >= 1, non-empty gate). Rules detected for the filesystem: `shutil.rmtree` -> fs-rmtree; `os.unlink/remove/rmdir/replace/rename` and `_REMOVE_METHODS` -> fs-remove; `os.mkdir/makedirs/link/symlink` and `_WRITE_METHODS` (write_text/write_bytes/mkdir/touch per PC-7) -> fs-write; plus gh/git/network/graphql rules. **Blind spot**: it never classifies `open(path, "a"/"w")`, `os.open(..., O_APPEND|O_WRONLY)`, `os.write`, or `os.fsync`, so `spend_ledger._append` (the append-only, fsynced ledger write) and any `with open(..., "a")` in live.py are invisible to it. "write_surface check green" therefore says nothing about the ledger. It also only looks at the call's literal strings, so a name-obfuscated `gh` call can slip. Compensating control already present: `find_writes`/`undocumented_writes`/`DOCUMENTED_WRITES` in `tests/test_regression_ledger.py:930-952` (with its own self-test `:935`) covering `open`, `os.open`, `os.write`, `os.fsync` under `evals/regression/`; AC-7 must cite both checks. Also note the inventory excludes `tests/` and the check ignores the unit-level behaviour of the launcher.

## Constraints & unknowns
AGENTS.md five properties applied:
- SAFETY: refuse loudly, derive limits from the machine (timeouts/parallelism in slice 5 only; until then operator values are explicit and the run is one-at-a-time under the ledger lock). Credential only via the launcher's named variable, never in a file/log/row; `run_claude` forwards the environment (`isolated_env :106`) so the entrypoint must pass only the named variable plus a minimal environment (verify). Nothing spawns without opt-in + cap; `claude`/launcher are spawned only after the whole ladder passes and a reservation exists.
- RELIABILITY: no claim that a run works until one real `claude -p` run is measured (launcher never run live; README says so). Any cost figure is labelled indicative (subscription) or real (API key); `meter.COST_BASIS` text at `meter.py:44`.
- RESILIENCY: SIGKILL leaves `open` counted at full belt; SIGTERM/SIGHUP settle; lost-runner and per-machine caps are stated residuals. Latch present -> refuse until a human deletes it (the launcher already says so); live.py never deletes it.
- SCALABILITY: ledger read in full per reserve (~29 ms at 100x, measured by #886); one run at a time is the ceiling.
- LIVENESS: not a daemon; N/A beyond NOT RUN rows being written for every failure so absence is visible.
- Host-agnostic: pure Python stdlib + git; no Claude hook; the `claude` binary is the system under test, not a trigger. POSIX only; Windows must refuse.
- Unverified: whether an agent subprocess can read the credential via `/proc` (launcher README states it can); whether hosted runners satisfy the launcher's "real home has `.claude`" and no-ancestor-`CLAUDE.md` preconditions (design D-8; no workflow exists until #819). Both stay documented limits, not claims.
- Unverified: Windows step behaviour (workflow is manual-dispatch).
