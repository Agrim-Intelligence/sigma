# Research: #629 scrub() leaves unquoted env-style secrets unredacted

## Blast radius

- The defect is the last entry of `_SECRET_PATTERN_SPECS` in `skills/sigma-loop/scripts/scrub.py`
  (`credential-assignment`): a leading `\b` means an env-style name such as GITHUB_TOKEN never matches (`_` is a word character, so there
  is no boundary before `TOKEN`); `auth`, `credential` are not key names; an unquoted/quoted value containing a
  space is cut at the space (rest survives).
- One pattern table, many routes: `scrub()` (Slack posts in `slack_client.py`, `drift_watch.py`; shared ledger in
  `ledger.py`), `hooks/research_capture.py` (loads scrub.py by path), `tools/leak_scan.py` (imports
  `_SECRET_PATTERNS`), `tools/readiness/exposure_scan.py` (`COMMIT_SHAPE_RULES`), `commit_secret_hits`. Fix once in
  scrub.py; every sink inherits.
- Side effect to measure: `leak_scan` and the commit gate scan this repository with the same rule, so a wider rule
  can flag existing text (a variable reference as the value, docs). To be measured on the tracked tree before and after.
- Work bound: no unbounded leading class; every quantifier either linear over a single char class or bounded.
