## 7. Risks and decisions for the plan

1. **Red can never write verify evidence.** The only writer of the evidence file is `_verify_goal_body` (`loop.py:5810`). Make `red_goal` a separate function that does not call `_evidence_path`, `state.*evidence*`, `_witness_verdict`, ledger or timing writes. Control: after `red`, the evidence file must not exist, `state.done_refusal` must still refuse, and `_test_first_refusal` must still refuse (no green). Break the clause by having `red` call the evidence writer and see the control go red.
2. **Selectors do not fail (all green).** `observe` returns `passed: True`, writes no rows. The verb must exit non-zero with a message that nothing is red (a test that is already green proves nothing, matching SKILL.md's "the fixture is broken" rule at lines 38-40).
3. **Selectors error rather than assert.** Collection errors, import errors and non-assertion failures write no row (`:181` and `:174-175`). Exit non-zero and say no assertion red was recorded. Mixed runs (some assertion-red, some erroring or passing) record only the assertion ones; the verb should list which nodes were recorded. `observe` does not return that, so derive it from the journal rows whose `observed_at == completed_at` for the run's nodes (reading, not changing, `observe`).
4. **No `## Tests` section.** `observe` returns `{'passed': False, 'error': 'plan has no ## Tests section'}` with no `provenance` key; `red_goal` must map that to a non-zero exit. It must also refuse a missing plan (`verification_plan` returns None) and an unsafe goal id (`state.unsafe_goal_reason`).
5. **Shell policy.** pytest executes repository code, so apply the same `shell_policy.repository_shell_commands_allowed(root)` refusal that verify applies (`loop.py:5735`); skipping it would make `red` a weaker gate than `verify`.
6. **Concurrency.** `red` should not take the verify lock (it would make a real verify read "held" and refuse), but it should refuse or warn when a verify receipt is live for the goal, because two pytest runs against one tree could change test bytes mid-observation (observe already refuses on a byte change, `:150`, `:162`).
7. **Idempotency and growth.** Each run appends one row per red node; `refusal` accepts any matching earlier row, so repeats are harmless but the journal grows with each run (at most 25 selectors per run). A retention path for goal witness files already exists (`docs/launch/write-surface.json` near line 1688), so growth is bounded by goal closure. State this number in the plan.
8. **Test-bytes binding.** A red recorded on different test bytes is refused by `refusal` (`:218`, file hash). The control must edit the test file between `red` and `verify` and see the PR gate refuse, then restore.
9. **Order trap.** `refusal` needs `observed_at < started_at` of the green. Running `red` then `verify` with no time between is fine; a red recorded after a green is not accepted (existing test `test_red_after_green_is_refused`).
10. **Skill budget.** Net-zero words in `skills/sigma-implement/SKILL.md` (section 3); a plan that appends fails `tests/test_phase_context_budget.py`.
11. **Unmeasured.** The claimed saving (a 25 to 50 minute full verify versus selector-only pytest) is the issue's figure, not measured here. The plan should state a measured time for one selector-only `red` run on this repository, or say it is unmeasured.
12. **Wording stays host-agnostic.** The verb is plain Python in `loop.py`, so it works on Cursor and Codex; the skill text may be Claude-flavoured, but the refusal text in `work.py` is the load-bearing pointer on every host.
