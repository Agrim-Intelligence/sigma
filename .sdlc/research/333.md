# Research — #333

The scanner has no package boundary to import: `scrub.py` is loaded by path, which keeps its
secret rules the single source of truth. History uses `git rev-list --objects --all`; tracked mode
uses `git ls-files` and `HEAD:<path>`. Both read blobs through Git, not the filesystem, so a deleted
historical file is visible only in history mode.

Reports are value-free. A finding contains a rule id, blob hash, path list, commit hashes, line and
a preview where every matching span on that line has been replaced. Inputs over 2 MiB and NUL-byte
blobs are counted but never decoded. The scan is O(unique reachable blobs plus reported history
lookups); on a repository 10x/100x larger it remains linear in blobs, while each `--find-object`
lookup is only done for a blob with a finding.

Private repository names remain outside the checkout. Their regex file is supplied by
`--patterns` or `SIGMA_LEAK_PATTERNS`, is validated as nonempty regular expressions, and is refused
when inside the scanned worktree. The scanner does not alter repository settings or write GitHub.

Recovery is rerunning the deterministic verb. An interrupted report is an ordinary incomplete
output file; no report is treated as a clean scan. Real findings require the issue's dedup and
class-B2 filing workflow before any external write.
