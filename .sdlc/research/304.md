# #304 research — lifecycle-label self-heal writes

## Scope

The GitHub onboarding control invokes the normal `loop.py start` and `next` flow against the
stateful fake GitHub client. Its current successful github-mode run reports 34 `label create`
calls: 14 required bootstrap labels from init, then two ten-label lifecycle self-heal passes.

## Relevant implementation

- `skills/agrim-loop/scripts/sources.py:1586` implements the hot `_ensure_labels` lifecycle
  self-heal. It currently attempts each lifecycle create and deliberately swallows the expected
  existing-label error.
- `GitHubSource._existing_label_names` at the same module already performs a bounded, paginated
  REST label read and returns `None` when the inventory cannot be trusted.
- `ensure_labels_report` already uses that helper for explicit bootstrap reporting. The hot path
  does not use it yet.
- `tests/test_onboarding_control.py` runs the documented control and receives the fake client’s
  summarized call counts through `github_run`.
- `tests/test_sources.py` contains direct `_ensure_labels` coverage for missing lifecycle labels.

## Constraints and decision

Use the existing bounded REST helper in `_ensure_labels`. If the read returns a complete inventory,
skip known labels and create only missing lifecycle labels. If the read fails or is incomplete,
retain the present best-effort create-and-ignore behavior; this preserves recovery when listing is
unavailable. Keep `_labels_ready` per source instance exactly as today.

The regression assertion is behavioral: the documented github onboarding run must make exactly the
14 label creations belonging to init. It will fail against the current 34-call behavior and does
not inspect source text. Direct source tests will retain the missing-label self-heal proof.

## Risk checks

- GitHub label names are case-insensitive, so all comparisons use the helper’s casefolded values.
- A repository with more than the bounded label inventory is treated as an unreadable inventory and
  falls back to existing behavior rather than assuming labels are absent.
- No label is recoloured, and no new background process, dependency, or ledger state is added.
