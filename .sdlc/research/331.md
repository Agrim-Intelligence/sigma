Base: origin/main 8f7c91b.

## Blast radius
- All new files: `docs/launch/decision-rule.md`, `docs/launch/scorecard.json`,
  `tools/readiness/decide.py`, `tests/test_readiness_decide.py`; plus a CHANGELOG entry.
- No existing code imports or is imported. `docs/launch/` and `tools/readiness/` do not exist on
  main.
- GitHub: labels `launch:blocker` and `launch:next` did not exist (404 on
  `repos/.../labels/<name>`); created by REST in step 1, both now return 200.

## Constraints found
- `docs/launch/definition.json` is written by the sibling goal #330 and is NOT on main. Its schema
  (from #330's body): `{"schema": "launch-definition/v1", "status": "proposed"|"signed", ...}`.
  Decision: a missing definition is NO-GO with reason `definition missing`, exit 1 (not 2).
- docs/launch/review-plan.md (#350) does not exist; the dimension list comes from the epic's
  section 5 table: D0–D13 without D4 (13 rows). D0 (launch definition, "prerequisite") is the
  definition clause of the rule, so the scorecard has 12 scored rows: 11 gating + D12 Market
  informational, matching #331's gating list.
- `tests/conftest.py` raises on any real `gh` subprocess; tests use `--blockers-json` or inject a
  fake `run` into `decide.main`.
- `gh api --paginate` on a REST array prints one JSON array per page, concatenated; decoded with a
  `raw_decode` loop (no `--jq`, no `--slurp`, which older gh lacks).
- Tools pattern: `tools/onboarding_control.py` (shebang, SPDX, USAGE/EXIT docstring), tests load it
  with `importlib.util.spec_from_file_location`.
- Leak guards (`test_no_private_names.py`, `test_self_contained.py`) scan tracked files, so new
  files are `git add -N` before running them.

## Risks
- Steering: a scorecard author could flip `gating` on a failing dimension. Mitigated by pinning the
  gating set in decide.py and refusing a mismatch (exit 2), with a sync test against the page.
- A failed blocker fetch must never read as zero blockers: exit 2.
- "exists on main": checked in the working tree the checker runs on; documented as "run on an
  up-to-date checkout of main".

## Size
Small: ~250 lines of code, ~250 lines of tests, one page. No per-item cost beyond one paginated
REST read (100 issues per page).
