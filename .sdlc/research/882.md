## 2. Layout and schema verify.py requires (read from the code)

A task is a directory under `evals/golden/` whose name equals `task.json` field `id`. Dot-prefixed directories and
`__pycache__` are skipped. Required:

| Path in the task dir | Requirement |
| --- | --- |
| `task.json` | JSON object with keys `id`, `kind`, `origin`, `prompt`, `visible_command`, `hidden_sha256`, `trap` |
| `repo/` | the start tree (directory) |
| `reference/` | the COMPLETE fixed tree, not an overlay (a file absent from it counts as deleted) |
| `hidden/files/` | the hidden tests (directory) |
| `hidden/verify.json` | `{"command": [...]}`: argv starting `python`/`python3`, containing `-m pytest`, `-p no:cacheprovider`, and the literal `.sigma-hidden/files` |
| `allowed_paths.json` | JSON list of strings; entry is an exact path or a prefix ending `/` |
| `rubric.json` | any JSON object (schema belongs to a later scorer goal) |
| `hidden/naive/` | optional; if present, the hidden tests must FAIL on `repo/` plus this overlay |

Field rules: `id` equals the directory name (so the directory must be named exactly `T1`); `origin` matches
`planned|issue:<digits>`; `kind` and `prompt` non-empty strings; `trap` a JSON boolean (the design prose says "trap text",
the code requires a bool; follow the code); `visible_command` a non-empty string list starting `python` or `python3`
(validated, never run); `hidden_sha256` maps path relative to `hidden/` (including `verify.json`) to sha256 hex.
No symlinks anywhere under `repo/`, `reference/`, `hidden/` or at any root.

Checks, in order, each printed as `RED T1 <property>: ...`: task-json, id, origin, visible_command, hidden-sha256
(present-but-undeclared, declared-but-absent, mismatch), verify-json, rubric, allowed_paths, symlink, reference-diff
(every added, changed or deleted path between `repo/` and `reference/` must match `allowed_paths.json`),
hidden-on-start (pytest must exit exactly 1), hidden-on-reference (exit exactly 0), naive.

Runs copy the tree to a scratch dir, copy `hidden/` to `.sigma-hidden`, and run the verify.json argv with the
interpreter under test in a scrubbed environment, bytecode off. Because it is `python -m pytest`, the tree root is on
`sys.path`, so a hidden test can `from intervals import ...` directly.

## 3. Proposed T1

**Algorithm: merge closed intervals** (`merge_intervals`). Familiar, small, and its classic edge cases are exactly the
ones a plausible-but-wrong implementation misses.

Files (paths relative to the T1 task directory):

- `repo/intervals.py` (start tree, buggy): sorts the argument in place, indexes `[0]` unconditionally, merges only when
  `start < last_end` (touching intervals stay apart), and sets the merged end to the new end instead of `max`. Its
  docstring states the real contract (closed ends, touching merges, input never modified), so the bug is findable from
  the prompt alone.
- `repo/test_intervals.py` (visible tests, pass on the start tree): an overlapping pair, and two disjoint intervals.
  Nothing else; the visible suite is green on the buggy code, which is the point.
- `reference/intervals.py` (fix): sorts a copy (`sorted(tuple(p) for p in intervals)`), merges on `start <= last_end`,
  takes `max` of ends, returns a list of tuples; handles empty input.
- `reference/test_intervals.py`: byte-identical copy of the visible test (reference is a full tree, so omitting it
  makes the diff report it deleted; this was hit in the prototype).
- `hidden/files/test_merge_hidden.py`: the hidden edge cases. Name differs from the visible test so the two modules
  never collide. Cases: empty input returns `[]`; touching intervals `(1,2),(2,3)` merge; a nested interval does not
  shrink the outer one `(1,10),(2,3)`; unsorted input; input list not modified; single-point and negative values;
  a chain mixing nested and touching; list-form pairs accepted and tuples returned.
- `hidden/verify.json`: `{"command": ["python", "-m", "pytest", "-q", "-p", "no:cacheprovider", ".sigma-hidden/files"]}`
- `allowed_paths.json`: `["intervals.py"]`
- `rubric.json`: `{"criteria": [...]}` with four plain-language criteria matching the hidden cases.
- `task.json`: `id` `T1`, `kind` `algorithm`, `origin` `planned`, a prompt that names the symptom ("returns wrong results
  for some inputs") but not the edge cases, `visible_command` `["python","-m","pytest","-q","-p","no:cacheprovider","."]`,
  `trap` `false`, `hidden_sha256` generated (section 4).
- No `hidden/naive/` (T2 owns the naive-patch control). No README (avoids the link check surface).

Measured in the prototype (a throwaway copy outside the repo, with the real `verify.py`): hidden tests on the start
tree: 7 failed, 1 passed (the unsorted case passes there, since the buggy code sorts; it stays as a regression guard,
so the exit is 1 as required); on the reference: all pass; `verify.py` printed `ok T1`, `golden: 1 task(s), 0 red`,
exit 0, 2.0 s wall for one task. Visible suite: 2 passed on the start tree.

Sensitivity note (RELIABILITY): the hidden tests are deterministic pure functions, so there is no probabilistic
control to disarm. Control still to run at implement time: break the reference once per hidden case (revert `<=` to
`<`, drop `max`, drop the empty guard, sort in place) and see the matching test red.

## 4. Hashes

`hidden_sha256` is sha256 hex of each regular file under `hidden/`, keyed by path relative to `hidden/`
(`files/test_merge_hidden.py`, `verify.json`), junk (`__pycache__`, `*.pyc`, `.DS_Store`) ignored. Generate from the
T1 task directory, then write the result into `task.json`:

```
python3 -c "import hashlib,json,pathlib; h=pathlib.Path('hidden'); print(json.dumps({p.relative_to(h).as_posix(): hashlib.sha256(p.read_bytes()).hexdigest() for p in sorted(h.rglob('*')) if p.is_file()}, indent=2))"
```

It must be regenerated after any edit to a hidden file; a stale hash is a `hidden-sha256` RED naming the file.

## 6. Risks

1. Test-file naming: `repo/test_intervals.py` sits under `evals/golden/`, which CI's `pytest tests/` never collects.
   Keep it that way; do not add a `conftest.py` or root pytest config.
2. Hash drift: hidden edits without regenerating `hidden_sha256` turn the gesture red; the plan should regenerate last.
3. Start-tree red must be exit 1 (assertion failures), not a collection error (exit 2); a syntax or import error in the
   start tree would be reported as "must fail ... (exit 2)". The prototype is exit 1.
4. Hidden tests live in the repository (accepted, design doubt D-2): an agent given a checkout can read them. Only the
   later executor can prevent that; not this goal's job.
5. Prompt/docstring leak: the start docstring states the contract; it must not enumerate the hidden cases, or they stop
   being hidden in spirit. The prototype states the contract only.
6. Interpreter range: the task must run on the repo's supported Pythons (3.10+); the prototype uses nothing newer than
   builtins. `python3` on this machine is 3.9; the verifier itself also ran green there.
