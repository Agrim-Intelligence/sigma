## Findings, confirmed against the code

1. Cost claim. A pass that CLOSES a goal reads the PR twice over REST (`pr_landing_state`, then
   `done_refusal` re-reads it), then `_record(done)` -> `_release_checkout` -> `finish` runs
   `_open_pr_refusal` (`gh pr view --json state,autoMergeRequest`, GraphQL) and `_pr_merged`
   (`gh pr view --json state`, GraphQL, up to twice). README/landing.md say "at most 10 REST reads
   per pass" and "REST, never GraphQL". Measured with an injected runner: 2 `pulls/<n>` reads and
   3 `gh pr view` calls per closed goal (ledger/journal off).
2. No lock: `next` (`_next` -> the pass) and the watch tick (`reconcile_tick.py`) are separate
   processes reading the same flags; both can read MERGED and both `_record(done)` -> two ledger
   `done` lines, two close comments, two unit-completion signals.
3. Crash window: the flag is cleared only after `_record` returns, i.e. after
   `_signal_unit_completion` and `_release_checkout` (network + git). A kill by the 120 s tick
   timeout in there leaves the flag set; the next pass records `done` again. The pass also has no
   wall-clock budget: 10 goals x (read + close + release) can exceed 120 s.
4. Liveness: a goal awaiting merge is invisible. `log.py active()` drops any goal whose last entry
   is `recorded` (review included) and `is_closed` treats `recorded result=review` as closed. No
   doctor row or status segment reports how long a goal has waited or when its PR was last read,
   so an armed PR whose check fails, a permanently unreadable PR, or a machine where nothing runs
   the pass all look like "nothing to do".
5. `record failed` / `record parked` go through `_record` which never touches the flag; a later
   merge makes the reconcile pass record `done` over the human's decision.
6. `finish` on an armed PR: `_open_pr_refusal` returns None for `autoMergeRequest` set, so a
   hand-run `work.py finish` deletes the work record (the only place the PR number lives); the
   goal can then never be reconciled. landing.md says it refuses.
7. A transient `source.complete()` failure on the reconcile path goes through `_record`'s #1201
   downgrade: `source.park()` (public `sdlc:parked` label + comment) before any retry.
8. The e2e repick assertion passes because the issue still carries `sdlc:in-progress`
   (`_fetch_pending` excludes it); it never exercises `_awaiting_merge_skip`.
9. `run_loop`: `parked += outcome not in ("done", "failed")` counts `review`.

## Constraints

- Locking: `state.phase_end_lock` already uses `fcntl.flock` / `msvcrt.locking`; kernel locks die
  with the holder (stale-safe by construction, including SIGKILL from `run_with_timeout`).
- `log.py` imports nothing from agrim-loop; it can only use the action log (the `recorded
  result=review` row's age is the awaiting age).
