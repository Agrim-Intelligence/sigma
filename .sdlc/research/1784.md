## Why `templates/` is wrong (PC-3, re-verified)

## Resolving `system_root` for the target (what the scaffold must do)

Call the slice-1 resolver, never re-implement it: load `architecture_doc.py` by path from
`sdlc_init.py` (same idiom as `_verify_detect()` :96-104; `sdlc_init` itself is loaded by path from
`wizard_actions.py`/`init_flow.py`, so the scripts dir is not on `sys.path`). Call
`resolve_system_root(str(Path(target)/".sdlc"), str(target))`. In both entry points `scaffold()` has
already created `config.json` before extras run (`main()` :757, `init_flow` :705 after `apply_config`).

Behaviour matrix I checked by running the resolver (read-only, 11 inputs):

| config value | resolver result | scaffold must |
|---|---|---|
| unset / `docs/architecture` | folder | write `docs/architecture/architecture.md` |
| `https://`, `ssh://`, `git@...` well-formed | `url` | REFUSE: "will not write into another repository; run the scaffold inside that repository" (D-5) |
| malformed URL, `/abs`, `a/../b`, `C:x`, `\\host`, control char, symlink escape, non-string, `""` | `invalid` with `error` | REFUSE with `resolved.error` |
| **`HTTPS://x/y`, `http://x/y`** | **`folder`** (resolver reads only lowercase `https://`) | **scaffold must add its own refusal**: it would create directories literally named `HTTPS:`/`x`/`y`. `lint` has `_url_like` (`"://" in value`) for the same trap. AC-1b says URL. |
| **`.`** | folder = repo root | decide: refuse or allow; default: refuse (a root-level `architecture.md` is not what `system_root` means) |
| **`.git`, `.git/x`, `.sdlc`** | folder (inside repo) | **default: refuse a first segment of `.git`** (writing into git metadata); `.sdlc` also refuse (runtime dir, git-ignored lists) |
| `docs\x` | folder (a literal backslash name on POSIX) | refuse any `\` (D-15; avoids cross-platform split) |
| `~/x` | folder | harmless (a literal `~` directory); leave |
| config unreadable (`None`) | folder default with `note` | proceed with the default and print the note (resolver semantics); do not invent a refusal |

These extra refusals are scaffold-only (a few lines in `scaffold_architecture_doc`), because changing
the slice-1 resolver would reopen the merged slice and its 1000-line control suite. Flag as a plan-review
question: `.`/`.git`/`.sdlc`/`://` belong arguably in the resolver (a slice-1 gap); defaulting to
scaffold-only keeps this PR in its lane.

Write semantics (RESILIENCY): validate fully BEFORE any `mkdir`; then `mkdir(parents=True,
exist_ok=True)` and `open(dest, "x", encoding="utf-8", newline="\n")`. `FileExistsError` => kept (this
also covers an existing file, a dangling symlink and a directory at that path, because `O_EXCL`
refuses all three). Any other `OSError` (the folder path is an existing FILE: `mkdir` raises
`FileExistsError`/`NotADirectoryError`, which must not be mistaken for "kept") => let it propagate;
`main()` catches `(ValueError, OSError)` from `scaffold_extras` and prints `extras_refusal_lines`
(:631-648) and exits 2 at the end. Distinguish "file exists" from "dir is a file" by checking
`dest.parent.is_dir()` after mkdir failure. Raise `ValueError` for policy refusals. WARNING: those
refusal lines special-case any message containing `AGENTS.md` or `Codex`; the new messages must not
contain either word, or they get the Codex remedy text. Place the branch LAST in `scaffold_extras`
(extras stop at the first failure, :644-646), so a refusal here skips nothing else.

"Write nothing" (AC-1b) scope: the preceding `scaffold()` and `_ignore_runtime_dirs` still run on a
first init (design-wide behaviour). The test must init first, edit the config value, snapshot the whole
tree, run the flag, assert the snapshot is byte-identical and exit code 2.

## D-12 (root-checkout rule)

The scaffold is operator-run (`/sigma-vision` or `/sigma-init`), never by the loop or a background
process, and writes one NEW UNTRACKED file in the operator's checkout. `work.py start` ignores
untracked files (work.py:2599 filters `??`), so only `git pull` can refuse, when a teammate's commit
adds the same path. Required: after a created outcome the scaffold prints both clearing commands
(design D-12): keep => `git add <path> && git commit`; undo => `rm <path>` (single file; an empty new
folder is harmless to git). Print the path repo-relative with `Path.as_posix()`. For the kept outcome
print `= <path> (exists, kept)` only. Test: the output of a created run contains both commands with the
real path; a kept run does not claim a creation. Not a #1161-type write (no plan/research copies).
