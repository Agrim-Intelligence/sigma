# Research: Cloud --land: work.py merge parks whenever the base's CI outlasts the 450 s pending-check wait
**Goal**: #2083 (Agrim-Intelligence/sigma), acceptance `.sdlc/acceptance/2083.md` AC-1..AC-4 · **Lane**: medium · **Date**: 2026-10-29

## Goal in one paragraph
In a cloud session (no GraphQL) `work.py merge` spends `gate()`'s fixed 450 s wait (`PENDING_ATTEMPTS` 10 x `PENDING_INTERVAL` 45 s), and if a check is still pending it returns `PARK: required checks still pending after 450s and auto-merge cannot be armed without GraphQL; re-run work.py merge once they finish`. `landing.md` maps that line to `record parked`, which contradicts the line's own "re-run" and strips `sdlc:goal`. Fix: (1) when GraphQL is refused and every pending check is one the base itself requires and the repo allows auto-merge, arm through the CCR REST route (`PUT /repos/{o}/{r}/pulls/{n}/ccr/auto_merge`) and print `auto-merge armed ...`; (2) otherwise the wait becomes a config key (default 450 s) so a 30-min CI can be waited out in-session; (3) doctor shows the value; (4) landing.md and the PARK line give one instruction.

## Risks
- R-1 (largest) Arming over an unconfirmed endpoint. If the proxy ignores or mis-handles the head pin, an arm could land a head Sigma did not vet. Mitigation: refuse to arm when the vetted head cannot be sent in a form the helper can state; on any non-2xx or unrecognised reply return `PARK: could not arm auto-merge ...` (same shape as `work.py:7883`), never fall through to a merge; label UNMEASURED.
- R-2 Arming when the host requires nothing lands immediately, before CI answers (the issue's caution, and the target repo's exact situation). Guarded by the subset test against the required-context set; empty/unreadable set must not arm.
- R-3 `protection()` can over-report (bypass actors, `evaluate`-mode rulesets, `work.py:4830-4833`): a check Sigma thinks is required may not be enforced for this actor. Unfixable here; document, and note undercount (the other residuals) fails toward waiting, the safe direction.
- R-4 Timeout/liveness: a larger wait makes `work.py merge` run longer (x up to 4 on the BEHIND path); `merge_budget_seconds` and the documented tool-call timeout (`landing.md:190-201`) must follow the key, else receipts mis-report and hosts cut the call. Cap at `MAX_RUN_SECONDS`.
- R-5 Behaviour change for the old `D3` tests and the documented PARK string; `Run the control`: each rewritten test must be seen red against the old code and each clause of the arm condition broken on its own (including the gesture the docs give: `SIGMA_GH_GRAPHQL=off` and `CLAUDE_CODE_REMOTE=true`).
- R-6 Ratchets: `tests/test_no_direct_gh.py` (new `["gh","api",...]` list is not counted; do not add any `["gh","pr",...]` literal), `tests/test_no_direct_gh_prose.py` (prose edits in landing.md must not add a direct `gh issue|pr` loop-path command), enforcement table regeneration, phase-context budget (`evals/phase_context_budget.json` has no landing.md entry per `rg`, but check `tests/test_*budget*` after editing sigma-loop prose).
- R-7 Cloud-only wait still consumes a single session's wall time: measured nothing; the issue's 30-min figure (22:19:24Z to 22:49:16Z) is from the run report, not re-measured here.
