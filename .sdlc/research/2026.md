# Research: Orchestrator measures its own context from its transcript tail; status shows it; re-write report
**Goal**: #2026 (slice 1 of Epic #2025, design `.sdlc/design/2024.md` §Detailed design 1) · **Lane**: medium · **Date**: 2026-10-24

## Goal in one paragraph
At each `loop.py next` / `next-batch`, read a bounded tail (256 KiB) of the orchestrator session's
OWN transcript — Claude: `<config>/projects/*/<CLAUDE_CODE_SESSION_ID>.jsonl`; Codex: the rollout
named by `CODEX_THREAD_ID`/`CODEX_SESSION_ID` — and record the latest turn's context size (Claude:
input + cache read + cache write; Codex: `input_tokens`, which already includes cached) with a
source (`host` / `unavailable`) and the session's first-pick baseline into the session heartbeat,
never message text. Show the reading in the `log.py slots` and `status.py` tails. Add a
"full-context re-writes by preceding idle gap" view to `orchestrator_context_report.py`. Make
transcript lookup honour `CLAUDE_CONFIG_DIR` / `CODEX_HOME`, and clear the session-id env in
`tests/conftest.py`. Slice 1 records and shows only; no hand-off decision (that is slice 2).

## Constraints & unknowns
- Unverified: whether Codex `cache_write_input_tokens` is a subset of `input_tokens`. The meter uses `input_tokens` alone on Codex (F4), so a write is never added on top either way.
- Unverified: the Claude transcript format is internal (design PC-8); a format change degrades to `unavailable`, which is the honest fallback.
- Constraint: the latest assistant line may sit beyond the 256 KiB tail when a huge tool result follows it; the meter then reports `unavailable` rather than scanning further. That is the bounded-read guarantee, not a bug.
- Constraint: generation is not a "same host session" key (CLI `start` mints a new one each call, `loop.py:7418-7419`); the transcript id is.
- Blocking: none.
- Non-blocking: where the first-pick baseline lives — decided in the plan (heartbeat, merged writer, keyed by transcript id).
- North-star: `north_star.py` → `absent` (drop-in); nothing to check.
