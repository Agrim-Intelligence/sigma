# Research: Commit gate: credential-assignment rule refuses non-literal values (calls, env reads, type annotations, booleans), parking green goals
**Goal**: #961 · **Lane**: medium · **Date**: 2026-10-10

Every claim below was read from the goal worktree `.sdlc/work/961` (branch `sdlc/961`, cut from
`origin/main` at `5f25b99`, release 1.0.5). Line numbers are worktree line numbers.

**How this dossier names the issue's table rows.** This file is committed through the INSTALLED
commit gate, which still carries the bug. So the five sample lines are never written out here.
`KEY` stands for a credential-named keyword from the rule's list, and the rows are:

- **R1**: a JS `const KEY = uiToken();` (a call)
- **R2**: `KEY = os.environ["X"]` (an env read: an attribute, then a subscript)
- **R3**: `def guard(KEY: str) -> bool:` (a type annotation)
- **R4**: `"KEY": True,` (a boolean in a dict or JSON-ish literal)
- **R5**: `KEY = "<14-char literal>"` (a quoted literal; it must stay refused)

## Goal in one paragraph

`work.py commit` scans every added staged line with `scrub.commit_secret_hits` and refuses on any hit.
The anchored legacy `credential-assignment` rule (scrub.py:146-148) takes any run of 4+ characters
from `[^\s"'<>&]` after a credential-named key and `:` or `=`. So calls, attribute or subscript reads,
type annotations and booleans all count as credential values. Green, reviewed goals get parked at the
last step. The fix has to stop those non-literal shapes from refusing. It must keep refusing quoted
literals and unquoted secret-like runs (known prefixes, entropy, bare identifiers), add a per-repo
escape hatch in `.sdlc/config.json` keyed only by rule + exact path or rule + exact line hash, and name
the rule plus that escape hatch in the refusal. The redactor (`scrub()`), the publish leak gate
(`tools/leak_scan.py`) and the exposure scanner (`tools/readiness/exposure_scan.py`) must not change.

## Constraints & unknowns

- **Bootstrap trap (plan must budget for it).** This goal's own `work.py commit` runs the INSTALLED
  gate (1.0.2 plugin cache), which still has the bug (Q9). Every added line in this goal, including
  tests, docs, CHANGELOG, the template comment, the plan and this dossier, must avoid "credential
  keyword, optional quote, `:` or `=`, then 4+ characters". Otherwise the goal parks on the defect
  it fixes. Tests must build sample lines from split fragments, as tests/test_scrub.py:373-374
  already does (`"my_to" "ken = ..."`). Docs must not show a raw example. The fallback, a hand
  commit, is the bypass this goal exists to retire.
- **Where the fix may live.** It goes in a gate-only post-filter inside `commit_secret_hits`
  (BR-1). The anchored spec (BR-3) and `SHAPE_RULES` (BR-4) are not touched, since changing either
  breaks AC-5 or widens the scanners (BR-13, BR-14). The post-filter must tell quoted from unquoted
  by the character after the separator in the LINE, because the anchored rule's optional `["']?`
  hides that: R5's anchored match is the same span whether quoted or not.
- **Measured value classes (Q7) and the safe exemption boundary.** Exempting only these keeps AC-2:
  - an identifier head followed by `(`, `.` or `[` (R1, R2, `getenv(...)`, `settings.x`, `cfg[0]`,
    `Optional[str]`);
  - `True` / `False` / `true` / `false` / `None` / `null` / `nil` / `undefined` followed by end of
    value or `,;)}]` (R4);
  - a closed set of bare type names after a `:` separator (`str`, `bytes`, `string`, `bool`, ...),
    which covers R3.

  Things that stay refused: any quoted value (R5, the 6-char quoted `abc123`), a bare identifier
  (`myToken`, `await`), an unquoted letter-and-digit run (the YAML or `.env` literal shape), and
  any head with a known provider prefix or secret-like entropy. Known-prefix tokens are also caught
  on their own by `gh-token` / `stripe-key` / `aws-key` (measured), which is a backstop, not a
  reason to skip the head check. Capitalised identifiers must NOT be exempted as "types": an
  unquoted YAML value like `Summer2024` is a real password shape.
- **Measured cost.** `commit_secret_hits` takes 32.3 µs/line today (all 7,063 lines of work.py in
  0.228 s on this machine, 2 hits). A post-filter runs only on anchored matches (101 in the whole
  tracked tree), so the added cost scales with hits, not bytes. At 10x or 100x staged bytes the gate
  stays linear, as it is now. Allowlist lookups should be set-based (O(1) per hit), and the list
  only grows by reviewed, hand-added entries.
- **Unverified:** whether a commit refusal's text reaches a public issue comment verbatim. An agent
  relays it, and park reasons land on the issue timeline. `scrub()` has no rule for a 64-hex string
  (scrub.py:44-150), so a hash printed in the refusal would survive. Not traced end to end here.
- **Unverified:** no fast-moving dependency is involved (stdlib `re` / `hashlib` only), so there is
  nothing to check upstream.
- **Blocking:** none. Each tension below has a fail-closed default that Plan can take and flag.
- Non-blocking: **numbers.** The issue's item 3 exempts numbers, but the orchestrator's allowed list
  omits them, and a numeric PIN or password (`KEY = 12345678`, measured as matched) is a real
  credential shape. Recommend: do not exempt numbers.
- Non-blocking: **placeholders.** The issue lists structural forms (`<...>`, `${...}`, `{{...}}`,
  `***`), but the orchestrator asks for a small EXACT list. Exact strings cannot cover `${NAME}` (Q8
  finds `${...}` values in tests/test_leak_scan.py:274-279). Recommend: an exact word list (in the
  spirit of `COMMIT_FIXTURE_VALUES`) plus, only if the user approves, exactly-delimited env-name forms

- Non-blocking: **escape-hatch shape.** Proposed key `work.allow_secret_content`, a list of
