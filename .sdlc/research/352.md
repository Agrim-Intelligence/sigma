## 3. Ambiguities the plan must pin, with the recommended reading

(a) Splitting a file over 3,000 lines. Measured with `ast`:
- sources.py has ONE top-level node, `class GitHubSource`, lines 835-5132 (4,298 lines, 126 methods,
  largest 221). Split literally at top-level boundaries the piece 835-5195 is 4,361 lines, over the
  cap: the spec cannot be met for this file as written. Recommend recursive descent: a top-level
  class spanning more than the cap also contributes its direct `def` children as boundaries.
  Prototype result: sources.py = 1-2986 and 2987-5195.
- No single top-level def exceeds the cap today (largest: work.py `main` 230, loop.py `_dispatch` 514,
  doctor.py `check` 596). For a def over the cap, or a file with no top-level def (a `.sh`, or a
  `.py` that fails `ast.parse`): last blank-line boundary inside the cap window, else a hard cut at
  the cap, with a stderr note and the JSON schema unchanged. Test on a synthetic 7,000-line file
  with no `def`.
- Use `ast`, not a column-0 regex: `render.py` has a docstring line starting `class `, a false hit.
- Boundary = first decorator line (else the `def`/`class` line), moved up over directly contiguous
  `#` comment lines (no blank gap). Pieces tile 1..n with no gap or overlap: the preamble joins the
  first piece, the tail after the last def joins the last. Greedy: cut at the latest boundary that
  keeps the piece <= 3,000. "Over" is `n > 3000`; exactly 3,000 is one unit. Test the tiling.

(b) Packing. Only files <= 3,000 lines are packed. Pieces of a split file stay alone (spec: "A larger
file is split"); otherwise the 7,000-line file's tail would pack with the three 500-line files and the
issue's "three small files pack into one unit" would not hold. Rule: group by
`PurePosixPath(path).parent`, sort paths bytewise, next-fit (close the unit when the next file would
exceed 3,000), units never span directories; then sort all units by (first path, first start) and
number them. Prototype Tier A: 17 units, max 2,997 (A01 hooks 2,267; loop.py A06-A08; sources.py
A11-A12; work.py A15-A17), total 36,018.

(c) The draw. Draw WHOLE FILES, then split/pack only the drawn files into B units. Do not draw packed
units: a unit can be 5% of 58.6k, so the 15-25% band is unreachable on the small populations a
hermetic test builds. Recipe: paths sorted bytewise; `rng = random.Random(seed)`;
`order = sorted(paths, key=lambda p: (rng.random(), p))` with keys drawn in sorted-path order
(`Random.random()` is the primitive the docs promise stable; `shuffle` is not, though it gave the
same output hash on 3.9, 3.10, 3.12 and 3.13). Walk `order`, add a file if cumulative + n <= ceiling,
stop at cumulative >= ceil(0.20 * pop). Measured (pop 58,577):
- ceiling 25%, `shuffle`: 21 files, 14,597 lines = 24.92% (inside the band, at its edge).
- ceiling 22%, `shuffle`: 25 files, 12,092 = 20.64%; ceiling 22%, random()-keyed: 15 files, 11,972 =
  20.44% (includes doctor.py). Recommend ceiling 22%, test bound 15-25%, stderr warning if the walk
  ends below 15%, and exit 2 on an empty population or empty draw (never an empty "ok").
- Tests: explicit `seed=` on a function (two seeds differ on 40+ files); the CLI test asserts
  `seed == int(sha[:8], 16)` only, since a temp repo's commit sha changes per run (unless dates and
  identity are pinned). For the band loop `seed in range(50)`, every file < 2% of the population.

(d) Seed = `int(resolved_full_sha[:8], 16)`; resolve `--sha` via `rev-parse` first so a 12-char sha
gives the same seed, and emit the full sha. (e) IDs `A01..`/`B01..`, width max(2, digits), assigned
after the (path, start) sort.

(f) `start`/`end` 1-based inclusive; `lines` = sum of `end-start+1`. Count by newline
(`raw.count(b"\n")` + 1 if the last byte is not `\n`), NOT `splitlines()`: `feature_doc.py` holds one
U+2028, so `splitlines()` = 968 but ast, editors and `git apply` say 967 (the only such file in
A+B); document the 1-line gap to the inventory's method. Skip a 0-line file (none exist). JSON: keys
in the issue's order, no extra top-level keys, `indent=2`, trailing newline. `--json PATH` writes the
file and prints a one-line summary; without it, print the JSON.

(g) `seed_defects.py`.
- Manifest `{"schema": "readiness-seeds/v1", "base_sha": <clone HEAD>, "seeds": [{"id": <patch stem>,
  "patch": <name>, "file": <path>, "lines": [..]}]}`; `score` reads `seeds[]`.
- `lines` = post-image numbers of every `+` line. Parse hunks by COUNTS from `@@ -a,b +c,d @@`
  (omitted `,n` = 1), not by prefix (a deleted line `-- x` looks like a `---` header); skip
  `\ No newline`. A pure-deletion run records the two surviving neighbours, clamped to the file.
- Measured `git apply` facts (scratch repo, git 2.39): several patch FILE arguments are NOT atomic
  (`git apply p1 p2 bad` left p1 and p2 applied, exit 1); one concatenated stream
  (`cat p1 p2 bad | git apply -`) applied nothing; `--check` over several file args tests each
  against the on-disk tree, so a patch depending on an earlier one passes; an independent patch to
  the same file applied at an offset (header `+20` landed on line 22), so header numbers would be
  wrong. Recommend: one file per patch and one patch per file (else exit 2 naming the paths);
  `git apply --check` each against the clean tree, then apply in sorted name order; afterwards
  read each file from the clone and confirm every recorded `+` text sits at its recorded number, else
  exit 1 ("authored against another base"). Use `--whitespace=nowarn` (a user's `apply.whitespace`
  can reject a patch) and absolute patch paths.
- Refuse with exit 2 before changing anything: resolved `seed_dir` equals or sits inside resolved
  clone (`Path.resolve()`; macOS `/tmp` is a symlink); clone is not its own
  `git rev-parse --show-toplevel` (measured: `git -C <subdir of a repo> apply` exits 0 and patches
  nothing; in a plain directory it patches); tracked files dirty (`git status --porcelain
  --untracked-files=no`; a second apply fails `--check` anyway); no `*.patch`; a patch that
  creates, deletes or renames. Write the manifest last, temp file + `os.replace`.
- Exit codes: apply 0 / 1 (will not apply, or verification mismatch) / 2; score 0 (recall >= 0.80) /
  1 (below) / 2 (unreadable or non-list JSON, entry not an object, `path` not a string, `line` not an
  int >= 1 (reject bool), manifest missing or zero seeds).
- Match: `abs(line - changed) <= 5` is inclusive (5 matches, 6 does not); normalise `./` and
  backslashes in `path`; an absolute path just does not match. A seed is matched if any finding
  matches; one finding may match two nearby seeds (tell seed authors to keep changed regions > 10 lines
  apart). Threshold in integers, `matched*5 >= total*4`; print `recall: 0.667 (2/3)`. A finding's `id`
  is the reviewer's own; require `path` and `line`, default a missing `id` to its index.
- Seed id = patch stem; recommend `NN-<class>-<slug>.patch` (six classes) so `score` can name a
  missed seed's class; do not refuse sets under six (the goal ships 3). The 3 example seeds live in
  the tests (temp repo) and one is quoted in the doc; never in `~/.sigma-ops/readiness/seeds/<sha12>/`
  (the real set) and no committed patch targets real code at the sha.
