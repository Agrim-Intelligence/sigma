# Research: #593 benchmark isolation launcher

## The harness contract (origin/main 7c35955, `evals/bench/bench.py`, `evals/bench/arms/common.py`)

- `--isolation-launcher` must be an absolute executable file OUTSIDE the repository, hidden root, task trees and
  scratch root (`_validate_isolation_launcher`). The repository copy of the launcher is therefore a source the
  owner installs; it cannot be handed to the harness in place.
- Every launched command is `launcher -- <argv...>` (`claude_argv`, `claude_version`, `command_passed`), started with
  `start_new_session=True`, cwd = the run directory, stdout and stderr discarded, stdin = the prompt (claude) or null.
  The harness kills the launcher's process group with SIGKILL at its own deadline and after a normal exit.
- Environment: `isolated_env` strips `SIGMA_BENCH_*` and points HOME, CLAUDE_CONFIG_DIR, CODEX_HOME at fresh
  `<run>/profile/{home,claude-config,codex-home}` and TMPDIR at `<run>/profile/tmp`; everything else is forwarded whole
  (credentials included). `_safe_arm_environment` drops any value containing the hidden root, so the launcher cannot
  be told the hidden root through the environment.
- Cost is read from `<CLAUDE_CONFIG_DIR>/projects/...` named by the harness's own CLAUDE_CONFIG_DIR, so a launcher that
  moved claude to a different config dir would make every run unpriced and stop the benchmark. The launcher must
  keep the harness's directories.
- The plugin is `claude -p ... --plugin-dir <run>/plugin`, a sibling of `<run>/profile` (A1 only).
- Exit status: the harness only tests `== 0`.
- The harness already hashes `~/.claude/plugins` (and `$CLAUDE_CONFIG_DIR/plugins`) itself; the launcher adds the
  other three surfaces and a per-run hash.

## Authentication (fetched 2026-10-05)

Source: Claude Code docs, "Authentication" (code.claude.com/docs/en/authentication) and "Environment variables"
(code.claude.com/docs/en/env-vars).
- `ANTHROPIC_API_KEY`: "In non-interactive mode (`-p`), the key is always used when present." Needs no login and no
  approval prompt. Per-token Console billing, which is what `--max-budget-usd` and the meter price.
- `CLAUDE_CODE_OAUTH_TOKEN`: one-year token from `claude setup-token`, subscription (Pro/Max/Team/Enterprise);
  "Takes precedence over keychain-stored credentials". Usage counts against the subscription, not dollars.
- Stored login: macOS Keychain, else `<config dir>/.credentials.json`; with CLAUDE_CONFIG_DIR set the file and the
  Keychain entry are keyed to that directory, so a fresh config dir reads a different (empty) entry.
- So authentication works in an empty profile with exactly one environment variable and no copied login state. No
  file is needed. Not covered by the docs, so unmeasured: system-wide managed settings, other keychain items.
