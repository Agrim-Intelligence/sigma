## Facts that change the plan (read from code, measured where stated)

- `tools/onboarding_control.py` GitHub path is a FAKE `gh` plus a local bare remote. It has no real-GitHub mode; the "real GitHub" gesture in `docs/onboarding-control.md` is a human running `/sigma-loop`. A scripted real-repo driver does not exist, so this goal adds one (`tools/readiness/blast_radius_drive.py`) that reuses the control's helpers (`Run`, `_env`, `_git`, `_init_and_verify`, `parse_quickstart`) and points the same scripted sequence at the drill repository. `blast_radius.py` stays read-only.
- `tools/readiness/egress/sitecustomize.py` records `program` and only the first two argv entries. `git -C <dir> push` records `-C <dir>` (verb invisible) and `gh api <endpoint> -X DELETE` records no method. A5 over that capture would be blind to both, so the hook gains additive `verb` (git) and `method`/`graphql` (gh api) fields; existing fields are unchanged.
- The inventory (`docs/launch/write-surface.json`) has twelve rules (gh-issue, gh-pr, gh-label, gh-project, gh-api-write, graphql-mutation, git-push, git-destructive, fs-*, network-post). `tools/readiness/write_surface.py` already defines the gh verb sets and the git destructive tokens; A5 classifies a launch with the same grammar.
- `work.py merge` under `auto_merge: always` runs `gh pr merge <pr> --squash` directly (no arming; the drill repo has allow_auto_merge false), then `_delete_remote_branch` and `_close_issue_the_base_cannot`. Under `off` it stops after the review gate and leaves the PR.
- The drill repo is empty (size 0, no branches), so the setup must push an initial commit to `main`. That is a setup write, named by its head sha and passed to the assertion as a baseline, not hidden.
- GitHub's repo events API PushEvent payload carries `ref`, `head`, `before`, `size`, `commits`; it is not known to carry `forced`. A2 therefore reads `forced` when present AND checks `before` is an ancestor of `head` through the REST compare endpoint; the real payload is recorded in the evidence.
- onboarding's `_env` clears HOME and git config, so the real drill passes `GH_CONFIG_DIR` and a `GIT_CONFIG_COUNT` credential helper through the environment; no token is written anywhere.
