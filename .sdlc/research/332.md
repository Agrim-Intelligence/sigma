# Research — #332 review baseline

The readiness baseline must inspect a pinned Git object, rather than the shared
checkout. `git ls-tree -r --name-only <sha>` supplies the tracked path set at that
object, and `git cat-file --batch` supplies each blob without reading working-tree
files. This excludes untracked worktrees and makes a repeated inventory reproducible
for the same commit.

`snapshot` has two independent push barriers: removing `origin` prevents an accidental
default push, while a 0755 `pre-push` hook refuses with a stable diagnostic even if a
reviewer later configures a destination. It uses `git clone --no-local` and detached
checkout, so a local source is copied through Git rather than shared by hard links.

The issue-state path is deliberately injected through module-level `RUN`. That keeps
tests hermetic and lets them assert the REST endpoint exactly; production only calls
`gh api repos/<owner>/<name>/issues/<n>`, never GraphQL.
