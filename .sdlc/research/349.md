# #349 research — growing-store audit

Issue #349 requires a code-and-prose inventory, not a hand-picked list. The initial source
scan found durable writers in `ledger.py` (journal retention), `actionlog.py` (per-goal JSONL),
`timing_store.py`, `state.py`, `watch_daemon.py`, `supervise_daemon.py`, and `work.py` (worktree
lifecycle). `work.finish()` is the correct completion seam: it confirms merge state, removes the
goal worktree, prunes git metadata, and then unlinks the work record.

The existing `ledger.prune_journal()` / `_maybe_prune_journal()` is reusable retention machinery.
The review-copy growth called out by the issue is different: it is under `.sdlc/evidence/<goal>/`
and must retain human-authored text (`.txt`, `.json`, `.md`) while deleting only `rv*/wt` tree
copies after a terminal finish. The removal must be fail-open and action-logged.

The inventory tool must statically identify writes from both Python and skill prose, then produce
one row per resolved store pattern with writer, growth, cap/pruner, current measured size, 10x/100x
projection, and an explicit decision. Any uncapped store not safely pruned in this change needs a
deduplicated B6 issue rather than an invented retention policy.

The terminal seam is not only successful `work.finish()`: failed-goal release also needs a narrow
cleanup invocation without deleting the failed goal's worktree. Host paths are inventory-only by
default. The audit may measure known Sigma/Codex/Claude host stores, but must not prune host-owned
data unless a Sigma writer, a justified retention policy, and a hermetic control establish that
authority.
