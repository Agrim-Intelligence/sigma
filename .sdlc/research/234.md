Board #17 today (read-only): fields Title, Assignees, Status (Backlog/Ready/In Progress/QC/Done/
Blocked/Parked), Labels, Linked pull requests, Milestone, Repository, Reviewers, Parent issue,
Sub-issues progress, Created, Updated, Closed. **No Priority, Phase, Area, Model tier.** One view,
`View 1` (table: Title, Assignees, Status, Linked pull requests, Sub-issues progress; no filter,
group or sort). Workflows: Auto-add sub-issues ON, Auto-close issue ON, Item added OFF, **Item closed
OFF**, PR linked OFF, PR merged OFF.

The code comment in the issue (`doctor.py:656-667`: "no public createProjectV2View") is stale: the
mutation exists. What does not exist is the half of a view that makes these six views distinct:
grouping, sorting, the board's column field, roadmap dates/markers and view order.

## Constraints / decisions forced by the schema

- A view can be made to match on name + layout + filter + visible fields only. Group, sort, column
  field, roadmap dates/markers and default-view position are printed as exact manual steps, one per
  property, and only when `verify` reads them as different.
- GitHub's project filter ANDs qualifiers; values inside one qualifier are ORed. "Status in
  (Parked, Blocked) OR label sdlc:needs-confirmation" crosses two fields, so it is expressed on ONE
  qualifier: the labels (`sdlc:parked`, `sdlc:blocked`, `sdlc:needs-confirmation`), which are the
  source of truth the Status lanes mirror.
- Priority is P0..P4 (the kit's `discovery.PRIORITIES`), not P0..P3: a four-option field leaves every
  P4 goal blank on the board (the same ruling #235 recorded).
- Area and Model tier: no writer exists in the loop today. The fields are created empty; a mirror is
  follow-up work, stated in docs.
