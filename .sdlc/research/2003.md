## Decisions / defaults
- Route store: the work record (`route`, `profile`, `rationale`). The fallback is the newest `goal_class` action-log row, used when there is no work record or the record has no route (work.enabled off, or after `finish`). Read by `work.route_of`.
- Default classification: a fresh `work.py start` cut writes `lean/1`, profile standard, source default, into the record and a `goal_class` row, unless there is legacy evidence (an approving gates record or an approving plan_review verdict row with no route). There is no timeline write on the default.
- Explicit: a new `loop.py classify <sdlc> <goal> <profile> --rationale R` verb writes the record (if present), a `goal_class` row and a timeline marker via `source.note`. It refuses an unknown profile, an empty rationale and a legacy goal (FR-33).
- work.enabled off: a goal is lean only through `classify`, because no start runs. This fails safe: legacy runs every phase.
- FR-96: `actionlog.enabled_for(config, sdlc_dir, goal, kind)`.
  - An explicit `enabled` value → today's strict rule.
  - An absent value → on for a `goal_class` row or a lean goal.
  - Used by `append` and the five goal-aware callers above.
- No fold writer in this slice; the shape is defined by its reader. The pre-implementation test review (slice 7/10) writes it.

## Risks
- Tests that assert work-record keys or action-log rows after `work.start` may see the new fields or row. Run every test that references start.
- The fallback route reader scans the goal's log on each append when the key is absent. It is O(rows), per goal, and bounded by one goal's file. A ponytail comment will name the ceiling.
- Re-classifying after plan-review is allowed and recorded. The small-goal safety net is slice 11.
