# Research: #464 — session, claim and lock markers under .sdlc/state

Revision: origin/main 7eb25e6 (worktree `.sdlc/work/464`). Parent tracker #419; sibling slices #458 (per-goal state, incl. `agents/`), #457, #461 (merged), #459, #460 (in flight).

## Writers and owners (all Sigma Python, repo-local gitignored `.sdlc/state`; none under a host configuration root)
| Pattern | Writer | Lifetime today | Reclaim today |
| --- | --- | --- | --- |
| `claims/<goal>.lock` (+ `slack-cmd-<name>.lock`) | `loop._try_acquire_claim_lock` (flock, stamps the short-lived CLI pid) | file is NEVER deleted by production code | `loop.reclaim_stale_claim_lock` exists but has ZERO production callers (only tests) |
| `claims/<goal>.claimed` | `loop._ensure_claimed` (touch once, O(1) marker) | never removed (retention.py says so) | none |
| `sessions/<pid>[-<thread>].active` | `loop.session_start` (+ `.active.<pid>.*` temp) | removed by `session_end` | `loop._prune_dead_session_entries`, only from `_next()`/`next_batch` and the CLI `start` verb |
| `sessions/locks/<slot>.lock` | `loop._session_locked` | 256 fixed stripes, never deleted | bounded by construction |
| `phase-end-<stripe>.lock` | `state.phase_end_lock` | 256 fixed stripes (2 hex chars) | bounded by construction |
| `STATE.md.lock`, `merge-reconcile.lock`, `knowledge-sync.lock`, `feature-judge-spend.lock` | state / loop / sync / feature_judge (flock) | one file each, never deleted (deleting a flock file admits a second holder) | bounded: 1 file each |
| `slack-commands.lock` | `slack_commands_listen.acquire_single_instance` (a DIRECTORY, mkdir) | rmdir'd on release | reclaimed by the next acquire after a grace window (pid dead, heartbeat stale, or no pidfile past `_LOCK_RECLAIM_GRACE_SECONDS`) |

All the flock families release on any process death (kernel drops the lock), so a crash never leaves them READING as held; the leftover is only an empty (or pid-stamped) file.

## Measured (operator's real store, `.sdlc/state`, 2026-10-03; four days of use)
- `claims/`: 82 files = 47 `.lock` + 35 `.claimed`, 0-6 bytes each (the `.lock` carries the dead CLI's pid), mtimes 2026-09-29..2026-10-02; every one survives. About 20 files/day. 10x = ~200/day (73k files/year), 100x = ~730k/year; bytes stay near zero but inode count and `claims/` directory size do not (not measured: filesystem inode/dir-lookup cost at that count).
- `sessions/`: 4 `.active` (42-111 B), all 4 pids verified alive on this machine; `sessions/locks`: 38 of a 256 cap; `phase-end-*.lock`: 124 of a 256 cap, all 0 B; `STATE.md.lock`, `merge-reconcile.lock` present, one each.
- Scratch, real CLIs: (1) `loop.py start` under a real long-lived pid, then `kill -9` of that pid: the `<pid>.active` file survives on disk; `session_active` reads it dead immediately (never reads alive); it is removed the next time ANY `start` or `next` runs. (2) A pick's CLI wins the claim lock and exits: the lock file survives with the dead pid stamped; nothing ever removes it (`reclaim_stale_claim_lock` has no caller). Same observation on the real store: locks for goals 112, 194, 239, 317, 351, 353-356, 360-362 have no `.claimed` and belong to goals that did not finish.
- Not measured: inode/dir cost at 10x/100x on a real filesystem; a reboot (same mechanism as kill -9: flock dies with the process, files remain); a crashed phase-end holder mid-write.

## Decision per family
- `claims/<goal>.lock`, `slack-cmd-<name>.lock`: ADD a bounded dead-owner sweep (new `liveness_prune.py`); also harden the acquirer against the unlink race (verify the locked inode is still the path's inode).
- `claims/<goal>.claimed`: terminal-goal prune via #458's `goal_state_prune` (add the family); safe because `_ensure_claimed` on a missing marker re-reads the ledger and, finding the claim, only re-touches.
- `sessions/*.active`: existing reclaim cited; add the sweep as a second trigger (`record done`, operator CLI) so a machine that never starts another session still self-heals.
- `sessions/locks`, `phase-end-*`, the four singletons: bounded caps, documented; new tests prove kill -9 of a real holder never leaves a held lock.
- `slack-commands.lock`: existing reclaim, cited with its existing test and a control.
- Out of scope / not mine: `state/heartbeat/<session>.json` (loop heartbeat) is not in this issue's pattern list; stated in the doc.
