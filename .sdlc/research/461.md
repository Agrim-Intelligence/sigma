# Research: #461 — event journal, time store and ledger stream files (B6)

Base: origin/main 46940d9 (the revision that produces every store below). Worktree `.sdlc/work/461`.

## Which patterns the scan produces (measured)
- Ran the documented gesture to a scratch file: 174 unique unresolved patterns; all 18 patterns the issue lists are present
  as scan rows and unresolved (so an unknown-pattern refusal cannot hit this file; `unscanned: true` is not needed).
- `.sdlc/ledger/<stream>...` rows come from `ledger.entry_file`, whose `<stream>` is dynamic: `entries` -> `.sdlc/ledger/entries/`,
  `events` -> `.sdlc/events/` (since #2574; nothing writes `.sdlc/ledger/events/` any more, it is read-only legacy).
  So the `<stream>` rows are an over-approximation that spans both a pruned store and an unpruned one.

## Writers and ownership (all under the project `.sdlc/`, none under a host configuration root)
- `.sdlc/events/<actor>-<host>.<pid>.jsonl` + `.last-prune`: `ledger.append(stream=events)` (callers: loop, phase_report, work, drift/comment watch, scope assign). Local, gitignored. Pruner: `ledger.prune_journal` (30 d by file mtime, writer's own file never a candidate, links refused), driven by `_prune_journal_if_due` at the top of `append`, stamp inside the dir, no mkdir.
- `.sdlc/ledger/entries/<actor>-<host>.<pid>.jsonl`, `.sdlc/ledger/TEAM.md`: `ledger.append(stream=entries)`; `sync.py` stages them in the ops-branch worktree (git-tracked). TEAM.md is regenerated from entries (`sync.render_team`-style pure function; `recent=25` rows plus open hand-offs).
- `.sdlc/state/time/<goal>/<pid>.jsonl`, `_sessions/<id>/turns.jsonl|<pid>.jsonl`, `.last-prune`: `timing_store.append/append_session`. Pruner: `timing_store.prune` (90 d per goal/session on newest file, own `*.jsonl` only, links refused), `maybe_prune` 24 h stamp, called from every append.

- Not measured: a live adopter's ledger/entries file count (ledger is off on this checkout); entry rate per developer; network-mounted or spinning disks; Linux/Windows sweep time.

## Existing control coverage
- tests/test_ledger_prune.py (journal) and tests/test_timing_store.py (time store) already cover cutoff, own-file survival, goal with one recent file, never-delete-foreign-file, stamp throttle, future stamp, links, legacy `.sdlc/ledger/events` never swept.
- Nothing ties the 18 audit patterns to those pruners, so a deleted/renamed pruner would leave the disposition claiming a cap that no longer exists.

## Decisions to make
1. events + time patterns: `capped`, name the pruner.
2. ledger entries stream + `<stream>` rows: intentionally unbounded; ceiling = one ~180 B entry line per entry and one file per distinct writer process (host.pid) per actor, git-tracked on the ops branch; reclaim = a maintainer with push access to the ops branch; no automatic lever (a sweep would create staged deletions in a teammate's pull).
3. TEAM.md: derived (regenerated from entries, bounded view), not a store.

## Risks
- Disposition entries must carry exact scan pattern text (copy from scan, trailing slashes included).
- A claimed-but-idle goal (>90 d) loses only durations in time store; accepted, documented.
