# #1572 research: test_upkeep_agent_1516 fails without committer identity

## Root cause (measured)
- Reproduced: `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_SYSTEM=/dev/null` with GIT_AUTHOR_*/GIT_COMMITTER_* unset ->
  both tests fail with `level 2 refused (stamp-failed): Committer identity unknown`.
- SURPRISE (measured): they ALSO fail on this host, which HAS a global identity (`user.name=swapnil-agrim`), because the
  `wired` fixture (tests/test_upkeep_agent_1516.py:~37) does `monkeypatch.setenv("HOME", rig.tmp/"home")` (an empty dir), so git
  no longer finds `~/.gitconfig`. With `GIT_CONFIG_GLOBAL=$HOME/.gitconfig` both pass; with GIT_AUTHOR_*/GIT_COMMITTER_* env set
  all 31 tests in the file pass. So the issue title understates it: any host relying on a global config fails. (CI sets
  `git config --global` in .github/workflows/ci.yml:~48 under the real HOME; whether CI hits the same override was NOT measured.)
- Origin of the error: production `feature_upkeep_resolution.stamp_commit` (skills/sigma-loop/scripts/feature_upkeep_resolution.py:171)
  runs `git commit --no-verify --no-gpg-sign --author=<orig> -m ...` via the injected `run` (`feature_rebase._run`, inherited
  env). `--author` sets only the author; the committer comes from config/env. It is reported as STAMP ("stamp-failed",
  feature_upkeep_level2.py:75, :461-464). The other tests in the file / test_upkeep_level2 / level1 do not hit it only where
  the surrounding env or HOME still supplies an identity (they do not override HOME). Temp-repo commits in tests go through
  `test_feature_rebase._git` (lines ~71-75) and `test_upkeep_level1._commit`, which set GIT_AUTHOR/COMMITTER env on *their own
  subprocess env only* -- that is why test setup works but production code under test (committing with inherited env) does not.
- Production committing with inherited identity is correct (the engine's committer is "true", per docstring). Scoping it is a
  test concern only; do not change production.

## Minimal fix
In the `wired` fixture, after `monkeypatch.setenv("HOME", ...)`, write `rig.tmp/"home"/".gitconfig"` containing
`[user] name = t / email = t@example.com` (the fixture already owns that HOME; no process-global env, nothing leaks, autouse not needed,
tests/test_ledger_single_branch.py unaffected). Alternative: `monkeypatch.setenv` of the four GIT_COMMITTER_*/GIT_AUTHOR_* vars in the
same fixture (also test-scoped via monkeypatch). Prefer the .gitconfig (keeps `git config` semantic the production reads).
Control (acceptance 2): delete that write -> both tests fail with `Committer identity unknown`; run on the documented gesture
`python -m pytest tests/test_upkeep_agent_1516.py -q` under `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_SYSTEM=/dev/null` and env unset.
Do NOT set GIT_AUTHOR_*/GIT_COMMITTER_* globally (conftest/session) -- breaks tests/test_ledger_single_branch.py.
