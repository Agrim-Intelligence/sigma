# Research: #955 loop.py start resets the shared STATE.md run cursor under a concurrent loop
**Goal**: #955 · **Lane**: large · **Date**: 2026-10-10 · **Code read at**: `.sdlc/work/955` (5f25b99, origin/main, release 1.0.5)

## Goal in one paragraph
Every loop in one checkout shares `.sdlc/state/STATE.md`. `loop.py start` always calls
`state.start_run`, which overwrites the run cursor (`run_started_at`, `run_tokens`,
`run_codex_raw_tokens`, the three dedupe lists, `run_iteration`). README documents concurrent
sessions in one checkout as supported ("Multiple concurrent sessions register independently",
README.md:2124-2127), so a second session's `start` silently re-anchors the first session's run:
its verify evidence becomes "predates this run", its wall-clock and token budgets restart from zero,
and phases it started before the second start are never credited. Acceptance: `.sdlc/acceptance/955.md`
(AC-1 repro fixed and seen red; AC-2 no zeroing or inheriting of iteration/token/minute counters;
AC-3 single-loop path unchanged; AC-4 a dead prior session does not affect a new `start`; AC-5 full
suite through `loop.py verify`).

production admission.

## 2. Existing session machinery
- **Registry**: `state/sessions/<pid>.active`, or `<pid>-<CODEX_THREAD_ID>.active` on Codex (loop.py:2440-2446).
  JSON `{in_flight, settled_admissions, generation}`. Writes go through `_session_locked` (a 256-stripe
  flock, loop.py:2529-2584) and `_session_write` (atomic mkstemp+replace, loop.py:2613-2633).
- **`session_start`** (loop.py:2672-2739): creates or refreshes the caller's own entry. On a re-`start`
  with the same identity it PRESERVES `in_flight` and `settled_admissions`. It writes a heartbeat and
  returns the generation (random uuid, or the stored one when re-called without one).
- **`session_end`** (loop.py:2742-2770): deletes the marker and heartbeat only when the generation
  matches (#383). A bare end never deletes a successor.
- **Liveness** `_session_pid_live` (loop.py:2656-2669): `ledger.pid_alive` (`os.kill(pid,0)`,
  ledger.py:1911-1938; single-machine) first, then marker mtime < `ledger.lease_ttl_seconds` (12h
  default, ledger.py:536-542) as the pid-reuse backstop. The generation is ownership for cleanup, not
  liveness. A reused pid with a fresh mtime therefore reads live until the TTL.
- **"Another live session holds this checkout"**: only `session_active()` (loop.py:2773-2783, any live
  entry INCLUDING self) and the `session-active` verb (ACTIVE/FREE, loop.py:6185-6188), which the
  README routine runs before `start` (README.md:2136). `start` itself never consults it. Dead entries
  are pruned at `start` (loop.py:6155) and on every `_next` (`_session_in_flight_goals` loop.py:2844-2862).
- **Goal → session mapping already exists**: a goal claimed by `_next`/`claim` is added to the claiming
  session's `in_flight` (`_claim` → `_session_claim`, loop.py:1759, 2965-2995). It leaves at `_record`
  and `_release` (`_session_release` loop.py:2998-3045; called at loop.py:4346, 3936, 4480). `_ensure_claimed`
  (the /sigma-goal arming path) passes no session_pid (loop.py:1890), so such goals are in no `in_flight`.
- **Run id**: `_arm_run_id` (loop.py:5452-5479) runs only on `start`/`next`/`next-batch`/`claim`.
  `verify` and `record` do not arm it, so interactive evidence carries `run: None` and record compares
  None == None. Under `supervise_daemon.py` `SIGMA_RUN_ID` is exported per worker (supervise_daemon.py:145-160).

## 3. Verify evidence stamping and the freshness guarantee
- **Stamp** (loop.py:5396-5401): `{command, exit, acceptance_sha256, verify_state, at: time.time() (float),
  run: run_identity(), pid: os.getpid(), root, head, content{fingerprint,…}, test_first, …}`. No session
  key and no run-start copy.
- **Check order** (state.py:1211-1303): no file → unreadable → `exit != 0` → **`at < load_cursor()["run_started_at"]`
  → "verify evidence predates this run"** (strict `<`, float; equality is accepted) → run-id mismatch (#498)
  → acceptance hash (#1897) → content fingerprint (#1897).
- **What it is FOR**: "a stale green from yesterday proves nothing" (state.py:1212-1214). The F11/#341
  sub-second fix (state.py:1226-1232, 447-459) is pinned by `test_done_refusal_rejects_sub_second_stale_evidence_…`,
  `…_accepts_evidence_a_fraction_of_a_second_after_run_start` and `…_boundary_at_exact_equality_is_still_accepted`
  (tests/test_state.py:321-405). The original introduction predates history: the `git log -S"predates this run"`
  root is `d378333 public snapshot`. #498 then added run-id attribution for CONCURRENT siblings, but it did not
  move the freshness anchor. That gap is this bug.
- **Per-goal claim time**: none usable (see the claim table). The usable per-goal-per-session fact is
  membership in a live session's `in_flight`.

**Recommendation.** Extend the per-session marker, which since #2521 already holds the session's
goal-count budget, with a `run` block: `started_at`, `tokens`, `codex_raw_tokens`, `token_credits`,
`codex_token_credits`, `phase_ends`, each list keeping the 4096 cap. Every `start` path (BR-2/4/5,
through ONE shared helper) stamps it with the same `now` it writes to STATE.md. STATE.md is still
reset exactly as today, so the single-loop path and the global fallback do not change.
- Session-scoped readers (`_next`, `next_batch`, `_reserve_goal_slot`, `_emit_run_stop_once`) read
  their own `run` block, falling back to global when the marker has no block (legacy or library callers).
- Goal-scoped readers (`done_refusal`, `record_phase_end`, goal-bearing `add_tokens`) resolve the
  goal's **live** owner(s) from `in_flight`. Freshness anchors to the owner's `started_at`, the max if
  several. With no live owner, the anchor is global STATE.md, as today. Credits go to the owner's block
  and to global.
- Unattributed spend (`spend` with no goal) credits every live session's block as well as global.
  This over-counts rather than under-counts.
- `start-run` gains an optional `--session-pid` that resets that session's block only when its marker
  already exists. It never creates one.
- Optional: one stderr line at `start` naming the other live sessions. Never stdout, never a refusal.

**Must NOT change:** `start` stdout (the bare generation line: SKILL.md:30, README.md:2139,
tests/test_loop.py:7732); `start` exit codes 0/1/2; the refusal strings and done_refusal's check
order; the float strict-`<` freshness compare; the STATE.md fields and values `start_run` writes;
per-session admission semantics (#2521); `_cursor_lock`'s no-nesting rule (state.py:395-399, so
session-side writes must be sequential, never nested); `session-end` generation ownership (#383);
"absent/zero budget key enforces nothing"; `record_phase_end`'s return tuple (phase_report.py:2000).

## Constraints & unknowns
- Unverified: the pid-reuse residual. If an owner's pid is reused by an unrelated process, it reads
  live until the 12h lease TTL. Its old `started_at` would then anchor freshness, and a green from that
  dead run would be accepted where today's global anchor refuses it. This is bounded by the TTL and by
  the #1897 content fingerprint. Not measured.
- Unverified: marker size at the 4096-attempt cap. About 340 KB was measured for STATE.md
  (docs/launch/dispositions/466.json:41) but not for markers. `_session_entries` parses every marker on
  every `_next` and release. A typical handoff-capped session (20 goals × ~7 phases ≈ 140 attempts) is
  ~4-5 KB, so 30 sessions ≈ 150 KB parsed per pick. The cap case should be measured or kept out of the hot scan.
- Unverified: whether Claude subagents share the orchestrator's `$PPID` (picking.md:116-121 claims
  this is measured). Not needed: the recommended design resolves ownership by goal, not caller pid.
- Blocking: none. AC-2's "neither zeroes nor inherits" already decides per-session budgets over a
  checkout-wide pool. Consequence to state in the docs: N concurrent sessions may spend N × each ceiling,
  the same as N sequential runs.
- Non-blocking: where the registry read primitives live (D-5); whether `start` should print a stderr
  notice listing the other live sessions; crediting a goal held by two live owners (all of them, which
  is conservative, vs newest); whether the goal-scoped credit is written session-first or global-first.
  The two locks must stay sequential, and per-block dedupe lists make a retry self-heal.
- North star: `north_star.py` → `absent`, so it was skipped.
- Not done here: the `loop.py note` phase note (`note` arms a claim; the caller ruled this phase
