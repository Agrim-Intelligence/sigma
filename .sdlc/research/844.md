## 1. Current behaviour of `skills/sigma-loop/scripts/breaker.py` (148 lines, stdlib `re` only)

Public functions: `acceptance(issue_body)`, `actionable(items)`, `scrub(text)`, `brief(issue_body, interface)`,
`no_channel(brief_text, scratch_paths)`. Module regexes: `_SECTION`, `_BULLET`, `_VAGUE`, `_CONCRETE`, `_PATH`, `_LEAK`.

Measured facts:

- `_SECTION = ^##+\s*(done_when|judged_when)\s*$` (case-insensitive, `##+` so level two and deeper). A body with
  `## Done when` (space, as every goal issue and `acceptance.py` use) gives `breaker.acceptance(body) == []`.
  `brief(body, "f(x)->bool")` then returns `(False, 'no done_when/judged_when list at all -- nothing for a breaker
  to attack')`. This confirms design PC-1. The same body with `## done_when` returns all 3 bullets.
- `acceptance.criteria` on the same 3-bullet `## Done when` body returns the 3 bullets. It requires 3-7
  statements of at most 1024 chars, raises ValueError otherwise, and skips fenced blocks. It returns `None` when
  the heading is absent. `breaker.acceptance` today has no count limit and does not skip fences (its `_BULLET`
  accepts `[ ]`, `[x]` or `[]`, and also `- ` without a checkbox is NOT matched; `acceptance.criteria` accepts
  an optional checkbox).
- `_LEAK` (used by both `scrub` and `no_channel`) alternates: diff headers (`diff --git`, `index <hex>`,
  `--- a/`, `@@ `), any line starting with `+` or `-` (not doubled), and the substring alternation
  `\b(def |class |import |return |self\.)` anywhere in a line. Measured `scrub` results:
  - blanked (wrongly, for criteria prose): "the CLI must return 0 on success", "it must import cleanly",
    "a class of errors is rejected", "the import step returns 3", "exit status 2 when self.x is unset".
  - kept: "returns False for negative age" ("returns" has no `return ` followed by a space), "imports nothing".
  - blanked (intended): `    self.x = 1`, `- foo`, `+x`, an absolute filesystem path (the `_PATH` rule).
  So the design's PC-1 claim (AC text containing `return ` is blanked) holds for the singular "return " and
  for "import ", "class ", "def ". Note `brief()` calls `scrub(i)` on each bullet, so a blanked criterion
  becomes an empty `*` bullet and the list still counts as actionable (silent loss).
- `actionable(items)` returns `(False, "no done_when/judged_when list at all ...")` for an empty list, and
  `(False, "... PLAN-phase defect ...")` only when EVERY item is vague/unobservable
  (`len(unattackable) == len(items)`). One concrete criterion makes the whole list pass. Confirms PC-8: no
  per-criterion verdict exists. The unattackable test is `_VAGUE.match(i) or not _CONCRETE.search(i)`.
- `brief()` uses `*` bullets on purpose (a `-` bullet would trip `_LEAK`'s diff-line arm via `no_channel`).
- `scrub` cost: 1000 lines in about 0.13 ms per call (measured with timeit, 20 runs). Linear in lines.

## 4. `acceptance.criteria` semantics: import vs duplicate

`acceptance.criteria(text)` is strict: level-two `## Done when` (regex `##\s+Done when\s*`, case-insensitive,
fence-aware), 3-7 single-line checklist items, raises ValueError on malformed content, `None` if no heading.
Siblings are imported by path with a local `_load(name)` using `importlib.util.spec_from_file_location(name,
pathlib.Path(__file__).with_name(name + '.py'))` (acceptance.py lines 22-24; reviewer.py lines 52-58 does the
same). So breaker.py can load acceptance the same way (same skill, so legal under the north-star rule quoted in
reviewer.py's `_load` docstring) rather than duplicate the parser. Design questions for PLAN:
- Reuse means the strict 3-7 rule and ValueError reach `breaker.acceptance`; the issue's acceptance record says
  "returning the same bullets acceptance.criteria returns". Plan must decide: catch ValueError and fall back to
  the lenient legacy scan, or let it propagate. `breaker.acceptance` today never raises; callers (`brief`)
  assume that. Recommendation: reuse `criteria` for the `Done when` path, catch ValueError into the legacy
  scan result (UNMEASURED which is less surprising), keep the done_when/judged_when path as is.
- `acceptance.py` imports `state`, `sources`, `frontmatter`, `ledger` lazily inside functions, so loading it for
  `criteria` only costs a module exec of acceptance.py (UNMEASURED; criteria itself is pure).
- Do not call anything in acceptance.py that mints positional ids; verdicts must not carry ids.

## 6. Output contract and validator: what exists to build on

`ast.parse` is already used elsewhere (`skills/sigma-loop/scripts/witness.py`, `skills/sigma-doctor/scripts/
enforcement_table.py`), so no new dependency. The validator input is the breaker's raw text. The contract (to be
fixed at PLAN) needs: a block delimiter grammar (for example a header line naming a path, and an end marker),
path rule (relative, under `tests/acceptance/<stem>/`, no `..`, no absolute, no symlink semantics since it
validates strings only), `.py` only, `ast.parse` success, at least one top-level `def test_*` (module-level
function; decide whether class methods count), and no repo-internal import at module top (define "repo-internal"
as an import whose root is in the repo's script/package set or a relative import; UNMEASURED how to enumerate
without false rejects; lazy imports inside functions are allowed). Returns `(ok, findings)` as `no_channel` does.
Findings should be a list of strings; file count and bytes must be bounded (see scale).

## 8. Risks

1. Over-narrowing `_LEAK`: the module exists to keep implementation out of the brief. Rule of thumb for PLAN:
   remove prose-word triggers (`return `, `import `, `class `) and keep code-shape triggers (`def name(`,
   `class Name:` / `class Name(`, `import x` at line start, `from x import`, `self.attr`, assignment/colon
   forms, diff lines, absolute paths). A criterion pasted as code (`return 0 <= age <= 120` at line start) must
   still be removed; prove with a red control.
2. `_LEAK` is shared with `no_channel`, which is a different job (whole-brief check): changing it changes the
   finding for any brief reviewer.py inspects, but reviewer discards that finding. `no_channel` still needs
   to flag diffs, absolute paths and self-attribute code (acceptance record criterion 3).
3. Silent blanking: today a scrubbed-to-empty criterion still produces an empty `*` bullet and an "ok" brief.
   A per-criterion verdict should surface this (a criterion that scrubs to empty is not attackable).
4. Heading repair must not change `acceptance()` results for existing `done_when`/`judged_when` bodies (tests
   above) and must not raise.
5. Shipping ids by accident: verdict dicts must carry exactly the criterion text, `actionable` bool, `reason`;
   a test should assert there is no `id` key and the module text states classification waits on issue 535.
6. Adversarial inputs to the validator: path escape (`../`, absolute, `tests/acceptance/other/`, case-folding,
   backslashes, NUL), duplicate paths across blocks, huge blocks, unterminated block, non-UTF8, Python that
   parses but defines `test_` only as a nested function or in a string.
7. Guard-red rule (AGENTS.md): every new guard needs a deliberately broken run; the documented invocation (if
   any doc shows a call) must be the one exercised.

## 9. Scale (AGENTS.md)

- `scrub`/`_LEAK`/`_PATH`/new verdict function: linear per criterion; measured scrub 0.13 ms per 1000 lines;
  the Done when list is bounded at 7 by `acceptance.criteria` (legacy path unbounded). At 10x and 100x
  criteria it stays linear and sub-millisecond for 100x (extrapolated, UNMEASURED beyond 1000 lines).
  Regex backtracking on `_VAGUE` is bounded by `[^.]{0,40}`.
- Validator: per-block cost is `ast.parse` over the block (linear in size, unmeasured). Needs an explicit cap
  on blocks and total bytes (value to be derived at PLAN; the repo's convention is derived limits, not
  constants) so a runaway breaker output cannot stall the loop. No lock, no shared state, no writer.
- No background process, network, quota or file write: nothing in SAFETY/LIVENESS is touched. Recovery: pure
  functions, idempotent, nothing to recover.
