# Research: Park a goal whose required metrics got worse, behind an opt-in gate
**Goal**: #1637 (PRD-0008 R-02) · **Lane**: large · **Date**: 2026-10-17 · read at 0c64f170

## Goal in one paragraph
With `gates.quality_ratchet.enabled` true (default off), `work.py merge` runs the R-01 measurement on its unattended landing path, outside `gate()`'s REST wait. A `required` metric that is `worse` beyond its `tolerance` is measured at the head a second time, and the goal parks only if both readings are worse. The park text carries `failing_check`, the metric, base and head. A `required` metric that reads `unmeasured` parks. A non-required one is recorded and the merge goes on. A waiver is a create-only record bound to goal + metric + head sha. It is an audit trail, not an access control. The gate gets an `ENFORCEMENT_GATES` row and a regenerated `docs/enforcement.md`.

## Constraints & unknowns
- **Host-agnostic (C-2):** everything runs in `merge()` Python. No hook carries it.
- **Opt-in (C-4, AC-2):** with the flag false, quality_delta is never loaded or called. Test with an injected runner that counts 0 calls. Commands come from the merge-base config (quality_delta.py:409-426). The flag is read from the operator's local config.
- **RESILIENCY:** a non-required `unmeasured` is recorded and the merge continues. A whole-run `unmeasured` (no record, `base_resolved` false, wrong worktree, memory floor, live scratch owner) parks only if some metric is `required`. A refusal (exit 2, malformed `quality`) must park, not crash `merge()`; it can never pass silently (C-7).
- **SAFETY:** no gh calls (no new ratchet site). Import `_load("quality_delta").measure(goal, cwd=rec["worktree"])`, not a subprocess. It has its own bounded git (30 s / 600 s), memory probe, credential-filtered env and group kill, plus injectable seams (quality_delta.py:456). An extra interpreter would add nothing bounded.
- **Scale ceiling (state it in the row):** per required metric, worst case ≈ 3 × (timeout + 2 s) plus 2-3 scratch worktree adds (≤600 s each). At the default 300 s that is ≈906 s of commands per required metric, in series, on top of `merge()`'s documented 22.5 min. One required metric at defaults can double the tool-call timeout the SKILL prescribes. Fleet-wide serial cost is unmeasured (PRD).
- **Dirty worktree:** quality_delta returns `unmeasured` on any untracked non-`.sdlc` file (497-500). Artefacts the verify run leaves behind would park every required metric. Unverified on a real project.
- **Concurrency:** scratch paths are per goal. A second concurrent `merge` of the same goal abstains (live owner), so it reads unmeasured and parks if required. That fails closed.
- **Tolerance semantics:** worse-beyond-tolerance means `delta > tol` for `lower` and `-delta > tol` for `higher`. With tol 0 any worse reading parks. Tolerance is read from the merge-base config. Percent vs absolute (PRD D-2, open): absolute is the default.
- **Waiver:** valid iff goal stem, metric name and `head` == the measured head all match. A new commit gives a new head, which voids the old waiver (AC-5). Write it create-only, bounded reason, control chars stripped (reviewer.py:714-716). Log it to the action log. Not authenticated: a maker can call it, as with accept-inline.
- **Python 3.9 / planned-test proof:** /usr/bin/python3 3.9.6. `## Tests` lists only new nodes, each seen red by AssertionError. Fixture repos use maintenance.auto=false and gc.auto=0. Run the test_work* suites one file at a time.
- North-star: `north_star.py` → `absent`, so skipped.
- Blocking: none.
- Non-blocking: (a) placement after `vetted_head` (recommended) vs before `gate()`. Before `gate()`, a BEHIND rebase changes the head after measuring. (b) a new gate kind vs `gate="merge"`. (c) whether `auto_merge: off` should still measure (recommend no). (d) the waiver verb's name and store path.
