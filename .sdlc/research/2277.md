# Research: kg.py freshness: report the graph's build commit and how far behind it is
**Goal**: #2277 · **Lane**: small · **Date**: 2026-11-27

## Goal in one paragraph
Add a read-only `freshness` verb to `skills/sigma-kg/scripts/kg.py`: a `freshness(sdlc_dir, repo_root=None, run=None)` function returning exactly seven keys (`enabled`, `holds_code`, `built`, `built_at_commit`, `ancestor`, `commits_behind`, `changed_files`), reading the graph file's last 64 KiB for `built_at_commit` (hex-validated, 40 or 64 chars) and its first 1 MiB for a code node, then asking git (commit always after `--end-of-options`) whether that commit is an ancestor of HEAD and how far behind it is. CLI prints one sorted JSON line, exit 0. New test file `tests/test_kg_freshness.py`; one CHANGELOG bullet. Slice 1 of epic #2276; `reuse.py source` (slice 4) consumes it as a subprocess.

- Unverified: no real `graphify-out/graph.json` exists on this machine to measure; head/tail bounds are taken from the builder source, not a sample file.
- Non-blocking: `_state_guard` (kg.py:819-820 → state.py:335-343) exits 2 before `main` if `.sdlc/state` or `.sdlc/journey` is a symlinked tree. FR-1/§6 say "exit 0 in every case". Recommend leaving the guard as is (it is a pre-existing safety refusal, and the brief says not to change existing behaviour) and documenting the exception; planner decides.
- Non-blocking: the brief says only exceptions null a git key. A non-zero `rev-list`/`diff` exit (e.g. 128) should also give `None` rather than `int("")` raising — plan should state it.
- Non-blocking: graphify's `indent=2` output means the node scan must let `[^{}]` span newlines (regex `\{[^{}]*\}` does; a line-based scan would not).
- Non-blocking: head decode at a 1 MiB cut may split a UTF-8 sequence — decode with `errors="ignore"` as the tail read does.
- Non-blocking: open issues #2123 (graph freshness) and #2127 (graph refresh) overlap in theme; design D-4 says neither blocks this.
