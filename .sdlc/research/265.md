# #265 research

## Existing seams

`loop.py` owns managing-session identity and the atomic `state/sessions/<identity>.active`
registry.  The ledger watcher already demonstrates the intended liveness rule: age, rather than an
old success status, distinguishes a live daemon from one that died.  `hooks/session_start.sh` is an
accelerator only; it must leave the Python-owned session state as the load-bearing source.

`phase_report.py` receives the same `--pid` used by the documented phase gesture, so it can refresh
the managing-session heartbeat at phase boundaries without a host hook.  `log.py slots` and
`agrim-status` are the two human-visible status surfaces.

## Design

Store one atomically-written JSON heartbeat per session at
`.sdlc/state/heartbeat/<session-marker-stem>.json`.  It contains the session PID and `last_seen`.
The session marker remains the authoritative declaration that a loop exists; a heartbeat is merely
its freshness signal.  Start and every phase boundary refresh it; a clean session end removes it.
A crash leaves both evidence files behind, which a later session-start hook can report.

The stale bound uses the existing watch interval convention: `max(3 * interval, 180)` with a
default interval of 900 seconds.  This is configuration-free for a stock install and follows the
existing watcher math where an installation has chosen a different watch interval.

The deterministic dead-loop control writes a stale heartbeat for an impossible PID alongside its
session marker and invokes the real SessionStart hook.  It exercises the user-facing gesture and
does not signal, suspend, or kill a process.
