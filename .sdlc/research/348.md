# Research: #348 crash, restore, and lost-ack drills

## Measured seam

The documented recovery gesture is `python3 skills/sigma-loop/scripts/loop.py
reconcile-merges <dir>` (`loop.py:5744-5757`, `6134-6141`).  Its implementation is
`_reconcile_awaiting_merges` (`loop.py:4009-4094`), which reads only work records
whose `awaiting_merge` flag remains present.  For an observed merged PR it calls
`work.done_refusal`, then `_record(..., "done", merged_pr=True)`.  The function's
own crash-safety contract is therefore the D3 seam: a kill before `_record` must
leave the flag for the next recovery pass, while a kill after `_record` must not
record completion twice.

The existing hermetic end-to-end GitHub fixture is not duplicated.  The stateful
fake is the `_FAKE_GH_BODY` literal in `tests/test_public_bootstrap_control.py`
and is extracted by `tools/onboarding_control.py:_fake_gh_body`.  The latter
already builds a local bare remote and fake-GitHub environment, drives one goal to
an open PR, performs `gh pr merge`, then invokes the exact documented
`reconcile-merges` gesture (`tools/onboarding_control.py:697-824`).  The new drill
tool can extract that same fake body and must reject unmodelled calls rather than
fall back to the host `gh`.

## Constraints

* The public tool is stdlib-only, POSIX-only for process-group drills, and writes
  only below its supplied work directory.
* Tests must be hermetic; the fake `gh` unhandled log is an invariant, not an
  informational artifact.
* Each D1--D4 seed must state every invariant in JSON, including a precise
  `skipped` reason on Windows rather than an apparent pass.
* Evidence is generated after implementation using the committed tool and named
  with the measured commit SHA.  It cannot be manufactured from unit-test output.
* D4 is a diagnostic drill: the result must distinguish a deliberately stopped
  watcher from dead and idle, and must report whether the stop-file cleanup is
  documented.  It must not delete a stop file outside its scratch repository.

## Existing kill helpers

`tests/test_feature_rebase.py:1019` uses `os._exit(9)` to model abrupt process
loss, and `tests/test_run_with_timeout.py` exercises POSIX process-group cleanup
as well as the Windows-specific path.  The drill should use a spawned child
process group, never signal the test process or a shared watcher.
