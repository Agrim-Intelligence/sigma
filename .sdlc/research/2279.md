## Goal in one paragraph
Extend `reuse.py check-research` so that a research dossier in the new format (`is_new_format`: a `## Reuse`
section carrying `**Source:**` or `**Searched at:**`) must also carry a `**Risk**:` header line above the first
`## ` heading (values `none`, or any of `sensitive`, `contract`, `migration`, comma-separated, `none` alone) and a
`## Test design` table with the exact header `| Criterion | Behaviour | Failure path | Hostile input | Helpers |`,
a separator, and exactly one row per acceptance-criterion id from `review_tests.criteria`. Row rules: Behaviour
not empty and not a dash; Failure path a case or `none:` plus three words or more; with `sensitive`, at least one
Hostile input cell is a case. No acceptance record: one error when `verify.enforce` is on, else one warning and the
per-criterion rule is skipped. Legacy dossiers stay unchecked. Three new functions (`parse_risk`,
`parse_test_design`, `test_design_errors`), wired into `_check` after the `## Reuse` checks; `check_research`'s
return shape and the CLI arguments are unchanged; the success line gains `## Test design` and `<k> criteria`.

## Hostile-input shapes the new parsing adds
Measured on Apple M4 Pro, Python 3.12, with the reused pieces only (`_section_lines` + `_CELL.split` + a
first-heading Risk scan), 1 MiB inputs: many rows (38,833) 0.029 s; one 1 MiB cell 0.008 s; one row of 1 MiB of
pipes 0.041 s; 524k short lines above the first heading 0.058 s; a Risk line of 1M commas 0.013 s. The new rule
code is unmeasured (not written yet); Plan must time it per shape.

- **Many rows**: coverage, duplicate and unknown-id checks must use sets/dicts (one lookup per row), never a scan of the criteria list per row.
- **One very long cell / many pipes in one row**: word counts via `str.split()` are linear; a wrong cell count should skip that row's cell rules (the `table_errors` precedent at reuse.py:212-214).
- **Risk value of many commas** (`**Risk**: ,,,,…`): one error per bad value would build ~1M strings; Plan should bound it (one error for the line, naming at most a few values with `%r`).
- **Many short lines above the first heading**: the Risk scan must stop at the first `## ` and be one pass.
- **Untrusted text echoed into errors**: criterion ids from rows and Risk values reach the terminal; echo with `%r` (escapes C0/C1, as `table_errors` does at reuse.py:208, 219).
- **Ids**: `ac-1`, `AC-01`, ` AC-1 ` (strip only), duplicates (`AC-1` twice), ids not in the record; criteria themselves can repeat an id (an explicit `AC-2:` at position 1 and a plain bullet at position 2), so coverage is by set.
- **Fences**: a `## Test design` heading inside a fence does not count (`_section_lines` already); a `**Risk**:` line or a `## ` line inside a fence above the first real heading is unspecified (Non-blocking Q3).
- **Table shape**: rows before a separator, a second table later in the section (all `|` lines merge, as in `parse_reuse`), a line without a trailing `|` (last cell dropped by `[1:-1]`), escaped `\|` kept in a cell.
- **No-record path**: costs one `git show` per ref via `_branch_doc` (timeout per call); a corrupt config or a non-dict `verify` raises (Non-blocking Q1).
