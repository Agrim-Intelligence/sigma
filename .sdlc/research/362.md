# Research: #362 hostile-input fixtures and the injection drill

Read at origin/main 12bd9f6.

## Parsers that read untrusted text, and their public entry points

| Surface | Entry point | Documented behaviour |
|---|---|---|
| Blocker edges, fetch time | `mirror.normalize_issue` -> `blocker_scan.extract_refs` | scrubbed body scanned in full; only the first `#N` after each explicit trigger registers (compile_plan docstring) |
| Blocker edges, check time | `blocker_scan._BLOCK_RE` | same shape, full trigger set, advisory unless explicit trigger |
| Unit declaration | `features.read` / `features.parse_body` | docs/branching-model.md 4a: bare marker only; fenced, comment, indented, quoted: nothing; `_UNIT_RE` rejects `/` and `..` |
| Comment notification | `comment_watch.tick` | writes one `note` ledger entry per new foreign comment plus a cursor; nothing else |
| Slack command | `slack_commands_listen.parse_command` / `handle_message_event` | structured grammar via shlex; unknown or malformed text refused with a reply, never executed |
| Redaction | `mirror.normalize_issue`, `actionlog.append`, `ledger.safe_append` | secret-shaped text scrubbed before it is stored or logged |
| Block A titles | `render.render_status`, `log.slots` | render refuses a title holding ` · `, a control character or a marker glyph; slots must still build the block (open issue 190) |

## Findings so far (measured by prototype at that sha)

1. `blocker_scan` is blind to markdown structure. A `Blocked by: #7` inside a fenced block or an HTML
   comment registers as an edge (`extract_refs` returned ref 7 for both). The unit parser, by contrast,
   ignores both constructs as documented. Edges drive `blockers.resolve`, which can grant `sdlc:goal` to a
   third issue (assigned to someone else, or carrying a Sigma provenance label) and comment on it.
2. The check-time scan reads comment text with no author filter (`backlog_check._fetch_scrubbed_comments`),
   by design: a human commenting a dependency is a documented feature. In a repository open to outside
   commenters that is a drive-by edge-minting surface. Not a code defect against its docs; a threat-model note.
3. `log.slots` with a goal title containing ` · ` degrades the whole Block A to an unconstructed notice
   (open issue 190). Same shape for a title holding a control character.
4. H04 (comma-joined numbers) behaves as the compile_plan docstring says: only the first registers.
5. 1 MB bodies: `normalize_issue` 0.2-0.4 s, `features.read` under 1 s on the worst shapes tried
   (repeated unterminated Q&A start markers 0.9 s, the linear-scan fix of 1498 holds). No exception.
6. `scrub` redacts a 40-character `gh*_` token in a title and body; `actionlog.append` redacts it in a note.

## Write-surface and structure constraints

- `tools/readiness/write_surface.py` ratchet (tests/test_write_surface.py) will see any `gh api -X POST`
  and file write in a new tool; the inventory in docs/launch/write-surface.json needs matching entries.
- tests/test_no_private_names.py and tools/leak_scan.py scan tests/ and tools/: fixtures hold no literal
  token; the token is built at run time. Control characters are written as escapes in the fixture and
  decoded by the test, so no fixture holds a NUL byte.
- The blast-radius drill repository convention (`sigma-drill-` prefix) is not yet in the tree; this tool
  defines the refusal itself.
