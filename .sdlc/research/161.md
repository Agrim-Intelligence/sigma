# #161 research — port the predecessor's #2756 (rebase upkeep keeps merge landings; `ack` exit)

(+203), `rebase_brief.py` (+2), `docs/branching-model.md`, three test files, a changelog fragment.
Name map: `sdlc-X` skill -> `sigma-X`, product name -> Sigma.

## What the upstream change does
1. `_rebase_feature` and `rebase_brief.attempt_rebase` run `git rebase --rebase-merges`, so a
   `Merge pull request #N` landing is recreated instead of flattened onto the first-parent line
   (where `direct_commits` then refuses it forever).
2. `feature_rebase.py ack <sdlc_dir> <unit> (<sha>...|--all)` writes
   `.sdlc/features/rebase-acks/<unit>.json` (tracked; keyed by patch-id; also read from
   `<remote>/<base>:<path>`). `_rebase_pass` subtracts acked commits from `direct_commits`.
3. `_direct_body` / the DIRECT_COMMITS clause name the ack exit; `_report` gains `acked`.

## Where Sigma differs (blast radius)
- Sigma main carries #144/#278's data-loss guard, which the upstream lacks: `dropped_paths` in
  `_rebase_feature` between the replayed head and `_pushed` (WOULD_DROP), `own_losses`, and
  `rebase_brief.push_branch` as the single push chokepoint (`attempt_rebase` -> `_would_lose` ->
  `push_branch`; `conflict_walk` pushes through `push_branch`).
- Sigma's `main()` uses a `USAGE` constant (upstream prints inline) — expected refactor diff.
- Sigma's `_report` also has `dropped`, `dropped_count`, `would_be`; `clause()` has `dropped`/`named`.
  Union merges in both.
- `_FOLDS` in `tests/test_feature_registry.py` needs `ack_path` (Sigma already has `blocked_path`).

## Composition analysis
- Order in Sigma: `_rebase_pass` -> [direct-commit check, now minus acks] -> `_rebase_feature`
  -> replay -> `dropped_paths` guard -> `_pushed`. The ack acts BEFORE the replay (a precondition),
  the guard AFTER it and before any push. So an ack can only let the pass reach the guard; the
  constant comment on `WOULD_DROP` already requires any acknowledgement lever to sit inside it.
- `--rebase-merges` vs the guard: `dropped_paths` compares trees `before`..`after` (shape-agnostic)
  and `_history_blobs` reads `before`'s history with `git log -m`, so merge results count.
  `own_losses` (b) excludes merges (`--no-merges`), which only fails closed. `rebase_stopped`
  checks `rebase-merge/` — the backend `--rebase-merges` uses — so CONFLICT vs FAILED is intact,
  and `conflict_walk` continues/aborts the stopped rebase the same way.
- `ack()` fetches and writes a file; it never rebases or pushes.
- The ack file lives under `.sdlc/features/rebase-acks/`; the registry only globs `units/`, so no
  reader mistakes it for a unit.

## Risks
- A base that copies + reverts a merge landing's content: `--rebase-merges` drops the upstream-
  equivalent side commits and the replay loses the content — measured destructive without the
  guard (sensitivity test), refused with it.
- `git patch-id` via `subprocess` (not the injected `run`): same as upstream; failure -> "" -> not
  acked (fails towards refusing).
- Portability: all fixtures are pure `git` argv, no shell; paths via `pathlib`/`as_posix`.
