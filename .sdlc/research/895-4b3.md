## 1. What the old code got wrong (found by reading, then pinned by tests)
- `_retry_gh` re-sent a non-idempotent merge/close. The "recheck" then read an EMPTY open-PR list as proof the
  first attempt landed; a PR closed by someone else, or a degraded empty list, read as "merged". `_find_design_pr`
  already refuses a malformed list (gh_api raises), but the inference itself conflated merged/closed/gone.
- The merge carried no head pin: it merged whatever the head was, not the files the identity check vetted.

## 2. Design
- Rows from `open_prs_for_head_gh` gain `headRefOid` (REST `head.sha`; fallback `--json ...,headRefOid`, key
  required there). `merge_design` passes it to `gh_api.merge_pr_gh` (4b-1; REST PUT with `sha`, ONE `gh pr merge`
  fallback on a primary rate limit while GraphQL is available, `outcome_unknown` on every exception).
- New `gh_api.close_pr_gh`: comment first (`comment_pr`, non-idempotent), then `PATCH pulls/N state=closed`
  (`_rest_write(idempotent=True)`; 5xx may fall back to ONE `gh pr close`). Success only on `state == "closed"`.
- Reconcile by a REST read of the PR (`view_pr_gh(["state"])`): MERGED / CLOSED counts, nothing else does.
  Definite refusals (`outcome_unknown is False`) skip the re-read. No retry anywhere.
- Strings returned keep the `could not merge|close PR #N` / `merged|closed PR #N` prefixes; no gh text embedded.
