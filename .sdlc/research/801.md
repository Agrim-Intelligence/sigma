# Research: run /sigma-loop in Claude Code cloud sessions (REST-first gh, GraphQL capability check)
**Goal**: #801 · **Lane**: large (whole goal) / medium (proposed slice 1) · **Date**: 2026-10-09

## Goal in one paragraph
The Claude Code cloud GitHub proxy rejects all GraphQL, so every `gh issue|pr|project` call fails. The issue asks for REST as the primary path, one startup capability check (no per-call retry), doctor/status reporting, board mirroring skipped with one notice, and a test that stops new `gh issue|pr` calls outside a shared helper. About 295 sites in 45 files is too big for one PR, so this phase proposes slice 1 and the follow-ups.

## Constraints & unknowns
- Verify command (from main repo `.sdlc/config.json`; the worktree has no gitignored config): `$HOME/.sigma-venv312/bin/python -m pytest tests -q -n 4 -p no:cacheprovider`, enforce true.
- AGENTS.md five properties:
  - RELIABILITY: no "works in cloud" claim until run in a real cloud session. The acceptance bullet "drains a backlog in a cloud session" cannot be met by slice 1 and must say so.
  - SAFETY: the probe is one bounded read-only call, with no background process, no retries and no quota use unless the operator opted in. The capability cache lives under `.sdlc/state/`, with no secrets. On an unsupported path, REFUSE LOUDLY (a clear "not supported here"), never proceed weakly.
  - LIVENESS: doctor and status must name "GraphQL unavailable" and the features that are off. A silent degraded mode is the failure to avoid.
  - RESILIENCY: the cache needs a TTL and a re-probe lever. The cloud proxy can change per session and the check is startup-only, so key the cache by the `CLAUDE_CODE_REMOTE` value and a timestamp. A stale "unavailable" must self-heal.
  - SCALABILITY: the probe is O(1). The REST list is O(pages). State the cap and the 5000 core/hour rate limit versus the `graphql` budget (REST is cheaper per call, already measured in #1829).
- Run the control (AGENTS.md): break the ratchet by adding a new `gh issue list` in a non-allowlisted file and see it RED, using the gesture the docs give (plain `pytest tests/test_no_direct_gh.py`). Do the same for the stale-allowlist direction (an allowlist entry whose file no longer calls gh must fail, so the ratchet only ever shrinks).
- The probe must be host-agnostic. It is Python, not a Claude hook. Cursor/Codex have no hooks.
- Unverified: proxy behaviour for `GET /issues/{n}/timeline`, `PUT /pulls/{n}/merge` and `POST /pulls` in a cloud session. The proxy docs say REST on `repos/{o}/{r}/...` works, but no cloud session was available. Unverified: what `gh api rate_limit` returns there.
- Unverified: the exact 403 wording of the third shape. Capture it in a cloud session and pin it in `test_gh_session.py` (the existing two shapes were pinned from #78's own repro).
- Blocking: none.
- Non-blocking: (a) detect by env `CLAUDE_CODE_REMOTE=true` only, or env plus a one-time `gh api graphql -f query='{viewer{login}}'` probe? Recommend env first (free), probe only when env is unset AND config opts in; a manual `GRAPHQL=off` override for testing. (b) Put the helper in `skills/sigma-loop/scripts/gh_api.py` (new, shared like gh_session) versus extending `sources.py`? Recommend a new thin module that sources/work import via `_load`, because sources.py is already 5000+ lines. (c) Is `status.py` in slice 1? Recommend doctor only, plus a one-line status hook if it is trivial.

### REST endpoint map (helper operations)
| Operation (gh) | REST | Notes |
| --- | --- | --- |
| `issue list --label` | `GET /repos/{o}/{r}/issues?labels=a,b&state&sort&direction&per_page&page` | EXISTS (`fetch_issues_rest`); must pass `--method GET`; filter items with `pull_request`; labels comma = AND |
| `issue view` | `GET /issues/{n}` (body, labels, state, user) + `GET /issues/{n}/comments` | comments are paginated separately; `--json author` becomes `.user.login` |
| `issue create` | `POST /issues` (title, body, labels[], assignees[]) | labels must exist (422 otherwise); the feature-label refusal in `_run` must be preserved |
| `issue edit --body/--add-assignee` | `PATCH /issues/{n}` or `POST /issues/{n}/assignees` | |
| `issue edit --add-label` | `POST /issues/{n}/labels` {labels:[...]} (adds) | |
| `issue edit --remove-label` | `DELETE /issues/{n}/labels/{name}` (URL-encode `:`) | 404 when the label is absent; treat as a no-op. Not atomic with the add (D-4); `PUT /issues/{n}/labels` replaces the full set |
| `issue comment` | `POST /issues/{n}/comments` | |
| `issue close` | `PATCH /issues/{n}` {state:"closed", state_reason} | |
| `label create` | `POST /labels` (422 `already_exists` is the idempotent path; never overwrite colour, see #1917) | |
| `pr view` | `GET /pulls/{n}` (already used in work.py) | `mergeStateStatus`/`reviewDecision`/checks are GraphQL-only fields. Use `GET /pulls/{n}` `.mergeable_state` plus `GET /commits/{sha}/check-runs` and `/status`; mapping must be verified |
| `pr list --head` | `GET /pulls?head=owner:branch&state` | head needs the `owner:` prefix |
| `pr create` | `POST /pulls` (title, head, base, body) | |
| `pr merge` | `PUT /pulls/{n}/merge` {merge_method, sha} | the `sha` guard maps to the head-sha check; there is NO REST equivalent of `--auto`. Wait for checks, then merge (see issue) |
| timeline | `GET /issues/{n}/timeline` | |
| Pagination | `gh api --paginate` is unbounded, so keep the bounded `page` loop with `cap`. `--jq` runs per page. | |

## Lane rationale
Whole goal: LARGE. It introduces a new boundary (shared gh helper), a new source of truth (capability state), a contract change (PR landing path), spans 17 code files and 95+ sites, and contradicts nothing numbered, but must be split. Proposed slice 1 is MEDIUM: 1 new module plus edits to gh_session.py, doctor.py and preflight (or `_preflight_rows`), 1 new ratchet test, 0 behaviour changes to existing callers.

### Slice 1 (confirmed, with corrections)
Confirmed: helper plus single capability check plus doctor plus ratchet plus follow-ups filed.
Corrections:
1. Do NOT migrate callers in slice 1. Move only `fetch_issues_rest` and re-export it, or leave it and have the helper import it, so existing tests keep passing.
2. The ratchet is a baseline allowlist keyed per file with a max count (a ratchet only goes down). It must fail on a NEW file and on a count that goes UP. It must also fail when a file in the allowlist has dropped below its count without the allowlist being lowered, so that migration slices are forced to shrink it. Scan with `ast` (as above), not substring only; supplement with a token scan for `"gh"` literals so the dynamic builders are at least flagged.
3. Add the third proxy shape to `gh_session` plus the capability API: `graphql_available(env, cache) -> {"available": bool, "reason": ..., "source": "env|probe|override"}`.
4. Do NOT claim cloud support in docs or CHANGELOG. State "detection and reporting only; migration is in follow-ups".

Slice-1 files: NEW `skills/sigma-loop/scripts/gh_api.py` (helper plus capability), EDIT `skills/sigma-loop/scripts/gh_session.py` (third shape plus capability), EDIT `skills/sigma-doctor/scripts/doctor.py` (a row), EDIT `skills/sigma-init/scripts/preflight.py` only if the check belongs there, NEW `tests/test_gh_api.py`, NEW `tests/test_no_direct_gh.py` (ratchet), EDIT `tests/test_gh_session.py`, plus a docs note (`docs/` page for the capability) and an AGENTS.md line.

## Risks

- R2: the AST ratchet undercounts dynamic argv; the 295 and the 95 differ because of comments and docs versus code.
- R3: the `_no_live_gh` guard (conftest.py:92) makes any un-injected probe fail every test. The probe must take `run=`.
- R4: no cloud session was available to this phase, so all proxy behaviour above is from docs and the issue text.
