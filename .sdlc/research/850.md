### 1. `work.py commit()` (`work.py:3698-3739`)
- Flow: `_record` (3719) -> `_copy_acceptance_into_worktree` (3723) -> `git add -A` (3724) -> `git diff --cached
  --name-only` (3725) -> `nothing to commit` (3726-3727) -> `_secret_refusal` (3728, returns a string, `""` = clean) ->
  `_hs_diff_stop` (3731) -> `_risk_categories` (3737) -> `git commit` (3738) -> `_emit_risk_gates`.
- `git diff --cached --name-only` has rename detection on by default: a sealed file renamed OUT of the dir lists only
  the new path, so "a staged path under the dir" would MISS a pure rename-out. Do not key the gate on that list.
- Fit: a `_sealed_commit_refusal(sdlc_dir, rec, goal, run)` between 3727 and 3728 (before the secret scan so the cheap
  local check runs first and a refused commit does no content scan). It must run `check()` whenever the record exists,
  regardless of the staged list: after `git add -A` the working tree equals the index for tracked/unignored paths, so
  `check()` is equivalent to "staged vs sealed" and also catches rename-out (file `missing`).
- Refusal shape (copy of `_secret_refusal`, `:3423-3535`): a returned string beginning `REFUSED —`, a state line,
  one bullet per path, and the index cleaned with the existing `_unstage(path, paths, run)` (`:3246`, per-path
  `git reset -q -- :(literal)p`, true only if git confirmed). Say "Nothing was committed and those index entries were
  reset" / "STILL STAGED" exactly as the secret refusal does. Name each path and its kind (missing/differs/unexpected).
- Remedy text must be satisfiable TODAY: the seal verb (slice 4) does not exist yet, and the record holds hashes only
  (no bytes). Restore is possible only from a commit that already holds the file: `git -C <wt> restore --source=HEAD
  --staged --worktree -- <path>`; if the sealed bytes were never committed, say so and name the lever: park the goal
  (`/sigma-unpark` is the polite one). Do not invent a re-seal gesture that does not ship.
- Exit code: `main()` (`work.py:8728-8734`) returns 4 only for results starting `_STALE_RESUME_REFUSAL_PREFIX` or
  `"TEST-FIRST REFUSED:"`; the comment there says the secret refusal's `REFUSED — ` stays exit 0 and "no test would
  have caught the difference". See Open decision D2.
- Byte-identity: `test_commit_makes_exactly_the_same_calls_when_nothing_staged_is_secret_shaped`
  (`tests/test_work.py:1033`) pins the exact git call sequence. The no-seal path must add ZERO git calls: one
  `lexists` on the record path (loading `sealed_tests` is not a git call).

### 2. `work.py pr()` (`:4080-4222`) and where the two checks go
- Order today: acceptance record refusal (4130) -> `_push_refused` -> porcelain-clean (the worktree must be clean) ->
  commits-ahead -> plan/hard-plan/plan-review (4157) -> research/acceptance-on-branch (4163) -> `_test_first_refusal`
  (4167) -> `_hs_push_stop`/`_hs_diff_stop` (4171) -> `git push` -> REST PR create. Every refusal returns a string ending
  `(nothing pushed)`; exit code 4 only for `TEST-FIRST REFUSED:`.
- Insert BOTH checks directly after `_test_first_refusal` (4167-4169) and before the push stop: tree-compare first
  (local, ms), sealed-green second (spawns pytest). `pr()` repeats on every review cycle (`work.max_review_cycles`
  default 3) so the green run is paid up to 1 + cycles times per goal.
- **3b. Tree-compare must read the committed tree at HEAD, not the working tree.** `pr()` has already required
  `git status --porcelain` empty, but ignored files are not in porcelain: a sealed file that is gitignored would be on
  disk (so working-tree `check()` passes) and absent from the pushed branch. Add to `sealed_tests.py`
  `check_tree(root, sdlc_dir, stem, rev="HEAD")`: `git ls-tree -r -z <rev> -- tests/acceptance/<stem>`, mode must be
  `100644` (a symlink `120000`/exec/submodule is `differs`), bytes via `git show <rev>:<path>` read as BYTES (work.py's
  `_run` returns `.strip()`ed text, `:1611`, which would change a trailing newline and the sha256, so do not use it for
  content), same `missing|differs|unexpected|record` problem shape, same debris rule applied to tree paths
  (`__pycache__/*.pyc`, `.pytest_cache/`). Reuse `_git` from sealed_tests (unattended env, timeout). This catches the
  raw-git bypass (`git add -f` / `git commit` in the worktree, design PC-6) at publication, which is where it is
  catchable. Refusal names EVERY problem path with its kind (AC-2), prefix e.g. `SEALED REFUSED:`, ends `(nothing pushed)`.
- **Sealed-green at HEAD**: new `sealed_tests.run_green(root, sdlc_dir, stem, *, timeout, run=None) -> {green, failing[],
  detail}`. Runner: `bounded_run.run_group` through the same `_default_run`/`_step` that `seal()` uses (process group,
  whole-group kill on timeout, merged tail output capped at `_TAIL` = 1 MiB, `unattended_env` minus `_DROP_ENV`,
  `PYTHONDONTWRITEBYTECODE=1`, `COLUMNS=240`, a distinct tmp `HOME`). Argv: `[<python>, -m, pytest, -q, -rA, --tb=short,
  --color=no, -p, no:cacheprovider, --rootdir=<root>, -o, addopts=, tests/acceptance/<stem>]`, cwd = the goal worktree
  (HEAD == working tree there, porcelain being clean). It is NOT a full-suite run: one directory, a handful of files.
  - Interpreter: `rec["proof"]["python"]` from the seal record (the interpreter that produced the red proof), so red and
    green come from the same runner; refuse `runner-unusable` if absent or not runnable. Whether that interpreter has the
    adopter's dependencies is UNMEASURED and is a named risk.
  - Verdict (reuse `red_green.classify_sealed(col_rc, col_out, run_rc, run_out, nodes)`): pass requires exit 0 AND every
    node in `rec["red"][*].test` printed as `PASSED` AND no `SKIPPED`/`XFAIL`/`XPASS`/`ERROR` for the dir. A deleted or
    skipped test must not read as green. Failure names each failing node (AC-2 "naming the failing test"), exit 1 plus
    `FAILED node - reason` lines; collection error names the file.
  - Timeout: derive, do not hard-code. The existing derivation is `verify.timeout_minutes` (default 60 min, `loop.py:6180`,
    `_verify_timeout_seconds`). Default: reuse it (same trust and cost class as `verify.command`); see D4.
  - Guard: refuse (do not run) if `rec["worktree"]` resolves to `project_root(sdlc_dir)`: `run_group` has none of
    `run_verify`'s main-checkout/`shell_policy` refusals, and sealed tests are model-authored code run with operator
    privileges (`sealed_tests.py` docstring: "same trust as `verify.command`").
  - `work.py` must not name `bounded_run`/`unattended_git` (`tests/test_unattended_isolation.py` `callers()` flags any
    file but `OWN`+`REGISTERED_CALLERS`); the runner therefore lives in `sealed_tests.py` (registered) and `work.py`
    calls only `sealed_tests`. Inject `run=` for tests (as `seal()` does).
- `_test_first_refusal` (`:3872-3894`) and `_plan_review_refusal` (`:5839`) are the style templates: total functions
  returning `""` or a refusal; `_plan_review_on` (`:5603`) shows the gate-block read. Neither is touched.

- Who is affected: only goals that HAVE a seal record. Today none can (no writer ships until slice 4), so the observable
  change on every existing adopter is: one `lexists` per `commit`/`pr`. Rollback = revert; no state migrates.
- Raw-git bypass: `commit` gate is bypassed by `git commit` in the worktree; `pr` tree-compare at HEAD is the backstop and
  is the only one that can be (PC-6). Bypass of `pr` itself (raw `git push`) is the D-11 ceiling: only CI/host protection
  can close it (CI runs `pytest tests`, which collects the sealed dir).
- Symlinks: sealed entries must be regular `.py` files (`_scan`); tree mode `100644` only; a symlinked `tests/acceptance/<stem>`
  directory: `os.listdir` follows it, so `check()` must `lstat` the dir (add to `check_tree`; for `check` flag as `record`).
  `seal_path`/`refuse_symlinks` already cover the record's own path.
- Worktree vs main: the record lives in the MAIN checkout's `.sdlc/state/sealed/`; sealed files live in the worktree.
  `check(root=rec["worktree"], sdlc_dir=<main .sdlc>)`. The sealed-green run's cwd is the worktree.
- Scalability: gate cost per goal is O(files in one dir) reads + one `ls-tree`; the green run is O(sealed tests), one
  pytest process per `pr` call. At 100x goals nothing is global: no lock, no shared file, each goal reads its own record.
  The only per-goal growth is permanent sealed dirs on the base (D-7, slice 5). Doctor row is O(records), capped at 200.
  **Unmeasured**: pytest startup + run time for a real sealed dir, and the memory of N parallel loop slots each running
  one (small compared with a full suite, but a number is owed; slice 5 owns the measurement).
- Resiliency: absent record = unsealed (passes); corrupt/foreign record = refuse, lever: park the goal (the loop cannot
  self-heal a record it cannot rewrite, and must not delete it); crash mid-green-run leaves nothing (tmp HOME removed by
  the context manager; a SIGKILL can leave a `sigma-sealed-*` dir, the existing documented limit); timeout kills the whole
  group and refuses `timeout` naming the budget; retries are idempotent (re-running `pr` re-runs the check).
