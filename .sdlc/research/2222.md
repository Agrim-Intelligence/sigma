# Research: Make acceptance criteria and agent-ready goals a built-in Sigma feature, protected from the agent
**Goal**: #2222 · **Lane**: large · **Date**: 2026-11-14

## Goal in one paragraph
Today `acceptance.criteria()` accepts only an exact `## Done when` heading, generated goal bodies carry no criteria, and the recorded file is create-only but nothing checks a *new* record against the original. The goal adds: alias `## Acceptance criteria`; one shared body helper for all writers; a `goal_readiness` off|warn|require setting checked at promote and pick; init template + doctor row; an append-only (ordered-prefix) guard at acceptance.py / work.py commit / work.py pr; and an `extend` verb that appends criteria for a newly found slice with a reason, posts on the issue, and which review blocks when reason-less.

## Constraints & unknowns
- AGENTS.md: guard must be run red per clause with the DOCUMENTED gesture; ordered-prefix clause weakened to plain membership must go red; no override flag for agents; no root-checkout files that break `git pull`/`work.py start` (any new record/comment file lives in the worktree copy or is byte-identical to branch copy, #1474/#954).
- Blocking Q1: **baseline for the prefix check.** Ledger `acceptance` event stores only a sha (`ledger.py:215`, `acceptance.py:227`), not text. Candidate baselines: (a) the copy on the goal branch/base via `_branch_doc` (`review_context.py:450-484`) , (b) the issue-body criteria at record time, (c) store `original_sha256`/`original_count` in record metadata. Without one, an agent can rewrite root and worktree copies together. Needs a decision (recommend (c) + (a): metadata line with sha of the first-recorded criteria block, verified against the criteria prefix; hash-only is tamper-evident, not tamper-proof, but git history on the branch backs it).
- Blocking Q2: **cap vs append.** Extension beyond 7 criteria contradicts `criteria()` and `breaker._MAX_CRITERIA`. Options: original 3-7, total up to N (e.g. 20) with a dedicated `## Added criteria` section. Recommend a separate `## Added criteria` section after `## Done when` so the original block stays byte-identical and prefix check is a block-equality test; `criteria()` gains an `added()` sibling and `recorded_acceptance` exposes both.
- Blocking Q3: **format of reason.** Reason must survive review brief; proposal `- [ ] <text> <!-- slice: <ref>; reason: <text> -->` is invisible in rendered markdown; prefer visible `- [ ] <text> (added: <slice>; reason: <why>)`. Confirm.
- Non-blocking: "if issue criteria and recorded differ, goal parks for a person": needs source fetch in work.py commit/pr (network) -- fail-open on fetch error vs park; AGENTS.md says contention fails closed only for security controls; decide and document. Existing "existing record wins" behaviour (`acceptance.py:161`) stays.
- Non-blocking: promote seam is GitHub-only (`promote.py:130 _github`); local-goal mode only gets the pick-time check.
- Non-blocking: doctor "open goals lacking criteria" is a per-goal body read; state a ceiling (cap at N goals, say "N+ unchecked") per SCALABILITY.
- Non-blocking: `goal_readiness.require` parks via `_record(... "parked" ...)` (`loop.py:5544`), modeled on `_park_design :6398`; `warn` returns PROCEED + message. Verb result first word convention: OFF|WARN|PARKED|PROCEED.
- Unverified: end-to-end live behaviour on GitHub (promote against a real repo) -- not run; tests use fakes (`tests/test_acceptance.py` `Source` class).
- North-star check not run to completion by me beyond: no numbered rule seen contradicted; `/sigma-init` template must not overwrite (create-only idiom exists).
- Review skills to flag: none of sensitive/migration; `contract` -> run `/sigma-contract-check` (acceptance record format is in `contract/README.md:36`, golden file).

## Recommended slice split (dependency order)
1. **S1 acceptance core**: alias heading + canonical normalisation; `added` section format; baseline metadata; `prefix_refusal()` in `acceptance.py` (+ contract README/golden additive). Resolves Q1-Q3 first.
2. **S2 append-only gates** (needs S1): wire into `acceptance.record/set-verify-command`, `work.commit`, `work.pr` (unconditional), park-on-divergence; per-clause red tests via documented CLI.
3. **S3 shared body helper** (needs S1 for criteria shape): `issue_body.py`; adopt in handoff open|track, compile_plan (scope, goal-review slices from `Requirements served`), brainstorm/scope SKILL prose.
4. **S4 goal_readiness** (needs S3 for the list of required sections): setting, `loop.py readiness-check` verb after design-check, promote seam, config.json.tmpl + configuration.md.
5. **S5 extend verb** (needs S1+S2): `acceptance.py extend`, issue comment, worktree sync, review brief surfacing + block on reasonless, integrate with `max_added_slices`.
6. **S6 init template + doctor row** (needs S4 setting) and docs/CHANGELOG/label-model/cloud-sessions (docs ride with each slice; S6 owns the sweep).
S3 and S4 can run parallel to S2 after S1.
