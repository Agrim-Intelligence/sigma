## 7. Retire / merge-into-owner-tests lever (design inputs, plan to decide)
- Problem: sealed dir is permanent and collected by `pytest tests`; the seal record vanishes with pruning but the files stay; there is no sanctioned way to fold them into an owner test file, and the commit gate would refuse any such edit while the record exists.
- Minimal polite lever: `work.py seal-retire <sdlc> <goal> --reason "<why>" [--into <owner test path>]` (name a plan call; must be in `_COMMANDS` for exit 4 handling or define own codes). It (1) requires a reason, (2) refuses for a goal not done/merged unless forced by an owner, (3) writes a tombstone atomically (e.g. `.sdlc/state/sealed/<stem>.retired.json`: schema, reason, `--into`, retired_at, last seal sha256s) then removes/renames the live record LAST, so a crash leaves the goal still sealed (re-runnable), (4) does NOT move or delete test files itself; afterwards `commit` is free to carry the move, so the human/maker does the `git mv`/merge. Alternative (less surface): documentation-only lever. Decide at plan.
- Guard interplay: tombstone name must not be seen as a record by `is_sealed`/`read_record`/doctor row (they glob `state/work/*.json` then `is_sealed(stem)`, so a `<stem>.retired.json` is invisible); `goal_state_prune` suffix `.json` under `sealed/` already prunes it (check it does not delete a tombstone before the files are folded: prune is age-gated at 7 days; may want a separate family).
- Honesty: retire is the same "delete the record" disarm that D-11 names as a ceiling; the lever makes it explicit, recorded and reasoned instead of silent. Say so.
