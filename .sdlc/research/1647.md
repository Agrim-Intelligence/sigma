## 1. The defect, in the code
`merge()` (work.py:6869) order today: no-PR park -> `_emit_test_trust` (6834) -> `merge_rights` (4342; REST `view_pr_gh`
isCrossRepository) -> `state.verify_required`/`done_refusal` (PARK "no fresh verify evidence") -> `phase_record_refusal` ->
`gate()` (4185) -> BEHIND rebase -> review gate -> policy -> direct PUT. For a PR GitHub already merged, `gate()` reads
`mergeable`/`mergeStateStatus`; GitHub reports UNKNOWN (or no mergeable state) on a merged PR, so after
UNKNOWN_ATTEMPTS=4 retries with backoff 3,6,12s it returns
`False, "GitHub could not compute mergeability (still UNKNOWN after retries) — GitHub is still computing it; wait a minute, ..."`
(`_PARK_MERGEABILITY_UNKNOWN`, 399; built at ~4267), and merge() returns `PARK: <that>` (the `not ok and not pending_arm` branch).
So the caller records `parked` on a goal that is already landed. A stale/missing verify evidence record or phase record
parks even earlier with a misleading reason.

## 2. Exact change
In `merge()`, immediately after the `if not rec or not rec.get("pr")` park (line ~6881) and BEFORE `_emit_test_trust`
(a merged PR has no use for a test-trust diff and it costs git calls):

    landing, why = pr_landing_state(sdlc_dir, rec, run)       # ONE REST read, GET pulls/<n>
    if landing == MERGED:   -> run post-landing effects, return "PR #N merged (already merged; outcome reconciled)"
    if landing == CLOSED_PR: -> return the named PARK (see wording below)
    else (OPEN_PR / UNKNOWN): fall through unchanged (the UNKNOWN read is not retried; gate() keeps its own budget).

Facts about `pr_landing_state` (4465): REST only, `gh api repos/{owner}/{repo}/pulls/<n>`; `merged` only on body
`merged: true` or non-empty `merged_at`; never raises (read error -> `(UNKNOWN, first line)`); runs from the record's
worktree if the dir exists, else `project_root(sdlc_dir)` (so a deleted worktree still resolves). Constants `MERGED`,
`OPEN_PR`, `CLOSED_PR`, `UNKNOWN` at 4462.
