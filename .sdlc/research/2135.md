# Research: Recognise a commit-signing outage and stop with a plain "signing is unavailable" message
**Goal**: #2135 · **Lane**: medium · **Date**: 2026-11-02

## Goal in one paragraph
When `git commit` fails because the host's signing helper is down, `work.py commit` and the ledger publish commits in `sync.py` report only a generic git failure. They must instead recognise the cause, stop with one plain message ("Commit signing is unavailable on this machine, so nothing can be committed or pushed. Start a fresh session ... Sigma will not turn signing off for you."), and the goal must park with that reason. Never retry unsigned, never add `-c commit.gpgsign=false`. The pre-flight probe is optional and out of scope unless trivial.

## Where the detection helper goes
Both `work.py` and `sync.py` load siblings with their own `_load` (work.py:74, sync.py:54); `work.py` already loads `sync` lazily. Precedent for a pure stderr classifier is `gh_session.py` (used by `work._run`, which is why it is in `tests/test_script_help.py` `LIBRARY_ONLY`) and `qkind.py`. Recommend one small new library, e.g. `skills/sigma-loop/scripts/commit_signing.py` (pure: `MESSAGE`, `unavailable(detail, signing_on)`), so the wording and the classifier have one source. A new script touches: `tests/test_script_help.py:60-110` (`LIBRARY_ONLY`), `evals/skills/cards/sigma-loop.json` (a `"role": "library"` entry, near 561), and the globbing tests (`test_import_boundary.py`, `test_config_discoverability.py`, `test_feature_registry.py:1904`) which should pass unchanged but must be run.

## Constraints & unknowns
- Host-agnostic: pure Python in `work.py`/`sync.py`, no host hook; Cursor/Codex see the same message. RESILIENCY: stop means no retry loop for the commit; the ledger watch tick will re-attempt next interval (bounded by its own interval), which is acceptable but state it. SAFETY: no `-c commit.gpgsign=false`, no `--no-gpg-sign`; refuse loudly. A structural test (like `tests/test_no_unsupervised_process_pause.py`) asserting the new code never contains those strings in the commit paths would be cheap.
- No ratchet is hit: no new `gh` call sites (`tests/test_no_direct_gh.py` unaffected); `tests/test_no_private_names.py` is strict, so docs and tests must not name the adopter repo (say "an adopter repo").
- Unverified: real signing service behaviour in a cloud container (only a fake helper was run). Say so in CHANGELOG "Not measured". Windows git path not run.
- Unresolved risk 1 (BR-9): "Sigma will not turn signing off" is false for the unattended rebase engine, which pins signing off. Scope the wording to the commit verbs or record the exception. Needs the owner's call only if wording is contested; default: scope it.
- Unresolved risk 2 (false positives): `failed to write commit object` also comes from object-store write failures (disk full, permissions). The ssh shape has no signer marker. Recommend requiring signing to be in effect (a `git config --type=bool commit.gpgsign` read, or `-S` in argv for the receipt) AND the fatal line AND no object-store marker (`No space left`, `unable to create temporary file`, `insufficient permission`), read on the failure path only. Residual false positive is accepted and measured by a test.
- Non-blocking: exit code and prefix for the stop (default: a `PARK:`-style first word like `merge` uses, plus exit 4 beside `SEALED REFUSED:` at work.py:10226); whether `unknown` qkind is acceptable (default yes; a new qkind is a follow-up). Blocking: none.
- North-star: `north_star.py` printed `absent` (drop-in project): no rule tripped.
