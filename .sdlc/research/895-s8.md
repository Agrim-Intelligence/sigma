## 1. gh_api.py - the primitive already exists

`comment_issue(run, number, body, repo=None, *, fallback_run=None, env=None, sdlc_dir=None, now=None)`
(skills/sigma-loop/scripts/gh_api.py:859). POSTs `api repos/<repo|{owner}/{repo}>/issues/N/comments --method POST
-f body=<text>` (`_endpoint` :298 supplies the `{owner}/{repo}` placeholder when `repo` is falsy), returns the parsed
JSON dict. Fallback argv: `["issue","comment",str(n),*--repo,"--body",body]`, built INSIDE the EXEMPT file (:864), so
the ratchet never sees it. Declared non-idempotent (`False`).

WRITE_POLICY (:708-722), columns (id, text, idempotent_ok, non_idempotent_ok). For a comment only column 4 counts:
`primary_rate_limit` = True (429, or 403 whose gh stderr says rate limit and not secondary/abuse); everything else
False: secondary_rate_limit, server_5xx, transport_ambiguous, auth_401, not_found_404, invalid_422, permission_403,
proxy_block, refused, other_unparsed. This is EXACTLY the policy asked for: one fallback, only on a primary rate
limit; no 5xx or transport fallback.

Cloud: `_rest_write` (:783-807) calls `graphql_available(env)["available"]` (:255) AFTER deciding the case is
fallback-eligible; env-only (no probe): `CLAUDE_CODE_REMOTE` in (true,1) -> unavailable; `SIGMA_GH_GRAPHQL` off/0/false
-> unavailable, on/1/true forces available (:266-269). Unavailable -> logs fell_back=False and re-raises the REST
error. So "no fallback in cloud" is already built in; slice 8 adds nothing.

Injected runner: `run` is any callable `run(args)->stdout str`, raising on failure; `_call` (:302) wraps any exception
into `GhApiError(str(exc), exc.hint, status, kind, returncode)` (:159) via `classify` (:182). Classification of a
write reads `.hint` (gh stderr) and the `__cause__` chain only, never `str(exc)` (`_write_case` :752), so a comment
body saying "HTTP 502" cannot masquerade. A `subprocess.TimeoutExpired` in the cause chain = transport_ambiguous.
`GhApiError(Exception)`: `str` = wrapped text (`gh api ... failed: <stderr>`, which EMBEDS argv and so the body, as the
old RuntimeError from `_default_run` :213 did), `.hint`, `.status`, `.kind`, `.returncode`. A 2xx with non-JSON stdout
raises GhApiError(kind other) "unparseable gh api output" (:317); the runner returning "" parses as `null` -> returns
None, no raise. `fallback_run` default = same `run`; `sdlc_dir` enables the bounded `state/gh-fallback.json` log
(:810, never body/argv). One stderr line when a fallback fires (:804). No breaker (writes never touch it).

## 6. Risks / ambiguities

1. Duplicate ruling (exact wording): sources.py:3342-3344 "A retry that turns out to have followed an actually-landed
   write double-posts the comment. Accepted, deliberately: for an audit trail that is otherwise all-or-nothing, a
   duplicate REJECT comment is a categorically safer failure than a silently missing one." Second home: docs/
   dossier-pipeline.md:1165. Slice 3's `comment_issue` already refuses 5xx/transport fallback, which contradicts it
   (cloud-sessions.md:191 says so). DECISION NEEDED: option A (recommended, per the stated policy) - no retry loop at
   all; the REJECT verdict's loud `FAILED`/exit 1 in loop.py is then the recovery lever. Option B - keep a bounded
   REST-only retry on 5xx/transport inside note(): preserves "never silently missing" but is a REST re-POST that can
   duplicate, and then `_NOTE_RETRIES` stays. The brief says a 5xx must not be retried via GraphQL; it does not rule
   out a REST re-POST, so confirm with the owner. Either way the ruling text must be re-worded, not silently dropped.
2. Retry removal changes behaviour for transient hiccups (account drift is the #1986 motivating case, the rest being
   rate limit/5xx): the first transient now surfaces immediately. The 4-attempt x 0.5s..4s backoff (up to 3.5s sleep)
   disappears. `_is_transient` stays used elsewhere (:1303 :1684 :2419).
3. `goal` coercion: `_n` does `int(str(goal).lstrip("#"))`; old code passed `goal` through to `gh issue comment`,
   which accepts URLs/branches. All callers pass numeric refs or "#N" (acceptance.py guards `.md`); a non-numeric
   would now raise ValueError (not GhApiError) - callers catch `Exception`, so still safe.
4. `self.repo` empty -> placeholder `{owner}/{repo}` is handled by `_endpoint` (:298); fallback omits `--repo` (gh
   infers). Cwd must be a git checkout with a remote (same as the old fallback and every other REST read).
5. Messages: GhApiError text embeds argv incl. the comment body (as before). Warnings/stderr lines that print `{exc}`
   (handoff.py:977,1128, feature_*, assign.py:586) will contain the body; unchanged risk, but the fallback path now
   also writes it. loop.py:6339 wording "failed after retries" becomes inaccurate with option A.
6. No caller parses 'GraphQL', 'gh issue comment' or `_is_transient` from a note() exception (grepped skills/ hooks/);
   spend_approval only formats the type name.
7. Hard-stop guard `hsg.blocks_issue_write(self, goal, "note")` (:3374) must remain first; it returns None silently on a
   foreign issue (parks instead). Unchanged.
