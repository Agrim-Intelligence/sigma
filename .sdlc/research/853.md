## 6. Plan-defect return (AC-5): what is missing
- `phase_gate.start_refusal` :222 allows `start implement` when ANY approving plan-review `verdict` row exists (`any(...)` at :232), whereas `status` :96 judges the LAST verdict. So recording a FIX-FIRST after an approval would block `record done` and `work.py pr` (the gates record is overwritten, `work.py:1455`) but NOT `start implement`. The return-to-plan must change `start_refusal` to last-verdict semantics (or consult a new defect row). Verified by reading; not executed.
- `record_plan_review(..., FIX-FIRST)` as the carrier is awkward: `phase_gate.record_verdict` raises on the `subagent` route without `--agent-id` (:274+), and attributing a breaker finding to the plan reviewer is dishonest. Recommended carrier: a Python-written action-log kind `plan_defect` (fields: `criterion`, `source`), read by `phase_gate.status` (plan_review not ok while a defect row is newer than the last approving verdict) and by `start_refusal`. Cost: `INTERNAL_KINDS`/`INTERNAL_FIELDS` change plus tests in `test_actionlog.py`. Alternative with less surface: reuse `record_plan_review` FIX-FIRST and accept the agent-id requirement. Plan decision.
- Ordering that spends nothing: run the pure checks (gate on, non-pytest, approving plan-review bound to the current plan, `criterion_verdicts`) BEFORE route resolution and BEFORE any spend. Then a Claude Code user still learns their criteria are vague even though their host refuses to run the breaker.

## 7. Premises that do not hold (need a ruling, none are blocking the start of slice A)

**R-1. "Judged unattackable" is a heuristic with a high flag rate.** Measured (read-only, `breaker.criterion_verdicts` over the 172 parseable acceptance records in the main checkout, 810 criteria): 362 criteria (45%) non-actionable; 132 of 172 records (77%) have at least one; 23 records (13%) are refused whole by `breaker.brief`; 2 criteria scrub to empty; `no_channel` passed on all 149 built briefs. Eyeballed sample of 4 flagged criteria: at least 2 are testable ("X exists, is stdlib-only, ..."). Precision was NOT hand-judged beyond that sample. So AC-3's wording "a criterion the brief judges unattackable returns the goal to plan" has two readings: (a) any flagged criterion bounces the goal (~77% of historical records would bounce), (b) only a whole-brief refusal bounces it (13%) and per-criterion verdicts are advisory (which is how `breaker.brief`'s docstring treats them). Recommend (b) plus naming the flagged criteria in the output, and that AC-3 be restated that way. This is a scope call for the owner.

**R-2. No criterion ids, so "at least one test per testable criterion" cannot be validated.** `validate_output` only requires a `test_*` per block. Ids and PROCESS/DOC/MEASURED tags are #535 (OPEN, B-2). A positional-id fallback exists in the design as something that "must not be shipped silently". Deliver the clause as: at least one block with at least one test, and state the per-criterion check as unmet until #535; or ship positional ids behind an explicit, documented flag. Also several of #853's own criteria are prose/doc criteria (skill prose, registry rows), which no pytest breaker test can attack.

**R-3. D-6 cap cannot be a `generation` check.** `seal()` raises before writing the record (the record is written LAST), so a refused attempt (pass-on-base, collection-error, timeout) leaves `generation` unchanged: a loop of failing breaker runs would be unbounded and each is paid. The bound needs an attempts counter written BEFORE the breaker spawn (per goal, pruned with the goal: add to `FILE_FAMILIES`). Cap semantics for the plan: attempts or re-seals? Recommended: count breaker runs; refuse the third.

**R-4. D-11 record-deletion hole is promised closed by this slice.** Shipped text (two `ENFORCEMENT_GATES` conditions, `CHANGELOG.md` Unreleased, `docs/enforcement.md`) says "slice 4 closes that" / "the configured record-required check of slice 4". #853's six criteria do not list it. Either implement it (when `gates.sealed_acceptance.enabled` and there is neither a seal record nor a recorded `--no-seal`, `commit`/`pr` refuse) or reword those three texts in this change. It needs the `--no-seal` record, so it belongs with slice C.

**R-5. The interface source is still open (D-2).** `breaker.brief(…, interface)` has no producer. With `interface=""` the brief says "(none given)" and the breaker must guess module and function names. D-1 accepts any in-body failure as red, so a test that fails on base because it guessed a wrong module name is accepted as red, then fails forever against the real implementation, and the sealed-green PR gate would force the maker to match the guess. For a goal whose criteria name their artefacts (like this one: `work.py seal-tests`) this is tolerable; for most it is not. Recommend a minimal source in slice A: an `## Interface` section read from the acceptance record (scrubbed), refusing if absent when the criteria name no file/verb, or an explicit `--interface-file`.
