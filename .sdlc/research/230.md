# #230 research — create sdlc:* and priority:* labels before the first pick; surface label-write failures

## Symptom (confirmed in code)
- `GitHubSource._fetch_pending` picks by a REST query on `goal_label` (`sdlc:goal`). If the label does
  not exist the query returns `[]`, `_next` returns `("DONE", None)` and `loop.py next` prints a bare
  `DONE` with nothing on stderr.
- `GitHubSource._ensure_labels` (sources.py) is the only creator on the loop path and runs only inside
  claim/park/offboard (`mark_in_progress` etc.) — after a pick. Chicken-and-egg on a fresh repo.
- `setup.py labels` → `ensure_core_labels` → `ensure_labels()` swallows every `gh label create`
  failure (`except Exception: pass`) and then prints `ensured on <repo>: ...` unconditionally.
  Measured RED: with a fake `gh` answering `label create` with exit 1 + GitHub's 403 text,
  `python3 setup.py labels .sdlc` exited 0 and printed `ensured on acme/app: sdlc:blocked, ...`;
  `loop.py start` exited 0 having written nothing.
- No code creates `priority:P0..P3` before use (`/agrim-triage` and `handoff.py` create on first use
  at the arbitrary colour `d4c5f9`). The Claude Code `issue_field_gate` hook refuses `gh issue create`
  without a priority label.

  (`triage._PRIORITY_PATTERNS` comment).

## Transport
- `gh label create` is REST (POST /repos/{o}/{r}/labels). `gh label list` is GraphQL — avoided.
  Reading labels: `gh api repos/<o>/<r>/labels --method GET -f per_page=100 -f page=N` (REST, `core`
  bucket). `--method GET` mandatory (`gh api` defaults to POST with `-f`).
- Error shapes: exists → `label with name "x" already exists; use --force ...` (exit 1); no permission
  → `HTTP 403: Resource not accessible by integration` (exit 1). `_run_gh` puts stderr in `exc.hint`.

## Cost / scale
Per repository, not per issue: 1 REST read (<=100 labels) + one create per MISSING label. Bootstrapped
repo: 1 read, 0 writes per `start`. 100x issues: unchanged. 100x labels: one read per 100 labels
(ceiling 100 pages, then falls back to create-and-classify). DONE census: one `per_page=1` REST read,
only on the drained path.
