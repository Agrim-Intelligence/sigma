# Research: #360 — mutation gate parser and per-module kill rate

Measured 2026-10 on mutmut 2.5.1 (highest 2.x offered by `pip index versions`), Python 3.12.13, in a throwaway
virtualenv outside the repository (the sigma-ops readiness directory). mutmut 3.x exists (3.8.0) and was not used.

The issue's two UNVERIFIED claims, checked by running the tool:
- "result regex has mis-encoded bytes": TRUE. The old patterns carry mojibake instead of the emoji; they match
  nothing mutmut prints.
- "the number comes before the emoji in the old parser; mutmut prints the emoji first": TRUE. mutmut redraws one
  carriage-return progress line per mutant, `<emoji> <count>` for killed/timeout/suspicious/survived/skipped; the
  LAST redraw is the tally. A worse fact the issue did not know: with `--simple-output` (words instead of emoji) the
  old patterns return a WRONG number, not zero — "4/4  KILLED 3" is read as 4 killed, 0 survived on a real run of
  3 killed, 1 survived.
- "2.x flags exist": TRUE for 2.5.1: `--paths-to-mutate`, `--use-coverage`, `--runner`, also `--simple-output`.
- NOT in the issue, found by running: `--use-coverage` needs a `.coverage` file, and mutmut imports `coverage` from
  its own environment, so the throwaway venv needs `coverage` and `pytest`; mutmut also refuses a directory without
  a `tests/` folder; `mutmut results` lists only non-killed mutants (survivor ids as ranges), so the killed count
  exists ONLY in the run's progress line; `results` ignores `--simple-output`. The repository's `.coveragerc` is
  `parallel = True`, `patch = subprocess`: coverage writes one data file per process and `coverage combine` must
  merge them before mutmut can read them. mutmut applies each mutant to the source file IN PLACE: a killed mutmut
  leaves a mutated file, so the sample runs only in a frozen clone and restores it after every module.
- The issue's test selection (`grep -l <module> tests/test_*.py`) selects 100-224 files for the large modules and 8-45
  for mid ones (measured); the 133-line `run_with_timeout.py`'s 8 files take 112 s per unmutated run, so a run per
  mutant is not feasible. The sample therefore selects files named for the module, else the (at most five) files
  that reference it, and records the rule and files per module.
