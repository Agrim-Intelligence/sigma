## Goal in one paragraph
#1551 gave `reviewer.py run` a `running` receipt (pid, started_at, timeout, run_id nonce) plus a
classifier that reads a dead or expired one as `failed/not_completed`, and a bounded `reviewer.py wait`.
This goal moves the generic part of that into one shared helper. `reviewer.py`, `loop.py verify` and
`work.py merge` all use it. It adds `loop.py wait-call <sdlc> <goal> verify|merge --max-seconds N`
(0 final / 1 failed / 3 running) and has both long calls print that gesture at launch. While one verify
for a goal is live, a second is refused. `landing.md` REQUIRED PATTERN changes to name the gesture.

## How #1551's receipt works today (Q1)
- **Path**: `<sdlc>/state/reviewer-runs/<goal_stem>.<phase>.json`, where phase must be in `RECEIPT_PHASES` and the goal is checked with `state.unsafe_goal_reason` (`reviewer.py:505-513`).
- **Write**: `_write_receipt` does mkstemp in the same dir, `json.dump`, fsync, `os.replace`, and stamps `at/goal/phase` (`:516-531`). There is ONE file per goal and phase, so the latest run wins. `clear_receipts` (`:534-539`) is called only by `work.py finish` (`work.py:7517`).
- **Running write**: `run_review` writes it after the cheap refusals (leak, shell policy, timeout bounds) and before the minutes-long content-key step and `Popen`. Fields: `outcome="running", pid=os.getpid(), started_at=int(time.time()), timeout_seconds, run_id=uuid4().hex, route, plan_sha256` (`:1055-1064`). The launch hint goes to stderr and only when `hint=True` (CLI only; `:1060-1064`, `:1196`).
- **Final write**: `finish()` closure (`:1044-1049`) calls `_finish_receipt` (`:1115-1134`). That re-reads the RAW file and writes only if `raw["run_id"] == run_id`. A cleared receipt is not resurrected, and a newer run is not clobbered. It is an unlocked check-then-replace; the docstring states two concurrent runs are unsupported. A `BaseException` after the running write finalises `not_completed` (`:1106-1111`).
- **Classifier**: `_classify(got, now)` (`:617-633`) runs only on `outcome=="running"`. Malformed (non-int or bool pid, pid outside 1.._MAX_PID, span > `_MAX_RUN_SECONDS`=86400, started_at > now+`_CLOCK_SKEW`=60) means not_completed. `now >= started_at+timeout_seconds+_RUN_GRACE` gives "deadline passed". `not _pid_alive(pid)` gives "runner pid N gone". Otherwise the receipt is returned unchanged. The deadline is DERIVED, never stored (comment `:580-584`).
- **`_pid_alive`** (`:598-610`): `os.kill(pid,0)`. Only `ProcessLookupError` counts as dead; any other `OSError` is alive. Off POSIX it returns True, so the deadline alone bounds it. A zombie reads alive until the deadline. It duplicates `ledger.pid_alive` (`ledger.py:1967`) in a different form.
- **Reader door**: `_read_receipt_at` (`:701-708`) returns `missing` / `unreadable` / (`ok`, classified dict).
- **`wait_review`** (`:662-691`): resolves the path once, then polls once a second with injectable `sleep`/`clock`. Exit codes: 0 `outcome=="ok"` (FINISHED, any verdict, findings printed); 1 any other non-running outcome; 2 unreadable / run_id mismatch / still missing after `min(_MISSING_RETRY=5, max_seconds)` s; 3 running at the bound. CLI clamps `--max-seconds` to 1..3600, default `WAIT_DEFAULT_SECONDS=20` (below the measured 30.2 s Codex yield). Codes 0 and 3 print to stdout, the rest to stderr (`:1198-1214`).
- **Reviewer-specific (stays in reviewer.py)**: `RECEIPT_PHASES` and the `reviewer-runs` path; `route` and `_route_applies`/`_failure_applies` (`:741-767`); `waived_inline`/`accept_inline`; `running_receipt`'s `_independent_on` gate (`:647-659`); verdict, findings and `content_key` fields; `_RUN_GRACE = 4*_KEY_SECONDS+60` (`:585`, reviewer post-run work); `_wait_gesture`/`_wait_text` wording (`:636-644`); `phase_gate.py:149-155` calling `rv.running_receipt` and the PRIVATE `rv._wait_gesture`.
- **Generic (extract)**: atomic write (with path and grace as parameters), `_pid_alive`, `_int`, `_classify` core (grace passed in), `_read_receipt_at`, nonce-guarded finish, the wait poll loop (exit 0/1/2/3 mapping with an "is final OK" predicate), and `_MAX_PID`/`_CLOCK_SKEW`/`_MAX_RUN_SECONDS`/`WAIT_DEFAULT_SECONDS`/`_MISSING_RETRY`.

## verify_goal flow (Q2)
Order (`loop.py:5538-5772`):
1. unsafe goal, exit 2 (`:5552-5556`).
2. load config, acceptance digest and commands; invalid record, exit 2 (`:5557-5564`).
3. NO-COMMAND, exit 3 (`:5565-5570`).
4. enforce on with no acceptance record, REFUSED exit 4 (`:5575-5582`).
5. **`work.ensure_fresh` may AUTO-REBASE the worktree**, then STALE exit 4 (`:5590-5613`, #1890).
6. `_verified_tree`, then shell-policy refusal, exit 2 (`:5618-5629`).
7. content fingerprint, then **the child**: `subprocess.run(command, shell=True, capture_output=True)` per command, no timeout (`:5636-5640`).
8. red_green observe, flake re-run (`_flake_verdict`), diff-revert, witness. All of these re-run tests and add wall time (`:5644-5711`).
9. #498 warning, then **evidence write** to `state.evidence_path` = `<sdlc>/state/verify/<goal>.json` (`state.py:1226-1231`) by plain `ev.write_text` (not atomic; `:5713-5726`).
10. ledger, actionlog and timing writes; exit 5 UNVERIFIED (`:5761-5765`); `VERIFIED|FAILED exit=N evidence=…` on stdout, exit 0/1 (`:5767-5772`).

Codes already in use are **0-5**. Exit 4 already means "refused before running anything" in two senses. There is no try/finally anywhere in the function. The CLI entry `loop.py:7152-7163` calls `_ensure_watcher`/`_ensure_ledger_delivery` first; `verify` is in `_ARMS_CLAIM` (`:1841`), and `wait-call` must NOT be added there.

**#498 warning** (`:5656-5674`): runs AFTER the child finishes, just before the evidence write. It reads the previous evidence file's `run` (`SIGMA_RUN_ID` via `state.run_identity`, `state.py:1234`) and `pid`. It warns only if `prev_run is not None and prev_run != this_run and ledger.pid_alive(prev_pid)`. Its state lives in the frozen-contract evidence file (`contract/README.md:34`). No test covers it (`rg "overwriting|different LIVE run" tests` finds nothing).

**Where the receipt and refusal must go**: after step 4 and BEFORE step 5. `ensure_fresh` rebases the very worktree a live sibling verify is testing, so a second verify must be refused before it mutates anything. Every return after the running write needs one nonce-guarded final write, which means a wrapper with try/finally. **Atomicity**: the reviewer's check-then-replace is unlocked by design, so it cannot be the refusal. The repo's proven primitive is the non-blocking `fcntl.flock` with an inode re-check and fail-open, as in `_try_acquire_claim_lock` (`loop.py:466-505`). The kernel releases it on death, so pid reuse cannot hold it. `O_EXCL` creates exist at `state.py:183`, `:1175` and `logroll.py:65`, but an O_EXCL marker needs stale-file reclaim; flock does not.

## work.py merge flow (Q3)
`merge()` (`work.py:6864`):
1. no record or PR returns `PARK:` (`:6899-6901`).
2. `_emit_test_trust`, then `merge_rights` (gh), then `done_refusal`, then `phase_record_refusal` (`:6906-6932`).
3. **`gate()`** (`:4180`): up to `PENDING_ATTEMPTS+1` rounds × `UNKNOWN_ATTEMPTS` reads (`:4223-4290`).
4. BEHIND goes to `_reconcile_behind` (`:5425-5476`, up to `BEHIND_REBASES`=3 rebases, each followed by up to `BEHIND_ATTEMPTS`=6 gate calls).
5. ledger and actionlog, then `ci_repair` or PARK, then `effective_review_mode`, `review_gate` and `protection`.
6. arm `--auto` (`:7046-7062`) or the direct REST merge `gh_api.merge_pr_gh` with a reconcile read loop (`RECONCILE_ATTEMPTS`=3 × 5 s; `:7069-7095`).
7. branch delete, issue close, `_record_confirmed_merge`.

It returns ONE string. `main()` prints it to stdout (`:8376-8378`), and an exception gives `work: <exc>` on stderr with exit 1. Exit 4 applies only to `_STALE_RESUME_REFUSAL_PREFIX`/`TEST-FIRST REFUSED:` (`:8389-8390`). Callers route on the first word (SKILL.md:226-232; `landing.md:188+`; drills `tools/readiness/drills.py:364-622`; `tools/onboarding_control.py:1164-1168`; `blast_radius_drive.py:189`). The receipt therefore wraps `merge()` around its ~20 return sites. The inner function's string comes back unchanged, and the launch hint goes to **stderr from `main` only** (as reviewer `hint=True`). The final receipt must carry the result line, because a yielded caller who later learns only "final" cannot route without it (`PARK` / `PR #N merged` / other).

## Constraints & unknowns
- **F1 (blocking-lite, design call): verify deadline.** Verify has no timeout and real runs take 25-52 min plus the flake and diff-revert passes. A short deadline makes a live verify read failed, which re-allows the overload this goal exists to stop. A long one (reviewer cap 86400 s) means a reused pid can keep a goal refused for hours. That breaches LIVENESS unless a lever is named. Options: (a) a new config key with a generous derived default; (b) primary liveness by a held `flock` (crash- and pid-reuse-proof), with pid plus deadline only as the classifier backstop the acceptance requires. Recommend (b) plus a stated default; the plan must name the lever.
- **F2 (blocking-lite): "built on the run-id check" vs the re-invocation case.** The #498 check exempts `prev_run == this_run` and `None`. The Codex hazard this goal targets is the SAME session re-invoking verify after a yield, which means the same `SIGMA_RUN_ID` (or None). A refusal keyed on run id would let exactly that case through. The refusal must key on a live receipt (pid, deadline, nonce) regardless of run id, and the #498 warning gets folded into it. Plan-review should confirm this reading of the acceptance.
- **F3: refusal exit code.** 0-5 are taken; 3 means NO-COMMAND in verify but "still running" in wait-call. Options: reuse 4 ("refused before running anything") with a distinct `REFUSED exit=4 -- live verify pid … wait with …` line, or a new 6. Non-blocking.
- **F4: wait-call semantics.** Is a verify that ran red (exit 1), or a merge that returned `PARK:`, "final" (0) or "failed" (1)? The reviewer precedent says final = the call completed whatever the verdict, so 0 should print the stored result line (`FAILED exit=1 …` / `PARK: …`). It also needs an exit for missing or unreadable (reviewer: 2), which the acceptance does not name. Non-blocking.
- **R1 pid reuse**: macOS pid space wraps; the deadline is the only backstop. flock (F1-b) removes it for verify.
- **R2 clock**: `started_at` is wall `time.time()`; the classifier tolerates 60 s skew; wait uses monotonic. A wall-clock jump forward expires early.
- **R3 crash between the running write and the final write**: SIGKILL means a dead pid, so it reads not_completed (reviewer C-tests prove the pattern). verify needs a try/finally wrapper; it has none today.
- **R4 merge deadline**: derived from code, not measured. Initial gate ≤ 10×45 + 11×21 ≈ 681 s; per rebase ≤ ~5 transient gates (≤21 s each) + backoff 5+10+20+30+30 s + one full gate ≈ 880 s; × `BEHIND_REBASES` 3 ≈ 44 min, plus untimed `gh`/`git` calls. That is above the documented 22.5 min. Derive the deadline from the constants plus a grace; do not hard-code 1,350,000.
- **R5 sdlc path**: the worktree has its own `.sdlc` with no `state/` (`.sdlc/work/1650/.sdlc` holds only acceptance/design/plans/…). A wait-call run against the worktree's `.sdlc` reads "missing". The printed gesture must carry the RESOLVED absolute sdlc dir (reviewer's `_wait_gesture` prints `sdlc_dir` unresolved, `reviewer.py:637-639`).
- **R6 #1890 auto-rebase ordering**: the receipt and refusal must precede `ensure_fresh` (`loop.py:5590`). Otherwise a second verify rebases a tree under a live first one. STALE (exit 4) after the running write must finalise the receipt.
- **R7 `record done` → `finish` clears receipts**: a wait-call after done reads missing. Acceptable, but it needs a defined code (F4).
- **R8 load**: on this 12-core machine, concurrent full-suite verifies (load 13-18) caused #1551's timing flake (brief, not re-measured). Tests must not launch real suites or models (acceptance).
- North-star: `north_star.py` returned `absent`; there is no rule to check.
- Deferred, not in scope: #1673 (loop.py red), #1571 (flake speed).
