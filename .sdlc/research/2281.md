## Goal in one paragraph
Add `reuse.py rerun <sdlc_dir> <goal> [--ref R] [--new-since-research] [--base B]`. It reads the goal dossier's recorded
`- pattern: ... paths: ...` queries and runs each with `git grep` at a commit (never the working tree, never HEAD, never
a shell), printing `Q<i> file:line: text` per hit. With `--new-since-research` it compares hits at the tip of the
remote-tracking base ref with hits at the dossier's `**Searched at:**` commit, by `(file, text)`, and prints only the
new ones. New code: `resolve_commit(root, ref, run=None)` (reused later by #2283 `inflight`), `git_grep`, `queries_for`,
`rerun`, `base_ref(sdlc_dir, run=None)` and a FETCH_HEAD age helper (both reused by #2283), plus the CLI branch, with a
30 s per-query and 120 s total bound, one-line refusals, exit 0 for every informational case and 2 only for usage.

## Hostile-input shapes
- **Pattern**: shell metacharacters, a leading `-`, a leading `;`, NUL or newline in a pattern. Argument-list use plus `-e` makes a leading `-` safe; `check-research` bans control characters but a legacy dossier is never checked, so `rerun` must refuse a query with a control character or an empty/over-long pattern itself (bounds `MAX_PATTERN`, `MAX_QUERIES` exist).
- **Paths**: `:(top)`, `*.py`, `-x`, `../x`, `/etc`. `--literal-pathspecs` covers magic and globs; a path starting `-` is after `--`; `..` and absolute paths still resolve against the repository only, but should be skipped with the same `_path_error` rule, not run.
- **Refs**: `--output=x`, `-n`, `HEAD~1;x`, a ref naming a blob or tag. Resolve with `rev-parse --verify --end-of-options <ref>^{commit}` and pass the 40 or 64 hex id only.
- **Searched-at line**: not hex, uppercase, 63 characters. Must match `SEARCHED_AT` first; otherwise print the "records no searched-at commit" line (decision for Plan).
- **Output**: a file name with a colon, a newline in a file name (`-z` handles it), a text line of 1 MiB, a binary file (`-I` skips), thousands of hits. Cap hits per query and total output (unmeasured; Plan must pick numbers and say they are judgements).
- **Timing**: 25 queries at 30 s would be 750 s, so the 120 s total is the real ceiling; `git grep` on a large tree at a commit is unmeasured here.
- **Hit identity**: `(file, text)` as a set, one lookup per hit; the searched-at side is a full `git grep` per query too, so a new-since run costs two greps per query.
