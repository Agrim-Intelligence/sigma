# Research: #398 public repository settings and a read-only verifier

Dossier for issue #398. Date of the research: 2026-10-03. origin/main `5d3937e`.

## Facts that shape the design

- CI check names (read from the live check-runs of the current main head, and derivable from
  `.github/workflows/ci.yml`: job id `test`, matrix `include` of os and python, no job `name:`):
  `test (ubuntu-latest, 3.10)`, `test (ubuntu-latest, 3.11)`, `test (ubuntu-latest, 3.12)`,
  `test (ubuntu-latest, 3.13)`, `test (macos-latest, 3.12)`. Reporting app is GitHub Actions. `windows.yml`
  is an experimental cell and is not required.
- Launch definition (`docs/launch/definition.md`): supported cells are exactly the five CI legs.
- The loop's merge path (`skills/agrim-loop/scripts/work.py`): `gate()` reads `mergeStateStatus`; on a base with
  no required checks GitHub reports CLEAN while CI is still pending, so `merge()` lands the PR. With required
  checks it reports BLOCKED, `gate()` re-polls 10 x 45 s, then `merge()` arms `gh pr merge --auto` only if the
  repository's `allow_auto_merge` is true; otherwise it tries a direct merge, GitHub refuses, and it parks.
  `protection()` reads `required_status_checks.contexts|checks` and `required_pull_request_reviews`.
  `gh pr merge` is never called with `--admin`, but a repository admin's merge bypasses required checks unless
  `enforce_admins` is on.
- Real REST shapes were read (GET only) from the current repository: `GET repos/{r}` carries `default_branch`,
  `security_and_analysis.{secret_scanning,secret_scanning_push_protection}.status` and `allow_auto_merge`;
  `GET .../branches/{b}/protection` answers 404 `Branch not protected` when unprotected;
  `GET .../private-vulnerability-reporting` answers `{"enabled": bool}`;
  `GET .../actions/permissions/workflow` answers `default_workflow_permissions`, `can_approve_pull_request_reviews`;
  `GET repos/{r}/teams` answers `slug`, `permission`, `privacy`.
- `gh api --include` prints the status line and headers before the body, which gives the HTTP status for a 404
  without guessing from stderr.
- The PR body of `work.py pr` is `Closes #398` on the default branch, and the merge path closes the issue. Item 4
  is owner-gated, so the issue is reopened with a comment after the merge.
- Write-surface inventory: the verifier is Python that shells out to `gh api --method GET`; the scanner only
  flags writes, so no inventory row is expected. Run `write_surface.py check` to confirm.
