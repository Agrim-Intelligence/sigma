# Research: #233 — Loop mirrors Priority and Phase to board fields on every status write

**Goal**: #233 · **Date**: 2026-09-29 · base `origin/main` (contains #235 `board_setup.py` + `tests/boardfake.py`, #232 done-means-merged).

  - `_set_board_status` (every Status write: `mark_in_progress`, `mark_qc`, `complete`, `mark_blocked`, `_offboard`,

  - `_ensure_board` -> `_ensure_status_field` -> `_ensure_priority_field` (creates Priority ONLY on a board Sigma created,

  - `_find_field` is exact-name only; `_load_items` flattens single-selects under the LOWER-cased field name (gh shape).

## Findings

1. **Priority default for unlabelled.** The issue says "P3 when unlabelled". The kit's rule is the opposite:
   `discovery.UNPRIORITISED = len(PRIORITIES)` sorts AFTER P4 (#698 backward-compat hinge), and README "Priority: the
   field decides" says "An issue with neither is left alone rather than blanked". Writing P3 onto an unlabelled card
   would (a) reorder the board queue (`_card_rank` reads the field first: unlabelled would jump ahead of every P4) and
   (b) trigger `_mirror_priority`'s field-wins correction on the next sync, writing `priority:P3` LABELS onto every
   unlabelled goal. Both are behaviour changes nobody asked for.
2. **Phase is known only at a boundary.** A Status write (pick/QC/done) does not know the phase; `phase_report.py start`
   does, is called exactly once per phase from Sigma's own Python on every host (SKILL.md), and is the issue's named hook.
3. **Cost of `_ensure_board` from a boundary.** It links the repo, reads the whole goal backlog over REST and may
   item-add/seed many cards (`_sync_backlog`) — O(backlog) per call. Too heavy for a per-boundary hook; the boundary
   path needs its own light resolve: project list, field list, item list.
4. **Board #17 was hand-made** (not `created_now`), so today it gets no Priority field from the loop at all.
5. **`gh` has no timeout** in `sources._run_gh`; a boundary hook must not be able to hang a phase start.
6. `gh project item-list --format json` already carries each issue card's `labels` (plain strings; `_priority_name`
   normalises both shapes) and every single-select value under the lower-cased field name — so the boundary needs no
   separate issue read for the label.

## Constraints

Fail-open (never change a pick's or a start's exit code); exactly one warning per run for a field that cannot be
created/written; Status semantics untouched; no rename/recolour/drop of any existing option; portable; NO real GitHub
mutation during this goal (acceptance on the fake; the board #17 run is an owner runbook).

## Size

Medium: ~150 lines in `sources.py`, ~60 in `phase_report.py`, one new test module, docs + CHANGELOG.
