## Goal in one paragraph

Provide the read-only resource preflight that the accepted B4 inventory design requires. Gather native available-memory facts, constrain them by visible cgroup-v2 ancestors and finite POSIX address-space limits, derive decode/record/output ceilings and worker slots, check an existing output volume and return a reproducible receipt. Do not implement the Git reader, language scanners or scale fixture builder.

## Constraints and unknowns

- Use Python 3.10-compatible standard library only, matching the repository matrix.
- Linux cgroup-v1 accounting refuses. A cgroup-v2 mount whose root is not the hierarchy root cannot prove all ancestor limits and refuses. Any inaccessible or ambiguous mapping refuses.
- macOS host_statistics64 uses the SDK's stable VM statistics layout; release the acquired host Mach send right. Finite RLIMIT_AS uses the revision-0 TASK_VM_INFO prefix.
- Windows uses MEMORYSTATUSEX and GetDiskFreeSpaceExW via checked ctypes signatures. Native Windows and Linux execution are not available on this macOS machine; the revised plan obtains their real documented-gesture receipts through narrowly scoped CI jobs and withholds completion until those receipts pass. Local fixtures remain explicitly separate evidence.
- The receipt is a point-in-time capacity calculation, not an OS memory reservation or a promised scan timing. Later callers must enforce the ceilings and account for parser/AST allocations separately.
- Contract review is required for the new public CLI/receipt. No auth/data migration boundary is touched.
- Blocking questions: none. Reserve fraction and observed encoded record size are explicit required caller inputs, not new fleet defaults.
