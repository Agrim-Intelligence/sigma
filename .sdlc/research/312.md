# #312 research -- a declined verify command parks every github-mode merge; the empty blocking lane sleeps ~3s per pick

**Size: small.** Three source files (state.py, work.py, loop.py aliases; sources.py), one tool
(tools/onboarding_control.py), tests, docs. No schema, no config key, no caller contract changes.

## 1. The defect, located
- `work.py merge` (~5110 before) called `state.done_refusal(sdlc_dir, goal)` unconditionally and
  returned `PARK: no fresh verify evidence for this run (...)` on any refusal.
- `loop.py verify` with no command declared exits 3 (NO-COMMAND) and writes NO evidence file.
- The github scaffold on a declined verify question writes `verify: {command: "", enforce: false}`
  (verify_detect.write_verify / unconfirmed_why), and README says declining "leaves it off".
- So: github mode + declined verify => every merge parks, forever, on evidence no gesture can make.
  `tools/onboarding_control.py` github/no-command avoided it by passing `--local-only`.
- `loop.py record done` gates on `_enforce_enabled(verify)` only (off here, so no demand) -- the two
  gates disagreed on the same configuration.
- docs/enforcement.md row "Verify evidence before a merge" said "whether or not `verify.enforce` is
  set" (generated from work.py ENFORCEMENT_GATES).

## 2. Decision (recorded; nobody available to ask)
The issue offered two options: (a) merge proceeds with enforce off and no command, or (b) init
refuses to leave work on without a command. (b) contradicts the README's documented decline path
and would make github mode unusable for a repo with no tests. Chosen: **(a)**, with the safety half
kept exactly:
- evidence REQUIRED iff `verify.enforce` is on (read generously, F17/#342) OR a verify command is
  declared (goal frontmatter `verify_command`, else config `verify.command`) even with enforce off.
- the command half keeps the pre-#312 merge contract ("whether or not enforce is set") whenever
  there is something to run; only the unsatisfiable case (nothing to run, nothing enforced) changes.
- ONE rule: `state.verify_required(config, goal)`. `enforce_enabled` and `declared_verify_command`
  moved from loop.py into state.py (loop.py keeps aliases; doctor.py's standalone restatement and
  its parity test are untouched). `record done` keeps gating on the enforce half -- widening it to
  the command half would make `verify.enforce` meaningless whenever a command exists (a product
  redesign, out of scope); with work on, `record done` needs a merged PR, and the merge applied the
  whole rule, so the merge never requires less than `record done`.
- A park with enforce on and no command names the `verify_detect.py` fix (state.verify_set_hint,
  the same text as loop.py's `_VERIFY_SET_HINT`, now built from it); otherwise it names
  `loop.py verify <sdlc> <goal>`. The `no fresh verify evidence` prefix is kept: loop.py's park
  reason classifier keys on it (`no_evidence`).

## 3. The blocking lane sleep
- `_blocking_priority_pending` calls `_fetch_pending([blocking_label], ...)`, whose empty-read branch
  retries 3 times with 1s + 2s backoff (#447's insurance for the PRIMARY backlog read).
- The blocking lane is an overlay that is empty almost always; failed and empty both fall through
  to the same full pool. Measured with a fake runner (stock github config, empty blocking lane,
  one goal): `next_pending` 3.005s wall.
- Fix: `_fetch_pending(..., retry_empty=True)`; the overlay passes False. Only the successful-empty
  branch changes; a raised read (transient) is still retried, and the unresolved-assignee retry is
  untouched. After: 0.000s on the same measurement. The backlog's own empty retry is unchanged.

## 4. Blast radius
- Tests relying on "no evidence parks" under configs with no command/enforce: test_work.py
  `test_merge_refuses_without_fresh_local_evidence`, `..._evidence_from_a_previous_run`,
  `..._a_failing_verify`, `test_a_park_before_the_merge_never_closes_its_issue`. Their intent is the
  evidence gate, so they now declare a command (ALWAYS_VERIFIED) -- same assertions.
- onboarding control: github/no-command now drives the confirm flow; check_no_command loses its
  github branches; new check_github_no_command; review-gate assertion tightened to require
  `sigma:block` in the park (else an evidence park satisfied it spuriously).
