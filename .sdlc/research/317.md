# #317 P2 RESEARCH — board recovery and retry control

`board_setup.create` computes `pinned = number if number is not None else proj.get("number")`. Omitting `--number` therefore reuses the configured board. The current recovery advice in `docs/board-fields.md` and CHANGELOG promises a new board without removing that pin. Removing the number alone also meets duplicate-title refusal if the old board already has the default SDLC title. The corrected procedure must clear the pin and pick an unused title explicitly; choosing to keep the old board uses `mirror_priority: true` instead.

The fake already supports real `board_setup.main` through an injected GitHub runner and exact owner/number markers, so the acceptance control needs no network mutation. Existing board/card state must remain unchanged when creating a different board.

`GitHubSource._resolved_repo` timestamps failures with `time.monotonic()` and retries at `_REPO_RETRY_S` (300 seconds). The existing test changes that constant to zero and then a billion, proving a policy swap instead of time passing. A controlled monotonic clock pins behavior before, at, and after expiry.

The final #308 code rejects bare-number marker upgrades, while its saved plan/research still describe the abandoned upgrade. Correct those records explicitly rather than claiming the rejected design shipped.
