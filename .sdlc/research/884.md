## What exists today
- `evals/regression/` holds `record.py` (builder, schema `sigma.regression-run/v1`), `check.py` (checker), `properties.json` and `fixtures/`. There is no `__init__.py`, and no `live.py` and no README in that directory. Siblings load each other by path with `importlib.util.spec_from_file_location` (see `check.py` loading `record.py`, and `record._load_scripts`), so `live.py` should do the same for the scrubber. It should not import `record.py` just for its loader.
- `sigma.regression-result/v1` appears in no code in the worktree. It is defined only in the 810 design ("Result schema" paragraph). Fields there: `schema`, `commit`, `cell`, `credential_basis`, `permission_mode`, `status` (GREEN/RED/FLAKY/WARN/NOT RUN), `reason`, `model`, `belt`, `cap`, `tokens`, indicative-or-real `cost`, `started`/`finished` UTC. The row never carries model output or any environment value. #819 (upload) and #820 (reader) consume it, so field names set here are a contract. Sibling issues #819 and #820 were not read (kept `gh` calls minimal); the planner should check them for field-name expectations.
- Shared scrubber: `skills/sigma-loop/scripts/scrub.py`, API `scrub(text)`, which is shape-based and best-effort by its own docstring. It also exposes `SHAPE_RULES`. Important behaviours for AC-4:
  - It redacts `sk-ant-...`, JWTs, `Authorization:` lines, and any `token|secret|password|api_key ...[:=] value` assignment (suffix rule, min 4 characters). A planted value inside `TOKEN=<value>` would be redacted by the scrubber even with exact-value redaction broken, so the control would pass vacuously.
  - The planted unknown-shape value must therefore appear in plain prose or after a key the scrubber does not match (for example a `--note <value>` or free text), and the red control is "exact-value redaction removed, planted value survives".
  - It returns the input unchanged when the input is empty.
- Refusal-line precedent: `<prog>: REFUSED [<code>]: <detail>` on stderr, exit 2, nothing on stdout (`skills/sigma-prd-intake/scripts/intake.py`, `tools/build_public_tree.py`, `skills/sigma-loop/scripts/render.py`, `skills/sigma-loop/scripts/autowatch.py`). Use `live.py: REFUSED [<code>]: <detail>`. `evals/bench/bench.py` uses an unbracketed `bench.py: REFUSED: <text>`; `evals/regression/check.py` also uses unbracketed. The bracketed form is the one the output contract and AC-1 name.
- Atomic result-file writing idiom to copy: `evals/regression/record.py::write_atomic` (mkdir parents, temp name with pid, `Path.write_text`, `os.replace`, unlink in `finally`).
- CI and platform reading conventions:
  - `evals/bench/bench.py::_truthy` treats `""`, `0`, `false`, `no`, `off` as falsy; `CI` is read through it. `bench.py` refuses any CI run outright, which is different from this entrypoint's behaviour.
  - Platform is read as `os.name == "posix"` (`evals/bench/arms/common.py` `IS_POSIX`, the launcher `os.name != "posix"`); `sys.platform == "win32"` appears in `evals/golden/verify.py`.
  - `GITHUB_EVENT_NAME` and `GITHUB_ACTIONS` are read nowhere in code today (design D-12). Event names to refuse per the design: `pull_request`, `pull_request_target`, `pull_request_review`, `pull_request_review_comment`; also refuse when `GITHUB_ACTIONS` is truthy and `GITHUB_EVENT_NAME` is unset or blank (fail closed).
  - The credential variable names that exist: `CLAUDE_CODE_OAUTH_TOKEN` (subscription; the only one the benchmark launcher allows) and `ANTHROPIC_API_KEY`. The opt-in variable name and the cap flag/variable have no precedent. The design only gives `SIGMA_REGRESSION_LIVE=1` as an example. `SIGMA_BENCH_*` is the sibling prefix and is stripped by `arms/common.py`.

## Design for the module (from the design plus owner rulings)
Ladder order, first failing code printed on stderr and in the row, all failing codes may be recorded in the row `reason`:
1. `no-credential`: neither `CLAUDE_CODE_OAUTH_TOKEN` nor `ANTHROPIC_API_KEY` set to a non-blank value. The check never echoes a value; the row carries only a basis (`api-key`, `subscription`, `none`).
2. `no-opt-in`: the opt-in variable absent or falsy.
3. `no-cap`: cap (dollars) and belt (dollars) absent, non-numeric, non-finite, zero or negative. Reject `bool`, `nan`, `inf`, hex and exponent-overflow strings; parse with `float` and `math.isfinite`.
4. `unsupported-platform`: `os.name != "posix"`.
5. `pull-request-event`: per the event list above and the fail-closed rule.
6. `subscription-in-gated-mode`: gated = `CI` or `GITHUB_ACTIONS` truthy (using the `_truthy` semantics) or an explicit release-gate flag; basis subscription (only the OAuth token set, or ambiguity rule when both are set) while gated is refused. The planner must decide the both-set case (see decisions).
- Argparse with **no required arguments**; `--help` handled before the ladder; unknown flags should also reach a deliberate result, not an argparse exit-2 usage message that looks like a refusal (argparse exits 2 on bad flags, with a different stderr; keep this distinct and test it so a typo is never read as a refusal row, or reuse a `bad-usage` code).
- Every refusal writes one `sigma.regression-result/v1` row, `status: "NOT RUN"`, to the results directory (default `.sdlc/eval/results/`, overridable by flag), and all text written to stderr, stdout and the row passes through exact-value redaction of the held credential(s) first, then `scrub.scrub`. Stdout stays empty on refusal.
- Edge: a row write failure (unwritable directory) must not swallow or change the refusal; still print `REFUSED` and exit 2, and add a second stderr line saying the row was not recorded.
- After the ladder passes, slice 1 has nothing it may run. It must not start a model. The planner should pick one deliberate terminal behaviour (suggested: `REFUSED [not-implemented]`, exit 2, NOT RUN row), rather than exiting 0 with nothing done, which would read as a pass. State it in the docstring.

## Test plan facts (`tests/test_regression_live.py`)
- Run the **documented gesture**: `python3 evals/regression/live.py` as a subprocess with `sys.executable`, no extra flag, the way `tests/test_regression_check.py` does (AGENTS.md: run the control on the gesture the docs give). The AC-5 reds must be shown on that gesture.
- **Environment trap (largest practical risk).** GitHub-hosted runners export `CI=true`, `GITHUB_ACTIONS=true` and `GITHUB_EVENT_NAME=pull_request`, and a developer shell may hold a real `CLAUDE_CODE_OAUTH_TOKEN`. A subprocess test that copies `os.environ` changes behaviour on those hosts: the bare-invocation test would hit a different rung, a real token would be present. Build the child environment from an allowlist (`PATH`, `HOME` set to a temp dir) and add only the variables each case needs. Pin this with a test that runs the bare gesture with the hostile variables present in the parent.
- Cwd: a cwd-relative default results directory lets the bare AC-1 test run in a temp cwd by absolute script path and inspect `.sdlc/eval/results/` there, with no pollution of the real tree. If instead the default is repo-root-relative, the bare test would write into the worktree's ignored `.sdlc/`. Decide in the plan; cwd-relative is easier to test hermetically.
- Platform rung: a subprocess cannot fake `os.name`. Needs an in-process seam (a small `platform_is_posix()` function called by the ladder, tested by calling the ladder function with an injected environment and platform), plus the real Windows step later (slice 4; `.github/workflows/windows.yml` is dispatch-only).
- AC-4 control: plant a held credential of a shape the scrubber does not know, built at run time (for example a fixed prefix concatenated with `os.urandom(16).hex()`), arrange for it to land in a log line and in a row `reason`, assert it is absent from stderr, stdout and the row file, and that `scrub.scrub` alone would have left it (assert that precondition, otherwise the test proves nothing). Cover raw, URL-encoded, base64 and quoted forms if the module redacts "common encodings" (design D-11); short values must not be redacted globally (a one- or two-character fake would shred all output), so fix a minimum length and test a below-minimum case explicitly.
- AC-5 reds, each seen failing with its guard broken, then green: unset credential (guard: the no-credential rung removed), unknown-shape planted credential (guard: exact-value redaction removed), pull-request event (guard: the event check removed). Record the red runs in a controls dossier like the sibling goals do (`.sdlc/research/<n>-controls.md`).
- Never-starts-a-model: assert statically that `live.py` imports none of `subprocess`, `pty`, `multiprocessing`, `os.exec*`/`os.spawn*`/`os.system`, nor `evals/bench/arms` (an `ast` walk, in the style of `tests/test_no_unsupervised_process_pause.py`), and dynamically that a fake `claude` placed first on `PATH` that writes a marker file when invoked is never run on any rung or on the terminal path. Neither check needs a real credential: use fakes.
- Ladder-order test: one parametrized table that sets the full environment, then breaks one rung at a time from the bottom up and checks the first failing code, and a case with several rungs broken at once proving the earliest wins.
- `tests/conftest.py` only guards `subprocess.run` against `gh`; it does not interfere.

## Risks (ranked)
1. **Hostile ambient environment** (CI variables, a real token in the developer shell) silently changes which rung fires, or lets a test see a real credential. Mitigation: allowlisted child env plus the hostile-parent test above. This also serves the rule that nothing here reads or prints a real credential value.
2. **A vacuous redaction control.** The shared scrubber already catches many shapes and any key-assignment shape, so a test that plants its value in an assignment or an `sk-ant-` shape passes even when exact-value redaction is deleted. The control only counts if the shape is unknown to the scrubber, the precondition is asserted, and the guard is broken once and seen red (AGENTS.md "run the control").
3. **Unspecified terminal behaviour and unfixed names.** The design leaves the opt-in variable, the cap and belt flag names, the results-file naming, and what happens after the ladder passes undecided; #819 and #820 will read the row. Pin them in the plan; otherwise a later slice renames a contract field. Also, silently exiting 0 after the ladder would be a half-guarantee.
4. Inventory ratchet drift: the new write sites must be added to `docs/launch/write-surface.json` and the rendered `.md` in the same change or `test_committed_inventory_matches_the_tracked_write_surface` and the CI ratchet go red; `open(..., "a")` writes are invisible to it, so use only the atomic idiom here.
5. Argparse exit 2 on unknown flags collides with the refusal exit code (design D-10 notes the same collision for the launcher).
6. Python 3.9 locally versus 3.10 floor in CI: syntax and stdlib choices must work on both.

## Decisions the plan must make
- Names: opt-in variable (design example `SIGMA_REGRESSION_LIVE=1`), cap and belt flags and variables in dollars, release-gate flag, `--results-dir` flag.
- Both credentials set at once: which basis is recorded and whether gated mode refuses on the subscription token alone or on any subscription token presence. Suggest basis is the one the run would use and, since this slice builds the subscription path only, `subscription-in-gated-mode` fires whenever the OAuth token is set and no API key is.
- Default results-directory anchor (cwd versus repo root) and row filename scheme (UTC timestamp plus pid, never overwrite).
- Terminal behaviour after the ladder passes (suggest `REFUSED [not-implemented]`).
- Whether slice 1 records only the first failing code or all failing codes in the row.
