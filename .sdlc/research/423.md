# Research — #423 managed policy vs. local file deletion

## Blast radius
- `managed_settings.read()` returns `not-adopted` when `.sdlc/managed-settings.json` is absent
  (`managed_settings.py` ~line 129). `gated_check` short-circuits on `is_adopted()` False, and
  `is_adopted` is "config declares `project_id`" OR "file exists". A declared project_id with
  the file deleted still reads `not-adopted` and `allowed: True`.
- Callers: `work.effective_review_mode` (merge gate), `work.effective_hard_plan_gate_locked`
  (pr gate); both already treat `allowed: False` as a refusal, so a new refusing status needs no
  change there. `ledger.journal_on` treats REFUSING_STATUSES as journal OFF via a stat-keyed
  cache (`_managed_read_cached`); a missing file has fingerprint None, so it is never served stale.
- `doctor._managed_settings_state` is a deliberate duplicate that reports `absent`.
- `hooks/plan_gate.sh` mirrors `read()` in inline Python (accelerator, Claude-only; `work.py pr`
  is the load-bearing, host-agnostic check). Left unchanged; documented.
- `tests/test_script_help.py` lists `managed_settings` as LIBRARY_ONLY (no CLI).

## Enrolment memory: where
- `.sdlc/*` is gitignored except named subdirs; `.sdlc/state/` is local runtime state.
- A marker beside the file would die with it; a second marker outside `.sdlc/` survives a
  deletion of the file or of `.sdlc/state`: the per-checkout git dir (`.git/` or the linked
  worktree's `.git/worktrees/<n>/`), found by walking up for `.git` without a subprocess (the
  reader's own rule: no subprocess). Both live in Sigma's Python / git state, no host hook.
- Marker written best-effort when `read()` parses a valid file (status ok or access-revoked).
  Presence-only check, so a truncated marker still counts (fail closed).

## Residual
Anyone who can write the checkout can delete both markers or run the lever. This raises a
one-file deletion (or deleting `.sdlc/`) from silent bypass to a refusal; it does not bind a
user with checkout write access. Declared-but-never-seen policy (fresh clone) stays not-adopted
so an enrolled repo's fresh clone is not an outage.
