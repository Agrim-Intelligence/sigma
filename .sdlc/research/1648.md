## Design for the build (recommended)
New module `skills/sigma-loop/scripts/codex_cli.py` (standalone, stdlib only, importable by path like codex_runtime; doctor loads siblings via `_load_loop_script(name)` l.1085). Public: `resolve(env=None, which=shutil.which, app_path=APP_PATH) -> str` raising `CodexCliError(ValueError)` with a typed reason (`not-found`, `override-invalid`, `ambiguous`). Order: `SIGMA_CODEX_BIN` (must be absolute, a file, `os.access X_OK`; invalid -> REFUSE, never fall through) -> PATH (`which` using env PATH) -> app path. Ambiguity: PATH hit and app path both executable and `os.path.realpath` differ -> refuse naming both. Same realpath (symlink) is one copy. Env-override wins without consulting others (an explicit override is not ambiguity). Make `app_path` an injectable parameter so tests never touch /Applications. Add `skew()` helper (pure compare of two version tuples) so supervisor and doctor share the comparison but differ in severity.

Wiring:
- `installed_skill`: replace l.199-201 with `codex_cli.resolve(env)`; keep `codex_executable=` param as explicit test seam. Return value unchanged.
- supervisor `_codex_main` (after l.390): skew check = running plugin.json version vs inventory entry version; refusal prints `supervisor: Codex preflight refused: ...` and returns 2 (existing path l.391-393 catches ValueError, so raising ValueError inside installed_skill or a new `codex_runtime.check_skew(entry_version, own_version)` slots in with no new control flow). Needs installed_skill (or a sibling) to expose the entry version; do not change the 2-tuple return that three callers unpack: add `installed_version(env)` or have resolve_install attach it, decide in plan.
- doctor: `_codex_plugins` uses resolver (argv[0] = resolved path; on `CodexCliError` return None so existing "unverified" rows fire, plus a specific row naming ambiguity/invalid override). In a Claude session `codex_plugins` is None (l.2938 gate), so the skew row needs its own guarded Codex read when the resolver finds a CLI; skip under cheap_only (spawns a CLI).
- reviewer.py: use resolver (see 4).

### SIGMA_CODEX_CMD vs SIGMA_CODEX_BIN (no third name)
Different jobs: BIN = which binary (used for inventory + default launch); CMD = full launch argv prefix (flags). Keep both, define precedence: CMD, when set, decides only the launch argv (unchanged, l.437-451). BIN/PATH/app decides the binary for `plugin list` and for the default launch. Reconcile the hole: today CMD="codex exec" still needs PATH for inventory. Recommended: when CMD is set and its argv[0] is a bare name resolved nowhere on PATH, nothing changes (BIN/app path serves inventory); when argv[0] is the bare word `codex` and BIN/app resolved a path, substitute the resolved path for argv[0] so an app-only machine can run with CMD="codex exec ...". Absolute argv[0] in CMD is respected as-is. Existing test at tests/test_codex_runtime.py:508 uses CMD="codex exec" with fake on PATH: must stay green. Owner confirmation worth requesting only if the substitution is judged surprising; it is a default-and-flag candidate, not a Block C.

## Constraints
- Host-agnostic: resolver is plain Python in sigma-loop/scripts, no hook.
- SAFETY: refuse loudly, never fall through from a bad override to PATH. Windows/Linux: app path only checked when `sys.platform=="darwin"`; elsewhere rung is skipped (not an error).
- Resolver must not execute the candidate to "answer" (existence + X_OK only); `--version` probing costs a spawn per call and the supervisor re-resolves every launch.
- Supervisor revalidates executable each launch (l.431): resolver must be deterministic; ambiguity appearing mid-run is a refusal, correct.
- Codex supervisor path must not dirty the verified install (no bytecode): the new module is loaded by path from codex_runtime-like code with `dont_write_bytecode` already set (supervise_daemon.py:84-95); load `codex_cli` the same way `_codex_runtime()` does (l.98-104), or import it from inside codex_runtime via spec_from_file_location. Plain `import codex_cli` risks writing __pycache__ in the Git install and failing `_clean_git_head` (existing tests 227/244 guard this).
- AGENTS.md: every guard broken once per clause via its documented gesture; each of the 7 clauses plus ambiguity-same-realpath and relative-override needs a red.
- Scalability: resolver is O(1) stat calls; no ceiling.

## Risks
1. Existing supervisor tests all break on skew (fixture version 1.0.3 vs 1.0.15). Highest risk; see above.
2. Doctor test runner exact-argv match breaks when argv[0] becomes absolute.
3. Ambiguity false positive: PATH copy being a symlink/wrapper to the app binary. Mitigate with realpath compare; an npm shim that execs the app binary would still look "different"; acceptable (refuse, name both, override fixes it) but document the lever `SIGMA_CODEX_BIN`.
4. Claude-session doctor reading Codex inventory spawns a CLI; keep out of cheap_only and bound by the existing runner timeouts.
5. App path is a single hardcoded string for one product layout (ChatGPT.app); a renamed bundle is not found - falls to not-found, with fix text naming SIGMA_CODEX_BIN.
6. Reviewer wiring scope creep vs B1 ownership.
