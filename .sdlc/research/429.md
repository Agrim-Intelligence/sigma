## gh redirection
- `gh api` with an explicit `repos/O/N/…` path spawns no git (GIT_TRACE file not written when run
  inside a repo with origin set), so GIT_* is irrelevant to gh; scrubbing it is harmless.
- `--hostname` beats `GH_HOST` (GH_HOST=evil.example still hit api.github.com); GH_REPO only fills
  `{owner}/{repo}` placeholders; old removes both. An `aliases: {api: …}` entry does NOT override
  builtin `api`. `HTTPS_PROXY` is honoured ("proxyconnect tcp: dial tcp 127.0.0.1:9"); MITM also
  needs a trusted CA (`SSL_CERT_FILE` on Linux) — not measured.
- `http_unix_socket: <sock>` in `$GH_CONFIG_DIR/config.yml` (default `~/.config/gh`, or
  `$XDG_CONFIG_HOME/gh`) routes the request to a local socket: a 20-line Python server answered
  `GET /repos/victim/widget/issues?…` with `[]`, gh exit 0, stdout `[]`. Neither old nor wip
  touches GH_CONFIG_DIR, so the blocker clause is forgeable by a config file (G1).
- Tokens only authenticate; a non-github.com host goes to `https://HOST/api/v3` (measured).

## Committed-tree read: design facts
- Resolve main exactly: `git show-ref --verify --hash refs/remotes/origin/main` (rc 128 when the
  ref is absent even if `refs/heads/refs/remotes/origin/main` exists). Do NOT use `git rev-parse
  --verify refs/remotes/origin/main^{commit}`: with the real ref deleted it resolved to
  `refs/heads/refs/remotes/origin/main` (= HEAD 4f54a8f6). `show-ref` follows symrefs (X2): detect
  with `git symbolic-ref -q refs/remotes/origin/main` (rc 0 = symref). Then peel
  `git rev-parse --verify -q <40-hex>^{commit}` (a full hex is taken as an object id). `rev-parse
  --end-of-options` works on 2.39.5.
- Read a file: `git --no-replace-objects --literal-pathspecs ls-tree -l -z <commit> -- <path>` →
  `100644 blob <oid> <size>\t<path>`; symlink `120000 blob`; directory `040000 tree <oid> -`;
  missing → empty output, rc 0. Then `git cat-file blob <oid>` (no filters applied; a non-blob id
  fails "bad file"). Size from `-l` allows a cap before reading.
- Once scorecard, definition, evidence and benchmark come from the pinned commit, the working tree
  is not needed: drop `hash-object` (old:338; source of A1-A3), the checkout symlink check
  (old:333-337) and the evidence "exists in working tree / resolves inside" check (old:240-249,
  the only `Path.is_relative_to` use). Mode 100644/100755 + size>0 at the commit is the check.
  `rev-parse --show-toplevel` remains as the anchor.
- No origin/main in PR CI (measured from job logs): pull_request job 110235346230 ran
  `git fetch … --depth=1 origin +73d476b…:refs/remotes/pull/382/merge` only; push job 110523640929
  ran `… +29a4277…:refs/remotes/origin/main` (depth 1). Locally, origin/main has
  `docs/launch/definition.json` but no `scorecard.json` until this PR merges.
- Affected tests: `test_shipped_scorecard_is_valid_and_nothing_is_scored_yet` runs the SHIPPED
  card via subprocess on ROOT: under committed reads it depends on the CI event and on merge
  state. Static scan of the old test file: 19 test functions use `git=False`/`commit=False`,
  delete origin/main, or write card/definition after building; 4 duplicate-key tests and
  `test_missing_scorecard_is_malformed` write AFTER the commit and would silently read the clean
  committed copy; `_cannot_verify` (11 callers) encodes "no main ⇒ exit 1 NO-GO".
- Pre-merge, the real-repo gesture cannot show "NO-GO, exit 1" (main has no scorecard); old on a
  scratch merge of main+PR printed NO-GO exit 1 only because it read the working tree.

## Optional REST main-sha check
- `gh api repos/O/N/git/ref/heads/main` → 346 bytes, `{"ref":"refs/heads/main",…,"object":
  {"sha":"29a4277…","type":"commit",…}}`, 0.53 s; equals local origin/main 29a4277. Exact match:
  `git/ref/heads/mai` → 404. Alt: `repos/O/N/commits/main -H 'Accept: application/vnd.github.sha'`
  → bare sha, 0.48 s (plain `commits/main` is 44,862 bytes; resolves any ref named main).
- Cost: one call. Failures (must be exit 2): 404 no access / branch renamed, 401/403/429, network;
  409 on an empty repo (not measured). A stale checkout refuses until `git fetch` (liveness cost).
- Closes X1, X2, X3 (all measured GO today). Also the planned rename: definition.md says once the
  private repo is renamed and the public one created, `Agrim-Intelligence/sigma` names the PUBLIC
  repo, so a stale origin URL would read the public repo's (empty) blocker list; its main sha
  differs, so the check refuses (reasoning, not measured).
- Applies only to the live path: `--blockers-json` (the gesture the reproductions use) makes no
  REST call, so X1-X3 stay GO offline unless the check runs there too.

## Open questions for the planner
1. Threat model: ambient-only (env, global/system config, ambiguous names) or also deliberate local
   state (update-ref, symref, set-url, local filter/autocrlf)? X1-X3 need the REST check.
2. Exit semantics: ignore ambient state and compute (exit 1, as wip) or detect and refuse (exit 2,
   or a new code that changes the documented exits)? The acceptance says "refuses … distinct exit".
3. No origin/main, or scorecard absent at main: exit 2 or NO-GO 1? 11 `_cannot_verify` tests and
   the PR-CI behaviour depend on it.
4. Drop the checkout byte-identity rule (committed tree only) or keep it via
   `hash-object --no-filters`? Is that sentence of decision-rule.md "the GO rule"?
5. Config disable: `GIT_CONFIG_NOSYSTEM=1` + `GIT_CONFIG_GLOBAL=os.devnull` (+ git ≥ 2.32 check,
   refuse below) vs `HOME`/`XDG_CONFIG_HOME` override; accept the safe.directory refusal.
6. gh config (`http_unix_socket`), proxies and PATH: document as trust roots, or isolate
   `GH_CONFIG_DIR` (loses stored auth) / refuse when `gh config get http_unix_socket` is set?
7. Offline `--blockers-json`: the blocker clause is whatever the file says; label it (info line)
   given the GO rule is out of scope?
8. Print `info:` lines naming host/OWNER/NAME read and the main sha used (visibility after rename).
9. Partial clones: `GIT_NO_LAZY_FETCH=1` and/or `-c protocol.allow=never` on every git call.
10. Replace the subprocess-on-ROOT shipped-scorecard test with in-process validation of the file.
