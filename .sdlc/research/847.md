## Findings

### 1. red_green and witness: what exists, and what a safe extension looks like

- `red_green.observe` (`red_green.py:132-188`) runs `python3 -m pytest -q -rA --tb=short --color=no --rootdir=<root> <nodes>`
  once, parses ONLY the text after the last `short test summary info` banner (`:153-154`), and writes a
  witness row for a node only when its `FAILED` reason starts with `AssertionError`/`assert` (`:169`) or a
  traceback block shows `E AssertionError|assert` (`:97-129`). An ImportError inside a test body is a
  `FAILED` node (measured, exit 1, reason `ModuleNotFoundE...`), but `observe` gives it no red. That is
  PC-4 in the design and it is why a second provenance is needed.
- `collect` (`:72-81`) raises `ValueError` on any non-zero `--collect-only` exit, so a collection error is
  already a generic refusal, but it does not name the file. Sealed needs a named refusal (AC: "refuses a
  collection error", "naming the test" for the pass-on-base clause).
- `refusal` (`:195-230`) credits a red only when `row.provenance == PROVENANCE` (`:222`), `kind == 'assertion'`
  and `file_hash` matches. So rows tagged `sealed-pytest-v1` can never satisfy the planned-test gate. This is
  the property that makes a purely additive extension safe. A control for it: append a sealed row and see
  `refusal` still say "no matching assertion red before green".
- `witness.verdict` (`witness.py:189-222`) ignores provenance. A sealed row with kind `assertion` would be
  credited as STRONG in `loop._witness_verdict` (`loop.py:5656-5687`). That is truthful for a real assertion
  failure, but it is a cross-contamination to know about.
- `witness.classify` (`witness.py:61,130-142`) labels any text matching `ImportError|ModuleNotFoundError|NameError`
  as `collection-error`, checked FIRST. Using it for sealed would call an in-body ImportError a
  "collection error", the exact thing D-1 says to accept. Sealed must classify by pytest outcome, never by
  `witness.classify`.
- `witness.record` (`:145-162`) never raises and returns `None` on `OSError`. Sealed must check the return
  value and refuse if any red row failed to persist (a silently lost red is a false seal). `KINDS` is a closed
  enum (`:55`); use existing `assertion` for AssertionError and `other` for any other body failure, with the
  exception class in `detail`. Do not add a kind. Witness rows carry no id (`:150-152`), so "red evidence ids"
  must be minted: sha256 of the canonical row JSON (test, file_hash, observed_at, provenance), first 16 hex.
- `red_green._run` (`:64-65`) is `subprocess.run` with no timeout and the literal `python3`. Callers: `loop.py:5626,5947`,
  `work.py:3863`. Tests inject `run=` (`tests/test_test_first_gate.py:30-52`).

**Recommended minimal, backward-compatible extension.** Leave `selectors`, `collect`, `observe`, `refusal`,
`PROVENANCE`, `_run` byte-identical. Add to `red_green.py` only: `SEALED_PROVENANCE = 'sealed-pytest-v1'` and one
PURE function that classifies a run (inputs: collect-only exit+stdout, run exit+stdout, collected node list;
output: `collection_errors`, `red`, `passed`, `other`). Put all I/O (tree build, run, witness append, seal
write) in `sealed_tests.py`. The pure function is unit-testable with the existing fake-runner pattern, and the
"existing provenance behaves exactly as before" criterion is checked by leaving
`tests/test_test_first_gate.py` (25 tests) untouched and green, plus a diff showing no changed line inside the
old functions.

### 2. Collection error vs test-body failure: measured

Pytest 8.4.2 and 9.1.1 behave the same for these cases.

| Case | `-rA` summary line | Exit | Notes |
| --- | --- | --- | --- |
| `import missing` inside a test body | `FAILED <node> - ModuleNotFoundE...` (reason truncated) | 1 | the run continues; other tests run |
| assertion / `RuntimeError` / `NameError` in body | `FAILED <node> - ...` | 1 | |
| parametrized body failure | `FAILED <file>::t[1] - ...` | 1 | one line per case |
| module-top `from missing import x` | `ERROR <file>` (no node id) | 2 | `Interrupted: 1 error during collection`; NOTHING runs, not even tests in other files |
| syntax error in test file | `ERROR <file>` | 2 | same |
| fixture raises | `ERROR <node> - ...` | 1 | `<error>` in junit, not `<failure>` |
| `pytest.skip` / body `importorskip` | `SKIPPED [1] file:line: reason` (no node id) | 0 or 1 | node absent from PASSED/FAILED |
| `xfail` | `XFAIL <node>` | - | |
| `python3 -m pytest` where pytest is not installed | none | 1 | the same exit code as a test failure |

Consequences for the design:
- The failure reason is truncated to terminal width in the summary, so reason text cannot classify. Classify on
  (a) `--collect-only` exit code first, (b) run exit code 1, (c) per-node membership.
- One collection error in any sealed file blanks the red proof for every file. Run `--collect-only` over the
  overlaid directory first; any non-zero exit or `ERROR <file>` line refuses, naming the files. `red_green.collect`'s
  node filter `if '::' in line` (`:76`) skips `ERROR <file>` lines, so a custom collect is needed to name them.
- Exit 1 is ambiguous with "pytest not installed". Pre-check `<python> -m pytest --version` (rc 0) and require a
  parsed summary, or refuse. Exit 3 (INTERNALERROR), 4, 5 are never red.
- Match nodes by collected id, not by `partition(' - ')` (`red_green.py:166`): an id containing ` - ` in a
  parameter breaks that. Use `line == 'FAILED ' + n or line.startswith('FAILED ' + n + ' - ')` for each collected `n`.
- Exhaustive accounting: every collected node must be exactly one of FAILED (red), PASSED (pass-on-base), or
  other. "Other" (skip, xfail, xpass, setup error, absent) refuses with the node named. Without this, a skipped
  test is neither red nor a pass and would slip through both clauses.
- Honest limit: an in-body ImportError proves "the symbol is missing", not "the assertion checks something".
  Record the exception class per red (from `detail`) so a reviewer can see it; do not try to judge it.

### 3. Atomic write and state-dir conventions (reuse list)

- Seal path `.sdlc/state/sealed/<goal>.json` follows `state/verify/<stem>.json` (`state.py:1226-1231`), with
  `state.unsafe_goal_reason(stem)` (`state.py:1189-1222`) and the stem rule from `work.stem` (`work.py:1340-1345`).
  Reuse; do not re-implement.
- Write with `state.refuse_symlinks(sdlc_dir, rel, create_parents=True)` (`state.py:249-286`, #708) then
  `state.atomic_write_text` (`state.py:1038-1067`: same-dir temp, fsync, `os.replace`, temp removed on failure,
  mode preserved). Other private atomic writers exist (`review_context._atomic_bytes` `:902`, `applier._write_atomic`
  `:138`, `resource_lease._atomic_write`); the `state` one is the public, symlink-aware one. Stated limit: no
  directory fsync, and two concurrent writers race (last wins). Say so; it is idempotent per goal.
- Measured with the probe: calling `state.atomic_write_text`, `state.refuse_symlinks`, `tempfile.TemporaryDirectory`
  and `subprocess.run(["git","archive",...])` adds ZERO write-surface rows. A literal `shutil.rmtree` or
  `Path.mkdir` adds `fs-rmtree`/`fs-write` rows that need entries in `docs/launch/write-surface.json` (CI step
  `ci.yml:60,112,237`). So use `TemporaryDirectory`, not hand rmtree.
- Plan hash: the approving plan-review record is `state/gates/<stem>.json` (`work.plan_review_record_path`
  `work.py:1383`; fields `plan_hash`, `reviewer_route`, `verdict` written `work.py:1457-1463`; `rc.plan_sha256`
  `review_context.py:522-531`). `sealed_tests` must not import `work.py` (cycle, and `_load` sibling style). Take
  `plan_hash` and `route` as parameters, validate 64-hex, store as given.
- `.sdlc/*` is gitignored in this repo (`.gitignore`, ".sdlc/*" block), so a seal in the main checkout's
  `.sdlc/state` cannot dirty the root checkout. In an adopting repo that also holds if `state/` is ignored; the
  slice that wires the verb should name this (AGENTS: nothing left in root that blocks `git pull`).
- Per-goal state growth: one small file per goal, never pruned unless added to
  `goal_state_prune.FILE_FAMILIES` (`goal_state_prune.py:35-36`, a one-tuple add; `tests/test_b6_462.py:264`
  only asserts the families do not overlap other dirs). AGENTS treats unbounded growth as a design-time defect, so
  add `("sealed", ".json")` here or name it in slice 3 with a number: ~1-3 KB per goal.

### 4. Consuming breaker (#844)

- `breaker.validate_output(text, stem)` (`breaker.py:362-413`) is pure and returns `(ok, findings)`; it does NOT
  return parsed blocks. Nothing in `breaker.py` writes files (design step 2 says Python writes them; that is slice 4).
  So slice 2 should take files ALREADY on disk under `tests/acceptance/<stem>/` and re-validate by rebuilding the
  `=== FILE: <path> ===` / `=== END FILE ===` text from disk and calling the public `validate_output`. Verified in
  the probe: a one-test file passes `(True, [])`; a wrong stem gives `path outside tests/acceptance/8-4/`. This
  needs no new breaker surface and gives the AC path rules (`test_acc_<s>_<suffix>.py`, flat dir, <=32 KiB/block,
  <=14 files) for free.
- On Python 3.9 `validate_output` flags any non-pytest module-top import as "cannot classify imports"
  (`breaker.py:340,357-358`). The loop runs on 3.12 (venv); note it for tests that must pass on both.
- The sealed dir must hold ONLY validated files. `validate_output` sees only what is passed to it. The seal must
  also refuse (or the read function must report) extra entries in the directory: a maker-added `conftest.py`,
  `__init__.py`, a symlink, or a subdirectory would change how sealed tests run at green. Use `lstat`; refuse symlinks.
- `_load` sibling-module pattern: `breaker.py:79-87`, `bounded_run.py:61`. Use the same.

### 5. Running tests "on base content": recommended mechanism

- Use `git -C <root> archive --format=tar -o <tmp>/base.tar <sha>` then extract with `tarfile` (use
  `filter='data'` where available) into `tempfile.TemporaryDirectory(prefix='sigma-sealed-')`, then copy the sealed
  files into `<tmp>/tests/acceptance/<stem>/`. Reasons: read-only against the repo (no ref, index or worktree
  metadata change; `git worktree add/remove` writes `.git/worktrees` and matches the `git-destructive` rule in
  `write_surface.py:344`), no `.pytest_cache`/`__pycache__` in any real checkout, and the sealed files are tested
  against BASE content (not the maker's HEAD).
- Measured on this repo: `git archive HEAD | tar -x` = 0.41 s, 38 MB, 2,497 files. No `.gitattributes`, so no
  `export-ignore` surprises (an adopting repo with one would silently drop files; worth a one-line note).
  Scaling: linear in tree size, per seal, seals are rare. 10x = about 4 s and 380 MB; 100x = about 40 s and 3.8 GB, a
  ceiling. Derive a guard from the machine (`shutil.disk_usage(tmp).free` >= ~3x `git ls-tree -r -l` total) and refuse
  loudly rather than fill the disk.
- Resolve the base to a commit sha first (`git rev-parse --verify <remote>/<base>^{commit}`) and RECORD it. The ref
  comes from the work record (`state/work/847.json`: `base: feature/sealed-tests`, `remote: origin`); never the bare
  local branch name (the #2235 lesson, `loop.py:5640-5650`). Pass `remote`/`base` through `state.safe_ref`
  (`state.py:349-366`) before they reach git.
- Run with `bounded_run.run_group(argv, cwd=tmp, timeout, env=..., merge=True, tail_bytes=1 MiB)`
  (`bounded_run.py:366`): own process group, SIGTERM then SIGKILL on the whole group, a lifeline process that
  stops the group if the caller is SIGKILLed, bounded output, and a loud REFUSED on Windows (`group_refusal` `:162`),
  which matches the SAFETY rule. `run_with_timeout.py` is a script wrapper (takes a script path,
  `run_with_timeout.py:51-129`), not usable for `python -m pytest`; `reviewer.py:206-221` and
  `mutation.py:213-231` hand-roll the same kill and are not the best reuse. `run_group` is already used by
  `feature_upkeep_job.py:189`, `feature_upkeep_launcher.py:272,637`. Note `bounded_run`'s own docstring line
  "Nothing in the product calls it yet" is stale.
- Timeout is NOT a module constant (SAFETY: derive). Make it a required parameter; the wiring slice passes
  `verify.timeout_minutes * 60` (`config.json.tmpl:141`, default 60). Collect-only and run share one budget.
- Interpreter: use `sys.executable` (overridable), NOT the literal `python3`. Measured: with this host's
  `/usr/bin/python3` (3.9.6, no xdist) ANY pytest run under `tests/` dies with `INTERNALERROR ... unknown hook
  'pytest_xdist_auto_num_workers'` from `tests/conftest.py`, even `--collect-only` on `tests/test_witness.py`.
  With the venv python the same trivial overlay runs in 0.19 s. So `red_green`'s literal `python3` only works if
  PATH already resolves to the venv. Record `{python, pytest_version}` in the seal. INTERNALERROR (exit 3) must
  refuse, never read as red.
- Environment: start from `bounded_run.unattended_env()` and also drop `PYTHONPATH`, `PYTHONHOME`, `VIRTUAL_ENV`
  pointing at the maker's worktree (otherwise "fails on base" can silently import the maker's code and read as a
  pass); set `PYTHONDONTWRITEBYTECODE=1`, `-p no:cacheprovider`, `--rootdir=<tmp>`, and `HOME=<tmp>`. Residual,
  stated: the sealed tests are model-authored code run with the operator's privileges and no network or syscall
  sandbox. That is the same trust as `verify.command`; do not describe it as isolated.
- Cost per seal (measured pieces): archive 0.4 s + collect 0.2 s + run 0.2 s on the toy overlay; real sealed files
  with the repo's heavy `tests/conftest.py` were not run beyond the trivial case, so total per-seal time is
  UNMEASURED for real breaker output. Slice 5 owns the measurement.

### 7. Size and lane

**Lane: medium.** One new module (est. 250-350 lines), about +60 lines in `red_green.py` (additive only), one
allowlist line, optionally a one-tuple add to `goal_state_prune.FILE_FAMILIES`, one new test file (est. 25-35
tests). No `work.py` change, no registry row, no docs regeneration. Medium rather than small because of the
real-pytest controls (each clause needs a real or faked run seen red), the base-tree builder and the bounded-run
integration. Not large: no cross-module wiring (slices 3-4).

Risks:
1. **Wrong-reason red (D-1).** An in-body ImportError from a typo'd import path reads as red. Mitigation:
   record the exception class per red; the breaker contract (imports inside bodies) is slice 1's.
2. **Re-seal as a laundering lever.** `seal()` has no notion of who wrote the files; re-running after the
   maker edited the dir would seal the edited files. Red-on-base is recomputed against base, so it still
   passes. Bound by D-6 (cap 2, in slice 4) and the commit gate (slice 3). Store a `generation` counter in the
   record now so slice 4 can enforce the cap without a schema change.
3. **Host environment.** Without the venv python, nothing under `tests/` runs (measured). Record interpreter and
   pytest version; refuse on exit 3/4/5 and on a missing summary.
4. **Concurrency.** Two seals for one goal race on the record (last wins) and interleave witness appends. By
   construction one verb per goal holds the claim; no new lock is proposed. State it.
5. **Crash cleanup.** SIGKILL leaves a `sigma-sealed-*` dir in `$TMPDIR` (bounded_run kills the pytest group, but
   not the temp dir). Lever: the OS temp reaper; no sweep proposed (a sweep adds an `fs-rmtree` write-surface row).
6. **Local evidence only.** D-11: all of this is agent-writable; CI/host protection is the real ceiling. A
   modified `tests/conftest.py` on the maker branch can change how sealed tests run at green; red-on-base uses
   BASE conftest, which is the stronger side.
7. **Interface ambiguity in AC-1.** "route" is listed in the record. Design line 144 says "route/host/command".
   Reading used here: `route` = the breaker's reviewer route dict (`{host, mechanism, verified}` as in
   `work.py:1457`), passed in and stored opaque; a separate `proof` block holds the runner facts.

## Proposed seal record (schema `sigma-sealed/1`)

```
{ "schema": "sigma-sealed/1", "goal": "<stem>", "sealed_at": "<iso>", "generation": 1,
  "plan_hash": "<64 hex>", "route": {...as passed...},
  "base": {"ref": "origin/<base>", "sha": "<40 hex>"},
  "dir": "tests/acceptance/<stem>/",
  "files": {"tests/acceptance/<stem>/test_acc_<s>_x.py": {"sha256": "...", "bytes": N}},
  "red": [{"test": "<nodeid>", "evidence_id": "<16 hex>", "kind": "assertion|other", "reason": "<ExceptionClass>"}],
  "exemptions": [{"test": "<nodeid>", "reason": "<non-empty>"}],
  "proof": {"provenance": "sealed-pytest-v1", "python": "...", "pytest": "...", "exit": 1} }
```

Write order (this IS the "atomic and last" clause): validate files -> resolve base sha -> build base tree ->
`--collect-only` (refuse collection errors) -> run -> classify -> append witness rows (check each `record` result)
-> write the seal LAST via `state.atomic_write_text`. A crash anywhere before the final replace leaves no seal;
orphan witness rows are harmless and a re-run succeeds. A re-run on an identical dir returns the existing seal
without rewriting (idempotent).

Read function (`check`, no writes): re-hash with `lstat` (no symlinks), return `{"sealed": bool, "problems":
[{"path", "kind": "missing|differs|unexpected"}]}`. An ABSENT record must return `sealed: False` and never look
like "no problems". Slice 3 compares git blob bytes (read as bytes; `work._run` strips stdout, see
`review_context.py:522-531`) against the same sha256.

## Open design questions: recommended defaults and the exact spot each touches

- **D-1 (what counts as red).** Default: accept any `FAILED` node (assertion, ImportError/ModuleNotFoundError,
  NameError, any exception) when `--collect-only` was clean and the run exited 1. Refuse: collection error
  (exit 2 or `ERROR <file>`), fixture/setup `ERROR <node>`, skip, xfail, xpass, INTERNALERROR, missing summary.
  Spots: the pure classifier added to `red_green.py` (the `FAILED` membership + exit-code branch), the collect
  step in `sealed_tests.seal` (collection refusal text names files), and the `kind`/`detail` written to
  `witness.record`. The owner call in the design (accepting ImportError) is to confirm, not to block coding.
- **D-5 (exemptions).** Default: recorded exemption, keyed by collected node id (prefix rule like
  `red_green._selected` `:68-69` so one exemption covers all parameter cases), reason must be a non-empty
  string after `.strip()`. Refuse: reason missing/blank, an exemption naming no collected node, an exemption for
  a test that actually fails on base (stale, would inflate), and a seal where every test is exempt (zero red
  proves nothing). Stored in `exemptions` of the seal record. Spot: after classification, in the pass-on-base
  clause of `sealed_tests.seal`. The `--seal-exempt <test> --reason` CLI spelling is slice 4's `work.py
  seal-tests`; slice 2 takes a `{node: reason}` mapping.
- **D-10 (separate record).** Default: separate `.sdlc/state/sealed/<stem>.json`, NOT a field on the plan-review
  record (`state/gates/<stem>.json`, overwritten by every re-review at `work.py:1466-1470`). It carries the
  `plan_hash` it was sealed under; staleness against a later plan-review is a slice 3 check. Spot: the path
  function and the final write in `sealed_tests.py`.
