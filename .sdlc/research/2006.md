## 7. Close gates and the reconcile branch (FR-63, FR-85, FR-87)

There are THREE closers, not two:
1. `merge()` -> `_close_issue_the_base_cannot` (work.py:7979; closes on every base, 7397).
2. merge-reconcile pass -> `_record(done)` -> `source.complete()` (loop.py:5121 -> 5160).
3. the CLI `record <goal> done` -> `_record(done)` (loop.py:8163-8170) — after `done_refusal` passes
   on a merged PR (8135). An agent that runs `record done` after a non-final slice merges closes the
   issue. FR-63's "SHALL NOT ... record done" covers it; the design names only 1 and 2.
Plus GitHub's own `Closes #N` on a default-branch base (FR-36 handles it by writing Refs).

Recommendation: ONE predicate in work.py, e.g. `unmerged_slices(sdlc_dir, config, goal, run, just_merged=None)`
-> list of slice ids (None/[] when not multi-PR: legacy route, work.enabled off, manifest <2 slices,
non-github mode). Read by: `_close_issue_the_base_cannot`'s caller (skip close, clause says
"slice k of n merged; issue stays open"), `_reconcile_one` (non-final branch: clear `awaiting_merge`,
keep record/claim/checkout, write action-log `merged` with `thread=<slice id>` + ledger `slice` event,
add/keep the overlay, NOT `_record(done)`, FR-85), and the `record done` verb (REFUSED exit 4 naming
the unmerged slices). Slice 6 extends the same predicate with discovered slices from the manifest of
record. `merge()` itself still deletes the remote slice branch and writes `merged`; `finish()` must not
run between slices (it only runs from `_record(done)` -> `_release_checkout`, so gating done suffices).

Reconcile caveat: `_reconcile_one` reads `rec["pr"]` (one PR per record). The work record must carry
the current slice's branch/PR in `branch`/`pr` (so every existing PR verb keeps working unchanged) plus
a `slices` map `{id: {branch, pr}}` for history.

  open PR body (REST, `view_pr_gh(... ["body"])`), replacing the `Closes #N` header line with the
  Refs header, writing via `gh_api.edit_pr_body`. Its CALLER (a discovered slice while the last PR is
  open) lands with slices 6/8; slice 4 ships the helper, the work.py function and their tests.
- **D-41 live keyword control (unmeasured).** Whether GitHub stops auto-closing after a body edit
  removes `Closes #N` has not been measured. A live control needs a real repo, a default-branch PR
  carrying `Closes #N`, an edit to `Refs`, a merge, and a read of the issue state — GitHub writes on a
  real repository. The plan must either (a) get owner consent for a throwaway-repo run and record the
  measurement, or (b) ship the helper with an opt-in live test (skipped by default) and state
  "unmeasured" in the docstring and the PR. Note: under the branching model every unit goal targets
  `feature/<unit>`, where `Closes` is never written, so the switch matters only for default-base goals.

## 9. FR-39 (work.enabled off)

- `work.enabled` false: `work.py main()` refuses every verb, no PR is ever opened, `record review` is
  refused (loop.py:8141-8150), `record done` prints "no branch/commit/PR was created" (8101-8105),
  `next_step._slices` already prints "work.enabled is off -- run the goal as one unit"
  (next_step.py:56-57), and `_reconcile_awaiting_merges` returns early (loop.py:5071).
- So FR-39 is mostly already true; slice 4's job is to make every new gate inert there: the
  `unmerged_slices` predicate returns "not multi-PR" when work is off, or `record done` would refuse
  forever (no slice PRs can exist). One test with work off + 3-slice manifest: `record done` passes,
  next-step says one unit in manifest order.

## 12. Risks

- **R1 GitHub auto-close on the default branch.** If D-41's re-parse is not what is assumed, a
  switched PR still closes the issue. Unmeasured; see §8.
- **R2 The `record done` closer (X1).** Missing it leaves FR-63 broken for the commonest agent path.
- **R3 `worktree_prune` (opt-in, `work.reclaim_merged_worktrees`).** Its proofs (worktree_prune.py:16-31)
  pass for a between-slices goal: record has a merged `pr`, no `awaiting_merge`, branch equals the
  recorded branch. With the opt-in on, it can remove the goal's checkout between slices. Add an
  exclusion (a between-slices record field) — off by default, so low frequency, real impact.
- **R4 `_reconcile_one`'s closed-unmerged park** applies to a slice PR closed by a human; fine for slice
  4 (5b fences restarts, BR-79).
- **R5 Phase-prose ceilings** (implement 0 tokens headroom, PC-34): put per-slice instructions in
  `next_step.py` (Python), not SKILL.md/running.md prose; tests/test_phase_context_budget.py.
- **R6 Label pins** change on purpose (§5); `test_public_bootstrap_control.py` uses a stateful fake
  `gh` that must accept the new label.
- **R7 Write-surface inventory** (§3) — a new helper and its call sites fail
  `test_committed_inventory_matches_the_tracked_write_surface` unless inventoried.
- **R8 Mixed fleet.** A 1.0.x machine never picks a between-slices goal while `sdlc:in-progress`
  stays (PC-45); on 1.0.x the owner's own reconcile pass would record done after slice 1 (design
  Rollback). Nothing to build here; keep `sdlc:in-progress` untouched.
- **R9 Run-the-control rows for this slice** (design 1164-1202), each must go red under its own break:
  merge() close gate; in-progress kept (1.0.x eligibility fixture); Closes only on last (write Closes on
  slice 1; skip the switch); continue own goal (remove the preamble); non-final reconcile (let it record
  done); all merged, issue open (skip the done); reconcile close gate (remove it); overlay seeding/strip
  (drop from `_LABEL_COLORS`, `complete()`, reconciler — three separate breaks); FR-65 (accept any merged
  PR whose body names the slice). Add: `record done` gate (X1) and work-off inertness (FR-39).
