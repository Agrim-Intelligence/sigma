## Goal in one paragraph
When a lean goal's first slice PR is pushed with an approved plan (and on every later approval), Python
publishes ONE trusted `sigma:`-prefixed goal-evidence comment on the issue (research record, plan path/ref/
sha256, acceptance sha256, plan-review verdict, manifest scope fingerprint, claim epoch, plan generation;
newest trusted wins). Any other machine that picks the issue (or picks it after an unpark) reads that
evidence through the trusted-author filter, reads plan + acceptance with `git show` from the open slice PR
head or else `origin/<slice base>`, checks both sha256 values, imports the gate inputs (plan-review gates
record marked imported, acceptance, manifest, route) into the goal worktree / state dir (never the main
checkout), skips research/plan/plan-review, and resumes at the first slice without a merged PR, reusing an
open slice PR and its branch, with an epoch bump and no fresh classification. `record done` accepts the
published goal evidence plus GitHub slice evidence in place of missing local rows. OUT of 5a (5b): epoch
check before every write, retirement, `resume --force/--restart`, generations in branch names, stall
sweep, lean_stalled parks, no hand-off to 1.0.x. Slice 6 owns FR-40/41 (fingerprint, branch-first
manifest); slice 7 owns FR-70/92 (per-slice evidence, red re-record).

**Base sha note.** The acceptance record names base `a461d49`; that commit is NOT an ancestor of
`64a208c` (the feature branch was rebased; `64a208c` is the same #2006 squash on newer main). In the
radius only `legacy.py`, `unpark.py`, `auto_unpark.py` differ between them (`git diff --stat a461d49
64a208c -- skills/sigma-loop/scripts/`); work.py, loop.py, phase_gate.py, acceptance.py, sources.py,

## Risks
- R1 Raw bytes. Hashing `work._run` or `_git_out(text=True)` output can never match the published sha (strip / newline translation) -> every resume refuses. Control: a plan ending in `\n` and one with `\r\n`.
- R2 Test-fake blast. `start` and `_next_untraced` are driven by fakes in ~30 and ~70 test files; an unconditional new `gh` read in either breaks many unrelated suites and the narrowed verify set would miss it. Gate every new read (lean + github mode + marker present).
- R3 Silent single-PR fallback (TD-6/Q2): a resumer without the manifest closes the issue after one slice.
- R4 Publication before push: publishing at `record_plan_review` time (before any slice push) produces evidence whose plan is on no remote ref -- the design's own control (`2000.md:1184`).
- R5 Reused open slice PR is refused by the test-first / sealed gates on the resumer (red records live on the dead machine) until slice 7's FR-92 re-record. 5a resumes, but `pr()` may refuse a mid-flight reuse under `verify.enforce`. State it in the plan; do not build FR-92 here.
- R6 Imported gates record forgery: the import must bind the record to the sha it verified from the remote ref, never copy a `plan_hash` from the comment unchecked; the evidence `plan` path must be derived from the goal stem (never a path from comment text).
- R7 Duplicated/racing publications: `note` retries can double-post; two approvals race. Reader = newest trusted by (`createdAt`, id); identical duplicates collapse.
- R8 Epoch semantics drift: 5a writes epochs nobody reads; 5b's reader (D-51 tie-break) must accept 5a's format -- fix the format in 5a (Q6).
- R9 Write-surface / marker / vocabulary ratchets (BR-7, BR-29, BR-30) fail late if missed.
