## Goal in one paragraph
`python3 tools/build_public_tree.py <commit> --out DIR` turns one reviewed commit of this private repository into the
tree of a fresh public repository (one initial commit, no history). It refuses a dirty or unreviewed commit, is
deterministic (same commit, same tree hash), writes its report outside every repository, runs the existing leak scan
(`tools/leak_refs.py tree`, patterns from an owner file) and the readiness exposure scan on the export, and fails on
any hit. Alongside it: a read-only name-handover checker that lists every place still holding this repository's
current name, with the exact ordered owner rename sequence; a documented switch for the tracked `.sdlc/` content (owner
decision, not guessed); and a prepared (never performed) rehearsal in a throwaway private repository. The hazard the
handover exists for: once a new repository takes the old name, GitHub's redirect from it stops, so any clone whose
`origin` still holds the old URL would then push to the PUBLIC repository.

**Verdict.** The goal is buildable and the mechanics are cheap (measured below), but three things the issue treats as
settled are not, and the plan cannot be written honestly until the owner answers them: (B1) the exposure scan the
builder must "fail on any hit" with exits 1 on today's `main` (41 findings, 2 stale allowlist entries); (B2) `main` has
no branch protection and 28 of the 30 most recently merged PRs carry no review marker, so "reviewed commit" has no
single honest definition yet; (B3) `exposure_scan.py` and the issue disagree on whether `tests/` and `tools/` ship.

Recommendation (layered, each level reported by name, never merged into one claim of "reviewed"):

3. `pr-merged` (REST, 2 calls): `commits/{sha}/pulls` yields a PR with `merged_at` set, `merge_commit_sha == <commit>`, base `main`.
