## 3. How the existing tests drive git (conventions to follow)

* `tests/test_feature_rebase.py` is the nearest precedent. `_git(cwd, *args)` (line 70) copies `os.environ` and sets `GIT_AUTHOR_NAME/EMAIL`, `GIT_COMMITTER_NAME/EMAIL`, `GIT_CONFIG_GLOBAL=os.devnull`, `GIT_CONFIG_SYSTEM=os.devnull`, runs `subprocess.run(["git", ...], capture_output=True, text=True)` and raises `AssertionError` on non-zero exit. `World.build` (line 94) makes a bare remote (`git init -q --bare`) and a checkout in `tmp_path`, adds `origin` as a plain path, pushes. No timeouts, no `run_with_timeout.py` in tests.
* `tests/test_feature_rebase.py:403` `test_every_push_carries_force_with_lease` shows the monkeypatch-the-runner seam (`m._run = watch`), and `:363` the stale-lease refusal test. `tests/test_hardening_698.py` and `tests/test_kg_sync.py` also build real bare remotes.
* Modules inject the git runner as `run(cwd, argv)` (feature_rebase) or call a private `_run_git(cwd, args)` that raises `RuntimeError("git ...: stderr")` (`sync.py:248`, which also sets `GIT_EDITOR=true` and `core.hooksPath` to an absent dir). `loop.py:3853-3868` runs git-touching children with `GIT_TERMINAL_PROMPT=0`, `stdin=DEVNULL`, and through `run_with_timeout.py <seconds> <script> <args>`, which kills the whole process GROUP on overrun (exit 124). `run_with_timeout.py` wraps a Python SCRIPT, not an arbitrary command, so a library primitive cannot reuse it directly: a plain `subprocess.run(timeout=)` kills only the direct `git` and can orphan an `ssh`/`git-remote-*` grandchild. PLAN decision: the primitive takes an injectable `run` (default: `Popen` with `start_new_session=True`, `communicate(timeout=)`, `os.killpg` on timeout, `GIT_TERMINAL_PROMPT=0`, `stdin=DEVNULL`, `LC_ALL=C`), and a timeout is an OUTAGE result. The Windows branch (`taskkill /T`) exists in `run_with_timeout.py`; a Windows-incapable primitive must refuse loudly (AGENTS.md SAFETY) rather than proceed with a plain timeout.
* Test env to use: `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_SYSTEM` = `os.devnull`, explicit author/committer env, `LC_ALL=C`, everything under `tmp_path`, remotes as bare repos addressed by filesystem path. No test may name `origin` of the real checkout; build each clone with `git init` (a clone needs no commits or checkout: `commit-tree` plus `push <sha>:<ref>` works from an empty repo, verified).
* The `slow` marker exists (`tests/conftest.py:84`: "cost grows with the repository"; nothing deselects it). The 1000-attempt smoke test is a candidate but is not repository-growth; either use no marker or mark it and state why.
* Process-pause guard: `tests/test_no_unsupervised_process_pause.py` scans for the literal `SIGSTOP`/`kill -STOP`; nothing in this slice needs it.

## 4. `feature_rebase.py` lease usage (what to reuse)

* Docstring of the function before `_pushed` (the "THE LEASE IS EXPLICIT, NOT IMPLICIT" paragraph, ~lines 1205-1215): bare `--force-with-lease` compares against the remote-tracking ref, a cache of the last fetch, and any concurrent `git fetch` re-arms it against the racer's sha; the explicit `--force-with-lease=<ref>:<sha>` names the sha the work was built on. Here that is stronger still: claim refs are never fetched into a tracking ref the lease could read, and the explicit form is the only correct one.
* Push at line 1304: `run(path, ["git","push","--force-with-lease=%s:%s" % (branch, sha), remote, "HEAD:refs/heads/%s" % branch])`.
* `_pushed` (line 1288) classifies a refusal by MEASUREMENT, not text: after a failed push it calls `remote_tip(run, cwd, remote, branch)` (line 647, `ls-remote --heads`, returns `None` for "could not read", never "absent"); a tip that is not the leased sha is `LEASE_REFUSED`, an unchanged tip is `FAILED`, an unreadable tip is `FAILED`. The docstring records that the earlier text test (`"stale info" in why`) broke when a long remote URL pushed the phrase past a 200-character truncation. Reuse this discipline and the three-way split; do not import the module (it loads half the package).
* Note one semantic difference: `remote_tip` returns `None` for "ref absent" and "unreadable" alike on some paths; claim refs need those separated (absent = create is possible, unreadable = outage), because "absent" is a valid `expected` value.
* Reuse of the `_ref_value` discipline (`sync.py:99`): it raises `ValueError("REFUSED: <key> <value> would reach git as an option (#710) ...")` for non-strings, a leading `-`, whitespace or control characters. `state.safe_ref` (`state.py:319`) is the non-raising sibling that returns an inert name. A claim primitive must REFUSE (raise), so copy `_ref_value`'s checks for the REMOTE name (config-supplied: `claims` remote, default `origin` per D-5) into `claim_refs.py` rather than import `sync` (sync pulls in `ledger` and a lot of surface). Add a test that the same hostile inputs `sync._ref_value` refuses are refused here (a drift guard), and a hostile-goal-id table (section 7).

## 5. Measurements taken (local bare remote, per-ref commits of ~120 bytes on the empty tree)

Namespace read (`git fetch -q origin '+refs/sigma/claims/*:refs/sigma/claims/*'` into a clone, then `git for-each-ref`), one run each, seconds:

| claim refs | first fetch | no-op fetch | fetch after 1 ref changed | `ls-remote refs/sigma/claims/*` | `for-each-ref` (local) | one create push at that size |
|---:|---:|---:|---:|---:|---:|---:|
| 10 | 0.040 | 0.026 | 0.035 | 0.015 | 0.009 | 0.045 |
| 100 | 0.054 | 0.029 | 0.041 | 0.016 | 0.010 | 0.054 |
| 1000 | 0.235 | 0.096 | 0.130 | 0.036 | 0.025 | 0.152 |
| 5000 | 1.532 | 0.473 | 0.569 | 0.115 | 0.128 | 0.662 |

Reading: fetch is linear in ref count with a ~25 ms floor (process start); 10x -> 100x refs is ~4x on first fetch, 100x -> 1000x is ~6x. `ls-remote` is 4x to 13x cheaper than fetch, so an "is anything claimed / which sha" pre-check should use `ls-remote`, and fetch only when the message bodies are needed. Building the commits is the dominant harness cost (`commit-tree` ~10 ms each: 1000 refs took 9.5 s, 5000 took 55 s), so the in-test measurement should use N in (10, 100, 1000) (about 11 s of setup) and batch the push (one `git push` of N refspecs worked: 0.47 s for 1000). NOT measured: network latency, GitHub-side ref advertisement limits, ref-count effect on a real hosted remote (B-1 spike, slice 1).

Object growth from renewals (D-6): 300 lease-guarded renewals on ONE ref left 301 loose objects on the bare remote (one per push, ~4 KB on disk each), 299 of them unreachable per `fsck --unreachable`; `git gc --prune=now` took it to 0 loose objects. So: one unreachable object per renewal, reclaimed by the host's gc; the empty tree is never written (virtual object), `git fsck` on the remote reports only `dangling commit`. Hosted-remote gc policy is unmeasured.

Parallel smoke test cost (feasibility): 1000 attempts = 100 goals x 10 clones, 10 workers: 10.8 s guarded, 12.8 s plain; 200 goals x 5 clones, 5 workers: 16.3 s; 100 x 10 with 20 workers: 10.2 s. Threads are enough (the work is `subprocess`, which releases the GIL); no `multiprocessing` needed. Each attempt = build commit + push, ~10 ms + ~45 ms. Expect 2 to 4x slower on a CI runner with 3 to 4 cores, so budget up to ~45 s and keep `workers` at `min(10, os.cpu_count() * 2)`.

## 7. Proposed API surface and test inventory (input to PLAN)

Module (stdlib only: `subprocess`, `os`, `re`, `time`, `json`/string formatting; Python 3.10-compatible; ONE function contains every `git push`):

* `validate_goal_id(goal)` -> lowercase ref component or raises `ValueError("REFUSED: ...")`; `validate_remote(remote)` copies the `_ref_value` checks; `claim_ref(goal)` -> `refs/sigma/claims/<id>`; namespace constant.
* `build_claim(cwd, holder, host, run, acquired_at, lease_seconds, nonce/renewed_at)` -> sha of a parentless empty-tree commit; message is `key: value` lines, parse with `parse_claim(message)`; explicit identity/date env; unique per call.
* Results: a small closed set with distinct values for WON, LOST_RACE, OUTAGE and a fourth REFUSED (hook decline, name collision, permission) so a non-race rejection is never reported as a lost race. The issue says three results; the fourth is required by M-3 and should be stated in PLAN. UP_TO_DATE is reported as WON-with-no-change or its own value, never silently as a fresh claim.
* `create(cwd, remote, goal, claim_sha)` expects absent; `renew(..., expected, new_sha)`; `reclaim(..., observed_stale_sha, new_sha)`; `delete(..., expected)`; all through `_push(cwd, remote, ref, expected, sha_or_None)` building `--force-with-lease=<ref>:<expected>` (empty `expected` only for create) and `--porcelain`; seam for the control: ONE small function returning the lease flag (`_lease_flag(ref, expected)`), which the control test monkeypatches to `--force`.
* `classify(rc, porcelain, stderr, tip_after)`: porcelain flag + reason first, then `ls-remote` tip measurement (section 4), exit 128 / `Could not read` / timeout -> OUTAGE; unknown shape -> OUTAGE-or-REFUSED, never WON.
* `read_all(cwd, remote)` -> `{goal: (sha, parsed claim)}` via `fetch` of the namespace, and `read_tips(...)` via `ls-remote` (cheap).
* `observed_age(seen, goal, sha, now)` -> pure: `seen` is a caller-owned mapping of `(goal) -> (sha, first_seen)`; returns `(age_seconds, new_seen)`; a changed sha resets the clock; unchanged sha keeps its original `first_seen`. Injected clock, no file, no new write surface (persisting `seen` across processes is slice 3/5). Wall-clock vs monotonic: `time.monotonic()` does not survive a process, so persistence in slice 5 must use wall time with a skew guard; record this in the docstring as a stated limit (D-7).

Tests (`tests/test_claim_refs.py`, deterministic, each run red once before trusted):

1. Staged-stale-view create: clone A creates; clone B (which read before A) creates -> guarded: LOST_RACE and the remote still holds A; control: swap the lease flag for `--force` -> B wins (assert the duplicate), proving the test can fail.
2. Same for reclaim (two reclaimers from one stale sha) and stale delete (delete with the pre-renewal sha after the holder renewed; ref must survive).
3. Renew by holder succeeds; renew with a stale expected sha is LOST_RACE and does not clobber; re-push of the already-held sha is reported as the no-op it is (M-2); two builds with identical inputs differ (nonce) and the unique-sha property is pinned.
4. Classification table driven by the real remote shapes in section 6: server-side race (slow `pre-receive` or injected runner output), hook decline (REFUSED), D/F conflict (REFUSED), missing remote path (OUTAGE), refused ssh (OUTAGE), timeout (OUTAGE, process group killed -- test with an injected sleeping runner, not a network), garbage output (not WON).
5. Validation table: each of `a/b`, `-x`, `x.lock`, `a..b`, `a b`, `A` (uppercase refused), non-string, empty, 65+ characters, control characters raises; `858`, `abc-1`, `slug.v2` pass; remote `--upload-pack=x` and whitespace refuse; drift guard against `sync._ref_value`.
6. Observed-age: unchanged sha ages, changed sha resets, injected clock, never negative on a backwards clock.
