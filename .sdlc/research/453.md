## 21-case classification proposed for planning

The classifications below account for every named harness evader, including the two
corrected-owner reruns cited by #453.  “Fixed” means add a planted, documented-gesture regression;
“out of scope” means retain/add the exact boundary in the leak-scan docstring and make the harness
report that classification rather than treating it as unclassified.

| Group / attempts | Proposed disposition | Likely handling seam and rationale |
| --- | --- | --- |

## Test and control strategy

1. Keep `tests/test_leak_scan.py`’s scratch git repository and invoke exactly
   `python3 tools/leak_scan.py`; each fixed row asserts exit 1 plus path/line/rule, never the
   secret value.  Put all literal token material together from fragments because the gate scans
   `tests/`.
2. Add individual planted rows for all fixed cases.  For G01/G02, create actual tracked symlinks
   and assert a line-0 `secret-file` finding without following the target.  Include existing clean
   symlink-to-nonsecret and public/example filename controls.
3. Give each rule family a deliberate control: move the secret-file check below the symlink return;
   remove each newly added filename/path alternative; remove the `hf_` pattern; remove the exact
   `credentials` config classification; and disable the Docker-auth recogniser.  The documented
   gesture must turn the corresponding planted assertion red, rather than merely unit-testing a
   helper.
4. Rework the preserved harness only enough to use current `sigma-*` support paths and accept a
   supplied GitHub owner/allowed public slug.  Its per-attempt result should be `fixed red`,
   `documented-oos`, or `unexpected`; fail if any of the 21 lacks one classification.  Run it after
   the implementation and record the command, revision, all 147 outcomes, and the 0-unclassified
   result.  The historical output is useful reproduction evidence, not post-change verification.
5. Preserve negative controls: placeholders and URL paths must remain clean; public/example secret
   filenames remain clean; this repository/public-slug owner URLs remain clean; a normal base64 JSON
   value must not become a Docker-auth finding.  Run the whole leak gate and the targeted suite.

## Risks and boundaries

- Filename rules are duplicated intentionally by the public-tree builder.  Expanding the gate but
  not the builder creates inconsistent publish decisions; expanding both too broadly rejects benign
  files.  Keep additions exact and test pattern parity.
- Unicode normalisation, percent decoding, and generic base64 decoding are high false-positive and
  scope-expansion risks.  The proposed classification deliberately avoids them and requires the
  documentation to say so plainly.
- A Docker auth detector must not log decoded credentials.  Findings remain location-only; decoded
  values must stay in memory and parsing failures need a stated policy (not an accidental clean
  result).
- Correctly configured owner tests are essential: the historical harness's owner/support-path drift
  can make both apparent escapes and apparent fixes meaningless.
- #433’s key-body algorithm is not in scope; this goal only consumes its preserved harness and must
  not regress its `key-body` guards.
