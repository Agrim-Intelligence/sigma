# #251 research — coexistence admission path

`loop.py claim` and `loop.py record` are public command-line entry points used by
`/agrim-goal`.  They already call `_coexist_notice(..., once=True)` before any
goal mutation.  `coexist.gate` is host-neutral: it reads Claude, Codex, Cursor,
and process evidence, writes the six-hour `state/coexist.notice` marker only
when it emits a notice, and accepts only `SIGMA_ALLOW_COEXIST=1` as the
acknowledgement.

The admission behavior is intentionally a notice, rather than a refusal.  A
claim is idempotent when it belongs to the current actor/writer and a terminal
record is already protected by its own work and evidence gates.  Blocking the
ordinary lifecycle would not prevent an older plugin from writing its own
state; the migration boundary is the operation that refuses because it rewrites
incompatible registry state.

The executable control must invoke `loop.py claim` and `loop.py record` as the
documentation does.  It must show that both host inventories proceed, the
override suppresses the notice, and state changes occur once.
