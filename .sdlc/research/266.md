# Research — #266

`work.gate()` is the only landing read that sees the required-check rollup.  It
already separates `failing` from `pending`; `merge()` turns every non-pending
failure into `PARK:` after recording the bounded CI observation.  The existing
anti-thrash ceiling is `work.max_review_cycles` (default 3), persisted on the
goal work record only after a remote review block is confirmed.

The repair path must therefore reuse that ceiling, persist its own counter
atomically before returning a repair dispatch, and treat an unknown/malformed
check as unsafe.  A completed `TIMED_OUT`, `CANCELLED`, or `STARTUP_FAILURE`
check is an infrastructure flake only when it has a numeric GitHub check-run
id: it can be rerun once with `gh run rerun <id>`.  A normal failed check is
not rerun; its bounded dispatch includes a bounded log excerpt.  Missing or
unreadable logs fail closed so an agent is never asked to guess.

The phase-cost record uses the existing `timing_store` with the `ci-repair`
kind, measuring only the dispatch preparation/rerun operation.  The host then
starts the normal Implement phase for the returned dispatch, so its own
`phase_report` measurement remains the authoritative model-cost record.
