## 2. Idioms to copy (copy, do not import: S-15, and `feature_judge` is loaded by path elsewhere so importing is the wrong coupling)

Lock (`skills/sigma-loop/scripts/feature_judge.py`):
- `import fcntl` inside `try/except ImportError: fcntl = None` at module top (line ~76), so import never fails on Windows.
- `_acquire_spend_lock` (line ~628): `os.open(path, O_CREAT|O_RDWR)`, then poll `fcntl.flock(fd, LOCK_EX|LOCK_NB)` against a `time.monotonic()` deadline with a 0.05 s sleep; returns the fd, `None` on timeout (fail closed), or a sentinel when the mechanism is unusable (fail open). `_release_spend_lock` does `LOCK_UN` then `close`, never raises.
- DELIBERATE DIFFERENCE for the ledger: `feature_judge` fails OPEN when `fcntl` is missing or the lock file cannot be opened. A spend guard must not. AGENTS.md SAFETY: "REFUSES loudly rather than proceeding weakly". The ledger must raise a typed refusal when `fcntl is None` (non-POSIX) and when the lock file cannot be opened, and treat lock timeout as NOT RUN (budget/lock), never proceed unlocked. Test each.

Signals (`evals/bench/bench.py:648` `_unwind_on_signals`, `BenchmarkSignal(BaseException)` at line 63):
- Installs a handler for SIGTERM and SIGHUP only on the main thread (returns `{}` otherwise) that raises `BenchmarkSignal`; returns the previous handlers so the caller restores them in `finally`. Because it is a `BaseException`, ordinary `except Exception` blocks do not swallow it, and `with` blocks release the lock as it propagates.
- HAZARD to design around (not stated in the design): `flock` locks belong to the open file description, so a SECOND `os.open` of the lock file in the SAME process conflicts with the first. If the handler itself tried to settle by taking the lock while the main flow is already inside the locked section (signal arrives mid-reserve or mid-settle), it self-deadlocks until timeout. So the handler must only raise (bench idiom); the settle happens in the `finally`/context-manager exit after the locked section has unwound, never inside the handler. Test: deliver SIGTERM while the lock is held by the same process (inject a hook inside the critical section) and require no hang.
- SIGKILL cannot be caught: leaves the `open` row (the AC-3 case). SIGINT is not in the design; a context manager that settles on any `BaseException` covers Ctrl-C for free; say so in the docstring but do not claim it is tested unless it is.

fsync: `record.py` `write_atomic` is the only existing write idiom in `evals/regression` (temp file then `os.replace`). It does not apply to an append log. Use `os.open(path, O_WRONLY|O_APPEND|O_CREAT, 0o600)`, one `os.write` of the whole line (a single sub-PIPE_BUF write under the exclusive lock cannot interleave), `os.fsync(fd)`, close. When a month file is newly created, also fsync the directory fd so the entry itself survives a power cut.

## 5. Ledger design pinned for the plan (derived from the design text, with gaps made explicit)

Format (design D-4): JSON lines, one file per UTC month, e.g. `<ledger_dir>/spend-YYYY-MM.jsonl`. Rows: `{"kind":"open","id","belt","t"}` fsynced BEFORE return from `reserve`; `{"kind":"settle","id","spent","t"}` after. Unsettled `open` counts at its full belt. Next belt = `cap - counted`; `<= 0` returns NOT RUN with code `budget`.

Decisions the plan must make (flag, default, record):
1. Money type. Dollars as strings parsed to `decimal.Decimal`, written as strings (`"0.40"`), not floats, so sums are exact and a ledger written on one host reads identically on another. Reject negative, NaN, infinite, non-numeric belts and caps with a refusal. Default recommendation: Decimal strings.
2. `settle` with `spent` greater than `belt`: count the larger of the two (overshoot is real spend; the design says the host's belt is a client-side estimate). `spent` missing or unparseable: treat as the full belt.
3. Duplicate `settle` for one id, `settle` with no `open`: the second is ignored and reported; an orphan settle is reported but contributes nothing (cannot reduce the count). Never let a settle reduce a counted figure below its belt-minus-unknown, i.e. a settle only ever replaces the belt count of ITS open.
4. Corrupt line rule (acceptance: "corrupt line counts as full cap spend for that month and is reported"): any line in the month file that is not valid JSON, not an object, has an unknown `kind`, or is missing required fields, makes the month's counted spend equal to the full cap, so the next belt is zero and the run is NOT RUN (budget). The report names file, line number and reason, not the content. A torn trailing line (crash mid-write, no newline) is the same case. This is the strongest fail-closed reading; the design ("a corrupt trailing line counts as full cap spend") and the acceptance ("a corrupt line") differ only in position, and counting any corrupt line as full cap is the conservative superset. State it in the docstring.
5. Month boundary. The month is the UTC month of the `open` row's `t`. The `settle` must go to the SAME file as its `open` (carry the month in the handle), otherwise a run spanning midnight UTC on the 1st leaves an unsettled open in the old file and a settle orphan in the new one. An unsettled open from a previous month counts only against that month's file (a fresh month starts with zero, per acceptance). Residual to state: spend by a run that started in month M and a hosted monthly cap in #819 sum over result artifacts, so the two figures can differ by that one boundary run.
6. Clock injection: `reserve(..., now=None)` takes an optional `datetime` (aware UTC) so month rollover is tested without sleeping or monkeypatching the system clock.
7. API sketch: `Ledger(ledger_dir, cap, lock_timeout_s=...)`; `reserve(requested_belt, run_id=None, now=None)` returns a handle `Reservation(id, month, belt)` or a `NotRun(code="budget"|"ledger-corrupt"|"lock-timeout", ...)` value (never raising for the expected NOT RUN case); `settle(handle, spent)`; a context manager `reserved(...)` installing the SIGTERM/SIGHUP unwind (main thread only, previous handlers restored in `finally`) that settles at the belt on abnormal exit unless the caller settled. The run id: `secrets.token_hex(8)`; the PID is recorded for diagnosis only, not used for correctness.
8. What settle writes when unwinding on a signal and the actual spend is unknown: settle at the FULL belt (fail closed), flagged `"reason":"signal"`. A signal-settle at zero would let a killed-but-spending `claude` go uncounted; the design notes a `claude` can outlive a killed `live.py` until the launcher deadline.
9. The module never starts a process, never reads a credential, never reads the environment, never imports `subprocess`. A test asserts the module's AST contains no `subprocess`, `os.system`, `os.exec*`, `os.spawn*`, `os.fork` imports/calls (documented-gesture sibling of the section-6 test).
10. Ledger directory is passed in; no default path in this slice (the entrypoint slice chooses `.sdlc/eval/results/` per D-6). No module-level side effects on import.

## 6. Tests (new `tests/test_regression_ledger.py`; tmp dirs, fake dollars, no model)

Run the real gesture the docs would give: `python3.12 -m pytest tests/test_regression_ledger.py -q`. Each guard is seen red once by deliberately breaking it (AGENTS.md "run the control"). Planned controls:

1. Kill between reserve and settle (AC-3), with a REAL subprocess and SIGKILL. Child is `subprocess.Popen([sys.executable, "-c", CHILD, ledger_dir, ...])` where CHILD loads `ledger.py` by path, calls `reserve`, then writes a `ready` marker file (only AFTER reserve returned, so the open row is fsynced) and sleeps. Parent polls for the marker with a bounded deadline, then `proc.send_signal(signal.SIGKILL)` (precedent: `tests/test_bench_isolation_launcher.py` lines 364-376, 510-524 use `os.killpg`/`send_signal` and `wait(timeout=...)`). Assert: `proc.returncode == -signal.SIGKILL`, the month file has an `open` row and no `settle`, and a fresh `Ledger.reserve` in the parent sees counted spend equal to the belt (next belt is `cap - belt`). Control: delete the "unsettled counts at belt" rule, test goes red.
2. Bounded child: the sleeping child gets a `stdin`/parent-death guard (it exits on its own after a timeout of a few seconds) so a failed parent never leaves a stray process; Popen is in a try/finally that kills it.
3. SIGTERM and SIGHUP: same shape, signal delivered, child must exit and the file must have a `settle` row for the open id (full belt, reason `signal`); parametrize both signals. Plus the self-deadlock control from section 2 (signal while the lock is held by the same process; must not hang; use a short lock timeout and a hard `proc.wait(timeout=...)` so a hang FAILS rather than hangs the suite, per the AGENTS.md note about lock tests that hang).
4. Lock exclusion: two real processes reserving concurrently against a cap that fits only one belt; exactly one gets a belt, the other gets `budget`. Probabilistic concurrency note (AGENTS.md "port across a performance boundary"): because the in-process window is tiny, add a deterministic seam test: hold the lock via the module's own acquire in the parent, run a child reserve with a short timeout, assert `lock-timeout` NOT RUN; demote the two-process race to a labeled smoke test in its docstring.
5. Clamp: cap 10, belt asks 4 and 4 then 4 returns 2, then zero or below returns `NotRun(budget)`. Exact-zero boundary and a settle lowering spend freeing budget.
6. Corrupt line fails closed: append garbage as a middle line, as a torn trailing line without newline, a JSON non-object, an unknown kind; each yields counted = cap, NotRun, and a report naming file and line. Control: make the parser skip bad lines, red.
7. Month rollover: reserve with `now` in two UTC months; two files, the new month starts at zero spent, an open in the old month does not count in the new one; settle of a run that started in month M lands in M's file even when settled with `now` in M+1.
8. Non-POSIX refusal: monkeypatch `ledger.fcntl = None`, reserve raises the typed refusal and writes nothing (does not fail open).
9. Decimal strictness: negative, NaN, `inf`, `"abc"`, float-looking values refused.
10. THE WRITE-SURFACE COMPANION TEST (acceptance last item): a test that parses every `.py` under `evals/regression` with `ast`, finds every `open(...)` with a write/append mode, `os.open(...)` with write flags, `os.write(...)`, `os.fsync`, and requires each `(path, function)` to appear in a documented list. Where the list lives is a plan decision; recommended: a `WRITES` table inside the test file mapping `(relative path, function)` to a one-line reason, with the failure message naming what to add. Not `docs/launch/write-surface.json`, because `check` ignores unknown rules and a new rule name would need a scanner change (out of scope; also the file is a launch artifact). Control: add an undocumented `open(p, "a")` to a scratch tree copy and see it red; also run it against the real tree and see it green. The test must also accept `record.py`'s existing `write_atomic` writes (its `open`/`os.replace` use) so it is green today; read `record.py` for the exact calls before writing the table.
11. No-model test: AST scan of `ledger.py` for `subprocess`, `os.system`, `os.exec*`, `os.spawn*`, `os.fork`, `socket`, `urllib`, `http`; red when one is planted.
12. Import hygiene: `ledger.py` imports on Windows (fcntl lazy); test by running a child with `fcntl` blocked in `sys.modules` (set `sys.modules["fcntl"] = None` before load) and asserting import succeeds and reserve refuses.

## 7. Scale, ceilings, failure and recovery (AGENTS.md five properties)

Scale (stated as design claims, to be MEASURED in P5 and reported with the number, not asserted):
- Per start: the month file is read in full under the lock. Rows are about 100 bytes; 2 rows per run. At the planned nightly volume (tens of runs per month) a month file is under 100 lines. At 10x (hundreds of runs) about 1,000 lines, 100 KB; 100x about 10,000 lines, 1 MB. Parsing 10,000 short JSON lines is milliseconds to tens of milliseconds; P5 measures it once and reports it, because the design's "few hundred lines at 100x" is an unmeasured claim.
- Growth is bounded by month: a new file each month, old months are never read again by `reserve` (only the current month's file is read). Old files are not pruned by the module (no deletion, no write-surface remove entry); retention of old month files is an operator concern and a known unbounded-but-tiny growth (about 1 MB per month at 100x). State it; do not claim it self-prunes.
- Ceiling: the lock serialises ledger access on one machine; the critical section is a read plus one fsynced append (single-digit milliseconds on an SSD; fsync dominates, measure it). The design's one-run-at-a-time ceiling (D-15) is far above the ledger's.
- Reading the whole file twice per run (reserve and settle) is fine; settle may append without reading since an `open` can only be settled once and duplicates are tolerated by the reader.

Failure and recovery:
- Crash/SIGKILL between reserve and settle: open row stays, counted at full belt next start. Self-healing: the over-count is permanent for that month unless a human adds a compensating settle; document a polite lever: an explicit `settle` row for that id appended by the module's own function (`settle_orphan(id, spent)`), so an operator can release a known-not-spent belt without hand-editing JSON. Decide in P3 whether the lever ships now (recommended: a function, no CLI) or is documented as a residual.
- Torn trailing write (power loss mid-append): fails closed as corruption (NOT RUN for the month); recovery lever is the same operator step: remove or repair the bad line by hand, documented with the module. Because a torn line fails the whole month closed, state the blast radius: an entire month's runs stop until repaired. This is the fail-closed price; the alternative (skip the bad line) is rejected per the design.
- Lock held by a dead process: `flock` is released by the kernel on process death, so no stale lock file problem (the lock file persisting is harmless).
- Lock timeout: NOT RUN (`lock-timeout`), never proceeds. Timeout value is a parameter; default derived, not copied from `feature_judge` (60 s per round was sized against `claude -p` latency, which does not apply). The critical section here is milliseconds, so a few seconds is generous; the plan picks and records it.
- Disk full or read-only dir: `os.write`/`fsync` raises; `reserve` must NOT return a handle if the fsync did not succeed (the invariant is "open row durable before launch"); surfaces as a refusal. Test with an unwritable dir (chmod, skipped on root) or a patched `os.fsync` that raises.
- Hosted runner lost (D-4, carried open): a killed job's runner VM loses the disk, so the local ledger forgets the belt. Not closable by any file in this module. The job-level reservation row is a #819/workflow-goal obligation. The module docstring and the PR must say so, not imply it is covered.
- Surviving child: a `claude` that outlives a SIGKILLed `live.py` can keep spending past the settle; the full-belt count for the unsettled open is the bound, until the launcher's `deadline_seconds`.
- Backup/restore: restoring an older month file loses newer rows and under-counts. Residual; no mitigation in this slice.
- Multi-machine: two machines have two ledgers and each believes it has the whole cap. The cap is per-ledger-home. State it.
- Permissions: ledger and lock files created `0o600`; directory `0o700` if created by the module.
