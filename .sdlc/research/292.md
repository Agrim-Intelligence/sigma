# #292 P2 RESEARCH — remote-aware rebase loss attribution

Issue #292 follows #278/#144. `feature_rebase.own_losses` permits a pure deletion only if
(a) absent locally, present remotely, (b) a unique non-merge commit deleted it, and (c) the selected
base never touched it since the remote tip. Its current negative revision set names only that tip
and selected base; a different upstream's revert is therefore misattributed to the local branch.
The push chokepoint in agrim-rebase/rebase_brief.py supplies this result to every human-attended
push path. Existing condition-(b) test also touches the path on the base, so condition (c) masks a
broken (b). `push_branch` advice conflates undoing the latest rebase with restoring an older loss.

Blast-radius query: `rg -n 'own_losses|pre_head|reset --keep|known_limit' skills tests docs`.
Affected production: feature_rebase.py own_losses and rebase_brief.py push refusal wording.
Affected contract: docs/branching-model.md §3b/§15. Tests: test_conflict_walk.py, feature_rebase,
rebase_brief, plus CLI/doctor/work integration consumers. No issue writes or actual remote pushes:
real-git controls use isolated temporary repositories with local bare remotes.

Preserve existing strict xfail for a revert masked by a later same-file edit; pin the documented
force-rewritten-base limit as a strict xfail, rather than claiming remote-ref exclusion repairs
unreachable history. No probabilistic concurrency port or new lock/process lifecycle is involved.
History reads remain 200-path chunks under per-read and total time budgets; measure real Git
histories at 100/1000/10000 commits before stating observed cost. This is a bounded synthetic
history measurement, not a fleet or production-repository latency guarantee.

## Red/green controls and independent review

Initial `python3 -m pytest tests/test_conflict_walk.py -q -k 292`: **2 failed, 1 passed,
1 xfailed**. The fork/upstream repro returned `rebased` and pushed the deletion; the recovery
advice omitted the remote content source. With the fix, selected #278/#292 cases: **32 passed,
1 xfailed**. The merge-only deletion control also failed when condition (b)'s filter was replaced
with `pass` in an in-memory module (no source file mutation), proving it detects that exact break.
The advice test executes the advertised `git reset --keep <pre_head>` and verifies it leaves the
prior 300-line loss unresolved while the named remote commit still contains all 300 lines.

Independent P6 review: **PASS, no actionable findings**. Reviewer ran **3 passed, 1 xfailed**,
checked the full diff, and independently executed the real-Git benchmark. The existing strict
masked-revert xfail remains unchanged; the added force-rewritten-upstream strict xfail makes the
remaining provenance limit executable rather than claiming a fix for it.

## Measured history-read cost

Reproduce with `python3 .sdlc/research/292-benchmark.py`. Raw samples:
[292-benchmark.json](292-benchmark.json). Git 2.55.0, macOS 26.6.2 arm64, 12 logical CPUs; real
Git commit counts explicitly checked. Three sequential wall-clock samples per case, caches not
flushed, machine not isolated. One affected path; attribution adds one local deletion commit.
Temporary repository construction (10,000 commits via fast-import) took 0.182 seconds and is
excluded from the guard times below.

| Baseline history | Rollback detection median | Deletion attribution median |
| --- | --- | --- |
| 100 commits (1x) | 11.42 ms | 27.89 ms |
| 1,000 commits (10x) | 16.86 ms | 29.98 ms |
| 10,000 commits (100x) | 74.49 ms | 64.61 ms |

Independent rerun medians were 15.89/21.25/83.24 ms and 33.83/34.16/73.22 ms respectively.
These are observations for this small-file, synthetic linear history, not upper bounds. Cold
storage, merge-heavy DAGs, many remote refs and multi-batch path sets remain unmeasured. The
existing 200-path chunks and operator timeout policies still bound reads; a timeout refuses the
push. No timeout/resource setting was derived from these laptop timings. New `--remotes`
exclusion enumerates locally available remote refs; stale/removed/re-written refs limit evidence
and are documented, with no automatic extra fetch or persistent state introduced.
