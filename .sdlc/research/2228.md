## What a fix at the cause looks like
The tests rewrite a record to name a pid that is NOT the process that took the lease, then ask the code to treat it as live. They must establish that premise rather than assume the pid is free. Candidates that do not loosen:
1. Rewrite the record to a pid that is guaranteed non-live and unreadable (e.g. a pid past pid_max, or `_dead_pid()`), keyed consistently in take_descendants/box["foot"]; `process_start` is then None and `reused` False without touching `reused`. Cheapest; stays honest about what is measured.
2. Rewrite `pid_start` in the record alongside `pid` (set to None or to `lease.process_start(new pid)`), the test now says which process it claims to be. Keeps pid 100.
3. Patch `lease.process_start` for the test (as :209,:218 do): consistent with existing style, but hides the real call.
FORBIDDEN as loosening: raising START_TOLERANCE; making `reused` return False for pid 100 or for unreadable/low pids; dropping the `reused(record)` clause from `note_peak`; patching `reused` to False; skipping or `known_flakes`; deleting either assertion (`note_peak(...) is True`, the ring `[414]`, `procs == 5`, `[100]`, `verify_run [500]`); asserting `note_peak` in (True, False). Also no change to what reused means.

## Test-first gate (red at base)
Neither existing test is red at base in a normal container (they pass; need an old live PID 100). A deterministic red at base needs a NEW test, e.g. a test that runs the same scenario with `process_start` patched to return a far-off value for pid 100 (simulating the occupant) and asserts `note_peak` True; this is red at base (reused True) and green after fix 1 or 2. Without that, the only red recording is the forced-PID-100 run above (not repeatable in the verify, needs root and ns_last_pid), so a test-only fix with no new test red at base would need `work.py pr --no-tests`. Recommend the deterministic simulation test, so no `--no-tests`. Control per AGENTS.md: break each clause alone (a) revert pid change to 100 under the simulation -> red, (b) delete `reused(record)` from note_peak -> the existing :205-272 tests / new test must go red, run via the documented gesture `python3 -m pytest tests/test_resource_lease.py -q`. The forced-PID-100 helper gives a live control as well (ns_last_pid requires root; here root).
