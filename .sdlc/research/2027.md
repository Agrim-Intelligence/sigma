# Research: Hand off on measured context, with a threshold derived from the session's start and capped by the host window
**Goal**: #2027 (slice 2 of Epic #2025) · **Lane**: medium · **Date**: 2026-10-24

## Goal in one paragraph
`_session_count_stop`, the one admission chokepoint, also returns `HANDOFF` once the session's
recorded context (slice 1's meter, #2026) reaches a threshold. The threshold is
`handoff.after_context_tokens` when set, else a documented multiple of the session's first-pick
context, capped at a fraction of the host window (F2). With the meter unavailable only the goal
count applies; `handoff.enabled: false` turns both off. Stdout stays the bare `HANDOFF`; the stderr
reason names context and threshold. The meter is read once per `next`/`next-batch` invocation,
outside the session lock, and passed to every `_session_count_stop` call (M5). Config template,
`docs/configuration.md`, doctor row, enforcement table and the running-the-loop row are updated.
Carried from slice 1's review (finding 4): `session_end` unlinks the heartbeat, so an end + start
in the same transcript loses `first_pick`.

Plans against slice 1 as approved at `sdlc/2026` head `a69692da` (PR #2031, not yet merged); this
worktree is cut from `origin/main` `504de5c1` and is rebased on main after #2031 lands, before any
implementation. Line numbers below are `origin/main` unless marked `(2026)`.
