# #237 research — end-to-end onboarding control

Goal: an executed, recorded control: fresh repo -> install -> /sigma-init -> one goal `done`, in
local-goals and github mode, following the README text; the empty-verify default must turn it red
at `record done`.

## Run constraints for this goal (owner, overriding the issue text)
- No real GitHub repo/issue/PR/label/board is created or deleted: github mode runs on the fake gh +
  a local bare origin. The real-GitHub half becomes an OWNER RUNBOOK in the doc.
- No model session (`claude -p`, a live /sigma-loop): the control drives the scripts the
  sigma-loop skill names. Token cost is therefore N/A.
- Any plugin install goes into an isolated profile (HOME / CLAUDE_CONFIG_DIR / CODEX_HOME in temp),
  with the real profile's plugin surface hashed before/after.

## Blast radius (measured)
- README.md `## Quickstart`: `/sigma-init --demo` + `/sigma-loop` (Claude Code block), the CLI
  install pair `claude plugin marketplace add <SIGMA_REPO>` / `install sigma@sigma`, the Codex pair,
  the script form `python3 <installed-sigma>/skills/sigma-init/scripts/init_flow.py . --codex --demo`,
  and under "What /sigma-init will ask you" the verify gestures
  `python3 skills/sigma-init/scripts/verify_detect.py confirm .sdlc <n> <id>`.
- `skills/sigma-init/scripts/init_flow.py` (#236): prints `[ask] <q>:` lines, the verify candidate
  confirm gesture with n + id, and `Next: ... (Codex/Cursor: <python> <loop.py> next <sdlc>)`.
  github-mode questions (board, ledger) only appear once mode is answered -> answering is iterative.
- `verify_detect.py` (#228): `write_verify` is the single writer and the guard against
  enforce ON + empty command; init writes enforce OFF + `_why` right after scaffolding.
- `loop.py`: `start/next/agent-start/verify/record/reconcile-merges`; `next` prints the goal file
  path (local) or issue number (github), `DONE` when empty, `HANDOFF` when the session pid changes.
- `work.py start/commit/pr/merge` (github mode, work.enabled on) + #232 done-means-merged:
  `record done` refused (exit 4) while the PR is open; reconcile records done after the merge.
- Existing fake gh: `tests/test_public_bootstrap_control.py::_FAKE_GH_BODY` (stateful, logs every
  call, logs unmodelled calls). Reused by `ast` extraction rather than duplicated (~450 lines).
- Guards touching new files: test_no_private_names, test_self_contained, test_no_network_in_core,
  test_no_cross_boundary_paths (all scan tracked + intent-to-add files).

## Findings during research (measured on this Mac, py3.12)
- `claude plugin marketplace add <path>` + `install sigma@sigma` into an isolated
  CLAUDE_CONFIG_DIR works (~1.6s) and installs the committed HEAD of the path, not the working
  tree. Real ~/.claude plugin surface hash unchanged before/after.
- The Codex CLI is not on PATH but ships inside the ChatGPT app bundle
  (`/Applications/ChatGPT.app/Contents/Resources/codex`, codex-cli 0.154.0-alpha.6.2); its
  `plugin marketplace add` + `plugin add sigma@sigma` into an isolated CODEX_HOME work (~0.15s).
- A template-only reintroduction of `verify.enforce: true` does NOT bite any more: init rewrites
  verify to enforce OFF on scaffold. The trap is only reachable if `write_verify` itself regresses.
- In github mode one goal cycle made 34 `gh label create` calls: 14 by init's labels step (fresh
  repo, all needed) and 2 x 10 by the loop's `_ensure_labels` passes, every one of which the fake
  answers 422 "already exists" -- wasted calls on every start/next.
