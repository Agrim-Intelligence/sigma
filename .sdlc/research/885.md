## 1. What verify.py and bench_tasks require of a task directory
Source: `evals/golden/verify.py` (:34-35 constants, :87-120 `_schema`, :123-153 `_contract`, :156-166 `_hashes`, :169-175 `_reference_diff`, :189-206 `_runs`, :213-240 `check_task`) and `tools/readiness/bench_tasks.py:491-499` (`_hidden_run`).
- Exact files: `task.json`, `rubric.json` (must parse to a JSON object, nothing more), `allowed_paths.json` (list of strings), `hidden/verify.json`, directories `repo/`, `reference/`, `hidden/files/`; `hidden/naive/` optional. Any symlink under `repo/`, `reference/`, `hidden/` or at a root is red. A directory without `task.json` is red, never skipped.
- `task.json` keys: `id` (equals the directory name), `kind`, `origin`, `prompt`, `visible_command`, `hidden_sha256`, `trap`. `origin` must match `planned|issue:<digits>` (:36) so T3 uses `planned`. **`trap` must be a boolean** (:98-99), not text; the "trap text" the lane brief asks for has no field of its own. It goes in `prompt` (visible to the agent, so it must not leak the trap) and in `rubric.json` (a free-form object). `visible_command` must be a non-empty argv starting `python`/`python3`; it is validated and never run.
- `hidden_sha256`: map of path relative to `hidden/` to sha256, whose keys must equal exactly the regular files under `hidden/` including `verify.json` and every file under `naive/` (:156-166). `__pycache__`, `*.pyc`, `.DS_Store` ignored.
- `hidden/verify.json`: `{"command": [...]}` that must contain `-m pytest`, `-p no:cacheprovider` and the argument `.sigma-hidden/files` (:141-146).
- How hidden files reach the tree: `_hidden_run` copies the start (or reference) tree to a temp dir, then copies the whole bundle to `<tree>/.sigma-hidden`, then runs the command with cwd at the tree root (`bench_tasks.py:495-499`). verify.py builds the bundle from `hidden/` minus `naive/` (`_ignore_hidden`, :178-185), so the scored tree never contains `naive/`. The hidden tests therefore run with the project root as cwd and can read project files and import the package (verified: my hidden test uses `pathlib.Path.cwd()` and `python -m shipping.cli`).
- Exit semantics (`_runs`, :189-206): hidden on `repo/` must exit exactly 1; on `reference/` exactly 0; naive overlay (start tree plus `hidden/naive/` copied over it, :202-205) must exit 1. Any other code or a timeout is red with the property name. Reds print `RED T3 <property>: ...`; exit 1 on any red, 2 on unreadable input.
- **Overlay limit**: the naive tree is an overlay, so it cannot delete or rename a file. A naive "replace everything" that cannot move docs/rates.md is therefore always red for the docs-rename reason as well as for the decoy reason; the naive control alone does not isolate the decoy (measured, see section 3). Isolation comes from planted single-edit controls.

### `_allowed` and the "no slash means no prefix" requirement
`_allowed` (`evals/golden/verify.py:76-77`) is `rel == entry or (entry.endswith("/") and rel.startswith(entry))`. It already satisfies the acceptance line: an entry without a trailing slash matches one exact path only. Measured in a scratch copy: with `allowed_paths.json` set to `["README.md","docs","shipping"]`, the reference's docs/tariffs.md, `shipping/cart.py` and `shipping/cli.py` were reported `reference-diff ... not in allowed_paths.json`. **No test pins it**: `tests/test_golden_verify.py:269` pins only that a `dir/` entry covers new files, and the #881 retro lists "no test pins that an allowed_paths entry without a trailing slash is not a prefix" as carried debt. This slice should add that test (plant `["calc.py","pkg"]` with a new `reference/pkg/new.py`, expect `reference-diff` red naming `pkg/new.py`; also a sibling `pkgextra.py` case) and see it red against a verify.py patched to `startswith(entry)`.

## 4. Recommended T3 design (proven green in the scratch clone)
**Domain**: a tiny parcel-shipping pricing package, stdlib only, no I/O beyond reading one JSON file.

**start tree `repo/`** (new): `README.md` (links docs/rates.md); docs/rates.md (names `calc_rate` and config key `rate_table`; no outbound link); `config/shipping.json` (`rate_table` plus `currency`); `shipping/__init__.py` (exports `calc_rate`); `shipping/rates.py` (defines `calc_rate`); `shipping/config.py` (`load_table` reads `["rate_table"]`); `shipping/cart.py` and `shipping/cli.py` (call `calc_rate`); `shipping/compat.py` (**decoy caller**: `from ._vendor.legacy_rates import calc_rate`, a different function with the same name); `shipping/_vendor/legacy_rates.py` (**decoy vendored file**: header "Vendored from the upstream ... Do not edit: re-vendor instead", defines its own `calc_rate(weight, service, rate_table)`); `generated/rate_schema.py` (**generated file**: first line `# AUTO-GENERATED ... DO NOT EDIT: regenerate it, never patch it by hand.`, a `SCHEMA` dict holding the strings `"calc_rate"` and `"rate_table"`); empty `__init__.py` files; tests/test_shipping.py (two visible behaviour tests that name neither renamed symbol, so they stay green on start, reference and any half refactor).
**`reference/`**: the complete post-change tree. Changes versus `repo/`: `calc_rate` becomes `quote_rate` in `shipping/{__init__,rates,cart,cli}.py`; `rate_table` becomes `tariff_table` in `config/shipping.json` and `shipping/config.py`; docs/rates.md deleted and docs/tariffs.md added with updated names; README link updated. Untouched and byte-identical: `shipping/compat.py`, `shipping/_vendor/**`, `generated/**`, `tests/**`.
**`allowed_paths.json`** (exact paths, no slash, nine entries): `README.md`, docs/rates.md, docs/tariffs.md, `config/shipping.json`, `shipping/__init__.py`, `shipping/rates.py`, `shipping/config.py`, `shipping/cart.py`, `shipping/cli.py`. Deliberately absent: `compat.py`, `_vendor/`, `generated/`, `tests/`. Using exact paths also exercises the no-prefix property on a real task.
**`hidden/files/test_hidden_rename.py`** (7 tests): every first-party module defines/uses `quote_rate` and none uses `calc_rate` (AST names, so a comment or the vendored function does not count); `quote_rate` prices a parcel; the CLI (`python -m shipping.cli`) quotes from the renamed config key; config has `tariff_table` and not `rate_table`; docs/tariffs.md exists, docs/rates.md does not, README points at the new page, the page uses the new names only; sha256 of `shipping/_vendor/legacy_rates.py`, `generated/rate_schema.py` and `shipping/compat.py` equals constants pinned in the test; the shim still reaches the vendored calculator and returns its flat price. `hidden/verify.json`: `{"command": ["python","-m","pytest","-q","-p","no:cacheprovider",".sigma-hidden/files"]}`.
**`hidden/naive/`** (overlay, 11 files): a global find-and-replace of both names over every file that mentions them: first-party code, config, docs/rates.md text (path unchanged, as a text replace would leave it), plus the decoy, generated and compat files. No README (link-scan reason above).
**`task.json`**: `id` T3, `kind` refactor, `origin` planned, `trap` true, `visible_command` `["python3","-m","pytest","-q","tests"]`, `hidden_sha256` for all 13 hidden files, `prompt` states the three renames and says "keep vendored and generated code as they are" without naming the files or the check (final wording is a plan decision; the issue warns that traps written by Sigma's own agents can tune Sigma to them, design doubt D-6).
**`rubric.json`**: `{"criteria": [...]}` with three criteria (renames at every first-party call site; renames config key and docs page; leaves vendored, generated and shim files untouched). The schema has no consumer yet (design doubt D-3); verify.py requires only an object.

## 5. Lane and risks
**Lane: medium.** About 45 tracked files (13 hidden, 15 reference, 15 repo, 3 contract files plus a small test and README edit) but no new tooling or design, and the shape is proven. Not small because of the number of byte-pinned files and the control matrix.
Risks:
1. The decoy hash constants live in the hidden test; any later edit to a decoy, generated or compat file without updating the constants and `hidden_sha256` goes red on `hidden-sha256` or `hidden-on-reference`. Intended, but the plan must order edits (write files, compute pins, then hash `hidden/`).
2. The hidden test reads project files by relative cwd; it is correct only because `_hidden_run` runs at the tree root. A future executor that does not set cwd to the work tree breaks it. Accepted; same coupling as bench.
3. Hidden tests and the reference ship in the repo (design doubt D-2, accepted, not resolved here): an agent run from a checkout could read them.
4. The `.sdlc` copy of this dossier is scanned: keep home-directory paths and uncited-path text out of every committed goal artifact (the plan, controls and retro too).
5. The AST helper in my scratch hidden test is clumsy (re-parses the file four times); the implementation should write one small helper. Style only.
6. The naive overlay isolates nothing alone (cannot delete). The acceptance wording "a planted edit to either (and a missed rename or deletion) is seen red" is met by planted controls, not by `naive`.
7. Task `.py` basenames join the documented-gestures basename pool (section 2); a future doc showing a gesture with the same basename could turn ambiguous.
8. Default `python3` on this machine is 3.9.6 while the repo floor is 3.10 and CI runs 3.10-3.13; task code is plain syntax, but only 3.12 was run.
9. Not measured: wall time at 10x/100x tasks (linear, bounded by the task count; one task is 0.70 s); full suite; Windows.
