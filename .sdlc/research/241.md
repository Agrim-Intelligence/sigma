# #241 research — CI: fail-fast false, fix the 3-test Linux cluster

## Symptom
CI run on main: `test (3.12)` green, `test (3.10)` red at the pytest step on exactly three tests:
- `tests/test_feature_doc.py::test_the_isolation_check_catches_a_sync_that_reads_a_sibling`
- `tests/test_feature_registry.py::test_the_path_recorder_records_an_open_not_only_a_replace`
- `tests/test_feature_registry.py::test_the_isolation_check_catches_a_write_that_reads_a_sibling`

Reproduced locally on a Python 3.10.20 venv: same 3 failed, 273 passed across the two files. The
recorder saw only the atomic-write `*.tmp` sibling (via the `os.replace` spy) or nothing.

## Root cause
The `_Recorder` class (one copy per test file) spied on reads by replacing `io.open` and
`builtins.open`. On Python 3.10, `pathlib.Path.open` (and so `read_text`/`read_bytes`) calls
`self._accessor.open`, and `pathlib._NormalAccessor.open` is `io.open` captured as a class
attribute at import time — replacing `io.open` later is invisible to pathlib. Verified by
`inspect.getsource(pathlib.Path.open)` on 3.10 vs 3.12 (3.11 removed the accessor; 3.12 calls
`io.open(self, ...)` directly). Both production modules read through pathlib (`path.read_bytes()`,
`path.read_text()`), so on 3.10 every sibling read was unrecorded. The same accessor also captures
`os.mkdir`/`os.rename`/`os.replace`/`os.unlink`, so `Path.mkdir` etc. were likewise invisible.

Not a production bug: the modules behave the same on both versions; the test harness was blind.

## Blast radius
- `tests/test_feature_registry.py`, `tests/test_feature_doc.py` (the two recorder copies).
- `.github/workflows/ci.yml`: no `fail-fast: false`, so a 3.10 failure can cancel the 3.12 leg.
- `.github/workflows/windows.yml`: dispatch-only, runs `tests/test_windows_real.py` on 3.12; does
  not touch the recorder. Nothing stale found. Last run green.

## Other 3.10 findings
Full suite on 3.10 after the fix: 8997 passed, 6 skipped — no other 3.10-only failures.
One unreproduced flake seen once on the concurrent 3.12 run: `tests/test_risk_detect.py::
test_detects_each_category` (the content-scan hits were all missing; path hits present). Passes
isolated and in 3 reruns under `-n 8`; unrelated to this change (subprocess bash script).
