# Research: #457 action log and witness streams (B6)

Revision: origin/main 76536c9 (producing code); store measured in this checkout's live `.sdlc/state` (data written by many past revisions; not a clean run).

## Measured (command: python script over `.sdlc/state/{log,witness}/*.jsonl`, listed in docs)
- action log: 85 files, 207,178 bytes, 1,166 events; per goal min 309 / median 1,616 / mean 2,437 / max 14,491 B; 177.7 B/event mean, 657 B max line (writer caps at ~600 + overhead).
- witness: 36 files, 639,969 bytes, 1,915 events; per goal median 3,803 / mean 17,776 / max 159,216 B; 334 B/event mean, 479 max. Witness is the larger store: one line per failing-test red per verify run.
- 10x/100x of the byte totals are linear: log ~2 MB / 20.7 MB, witness ~6.4 MB / 64 MB. Not measured: disk-block overhead on other filesystems; a clean-room run; a goal with thousands of verifies.
- Reader cost at 100x (measured, 8,500 copies of the real log files): `sigma-log slots` 0.06 s at 85 files -> 0.68 s at 8,500 (`active()` reads every file on every call). Real ceiling is the per-call O(files) read, not disk.

## Ownership (from writers)
- `.sdlc/state/log/<goal>.jsonl`: `actionlog.append` (actionlog.py ~L360-373), called from loop.py/work.py. Sigma-owned, repo-local, gitignored, never under a host config root.
- `.sdlc/state/witness/<goal>.jsonl`: `witness.record` (witness.py:157-158), called from loop.py verify paths. Sigma-owned, same.
- Neither is under `~/.claude`, `~/.cursor`, `~/.codex`; nothing in scope touches a host config root.

## Readers (what a prune must not break)
- `log.py active/slots/status` and `actionlog.active_goals`: read every file; a goal is live iff its newest code-written row is not `recorded` (or is `recorded` result=review = awaiting merge).
- `work._branch_base_from_log`: a finished-then-restarted goal reads its original base from the log; absent -> falls back to config base (degrades, does not fail).
- `triage.py:340`: parked reason from the log, for OPEN parked goals only.
- `doctor.py` dispatch-compliance: 30-day window of ledger phase events vs the goal's log.
- Witness: `witness.verdict` / `red_green.py` consult the goal's witnesses at verify/pr/merge time, i.e. only while the goal is live.
- Audit trail: `actionlog.py` docstring: "best-effort status cache, not a durability-critical record"; durable records are the ledger/journal events, the PR and `.sdlc/` committed artifacts. Existing pruners: ledger journal 30 d, timing store 90 d. doctor.py:3550 and timing_store.py:214 both state the log "is never pruned" (to be corrected).

## Decision
Add a bounded pruner. Candidate = goal whose action log's newest code-written row is `recorded result=done`, whose log AND witness files are older than the retention window (default 90 d, floor 30 d = doctor window), with no live owner (claimed marker, agent marker, work record, phase marker, goal worktree). Parked/failed/awaiting-merge/reopened goals are never candidates. Witness-only stems (no log) are never candidates (closure unprovable).
