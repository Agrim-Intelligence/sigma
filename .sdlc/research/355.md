# Research: #355 — source and freeze the benchmark task set (reduced scope)

Origin/main `e18e7d0`. The issue body still says 30 tasks (15 external, 15 internal, 5 traps). The owner reduced the
benchmark on 2026-10-03; `docs/bench/preregistration.md` (amended by the merged changes for #494 and #502) governs: about
15 tasks balanced as far as the pool permits, one repeat, three traps authored outside the Sigma team, three arms, an
exact one-sided sign test whose operating characteristics are tabulated for 12 to 18 tasks only.

## What the harness already fixes (evals/bench/bench.py, merged for #354)

- `_load_tasks` reads `tasks/manifest.json`: `schema` `sigma.benchmark-tasks/v1`, `tasks[]` of `id, prompt, source,
  visible_command (argv), hidden_bundle`. `source` must be a directory beside the manifest (copied as the arm's tree);
  `hidden_bundle` is a relative name under the hidden root. The issue's `task.json` sketch (`visible_tests_cmd`,
  `hidden_sha256`, `timeout_min`) is NOT what the harness reads; extra keys are ignored, so the format here is the
  harness's four-plus-one fields plus the pre-registration's extras.
- Scoring (`_hidden_passed`) copies the final tree, copies the bundle to `.sigma-hidden/`, and runs `verify.json`'s
  argv there. The hidden root must be outside the repository, the scratch root and every task source.
- The harness has no fetch step: an external task whose `source` directory is absent is refused loudly, which is the
  safe failure; `bench_tasks.py materialize` fills it.

## Model and cutoff

The pre-registration proposes `claude-sonnet-5-5`. Anthropic's models overview (read 2026-10-04) lists Claude Sonnet 5.5
with a training data cutoff of Jun 2026 and a reliable knowledge cutoff of Jun 2026 (months only). Rule date used:
2026-07-01 (every PR created after all of June). Primary source, but a month, not a day; whether the owner pins this
ID is still the owner's decision.

## External pool

REST search only. Three query shapes (Q1 broad closed/linked/python sorted by reactions, Q2 label:bug, Q3 five-repo
OR groups over about 105 permissively licensed libraries), then per issue: timeline (cross-referenced merged PR), the
PR, its files. The broad queries return thousands of results dominated by large projects and small agent-written
repositories; the curated-library query is what produced candidates. Rejection causes found: tests that hang on the
base commit (an infinite-loop bug), console-script tests that need the project installed per tree, version modules
generated at build time, visible suites already red on the base commit (A3 would never see a pass), docs-only or
test-free PRs, PRs over 300 non-test lines, two merged PRs for one issue, merge commits not reachable.

## Findings that shape the build

- Visible tests must PASS on the starting tree, or A3 (retry until visible passes) can never stop on success.
- A hidden test that hangs on the base commit makes scoring wait the full timeout: reject, and kill process groups.
- CI has no hidden root, so the "no hidden file under evals/bench/" control needs per-file hashes in `task.json`.
- Verification environment is a venv of dependencies only; tests import the project from the tree (flat layout).
