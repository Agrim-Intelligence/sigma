# #358 research — unguarded write paths

Date: 2026-10-01

## Seams inspected

* `work._delete_remote_branch()` directly issues the REST delete after merge and finish cleanup.
  Its callers have the goal's resolved base in the work record and the effective work settings.
* `channel_notify.tick()` reads `ledger.autowatch.channel_webhook_url` and delegates to `_post()`.
  The documented operator gesture configures a loopback URL, so validation belongs immediately
  before the send and must remain fail-open.
* `work.merge_design()` already gates its write by `work.enabled`; `work.policy()` is the shared
  normalization for `auto_merge` and returns `off` safely for invalid values.
* `tools/readiness/write_surface.py` owns generated gate descriptions; its `render` command is
  the source of the Markdown inventory.

## Constraints

The branch cleanup must never turn a successful merge into failure. A failed `origin/HEAD` read
therefore removes only that optional comparison. Remote webhook refusal must not write the local
cursor, so it is checked before `_post()` and returns a normal empty/no-send path. Existing tests
inject every command or POST, so no network is needed.
