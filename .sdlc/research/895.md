## 2. Run contract and failure classification today
- `run(args)`: args WITHOUT "gh", returns stdout str, RAISES (gh_api.py module doc). `_default_run` (gh_api.py ~L67): `subprocess.run(["gh",*args], timeout=120)`; nonzero -> `RuntimeError("gh ... failed: "+stderr)` with `.hint=stderr`. Timeout raises raw `subprocess.TimeoutExpired` (not RuntimeError), wrapped by `_call` into `GhApiError(str(exc))`; `GhApiError` has only `.hint`: NO status, NO headers, NO cause class (`__cause__` is set via `from exc`).
- `sources._run_gh` has NO timeout; proxy text replaced in hint by `gh_session.proxy_session_block`.
- `gh api` stderr on HTTP error is `gh: <message> (HTTP 403)` (message = body `message`), so status IS in text as `HTTP <n>`; headers are NOT shown (needs `-i`, which changes stdout and would break `_json`). Rate-limit text: "API rate limit exceeded" / "secondary rate limit" / "You have exceeded a secondary rate limit". So classification = regex on `str(exc)` + `.hint`: `HTTP (\d{3})`; 403 is rate-limit iff text matches rate.?limit (header-less; document as the ceiling), else permission -> no fallback. Connection: "dial tcp", "i/o timeout", "connection (refused|reset)", "no such host", `TimeoutExpired`. 401/404/422 never fall back; proxy block (`proxy_session_block`/`graphql_unavailable`) never falls back.
- Needed: add `GhApiError.status` (int|None) and `.kind` in {rate_limit,server,transport,auth,permission,not_found,invalid,other}; one `classify(exc)`; `_call` fills them. Unmeasured: exact stderr of 429/secondary-limit (take from gh source/docs, label as inferred in code+docs; add test fixtures, not live claims). A real 5xx text `(HTTP 502)` likewise.

## 3. Policy home, breaker, log
- Policy lives in gh_api: new `read_issue(run, number, fields, repo, *, gql_run=None, env, state_dir)` and `read_issues(...)`: REST via `view_issue`/`list_issues` -> normalise to gh shape; on fallback-class error AND `graphql_available(env)["available"]` AND breaker/budget allow -> ONE `gql_run(["issue","view"|"list",...])`; log each fallback; re-raise original REST error if no fallback, if fallback fails raise `GhApiError` naming both.
- Callers pass `source._run` as gql_run and the REST runner = the same seam (`source._run` accepts `api ...` argv already; `_fetch_issues_rest` does this), so test fakes keep injecting one runner.
- GOTCHA: `_load()` re-execs a fresh module copy per importer (sources.py:183-227 comment; gh_api itself loads sources lazily), so module-global breaker state is per-copy: NOT session-level. Put state in a file: `<sdlc_dir>/state/gh-rest-breaker.json` (`.sdlc/state` is gitignored per-machine runtime, state.py:120; symlink guard state.py:263) written atomically (reuse gh_api `_write_cache` pattern, tmp+os.replace). Fields: consecutive_failures, opened_at, last_kind. Opens after 3 consecutive fallback-class REST failures; cool-down (e.g. 300 s, `SIGMA_GH_BREAKER_COOLDOWN`); while open, go straight to GraphQL (if available) else REST anyway (half-open probe every call after cool-down); any REST success resets. Host-agnostic (pure Python, works with cursor, no hooks). Corrupt/unwritable file = closed breaker (fail-open, noted). Concurrent loop workers race on it: last-writer-wins is acceptable (advisory counter); state it.
- Fallback log: append JSONL `.sdlc/state/gh-fallback.log` (ts, op, kind, status, rest_error[:120], fell_back) bounded (rotate/truncate at e.g. 200 lines, AGENTS.md unbounded-growth rule); also one stderr line. No secrets (args may hold bodies: log op+number only).
- Dir plumbing: callers lack sdlc_dir in places (GitHubSource has none, sources.py ~1262 comment); default via env `SIGMA_SDLC_DIR`/cwd `.sdlc` lookup as state.py does; if none resolvable, in-process breaker only (documented ceiling).
