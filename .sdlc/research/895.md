## 2. Corrections / risks in the design notes

1. assign.py's second site is `source._run(["issue","edit",...])` at assign.py:314 (a write, not in scope). Baseline 2->1
   is correct. `resolve_assignment` has `sdlc_dir`, `_active_members` does not: add an optional `sdlc_dir=None` kwarg.
2. ORDERING IS LOAD-BEARING. `gh issue list` default = created DESC, but `fetch_issues_rest` defaults `sort=created,
   direction=asc`. Every site must pass `direction="desc"` (else a >cap board returns the OLDEST rows, the opposite
   of today). Site 6 must be `sort="updated", direction="desc"` (native REST params; no `--search` needed on the REST
   leg) because `candidates[:max_issues]` depends on it. Fallback argv can only express created-desc (default) or
   `--search sort:updated-desc`; `list_issues_gh` must REFUSE (ValueError) other combos, e.g. created/asc, rather
   than emit a fallback in a different order.
3. LABELS AND: confirmed equivalent (REST comma-join ANDs, same as repeated `--label`; documented in
   fetch_issues_rest). Label names containing a comma cannot be sent; sdlc:* never do.
4. NEW LITERAL RISK for the ratchet: design 5 proposes `lambda args: run(["gh", *args])`, which is a NEW rule-3 site
   (`["gh", *args]`) -> doctor 7 becomes 8. `doctor._gh_runner(doctor_run)` (doctor.py:1228) already is exactly that
   adapter. Build the raising wrapper ON TOP of `_gh_runner(run)`, not a second literal.
5. FAILURE-AS-EMPTY TRAP. `_gh_runner`/doctor `run` NEVER raises; failure is a falsy `_RawFailure` (`.raw`). Fed straight
   to `fetch_issues_rest` it does `json.loads(raw or "[]")` -> empty list = SUCCESS, never classified, never falls
   back (and breaker never trips). The raising wrapper (raise RuntimeError with `.hint = _failure_text(res)` when
   `hasattr(res,"raw")`) is required, not optional. Use the existing `_failure_text()` (doctor.py:~42), don't
   re-implement. Same latent flaw already exists at doctor.py:2513 (`census(run=_gh_runner(run))`): after slice 2c the
   census REST read through plain `_gh_runner` reads an outage as an empty ok census (previously also `[]`-ok;
   NOT a regression, but name it or route 2513 through the raising wrapper).
6. Doctor success path returns stdout+stderr concatenated; any gh stderr warning breaks `json.loads` on a page ->
   ValueError -> GhApiError kind other -> NO fallback -> `None` (fail-open, same as old bad-JSON arm). Acceptable.
7. Non-list payload: `fetch_issues_rest` iterates `page_items` blindly; a dict body yields `[]` (not an error), so the
   `isinstance(list)` guards at sites 1-4 become dead code and test_assign.py:581 ("unexpected gh output" warning on
   `{"not":"a list"}`) will flip from warning to silent `[]`. Either harden `fetch_issues_rest` (shared; touches
   triage/mirror/status callers' fakes) or accept and rewrite that test; decide at plan time. Recommend a small guard
   inside `list_issues_gh`'s wrapped run (validate each page `json.loads` is a list) -> GhApiError other.
8. Fallback runner trap is real in doctor: `gql_run` must be the same raising wrapper, and the `graphql_available(env)`
   gate lives inside the shared helper, so passing a different raw `run` as fallback cannot bypass it only if the
   helper owns the call. Control (c) must prove this.
9. `sdlc_dir` for doctor: `check()` has it (sdlc_dir param, doctor.py:2289) but the six helpers take
   `(gh_cfg, [cfg,] run)` and are called directly by test_doctor.py (8+ direct references). Threading = optional
   `sdlc_dir=None` kwarg on 6 functions + 6 call sites at 2432/2470/2494/2558/2573/2590. Cost small; but doctor is a
   diagnostic and would start WRITING `state/gh-rest-breaker.json`/`gh-fallback.json`. Recommend thread it (SHARES
   breaker; consistent with other slices) but flag the new write behaviour; otherwise pass None and document that
   doctor neither trips nor reads the breaker.
10. `assign._active_members` docstring says "REST-search-backed, never GraphQL": unverified/likely false for a bare
    `gh issue list` (no label). Fix the sentence when touching it.
11. GitHubSource has `sdlc_dir` and `_repo`; `_list_issues` as designed mirrors `_read_issue` (sources.py:1313). OK.
    reconcile adapter needs `state`+`closedAt`: `to_gh_shape` already maps both (state upper-cased, MERGED mapping
    harmless for issues). `labels` returns REST dicts with `name` (what `_names()` reads). `body` missing key raises
    GhApiError -- REST list always has `body`, so fine; sites 5,7-10 request only number/labels.
12. Cost: REST list = ceil(n/100) requests (stops when a page < per_page). Doctor cap 200 = <=2 requests/site, 3 for
    multi-state scan x2 pages = up to 6; census / blocking at cap 5000 = up to 50 requests. Doctor runs every gh call
    under `network_timeout()` (default 15s per call): worst case per site ~ 2 REST + 1 fallback = 45s, multi-state
    ~135s -- name as ceiling; was ~15s/site. The GraphQL `search()` this removes is ~2600 points/call (per
    fetch_issues_rest docstring, measured by #1829 research, not re-measured here).
13. Fallback on a partially paged read (page 3 of 50 fails) discards the pages and re-lists ONCE via gh -> consistent.
    A rate-limited PAT paging 50 requests is more likely to hit rate_limit; one fallback list may then also fail:
    all sites keep their fail-open arm, so this is bounded.
14. `log` entry for lists: `number: None` and `op: "issue_list"`; confirm the bounded log tests accept a null number
    (read_issue regression keys must stay byte-identical).
