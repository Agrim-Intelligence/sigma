## 0. Verdict in four lines

* Every Projects v2 call made BY THE LOOP is inside `GitHubSource` (`skills/sigma-loop/scripts/sources.py`) and reaches
  `gh` through `self._run`. Every one of them is already preceded, in its entry point, by a read of
  `self.project_enabled` (or by `_ready_lane`, which checks it). `project_enabled` is a plain attribute set once from
  config (sources.py:1097). It never consults GraphQL availability.
* The cheapest correct gate is ONE predicate, `GitHubSource.board_active` (property), = `project_enabled` AND
  `gh_api.graphql_available()["available"]`. It emits ONE stderr notice per process when it is the GraphQL half that
  says no. Swap the 5 internal `project_enabled` guards and the 3 external readers onto it. No change to `_run`.
* Do NOT gate `_run` or `_graphql` generically: `_graphql` also carries label transitions (`_swap_labels` 1679,
  `_label_node_ids` 1547, `_issue_node_id` 1619) and `reconcile.py:428` timeline reads. Those are label writes
  (source of truth), not the board, and are other slices' business.
* Doctor, `board_migrate.py`, `board_setup.py`, `board_layout.py` are human-invoked and use their own `run`, not
  `GitHubSource`. They stay out of the gate; they need only the one-line doctor wording in section 4.

## 2. How availability and notices work today

`gh_api.graphql_available(env=None, cache_dir=None, run=None, now=None, probe=False)` (gh_api.py:255) returns
`{"available", "reason", "source"}`. Precedence: `SIGMA_GH_GRAPHQL=off|on` override, then `CLAUDE_CODE_REMOTE=true|1`
(unavailable, inferred), then optional probe (needs injected `run`, cached), else "no cloud signal" => available.
It is O(1) with `probe=False`; the existing callers in work.py (5324, 5340, 6252) and gh_api.py (559, 582, 800) call it
bare (env only). Use the bare form: no probe, no network, no new cost.

Existing "once" idioms to reuse (do not invent a third):
* instance flag + `sys.stderr.write` in try/except: `_scope_warned` (sources.py 1147, used 4076-4085). Exact shape to copy.
* per-distinct-text set: `_board_write_failures_warned` (1151).
* attempt-once: `_board_attempted` (1138), `_ro_attempted` (1127).
* gh_api breaker log lines (gh_api.py 590, 805) are the REST-fallback precedent, per call.
"Once per process" must be stronger than per instance if several `GitHubSource` objects are built (doctor, triage and
phase_report each build their own). Recommend a module-level `_BOARD_GRAPHQL_NOTICED = False` in sources.py (the
flag is reset by tests via monkeypatch), set in the predicate. One process, one line, regardless of instance count.

## 3. Recommended single gate and how a test enforces it

Gate (sources.py, on `GitHubSource`):

```
@property
def board_active(self):
    """PE and GraphQL reachable. The ONLY board entry condition. One stderr notice per process when GraphQL is the reason."""
    if not self.project_enabled:
        return False
    if gh_api.graphql_available()["available"]:
        return True
    _notice_once()            # module flag; message names SIGMA_GH_GRAPHQL and that sdlc:* labels remain the source of truth
    return False
```

Rules: swap `not self.project_enabled` for `not self.board_active` at 1889, 3110, 3882, 3923, 5248 (the `(self.project_enabled and number)`
form at 5248 becomes `self.board_active and number`), and at promote.py:618, unpark.py:453, auto_unpark.py:385.
`_set_board_status` returning False is already the honest "not moved" answer and callers handle it, so no new return
shape. Never raise, never park: every guarded function already returns None/False/early on a falsy gate. With
GraphQL available the predicate reduces to the old attribute read and adds one dict-returning env lookup that no
board call can observe: argv and behaviour byte-identical. (Verify with the existing boardfake tests unchanged.)
Cost: one `os.environ` lookup per guarded call; no scaling concern. Ceiling: none new.

Honest limit: `_ensure_board`, `_item_id`, `_archive_card`'s inner calls are not individually gated; they are
reachable only through a guarded entry. That "reachable only through" claim is exactly what the test must prove.

Structural test (new `tests/test_board_gate.py`, AST over sources.py, about 40 lines, no live gh):
1. Find every function in `GitHubSource` that contains a list literal starting `"project"` or starting `"api","graphql"` with a
   `ProjectV2` / `projectV2` string in the same function ("board argv"). Call these LEAVES.
2. Build the intra-class call graph by `self.<name>(...)` attribute calls. For every LEAF, walk callers to the
   public/external entry functions. Assert every path passes through a function whose source references
   `board_active` (the GATES), except an explicit allowlist `{ "_find_project", ... }` justified only if every caller is a gate.
3. Assert `project_enabled` is read ONLY inside `board_active` within `skills/` (grep-by-AST over `Attribute(attr='project_enabled')`),
   so a new caller cannot bypass the gate by reading the raw attribute.
4. Control, per AGENTS.md "run the control": delete the `board_active` reference from `_set_board_status` and see the
   test go RED; reintroduce it, see green. Also run the DOCUMENTED gesture, not a stronger one: the invocation in
   the docs is `python3 -m pytest tests/test_board_gate.py` with a normal env, so the test must set its own
   `CLAUDE_CODE_REMOTE` via monkeypatch and not require the caller to export it.
Runtime half (same file): monkeypatch `CLAUDE_CODE_REMOTE=1`; `GitHubSource` with `project.enabled: true`, a
recording `run` that raises AssertionError on any argv whose first token is `project` or whose second is `graphql`; drive
`next_pending`, `claim`, `complete`, `park`, `_set_board_status`, `set_board_phase`, `_ensure_board`; assert no board
argv, no raise, and exactly one stderr notice across two instances (reset the module flag first). Twin with
`SIGMA_GH_GRAPHQL=on` and the stock fake: board argv flows exactly as before.
Sensitivity caution (AGENTS.md ports rule): this is a deterministic AST/recording test, not probabilistic; no collapse risk.
