## 1. merge_rights permission read

- Mapping to the GraphQL enum `_CAN_MERGE = (ADMIN, MAINTAIN, WRITE)`: admin->ADMIN, maintain->MAINTAIN,
  push->WRITE, triage->TRIAGE, pull->READ (highest true wins). The error text keeps `"<perm> access on this repo"`.
- Fail CLOSED: missing/null `permissions`, non-object, non-bool values, all false, an exception, empty output => "could
  not determine merge rights" (returned line routes to `record review`, never a park/failed record).
- UNMEASURED: whether a cloud session's token (an installation / proxy token) gets `permissions` on this endpoint; GitHub
  documents it as present for authenticated reads but it is not verified for that token class. If absent, the
  result is the fail-closed line above, not a merge.

## 2. protection()
- MEASURED: this repo enforces via RULESETS. Classic `GET branches/main/protection` -> 404 "Branch not protected", so
  today protection() says "not protected" for a repo that requires 1 review + required check `test`.
  `GET repos/{o}/{r}/rules/branches/main` -> list of `{type, parameters, ruleset_id,...}`; `pull_request`
  `parameters.required_approving_review_count` = 1; `required_status_checks` `parameters.required_status_checks[
  {context, integration_id}]`.
- Design: classic (kept, same parse) UNION rules (new). enforces = checks or reviews from either. Either read failing or
