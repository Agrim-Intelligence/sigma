# #414 P2 RESEARCH: planned-test red proof loses reds to pytest's 80-column summary trim

Worktree read: `.sdlc/work/414` (branch `sdlc/414`). The issue cites the old pre-rename loop path; the code is `skills/sigma-loop/scripts/red_green.py`.

## Mechanism (read)
- `_run(root, argv)` (line 64) is `subprocess.run(argv, cwd=root, capture_output=True, text=True)`. It passes no `env`, so the child inherits the caller's environment. Piped stdout means pytest takes its width from `COLUMNS`, else 80.
- `observe()` (line 132) calls `run(root, ['python3','-m','pytest','-q','-rA','--tb=short','--color=no','--rootdir=..', *nodes])` (line 145). It splits on `=+ short test summary info =+` and takes the last chunk.
- Only the `FAILED <node> - <reason>` line is parsed (line 165): `partition(' - ')`, then `re.match(r'(AssertionError\b|assert\b)', reason)`.
- Fallback `_split_traceback_assertions` (line 97) joins bare `FAILED <node>` lines to `E   AssertionError`/`E   assert` traceback blocks. It only credits a node when file + unparameterized function name pick exactly one node. It returns the empty set if the output has any `Captured stdout|stderr|log` section. So parameterized ids and any noisy test are not rescued.
- `collect()` (`--collect-only -q`) is not affected: node ids are not trimmed there.

## Measurement (pytest 9.1.1, py3.12, scratch repo in the scratchpad `m/`)
Raw `-q -rA --tb=short --color=no`, piped:
- Default width: `FAILED <node>` with the ` - reason` dropped for ids over about 80 columns. The ids are not truncated in pytest 9.1.1. The issue's `Ass...` cut happens only for ids short enough to leave a few columns of reason.
- `COLUMNS=1000`: full `FAILED <node> - assert 1 == 2` / `- assert False`. The `short test summary info` banner is padded to 1000 columns of `=` but still matches the `^=+ short test summary info =+\s*$` split.
- `COLUMNS=100000`: no failure.

Through the real `observe()` against the scratch repo (5 failing tests: a 140+ character id, a parameterized pair, a noisy test with print):
- Default env: **0 of 5 witness rows recorded**. The fallback did not rescue even the non-parameterized ones, because the file has a Captured stdout block and the fallback bails.
- `COLUMNS=1000` in env: **5 of 5 recorded**.

This confirms the issue's claim and its fix. pytest 7 and 8 were not measured (`SIGMA_VENV312` holds 9.1.1 only). The behaviour is documented as honouring `COLUMNS` through `shutil.get_terminal_size`, but that is unmeasured here.

## Design options
(a) Set a wide `COLUMNS` in the subprocess env. Smallest change. Measured working. Needs `env=dict(os.environ, COLUMNS=...)` in `_run`. Open points:
  - Value: 1000 was measured. Anything at least longer than the longest `FAILED <node> - <reason>` line works; 4000 gives headroom for node ids with long parametrize ids. The cost is a longer `=` banner only (about 1 kB, measured at 1000).
  - Override a user's `COLUMNS` unconditionally. A user who exports `COLUMNS=60` would silently reintroduce the bug, so respecting it is wrong here. `LINES` is irrelevant.
  - Only `_run`'s env: injected `run=` fakes (tests) keep their own signature `run(root, argv)`, so the contract stays unchanged. Putting COLUMNS in `_run` covers the `collect` call too, which is harmless.
(b) Parse without reasons (junitxml, `-rA` plus `--tb=line`, json report). Larger: junitxml adds a temp file and changes the trust model (forged output defences exist today for captured text). Not warranted. The existing fallback shows the cost of reconstructing attribution.
(c) Belt and braces: (a), plus make `observe` count a `FAILED <node>` line with no reason as unattributed (no change; fail closed stays). Not needed.

## Recommendation
Do (a): in `_run`, build env `{**os.environ, 'COLUMNS': '4000'}` (override any inherited value), add `import os` (not currently imported; imports at lines 7-14), keep `run=` fakes unchanged. Add the two tests above, a one-clause doc line in `docs/enforcement.md`, and optionally refresh the `test_key_body.py` docstring.

## Risks
- A fake `run` that ignores env is not affected. A test that asserts `subprocess.run` is called with exact kwargs would break; grep found none (`tests/test_test_first_gate.py` uses fakes only).
- Pytest versions where `COLUMNS` is not honoured: unmeasured on 7/8; the real-pytest test running on the CI matrix is the evidence.
- 4000-column banner makes `proc.stdout` slightly larger; negligible.
- `onboarding_control._pytest_env()` builds a restricted env for variants; unchanged because it does not go through `_run`.
- Old reds already lost stay lost; no data migration. The `#352` workaround (`COLUMNS=1000` in its verify) can be dropped later.
- Host-agnostic: the change lives in Sigma's Python, so it applies to every host. Safety/resource: no new limits.
