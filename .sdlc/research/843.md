## 6. Design proposal (stage 1, skeleton)

CLI (hand or argparse, `usage:` on stdout for `-h`/`--help`): `python3 skills/sigma-kg/scripts/sysgraph_merge.py merge <fragments-dir> --out <dir>`. `--stale-after-days`, `--as-of`, `--traces` are later slices: reject unknown flags with exit 2, do not accept-and-ignore them. No default `--out` (SAFETY: nothing writes unless operator names a directory).

Layout: `<fragments-dir>/*.json` (flat, non-recursive, sorted by file name; D-8 in 678.md leaves `fragments/<repo>/` open; accept flat now, note it). Output files, fixed names so "refuse to write outside --out" is structural:
- `<out>/merged.json`: `{"sysgraph_version": "1.0", "merged_from": [{"repo","commit","commit_time","file"}...sorted by repo], "nodes": [...deduped by id, sorted by id], "edges": [...sorted by (type, from, to)]}` , `json.dumps(sort_keys=True, indent=2, ensure_ascii=False) + "\n"`. Stage-1 does union only: no resolution (that is slices 2-4). Edge dedup is out of scope; keep all, sorted. Same-id node conflict: keep the one from the fragment with the greater (commit_time, commit) and note it, or simply first in repo-sorted order; pick one rule and test it.
- `<out>/unresolved.json`: `{"unresolved": []}` skeleton in slice 1 (contract file exists so downstream can rely on it; entries land in slice 3).
- Report on stdout (and nothing else written): `merge: <N> fragment file(s) read; <R> repositor(y|ies) contributed; <S> superseded; <K> skipped corrupt; <V> refused version` then one line per skipped/refused: `skipped corrupt: <filename>: <reason>` / `refused version: <filename>: sysgraph_version "2.0" unsupported major 2 (supported: 1)`, then `wrote: <out>/merged.json, <out>/unresolved.json`. Deterministic (no wall clock, no absolute temp paths).
- Selection: group by `repo`; key `(commit_time, commit)`, max wins; commit_time compared as parsed string (fixed-width ISO sorts lexicographically; validate with the `_TIME_RE` shape so the compare is sound); order-independence tested by shuffling and by reversing file order, and with a tie on time (sha decides) and equal time+sha across two files (smaller file name wins, deterministic, reported).
- Corrupt = unreadable, non-UTF-8, non-JSON, not an object, missing/non-string `repo`, missing/invalid `commit_time` or `commit`, `nodes`/`edges` not lists. Version problems are a separate class (REFUSED), including a malformed version string.
- Atomicity: per file temp + `os.replace` (state.py:1081 shape). Two files are not jointly atomic: write `unresolved.json` first then `merged.json` (consumers key off merged.json) and state in the module docstring that a crash between them leaves the old merged plus a new unresolved; stage everything in memory before writing so a data error never leaves a partial `--out`. Out-dir safety: `os.path.realpath(out)`; refuse if the out directory or either target is a symlink, or if `--out` equals or is inside `<fragments-dir>` (a rerun would then read its own output as a fragment) — also skip non-fragment names defensively. Fragments dir missing / not a directory -> exit 2.
- Exit codes: 0 ok (>=1 repository contributed); 1 nothing contributed (zero valid fragments; writes nothing); 2 usage/IO.
- Scalability: reads one file at a time, keeps only the winning parsed fragment per repo in memory (O(repos x fragment size), documented ceiling; 100x measurement is a slice-1 plan item, bound each file by a size limit derived from the machine like #663 `default_max_bytes` = page_size*phys_pages//32, `--max-bytes` override). Liveness (stale merge nobody reran) is out of scope (678.md D-8).

## 7. Constraints

- Stdlib only, no model/network/subprocess; Python 3.9 syntax.
- Deterministic bytes across reruns: sorted keys, sorted lists, trailing newline, no timestamps, report free of absolute temp paths.
- Must not make `git pull`/`work.py start` refuse in the root checkout (AGENTS.md): merge writes only to caller-named `--out`; tests use `tmp_path`.
- Unknown top-level keys in a fragment are ignored (match #663), but not copied into merged.json.
- Guard control rule: each new guard clause (tie-break, version refusal, corrupt skip, out-dir containment, symlink refusal) must be seen red by breaking it alone; tie-break order check must be weakened to plain membership/first-wins to see the test go red. The "all file orders give the same choice" claim needs a test over permutations, not one shuffle.
- `-h` must not create files (test_script_help snapshot diff).

## 9. Open doubts (need owner or later goal)
