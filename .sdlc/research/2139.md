# Research: A blocked goal can stay blocked after its blocker closes; the chain reports `claimed`
**Goal**: #2139 · **Lane**: medium (top of the band; see Lane rationale) · **Date**: 2026-11-05

## Goal in one paragraph
Three defects around the `sdlc:blocked` overlay, in scope after the split (part 3, "the sweep only runs on a pick", is #2140 and out of scope). (1) The auto-unpark sweep keeps the label while ANY referenced issue is open, including one named only by a weak word (`needs`, `after`, `requires`, `waiting on`), so a goal whose explicit blocker closed stays blocked because of prose next to an unrelated open issue. (2) A goal labelled by hand with no recorded blocker is never lifted, and nothing says so. (4) `chain.py run` reports such a member as reason `claimed` (exit 3) although nothing holds a lease, the plan forecast assumed the sweep would lift it, and the sheet asked nothing; even the plain case (blocker closes, sweep lifts, the #1129 cooldown empties the pick) produces one false `claimed` stop. The fix: the sweep counts only explicit references once a goal names one; the chain plan answers read-only "would the sweep lift this member?" and asks up front when the answer is no; a cycle whose sweep just freed a member is `running`, a sweep the #2021 interval skipped is forced once, and a root held only by the label stops `decision` naming `/sigma-unpark #N`.

Reproduced on this worktree's code (main 57f4391, scratch copy byte-identical apart from `__pycache__`), with the two scenario files supplied with the brief, run outside the repo:

| Scenario | Today |
| --- | --- |
| explicit blocker only, interval 0 | cycle 2 `stuck` exit 3 `claimed` (sweep lifted the goal, cooldown emptied the pick), cycle 3 picks it |
| explicit blocker closed + a `needs` comment naming an unrelated open issue | `claimed` on cycles 2-5; label never lifted |
| explicit blocker only, default 10-minute interval | `claimed` on cycles 2-5; the chain's own sweep is skipped by the interval and nothing lifts the label |
| single member labelled by hand, no recorded blocker | `claimed` on cycles 1-3 |

## How the pieces work today (answers to the brief's mapping questions)

### 1. The sweep
- Per issue (`auto_unpark.py:500-578`): skip a blocked-only issue the stored map says still waits (#1625, 503-505); one comment read through `_CommentReads` (507); skip the keep-parked marker (508-509) and a declared gate (510-511); `extra_text` = capped, dismissal-filtered, prefix-stripped comments (512-514); `refs` = every `_BLOCK_RE` ref in title + FULL body + comments, any state (515); state read per distinct ref, memoised in the shared `open_cache` (518, `_ref_is_open` 325-363: unreadable reads as open); any finding holds (519-520); a parked issue is resumed only with the waiting note of #1549, and a later label-only re-park cancels that note (the rule of #1630; lines 537-540); one `swap-label` (+ card move on a board repo, 553-577); `resolved[n] = sorted(refs)` (578).
- `eligible` = `len(resolved) + len(rearms)` (`auto_unpark.py:1005`); `unparked` = the issues whose every unpark action landed, plus filing-cap re-arms (954-1006); the audit comment `_UNPARK_COMMENT` "Auto-unparked by Sigma — blocker(s) {refs} closed; re-added {label} for re-examination." (855-856, posted 964-991, or through the decision record 975-984 with the same refs).
- `blocking` sync (`compute_blocking_actions`, 582-684) runs only when both label queries succeeded (925-932), uses the same scanners and adds `sdlc:blocking` for every finding, confident or not (641-644).
- Interval (#2021): an applying, non-forced sweep runs on the first pick of a session, then at most once per `interval_minutes` (default 10, `auto_unpark.py:113`); skipped -> `{"skipped": "interval", "unparked": []}` (915-917). The session key is `SIGMA_RUN_ID|session_pid`, or None (interval only) when neither is known (192-199); chain's call passes neither.

### 2. The chain path
- Record: `.sdlc/state/chains/c<N>.json`, `SCHEMA = "chain-plan/1"` (`chain.py:198`); `_read_record` refuses any other schema (253-261), so the change must ADD optional member fields, never bump the schema. No contract file under `contract/` describes it (`contract/vocabulary.json` is the ledger's).
- Member row (live, `chain.py:632-641`): `number, verdict, labels, prio, spend, assignees, in_progress, blocked`, optional `base_verdict`, `checkpoint`; `_finish` adds `unit, depth, waits_on` (373-399); `_brief_kinds` adds `kind, park_why, kind_guess, answered` for parked rows (310-334); `stale_label` (649-651). Map rows (`chain.py:457-464`): `number, verdict, life, prio, in_progress, blocked, assignees | assignees_unknown`. `waits_on` holds only open in-chain members; closed prerequisites are in `done`, open outside ones in `externals[].needed_by`.
- Parked member end to end: plan `_brief_kinds` -> `park_why`; sheet `questions_of` -> `chain_asks.park_questions` (`park:<n>`, options `[keep it parked, release it]`, first recommended, `UNGROUPED`); `answer` records it (no GitHub write, `chain.py:1227-1243`); `--defaults` takes `keep it parked`; `approve` requires no open question (`chain.py:1289-1305`); `arm` -> `chain_enact.enact` releases `chain_asks.released(rec)` with `unpark.resolve(..., "unpark")` (`chain_enact.py:77-95`); forecast/arm/run read `chain_asks.view(rec)` (released -> `armed`, kept -> `kept-parked`); the run's stop words come from `chain_asks.stop_context` (`chain.py:1857-1858`), the reason from `_stop_of_first_root` (parked branch `chain_forecast.py:153-158`).
- First cycle: `run` refuses until approved and armed (`chain.py:1725-1732`); each call is one cycle, `blk["cycle"] += 1` (1761); order: sweep (1750), cap admit (1762), growth (1772), `label_drain.plan` read (1787), confirm-closed reads (1790), hidden-wait skip (1799-1810), width plan (1811-1813), pick (1814-1822), outcome (1823-1865).
- Cooldown (#1129): in the loop `_next` folds `just_unparked` into `skip` (`loop.py:3034-3042, 3069-3071`); in the chain the sweep's refs become the pick's `--skip` (`chain.py:1750, 1782`). `chain.run` learns what the sweep lifted ONLY from that return value; `_default_sweep` drops `skipped` (1498-1499); what the pick subprocess's own sweep lifts is invisible to it.
- Forcing a sweep: `sweep_unpark(..., force=True)` (915), as the CLI does (1041).

## 4. Where the code disagrees with the hypotheses, and what to do instead
- **A (a)**: `confident` is the right discriminator, computed per ref as an OR across matches (`backlog_check.py:422-424`): a ref is explicit when any match of it is an `EXPLICIT_TRIGGERS` form (`blocked by`, `depends on|upon`, `blocked on|until`, the tight follow-up forms; follow-up forms only in title/body, `blocker_scan.py:136-138, 196-198`). "Names an explicit blocker (any state)" = run `_explicit_blockers` once more with every ref marked open and ask `any(confident)`: pure regex, zero `gh` calls. In the sweep there is no `blocker_refs` field on the goal doc, so the `_record_blocker_refs` path (always confident) never applies. Explicit can come from title, full body or a trusted comment (each comment capped at the excerpt budget). Caveat to record: a `DISMISS_MARKER` dismissal is not applied by the sweep (it is applied in `cross_check` only), so a dismissed explicit ref still holds (TD-5, pre-existing).
- **A (resolved)**: the hypothesis's "today they would name a still-open weak ref" is a consequence of A, not a current bug (see Claim verification). The filter must also feed the decision-record text (`auto_unpark.py:978-981`).
- **A (blocking)**: not in the hypothesis. Recommend applying the same holding rule in `compute_blocking_actions` (D-2), otherwise the pass that frees the goal still labels, re-ranks and may grant membership to the unrelated issue named weakly, and `docs/label-model.md:836-837` stays false.

## Lane rationale
Medium, top of the band. Separable if Plan-Review wants it smaller: A (BR-1/BR-2 + TA1-TA7 + label-model/backlog docs) can land alone; B and C share the stop rule and should land together.
