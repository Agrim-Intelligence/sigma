# #228 research — init sets a real verify command

## Reproduced (before the fix)

Fresh git repo, `sdlc_init.py . --demo`, `loop.py start`, write `sigma-demo.md`, then:

- `loop.py verify .sdlc .sdlc/goals/0000-demo.md` -> `NO-COMMAND`, exit 3.
- `loop.py record .sdlc .sdlc/goals/0000-demo.md done` -> `REFUSED: no verify evidence`, exit 4.

The shipped template (`skills/sigma-init/templates/config.json.tmpl`) has
`"verify": {"command": "", "enforce": true}`. Nothing fills the command.

## Where the command is really read

`loop.py verify_goal`: goal frontmatter `verify_command` (local-goals mode, only when the goal
argument is a `.md` path), else config `verify.command`. `.sdlc/project.md`'s "Verify command"
section is read by nothing for this. `sigma-init/SKILL.md` step 3 and the template's `_verify`
comment both send the user there. That is the false instruction.

## Blast radius

- `skills/sigma-init/scripts/sdlc_init.py` — `scaffold()` (shared by the CLI and
  `wizard_actions.run_scaffold`), `_DEMO_GOAL`, `main()`.
- `skills/sigma-init/templates/config.json.tmpl`, `templates/project.md.tmpl`, `SKILL.md`.
- `skills/sigma-loop/scripts/loop.py` — `verify_goal` (NO-COMMAND, exit 3), `record done` refusal
  (exit 4), `_config_warnings`.
- `skills/sigma-doctor/scripts/doctor.py` — row `verify command present (enforce is on)` already
  exists and is not gated by `cheap_only`. Its fix text names no gesture.
  `_any_goal_verify_command` counts `verify_command:` with an empty value as a command.
- `skills/sigma-init/scripts/setup_wizard.py` — `_MODES` allow-list does not include that row, so
  the first-run wizard never raises the trap.
- `skills/sigma-setup/scripts/setup.py configure` already never enables enforce without a command.
  It is the model to follow.

## Constraints

- Frontmatter parser strips `"` from both ends of a value (`v.strip().strip('"')`). A demo
  `verify_command` must not start or end with a double quote. Passing the file name as a trailing
  `sys.argv` argument avoids the problem, and it runs under both `sh` and `cmd.exe`
  (`shell=True`).
- Detection must not run repository code: read files only, bounded scans, stdlib only.
- `python3` is not on PATH on every Windows install. `shutil.which` decides between `python3` and
  `python`. That is a PATH lookup, not an execution.
- `test_setup_wizard.py` pins the allow-list shape. The docstring says "six".
