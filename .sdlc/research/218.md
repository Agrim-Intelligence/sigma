# Research — #218 hook-path adoption

`setup.py init` delegates to `init_flow.py`, and `/agrim-init` runs the same flow; there is one supported adoption path. `sdlc_init.py` already shells out to `setup.py` for repository-local setup work, so a narrow `setup.py hooks <repo>` command keeps the git-config decision in the setup boundary without a cross-skill Python import.

The checked-in `hooks/` directory contains host hooks, not Git hook entrypoints. The revival hook directory is intentionally outside the public core surface, and `tests/test_no_private_names.py` rejects its raw name. The installer therefore needs only to set the established relative Git configuration value; it must not copy or expose the private hook implementation.

Safety decision: read the local value first. An unset value is written with `git config --local`; an equal value is an idempotent success; any different value is a refusal before the init flow writes files. Git repository-selection/config override environment variables are removed from the subprocess environment so the command cannot write another repository's configuration.

Controls: use real temporary Git repositories through the documented init CLI, assert `git config --local --get core.hooksPath`, and preseed a differing local value to prove the refusal preserves it and leaves no `.sdlc` scaffold behind.
