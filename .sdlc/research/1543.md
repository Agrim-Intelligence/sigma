## Edge cases
- **What counts as a third case**: an if/elif chain, `match`, or isinstance ladder whose tests compare one
  value's type or kind field, where the diff makes the count 3 or more (adds the third, or adds to a longer
  one). Mechanically: count the hunk's `elif`/`case`/`isinstance` arms on the same subject. A dict of
  handlers is already the structure, so it is not reported.
- **False positives**: exhaustive switches over a closed enum (liveness markers, verdict tokens), parsers and
  CLI subcommand dispatch, serialisation by tag. The rule names no exemption; review's own precision gate
  (no failing case, so never blocking) limits the cost. Non-blocking question below.
- **Zones**: "new or modern-zone" is exactly the rows where `classify` prints `follow sound design`
  (zones.py:41). Legacy existing files never (1542's rule); undeclared existing files never; `unknown` or
  `unreachable` never. With no zones declared, NEW files still qualify (D-3).
- **Interactive runs**: with no work record `classify` reads `unknown` (docs/change-zones.md:186-190), so the
  zone half is dormant there except for plainly new files a reviewer can see in the diff.
- **Forces**: the fourth force is dormant until #660 lands; the sentence says "goal-design quality scenario"
  and adds no catalogue (NG-1). Two variants justify an abstraction; three cases demand one in new code:
  the two rules point the same way.
