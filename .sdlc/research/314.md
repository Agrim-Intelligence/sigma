## Safety that stays (not the gate's job)

- Two watchers on one `.sdlc`: impossible by the SHARED lock (`state/watch.pid` + heartbeat +
  `watch.decide.lock`), which both plugins' `watch_daemon.py` take -- the gate never contributed
  to that (the override already proved it: `test_override_never_admits_a_second_watcher`).
- `migrate.py --apply` while a watcher is live: `_running_watcher` refusal (exit 2) is independent
  of the gate and stays.
- Nothing in Sigma signals a foreign pid: grep for `os.kill`/`signal` in coexist/watch_daemon/
  migrate -- only `pid_alive` probes (signal 0 / OpenProcess), never a kill.

## "One notice per run"

`loop.py` verbs are separate processes, and `SIGMA_RUN_ID` is not inherited across an agent's
separate tool calls, so an in-process flag cannot mean "per run". Decision: user-invoked START
surfaces (init, loop start, migrate) always say it once; per-verb surfaces (the watcher spawn and
the watcher itself, claim, record) say it only when `state/coexist.notice` is absent or older than
`NOTICE_TTL_SECONDS` (6 h), and every printed notice refreshes it. In-process repeats are also
deduped. Cost: one `stat` per per-verb call while the marker is fresh (assess is skipped).

## Takeover

`migrate.plan()` is read-only but linear in the SDLC dir: measured 1.26-1.70 s on the 8,888-file
larger #239 proof copy on a loaded laptop (#239 measured 0.35 s unloaded) -- too much for every
`loop.py start`. So `coexist.takeover_line()` runs it only behind `_legacy_hint()`: the bounded
state scan (<= 200 records) + <= 200 feature docs for the old marker + config.json values
migrate rewrites (known `*_env` values, `drift_watch.channels.<old>`) + the old AGENTS.md block.
Measured hint cost: 0.5-20 ms on both proof copies; hint False after migration on both (a config
COMMENT naming the old plugin is not a hint -- that copy's config has many). When the hint holds,
init and `loop.py start` print ONE `sigma: takeover:` line with the exact dry-run command.
`--apply` is never run by Sigma itself -- only on the user's explicit yes (init SKILL text).
Until then the #239 read fallbacks keep working.
