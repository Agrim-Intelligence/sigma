# #424 research — Slack listener markers survive SIGTERM/SIGHUP

Measured 2026-10-02, macOS, Python 3.9.6 and 3.12 (repo venv).

## Blast radius
- `skills/sigma-loop/scripts/slack_commands_listen.py`: `release_single_instance` (ownership-checked
  against the pidfile) is called only from `run()`'s `finally`. Default SIGTERM/SIGHUP disposition
  kills the interpreter without unwinding, so pidfile, heartbeat and lock dir stay.
- Reference: `watch_daemon.py::_install_cleanup` (signal handlers for SIGTERM/SIGINT/SIGHUP via
  `getattr(signal, name, None)`, cleanup, restore SIG_DFL, re-raise to die by the signal, plus atexit).
- Consumers of the markers: `heartbeat_liveness`, `ensure()`, `status()` (stale heartbeat => DEAD /
  restart); a left-behind lock dir blocks the next acquire until the heartbeat ages out.
- `docs/threat-model.md` TM-09 lists mitigation "none" and cites #424.

## Constraints
- `signal.signal` only works on the main thread; `run()` is called in-process by many tests, so handlers
  must be installed only on the main thread and restored (plus atexit unregistered) on exit.
- SIGHUP does not exist on Windows; real-signal controls skip on win32 (CI is ubuntu + macos).
- No SIGSTOP/pausing; SIGINT already unwinds via KeyboardInterrupt and is left alone.

## Controls (red first)
Real subprocess runs `run()` with a fake client; parent waits for a READY handshake line (no sleeps),
sends the signal, asserts death-by-signal rc and removed markers; successor control rewrites the pidfile
to a foreign pid before the signal and asserts the markers survive; in-process seam control calls the
installed handler with `os.kill` captured.
