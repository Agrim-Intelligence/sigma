# Research: Approve the verify command once per environment, bound to its exact hash
**Goal**: #2066 · **Lane**: medium · **Date**: 2026-10-27

## Goal in one paragraph

`loop.py verify` and `loop.py red` run repository-supplied code only after the checkout's git-local
`sigma.allowRepositoryShellCommands` is true. Git config is not cloned, so every fresh Claude Code cloud
container is untrusted, and a goal started there stops at verify. The goal is a second, narrower source of the
same decision. An operator sets `SIGMA_TRUSTED_VERIFY_SHA256` once in the environment's own settings, and it
grants the VERIFY PATH only, and only while every command that path is about to run hashes to that value. The
git-local grant is unchanged, and every failure refuses.

## Constraints & unknowns

- **Measured (one private backlog, 2026-10-27).** 214 acceptance records. 117 have `verify_command: null`; 62 equal the repository command `bash scripts/verify.sh` (deduplicated to one command); 34 add their own command: the repository command followed by extra test selectors. Those 34 (16%) run a second, agent-authored string, so an exact-command environment approval will not cover them, by design. In a cloud container they stop at verify as today. That is the fail-closed reading of "bind it to the exact command".
- **Unverified.** How the Claude Code cloud environment-variables panel delivers values: whether they reach the Bash tool's processes and their Python children, whether it trims whitespace, and whether a change reaches running sessions. No cloud session is available here. The end-to-end cloud run is UNMEASURED, and the docs must say so.
- **Unverified.** Whether `loop.py red`'s planned node ids can carry a leading `-`, which pytest would read as an option. The same argv already runs inside `verify` under the same decision (`red_green.py:184`), so the environment grant does not widen this.
- **Blocking:** none.
- **Non-blocking:** whether the doctor row keeps its name (`verify command trusted in this checkout`; pinned by `tests/test_upgrading_verify_trust.py:26`) and reports the source in the advisory on a passing row (the #1513 printer rule, `doctor.py:6966-6975`), or is renamed.
- **Non-blocking:** how the operator gets the hash on a machine where the git-local grant already passes (the row is green there, so it shows no red hint): a documented stdlib one-liner, run by a test (the documented-gesture rule).
- North star: `north_star.py` printed `absent`.
