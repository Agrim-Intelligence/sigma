# Research: #465 — per-goal worktrees under .sdlc/work

Revision: origin/main 3d5d09d (worktree `.sdlc/work/465`). Parent tracker #419; sibling slices #458, #461, #462, #464 (merged), #459, #463 (in flight, not touched).

## Writer and owner
`work.start` (`git worktree add [-b] .sdlc/work/<goal> ...`) is the only writer of `.sdlc/work/<goal>`; the owning record is `.sdlc/state/work/<goal>.json` (worktree, branch, base, pr). Both live under the project's own `.sdlc/`, none under a host configuration root. Other worktrees on the machine (`.claude/worktrees/*`, scratch clones elsewhere) are not Sigma's `.sdlc/work` and are out of scope (not measured).

## Removers today (read from code)
- `work.finish` (non-force `git worktree remove`, `git worktree prune`, unlink the record, delete the branch only when the PR is confirmed MERGED). Reached from `loop._release_checkout`, which runs inside `_record` on a real `done` (also the merge-reconcile pass, via `_record`), and from the `work.py finish` CLI. It KEEPS the tree when `git worktree remove` refuses (tracked changes or untracked files), when the PR is open, or while `awaiting_merge`.
- Never removes: a goal that never reaches `record done` (killed slot, crashed turn), a PARKED or FAILED goal (by design: the tree is the human's WIP), a goal whose `finish` was refused once and never retried, a branch renamed `wip/<n>-paused`. No sweep, no age, no owner of the leftover: nothing ever looks at a survivor again.

## Measured (operator's real store, 2026-10-03, one developer machine, Darwin, APFS)
Commands: `git worktree list`; `du -sk .sdlc/work/*`; `git -C <wt> status --porcelain [--ignored]`; `git -C <wt> rev-list --count @{u}..HEAD`; `git ls-files -z | xargs -0 stat -f %z`; `du -sk .git/worktrees`; `gh api repos/{owner}/{repo}/pulls/<n>` (merged, head.sha) plus `git merge-base --is-ancestor HEAD <head.sha>`.
- 14 worktrees under `.sdlc/work` (13 at plan time + this goal's), total 455 MB by `du` (17 MB to 63 MB each; 20 MB for a fresh one).
- One fresh checkout: 903 tracked files, 18,548,058 B tracked content; its `.git/worktrees/<id>` linkage is 112 KB (all 18 admin entries on the machine: 1,796 KB). The object store is shared (main `.git` 18 MB), so a worktree costs its working files, not another repository. Growth is linear in surviving goals: 10x = 140 worktrees = about 4.5 GB, 100x = 45 GB (extrapolation of the measured mean, not a measurement).
- Classification of the 13 older survivors: 6 have a PR; 3 of those PRs are MERGED (goals 112, 282, 317; clean tree; HEAD is an ancestor of the merged PR's head sha; about 139 MB), 3 are CLOSED UNMERGED (144, 314, 331; clean, kept: a human closed them, the work may be wanted), 1 is OPEN (397, another session's, untouched). 6 have no PR (264, 337 with unpushed commits; 343 and 459 with uncommitted changes; 346 on `wip/346-paused` with no upstream; 463 clean). Why the merged three survive: the record and tree exist and the PR is merged; whether `record done` predated `_release_checkout` or was never reached is not determinable from what is on disk.
- Ignored contents of a worktree: `__pycache__`, `.pytest_cache`, and `.sdlc/state/time/*` (about 276 KB per old worktree; worktree-local time events). Non-force `git worktree remove` deletes ignored files too; this is existing `finish` behaviour and is unchanged.
- NOT measured: filesystem cost at 100 worktrees, Linux numbers, the cost of `git worktree remove` on a 100k-file repo, a Windows host, how many survivors the loop itself produces per week (only the snapshot above).

## Decision
Add a bounded, tested sweep `worktree_prune.py` (stdlib) that removes ONLY provably safe worktrees, by delegating the removal to `work.finish(merged=True)` (the same code path a `record done` takes) after its own proof, and an operator lever (`list-removable`, `sweep --dry-run`). A tree with uncommitted or unpushed work, an open or closed-unmerged PR, no PR, a live agent or session, or any state the sweep cannot read is KEPT and reported for a human. Crash mid-remove: a journal under `state/worktree-prune/` lets the next sweep finish, never guess.
