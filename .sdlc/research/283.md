## 6. Risks and unknowns for the plan
1. **`escalate` breaks a Sigma invariant.** Sigma validates the Codex mapping BEFORE any `model_choice` is
   recorded so a bad `model_host_overrides.codex` never leaves a false audit row (`predict.py:581-585`,
   `loop.py:824-833`). Upstream's `_escalate` records first (`te.record`). Decide: run
   `predict.py host-model codex <next> <sdlc>` before `te.record` (sibling process, as the pick-time hook does),
   or record the deviation. Not addressed by any ported test.
2. **OFF wording is wrong for Codex in Sigma.** Upstream says `OFF` means phases "already run at the session
   model". Sigma's `running.md` says `off` maps Codex to the ordinary-work model, never the parent session.
   The words appear in `tier_escalation.py` (`decide`, OFF message), merged `running.md`, and the CHANGELOG text.
   Also `ESCALATE <tier> effort=<e>` (`te.EFFORT`) vs the effort `host-model codex <tier>` returns: two
   sources; the doc should say the Codex resolver's effort wins on Codex.
3. **Sigma's own repo is `OFF`.** `.sdlc/config.json` has no `model_selection` (only `model_selection_max_tier:
   opus`), so `loop.py escalate` here answers `OFF`; live dogfooding needs `model_selection: auto`.
4. **CHANGELOG** (`## Unreleased`, bullet style, not upstream's `###` headings). Rebrand the predecessor's
   loop and plan-review skill names to `agrim-loop` and `agrim-plan-review`; do not name the upstream
   product. Upstream's "24 goals ... two boards" is the
   predecessor's measurement, not Sigma's: attribute it or drop it (AGENTS.md RELIABILITY). Keep upstream's
   honest scope line: the verb decides and records; re-dispatch at the new tier is the host's, and Cursor cannot.
5. **Unbounded per-goal file** (`state/escalation/<goal>.json`, <100 B, never pruned, read by exact path).
   AGENTS.md SCALABILITY calls unpruned growth a design-time defect; the module docstring states the 10x/100x
   figure and Sigma's per-goal `state/log/` has the same lifetime (no pruner found in `actionlog.py`). Say
   so in the plan rather than leave it implicit.
6. **The write-ordering limit** (a floor is read, then renamed; two simultaneous first writers could leave the
   lower tier) is documented upstream; a goal has one slot. Not tested here.
7. **Cross-commit interaction.** Commit 2's new ceiling rule sits in the same paragraph Sigma rewrote
   for commit 1's Codex lines (hunk 2), and `loop.py` hunks 6/7/8 share the file with both; resolve in
   commit order and re-run `test_loop.py` after each. `resolve_step` keeps whole-text haiku matching
   (`haiku_anywhere=True`), so `resolve`'s title-only rule and `resolve-step`'s do not agree by design.
8. **Not verified:** the A4/A5 fixes (not applied in scratch, full suite not re-run after them);
   Windows/`windows.yml`; `evals/run.py`; `agrim-doctor`; a real host re-dispatch at the escalated tier;
   the goal-file `_read_goal` path against Sigma's `frontmatter.get` beyond the ported tests (the fence
   regex is byte-identical, `frontmatter.py:4`, and the ported tests pass).
