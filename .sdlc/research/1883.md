# #1883 Research — five DAG tests fail only inside the full suite

lane: small

## Verdict

Root cause: **an import-time clock in the tests, not leaked state.** No module global, cache,
env var, sys.modules entry or shared file is involved.

- `tests/test_auto_unpark_dag.py` and `tests/test_dag_pick_1619.py` (whose `_store` helper
  `tests/test_batch_one_read_1621.py` uses) set `NOW = time.time()` when the module is imported, which
  happens at collection. They then write the stored map with `checked_at = NOW - 60`. Because
  `checked=NOW - 60` is a default argument, it is also fixed when the function is defined.
- Production code reads the real clock when it is called. `dag_pick._entry`
  (`skills/sigma-loop/scripts/dag_pick.py` ~L76-83) refuses any map whose `checked_at` is more
  than `dag_store.CHANGE_CHECK_SECONDS` (600 s) old, with reason "no change check within 600
  seconds". `dag_store.usable` applies the same check to `dag_order` and auto-unpark.
- So a test that runs more than about 540 s after collection sees a map that is too old. The
  code then takes the old path that ignores the map, as designed. In the full suite, collection
  happens at startup and these files run many minutes later. When each file runs alone, it
  finishes within seconds of collection, so it passes.

**Why the numbers look shifted by one.** Nothing is renumbered. The fixture boards list the
dependent goal before its root (`_board([DEP_A, ROOT_A])`, with DEP_A=11 and ROOT_A=10). When the map
cannot be used, nothing holds 11 back, so the code picks it in board order: `('goal','11')`
instead of `('goal','10')`, and 21 instead of 30. In the auto-unpark tests, ignoring the map means
the comment and state reads happen again: `fetches=1`, and `(25, 25)` instead of `(0, 0)`.

**Production bug?** No. The 600-second limit is the designed safety check (an old map falls back
to the live path). The live loop always passes the real `time.time()`, and no cache can go stale
here: `cache["dag_pick"]` lasts only for one batch. This is a test-only bug.

## Reproduction (narrow, measured)

All runs used <repo>/.sdlc/work/1883 at e6598ae5, with venv Python 3.12, one run at a time, and
>=54% free memory.

1. Running the two files together, in both orders, passes: 23 passed (70 s and 11 s). This
   rules out leaked state between these two files.
2. **Deterministic repro.** A scratch pytest plugin, <scratch>/clockshift.py, moves `time.time`
   forward by `CLOCK_SHIFT` seconds at `pytest_collection_finish`. That simulates a long suite
   without waiting for one:

   ```
   # clockshift.py
   import os, time
   _real = time.time
   def pytest_collection_finish(session):
       off = float(os.environ.get("CLOCK_SHIFT", "0"))
       time.time = lambda: _real() + off
   ```
   ```
   CLOCK_SHIFT=700 PYTHONPATH=<scratch> python -m pytest -p clockshift \
     tests/test_auto_unpark_dag.py tests/test_batch_one_read_1621.py -q -p no:cacheprovider
   ```
   Results over the six-file set below:
   - shift 0: 113 passed.
   - shift 530: 16 failed. These are sibling files that run late enough to pass the 540 s mark.
   - shift 700: 21 failed, **including exactly the five reported tests** with the reported
     assertion shapes.
3. I did not measure `--dist loadfile` against the default. It cannot help, because every
   xdist worker collects everything at startup either way. Distribution only changes which
   tests pass 540 s. It also explains why the failing set can change from one full run to the
   next.

## Fix location (recommendation)

Fix the tests, not the production code. In each in-scope helper, take the stamps from the clock
when the helper is called: `checked=None` → `time.time() - 60`, and the same for `built`. Turn
the explicit relative stamps (`NOW - 3600` and similar) into offsets from that same call-time
`now`. For tests that pass `now=NOW` to a reader, use one per-test `now`, so that the writer and
the reader agree. Fixing `test_dag_pick_1619._store` alone fixes all three 1621 tests.

Control: the clockshift run at 700 must go from 21 failures to 0. Then break the fix in each
file on its own (restore one import-time default) and watch that file's tests go red again
under the shift.

## Debt in radius

- Import-time `NOW` combined with a production freshness window shorter than the suite runtime
  is a pattern. Defer with a ticket: a ratchet test that flags `checked=NOW` default arguments in
  `tests/`. That is optional, not required for this goal.
