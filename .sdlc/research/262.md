# Research — #262 phase instruction budget

## Existing mechanisms

- `evals/skill_structure.py` already provides the repository's deliberately conservative,
  stdlib-only token estimator: `ceil(characters / 4)`.  The new measurement must reuse that
  function rather than introduce a second proxy.
- `skills/sigma-loop/scripts/review_context.py` already renders the review packs.  Its public
  `brief()` seam accepts an explicit repository root, so the fixture can be measured without
  GitHub access or a live project checkout.
- `examples/hello-sdlc/` is an intentionally small local-mode project, including the `.sdlc`
  directory needed by `brief()`.

## Scope boundary

The goal asks for a measurement and ratchet only.  It must not modify any skill prompt, dispatch
behaviour, or review brief content.  The measurement will state exactly which files it loads for
each phase so changes to that mapping are visible in a diff.

## Failure controls

1. A synthetic 500-word append to `sigma-loop/references/running.md` must make the documented
   gate fail, proving the actual highest-risk reference is counted.
2. A committed ceiling above a measurement by more than five percent must fail, so a check-in
   cannot ratchet upward by editing only JSON.
3. A lower committed ceiling must fail, so the ceiling remains an enforceable upper bound rather
   than advisory report metadata.

## Measurement limits

The script is deterministic and performs no network operation.  Review briefs are rendered
against `examples/hello-sdlc/`; the output represents the fixture project, not a claim about a
consumer repository's own governing files.
