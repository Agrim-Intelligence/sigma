# #338 research — supported CI cells

## Scope and current state

`.github/workflows/ci.yml` has one `test` job, a 60-minute timeout, and
`fail-fast: false`, but its matrix contains only Linux Python 3.10 and 3.12.
The job runs pytest, `evals/run.py`, `decision_gate.py`, and the frontmatter
check in every current leg. `.github/workflows/windows.yml` is dispatch-only
and remains the experimental Windows watcher check required by the issue.

The supported launch cells in #338 are Linux on Python 3.10, 3.11, 3.12, and
3.13, plus macOS on Python 3.12. An explicit `include` matrix is necessary:
the requested cells are not a Cartesian product.

## Portability inspection

`rg` found no test that shells out to a `timeout` executable. Timeout handling
uses `subprocess` or process methods, so there is no macOS GNU-timeout fix to
make before CI execution. No README sentence currently claims a narrower CI
matrix; the README will state the actual five supported cells with the
workflow link.

## Constraints and evidence plan

The workflow test must parse only repository text and make no network request.
It will pin exact include entries, runner/interpreter interpolation, timeout,
fail-fast behavior, and the required gates. The red control removes the macOS
entry in a temporary copy and must fail through the same validator used for the
real workflow. A real temporary macOS-only failure and five-leg GitHub run are
post-review/PR evidence because no PR may be opened during this implementation
phase.
