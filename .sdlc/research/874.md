# Research: #874 Regression record builder (record.py and the sigma.regression-run/v1 schema)

Slice 1 of epic #870, story #809. Covers AC-2 and AC-5 of the source issue. Everything below was read
from this worktree's tree (HEAD is the #963 merge); nothing was run against a model.

## Goal restated
Add a new `record.py` with a `build <run_dir>` verb in a new regression directory under `evals/`
(to be created by this goal; it does not exist yet). It assembles one JSON record, schema string
`sigma.regression-run/v1`, from the durable evidence a Sigma run leaves in a scratch repository. Every
source stream carries `source` and `present`. Action-log rows are filtered by
`actionlog.INTERNAL_KINDS`, imported, never copied. Phase ends are recorded as
`evidence: "call-existence"` with a top-level `caveats` list saying so. Unit tests build synthetic run
directories, including ones with absent streams.

## Sources the builder reads, and their real on-disk formats
All paths are relative to a project's `.sdlc` directory (the "sdlc dir" inside the run's repo).
These are runtime paths; none are tracked files.

1. **Action log** (`state/log/<stem>.jsonl`). Writer: `skills/sigma-loop/scripts/actionlog.py`
   (`append`, `log_path`; `read_goal` is the reader and skips malformed lines, sorts by `ts`). One JSON
   object per line, `sort_keys=True`: envelope `ts` (UTC, ms, `...Z`), `goal`, `thread`, `actor`, `kind`,
   then the kind's whitelisted fields (empty values omitted). `INTERNAL_KINDS` is a tuple:
   `claimed, worktree_start, verify_run, recorded, gate, merge_armed, merged, decompose_check, released,
   agent_reclaimed, phase, verdict, phase_waived`. `AGENT_KINDS` (`file, model_choice, agent_dispatch,
   agent_done, note`) are agent-writable and must never reach the record. Only written when
   `action_log.enabled` is exactly `True`. Relevant row shapes:
   - `phase`: `phase, state (start|end), agent_id, cost, verified`. The `cost` is the banner figure or the word `unavailable`.
   - `verdict`: `phase (plan_review|review), verdict, route, agent_id, plan_hash, verified`. Written by `phase_gate.record_verdict` (via `work.py record-plan-review`/`record-review`). This is the durable plan-review evidence.
   - `gate`: `gate` in `merge, code_review, post_review, test_trust, risk_*`, plus `verdict, why`.
   - `merged`/`merge_armed`: `pr`. `recorded`: `result, detail` (the `record done` row).
   - `worktree_start`: `worktree, branch, base, base_resolved`.
   The module loads `state` and `work` eagerly at import (its own `_load`), so importing it by path works from any cwd.
2. **Journal** (`events/*.jsonl`, directory from `ledger.local_events_dir`; files named `<actor>-<host>.<pid>.jsonl`, many per run; the legacy ledger events directory is still READ by other tools for one release). Writer: `ledger.append(..., stream=EVENTS)`; gated by `journal.enabled` exactly `True` (OFF by default; ships off). Each line: `id` (`<who>:<instance>:<seq>`), `ts` (whole-second UTC), `actor`, `kind`, `goal`, then the kind's fields. `EVENT_KINDS` = phase, gate, verify, slice, spend, retro, park, scan, run_stop, model_choice, merge_observed, review_posted, ci_observed. Retention is 30 days (`JOURNAL_RETENTION_DAYS`); the prune stamp file lives in the same directory and is NOT a `.jsonl`, so glob `*.jsonl` only. The union of all files is the stream (readers union, never route by filename).
   - `phase` end event: `phase, state=end, ms, tokens_in, tokens_out, attempt_id, model, unpriced_turns`. Numeric fields are written as STRINGS (phase_report passes `str(...)`; `ledger` re-stringifies through `int()`), so the builder must coerce and tolerate non-numeric. Tokens are present only when the phase was measured from a transcript; otherwise the end event has no `tokens_*` (so absent tokens are data, not an error). A `phase` start event has only `phase, state`.
   - `spend`: `phase, model, tokens_in, tokens_out, cost_cents, attempt_id`; written by `phase_report.py` only when a dollar cost is known and `unpriced_turns` is zero.
   - `review_posted`: `observation_key, brief_hash, evidence_id, comment_id (int), pr (int), head_sha, verdict` (approve|block|unblock). Written by `work._repair_review_post_effects`. Typed events with a closed required field set.
   - `gate` event: `gate, verdict, cycle, why, decision_id`. `work.record_plan_review` mirrors the plan-review verdict here as `gate=plan_review`, verdict `pass|warn|block`.
3. **Verify state** (`state/verify/<stem>.json`, `state.evidence_path`; writer `loop.py verify_goal`). Indented JSON keys: `command, exit, acceptance_sha256, verify_state (pass|fail), at (epoch float), run, pid, root, head, content{fingerprint, base_ref, files, detail}, flake, test_first, witness, diff_revert, tail`. `root` and `tail` can embed absolute machine paths and command output; the record should carry only a small allowlisted projection (`exit`, `verify_state`, `at`, `head`, `test_first.passed`), not the raw file. Retention: `goal_state_prune.py` keeps verify/phase state 7 days after done (read for the decision, not re-verified here).
4. **Plan and research files** (`plans/<stem>.md`, `research/<stem>.md`; in GitHub mode a numeric stem may carry a slug, `review_context.phase_doc_file(sdlc_dir, goal, "plans"|"research")` is the shared resolver, ties go to the newest mtime). These are tracked files on the goal branch. The builder needs presence, size, and a sha256, not the text. Reusing `phase_doc_file` means importing `review_context`, a large module; a local stem-or-slug glob is simpler but then needs a control showing the numeric-stem-with-slug case.
5. **Plan-review gate state** (`state/gates/<stem>.json`, `work.plan_review_record_path`): JSON `at, goal, plan, plan_hash, reviewer_route{host,mechanism,verified}, verdict (pass|warn|block)`. It is UNLINKED by `work.finish`, which `record done` reaches, so it is absent after `done`. Treat as an optional pre-finish cross-check only; the action-log `verdict` row is the durable source.
6. **Review evidence**: the `review_posted` journal event, plus the marker `<!-- sigma-review-evidence:<evidence_id> -->` inside a PR comment body in the fake GitHub store (a JSON file of the run: `prs.<n>.comments[]` entries `{body, assoc}`; the fake does not yet give comments an `id`, slice 3). The per-generation review files are pruned at `done` and must not be read.
7. **Commit order**: `git log --format=%H%x09%s` on the run's bare remote and on the branch (the control's layout is a `repo` clone, a bare `remote.git`, a fake `gh` state JSON and a call log, all under one scratch directory). Needs a real git binary and a fixed branch name (`main` is the control's default branch); subprocess must be hermetic (no global config, bounded, no network).
8. **Per-phase tokens**: derived from journal `phase` end events (`tokens_in`, `tokens_out`) and `spend` events, grouped by phase and `attempt_id`, because a retried phase writes more than one end.

What does NOT exist as a source: a "phase end that proves the phase did its work". A `phase` end row records that `phase_report.py end` was called, nothing more (`phase_gate.py` says so in its docstring). Hence `evidence: "call-existence"` plus caveats.

## Existing layout, imports and test conventions
- `evals/` holds Tier-0/Tier-1 scripts at its top level (`run.py`, `skill_structure.py`, `phase_context_budget.py`) and `bench/` (tracked, has `__init__.py`; its tests live under `tests/test_bench_*.py`, not beside the code). So new tests belong in `tests/` (e.g. a `test_regression_record.py`), which is the only path the CI pytest step runs.
- Import idiom for script modules: `importlib.util.spec_from_file_location(name, path)` then `module_from_spec` and `exec_module` (used by `tests/test_actionlog.py`, `tests/test_bench_meter.py`, `evals/bench/meter.py`, and `actionlog.py` itself for `state`/`work`). `evals/bench/bench.py` instead prepends its own directory to `sys.path`. The repo-wide convention for reaching `skills/sigma-loop/scripts` from another tree is the importlib-by-path form; `record.py` should locate it relative to `__file__` (parents of the new directory up to the repo root), never an absolute or home path, and never copy the kind tuple.
- Stdlib only (kit rule; `evals/skill_structure.py` states it). CI runs Python 3.10 to 3.13 on Linux and 3.12 on macOS; the local interpreter here is 3.9.6, so avoid 3.10-only syntax (`match`, `X | Y` annotations evaluated at runtime) if tests are to run locally.
- `tests/conftest.py` installs an autouse guard that makes any real `gh` subprocess raise; the builder must not call `gh` (it reads the fake store file, not a live CLI).
- Test pattern for a synthetic run directory: build `tmp_path` with the `state/log`, `events`, `state/verify`, `plans`, `research` trees plus `git init` repo and bare remote (see `tests/test_actionlog.py` `_sdlc` helper for the minimal sdlc dir with config + `STATE.md`). Git-using tests need a committer identity; CI sets a global one, but tests should pass `-c user.name -c user.email` and `GIT_CONFIG_GLOBAL` to a null device so they pass on a developer machine too.
- Controls required by the repo rules: each guard deliberately broken once and seen red. For this slice that means at minimum: (a) replace the imported `INTERNAL_KINDS` filter with a pass-through and watch the "agent-kind row never reaches the record" test fail; (b) make an absent stream raise and watch the absent-streams test fail; (c) drop the `evidence`/caveats and watch that test fail. Run on the gesture the docs give: the issue states the verb as `record.py build <run_dir>`; run exactly that through a subprocess in at least one test, not only the in-process function.

## Constraints
- AGENTS.md five properties apply. Reliability: no performance claim is made by this slice; if the record carries durations, they are copied event values, not measured. Scalability: reading cost is linear in journal size (30-day cap) and action-log size per goal; state it in the module docstring; no unbounded growth (single output file written once, overwritten). Resiliency: a malformed JSON line is skipped and counted, never fatal (mirror `actionlog.read_goal`); a missing/unreadable stream is `present: false`; an unreadable git remote is `present: false` with a reason. Safety: no network, no `gh`, read-only against the run directory; output written atomically (temp then replace) and only to the path asked for; scrub nothing new but do not copy raw verify `tail`/`root` (may contain paths/secrets). Liveness: not a long-running component.
- Host-agnostic: pure Python plus git; no hook dependency.
- Output contract: this tool prints no status block; keep stdout to the written path or a one-line summary and stderr for refusals.
- Python docstring, not a README. No home-directory path or machine-specific path in code, tests, fixtures or docs.
- The record must contain no agent-kind rows anywhere, including a "process" section; AC-2 is enforced by filtering at read time, and a test must plant an `agent_dispatch`, `note` and `file` row and prove none survive.
- Determinism: sort sections stably so two builds of the same directory are byte-identical apart from nothing; do not stamp a build time inside the compared body (or put it in one clearly separate field), otherwise slice 2's mutated-copy controls cannot compare records.

## Proposed record shape (for the plan to confirm)
Top level: `schema` ("sigma.regression-run/v1"), `goal` (stem), `run_dir` as the string given (basename only, to avoid leaking a path), `caveats` (list of strings, always includes the call-existence statement), `streams` object. Each stream entry: `source` (what was read, repo-relative), `present` (bool), `reason` when absent or partial, plus `rows`/`items`. Streams: `plan`, `research`, `plan_review_verdict` (from the `verdict` row, with the optional gate-file cross-check), `verify`, `journal` (counts per kind plus selected typed events), `action_log` (INTERNAL rows only; also a count of rows dropped as non-internal, as a number, so a drop is visible without carrying content), `review_evidence` (journal `review_posted` plus marker found in the store), `commit_order`, `tokens` (per phase). `phases`: list of `{phase, evidence: "call-existence", start_present, end_present, tokens_in, tokens_out, cost_cents}`.

## Lane and size
Size: **medium**. One new module of roughly 250 to 400 lines and one test file of roughly 400 lines; about 8 source readers, but each is a small JSON-lines or JSON read. No change to existing code beyond an inventory entry. Risk concentrated in the real formats (stringly numerics, multi-file journal union, numeric-stem plan slugs, git under a hermetic env) and in making the controls sensitive. Lane: normal single-slice goal flow (research, plan, plan-review, implement, review, retro); it does not need decomposition. Plan-review is warranted because the schema is a contract for four later slices.

## Open doubts
1. **Run directory contract.** The design says the run directory is the control's scratch directory (repo clone, bare remote, fake gh state, call log). Synthetic tests are free to choose a layout, but the layout names (repo subdirectory, remote git directory, state file name) must be fixed here because slice 4 will pass the control's real directory. Proposal: accept `<run_dir>` containing `repo/` (with its sdlc dir), `remote.git/`, `gh_state.json`, each optional and each reported present or absent; flags may override. Needs plan-review agreement; unverified that the control's names stay stable (they are literals in `tools/onboarding_control.py`).
2. **Which goal.** A run directory may hold several goals' logs. Proposal: `--goal <stem>` optional, default the single goal found, refuse (exit 2) on several rather than guess.
3. **Stringly numerics.** Journal tokens are strings; a non-numeric value should become `null` with a note, not crash. Not yet verified against a real journal written by `phase_report.py end` (only read from the writer code); the plan should include one test that writes events through the real `ledger.append` rather than hand-written lines, to catch drift.
4. **Verify evidence projection.** Which fields slice 2's properties will want is unknown; keep the projection small and additive.
5. **Write-surface ratchet.** Whether the scanner flags `write_text` in a new `evals/` file as a new unlisted site was read from the inventory (23 tracked Python files under the bench directory already appear) but the `check` was not run against the new file; run it in the implement phase.
6. **Commit order scope.** "Branch" for a run where `work.py` cut a branch whose name embeds the goal stem: whether to read all refs or just `main` plus the one `sdlc/<stem>` branch. Proposal: main on the remote plus the goal branch if present; absent branch is `present: false`.
7. **`action_log.enabled` off.** The action-log stream is then genuinely absent; the verdict-derived plan-review and `phases` evidence cannot be built. They must report `present: false` (AC-5), and slice 2's checker is where that becomes NOT EVALUABLE; not decided here.
8. **Python 3.9 locally.** `ledger`/`actionlog` import cleanly on 3.9 (existing tests do), but the interpreter in use for tests is not the CI floor (3.10); any 3.10-only syntax would hide on this machine.
