## Formats and parser (concrete)

- FR bullet: `- **FR-n.** <EARS sentence>` (mirrors `- **PC-1.** ...`, `- **X-1.** ...` shapes). Empty: single `- None.` bullet (precedent `writing-the-artifact.md:126,229`). Regex: `^- \*\*FR-(\d+)\.\*\* (.+)$`. Enforce ids 1..n ascending in document order, no duplicates (a gap means renumbering happened or a deletion; report it. Holes are legitimate? "never renumbered" implies a dropped FR leaves a gap; so check strictly increasing + unique, NOT contiguous. Recommend this, D3).
- EARS check: strip nothing; test against `EARS` (accept TAGGED too? AC-2 says "EARS sentence" and the issue says nothing about tags; accept EARS only. A requirement that must be PROCESS:/MEASURED: is a goal acceptance criterion, not a functional requirement. D2).
- Slice table: heading `## Slice-count estimate`, GFM table, today `| Slice | Covers | Depends on |` (`writing-the-artifact.md:77-79`); new header `| Slice | Covers | Requirements | Depends on |`. Parse BY HEADER NAME (case-insensitive, split on unescaped `|`), not by position, so column order is not load-bearing. `Requirements` cell: comma-separated `FR-n`, or `—` (em dash) for none; stripped tokens, same rule as `Depends on` ("read by splitting on commas and stripping").
- Trace rules: (a) FR in no slice row => uncovered => schema violation; (b) token in a Requirements cell that is not a declared FR => violation (typo is how coverage is faked); (c) `- None.` FR section with a non-`—` Requirements cell => violation; (d) Requirements column missing while FR present => violation, never "no coverage claimed"; (e) missing `## Functional requirements` heading => violation (same absent-vs-empty doctrine as `Premise check`, `reading-the-target.md:83`).
- Must parse only the section bodies between `## ` headings; `Detailed design` free text can contain table-like lines, and the blast-radius table may be split under `###` (`writing-the-artifact.md:~245`); the slice table never is.

## Compile step and `## Requirements served`

Child bodies are hand-authored by the reviewing model into `plan.json` `issues[].body` ("the slice's own `Covers` scope plus pointers", `confirm.md:~31-35`; `compile_plan.py` passes bodies through, adding only code-written markers like `Tracks #N` / `Part of epic #N.`). So `## Requirements served` fits inside `body`, after the scope text, before the `Design:` / `Story #` pointer lines. Make it mechanical: `goal_design.py served <artifact> --slice <n>` prints
```
## Requirements served
- **FR-2.** WHEN ... THE ... SHALL ...
```
which the model pastes verbatim. Phantom-blocker hazard (`confirm.md:~100-120`, `blocker_scan` 40-char `needs|after|requires|depends on|blocked by ... #N` rule): FR sentences are EARS text (`WHEN`, `IF`, `THE X SHALL`) and may contain "after", "requires" etc. If an FR sentence ever contains `#N` near those words it mints a phantom blocker that writes to a third issue. Mitigation in the verb: refuse to emit (exit 2) a sentence containing `#\d+` at all (FR sentences have no business citing issue numbers) - control: run `served` on an FR with "after #5" and see it refuse. Also run the repo's existing phantom-blocker control (`confirm.md` runnable control) over the final plan. A plan check `goal_design.py requirements <artifact> --plan <plan.json>` (every child body contains every FR sentence its slice row claims) closes AC-4 against forgetting; it keys children to slices by plan key = slice number (confirm.md already maps `Slice` values to plan keys).
