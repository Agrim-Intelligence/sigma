# Research: hex-encoded and single-line encrypted private-key openings in leak_scan

**Goal**: #451 · **Lane**: medium · **Base**: origin/main 2b1f07c (includes the embedded-token recogniser, #449, and UTF-32 decoding, #450)

## Goal in one paragraph

`key-body` reads a private key's DER header only from BASE64 (`_der_private`, called from the line-start
alternative `k` of `_BODY_LINE` and from `_DER_TOKEN`, which finds a token anywhere in a line). Four
shapes pass CLEAN through the documented gesture `python3 tools/leak_scan.py`: a hex-encoded body, the
hex first line of a PKCS1 key, the lone first line of an encrypted PKCS8 and of a PKCS12. A header-less
single armored PGP private-key first line passes too.

## Decisions per case

- Hex DER first line: a hex run (case-insensitive), at a token boundary like the base64 token (not after an
  alphanumeric; or right after a literal `\n`/`\r`/`\t`; or after `0x`), first byte `30` (SEQUENCE) or a PGP
  secret-packet tag, whose first 18 to 24 bytes decode to the same private-key header the base64 reader
  accepts. It composes with #449 (a hex key mid-line in JSON or shell is found anywhere in the line) and with
  #450 (UTF-16/UTF-32 text is decoded first, so hex text in either is the same string).
- Hex "as a line-count class" is NOT added: #433 measured +4 false positives on the 97-file corpus (hash
  lists have the same widths as hex body lines). A hex body whose first line is missing stays unrecognised.
- Encrypted PKCS8: `SEQUENCE { SEQUENCE { OID <PBE scheme> ...` where the OID is PBES2 (1.2.840.113549.1.5.13),
  a PKCS5 PBES1 scheme (5.1, 5.3, 5.4, 5.6, 5.9, 5.10) or a PKCS12 PBE (1.2.840.113549.1.12.1.x). PBKDF2 alone
  (5.12) and public structures (SPKI opens with the 1.1.1 arc, PKCS7 with an OID directly) are not matched.
- PKCS12: `SEQUENCE { INTEGER 3, SEQUENCE { OID data (1.2.840.113549.1.7.1) ...`, definite or BER-indefinite
  lengths. The OID must be visible, so the first line needs about 30 base64 / 44 hex characters; the
  `signedData` (public-key integrity) form is not matched.
- PGP: a secret-key (tag 5) or secret-subkey (tag 7) packet, old or new format, version 3, 4 or 6, public-key
  algorithm in a known set. Public key (tag 6/14), signature and literal packets are not matched. The
  base64 token can start with `l`, `n` or `x` (and `M` for DER).
- Not recognised, stated in the contract: colon- or space-separated hex (`30:82:04`), `0x30, 0x82` / `\x30\x82`
  byte lists, a hex body with no first line, a first line wrapped below 24 base64 / 36 hex characters,
  PGP/DER inside base64 of a whole PEM (existing line), legacy-encrypted RSA/EC bodies (random ciphertext).
