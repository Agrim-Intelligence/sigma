# Research: #514 — the predecessor's fold empties a Sigma-written index.json

Origin/main `0305c6c`. Reproduced exactly (scratch repository, fake HOME, the predecessor's latest installed
version executed only from a temporary COPY of its scripts; the installed directory's content hash is the same
before and after):

- Sigma `write_index` writes `.sdlc/features/index.json`: 236 bytes, schema `sigma/features@1`, 1 unit, no shard.
  Sigma reads 1 unit.
- The predecessor's `feature_sync.py fold <sdlc_dir>` prints that the document declares a schema other than its own
  so none of it was read, exits 0, and writes `index.json` anyway: 57 bytes, the predecessor's schema id, 0 units.
  Sigma then reads 0 units.

Cause: the predecessor's `fold` is `write_index(read())`; its `read` treats a Sigma-schema document as empty, so it
folds an empty registry over the sheet. Sigma cannot stop another program's write.

Options measured or read:
- (a) Write the sheet under the predecessor's schema id. Measured: its fold then leaves a one-unit sheet byte for
  byte unchanged. Rejected: Sigma's own delta detection (#314) is defined by the two ids differing, `migrate.py`
  exists to convert that id, and propagation refuses to overwrite a sibling sheet that still carries the old id; so
  it breaks Sigma's readers and the cut-over, which is worse than the bug.
- (b1) Refuse Sigma's registry writes while the predecessor can run. Rejected: contradicts the #314 policy (notice,
  never refusal) and does not prevent the loss, which happens in the predecessor's write.
- (b2) Existing one-time backup under `state/backup/features-<time>/`. Not enough: it is taken once, only when a
  `features/` directory already exists and only when the predecessor is active at that write; a repository whose
  first registry write creates `features/` has none, and a later restore discards later writes.
- (c) CHOSEN, as refined by four plan-review rounds (the plan supersedes this paragraph): a Sigma-only copy of the
  sheet at `state/backup/index-sigma.json` (outside `features/`, so the predecessor never reads or writes it),
  refreshed on every Sigma write and on observation at every gated verb; a loud signal when the sheet comes back in
  the predecessor's schema without units the copy holds; one explicit lever `feature_sync.py recover` (and
  `--discard`); Sigma's fold and migrate's index conversion refuse/hold meanwhile. Nothing restores the tracked
  sheet unprompted. Rejected after review: a recovered view inside `read`, an automatic restore, `git show` as the
  only source, a shard per unit.

Residuals: a unit shard the predecessor overwrites directly (module-level `write_unit`, no CLI path run); a sheet
the predecessor changes legitimately in its own schema keeps its entries (the copy only fills missing units); the
copy is machine-local, so a fresh clone after the loss has nothing to recover from but git history.
Cost: one file, rewritten only when the sheet's bytes change, size equal to the sheet.
