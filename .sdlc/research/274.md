# Research — #274 benchmark harness

## Current surface

`docs/bench/preregistration.md` is the method of record.  It fixes the later
comparison to named arms, repeat counts, hidden-test scoring, common metrics,
and an explicit spending ceiling.  The only shipped benchmark implementation
today is `evals/bench/meter.py`; it prices an already-recorded Claude transcript
and deliberately has no task runner, result schema, arm abstraction, or
hidden-test isolation mechanism.

The issue's two closed predecessors (#262 and #267) supply the shared price
meter and the test-first evidence gate.  No `sdlc/274` branch, worktree, work
record, session marker, or PR existed before this claim, and no Claude marker
mentions this goal.

## Design boundary

This goal must make a reproducible *smoke harness*, without spending money or
running a live model. The harness supplies only its in-tree `FakeArm` smoke
fixture; it copies each task's starting tree into a fresh worktree, then scores
a copy only after that trusted fixture returns. The hidden bundle is resolved
from an operator-supplied external root and is never put in the worktree or
handed to the fixture API. All live arms refuse until a separately reviewed,
enforceable isolation protocol exists.

The result must be a committed JSON schema with one row per arm/task/repeat,
including outcome, visible/hidden test outcome, wall time, cost, interventions
and an explicit skip/failure reason.  A missing or non-positive `max_usd`
ceiling, CI environment, or requested background mode is a fail-closed refusal.

## Extension seam

Issue #354 names an in-process `Arm.run(workdir, prompt, env, deadline) ->
ArmRun` extension contract, but that callback has the harness process's full
filesystem authority and cannot isolate a hostile implementation. This goal
therefore reserves direct callbacks for the built-in trusted fake smoke arm;
no live arm can be started: neither a Python callback nor an arbitrary external
launcher is an enforceable boundary. This is an intentional compatibility
constraint for #354 to resolve rather than a claim that environment filtering
or a launcher path contains an arm. The goal provides only a hermetic in-process
fake smoke fixture. #354 must resolve the safe live-arm protocol before it can
add predecessor and matched-spend arms. No live `claude` invocation, plugin
installation, or benchmark publication belongs here.

## Acceptance controls

1. The documented `bench.py run` gesture without `--max-usd` must exit with a
   refusal before a fake arm is invoked; restoring the ceiling makes the same
   two-task smoke run write schema-valid results.
2. A hidden bundle inside a task source or arm worktree must be rejected; with
   an external bundle, the fake arm sees neither bundle bytes nor its absolute
   path and the harness scores the copied final tree afterwards.
3. The two-task, one-arm smoke test runs entirely with a fake local command and
   writes deterministic rows; it performs no network or model spend.
