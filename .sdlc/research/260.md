## What the code proves (path, then the test that exercises it)
1. The brief digest is bound to one generation: `work.review_paths` refuses a brief outside its generation directory or whose sha256 differs from the manifest (`tests/test_work.py::test_review_evidence_requires_result_for_the_selected_generation`).
2. A result is accepted as evidence only for that generation, brief digest, PR and head: `work.review_evidence` (`test_review_evidence_refuses_a_result_for_a_different_pr_or_head`).
3. For a PR review the worktree's head and the base..head diff digest must equal the manifest's when evidence is written: `work.review_evidence` via `review_context.worktree_head`/`pr_diff_sha256` (`test_documented_gesture_refuses_evidence_when_the_head_moved_after_publication`).
4. Result and evidence are create-once per generation (`O_CREAT|O_EXCL`): `work._write_review_result`, `work.review_evidence` (`test_review_evidence_is_write_once_for_one_generation`); a re-review needs a new generation. A probe of `_write_review_result` with a second, different verdict is part of the plan's controls (no existing test names the result file's refusal string).
5. `work.post_review` re-derives the chain, requires the evidence to belong to the goal's current generation pointer, the same verdict and PR, and that the PR's current remote head equals the evidence head, else PARK (`test_post_review_refuses_missing_or_malformed_evidence_before_any_remote_post`, `test_post_review_refuses_evidence_hand_written_outside_the_generation_chain`, `test_evidence_backed_post_parks_before_comment_when_the_pr_head_moved`).
6. `inline` cannot be recorded when the resolver now says otherwise, and a resolution carrying a verdict is refused: `work.run_resolved_review` (`test_an_inline_resolution_cannot_bypass_a_configured_independent_reviewer`).

## What it does not prove
- Who called the host's task tool: `work.record_subagent_review` says so in its own docstring and checks only that the resolver currently selects `subagent`; it accepts any verdict and reason from its caller, so a maker can record its own approving verdict. `work.post_review` carries a `ponytail:` comment naming the same gap (a self-consistent fabricated result for a fresh generation is undetectable locally).
- The route is chosen from `review.host` / `review.command` config plus the `CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, `CODEX_SESSION_ID`, `CODEX_THREAD_ID` environment variables (`reviewer.resolve`); nothing proves a fresh context.
- The merge check does not read the evidence: `work.review_gate` reads PR comments (`sigma:approve`/`sigma:block`, latest wins, from any commenter), formal reviews and unresolved threads; under the default `require_review: changes` an approval is not even required, and an unreadable review state passes (fail-open). `evidence.json` and the `sigma-review-evidence` marker are read only by `post_review` and `reconcile_review_post`.
