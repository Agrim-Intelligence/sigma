# #612 research — first live-run deviations

## Scope and evidence

Source: GitHub issue #612 (first private-repository, headless Claude Code run, 2026-10-05) and
`.sdlc/acceptance/612.md`.  This is a docs/host-contract goal unless investigation below calls out a
small behavior/test adjustment.  The reported run completed init, loop, PR, merge, `make test`,
issue closure, and a passing verify record; this research does not claim the seven deviations have
been reproduced in that exact external repository.

## Affected paths and root-cause hypotheses

1. **Auto-mode post-PR review conflicts with Claude self-approval policy.**
   - `README.md` (`/sigma-loop` overview; controls table, especially PR review/independent review)
     says the loop is autonomous and asks for author-blind review, but does not put the attended
     fallback before a user starts it.
   - `skills/sigma-loop/SKILL.md:98-104,217-229` and
     `skills/sigma-loop/references/running.md:135-153,182-192` require a fresh reviewer, then
     direct the loop to `work.py post-review ... --verdict approve`.  That is the gesture the
     host classified as self-approval.  `work.py:review_gate` deliberately supports a trusted
     `sigma:approve` comment where GitHub cannot self-approve and emits a loud same-author warning
     (`skills/sigma-loop/scripts/work.py:4930-5010`); it cannot make the host authorize its own
     tool action.
   - Likely fix: document a host-appropriate resolver route and the explicit attended handoff/
     deferral before auto-mode starts; preserve the existing "park, do not force" rule.  Do not
     promise technical independence that `review.independent` only asks for.
   - Tests/docs: `tests/test_public_bootstrap_control.py`, `tests/test_phase_context_budget.py`,
     `tests/test_enforcement_table.py`, README and both loop instruction references.

2. **`/sigma-init --verify` needs a second invocation.**
   - `skills/sigma-init/scripts/init_flow.py:158-162` rejects a literal command; `:527-552`
     maps `--verify N:ID` to `verify_detect.py confirm` and prints a rerun ask.  The safety
     boundary is intentional: detected repository text must not be pasted into a shell command.
   - `skills/sigma-init/SKILL.md:174-190` explains the lower-level confirm gesture, but its
     initial flag table (`:40-43`) and README onboarding need a prominent first-run example such
     as rerunning `/sigma-init --verify N:ID` using the candidate printed by the first run.
   - Tests: `tests/test_onboarding_control.py` validates the ask grammar and shown flags; retain
     its documented-gesture control rather than adding an inline-command bypass.

3. **Trivial goal/no Done-when path was misunderstood.**
   - The intended order is acceptance *before* research/code: `running.md:125-133` says an absent
     `## Done when` must be drafted and recorded before P1 can proceed.  Thus the live run writing
     acceptance after work is not a documented permitted path.
   - The only phase waiver is `research,retro`: `loop.py:6317-6327` and `phase_gate.py` (called
     there) record it and explicitly say plan, plan-review, implement, and review are never
     waivable. `README.md:66-68` and `running.md:92-99` are the user-facing seams.
   - `work.py:3171-3190` accepts a nonempty `--no-tests` reason as an explicit test-first-proof
     exception. It is not a trivial-goal waiver and should be documented as such, including which
     visible phases remain mandatory.  Acceptance after work must be refused/treated as a run
     deviation, not retrospectively blessed.
   - Tests: phase-gate tests (locate by `waive-phases`), `tests/test_public_bootstrap_control.py`
     (`--no-tests` invocation), and a new documentation control that copies the stated gesture.

4. **Init's expected untracked artifacts are not explained at the discovery point.**
   - `sdlc_init.scaffold()` writes `.sdlc/*` and `_ignore_runtime_dirs()` changes `.gitignore`
     (`skills/sigma-init/scripts/sdlc_init.py:74-94`); after success it only prints the late tip
     at `:724-735`: commit durable `.sdlc/goals/`, `project.md`, and `config.json`, while runtime
     dirs are ignored. Fresh files therefore correctly appear untracked until the user stages the
     durable set; `.gitignore` is also expected to be untracked in a scratch repo.
   - Document this in init/README with explicit handling: inspect `git status`, stage/commit the
     listed durable files and `.gitignore`, leave runtime dirs ignored; never blanket-ignore
     `.sdlc/` because plans/acceptance are durable evidence.
   - Tests: `tests/test_onboarding_control.py` and init-flow/scaffold tests; assert the docs name
     tracked-vs-runtime boundaries, not a machine-specific `git status` ordering.

5. **Claude-only coexistence warning names a Codex path.**
   - `coexist.py:746-751` and `:923-926` always collect both Claude and Codex signals.  The report
     is therefore multi-host even when the active run is Claude-only; `codex_root()` defaults to
     `CODEX_HOME`/`~/.codex` (`:187-190`).  Its output must filter explanatory/remediation paths
     to the active host (or clearly separate detected active runners), without weakening the
     underlying whole-machine coexistence detection.
   - Tests: `tests/test_coexist.py` fixtures already model Claude/Codex states. Add a Claude-only
     control that asserts no Codex config path appears, and reciprocal Codex coverage if host
     selection is introduced.

6. **Empty `reconcile-merges` is already success, but undocumented.**
   - `loop.py:6262-6269` prints only changed records.  `tests/test_public_bootstrap_control.py:
     984-994,1086-1091` proves empty before merge and on an idempotent repeat, then exactly
     `1 done (PR #<n> merged)` after a merge.  The observed silence is intended no-op success,
     but README/onboarding should state it and name the nonempty success line.
   - Docs: `README.md` Done-means-merged row and `docs/onboarding-control.md:102-118,293-299`.

7. **No phase-report cost lines means the documented phase boundary was not executed/visible.**
   - The contract is explicit in `README.md:64-68`, `running.md:92-98`, and
     `docs/agent-rules-detail.md:194-199`: call `phase_report.py start` before every dispatched
     phase and `end` after it; `end` prints the constructed Block B/cost line.
   - `phase_report.py:end` always calls `emit(...)` after best-effort measurement
     (`skills/sigma-loop/scripts/phase_report.py:2030-2295`); unavailable usage is still an honest
     rendered line, rather than a reason to omit reporting.  Hypothesis: the live run's executor
     omitted the documented start/end commands (or output was hidden by the host), not that zero
     cost suppresses output.
   - Tests: `tests/test_phase_report.py` is the direct CLI/output seam, including its
     documented-gesture controls at `:2909+`; `tests/test_onboarding_control.py` already checks
     a cost line. Add a small end-to-end instruction/output control if current tests do not prove
     the auto-mode runner relays `end` stdout.

## Host-agnostic requirements

- Keep lifecycle authority in Python and portable instructions: Claude Code, Codex, and Cursor
  must each get a truthful review route. A host policy refusal is a park/defer-to-attended-review
  outcome, never a self-approval workaround.
- Never turn `--verify N:ID` into an inline shell command; number+digest confirmation is the
  repository-command trust boundary.
- Preserve durable versus runtime `.sdlc` separation, idempotent/silent no-op reconciliation,
  and phase-report output as a constructed report rather than hand-written status prose.
- Coexistence detection may inspect all installed hosts for safety, but user-facing action text
  must not name irrelevant host paths on the active-host path.
