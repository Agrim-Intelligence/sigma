# Research: #259 commit-boundary content secrets

## Existing boundary

`skills/sigma-loop/scripts/work.py:commit()` is the repository's documented
commit gesture. The loop skill, plan skill, and landing/running references all
direct committing phases through `work.py commit`; no phase-specific direct
`git commit` gesture was found.

The current `_secret_refusal` reads staged paths only. `scrub.py` is the shared
secret-shape source for repository handlers and already provides the shapes
the commit boundary needs. Its current representation pairs regular
expressions with redaction replacements, so it does not expose a stable rule
name for every match.

## Design

Expose a secret-safe matcher from `scrub.py` that returns only `(rule, line,
column)` metadata. It must never return a matching span or value. `work.py`
will request the staged added-line diff with `git diff --cached --unified=0`,
ask that matcher for hits, and combine those with existing filename offenders.
It will unstage only paths that have an added-line hit or a filename hit.

Known synthetic fixture shapes used by Sigma's tests will be an explicit,
small allowlist in `scrub.py`; it applies only to the commit matcher and is
not a general path or content bypass. The control reports `rule at path:line`
and no content.

## Controls

1. The documented `work.py commit` gesture red-fails for an ordinary staged
   Python file containing a synthetic cloud-key shape, reports rule and
   position, and does not print the value.
2. A known synthetic fixture shape stages and commits.
3. The enforcement table is regenerated and checks the commit-boundary scope.
4. Existing filename and diff paths retain their reset/remedy behavior.
