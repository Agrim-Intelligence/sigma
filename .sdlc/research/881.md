## Risks
1. `_hidden_run` copies the whole `hidden/` dir to `.sigma-hidden`, so `hidden/naive/` and `hidden/files/` both land in the scored tree; the verify.json command must name `.sigma-hidden/files` explicitly or pytest could collect `naive/` tests.
2. The pin must hold the SAME chain verify.py runs: `bench_tasks.clean_env -> _bench_module().arms_common.isolated_env`. A test that only checks `hasattr` would pass while the import chain is broken; import bench.py by path, assert `isolated_env` call output.
3. AC-3 "deleted file" needs full-tree compare of `repo/` vs `reference/` (not overlay), excluding `__pycache__`; symlinks skipped by `bundle_files`.
4. `_load_json` raises `SystemExit` with a message on a bad file, which is exit-code ambiguity (string exit = 1). verify.py should do its own JSON reads for exit 2 on unreadable input (design says exit 2).
5. Tails are 1500 chars, so a failing property message cannot rely on full pytest output.
6. Controls must run the documented gesture `python3 evals/golden/verify.py` (AGENTS.md "gesture the DOCS give") with the planted tree reached by a path the docs do not need flags for: the script resolves tasks relative to its own file, so the test must COPY verify.py plus a tmp task tree together, not pass a flag. The design's `--only/--json` optional flags cannot be the thing the control depends on.
7. `python3` on this machine is 3.9.6 (pytest present); repo floor is 3.10. Keep stdlib syntax 3.10-safe; the 3.9.6 interpreter is only a sandbox default.

Plan should settle by documenting the gesture in `evals/README.md` (not a scanned source) AND, if a `docs/*.md` line is added, confirm the guard resolves it.

- How `hidden/naive/` is composed: overlay onto start (bench `obvious/` analogue, :596-602) vs complete tree. Design is silent; overlay needs no deletion semantics, and a naive patch rarely deletes.
- `visible_command` validation: the design says validate, not run. Minimal viable check: non-empty list of strings, first token `python`/`python3`; whether to also execute it on the start tree is unspecified.
- Task dirs in the planted-tree controls: tests copy `evals/golden` entirely? Only slice 1 exists (no T1-T3 yet, those are slices 2-4), so the test plants its own tmp task trees; the committed gesture then verifies an empty set. An empty-set run must not read as green-vacuous: decide whether zero tasks is exit 0 or a refusal.
