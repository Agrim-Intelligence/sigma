# Research: Make main's full test suite pass in the cloud container, fixing causes not hiding them
**Goal**: #2225 · **Lane**: large · **Date**: 2026-11-15

## Goal in one paragraph

The configured full verify (`python3 -m pytest tests/ --ignore=... -rsEf -q -n 2 -p no:cacheprovider`, from
`.sdlc/config.json` and `tools/cloud/setup.sh:28`) fails on unmodified `main` (`524d533`) in the claude.ai cloud
container, so no `--land` run can open a PR. Every failure must be explained by its real cause and fixed there
(no skip/disable/delete/loosen/quarantine/`verify.known_flakes`), anything only fixable outside the repo is
reported with evidence and an exact setup-script change, no ceiling is raised silently, and the container facts
land in `tools/cloud/README.md`. Research finds **five independent cause families**, none of which is "the
container is broken": (A) tests that use mode-000 files to force a read error, which root ignores; (B) liveness
checks that read an unreaped zombie as alive, while this container's PID 1 reaps orphans only every ~2 s;
(C) two `fcntl`-absence tests whose `PYTHONPATH` shim cannot shadow `fcntl` because this interpreter builds it in;
(D) committed prose growth past the phase-context ceilings (a real repo defect, not environmental); (E) the
collection RSS guard divides whole-tree collection memory by the post-`-k` selected count.
