# Research: Release dependents when a goal closes (stale sdlc:blocked in --land fleets)
**Goal**: Agrim-Intelligence/sigma#2223 · **Lane**: medium (upper end; large only if the plan also splits the doctor row or the watcher duty into slices) · **Date**: 2026-11-14

Paths are relative to the goal worktree (HEAD 524d533). Script dir
`S = skills/sigma-loop/scripts`. Nothing was edited; no phase note was posted (caller asked for the dossier only).

## Goal in one paragraph
Add one scoped verb, `release-dependents <closed goal>`, that finds open `sdlc:blocked` goals naming the closed goal,
re-runs the sweep's own decision code, and drops `sdlc:blocked` over REST. It runs where a goal ends (`record done`,
confirmed merge), from the watcher tick for closes Sigma never saw, and at orchestrate wave end. `/sigma-doctor` reports
blocked goals whose dependencies are all closed, with the oldest age. The `--land` scope sentence gains a named exception.

### Traps found in the reuse (each needs a plan decision and a red-seen test)
1. **Stale map defeats the release.** With `discovery.dag.mode == on`, `_map_still_waiting` (`auto_unpark.py:446-463`) skips a
   blocked goal when the stored map shows an open blocker. Right after N closes, the map still stores N as open (it refreshes
   every `ttl_minutes`, default 60, `S/dag_store.py:116,DEFAULT_TTL_MINUTES`), so `compute_unpark_actions` would skip the very
   goal being released. The release path needs a bypass (new kwarg such as `use_map=False`, default True so the sweep is
   byte-identical) or an override of N's state; the map may supply candidates but must never supply "still open".
2. **`remove` list includes `sdlc:in-progress`** (`auto_unpark.py:612-613`, the #1393 half-applied-park repair). A dependent that
   carries `blocked` and a live claim would lose its claim. The issue says it "only ever removes sdlc:blocked": the verb must
   filter each action to `remove == [blocked]` and never `add`/`remove` anything else (and drop the `add goal` arm: a blocked goal keeps membership).
3. **Parked goals.** The sweep resumes a parked goal that carries a waiting-on-dependency note (#1549). Safety clause 7 says a
   parked goal is never resumed, so the verb must pass only `blocked_only` issues (blocked label present, parked absent).
   The one existing opt-in route for parked stays `/sigma-unpark` and the full sweep. Name this in the docs.
4. **Human/machine label collision.** `doctor._blocked_label_collision` (`doctor.py:2586`) says the refusal "belongs at the site
   that would act": nothing refuses today (`grep collision auto_unpark.py loop.py` empty). The new verb writes across the fleet,
   so it should refuse when `source.blocked_label == source.goal_blocked_label` (`S/sources.py:1080-1085`). Existing debt.
5. **Cloud/`--land` hook sees no `land_scope`.** `loop.py record` builds `sources.get_source(...)` itself (`S/loop.py:8971,8975`),
   so `_record` never sees a scoped source and nothing in code enforces the `--land` sentence except the picker. The exception is
   therefore prose plus a test, not a code gate (see section 7).

## 4. Dependency map (dag)
- Reverse edges: `dag_core.build` -> `Graph.dependents[number]` (sorted direct dependents) and `Graph.edges` of
  `(blocker, blocked, source)` (`S/dag_core.py:74-98`); transitive `open_dependents` (125). Load a graph from the stored map with
  `dag_chain._graph(m)` (`S/dag_chain.py:96-104`); edge sources are `body|comment|timeline|other` (`S/dag_store.py:77`). Nodes carry
  `life` (`blocked`, `parked`, ...) and `state`.
- Load + freshness: `dag_store.load(sdlc, config)` (`dag_store.py:370`, local file vs newer ledger snapshot), `usable(m, now, ttl)`
  (`457-480`: schema, built, not partial, age <= 2 x ttl or a change check within 600 s), and the stricter picker form
  `dag_pick._entry` (`S/dag_pick.py:65-84`): usable AND `checked_at` within `CHANGE_CHECK_SECONDS` (600). **"Fresh" for this verb
  should be exactly `dag_pick._entry`'s answer** (reuse, do not restate). Mode `off` reads nothing (`dag_store.py:113`); default is
  `shadow`; the sweep only acts on exactly `on`.
- Staleness caveat: reverse edges are candidates only. Their states are stale at the instant of the close (trap 1), so each
  candidate still gets live reads from the decision code. A missed edge costs latency, never a wrong release.
- Cloud note: the map is `.sdlc/state/dag.json` (gitignored); a fresh cloud container has none unless the ledger snapshot is on, so
  in `--land` fleets the **no-map listing path is the norm**, not the fallback. Plan for it first.

**Recommended hook set.** One hook in `_record`, `outcome == "done"` (covers CLI, `run_loop`, and the merge-reconcile pass in one
place, after `complete()` has closed N at 5564 and after the terminal ledger entry, with the other fail-open tail steps near 5736-5760).
The `work.merge` hook asked for in the issue has two costs: `merge()` has no `source` (its `run` is the `(cwd, argv)` shape, e.g.
`CloudGitHub.work_run` in `tests/test_goal_land.py:640`), so a hook there builds a second `GitHubSource` with the real runner and
every merge test then reaches real `gh`; and it adds a second pass over the same goals. Decision for the plan: either (a) `_record`
only, with the argument that `record done` is mandatory after merge in the landing flow, or (b) also hook `merge()` through an
injectable seam. I recommend (a) plus an explicit doc sentence, and treat "confirmed-merge path" in the Done-when as satisfied by
`_record(done, merged_pr=True)` (that is literally the confirmed-merge path in `_reconcile_one`). Raise it as a non-blocking question.

**`complete()` stays untouched**: `tests/test_merge_reconcile.py:869-890` pins its exact call count (6 calls) and that its cost
is named in docs; adding reads there would break the pin for every source user.

`sigma-orchestrate` today (prose): `skills/sigma-orchestrate/SKILL.md:232` ("unpark dependents that were waiting only on a merged
blocker") and `references/run.md:15,124-137` (step 4 and "## Unblocking": `unpark.py brief` then `unpark.py resolve --decision

## Scale and failure model (to state in the plan, AGENTS.md five properties)
- **Per-close cost** (not measured; arithmetic from the code): map path = 0 list calls + per candidate 1 issue read (body) + 1 comments
  read + 1 state read per distinct ref (memoised) + 1 label write + 1 note + 1 N label strip. Listing path = ceil(cap / 100) list calls
  (one page up to 100) + the same per candidate. A close with D dependents costs about 3D + 4 REST calls. At 10x/100x fleets the cost is per
  closed goal, so it is O(D) and not O(backlog) only on the map path; the listing path is O(blocked goals read), bounded by the ceiling.
- **Ceiling to name**: the listing cap (recommend 100 = one REST page, probe with `cap + 1` so "N+ not checked" is exact when it is hit)
  and a per-run candidate-read budget derived like `dag_refresh.bounds()`. `_list_issues` returns newest first only (`updated/desc` or `created/desc`,
  `S/gh_api.py:686-716`), so past the cap the dropped rows are the OLDEST blocked goals, the very ones most likely stale. State that
  loudly; the doctor row is the backstop.
- **Comment-only edges**: a dependent that names N only in a comment is invisible to a body prefilter. A fresh map sees it (edge source
  `comment`); the listing path sees it only if comments are read. Plan call: read comments for every listed blocked goal (cost up to cap
  reads, mitigated by `_CommentReads` persist cache keyed on `updatedAt`, `auto_unpark.py:142-189`), or prefilter on body and leave
  comment-only edges to the watcher's all-blocked mode. Recommend the second plus a docs sentence.
- **Recovery**: every action is idempotent (swap/remove no-ops); a missed release is caught by the watcher duty (bounded latency of one
  tick interval, throttled) and the doctor row; "any read failure releases nothing" means partial data never writes (use the
  `_fetch_parked_issues_status` `complete` flag, `auto_unpark.py:271-301`, as precedent). Quota: gate unattended callers with
  `gh_quota.rest_deferral(config)` (`S/gh_quota.py:252`), as `_auto_unpark_sweep` does (`loop.py:1400`).
- **Liveness**: the watcher duty should write a small state file (`state/release-dependents.last.json`: last run, checked, released,
  not-checked) read by doctor, so "the pipeline died" shows as age, not zero errors (`_blocker_rank_row` pattern).
