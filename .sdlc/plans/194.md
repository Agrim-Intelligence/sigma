## Design

Reality at main: the false "85% coverage floor" README claim was already removed by #277; the README says CI
measures no coverage. What is missing is a measurement, a floor and a guard that keeps the README honest once
one exists. Measured (research, run 2): **90.91%** line coverage of `skills/` and `hooks/`, coverage.py 7.16.2,
Python 3.12.13, macOS, 37,806 statements, 3,436 missed, 11,569 passed.

Smallest correct change, five files plus the record:

1. `.coveragerc` (test-only config): `source = skills, hooks`, `parallel`, `patch = subprocess`, `data_file`,
   `[report] fail_under = 85`. Floor = whole measured percent (90) minus 5 points of headroom: the Linux skip set
   differs from macOS and measured scope understates (see not-measured), so the floor must clear a ~5-point
   platform/skip swing without being a number nobody measured.
2. `.github/workflows/ci.yml`: **one leg only** (ubuntu-latest, Python 3.12): its plain pytest step is skipped and a
   coverage step runs `python -m coverage run -m pytest tests/ -rs -q`, `coverage combine`, `coverage report`
   (fails under the floor), after a `coverage erase` so a stale data file from a crashed run cannot be merged into the
   figure; `coverage==7.16.2` is pip-installed there only (pinned: the measurement is of that
   version). The other four legs are unchanged. Cost: the baseline for that leg is 1,481 s (run 37098147702); the
   PR's own CI leg is the measurement. Ceiling: job timeout is 60 min; if the leg exceeds ~45 min the step is
   reverted to measure-only on a schedule (follow-up), not left red. At 10x the suite the leg is the slowest
   one anyway; coverage adds a roughly constant multiplier (not measured on CI until the PR leg runs).
3. `docs/launch/coverage.json` (the measurement record) and `docs/launch/coverage.md` (commands, versions, figures,
   the not-measured list, floor derivation, CI cost measured on the PR leg, refresh gesture, recovery).
4. `README.md` Dev/test paragraph: replace "CI measures **no** code coverage today ... #194" with one sentence:
   CI enforces a line-coverage floor of **85%** over skills/hooks on Linux Python 3.12, last measured **90.9%**
   (tool, platform), pointing at the doc. The claim names its platform and the figure's own limits.
5. `tests/test_coverage_record.py` (new) and one edit to `tests/test_readme_first_run.py`: its
   `test_control_a_planted_coverage_claim...` first assertion runs against the REAL config files, which now
   enforce a floor, so it would go red; it takes `[]` for that assertion instead (the third assertion already
   covers "an enforcing CI clears it"). It is a repair of a pre-existing test, not new behaviour: there is no
   state in which its final bytes are red by assertion, so it is NOT a planned `## Tests` node; the full `verify`
   suite and a by-hand check (revert the edit, see it red against the new `.coveragerc`) cover it.
6. CHANGELOG entry (names no docs/launch or tests path).

## Failure modes and recovery

- Coverage tooling unavailable or a new Python incompatible: the step fails loudly on that one leg; the other four
  legs still gate merges. Recovery: unpin/bump the version in ci.yml AND the record (the test names both).
- Floor too tight after a legitimate change (new low-coverage script): fix by adding tests or by lowering
  `fail_under` together with the record and README (the test refuses a partial edit). No automatic lowering.
- Data files from a crashed run (`.coverage.*`) are gitignored already and removed by the next `coverage combine`.
- Nothing here spawns background work, sends data, or ships new runtime code; coverage is a CI-only dev tool.
