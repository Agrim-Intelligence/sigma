# #317 Board recovery instructions implementation plan

> Execution: Codex native implementation using Superpowers planning/TDD, then a fresh independent review agent.

**Goal:** The documented recovery for a dropped `setup_created` marker creates a new owned board when chosen, and the retry-TTL control advances time instead of changing policy.

**Architecture:** Correct the operator runbook and historical #308 artifacts without changing production board semantics. Exercise the copied documented recovery against `boardfake.GitHub`; test the existing repo-resolution TTL with a fake monotonic clock.

**Tech stack:** Python stdlib, pytest, repository GitHub board fake.

**Spec:** https://github.com/Agrim-Intelligence/sigma/issues/317

## Global constraints

- An existing pin wins when `create` omits `--number`; a bare legacy marker is never upgraded.
- Keep the existing board through `mirror_priority: true`, or explicitly remove the pin and use an unused title to create another board. Never imply that cards migrate automatically.
- No live board creation during tests or this goal's acceptance control.
- Preserve the production five-minute retry policy; change only the test clock.
- No new production paths, background processes, dependencies, or growing state.

## Review focus

1. A pinned legacy board must remain unchanged when the operator intentionally creates a separate one.
2. The default title can already exist; the new-board gesture must select an unused title.
3. Existing board cards do not automatically migrate to the replacement board.
4. Repository resolution must not retry just before TTL expiry, must retry at expiry, and must cache success after further time.
5. The recovery control must execute the documentation's real invocation, not silently add a stronger flag or config change.
