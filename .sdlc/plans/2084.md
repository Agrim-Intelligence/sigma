## Bullet grammar
`` - `<runner>: <path> > <suite> > <test>` `` . Runner name is `[a-z][a-z0-9_-]*` followed by `: ` (colon plus a space; a pytest selector never contains whitespace, so the two cannot collide). `{file}` = text before the first ` > `. `{name}` = the remainder after the first ` > ` (suite titles may contain `>`; the whole remainder is passed, so `-t "suite > test"`). A bullet with no ` > ` has an empty `{name}` and runs the whole file. The runner node id IS the bullet text, so `_selected(node, scope)` (`node == s`) works unchanged for it.

## Design
**Provenances.** `PROVENANCE = 'planned-pytest-v1'` unchanged. New `RUNNER_PROVENANCE = 'planned-runner-v1'` (red confirmed by `red_pattern`) and `RUNNER_EXIT_PROVENANCE = 'planned-runner-exit-v1'` (red from a nonzero exit alone: weaker, documented). Both are accepted by `refusal` for a runner node; a pytest node still needs `PROVENANCE`. A pattern-confirmed red row is `kind='assertion'`; an exit-only red row is `kind='other'` (not in `witness.STRONG_KINDS`), so exit-only red never reads as strong in `witness.verdict`. `file_hash` is the file bytes digest, as for pytest. The PR gate accepts the weaker row (otherwise AC-2 is unreachable without a pattern); it is documented as weaker and visible in the journal and the `runners` map.

**red_green.py.**
1. `selectors(plan, runners=None)`: a bullet matching `^([a-z][a-z0-9_-]*): (\S.*)$` is a runner bullet. Unknown runner (`runners` None or missing the name): `ValueError("unknown test runner 'vitest': configure tests.runners.vitest in .sdlc/config.json")`. File checks as the pytest branch except no `.py` suffix; `name` must hold no backtick, newline or NUL. The 1-25 cap and duplicate removal stay. The existing pytest messages are unchanged.
2. `render_command(template, file, name, runner='<name>')`: an ALLOWLIST, not a quote-state machine (round-2 N1: a state machine is unsound against `$( "..." )`, `$'..'`, a backslash before a placeholder and heredocs). Steps, all on the template text before any value is substituted: (a) literal braces: `{{` and `}}` are escapes for `{` and `}` (chosen over exempting `${`, which would reopen `$`); they are unescaped last. (b) If the template contains a placeholder (`{file}`/`{name}`), it must contain none of: a single quote, a double quote, a backtick, `$`, a backslash, `<<`; otherwise `ValueError("tests.runners.<runner>: a template that uses {file}/{name} may not contain ' \" ` $ \\ or <<; write the placeholder bare, Sigma quotes it")`. (c) `shlex.split` the template (posix); every token that contains a placeholder must BE exactly `{file}` or `{name}`, or match `^--[A-Za-z0-9][\w-]*=\{(file|name)\}$` (the `--flag=` suffix form); anything else (`x{name}`, `a;{name}`, `$x{name}`, a placeholder in a glued token) raises naming `tests.runners.<runner>`. A `shlex.split` failure (unbalanced quote) raises likewise. (d) any other `{word}` placeholder raises naming the key and the word. (e) Only then substitute by regex over `\{(file|name)\}` with `shlex.quote(value)`. A `{file}` or `{name}` beginning with `-` raises. Pure function, no shell. `selectors` calls it once per runner bullet with the real values, so a bad template fails at red, never at run time. The doc line in `docs/configuration.md` states the allowlist, the `{{`/`}}` escape, and that `$VAR`, quotes and heredocs belong in a script the template calls, not in a template that takes `{file}`/`{name}`.
3. `collect(root, scope, run)`: runner entries pass through as themselves (no collection); only the pytest entries are collected, and only if any exist.
4. `_hashes`: file for a runner node = `parse_runner(node).file`; otherwise `node.split('::')[0]`.
5. `observe(..., runners=None, timeout=None, exec_runner=None)`: run the pytest group exactly as today when it has nodes (byte-identical branch, still using the existing `run` seam). Runner commands go through a SEPARATE injectable seam, `exec_runner(command, cwd, deadline_seconds) -> (status, exit, output)`; the default wraps `bounded_run.run_group(command, cwd, remaining, shell=True, env=<same env helper>, merge=True, tail_bytes=200000)` (its ring-buffered, process-group TERM-then-KILL stop; no `capture_output`, no hand-rolled Popen/killpg; the implementer confirms the `Result` field names against `bounded_run.py` and adapts the thin wrapper only). `run_group` refusing on a platform without process groups makes the runner path REFUSE loudly (Windows: not supported, say so), never fall back to an unbounded run. ONE deadline, `time.monotonic() + timeout` (loop passes `_verify_timeout_seconds(config)`), is shared by ALL runner runs in the call; each run gets the remaining time, and when it is spent the remaining runners are not started. ONE `started` before the first run (pytest or runner) and ONE `completed` after the last; the before/after file-hash and plan-hash snapshot guard brackets the same span. Per runner: exit 0 = passed. Nonzero exit = candidate red, judged on the last 200,000 characters of output only. NO red row (and `error` says why) when the exit is 126 or 127 (command not executable / not found), negative (killed by a signal), or the status is a timeout/stop/refusal: a harness failure is not a red. Credit: `RUNNER_PROVENANCE` + `kind='assertion'` when a `red_pattern` is set and matches; `RUNNER_EXIT_PROVENANCE` + `kind='other'` (non-strong) when none is set; nothing when a pattern is set and does not match. Every red row uses the single `completed` as `observed_at`. The top-level `provenance` key stays `PROVENANCE`. `passed` is true only when every pytest node passed and every runner exited 0. **Aggregate `exit`** (read by `_verify_goal_body`, which copies `test_first["exit"]` into the verify return code): the first nonzero among the pytest exit then the runner exits in bullet order, else 0; a mixed plan therefore cannot report 0 while any part failed. **Command binding (N3)**: for each runner node compute `command_sha256 = sha256(rendered command)` and `pattern_sha256 = sha256(red_pattern or "")`; store both in the proof's `runners` map and in each red row's `detail` (as `bound:<command_sha256>:<pattern_sha256>`; the implementer confirms `witness.record` keeps `detail` verbatim in the journal row and, if it does not, adds the one optional field it needs, with a test). The returned dict is JSON-safe: it keeps its shape and adds `runners: {node: {"exit": int, "red": "pattern"|"exit"|None, "command_sha256": hex, "pattern_sha256": hex}}`; no compiled regex or other non-JSON object. A catastrophic `red_pattern` is a documented limit (Python `re` has no timeout); the input is bounded and the pattern is trusted repository config like the command beside it.
6. `refusal(..., runners=None)`: `selectors(plan, runners)` first (a runner no longer configured fails closed through the existing `except ValueError`); the row test becomes: a pytest node needs (`PROVENANCE`, `kind='assertion'`); a runner node needs (`RUNNER_PROVENANCE`, `'assertion'`) or (`RUNNER_EXIT_PROVENANCE`, `'other'`). Provenance and kind are checked as a pair, so an exit-only row cannot pass as a pattern-confirmed one. **Command binding**: `refusal` re-renders each runner command from the CURRENT plan and config, and the red row's `bound:` hashes and the proof's `runners[node]` hashes must both equal the current `command_sha256` and `pattern_sha256`; any difference refuses with 'runner command changed since observed'. Editing the template (or the pattern) after a red therefore voids both proofs.

**state.py.** `test_runners(config)` -> `{name: {"command": str, "red_pattern": str-or-None}}` (compile-checked for validity but returned as a string, so the map stays JSON-safe; `red_green` compiles at use). The name `none` is reserved and rejected (it collides with the plan's `none: <reason>` docs-only line). **Loaded once**: `red_goal` and `_verify_goal_body` call `state.test_runners(config)` exactly once and pass that same map to the trust gate, `_planned_scope`, `observe` and the flake loop (no second read that could differ). A `ValueError` from it prints its `tests.runners.<name>` message and exits 2 in `red_goal`; in `_verify_goal_body` it takes the existing trust-refusal exit (2) with the same ledger/actionlog writes, before any command runs; absent block = `{}`; a non-string/non-object value, an empty command, a bad name, or an invalid regex raises `ValueError` naming `tests.runners.<name>[.red_pattern]`. `runner_commands(plan, config)` -> the rendered command strings the plan would run (empty when there are no runner bullets); it is the single list the trust gate and the flake loop use.

**Trust (loop.py, AC-3).** New `_runner_trust_refusal(trust, runner_cmds)` -> text or None: no runner commands -> None (the existing decision stands, so a pytest-only goal behaves exactly as today); `trust.source == "git-local"` -> None; otherwise the text of `shell_policy.verify_refusal_message(Decision(None, "runner-command", ...))`, which names the git-local gesture and says the environment approval does not cover a runner command. Trust is a capability, not a courtesy: `loop.py` passes `runners` into `observe`/`selectors`/`_planned_scope` ONLY when `trust.source == "git-local"` and otherwise passes `runners=None`, so even with the refusal call removed a runner bullet hits the unknown-runner path and nothing runs; `_runner_trust_refusal` supplies the right text (it lists runner commands via `state.runner_commands(plan, config)`, which executes nothing). It is called in `red_goal` and `_verify_goal_body` immediately after the existing decision and BEFORE `observe`, the verify commands, the flake check or the witness run anything. `red_goal` exits 2. `_verify_goal_body` refuses with exit 2 and the same ledger/actionlog writes as the existing trust refusal (Q-3). A `ValueError` from reading the plan/config in this gate returns None: `observe` then reports the unknown-runner message (AC-4) through its existing `error` path, and `red_goal` already prints it with exit 2.

**Flake and witness (Q-4).** `_planned_scope` passes `runners` and returns `(selectors, nodes)` where runner entries are in `nodes`. `_flake_verdict` splits `nodes`: pytest nodes go to `flake_check.check` as today (skipped when there are none); runner nodes run their rendered command 3 times sequentially through the same `exec_runner` seam under ONE shared deadline for the whole flake step (`_verify_timeout_seconds(config)`, not 3600s per run; when spent, the verdict is `absent` with the reason) (same trust, already passed the gate) and reuse the existing `verified`/`unverified`/`absent` vocabulary (all three exit codes equal -> `verified`, else `unverified` with the disagreement). Cost: 3 extra runner runs per bullet (bounded by the 25-bullet cap); the flake check is still advisory and never gates. The witness verdict gets the runner file hash through `witness.test_source`. Everything in the verify path that wraps these stays `except Exception` advisory.

**Ceilings and honest limits (to state in the docs and the PR body).**
- Runner timeout: bounded by `_verify_timeout_seconds(config)` with the process group killed; a chosen bound, not a measured one; one deadline is shared by all runner runs in a call (and by the flake step). A catastrophic `red_pattern` regex is NOT bounded (no `re` timeout): the pattern is trusted repository config, its input is truncated to 200,000 characters, and `docs/configuration.md` names the limit.
- A runner that matches zero tests (a `-t` filter naming nothing) can exit 0 and read as a false green; vitest-specific flags such as `--passWithNoTests` are the operator's template choice. Sigma cannot detect it from an exit status alone. Unmeasured against a real runner.
- Exit 126, 127, signal deaths and timeouts earn no red (harness failure), so a mis-configured template shows as 'nothing red', not as a false red.
- Runner red without `red_pattern` cannot tell an assertion from a compile error: recorded under the weaker provenance.
- Not measured against a real vitest project (none installed). AC-5 uses a shell stub. No "works with vitest" claim is made.
- The cloud environment approval never covers a runner (Q-1 (a)). A cloud run must either use the git-local grant or `--no-tests`.
- `diff-revert` (BR-13) and the no-plan diff fallback (TD-5) remain pytest-only.
- Scaling: runner cost is linear in bullets (cap 25), each run once for red/verify plus 3x for flake; no new store or lock.
