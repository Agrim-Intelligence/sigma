# #363 Knowledge-graph launch-control plan

**Goal:** Make the supported knowledge-graph path observable end to end and make a graphify
skill/package mismatch a doctor failure with its exact repair.

## Constraints

- Keep the graph opt-in and do not select or invoke a paid backend.
- Preserve the existing fail-open refresh behavior and its persisted failure signal.
- Treat only graphify's explicit skill/package mismatch warning as a mismatch; an arbitrary
  successful version output remains an installed builder.
- Run the real, read-only `graphify --version` probe. Use a deterministic local builder for
  extraction behavior when no operator-configured backend exists.

## Task 1 — Detect the real graphify version split

Files: `skills/agrim-doctor/scripts/doctor.py`, `tests/test_doctor.py`.

1. Add a focused failing doctor test whose injected `graphify --version` output contains the
   observed skill/package mismatch warning and a successful version line. Assert that doctor
   reports a failed mismatch row and names `graphify install`.
2. Add the minimal parser and doctor row. Preserve the ordinary installed row for present,
   matching, and non-graphify builders.
3. Prove the test is sensitive by restoring the old presence-only behavior in a scratch mutation,
   observing RED, and restoring the implementation.

## Task 2 — Pin the supported control flow

Files: `tools/kg_control.py`, `tests/test_kg_control.py`, documentation if command text changes.

1. Build a temporary, opt-in repository with a deterministic builder that supports `extract` and
   `query`; verify build, query, context pre-flight inputs, auto-refresh, persisted failure state,
   and the doctor row through public CLIs.
2. Cover disabled, missing-builder, mismatched-builder, and failed-refresh controls. Each must be
   observed RED against its relevant broken behavior.
3. Run the control’s documented command and record elapsed duration plus fixture corpus size. State
   that a live extraction cost is unavailable when no configured backend exists.

## Definition of done

The mismatch is visible with a copyable repair, the control proves the opt-in flow and existing
failure visibility without charging a backend, focused and full tests pass, and an independent
review finds no unresolved issue.
