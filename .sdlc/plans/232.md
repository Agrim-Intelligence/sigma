# #232 plan — done means merged

Owner decision: done only after merge. Research: `.sdlc/research/232.md`.

## Decisions (made here, recorded; nobody available to ask)

- D1. `record done` with `work.enabled` and a PR on record is allowed ONLY on a positively confirmed
  merged PR (REST `pulls/<n>`: `merged` true or `merged_at` set). Open (armed or not, any
  `auto_merge` policy, fork, read-only) → REFUSED exit 4 naming the PR and `record review`. Closed
  unmerged → REFUSED naming `record parked`/`failed`. Unreadable → REFUSED naming `record review`
  (fail-closed: the refusal no longer wedges anything, because `review` is always available and the
  reconcile pass finishes the goal later). No PR on record, or `work.enabled` off → unchanged.
- D2. New non-terminal outcome `loop.py record <dir> <goal> review` ("awaiting merge"). Requires
  `work.enabled` and a PR on record, else refused (exit 2) — nothing to await. Effects: work record
  gains `awaiting_merge: {since, pr, goal}`; GitHub: no label removed (the claim's `sdlc:in-progress`
  stays; NOT re-added -- `mark_in_progress` stays its single writer, pinned by tests/test_docs.py --
  so `_next` also skips flagged goals locally), board → QC (existing `mark_qc`), one audit comment
  (only on the first `review`); local: journey
  note, status stays `in_progress`. Ledger: `parked` with why `awaiting merge of PR #N` (ends the
  lease so auto-reclaim cannot hand it back to Ready; #1394 precedent); no park EVENT (park metrics
  unchanged). Action log `recorded result=review`. Session/agent/phase markers released. Worktree
  KEPT (the merge-time `done` releases it). No unit-completion signal, no issue close.
- D3. `merge()` under `auto_merge: off` runs `effective_review_mode` + `review_gate` BEFORE leaving
  the PR for a human: a `sigma:block` / Request-changes / unresolved thread now PARKs on defaults.
  The line names the gate: `... — review gate passed (require_review: changes) — auto_merge is off,
  leaving PR #N for a human` (ending unchanged, so routing on it still works).
- D4. `loop.py reconcile-merges <dir>` + `_reconcile_awaiting_merges()`: for work records with
  `awaiting_merge`, oldest-checked first, at most 10 per pass, skipping any checked < 120 s ago:
  merged → `done_refusal` replays the merge receipt, then `_record(done)` (closes the issue, strips
  labels, board Done, releases the checkout) and clears the flag; closed-unmerged → `_record(parked,
  "PR #N was closed without merging")` and clears the flag; open/unreadable → stamp `checked_at`,
  nothing else. Idempotent: the flag is cleared only after a recorded `done`/`parked`; a `done`
  downgraded to `parked` by a raising `complete()` keeps the flag so the next pass retries.
  Triggers (layered, host-agnostic, all Python): `_next()` (inside the budget/handoff gate, since it
  writes to GitHub), `reconcile_tick.py` (watch daemon), and the explicit CLI verb. Zero cost when no
  record is awaiting (one directory listing, no `gh`).
- D5. `run_loop()` (programmatic driver) gets the same backstop: a `done` result whose PR is not
  confirmed merged is recorded `review` (open/unknown) or `parked` (closed).
- D6. Local-goals mode with no PR: unchanged (no PR → no refusal, `review` refused as meaningless).

## Definition of done

On shipped defaults, one goal end to end against the fake gh + bare origin: issue open while PR
open (board QC, `sdlc:in-progress`), closed only after the PR merged; review gate ran (a `sigma:block`
parks the merge). Every guard seen red once. Cost at 100x stated with the measured per-pass call
count.
