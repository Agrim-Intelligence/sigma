## Documented gesture and receipt

`python tools/parity/resources.py --reserve-fraction 0.25 --record-bytes 256 --output-dir .`

Both numeric inputs are required: the fraction is an operator policy input, and record-bytes is the caller's observed serialized record size, labelled caller-supplied in the receipt. No OS/test/source override flags exist. The command writes no file and invokes no executable/network service. Before importing the local resource_sources module, resources.py sets sys.dont_write_bytecode=True; the documented gesture needs neither -B nor an environment opt-out to avoid __pycache__. Success prints one JSON receipt; every refusal, including malformed/missing/unknown CLI arguments, prints exactly the typed JSON object on stderr and exits 2 without stdout. Override ArgumentParser.error to raise the typed invalid-input refusal rather than emitting stock argparse prose. --help is the ordinary requested help response, not a refusal or success receipt.

Receipt schema parity-resource-preflight/v1 is frozen below. It records every memory source and its arithmetic and explicitly describes snapshot-derived capacities, not allocations/reservations or measured scan throughput.

### Exact success/refusal schema

All byte counts, page counts, numerator/denominator values and potentially large counts are canonical unsigned decimal STRINGS (`0` or a nonzero digit followed by digits), never JSON floats or imprecise JavaScript numbers. CPU/worker counts and the decode-expansion factor are positive JSON integers; no bool counts as an integer. Floats, negative values, duplicate keys or nonfinite values cannot enter a successful receipt. The CLI emits UTF-8 JSON followed by one newline.

Success has exactly these top-level keys:

- `schema`: literal `parity-resource-preflight/v1`.
- `status`: literal `ok`.
- `platform`: one of `linux`, `darwin`, `win32`.
- `python`: the executing interpreter's version string.
- `sampled_at`: UTC ISO-8601 string ending in `Z`.
- `inputs`: object with exactly `reserve_numerator`, `reserve_denominator`, `record_bytes`; all decimal strings. Record size is explicitly caller-supplied, not an attested observation.
- `cpu_count`: positive JSON integer.
- `cgroup`: object with exactly `mode`, `mount`, `mount_root`, `process_path`, `ancestors`. Mode is `v2`, `none`, or `not-applicable` on success. A v2 record contains the resolved cgroup2 mount path, its hierarchy root (`/`), the process's unified cgroup path, and the ordered full paths of every selected ancestor from process to mounted root. `none` records a verified absence of a memory controller, rather than pretending it is an unlimited v2 hierarchy; its paths are null and ancestors empty. `not-applicable` is the explicit Darwin/Windows value with null paths and empty ancestors.
- `sources`: nonempty array of source objects, each with exactly `name`, `location`, `mode`, `limit_bytes`, `used_bytes`, `available_bytes`, `facts`. `name` is a static API/proc/cgroup identifier; `location` identifies the actual native API, proc file or resolved cgroup ancestor directory. `mode` is `finite` or `unlimited`; finite byte fields are decimal strings with `limit - used = available > 0`; unlimited has null limit/available and a decimal used count, except an unavailable measurement is explicitly null for RLIMIT_AS with no finite cap or the cgroup-v2 hierarchy root. `facts` is a string-to-decimal-string object, with unit-bearing keys such as `free_pages`, `inactive_pages`, `speculative_pages`, `page_bytes`. Ordered sources preserve collection order, including every cgroup ancestor; each v2 ancestor has a source row even if unlimited. The hierarchy root has a static `cgroup-v2-root` unlimited row with null used bytes: Linux defines memory.current and memory.max only for non-root cgroups, so root usage is never invented. Non-root missing files still refuse. Kernel paths reject traversal, NUL and control characters before use and are emitted as escaped JSON strings; no raw line-oriented path output is used.
- `disk`: object with exactly `api` (`fstatvfs` or `GetDiskFreeSpaceExW`), `directory` (the resolved existing directory string), `available_bytes` (decimal string).
- `limits`: object with exactly `available_bytes`, `reserve_bytes`, `usable_bytes`, `decode_bytes`, `output_buffer_bytes`, `record_memory_bytes`, `object_overhead_bytes`, `blob_bytes_per_worker`, `output_records`, `output_bytes` (decimal strings), `worker_slots` and `decode_expansion` (positive JSON integers).
- `limitations`: the exact array `snapshot-not-reservation`, `decoded-text-only`, `cpu-count-not-quota`, `caller-supplied-record-size`, `scan-throughput-unmeasured`.

Refusal has exactly `schema` (same literal), `status` (`refused`), `platform` (current sys.platform string), `code` (one of the stable values below), `source` (static identifier of the failed validation/API, never an exception's arbitrary text), and `cgroup` (the same provenance object where discovered, else null). A v1 refusal preserves mode `v1-unsupported` and the safely parsed process path, with null unknown mount/root and no invented ancestors. A refusal before source discovery, such as invalid CLI input, explicitly has null cgroup provenance. It appears only on stderr, exit 2, without success stdout. No partial successful receipt is emitted.

Stable refusal codes: `invalid-input`, `unsupported-platform`, `source-unavailable`, `invalid-source`, `native-binding-unavailable`, `native-api-failed`, `cgroup-v1-memory-availability-unsupported`, `cgroup-mapping-unsupported`, `memory-exhausted`, `budget-exhausted`, `disk-exhausted`. Map OS read failures to source-unavailable, native binding/status errors to their named codes, malformed/inconsistent facts to invalid-source, nonpositive remaining finite memory to memory-exhausted, invalid CLI arguments to invalid-input, and arithmetic with no positive usable partition to budget-exhausted. Freeze exact representative success/refusal fixtures in tests. An additive or incompatible shape change requires an explicit version/contract decision rather than silently changing v1.

### Exact allocation equations and order

Use arbitrary-precision Python integer arithmetic throughout. Validate each finite source before taking a minimum; available values cannot exceed sys.maxsize. Let `A` be the minimum remaining capacity across the applicable finite sources. Convert the validated finite fraction `r` to its exact binary-float integer ratio `p/q`, with `0 < p < q`. Then compute in this order:

1. `U = A * (q-p) // q`; `reserve_bytes = A-U` (reservation rounded up, usable rounded down).
2. `D = U // 2`; `O = U-D`. The odd remaining byte belongs to output, so `D+O=U` exactly.
3. `E = 1 + ctypes.sizeof(ctypes.c_uint32)` (encoded byte plus worst-case Unicode code point); `H = sys.getsizeof(b'') + sys.getsizeof(chr(sys.maxunicode)) - ctypes.sizeof(ctypes.c_uint32)` (measured object overhead, not a copied machine limit).
4. `R = E * record_bytes + H`; `W = min(cpu_count, D // R)`.
5. Refuse W=0 before division. `B = (D // W - H) // E`; `N = O // record_bytes`; `T = N * record_bytes`.
6. Refuse any nonpositive U/D/O/B/N/T. Then require `disk_available >= T`; equality passes, one byte less refuses disk-exhausted.

The receipt names A/U/D/O/R/W/B/N/T through the limit fields above. Enforce `W*(E*B+H) <= D`, `T <= O`, and `D+O <= U <= A`; arithmetic cannot wrap because it stays in Python integers and large outputs serialize as decimal strings. Library inputs and CPU count must be positive non-bool integers within sys.maxsize. Oversized/malformed sources refuse rather than truncate. These are raw/decoded text-buffer ceilings; future parsers must budget their own object graphs.

Compatibility fixture: A=100000, r=0.5, record_bytes=16, cpu_count=2, synthetic measured H=112, E=5 yields U=50000, D=25000, O=25000, R=192, W=2, B=2477, N=1562, T=24992. The intact fake-source CLI fixture must produce that exact shape/arithmetic; each stable refusal code has an exact-shape representative. Add distinct v2, no-controller and v1-refusal compatibility fixtures, plus two equal-capacity/different-path v2 fixtures whose provenance must differ. Assert ancestor-path coverage against source locations, including an unlimited ancestor. Tests patch only normal measurement/time seams and invoke the same public argv as the documentation.
