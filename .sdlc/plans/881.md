## Decisions (made, not open)
- **Layout**: golden root = `Path(__file__).resolve().parent`; tasks = child dirs holding a `task.json`. No flag is
  needed. Flags: `--only ID` (a mistyped ID exits 2), `--help` prints usage, exits 0, verifies nothing.
  `--json OUT` is SKIPPED (YAGNI; it would need `write_text` and a write-surface entry).
- **No write-surface calls**: use `tempfile.TemporaryDirectory`, `shutil.copytree`, `subprocess`; never `rmtree`,
  `os.remove`, `write_text`, `mkdir`. Expected write-surface entries: zero. The plan step 8 proves it by running the
  ratchet, not by assuming.
- **Zero tasks**: exit 0 with the loud line `0 golden tasks found under <root> (nothing verified)`. Reason: slice 1
  ships none, and the CI step must be green before slices 2-4 land; a refusal would make this PR red by design.
  RELIABILITY: a vacuous green is the risk, so (a) the line is on stdout and says nothing was verified, never "ok",
  and (b) a control plants a broken task in a copy and requires exit 1, proving the zero-task path is not a blanket
  pass. Slice 2 may tighten this to "at least 1".
- **Exit codes**: 0 all green; 1 any red, each line `RED <task> <property>: <detail>`; 2 unreadable or invalid input
  (bad JSON, missing file, unknown `--only`). Windows: `sys.platform == "win32"` -> refuse, stderr, exit 2 (SAFETY;
  `_run` uses `killpg`/`start_new_session`).
- **task.json**: keys `id` (must equal dir name), `kind`, `origin`, `prompt`, `visible_command`, `hidden_sha256`,
  `trap`. `origin` matches `^(planned|issue:[0-9]+)$`. `visible_command`: non-empty list of strings, first token
  `python` or `python3`; validated only, never run. `hidden_sha256` is a MAP `{path-relative-to-hidden/: sha256-hex}` (golden's own format; bench's string digest is not
  reused) whose keys equal exactly the set of regular files under `hidden/files/**`, `hidden/verify.json`,
  `hidden/naive/**` (missing, extra, or mismatched all red, naming the file). Junk is IGNORED explicitly, in code and
  README: any path with a `__pycache__` component, `*.pyc`, `.DS_Store`. verify.py reads all JSON itself with
  `json.load` (bench `_load_json` raises `SystemExit(str)` = exit 1, which would masquerade as red).
- **Pre-parse before any bench call** (verified: `_hidden_run` -> `_load_json(bundle/"verify.json")["command"]` is
  unguarded): per task, `hidden/verify.json`, `rubric.json`, `allowed_paths.json` must each EXIST and parse; a missing
  file is RED `<task> <file>: missing` (the task is readable, its contract is broken); invalid JSON is exit 2.
  `verify.json["command"]` must be a non-empty list of strings containing `.sigma-hidden/files` and
  `-p no:cacheprovider`, else red `verify-json`. allowed_paths: list of strings; rubric: JSON object.
- **A child dir without `task.json` is RED** (`<dir> task-json: missing`), never skipped: only a golden root with no
  child dirs at all is "0 tasks". Dirs named `__pycache__` or starting with `.` are ignored.
- **Reference** is a FULL tree. AC-3: compare `repo/` vs `reference/` by relative path + sha256 (own walker via
  `os.walk`, regular files only, skip `__pycache__`); added, changed and deleted paths must each be in
  `allowed_paths.json` (exact path or `dir/` prefix). A deleted file is red.
- **Running**: per task, `bench_tasks._hidden_run(tree, bundle, task, python, timeout, env)` with `bundle` =
  a temp copy of `hidden/` WITHOUT `naive/` (so `.sigma-hidden/` never contains naive tests; research risk 1), env =
  `bench_tasks.clean_env(profile_dir)`, python = `sys.executable`, timeout 120 s, overridable ONLY by the test-only env var `SIGMA_GOLDEN_TIMEOUT`
  (int, bounded 1..600, else exit 2; documented in evals/README.md as test-only; `clean_env` forwards it to the child
  harmlessly, nothing there reads it) (process group SIGKILL by `_run`; `(None,"timeout")` is red). hidden/verify.json `command` must be argv with `.sigma-hidden/files` explicit and
  `-p no:cacheprovider`. Start tree: exit must be exactly 1 (AC-1; 0, 2+ or timeout red). Reference tree: exit 0 (AC-2).
- **hidden/naive** (optional): OVERLAY onto a copy of `repo/` (bench `obvious/` analogue; no deletions needed), then
  hidden tests must exit 1 (AC-6); exit 0 red "hidden tests pass on the naive patch". Naive files are hashed (above).
- Python 3.10-floor syntax only (no `match`-free issue; no 3.11+ features). Repo verify command is
  `$HOME/.sigma-venv312/bin/python -m pytest tests -q -n 4 -p no:cacheprovider`; run it for every pytest step below.

## Scale and failure
Cost is linear and sequential: per task 2 pytest runs (+1 naive), ~0.3-0.5 s each (research: 0.27 s floor), so 10x
(30 tasks) is on the order of tens of seconds and 100x (300) several minutes; UNMEASURED beyond the step 12 figure, and
single-threaded is the named ceiling (parallelism deferred; past ~100 tasks add it or shard CI). Follow-up (recorded, not open): when slice 2 lands the first task, the zero-task exit-0 path becomes a refusal (exit 2)
and its control inverts. Growth is bounded by
committed tasks; nothing accumulates (no cache, no state). Failure: a hung test is killed by process group at the
timeout and reported red, the run continues to the next task; every temp dir is a `TemporaryDirectory` removed on exit
and on exception; a SIGKILL of verify.py itself leaves only OS-tmp scratch. Re-running is the recovery (stateless). No
network, no model, no spend, no background process, env scrubbed of secrets by `clean_env`.
