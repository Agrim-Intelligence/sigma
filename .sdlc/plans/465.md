# Plan: #465 — sweep of provably finished goal worktrees under .sdlc/work

Inputs: issue #465, `.sdlc/research/465.md`, `.sdlc/acceptance/465.md`. Worktree `.sdlc/work/465`. Two author-blind plan reviews returned FIX-FIRST; this revision answers them (summary at the end).

## Design
The sweep reclaims ONLY the checkout directory (the 20-60 MB part). It never deletes a branch, a remote ref, the work record, a ledger entry or an action-log row, and never calls `work.finish`: the work record is the only place a goal's PR number lives and a goal that survives with a merged PR is one whose `record done` never ran, so the record must stay for the paths that still need it (`record done`, merge-reconcile, `work.finish` on a vanished directory, `work.start`'s documented "worktree DIRECTORY vanished while the record and branch survived" path). The branch ref keeps every commit, so even a removal that raced a session loses no commit.

- New `skills/agrim-loop/scripts/worktree_prune.py` (stdlib; loads `loop`, `ledger`, `state`, `work`, `liveness_prune` by path). `sweep(sdlc_dir, config=None, limit=3, max_examine=20, max_pr_reads=8, budget_seconds=None, dry_run=False, run=None, exclude=(), quiet_unsupported=False)` -> `{"removed": [goal...], "kept": [{"goal","worktree","reason"}...], "busy": bool}`; never raises. `limit` caps removals, `max_examine` caps candidates examined (`0` = no cap, CLI only), a wall-clock budget stops both with a `budget` reason; hooks always pass explicit values, so no hook can pass `0`. Candidates come from `state/work/<stem>.json`, sorted by goal. Every unreadable or unprovable fact KEEPS the tree and names the reason for a human. Checks, cheapest first:
  1. safe stem (`state.unsafe_goal_reason`) -> else `not-owned`; stem in `exclude` -> `excluded`;
  2. the recorded worktree path equals `<project root>/<work.worktree_dir>/<stem>` exactly (resolved), is a directory and not a symlink -> else `outside-work-root`; missing directory -> `worktree-missing` (left to `work.finish`);
  3. the process's current directory is not inside it -> else `current`;
  4. no `awaiting_merge` flag in the record (the merge-reconcile pass owns that goal) -> else `awaiting-merge`;
  5. no alive or unknown `agents/<stem>/*.active` marker and the goal in no LIVE session's `in_flight` list (the #464 helpers `liveness_prune._agents_dead` / `_live_in_flight`) -> `live-agent`, `live-session`. A host with no hooks leaves neither: there liveness rests on checks 6-10 only, stated in the doc. Check 5 is run AGAIN immediately before removal (a session that resumed in the tree after the first look is caught);
  6. EVERY git call against the tree first asserts `git rev-parse --show-toplevel` equals the path (both sides `resolve()`d: macOS `/private`) (a tree whose `.git` file is gone resolves to the MAIN repo; every later check would then be about the wrong repository) -> else `not-a-worktree`; the checked-out branch (`git symbolic-ref --short -q HEAD`) equals `record["branch"]` -> else `branch-mismatch` (a detached HEAD or a `wip/<n>-paused` rename is WIP);
  7. `git status --porcelain --untracked-files=all` is empty -> else `dirty`; `git ls-files -v` shows no assume-unchanged / skip-worktree entry (they hide edits from `status` and from `git worktree remove`) -> else `hidden-changes`; and every IGNORED file (`git ls-files --others --ignored --exclude-standard`, at most 5,000 listed, more -> `ignored-content`) is regenerable: a path with a `__pycache__`, `.pytest_cache`, `.mypy_cache` or `.ruff_cache` component, `*.pyc`, `.DS_Store`, or under `.sdlc/state/time/` (worktree-local time events from a run inside the tree: measured on the real survivors as test fixtures only; not merged anywhere; the existing `finish` already discards them on every `done`; named as a loss in the doc) -> else `ignored-content` (a `.env.local`, a local database, scratch notes are user data);
  8. the record has a numeric `pr` -> else `no-pr` (nothing proves the work landed: parked, abandoned, never-pushed goals all land here);
  9. at most `max_pr_reads` REST reads per sweep (`gh api repos/{owner}/{repo}/pulls/<n>`, never GraphQL; the rest read `deferred`): the PR is positively `merged` -> else `pr-open`, `pr-closed-unmerged` (a human closed it: the work may be wanted), `pr-unknown`; and its `head.ref` equals `record["branch"]` and its `head.repo.full_name` equals `base.repo.full_name` -> else `pr-mismatch` (a fork, a wrong repo, or `head.repo: null`);
  10. `git merge-base --is-ancestor HEAD <PR head sha>` exits 0, i.e. every commit in the tree was in the merged PR (right for squash and rebase merges, where the branch is not an ancestor of main) -> exit 1 `unpushed`, anything else (sha absent locally, git error) `unprovable`.
  Only then, and only when not `dry_run`, under `limit` and the budget: re-read the tree's HEAD and the record's sha256 immediately before acting (abort `moved` unless both are what was proven), write a journal `state/worktree-prune/<stem>.json` (`worktree`, `head`, `branch`, `record_sha256`, `heals`; atomic; if it cannot be written the removal is NOT started, `journal-failed`), then run the sweep's OWN `git worktree remove <path>` (never `--force`; the argv is a literal, asserted by a test) and `git worktree prune`. The journal is unlinked only when `git worktree remove` returned success, or when the tree is re-proven intact (toplevel ok, status clean, HEAD equal to the journalled head); otherwise (a failure or a timeout midway, which can leave a half-deleted tree) it stays for the heal pass. The removal call has its own 60 s bound (`min(SIGMA_WATCH_CALL_TIMEOUT, 60)`, not the remaining budget: a removal is never started with less than one budget unit left, and never killed early by a nearly spent budget). Reported `removed` or `remove-failed`. The record is left in place, now naming a directory that is gone.
- Opt-in (AGENTS.md SAFETY: nothing consumes quota without the operator opting in). The REST reads are quota, so the automatic triggers run only when `work.reclaim_merged_worktrees` is `true` (new key in `work.DEFAULTS`, default `false`; documented; read with `work.settings`). The operator lever below always works and is the documented way to reclaim by default; the doc states that a default install therefore keeps its survivors until the operator runs it or enables the key, with the measured cost per tree.
- ONE SWEEP AT A TIME: the whole sweep, heal pass included, runs under a non-blocking `flock` on `state/worktree-prune.lock` (a singleton file, never deleted: deleting a flock file admits a second holder). Held -> `{"busy": true}`, nothing removed or healed. Without `fcntl` the sweep REFUSES loudly (stderr, the lever exits 2) and removes nothing; the hooks skip it silently (no stderr per `done`).
- Heal pass (under that lock, so any journal is from a sweep that died or a removal that failed midway, never from a live one). A journal is a HINT, never an authority: it acts only while the record exists, its `worktree`, `branch` and `record_sha256` equal the journal's and, where a tree exists, its HEAD equals the journalled head; any mismatch (a goal re-run after the crash has a new tree and record) deletes the journal and the normal checks decide. Then: `git worktree prune` (only when a journal exists; it is global, as is the one `work.finish` already runs: it also drops other goals' admin entries whose directory is temporarily missing, named in the doc); directory missing -> drop the journal (the record stays, as above); directory present and registered, only ` D` status lines (tracked files deleted by the interrupted `git worktree remove`; their content is in the journalled HEAD, which a merged PR contains) -> `git checkout -- .` so the ordinary removal runs in the same sweep, otherwise `dirty`; the restore happens AT MOST ONCE per journal (`heals` is incremented before it): a tree whose removal is killed again after one restore is `heal-gave-up` and left, with its journal, for a human, so recovery can never become a recurring I/O storm on a tree too big to remove within its bound; present and NOT registered (git pruned it: its `.git` file went first) -> `shutil.rmtree` only when, re-checked immediately before, the path still passes check 2, is still not registered and the record sha256 still matches, and and every remaining entry is regenerable (check 7's list) or matches the blob at that path in `git ls-tree -r <journalled head>` (run in the MAIN repo; a symlink compared by `readlink` against the blob, an unreadable entry counts as a mismatch; never `check-ignore`, which in a tree with no `.git` reads the main repo's `.sdlc/*` rule and calls everything ignored), else keep it `debris-unverified` for a human.
- Triggers, all Sigma Python (host-agnostic, no hook load-bearing, no daemon, no process pause): `loop._record` on a real `done` after `_release_checkout` (excludes its own goal) and the CLI `start` verb; both only when the opt-in is true, fail-open, `limit=3`, `max_examine=20`, 20 s budget; the trigger is SKIPPED when `_record` runs for the merge-reconcile pass, which holds `merge-reconcile.lock` (an explicit `housekeeping=False` keyword that only `_reconcile_one` passes; NOT `merged_pr`, which every ordinary `record done` on a PR-bearing goal also sets), and an automatic sweep is skipped when the previous one ran less than 15 minutes ago (`state/worktree-prune-seen.json` mtime; the lever ignores it). EVERY `git` and `gh` call the sweep makes goes through the module's own runner whose timeout is `min(SIGMA_WATCH_CALL_TIMEOUT (default 120 s, the loop's convention), the sweep budget still remaining)` with a 5 s floor, so a hung call keeps the tree and can never hold a `done` past its budget. A timeout that kills `git worktree remove` is itself a crash-mid-remove: the heal pass is its recovery and a test kills it that way. Operator lever: `python3 skills/agrim-loop/scripts/worktree_prune.py sweep .sdlc [--dry-run] [--limit N] [--max-examine N]` and `list-removable .sdlc` (= `sweep --dry-run` plus `bytes` per tree; JSON, exit 0). Ownership of liveness is shared with #464's helpers; the lever works with the opt-in off.
- No starvation: candidates are examined least-recently-examined first (`state/worktree-prune-seen.json`, `{stem: epoch}`, written under the sweep lock, pruned of stems with no record each sweep; a never-seen stem sorts first), so permanently unremovable survivors (open or closed-unmerged PR, no PR, unpushed) rotate instead of sorting ahead of a newer removable tree: every survivor is examined within ceil(N / `max_examine`) sweeps, and the REST budget is spent on trees that PASSED the local checks 1-7 (a PR read is never spent on a tree already kept locally).
- Scale and ceilings: local checks are O(candidates examined) at about four git calls each; network is at most `max_pr_reads` (8) REST reads per sweep, so a backlog drains at `limit` (3) trees per trigger and at once with `--limit 0 --max-examine 0`; a removable tree is reached within ceil(N / 20) sweeps whatever sorts ahead of it (the rotation above); the per-sweep REST cost is at most 8 reads and the per-sweep git cost at most 20 x 4 calls, paid at most every 15 minutes by the automatic path. Timings measured after implementation on the real store (dry run only) and on a 100-worktree scratch repo; the doc records what was not measured. Residual windows, named: (a) between the pre-removal re-read and git's own cleanliness check a session can start work in the tree: git refuses a dirty tree, a commit it made is on the branch ref (no deletion happens), and `work.start` re-attaches the branch, so the harm is a vanished checkout, recoverable; (b) a shell or editor of another process with its cwd inside a removed tree is not detected (check 3 covers only the sweeping process); the tree was clean and merged, so nothing is lost; (c) the record stays pointing at a missing directory until a `record done` or `work.py finish` clears it. Measured readers: `work.finish` and `pr_landing_state` fall back to the project root; `work.start` takes its documented vanished-directory path and CLEARS `pr` (so a `start` before a `record done` loses the stored PR number); `pr`, `rebase`, `commit`, `merge` use the recorded directory and raise on a swept goal (the goal is merged, so unreachable by the loop); `feature_rebase` lists it as skipped every pass and `goal_state_prune`/`liveness_prune`/`retention` treat the record as an owner, so a swept goal keeps its per-goal state until the record clears. That is the same as a survivor today; clearing it needs a reclaim-time `done` and is filed as a follow-up, not done here; (d) `--limit`-bounded sweeps from hooks leave a backlog for later triggers and the lever.
- Docs `docs/launch/b6-worktrees.md` (ownership, measured table, decision, opt-in, recovery, ceilings, not measured; no host paths), CHANGELOG entry that names no `docs/launch/` path, `docs/launch/write-surface.json` for each new write/remove site (and `finish`'s changed gate text), `--help` allowlist if the script-help test needs it, config doc line for the new key, disposition `docs/launch/dispositions/465.json` for the two patterns (and `.sdlc/state/worktree-prune/<goal>.json` / `.lock` if the scan produces them) after re-running the documented scan. No `unscanned` waiver unless a pattern is not produced by the scan.

## Test notes
Every test builds a REAL throwaway repo in tmp (bare "origin", a clone whose `.gitignore` carries Sigma's own `.sdlc/*` rule, real `git worktree add`, real commits, real `state/work/<n>.json` records as `work.start` writes them) and drives the documented CLI (`worktree_prune.py sweep|list-removable .sdlc`) with a fake `gh` executable on PATH that serves a fixture PR body (merged / open / closed / wrong head ref / failure / sleeps) for the REST URL and exits 1 on any `gh pr view` (GraphQL), so a regression to GraphQL goes red; git is never mocked. In-process deterministic seams use a `run` wrapper that delegates to real git and records every argv, including those `finish` issues: the never-force test checks the real `git worktree remove` argv and that no other mutating call is made (no `branch -D`, no `gh ... -X DELETE`, no `gh pr view`) and that the record, branch and every log row are untouched; the crash test makes a REAL partial removal (skipped loudly when the user is root, where permissions do not deny; the runner-raise variant, which needs no permission trick, carries the same assertions there: a nested directory made unwritable with `chmod a-w` so the real non-force `git worktree remove` fails midway, restored in a `finally`; a variant raises from the runner after a real half-delete to stand for the SIGKILL), asserts the journal survives the failed removal, then a second sweep with real git must finish the removal, a variant also removes the tree's `.git` file (unregistered debris), a variant leaves a foreign untracked file in it, a variant has a human-deleted tracked file in a kept tree with no journal (must stay `dirty`); the proof-to-removal test makes a real commit in the tree right after the PR read; the held-lock test holds the `flock` from a real subprocess (reaped in a `finally`) and runs the second sweep under a hard timeout, so a guard that blocks instead of skipping goes RED rather than hanging, and asserts it neither removes nor heals; the opt-in test uses a PR-bearing goal for the CLI path (it must fire) and an in-process `housekeeping=False` case for the reconcile path (it must not), each going red when its gate is wrong, and runs `loop.py record ... done` and `loop.py start` over a scratch store with the key off (nothing removed, nothing called) and on (a merged tree is removed, a broken `gh` leaves `done` intact). Controls, each broken once and seen red then restored, on the CLI gesture where one exists: dirty, hidden-changes, ignored-content, branch, toplevel, PR-merged, head-ref, is-ancestor, live-agent, live-session, current-directory, exclude, awaiting-merge, work-root, symlink, `limit`, `max-examine`, the sweep lock, the pre-removal re-read, the journal-as-hint match, the heal restore, the debris blob proof, the timeout, the opt-in gate, and a control that adds `--force` (the never-force test and the dirty-tree test both go red). Broken together where one masks another (dirty + is-ancestor on the same tree; toplevel + branch on a tree whose `.git` is gone).

The starvation test keeps 25 permanently unremovable worktrees ahead of one removable tree and drives the AUTOMATIC path (`start`, interval bypassed by clearing the stamp) with `max_examine` 20; it goes red under the old sort-by-goal order. The never-force allowed-argv list includes `git worktree prune`.

## Definition of done
Every `## Tests` node red then green on the documented gesture; controls broken once and restored; full `loop.py verify` green; `growth_audit.py` gesture on a scratch copy resolves the rows; a dry run on the real store (nothing removed) lists the three trees found removable by hand (112, 282, 317) and keeps the rest with reasons; five CI legs green.

## What the plan reviews changed
Round 3 and 4 (journal dropped on a failed removal; the sweep discarded the only merge record via `finish`; the reconcile gate was disarmed for PR-bearing goals; starvation; a restore/kill livelock; no test that readers cope with a swept record): the sweep no longer calls `finish` and keeps the record; the explicit `housekeeping` keyword; rotation by least-recently-examined with a 15-minute interval; restore at most once; reader tests and a named reader table; a follow-up for clearing swept records.

Round 1 (heal raced a live sweep; a stale journal wedged a goal; `finish(merged=True)` wrote ledger observations; a commit could land between proof and removal; ignored files were deleted unchecked; budgets and timeouts): the sweep lock, journal-as-hint, `reclaim_only` (no ledger, no branch deletion), pre-removal re-read, the ignored-file rule, caps and timeouts. Round 2 (debris proof passed against the bug via `check-ignore`; the claim lock protected nothing; `finish` deleted remote branches never proven; no opt-in; heal restored human deletions; examination unbounded; stem/path mismatch; skip-worktree; huge ignored lists): blob-hash proof and the toplevel assertion; no claim lock (replaced by the recoverable-by-construction argument); branch and remote deletion removed outright; the opt-in key; journal dropped on every normal return; `max_examine`; exact-path check; `hidden-changes`; the listing cap.
