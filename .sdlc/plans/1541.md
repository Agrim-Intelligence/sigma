- Diff: the WORKING TREE against the fork, so Implement-time edits are seen and never print a false `within`: `git --no-optional-locks -c diff.algorithm=myers -c diff.renames=true diff-index --numstat -z -M --no-textconv --no-ext-diff <fork>` (option order checked on git here; output identical to `diff`). `diff-index`, NOT `diff`, is the AC-5 guard: `git diff --numstat <fork>` rewrites `.git/index` when tracked files are stat-stale even with `--no-optional-locks` or `GIT_OPTIONAL_LOCKS=0` (reproduced by the reviewer); `diff-index` never touches the index. Counting options are pinned against user diff config (`diff.algorithm`, `diff.renames`, no textconv, no ext-diff). `--no-optional-locks` stays on every git call in `check` as belt and braces only; it is not the guard. Numstat facts (confirmed on real git output; doc states each, a test pins each): a mode-only change prints `0\t0` (a legacy row with 0 changed lines, never restructure); a deletion prints `0\tN` (counts N); a rename prints `A\tD\t\0old\0new\0`, counts once and is keyed on the OLD path (the one that existed at the fork); a submodule gitlink change prints `1\t1\t<path>`, so it counts 2 and can print a legacy row (documented, pinned in `test_check_counts_deleted_lines_and_renames_once`, which also covers the mode-only case). Changed lines = added PLUS deleted (one edited line counts 2; doc says so). Untracked files are absent from this diff and are never existing legacy files. Parse: `A\tD\tpath\0`; rename `A\tD\t\0old\0new\0` counts once, keyed on the OLD path (the one that existed). `-\t-` = binary: restructure, changed column `binary`. A path with tab/CR/LF in it = Refusal ONLY when that path would print a row; a new non-legacy file with an odd name never refuses the run. Only paths whose `_newness` is `existing` and `_match` is `legacy` get a row.
- Rows (literal): `<path>\tlegacy\t<changed|binary>\t<restructure|->\t<intent: yes|intent: no|intent: unknown>`, e.g. `src/a.py\tlegacy\t41\trestructure\tintent: no`; the fifth column carries the `intent: ` prefix. Verdict line `verdict: over`.
- Intent: record read with `acceptance.read`; FileNotFoundError, ValueError or `drafted is None` = `unknown`; `drafted is True` = `no`; `drafted is False` = `yes` iff some criterion has a backticked, whitespace-free span T (strip leading `./` and one trailing `/`; skip empty, `.`, absolute, any `..` component, any of `*?[`) with file == T or file startswith T + `/`; else `no`. Documented gaps (docs/change-zones.md, each pinned by a test): negation is not parsed, so a criterion like `` `src/legacy/a.py` stays unchanged `` grants `intent: yes`; spans containing whitespace never match (a file with spaces gets intent only through its directory); a suffix such as `:12` or `::test` makes a span never match (fails toward over); matching is case-sensitive; `drafted: false` is the recorder's own claim, not proof.
- Verdict (diff): `over` if any row has restructure and intent `no`; else `unknown` if any legacy-existing row has intent `unknown` or any state is unknown; else `within`. Restructure with intent `yes` is within. No legacy-existing file touched is `within` even with no record (intent is irrelevant; documented and tested).
- Plan: read at most 256 KiB (unreadable/missing/oversize = Refusal). Paths = backtick spans without whitespace inside the section whose heading matches `^##\s+(Files|File structure)\b` (to the next `## `), each through `_normalise(span, top, top)` (Refusal skipped), de-duplicated, blobs only (`_blobs`: one batched `cat-file --batch-check` of `<fork>:<path>`, type `blob`, so directories drop out). NEW/EDIT words ignored. Rows: `<path>\tlegacy\t-\t-\tintent: <yes|no|unknown>`. A plan naming an existing legacy file without intent reads `over` even for a one-line seam edit (literal PRD reading; the doc says so); a plan with no `## Files` section reads `unknown`. Verdict: no section or zero recognised paths = `unknown`; else `over` if a named existing legacy file has intent `no`; else `unknown` if any has intent `unknown`; else `within`.
- Output: rows, then `verdict: over|within|unknown`; exit 0 for all three; bad arguments, bad config, outside checkout = exit 2, empty stdout.
- Scale: one `merge-base`, one `diff --numstat`, one `cat-file --batch-check` per run (constant processes); linear in changed files; 10x/100x changes only output and parse time. Ceilings: `GIT_TIMEOUT` 10 s (timeout = unknown), plan 256 KiB, acceptance 32 KiB. Cost on this repo is measured in step 13; nothing above ~1.5k changed files is claimed.
- Resiliency: nothing stored, nothing to recover; every git failure is `unknown`, never `within`.
