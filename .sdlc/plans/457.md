# Plan: #457 — bounded prune of closed-goal action-log and witness streams

Inputs: issue #457, `.sdlc/research/457.md`, `.sdlc/acceptance/457.md`. Worktree `.sdlc/work/457`.

## Design
- New module `skills/agrim-loop/scripts/retention.py`: `prune_closed_goal_streams(sdlc_dir, keep_days=None, now=None, dry_run=False, limit=200) -> {"removed": [...], "kept": {reason: n}}`.
- Candidate rule (ALL must hold, else kept with a reason): safe goal stem; `state/log/<stem>.jsonl` exists, regular, not a symlink, and `state/log` / `state/witness` are not symlinks; the log's newest row among `actionlog.INTERNAL_KINDS` is `recorded` with `result == "done"`; the log AND the witness file (if any) have mtime AND last-row `ts` older than the cutoff; no live owner: `state/claims/<stem>.claimed`, `state/agents/<stem>/`, `state/work/<stem>.json`, `state/phase/<stem>.json`, worktree dir `.sdlc/work/<stem>`. `.lock` claim leftovers are not markers (short-lived mutexes, never cleaned).
- Order: witness first, then log. The log is the proof of closure, so a crash between the two leaves a still-eligible log; the next sweep finishes. Re-check mtime, size and markers immediately before each unlink; unlink only (`missing_ok`), never rmtree, never anything but these two direct children.
- Window: config `action_log.retention_days` (int, floored at 30, default 90); `false` disables. Bounded per sweep by `limit` (default 200, oldest first) so a first run on a large backlog is polite. No stamp file, no mkdir, never raises.
- Triggers (host-agnostic, Sigma Python only): `loop.py _record` after a `done` outcome (fail-open, next to the review-copy prune); operator lever `loop.py prune-state <sdlc> [--dry-run] [--keep-days N] [--limit N]` prints removed/kept counts.
- Recovery: crash mid-sweep -> witness removed, log kept, next sweep completes; restore-from-backup -> restored files have fresh mtime so they wait out the window, then are re-pruned; a writer appending after the final check recreates a fresh file (history of an already-merged goal only); a reopened goal appends `claimed`, which makes it ineligible. No process pausing, no human.
- Scale: per sweep one `iterdir` + stat per file, content read only for files already past the cutoff (bounded by `limit`). 100x = 8,500 stats. Live per-goal witness growth is not bounded while the goal is live (max 159 KB observed): ceiling, documented.
- Docs: `docs/launch/b6-action-log-witness.md` (measurements with commands, ownership, decision, recovery, ceilings, lever); correct the two "never pruned" comments in `doctor.py` and `timing_store.py`; `docs/launch/dispositions/457.json` with the 7 patterns; run the documented gesture from `docs/launch/growth-audit.md` to a scratch copy and show rows resolved.
