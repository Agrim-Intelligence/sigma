## What is and is not measured (stated up front)

- **No real `claude` run is made, ever, by this plan.** The launcher README says no `claude -p` has run through it; that stays true. Every run-path test uses a FAKE launcher script and a FAKE `claude` script in a temp dir. What the tests prove: our argv/env/ordering/ledger/row behaviour against fakes. What they do NOT prove: that the real launcher + real `claude` + real subscription token work together, that a real exit 97 arrives as modelled, or what a real run costs. First real use may surface launcher defects (README TD-3), which become separate launcher goals.
- **Windows is unmeasured** until the `windows.yml` step is dispatched (manual `workflow_dispatch`). The step text is pinned and its failure mode is shown locally; the green leg on a real Windows runner is a post-merge action (PR body must say so; AC-7's Windows leg stays "pending dispatch").
- **Dollar figures from a subscription are indicative** (`meter.COST_BASIS`), never a bill. Ledger arithmetic is exact (Decimal); the meter's inputs are not.
- **No performance claim** is made. Per run: one `reserve` + one `settle` (measured ~4 ms each by #886, not re-measured here) and one launcher `--dry-run` (bounded 60 s by `VERSION_TIMEOUT_SECONDS`; real duration unmeasured). Ceiling: ONE run at a time per machine (ledger lock, single latch); stated in README.
- Residuals carried unchanged: per-machine ledger (lost hosted runner forgets the belt; job-level reservation is #819); `/proc/<pid>/environ` readability of the credential by the agent's subprocesses (launcher README); hosted-runner satisfaction of launcher preconditions (no workflow until #819).
