## Design (revised after plan-review round 1)
Handler: `release_single_instance(sdlc_dir)` (ownership-checked, idempotent), THEN restore SIG_DFL, THEN
`os.kill` self with the same signal (death-by-signal). Release first so a second signal mid-release
re-enters an idempotent handler instead of killing half-cleaned.
- Installed BEFORE `acquire_single_instance`, uninstalled on every exit path (nested finally so a restore
  failure cannot skip release). Residual (documented): span between `os.mkdir` and the heartbeat write.
- Ownership: pidfile pid == ours, OR pidfile absent and heartbeat pid == ours (acquire writes heartbeat
  before pidfile, #2751). A foreign heartbeat/pidfile is never touched.
- SIGTERM/SIGHUP via `getattr(signal, name, None)`; an already-ignored signal stays ignored (nohup).
- Main thread only; otherwise a no-op uninstall. Previous handler `None` restores SIG_DFL, guarded.
- No atexit (run()'s finally covers unwinding exits; per-call registration leaks in-process). SIGINT untouched.
- Hung main thread in C: SIGKILL stays the lever; heartbeat age exposes it. Documented in the docstring.
- `release_single_instance` docstring and watch_daemon `_install_cleanup` docstring corrected; TM-09 updated.

## Round-2 plan-review refinements (incorporated)
- A `_DYING` flag set by the handler stops a request thread recreating the heartbeat before death; cleared
  by uninstall. The `finally` path keeps the same race as a stated residual.
- Heartbeat-ownership fallback requires a FRESH heartbeat (a stale own heartbeat with no pidfile belongs to
  a successor mid-reclaim).
- Handler always ends with `os._exit(128+signum)` after `os.kill`; docstring states POSIX-only effect.
- Successor control rewrites pidfile AND heartbeat to the successor; bare-SIGHUP breakage is caught only by
  the seam control that removes SIGHUP from `signal`; only the real-subprocess controls are red on unfixed
  code by behaviour (seams are red by AttributeError there).
