# #1047 plan: smoke runner wall-time ceiling from three measured CI runs

## Goal / done_when
The runner prints `smoke wall: N.NNs, ceiling M.MMs` on every run, exits 1 with a named finding when N exceeds the ceiling in `evals/skills/budget.json`, the number is visible in the CI job log, and the committed ceiling is derived from three real CI job logs (cited in the PR and budget.json).

## Files
- edit `evals/skills/smoke.py`: `--budget` (default `evals/skills/budget.json`); read `ceiling_seconds` (null/absent = unset); print the wall line; breach = FINDING. Malformed budget = FINDING, not traceback.
- new `evals/skills/budget.json`: `{"ceiling_seconds": null, "measured": []}` first; then the derived ceiling plus the three runs.
- edit `.github/workflows/ci.yml`: one step `python3 evals/skills/smoke.py` (own step so its output is in the log, unaffected by `-q`), placed before pytest.
- edit `tests/test_skill_smoke.py` (new tests), `evals/README.md` (replace "Not measured: ..." sentence), `CHANGELOG.md`.
- not edited: `.sdlc/config.json`, any card.

## Design
- Mechanism that surfaces the number: dedicated CI step prints the runner's own line (D-10 option a). The loaded case (xdist) is covered by the wrapper's bare-gesture subprocess asserting the same ceiling.
- Ceiling = max of three distinct-commit CI walls (never an average) x headroom factor, rounded up, with a floor of 1.0s (below that is timer noise on a shared runner). Cancelled runs are re-triggered. Not a guess: every input is a printed number.
- Headroom factor comes from the local loaded/unloaded ratio (12 busy loops: 0.15-0.17s vs 0.10-0.13s unloaded, ratio about 1.4), labelled local; both inputs are printed in budget.json.
- budget.json states scope: macOS-latest 3.12 PR leg only (the `full` job's other legs have no standalone step).
- Time source `time.monotonic()` around check() only (README says so). Down-only: ceiling edits are reviewed in PR.
- Step runs before pytest so an earlier failure cannot hide the line.
- The three runs predate the ceiling commit; that is the only possible order, so each is cited by job-log id.

## Steps (test-first)
1. Tests: wall line printed; breach exits 1 naming `wall`; unset ceiling prints `ceiling unset` and passes; malformed budget is a finding; budget file shipped and parseable.
2. Implement; green.
3. CI step, README, CHANGELOG. Controls. Verify, PR with ceiling unset.
4. Three CI runs of the PR -> read lines -> commit ceiling -> push. After this, `test_shipped_budget_is_parseable` asserts a numeric ceiling and 3 non-empty `measured` entries.

## Controls (documented gesture `python3 evals/skills/smoke.py`)
- Set `ceiling_seconds` to 0.001 in budget.json -> bare gesture exit 1 naming wall time; restore.
- Remove the breach comparison -> new breach test red; restore.

## Scalability / resiliency / safety
Single-process, sequential, O(skills + scripts); no chokepoint. A CI-runner slowdown turns the check red (the point); recovery = a reviewed edit of budget.json from fresh logs. Runner stays read-only; budget file read only.

## Definition of done
Mechanism shipped; three CI lines cited; ceiling committed and derived; controls seen red; verify green.
