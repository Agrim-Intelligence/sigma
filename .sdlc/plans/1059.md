## Design (revised after plan-review FIX-FIRST)
- matrix.json: `{"rows":[{"row":"<catalogue id>","gate":"<gate id>","status":"red|pending","run_id":"","date":"YYYY-MM-DD","commit":"<40 hex>","pin":"<16 hex>"}]}`. One entry per catalogue (row, gate) pair. `pin` = first 16 hex of sha256 of the canonical JSON of [row.regression, row.form, row.mutation, gate.argv] at record time. `pending` entries carry no run_id/date/commit/pin and are legal only while gates.json says the gate is pending.
- matrix.py `check [--root DIR] [--skip-objects]`, reads DIR/evals/regression/{catalogue,gates,matrix}.json; stderr `matrix.py: <kind>: <detail>`; exit 0 clean, 1 problems, 2 unreadable or an empty catalogue. Kinds: `missing-row` (catalogue pair with no entry), `no-evidence` (red entry lacking run_id/date/commit/pin), `bad-commit` (not `re.fullmatch([0-9a-f]{40})`, or `git cat-file -e sha^{commit}` fails), `row-absent-at-commit` (`git show sha:evals/regression/catalogue.json` lacks the row, or `gates.json` lacks the gate), `stale-evidence` (pin differs from the current row/gate), `bad-date`, `bad-status`, `duplicate-entry`, `unknown-pair` (entry not in the catalogue), `stale-pending` (pending entry for a live gate), `red-on-pending` (red entry for a now-pending gate), `pending-with-evidence`. git runs with GIT_* stripped (control.py's `archive` and `rev-parse` too). In a shallow clone (`git rev-parse --is-shallow-repository`) an absent object is NOT a pass: it prints `matrix.py: note: shallow clone, commit existence not verified for N entries` on stdout and still exits per the other checks; a full clone enforces it. `--skip-objects` skips only the object-store checks (bad-commit existence and row-absent-at-commit) and prints a note; format is still enforced.
- control.py `--record [--matrix PATH] [--run-id ID]`: collect `(row, gate, verdict)` in `_control`; after the loop, only when the baseline passed, merge into the matrix (default this script's own `evals/regression/matrix.json`, never `--repo`): red -> evidence with run_id (`<UTC stamp>-<6 hex>` or `--run-id`), UTC date, full `git rev-parse HEAD` of `--repo`, pin; stays-green, vacuous, broken and timeout -> entry removed; MUTATOR-FAIL -> live-gate entries removed, pending gates keep pending entries (stale evidence never survives); pending gate -> pending entry; entries whose pair is not in the tested catalogue are pruned; unselected pairs keep their entries. Written by a named helper `_write_matrix` through `record.write_atomic` (temp file + `os.replace`, temp unlinked in `finally`). Without `--record` nothing is written. Exit codes unchanged; a run that exits nonzero still records the reds it saw (README says a matrix with a missing entry fails `check`).
- Squash merges: the recorded commit must outlive the PR, so the documented gesture records against `origin/main`: `python3 evals/regression/control.py run --record --repo <detached worktree of origin/main> --matrix evals/regression/matrix.json`. The default (no `--repo`) records this tree's HEAD, which a squash merge drops from main; the README says so, and says to re-record on main.
- Ceilings named in the README: concurrent `--record` is last-writer-wins (run it serially); a SIGKILL can leave `matrix.json.tmp.<pid>` (added to .gitignore); a hand-edited row is indistinguishable from a recorded one except by `check`'s pin and commit tests, so a record is a claim, not proof; the control on CI is the live check but no workflow runs it yet (slice 5, #1052 area) so today it is operator-run. Windows: control tests are POSIX; confirm the windows workflow does not collect them.

## Refinements from plan-review round 2 (SOUND-WITH-REFINEMENTS), all taken
- `--matrix` defaults to this script's own tree (never `--repo`); the origin/main gesture passes it explicitly. Deviation from acceptance stated in the PR: the committed evidence is recorded against `origin/main` (not this branch's HEAD) because a squash merge drops branch commits; valid only because this PR changes neither `catalogue.json`, `gates.json` nor any gate target.
- `pin` hashes `[row.regression, row.form, row.mutation, gate.argv]`; README: it detects re-pointing, not drift in mutator or test content.
- MUTATOR-FAIL removes the live-gate entries of that row; its pending gates still get pending entries.
- `GIT_*` is stripped for every git call in control.py (`archive`, `rev-parse`) and matrix.py.
- No new DOCUMENTED_WRITES row: `record.write_atomic` called from control.py is not a labelled site. The four `record.py::write_atomic` reasons and the write-surface purpose text are edited to name `matrix.json` and `control.py --record` as a second caller; counts unchanged.
- `test_committed_matrix_passes_on_this_tree` skips only the object-store checks (`--skip-objects`), because CI checkouts are shallow and the recorded commit is an ancestor; commit existence is covered by the fixture tests and by running `matrix.py check` on a full clone. Shallow clone and `--skip-objects` print "unverified" and are not described as a pass.
- A later PR that adds a catalogue row records that row's evidence on its own head before merge; after a squash that commit is gone, so the owner re-records on main (README). `run_id` is free-form non-empty. `matrix.json.tmp.*` goes in `.gitignore`.

## Controls
Break matrix.py once per check (accept any commit; skip missing-row; skip no-evidence) and see its test red. Run `python3 evals/regression/matrix.py check --root <copy with real git history>` as the README documents: fake commit exits 1, the same copy with a real sha exits 0.

## Ceilings / recovery
Check is O(rows) with one git call per distinct commit. A crash mid-record leaves only `matrix.json.tmp.<pid>` (unlinked in `finally`); matrix.json is never half-written. A stale matrix is caught by `check`, re-run `--record` to refresh.
