## Design
- Format: `docs/launch/dispositions/<slice>.json`, a JSON array of objects with EXACTLY the keys
  `pattern`, `issue` (`#<digits>`), `decision`, `pruner_or_cap`, `evidence` (all non-empty strings),
  plus the OPTIONAL key `unscanned` (boolean `true` only).
- `load_dispositions(repository, rows)` returns `{pattern: entry}`. It REFUSES (raises `DispositionError`)
  on: unreadable/invalid JSON, duplicate JSON object keys, non-array top level, non-object entry,
  missing/extra/non-string/empty field, bad `issue`, `unscanned` that is not `true`, a pattern repeated
  within or across files, and a pattern the scan does not produce unless the entry says `unscanned: true`.
  Why the escape hatch exists (measured): the former hard-coded review-copy pattern
  `.sdlc/evidence/<goal>/rv*/wt` is NOT produced by a scan of current origin/main (its writer is outside
  Sigma's Python and skill prose, and the one prose row that once parented it has since gone), so a
  strict check would refuse the migrated entry and the documented gesture. `unscanned: true` is for a
  source-proven store whose writer the scan cannot see; the entry's `evidence` names that writer. It
  resolves a row only if the scan produces that pattern. No directory = no dispositions.
- `b6_disposition(rows, issue, dispositions=None)` and `store_measurements(repo, rows, issue,
  dispositions=None)` use the dict instead of the constant; a resolved row takes the entry's
  `pruner_or_cap` and `decision`. The constant is deleted.
- `main` loads and validates BEFORE writing anything, always (not only with `--b6-issue`); on refusal
  prints `growth_audit.py: REFUSED: <why>` to stderr, exits 2, writes no `--json` file.
- `docs/launch/dispositions/review-copy.json` holds the former constant: pruner "terminal review-copy
  lifecycle prune", decision "source-proven prune".
- `docs/launch/growth-audit.md`: format, refusal list, known-pattern rule, and the control gesture.
- Committed `growth-audit.json` is NOT regenerated; the gesture is run to a scratch file and compared.
- Scale: validation is O(files + entries) over a handful of small files; no new unbounded growth.
- Existing tests in `tests/test_readiness_growth_audit.py` that relied on the constant pass the
  committed review-copy disposition explicitly. Real-repo `unresolved_patterns` is unchanged by the
  migration (the scan does not produce that pattern).

## Test notes

The file name and test ids are deliberately short: pytest's non-tty summary line drops the
`AssertionError` reason when the node id is long, and `red_green.py` only credits a red it can read there.
The file drives the exact gesture copied out of `docs/launch/growth-audit.md` (parsed from the doc,
script path substituted, cwd = a scratch repo) and asserts: review-copy file exists in the committed
format and the row output is unchanged; a valid disposition resolves a produced pattern in both
outputs; unknown / duplicate (cross-file) / malformed (parametrized) files exit non-zero and leave
`--json` byte-identical to its prior content; an `unscanned: true` entry for an unproduced pattern is accepted while the same entry without the
flag is refused, and a non-`true` flag is refused; unknown/typo/host patterns and duplicate JSON keys
are refused; validation also runs without `--b6-issue`; no dispositions dir leaves
every pattern unresolved. Every node asserts new behaviour, so each is red on the old constant.
Known weakness, documented in growth-audit.md: `unscanned: true` bypasses the unknown-pattern guard for
that one entry; reviewers of a sibling slice must check its `evidence`.

## Definition of done
Every `## Tests` node red by assertion on old code then green; full verify green; control broken once
(guard deleted -> unknown-pattern test red) and restored; regeneration to scratch has identical
`rows` and unresolved/store shape to the committed snapshot modulo drift since 64709b3.
