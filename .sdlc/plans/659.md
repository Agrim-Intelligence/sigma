## Format spec (the contract the code and docs share)
- Section `## Functional requirements` placed immediately after `## Premise check`, before `## Queries run`.
- Bullet regex `^- \*\*FR-(\d+)\.\*\* (.+)$`; empty form is one bullet `- None.`
- Ids: integers >= 1, strictly increasing in document order, unique; gaps allowed (never renumbered), `FR-0` / non-integer refused (D3).
- Sentence must match the shared `EARS` pattern only; TAGGED/VAGUE do not qualify (D2).
- Slice table under `## Slice-count estimate`: `| Slice | Covers | Requirements | Depends on |`, parsed BY HEADER NAME (case-insensitive), cells split on commas and stripped; `—` means none (D6).
- Only section bodies between `## ` headings are parsed; the slice table is read only from the Slice-count estimate section.
- Violations (each named with its FR id or cell): (a) FR in no slice row; (b) Requirements token that is not a declared FR; (c) `- None.` section with any non-`—` Requirements cell (D7); (d) FR present but Requirements column missing; (e) `## Functional requirements` heading missing (pre-#659 artifacts count as violations; they are not re-reviewed, issue forbids rewriting them); (f) non-EARS sentence; (g) bad/duplicate/non-increasing id; (h) section body line that is neither an FR bullet nor `- None.`.
- Safety bounds: read cap 1 MiB (over cap: refuse, exit 2, loud); sentence length cap 2000 chars checked BEFORE regex (refuse over cap) so the regex never sees unbounded input; a warning (not refusal) at more than 50 FRs as a decomposition hint (my number, unmeasured threshold).
