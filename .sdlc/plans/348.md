## Revision after independent plan review (supersedes ambiguous earlier steps)

### Deterministic common contract

The new tool reuses the stateful fake `gh` from
`tests/test_public_bootstrap_control.py` through the existing AST extractor. All
remotes, state, process groups, and copies live below a new empty `--workdir`.
The result schema includes `schema`, `drill`, `seed`, `platform`,
`frozen_commit` (40 lower-case hexadecimal characters), `started_at_ns`,
`finished_at_ns`, `recovery_commands`, `fault`, `fake_gh_unhandled`, and
per-invariant `{name, passed, observed}` records. A platform skip is explicit
and never recorded as a pass.

The evidence generator resolves the full `HEAD` SHA once before execution, runs
from that precise checkout, emits the full SHA in the body, names the artifact
`drills-<sha12>.json`, and refuses a mismatch among filename prefix, body SHA,
or checkout SHA. It records commands, interpreter, platform, and all 20 drill
outcomes, and writes atomically. A post-evidence code change requires new
evidence generated at the new frozen commit.

### D1: merge window is barrier-driven, not race-driven

The child enters a fresh process group using `start_new_session=True`; before
any signal the driver asserts that child PID and PGID differ from the driver
group. A test-only parent/child barrier pauses the child immediately before the
merge continuation and records `merge_entered_at_ns`. Only after receiving that
barrier does the parent record `kill_requested_at_ns`, send SIGKILL solely to
the child's PGID, and record `kill_sent_at_ns`. The seed selects only a bounded,
recorded `random.Random(seed)` delay after the barrier; it never decides whether
the signal reaches the merge seam. The result asserts
`entered <= requested <= sent <= recovery_started`, captures PID/PGID, status,
and duration, and proves no child remains before cleanup.

Recovery is exactly `loop.py next <dir>` followed by
`loop.py reconcile-merges <dir>`. It proves one PR (open or merged), closed
issue iff merged PR, no orphaned in-progress claim beyond the configured TTL, and
a worktree that is either resumable or absent, never half-removed.

### D2: restored state converges with external truth

Take the state snapshot only after a durable claim/work record and before fake
merge. Record the external PR number/state, issue state, project state, labels,
and remote ref before restoring the snapshot. After restoring it, run the same
`next` then `reconcile-merges` gestures. Assert all of these individually:
(1) `next` does not return the restored goal; (2) done has exactly one terminal
action-log entry and completion transition; (3) exactly one PR is open or merged;
(4) issue closed iff that PR is merged; (5) external project/labels/PR/issue and
local work record/completion cursor agree; (6) no already-done goal is
re-executed; and (7) worktree terminal shape is resumable-or-removed only.
A local retry that merely masks stale state fails the convergence control.

### D3 control

D3 kills after fake `gh pr merge` has succeeded but before local terminal
recording. Two documented `reconcile-merges` passes must yield one landing and
one terminal record. The preserved scratch-only no-op mutation remains the red
evidence; it makes `recorded_done` false under the same documented gesture.

### D4: capture actual diagnostic behaviour and handle B6 without duplicates

D4 creates `state/watch.stop` in a fresh scratch repo, starts the real daemon,
and waits for its actual `stop-file present` exit. It then runs the real doctor
and `hooks/session_start.sh` gestures against that same tree, preserving the
stop file. The result records each command's exit code, stdout, stderr, and
whether it specifically diagnoses stopped, dead/stale, idle/on, or gives no
watcher diagnosis. It must not assume the desired stopped-by-stop-file text:
doctor's current watcher row is heartbeat based and the session-start accelerator
mirrors that math. It also records the exact documented removal-lever path/line.

For every failed invariant, form a seed-specific factual finding, save it, run
`python3 skills/agrim-scope/scripts/dedup.py .sdlc @<finding-file>`, and retain
the entire returned pack in result JSON. Normal tests and ordinary drill runs
never file issues. The explicit evidence-generation command can create exactly
one new issue only when `candidates` is empty; it must carry `readiness`,
`launch:blocker`, and class `B6`. A returned candidate produces no new issue
and records the candidate ref. Finding prose must respect the issue-body
dependency-word restriction.

## Second plan-review correction: exact fault seams and D4 red outcome

This addendum supersedes D1/D2/D4 wording above wherever more specific.

### D1 checkpoint injection

The fixture must instrument the actual fake `gh pr merge` path, not a generic
pre-merge pause. It exposes three named, causally ordered checkpoints:
`pre_write` immediately before the fake updates the remote; `durable_remote_update`
after that remote update succeeds and before the fake emits its successful merge
response; and `post_response_before_ack` after the successful fake response is
available to the caller but before the local acknowledgement/terminal record.
Checkpoint selection is a fixed, recorded mapping for the mandatory evidence
seeds, not unconstrained random sampling:
`{1: pre_write, 2: durable_remote_update, 3: post_response_before_ack,
4: pre_write, 5: durable_remote_update}`. The tool rejects a seed outside its
documented mapping unless a future explicit mapping entry is added. It records
the mapping version, selected checkpoint, all checkpoint timestamps, and fake PR
state. This guarantees that seeds 1--5 cover all three actual merge-path seams,
including `durable_remote_update`.

The child signals the selected checkpoint only after entering it. The parent then
records request/signal monotonic timestamps and SIGKILLs only the fresh child
process group. The result must prove the selected checkpoint was reached, the
signal was delivered while that checkpoint remained blocked, and no later
checkpoint executed before recovery. Thus a seed selecting
`durable_remote_update` proves a real landed remote update with no response/ack;
a seed selecting `post_response_before_ack` proves a successful response without
local acknowledgement. A generic paused pre-merge control is insufficient and is
not a passing D1 result. The focused evidence test reads all five D1 result
objects and asserts both the exact mapping and checkpoint set equality:
`{pre_write, durable_remote_update, post_response_before_ack}`. Evidence
generation refuses a D1 five-seed file that lacks any member of that set.

### D2 stale-overlay removal before pick

After restoring the pre-merge local state but before calling `loop.py next`, D2
must remove `sdlc:in-progress` **from the fake GitHub issue only**, record the
pre/post label sets, and assert that the local awaiting-merge/completion guards
rather than the external occupancy overlay prevent re-pick. It then calls the
documented `next` gesture and proves it does not return the restored goal before
running `reconcile-merges`. The prior convergence checks remain required after
this deliberately lost-overlay case.

### D4 reporting is a deliberate red control today

D4 has two distinct reporting invariants, one for `/agrim-doctor` and one for
the session-start gesture. Each must require an explicit stop-file diagnosis,
distinct from dead/stale and idle/on, while the stop file persists. Current code
is expected to fail both because the doctor watcher row and session-start
accelerator are heartbeat-based rather than stop-file-aware. That failure is a
correct D4 measured outcome, not a passed diagnostic check.

For each failed D4 reporting invariant, persist command, exit code, stdout,
stderr, stop-file existence, and the exact invariant result; write a
seed-specific factual finding; run dedup first; and record the entire pack. The
explicit evidence-generation path then follows the B6 rule: no candidate permits
one `readiness` + `launch:blocker` B6 filing, while any candidate suppresses a
duplicate filing and records its reference. The evidence must distinguish
`control_failed_and_recorded` from `reporting_invariant_passed`; it cannot
count the expected current failure as diagnostic success.
