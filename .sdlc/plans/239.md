# #239 Plan — upgrade path from the retired brand: read fallbacks + one-shot migrate

Goal: a repo adopted by the retired plugin (any 1.4.x) installs Sigma and continues its loop with
no data loss. `<R>` = retired lowercase brand, `<R_>` = its env prefix (never spelled whole in a
shipped file — `tests/test_no_private_names.py`; spell from fragments like `doctor._RETIRED_BRAND`).

## Decisions (recorded; nobody available to ask)

- D1 ONE helper, `skills/sigma-loop/scripts/legacy.py`, library-only (no `__main__`; added to
  `test_script_help.LIBRARY_ONLY`). Every reader calls it; no per-caller copies. doctor's existing
  `_legacy_env_names_in_config` delegates to it.
- D2 Env precedence: a name is "set" when present AND non-empty (the `${X:-}` / `get(X) or` idiom
  every current reader already uses). `SIGMA_X` set → it wins; else `<R_>X` if set; else default.
  Config values that NAME an env var (`*_env`) resolve through the same helper in both directions
  (a config still naming `<R_>X` prefers `SIGMA_X` when that is set). Values are never logged.
- D3 Schema ids: `<R>/<kind>@<n>` reads as `sigma/<kind>@<n>` for exactly the four kinds Sigma knows
  (features, landing, withheld, propagation); version must still match — a legacy `@2` is refused
  exactly as a Sigma `@2` is. Writes always use the Sigma id (migrate-by-use; one-way, as the issue
  already notes for 1.4.24).
- D4 Markers: file markers (feature-doc managed block, AGENTS.md Codex block) are recognised in
  either spelling; a mixed pair (legacy begin + Sigma end) or both families present is GARBLED /
  malformed — refuse, never guess. GitHub-side markers (approve/block/unblock, keep-parked,
  dismissed-finding, decompose-of/decomposed-from/decompose-filed, design-of/design-filed,
  unpark-qa block, feature flag markers, scope/ownership watermarks) are recognised in either
  spelling at every reader via `legacy.has_marker` / `legacy.find_marker` /
  `legacy.MARKER_PREFIX_RE`. Rationale: a legacy `block` comment on an in-flight PR not being
  seen is a SAFETY break (merge of a blocked PR); `keep-parked` is a human decision.
  Writers keep writing Sigma spellings only.
- D5 Config key `drift_watch.channels.<R>` is read as a fallback for `channels.sigma` (sigma wins).
- D6 Migrate lives at `skills/sigma-doctor/scripts/migrate.py` (beside `board_migrate.py`, the
  existing human-invoked one-shot migration; no new skill → no catalog-count churn). Documented in
  sigma-doctor SKILL.md, README, `docs/upgrading.md`, CHANGELOG `## Unreleased`.
- D7 Migrate is byte-preserving: it swaps exact tokens in place (CRLF, key order, comments kept) and
  VERIFIES each result by re-parsing (JSON equal modulo the intended change; feature doc INTACT with
  identical body and digest; Codex block content identical). Any mismatch, ambiguity, unknown legacy
  schema, duplicate token or mixed markers → that file is REFUSED (untouched, listed, exit 2).
  Each write is atomic (temp in same dir + `os.replace`, mode kept) and guarded by a re-read: bytes
  changed since planning → refused ("changed underneath; rerun").
- D8 NOT migrated, reported as "left as is": ledger entries (append-only shared history), timing
  sessions (historical skill labels), prose, the legacy journal config block (enabling the journal
  is an opt-in; D24 said never alias it). Env vars are listed by NAME only.
- D9 "Never writes to a path the legacy plugin still owns without saying so": migrate always states
  that every file it changes is one the retired plugin reads, that committed ones reach teammates
  via git, and, if the retired plugin is found installed on this machine (read-only probe of
  `~/.claude/plugins/marketplaces/<R>` and `installed_plugins.json`), says so by path.
- D10 Scan scope: every `*.json` under the SDLC dir except `work/` (worktrees) and any dir holding a
  `.git`; top-level `schema` only. `features/*.md`; repo-root `AGENTS.md`; `config.json`.
  Cost: one read+parse per JSON file, linear; the real-adopted-repo copy = 8.8k files / 57 MB (measured runtime
  recorded in evidence). At 100x, linear; no lock is held, nothing runs in the background.
- D11 Exit codes: 0 = nothing to do / plan printed / applied; 2 = any refusal or bad usage.
