# Plan: #1210 ledger publish retries a stranded commit, not only a newly staged one

Inputs: issue #1210 and `.sdlc/research/1210.md`. Worktree `.sdlc/work/1210`, branch `sdlc/1210`, cut from
origin/main at 57d810a. This is revision 3, after two plan-review rounds (FIX-FIRST, then FIX-FIRST on one test setup). Its
changes are listed under "Revision 2" and "Revision 3" at the end.

## Goal

After a ledger push fails, the next `sync.publish()` call (the watcher's next tick) pushes the stranded
commit, even when no new entry was written in between. Two things must not happen:

- An idle clone with nothing to push must not push. That covers both a clone that is caught up and a clone
  whose remote-tracking ref can never exist (no remote configured, or a path/URL remote).
- `publish()` must not raise on any git failure in staging; it returns a status string instead.

## Design

**1. `skills/sigma-loop/scripts/sync.py`: a new helper `_stranded`, and `publish()` (ledger) reshaped like the
knowledge channel.**

```python
def _stranded(git, path, rem, name):
    """True when HEAD holds commits a push should still carry although this call committed nothing:
    ahead of `<rem>/<name>`, or -- with no such ref -- `rem` is a configured remote NAME, so the ref is
    absent only because no fetch or push of the branch has succeeded yet (a first push that failed).
    For a remote that is not configured, or a URL/path value, the ref can never exist: #1142's
    `_record_push` cannot write it, so "absent" carries no information there, and reading it as
    "push" would push on every tick forever (plan review #1210 B1). Never raises."""
    ahead = _ahead(git, path, rem, name)
    if ahead is not None:
        return ahead > 0
    try:
        return rem in git(path, ["remote"]).split()
    except Exception:                            # noqa: BLE001 - cannot tell: no new network write
        return False
```

`publish()` body, ledger branch:

```python
    path, name, rem = worktree(sdlc_dir), branch(config), remote(config)
    if not is_worktree(sdlc_dir):
        return "not a worktree — ..."                       # unchanged
    try:
        who = ledger.actor(config)
        mine = _staged_paths(path, ledger.ENTRIES, who)
        if not mine:
            return "nothing to publish"
        # (#2574 comment unchanged)
        to_stage = list(mine)
        if _ensure_gitattributes(path):
            to_stage.append(".gitattributes")
        _write_team(sdlc_dir, path)
        to_stage.append("TEAM.md")
        git(path, ["add", *to_stage])
        if git(path, ["diff", "--cached", "--name-only"]):
            git(path, ["commit", "-m", f"ledger: {who}"])   # a new commit: pushed as before
        elif not _stranded(git, path, rem, name):
            return "nothing to publish"
    except Exception as exc:                     # noqa: BLE001 - "always returns a status string,
        return f"publish deferred: {exc}"        # never raises" (#2449), staging included (#1210)
    # regenerate_team and _push_with_retry unchanged
```

- **A commit made by this call is pushed exactly as today.** The new rule only governs calls that staged
  nothing, so no existing path (bootstrap, a new entry, a no-remote first commit) changes outcome.
- **The `_stranded` clauses:** `ahead > 0` → push; `ahead == 0` → nothing to publish; ref absent + named
  remote → push; ref absent + not a named remote → nothing to publish (today's answer).
- **Unchanged: `not mine` → "nothing to publish".** A clone that owns no entries file has no publish commit
  of its own to strand. Its only possible local commit is `init`'s scaffold, and pushing that is `bootstrap`'s
  job, not a tick's. It now sits inside the `try`.
- **Widened `try`, tested on its own.**
  - Before the change, `ledger.actor`, `_staged_paths`, `_ensure_gitattributes`, `_write_team`, `git add` and
    `git diff --cached` could all raise out of `publish()`. Measured: `RAISED: RuntimeError git add: fatal:
    Unable to create '.../index.lock'`. After the change they return `publish deferred: <exc>`.
  - The `sync.py publish` exit code for that case goes from 1 to 0 with the deferral printed, which matches
    #2449's commit path. The plan review checked the callers and found that nothing reads that exit code or
    expects a raise:
    - `watch_daemon.run_call` uses "log" mode and ignores the exit code.
    - `publish_after_write`, `_ensure_ledger_delivery` and `slack_commands_listen.py` (lines 983 and 1015)
      each swallow the result.
- Docstring: add one paragraph naming the rule and #1210.

**2. The "will retry next tick" wording is kept. The fix makes it true for the transient states it names; two
permanent states stay as they were.**
- **Now true:** after a push, fetch or rebase failure on a configured remote, the commit stays ahead of the
  tracking ref (or the ref is absent on a named remote), so the next tick's `publish` pushes it.
- **Already worded correctly:** the permanent #1142 states (`_UNRELATED` "publish refused", `_NO_BASE_VISIBLE`)

- **Two existing lines become true as a side effect:**
  - `publish_after_write`'s "`sync.py publish .sdlc` will retry it" (`sync.py`);
  - the doctor's "`sync.py publish .sdlc` publishes now", shown next to "N commits never pushed"

## Tests (new, in `tests/test_ledger_publish.py`, real git), each seen red first

Every stranded state is built **by hand** (a commit in the worktree, as
`test_a_commit_that_never_reached_the_remote_is_counted_separately` already does), never through a publish
call that the clause under test governs. That way each clause control fails its own test at the retry
assertion, not during setup.

Each hand commit regenerates `TEAM.md` first, with `sync._write_team(base, wt)`, the function `publish()`
itself calls. Otherwise the retry call would itself stage `TEAM.md`, commit it and take the unchanged
"this call committed" path, and the clause under test would never be reached (round 2, B1). Each retry
in T1, T3 and T4 goes through a recording spy and asserts that no `commit` happens before the first
`push`, so a setup that drifts back onto the committed path fails loudly instead of passing.

- **T1 `test_a_push_that_failed_once_is_retried_by_the_next_publish_with_no_new_entry`.** This is the issue's
  end-to-end reproduction, a witness rather than a clause control.
  - Setup: clone A comes from the `clone` fixture. Clone B is built with the fixture's recipe (`git init` +
    `remote add` on `tmp_path / "origin.git"`, actor `eli`). Both are bootstrapped.
  - A writes a note and publishes through a wrapper that raises on `push`, with `attempts=1`. Assert the
    result starts `publish deferred (will retry next tick)`.
  - B writes a note and publishes, so A's retry has to fetch and rebase.
  - A publishes with the default attempts and no new entry.
  - Asserts: `published`; ahead count `0`; origin's branch holds both notes' text.
  - Red on base at the retry assertion (C0).
- **T2 `test_a_publish_with_nothing_ahead_makes_no_network_call`.**
  - Setup: bootstrap, then publish again through a spy that delegates to `_run_git`.
  - Asserts: `nothing to publish`, and no `push`, `fetch` or `ls-remote` among the recorded calls.
- **T3 `test_a_stranded_commit_ahead_of_the_tracking_ref_is_pushed_with_no_new_entry`** (the `> 0` clause).
  - Setup: bootstrap, note, hand commit. The tracking ref is present and the clone is 1 ahead.
  - Asserts: `published`; ahead `0`; origin has the note.
- **T4 `test_a_first_push_that_failed_is_retried_though_no_tracking_ref_exists_yet`** (absent ref + named
  remote).
  - Setup: `sync.init` with the remote branch absent, then note and hand commit. Assert that
    `refs/remotes/origin/sdlc-ledger` is absent.
  - Asserts: `published`; origin now has the branch and this clone's entries file.
- **T5 `test_an_idle_clone_whose_tracking_ref_can_never_exist_does_not_push`** (absent ref + not a named
  remote), parametrized over two cases:
  - (a) No remote configured. Bootstrap returns `publish deferred`.
  - (b) A named-remote bootstrap, then the config's `ledger.remote` is set to the origin's filesystem path
    (the pre-#1142 shape).
  - Then an idle publish through the spy. Asserts `nothing to publish` and no `push`.
- **T6 `test_a_git_add_that_fails_returns_a_status_instead_of_raising`.**
  - Setup: bootstrap, note, then publish through a wrapper that raises on `add`.
  - Asserts: the result starts `publish deferred` and carries the `add` error.

## Out of scope, named

- **Permanent states that still say "will retry next tick"** on ticks with a new entry: no remote configured,
  or a server that rejects every push. Both predate this change. Idle ticks of a clone holding a stranded
  commit gain per-tick cost against a rejecting server, an unreachable remote, or an unrelated history
  (measured; see the CHANGELOG entry and the PR).
- **A remote branch an admin deleted.** If a later prune removes the tracking ref, an idle clone on a
  named remote recreates the branch on its next tick. Before the fix, only a clone with a new entry did
  that. `_fetch`'s explicit refspec never prunes, but any ordinary `git pull` in the main checkout does
  when `fetch.prune=true` is set and the default wildcard refspec is in place, so the prune need not be
  manual (P6 review, finding 8). Recreating on the next entry was already the behaviour, so this is not
  a new kind of hazard; it now happens within one tick.
- **A stranded commit when the actor was renamed** between the failed push and the retry (the `not mine`
  case). The next entry the new actor writes carries it.
- **A recurring rebase conflict on the ledger.** Entries are single-writer, and no shape for this is known.
