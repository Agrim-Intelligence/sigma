# Plan #2108 — a cold cost ring admits a verify at more than one worker

Lane: medium (it changes the guard's admission rule; the issue tags it frontier, run here on a smaller model, so
every choice below is the conservative one). PROVISIONAL (owner to ratify): option 1 only.

## Decision

Option 1: a per-worker cold estimate for `verify`, `Limits.verify_cold_cost`, derived from the machine
(one eighth of total memory) or set by `resource.verify_cold_mb` (an integer of at least 1, megabytes; anything else
reads as derived with a note, exactly as every other key). On a cold ring `verify` is admitted
`n = min(want, room // estimate, max_verify_workers)`, never fewer than 1.

Option 2 (doctor recommends a literal) is rejected: a literal is the one thing the guard cannot lower, so advising
one trades the slow first run for an unbounded one. Doctor keeps `-n {workers}`; its advice is now true on a cold
ring, and its text says so. Option 3 (seed from a repository file) is rejected as the issue suggests.

The real `sigma-cloud` number is UNMEASURED: the 1/8 ratio is uncalibrated policy defaults,
like every other fraction in `resource_guard.py`. A too-low estimate is caught only by the shed (3 critical
samples), so the default is deliberately high: four sessions' worth (1/8 against a session's 1/32). No byte floor: the repo bans byte literals in the guard.

## Which exceptions fail open, which fail closed

Fail open (admit more than one worker): a cold ring with `room >= 2 * estimate`, and `resource.verify_cold_mb`
set below the derived estimate. A literal `-n N` on a cold ring still runs N (unchanged: `record.cold` keeps the
old "nothing measured says N do not fit" path, so no literal that ran before now holds).

Fail closed (one worker, or hold): `room <= 0` holds; `room < 2 * estimate` admits one; a verify already running
on a cold ring holds (unchanged); `critical` holds (unchanged); `max_verify_workers` caps; a bad
`verify_cold_mb` reads as the derived estimate, never zero; `mode: observe` is unchanged (logs, grants `want`).
Every other kind keeps `bound = 1` and a session keeps `room // session_cost` (AC-3).

The lease reserves `n * estimate` for a cold verify (it reserved 0 before), so a goal start sees the room taken;
the ring then learns the measured per-worker cost from the run, and the next admission uses it.
