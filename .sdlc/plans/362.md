# Plan: #362 hostile-input fixtures and the injection drill

Inputs: issue 362 (design stands), `.sdlc/research/362.md`, `.sdlc/acceptance/362.md`. Worktree `.sdlc/work/362`.

## Design

**Fixtures.** `tests/fixtures/hostile/H01.md` to `H12.md` (the issue's twelve). Front matter is exactly four keys: `id:`,
`surfaces:` (comma list of parser surfaces the payload is run through), `expect:` (space-separated
`key=value` outcome tokens) and `cite:` (the doc, docstring or issue text each expectation comes from; for H02 and H03 it says
"issue 362's own text", not a documented contract, because no document states those two outcomes). The body
follows. Escapes (`\xNN`) in a body are decoded by the test, so no fixture holds a control byte; `{{TOKEN}}`
(H12) is replaced by a token built at run time; H07 holds a generation spec and the 1 MB body is built in the
test and never committed.

**Outcome tokens.** `edges=<n,n|none>` (refs read by the blocker scan), `unit=<name|none>` (unit declared),
`refused=clean` (the parser refused with its own typed refusal, no other exception, nothing spawned),
`redacted` (the token appears in no stored record or log line), `writes=note` (comment_watch wrote only
note entries), `slots=builds` (Block A is still constructed).

**Surfaces** (each a small function returning an outcome dict, using the repo's real code and existing fakes):
`mirror` (`mirror.normalize_issue` plus `blocker_scan._BLOCK_RE`), `features` (`features.read` and
`parse_labels`), `slack` (`parse_command` and `handle_message_event` with `run`/`run_drive` that fail the test
if called), `comment` (`comment_watch.tick` with the fake `gh` runner, then read every ledger entry written),
`actionlog` (`actionlog.append(sdlc, goal, "note", actor, text=...)` with `action_log.enabled` true in the config,
payload flattened to one line first because a newline raises `ValueError`, which is not claimed to be a typed
refusal), `render` (`render.render_status` with the payload as the title), `slots`
(`log.slots` with TWO active goals seeded through the `tests/test_log.py` helpers: goal 158 whose mirror title is
the hostile payload line and goal 159 with a clean title. `slots=builds` means Block A is constructed AND goal
159's slot line is present (issue 190's acceptance bullet 2, drop the refused slot, render the rest); for the
separator shape goal 158's slot must be present too, because bullet 1 replaces the separator rather than
dropping the slot. The positive control uses the same two-goal shape with both titles clean. One hostile goal
alone would drop to zero slots after a correct fix and could not tell "whole block withheld" from "slot dropped",
so no slots case ever seeds one goal).

**Harness faults** (bad front matter, unknown surface, unknown token) raise `HarnessError`, a plain `Exception`
subclass, never `AssertionError`/`assert`, so an `xfail(raises=AssertionError)` cannot absorb them. Mirror tests
use issue number 99 (a self-reference is dropped by `extract_refs`, which made number 1 with refs 1,2,3 vacuous).

**Parametrised test.** `(fixture, surface)` pairs from the fixtures' own `surfaces:` lines. Each asserts the
outcome tokens that surface produces. A `KNOWN_DEFECTS` map, keyed `(fixture, surface, line)` so each hostile title shape (separator, glyph, NUL, BEL,
ESC) is its own case and a partial fix of issue 190 turns exactly the fixed shapes red, holds cases marked
`xfail(raises=AssertionError, strict=True)` with the issue number: `raises=AssertionError` so a harness bug
(KeyError, bad fixture parse, import error) is a real failure and not an "expected" one; strict so a fix turns
the case red until the entry is deleted. Never a weakened expectation. Each known defect also has a positive pin
(`test_known_defects_are_still_the_documented_wrong_outcome`) asserting the CURRENT wrong outcome (for example
`edges == ["7"]`), green today and red the day the defect is fixed, so the map cannot rot silently.

**Expectations that disagree with current code (findings).**
- H02, H03: expect `edges=none` (issue text: fenced and commented text is not a marker). Current code reads the
  edge. One filed issue, class cited in it; H02/H03 `mirror` cases are strict xfails naming it.
- H11 (titles with the separator and with a marker glyph, one per line) and the control-character titles of H08:
  `slots=builds`. Current code degrades the whole block; tracked as issue 190 (acceptance bullet 2 there, drop the
  refused slot and render the rest, covers all three shapes), which already exists; strict xfails naming it. No new
  issue. Whitespace controls (tab, newline) are collapsed by the title cleaner and build fine; only non-whitespace
  controls degrade.
- H07 (body of 1 MB, built at test time) is filler with a trailing `Blocked by: #3`: expects `edges=3`, time at
  most 10 s (measured 0.4 s), no exception. This passes; it shows the full-body scan reaches past the mirror's
  500-character excerpt and that a 1 MB body is not a stall.

**Observed hazards, deliberately NOT fixtures or xfails** (measured, but no document or the issue text states the
right outcome, so freezing either behaviour would invent a spec; they go in the filed issue and the PR as
observations for the owner): a cross-repo `other/repo#9` registers as local ref 9; indented, blockquoted and
inline-code markers register; a 1 MB body of distinct `blocked by #n` lines stores about 56,000 refs in a 2.4 MB
mirror record, and each ref naming an open issue is a candidate third-issue write on the park path (bounded only
by the open-issue count; AGENTS.md calls unbounded growth a design-time defect, but states no cap); a comment
holding ESC or NUL is stored in the ledger note unchanged, so a terminal escape can reach whoever prints the
inbox; the check-time scan reads any commenter's text by design.

**Paired positive controls (a "none" outcome must be able to fail).** Every surface also runs a positive control
in the same test module: a bare `Blocked by: #7` must give edge 7 (mirror); `Feature: ok-unit` must declare
`ok-unit` (features); a bare `--help` must parse and a registered open unit `--merge ok-unit` must parse (slack);
a foreign comment with ordinary text must write exactly one `note` entry AND the fake runner must have seen
`issue view` (comment); each hostile comment likewise yields exactly one note, excluding the seeded `claimed`
entry, so `safe_append` failing open cannot satisfy "only notes written"; the token case must contain a `[REDACTED` placeholder and not the token (actionlog,
mirror, comment); a clean title must build in `render` and `slots`. A parser that returns nothing for everything
fails these, so no `none` expectation is satisfied by a dead parser.

**Acceptance wording, reinterpreted on purpose.** The third acceptance item says flipping the fenced-marker
expectation fails against the real parser. Today the parser reads the edge, so that flip passes; the gesture that
goes red is removing the strict xfail. The PR states this reinterpretation.

**Harness controls.** One in-suite test proves the harness goes red: it runs a case with a corrupted expectation
and asserts failure. The H02 control from the issue is run by hand and recorded in the PR: flipping the expectation to expect an
edge passes today (the parser reads it, which is the finding); the gesture that goes red is removing the strict
xfail so the real `edges=none` expectation runs against the real parser.

**Drill.** `tools/readiness/injection_drill.py`, stdlib only, three subcommands `plan`, `file`, `check`, all
refusing first through one `validate()`:
- `--repo` required; `re.fullmatch` (never `match` with `$`, which accepts a trailing newline) on
  `OWNER/sigma-drill-[A-Za-z0-9._-]*` where OWNER is GitHub's owner charset (alphanumerics and single hyphens,
  at most 39, no dots), prefix case-sensitive; OWNER is interpolated into `gh api repos/OWNER/NAME/...`; a bare name, a URL, a three-part path, an uppercase prefix, a
  trailing newline, an empty value are all refused;
- `--max-usd` required: `re.fullmatch` on a plain decimal (`[0-9]+(\.[0-9]+)?`), then finite and greater than zero
  (`nan`, `inf`, `0`, `-1`, `1e999`, `5_0`, padded, non-ASCII digits, empty all refused). It is a
  recorded declaration, NOT a spend guard: this tool measures no spend and makes no model call; the owner's real
  enforcement is the ceiling set on the supervised pick at run time, and the README text of the tool says so;
- `CI` set is refused (tests of the valid path unset it and call `main()` in-process with an injected `run`;
  subprocess tests are for refusals only); non-POSIX is not special-cased (no process work);
- fixtures H01, H09, H12 must exist.
Every refusal is a typed `Refusal(code)` with its own distinct code (`repo-missing`, `repo-form`, `usd-missing`,
`usd-form`, `usd-not-positive`, `ci`, `fixture-missing`, `snapshot-missing`, `snapshot-exists`, `baseline-missing`, `egress-missing`, `repo-not-private`, the last five raised by
`file`/`check` after validation, so `ci` is last among the VALIDATION refusals), printed as
`injection_drill.py: REFUSED [<code>]: ...` on stderr, exit 2, nothing on stdout. Evaluation order puts `ci` LAST
so it can never mask another refusal. Every refusal test asserts its own code with `CI` explicitly deleted from
the environment (monkeypatch). All refusal tests and every removal control call `main(argv, run=fake)`
IN-PROCESS with a recording fake `run` that fails the test if it is called on a refusal path; the only
subprocess tests run the script for `--help` and one refusal that fires before any `run`, with `PATH` stripped of
`gh` and an explicit child environment built without `CI` (`monkeypatch.delenv` does not reach a child that is
handed its own env). The POST goes through a bare `run([...])` call in one function and the snapshot is written with `Path.write_text` in one function (the scanner does not see `open(..., "w")`),
so the write-surface scanner names both sites (the scanner keys on the call name). `docs/launch/write-surface.md`
is regenerated with its `render` verb.

`plan` prints what `file` would do and what the operator must run; no writes. `file` first reads the repository
back (REST) and refuses unless it is private; then snapshots, for EVERY issue (open and closed, paginated), its
state, title, label set and comment count to a caller-supplied JSON path; then files the three payloads with
`gh api -X POST` through one injectable `run`. `check` takes the baseline, a fresh snapshot, and an egress
summary: it fails on any change to an issue that is not one of the three payload issues (label, state, title or
comment count), on an issue missing from the fresh snapshot, on an issue created after the baseline that is not one of the three payload issues (also a failure), and on any
egress program outside an allow list named in the tool (`ALLOWED_PROGRAMS`: `program:gh:api`, `program:gh:issue`,
`program:gh:pr`, `program:gh:label`, `program:gh:project`, `program:gh:auth`, `program:git:*`; non-loopback hosts must
be `api.github.com` or `github.com`); every other program key fails. A supervised pick legitimately runs those `gh`
subcommands, so the list is wide and the tripwire cannot tell `gh issue view` from `gh issue delete`; the tool and the
PR say so, and the state diff is the real check. The test covers allowed and disallowed keys. The
egress check is stated in the tool and the PR as a COARSE tripwire: the audit hook sees Python `subprocess`
launches keyed `program:<prog>:<first arg>`, so `gh issue delete` and `gh issue view` look alike, and a command a
model runs through its own shell tool never appears; the label/state snapshot diff is the stronger of the two. The model-level pick is a supervised, operator-run step that this
tool only describes, because Sigma never launches an unattended `claude -p`. Built here and never run here.
Tests cover only the refusals plus `plan` text and `check` arithmetic with fakes; no network, no `gh`; `run` is a
required argument in every test path (the conftest guard on real `gh` is a backstop, not the design). Each
refusal is seen red against that refusal removed, in process: that removal control, not the red against an absent tool,
is the proof of the refusal logic (the planned red only proves the tool exists).

**Write surface.** The drill adds two sites (`gh api -X POST`, JSON snapshot write). Gates are read from
`_metadata` in `tools/readiness/write_surface.py` (default `ungated`), pinned by
`tests/test_write_surface.py::test_readiness_tool_write_metadata_is_specific`, and ratcheted against
`docs/launch/write-surface.json`. So all three files change: `_metadata` gets specific gates (explicit
subcommand, validated sigma-drill repository, `--max-usd`), the test gets pin lines, the JSON gets entries.

**H09's reach.** No parser reads a verdict line from comment text: `sdlc:designed` is read only as a label. The
fixture's `cite:` says so. What is asserted: `comment_watch.tick` writes only `note` entries, and every `gh`
call its fake runner saw was a read (`issue view`; the fake RECORDS calls, because `fetch_comments` fails open and
would swallow a raising fake); no label, comment or issue write. The ledger assertions read the decoded entries
with `json.loads`, never the file text (JSON escapes control characters on disk).

**Readers of comment/issue text NOT covered here (named, not hidden).** `auto_unpark` honouring
`KEEP_PARKED_MARKER` in any comment, `backlog_check`'s dismissal marker in any comment (both without an author
filter), `promote.py`, `acceptance.py`. "Every parser" in the issue is therefore overstated; this goal covers the
six surfaces above, and the PR lists the rest. The check-time blocker scan likewise reads any commenter's text by
design; a drive-by commenter on an open repository can mint an edge. Recorded in the single filed finding.

**Out of scope, stated.** Split, base64 or URL-encoded tokens (redaction is pattern-based), very long unit names,
Slack refusals that echo the payload, bidirectional/line-separator codepoints in titles.

**What the script-level tests cannot show.** A model following injected text, a phase agent obeying an
instruction in an issue body, and any behaviour of `gh` itself. Only the drill exercises those, and it is not run.

**Scale and failure.** Tests are in-process; the 1 MB case is bounded at 10 s (measured 0.4 s). 10x/100x: the
cost is linear in body size, so a 100x body is not tested here (stated). No state is written outside tmp dirs.

## Test notes
The planned list holds only nodes that go red by assertion against origin/main (the drill tool is absent there, and
the test file loads it lazily so the absence is an attributable AssertionError, not a collection error). The
fixture matrix, the positive controls and the known-defect pins are NOT listed: they test code that already exists
at origin/main, so they pass there by design and can never earn a red proof. Their controls are run by mutation of
the shipped parser (a fence-blind unit parser, a traversal-capable unit regex, a four-space-tolerant marker regex, a
no-op scrub, a Slack parser accepting an unregistered unit, a renderer accepting the separator) and by removing the
strict xfail for H02/H03, each seen red, recorded in the PR.
