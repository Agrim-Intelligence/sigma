# Plan: #464 — dead-owner sweep for session, claim and lock markers

Inputs: issue #464, `.sdlc/research/464.md`, `.sdlc/acceptance/464.md`. Worktree `.sdlc/work/464`.

## Design
- New `skills/agrim-loop/scripts/liveness_prune.py` (stdlib; loads `loop`, `ledger`, `work`, `state` by path like `goal_state_prune.py`). `sweep(sdlc_dir, config=None, limit=200, now=None, dry_run=False, sessions=True, budget_seconds=None)` -> `{"removed": [...], "kept": {reason: n}}`, never raises. Families:
  1. `state/claims/<stem>.lock` (covers `slack-cmd-<name>.lock`). Removed only when ALL hold: regular non-symlink file in a non-symlink `claims/`; safe stem; mtime older than `max(claim-lease TTL, 1 h)` (`ledger.lease_ttl_seconds`; `None` = never-expire config falls back to the 12 h default; the 1 h floor keeps a tiny configured TTL from shrinking the "never judge a lock mid-acquire" window); no alive or unknown `agents/<stem>/*.active` marker (`loop.agent_alive`, fail toward keep); the goal in no LIVE session's `in_flight` list (computed ONCE per sweep; refs compared by normalised stem, `#` stripped); and the sweep WINS a non-blocking `flock` on it, opened `O_RDWR|O_NOFOLLOW|O_NONBLOCK` and never `O_CREAT` (a live holder is never touched, a FIFO or swapped symlink never followed), then re-checks by `lstat` that the locked inode is still the path's inode and the mtime is still old, then unlinks, then releases. `limit` caps removals (`0` = no cap, the operator lever), never examinations; `budget_seconds` stops removals past a wall-clock budget (hooks use 5 s).
  2. `state/claims/<stem>.claimed`, the durable "claim established here" cache marker: removed when older than 30 days (mtime is its creation; never refreshed) with no work record and no alive/unknown agent marker. Safe by construction: `_ensure_claimed` on a missing marker re-reads the ledger, finds the existing claim and only re-touches (one O(ledger) read, measured 31 ms mean over 1,591 entries, at most once per goal per 30 days). This bounds the family by age (about 30 days of claims) for parked, failed and log-less goals too. #458's terminal prune is not changed.
  3. `state/sessions/<pid>[-<thread>].active` and `*.active.<pid>.*` temp files of dead writers (`sessions=True`, operator lever only): delegates to the existing `loop._prune_dead_session_entries`. Hooks pass `sessions=False`: `loop.py start` already prunes sessions, and `_session_pid_live` also reads an entry dead past the lease TTL regardless of pid, so adding `record done` as a trigger would raise how often a quiet-but-live session older than the TTL is pruned by another session (existing behaviour, not widened here). Dry-run lists dead entries by the same `_session_pid_live` verdict.
  Without `fcntl` the lock family refuses LOUDLY on stderr ("not supported on this platform"; the lever exits 2) and removes nothing; the session family also no-ops there (`_session_locked(require_lock=True)` raises and the prune swallows it): documented.
- `loop._try_acquire_claim_lock` hardening (the seam the sweep races): after winning `flock` and BEFORE `_write_claim_lock_liveness`, compare `fstat(fd)` with `lstat(path)` (dev, ino); if the path is gone or names another inode, close and retry (bounded, 3 tries), then report contended (`None`) rather than a lock on an unlinked inode. Without it, an unlink between an acquirer's `open` and `flock` lets two processes both win. `reclaim_stale_claim_lock` (no production caller) gains the same safety through the hardened acquirer; stated in the doc.
- Hooks (fail-open, stderr note, `sessions=False`, 5 s budget): `loop._record` after `goal_state_prune.after_done` on a real `done`, and the CLI `start` verb after its existing `_prune_dead_session_entries`. Operator lever, any host: `python3 skills/agrim-loop/scripts/liveness_prune.py sweep .sdlc [--dry-run] [--limit N]`. Host-agnostic: Sigma Python only, no hook is load-bearing, no daemon, no process pausing.
- Documented caps, no code (`docs/launch/b6-claims-sessions-locks.md`): `sessions/locks/<slot>.lock` and `phase-end-<stripe>.lock` (256 stripes each, 0 B), the four singleton locks (`STATE.md.lock`, `merge-reconcile.lock`, `knowledge-sync.lock`, `feature-judge-spend.lock`: one file each; deleting a flock file would admit a second holder, so they are never pruned), `slack-commands.lock` (existing mkdir reclaim after a grace window). `state/heartbeat/` is not in this issue's patterns: named as not covered.
- Recovery without a human: a crash mid-sweep leaves a subset, every unlink is `missing_ok`, the next `done`/`start`/lever run finishes. Restore-from-backup brings back old-mtime locks of dead goals: the next sweep removes them again; a restored lock of a live holder is kept by the flock. Reboot = kill -9 of every holder: flocks die with the process, files are swept after the TTL. Lost trigger costs latency only: the files are inert (read dead, never read alive).
- Scale: scan is one `lstat` + one agent-dir glob per candidate lock, O(files); steady-state ceiling is the files younger than the TTL (about 20/day measured, so ~10 held at 12 h) plus held locks, and ~30 days of `.claimed` (about 600 at the measured rate, 6,000 at 10x). A backlog of N stale files drains at `limit` per hook call and at once with `--limit 0`; timing at 10x/100x file counts is measured after implementation and recorded in the doc, with what was not measured.
- Disposition `docs/launch/dispositions/464.json` for all 18 patterns (the scanner slice #456 has merged, so the gesture test is runnable) (no `unscanned` waiver: every pattern is produced by the scan). Write-surface inventory gets the new `fs-remove` entries; CHANGELOG names no `docs/launch/` path.

## Test notes
All planned tests drive CLIs over a scratch `.sdlc` (`liveness_prune.py sweep`, `goal_state_prune.py sweep`, `loop.py record|start`) except the seam control, so each is red on old code (missing module, no `.claimed` removal, double-win on the unlinked inode). The kill -9 test uses a real subprocess that wins the lock through `loop._try_acquire_claim_lock`, is SIGKILLed, and a second live holder subprocess stays alive: after the sweep the dead one's lock is gone and the live one's stays. The seam control is deterministic in-process: `fcntl.flock` is wrapped so that the sweep (a full `liveness_prune.sweep`) runs between the acquirer's `open` and its `flock`; the acquirer must end holding the lock on the inode now at the path and a concurrent second acquirer must be refused. Extra, not planned (behaviour already exists, so they cannot be red on old code): `tests/test_flock_markers_release_on_kill.py` (also: `_ensure_claimed` after a `.claimed` prune re-reads the ledger, appends no second `claimed` and does not relabel) (kill -9 of a real holder of each singleton/stripe lock leaves it acquirable, and while alive it is held; control: remove the `flock` call -> red) plus the existing `test_loop.py` dead-session prune tests and slack grace-window tests, each control-broken once. Controls for the new code (each broken once, seen red, restored): the TTL age gate, the live-holder flock, the agent-marker check, the in-flight check, the symlink checks, the inode re-check in the acquirer, the sweep's post-flock inode check, `--limit`.
