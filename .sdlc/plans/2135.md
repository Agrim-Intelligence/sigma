# #2135 plan: recognise a commit-signing outage and stop with one plain "signing is unavailable" message

## Goal / done_when
When `git commit` fails because the host's signing helper is down, `work.py commit` and every
ledger-publish commit in `sync.py` must recognise the cause, stop with one plain message, never retry
unsigned, and leave the goal to park with that reason. done_when (from the acceptance record):

1. `work.py commit` stops with the plain "Commit signing is unavailable" message (not a generic git failure).
2. `sync.py` scaffold, `_publish_knowledge`, `publish_receipt` (`-S`) recognise the same condition, return the
   same message, and do not retry into the same failure. The two further sites the research found
   (`_publish_ledger` main commit, `regenerate_team` amend) are covered too.
3. No path retries unsigned or adds `-c commit.gpgsign=false` / `--no-gpg-sign`.
4. A test simulates the outage with a `gpg.ssh.program` helper that prints an error and exits 1, asserts the
   plain message for `work.py commit` and a `sync.py` publish commit, and was seen red before the fix.

Lane: medium. Research dossier: `.sdlc/research/2135.md`. Acceptance: `.sdlc/acceptance/2135.md`.

## Decisions taken (defaulted and recorded; nobody will answer)
- D1 One pure library `skills/sigma-loop/scripts/commit_signing.py` owns the wording and the classifier, so
  `work.py` and `sync.py` cannot drift. It is stdlib only, no I/O of its own.
  - `MESSAGE`, `NEEDLE` (its first clause, the substring every consumer keys on), `PARK_PREFIX = "PARK: " + NEEDLE`.
  - `class SigningUnavailable(RuntimeError)` carrying the finished plain text.
  - `unavailable(detail, signing_on) -> bool`: true only when signing is in effect AND the text has
    `failed to write commit object` AND no object-store marker (`No space left`, `unable to create temporary file`,
    `insufficient permission`, a `Permission denied` line that names the object store). `signing_on` is a bool
    the CALLER reads, and only on the failure path.
  - `plain(detail) -> str`: `MESSAGE` plus one short detail line (the last non-empty line of git's stderr that is
    not the `fatal: failed to write commit object` line, clipped to 200 characters).
  - `signing_on(read, forced=False) -> bool`: `forced` is "`-S` is in the argv"; else `read()` is a callable that
    returns the output of `git config --type=bool commit.gpgsign`; any exception from it means False.
- D2 Wording is scoped to what is true. MESSAGE: "Commit signing is unavailable on this machine, so nothing can be
  committed or pushed. Start a fresh session (in a Claude Code cloud container the signer comes back when the
  container restarts). Sigma's commit and publish steps will not turn signing off for you." It does NOT claim
  Sigma never disables signing anywhere: the unattended rebase engine (`unattended_git.py` pin,
  `feature_upkeep_resolution.py` `--no-gpg-sign`) is a deliberate, separate, pinned path and is out of scope.
- D3 `work.py commit` returns `PARK: ` + MESSAGE + detail (the same shape `merge` uses for a human-needed stop).
  The CLI maps a result starting with `commit_signing.PARK_PREFIX` to exit 4, beside `SEALED REFUSED:`, so a
  chained `commit` then `pr` cannot continue. The NEEDLE is added to `MECHANICAL_PARK_PREFIXES`, so the park is
  classified as infrastructure and never as a "needs human judgment" decision. qkind stays `unknown` (no new
  qkind: it ripples into the ledger, decision bank and label docs; follow-up). The park itself stays
  agent-driven (`record parked "<printed message>"`); SKILL.md and landing.md say so.
- D4 `sync.py`: one helper `_commit(git, path, args, forced=False)` is the ONLY place `sync.py` runs
  `git commit`. On failure it reads the signing config (failure path only), classifies, and raises
  `SigningUnavailable(plain)`; any other failure is re-raised untouched. The five sites call it:
  scaffold (`init`, was `except Exception: pass`), `_publish_knowledge`, `_push_receipt` (`forced=True` for
  its `-S`), `_publish_ledger`, and the `commit --amend` in `regenerate_team`. Each broad `except` gains an
  `except SigningUnavailable as exc: return str(exc)` ahead of it, so the plain text is not wrapped in
  `publish deferred:` / `receipt pending:`. `_push_with_retry` also catches it from `after_rebase`, aborts the
  rebase and returns the plain text immediately (no retry into the same failure). `_push_receipt` result is
  consumed by `work.py pr` (prefixes `receipt pending for PR #N:`) and the merge receipt (`work.py` ~1503): both
  consumers pass the plain text through unwrapped when it carries the NEEDLE (see Task 4).
- D5 BR-7 (a rebase replay re-signs commits and can fail as a rebase error): measured in Task 4 against the same
  fake signer. Default is DEFERRED with a note in the CHANGELOG and PR body; it is reused only if the rebase
  stderr carries the same fatal line and the reuse is one added `except` (no new code path). Whatever the
  measurement says, the result is recorded in the PR body.
- D6 Deferred, stated in the PR body and CHANGELOG ("Not covered"): the pre-flight probe (a `sigma-doctor` row /
  `loop.py next` check), the commit sites in `release_manifest.py`, `decision_store.py` and
  `skills/sigma-define/scripts/define.py`, a dedicated qkind, and the unattended rebase engine. No issue filing
  needed beyond the note.
- D7 Retry bound (RESILIENCY): a failed commit never loops inside a call. The ledger watch tick re-attempts at its
  own existing interval (`SIGMA_WATCH_INTERVAL`); that is unchanged, bounded, and stated in the docs paragraph.
- D8 Public-repo rule: nothing in the tree names the reporting repo; docs and tests say "an adopter repo".
  Test fixtures use worktree-relative or `tmp_path` paths only.
