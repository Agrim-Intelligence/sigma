# Plan: #360 — read real mutmut output and record the kill rate per Tier A module

Inputs: issue #360, `.sdlc/research/360.md`, `.sdlc/acceptance/360.md`. Worktree `.sdlc/work/360`, origin/main `70c2c6e`.

## Design

1. `mutation.py`: `_parse_counts` reads the LAST progress tally, emoji (written as `\N{...}` escapes, plain ASCII)
   or `--simple-output` words, count AFTER the label; the legacy `N killed` wording stays as a fallback so existing
   callers' strings still parse. `_parse_results` stays `(killed, survived)`. New `parse_survivor_ids` reads
   `mutmut results`. `run()` gains `tool`, `runner`, `use_coverage`, always passes `--simple-output`, returns `counts`
   (timeout/suspicious/skipped are reported, not in the denominator), puts the output tail in the no-mutants reason,
   and `_default_run` kills the whole process group on a timeout (mutmut mutates files in place and spawns the test
   runner through a shell). Nothing imports mutmut; absent tool still resolves to `absent`.
2. `tools/readiness/mutation_sample.py` (stdlib): modules = unique Tier A `.py` files; non-Python recorded
   `absent`/`not-python`. Sequential, cheapest (line count) first. Per module: restore + clean the frozen clone;
   scoped tests (filename, else <=5 referencing files); `coverage run -m pytest <files>` + `coverage combine`;
   `mutation.run(--runner "<venv python> -m pytest -x -q -p no:cacheprovider <files>")`; survivors via
   `mutmut results`/`show` (capped at 60 diffs, total recorded); restore again. Per-module timeout and an overall
   wall-clock cap (budget persisted across resumes); unreached modules `absent`/`not-run-budget`; 1-minute load above
   a limit pauses between modules; the result file is rewritten after every module and recorded modules are skipped
   on a re-run; a clone with tracked modifications, or a result for another commit, is refused. A measured number is
   only ever a count mutmut printed; timeout / no tests / failing baseline / crash / not reached are `absent`
   with a reason code. Host paths are scrubbed from the file and the venv is a placeholder.
3. Evidence `docs/launch/evidence/mutation-<sha12>.json` from the real run, with `budget` (documented deviation from
   the issue's 60 min/module: 15 min/module, ~3 h overall, sequential, nice), mutmut and python versions, tests used.
4. Docs: one short evidence note stating what a kill rate does and does not mean. Out of scope: wiring into verify,
   thresholds, mutmut 3.x.

## Test notes
Fixtures `tests/fixtures/mutmut/2.5.1-*.txt` are the stdout of real mutmut 2.5.1 runs (commands in test_mutation.py);
not hand-written. The eight listed nodes fail by ASSERTION on origin/main (old regexes; no `tool`/`runner`/
`parse_survivor_ids`/`counts`; the old timeout kill waits for the grandchild), checked with `red_green.observe`.
`tests/test_mutation_sample.py` (new tool, no old behaviour to be red against) is NOT in the list: it cannot go red on
old code by assertion. Its controls are each judged by a mutation I run and record (read the first tally instead of
the last; count timeouts into the rate; remove the process-group kill; drop either restore; drop the resume skip;
drop the budget break; drop the load pause; drop the dirty-clone refusal; drop the host-path scrub; reverse the
order). Reviewer refinements applied in code: `killpg` guarded where unavailable; unfinished work restored in a
`finally` and on SIGTERM; the sample STOPS (not-run-budget, reason names the load) if the machine stays above the
load limit past a bounded wait; each measured entry also carries `rate_range_all_mutants` ([timeouts counted as
survived, timeouts counted as killed]); the write-surface inventory gains the three new sites with gates, control run
on the documented gesture (a temporary tracked `gh label delete` line goes red, then green). Everything runs without
mutmut installed. The real-tool run is recorded in the evidence file, not repeated in the suite. Budget: 15 min per
module and about 3 h overall are the owner's constraint for this goal (a documented deviation from the issue's 60
minutes), exposed as options. Residuals stated in the PR: coverage-scoped kill rate; modules that exceed the timeout
have no number; mutmut 2.x only.
