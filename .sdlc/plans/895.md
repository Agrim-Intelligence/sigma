## Design (binding)

### D1. `gh_api.pr_changes_requested(run, number, repo=None, *, gql_run=None, env=None, sdlc_dir=None, now=None) -> list[str]`
Logins whose LATEST decisive review is CHANGES_REQUESTED. Op `pr_reviews_read` through `_rest_first`.
- REST: `GET repos/{owner}/{repo}/pulls/N/reviews --method GET -f per_page=100 -f page=k`, `REVIEW_PAGE_CAP = 10`.
  A FULL page (100 rows) at the cap RAISES GhApiError(other); never truncate. Page not a list, or any row not a dict: raise.
- Decisive states: APPROVED, CHANGES_REQUESTED, DISMISSED. COMMENTED and PENDING ignored (never decide, never clear).
  Any other state string (or non-str) RAISES. Semantics (documented and tested): CR then later COMMENTED stays requested;
  CR then later APPROVED clears; CR then DISMISSED clears; bot logins are raw REST (`x[bot]`).
- Order per user by `(submitted_at, id)`; a decisive review lacking str `submitted_at` or int (non-bool) `id` RAISES.
  Key = lower-cased login. A review with null `user` (deleted account) is keyed by its own id (one ghost can never clear
  another's CR) and reported as `(deleted user)`.
- Fallback (ONE, only on rate_limit/server/transport, never cloud or breaker-open, as PR A): `gh pr view N --json reviews`
  (all reviews, GraphQL), normalized to the same rows and run through the SAME reducer. `latestReviews` is NOT used
  (it omits the COMMENTED-later case). Fallback reply with >= 100 reviews, non-list `reviews`, or missing keys RAISES.

### D2. `gh_api.open_prs_for_head_gh(run, branch, limit, repo=None, *, gql_run=None, env=None, sdlc_dir=None, now=None) -> list[dict]`
Rows in `gh pr list --json number,url,mergeable,mergeStateStatus,isCrossRepository,headRefName,files,changedFiles` shape.
Op `pr_list_read` through `_rest_first`.
- REST: ONE `GET repos/{owner}/{repo}/pulls?head={owner}:<quote(branch, safe="")>&state=open&per_page=<limit>` (with `repo`
  given use its owner; `{owner}` expansion in the query string is MEASURED live). Then per row `pulls/N`: number, `html_url`
  -> `url`, mergeable/mergeStateStatus via existing `_mergeability`, `isCrossRepository` via existing `_cross_repo`,
  `headRefName`, `changed_files` (int, non-bool, else raise; list rows carry null, MEASURED) and ONE
  `pulls/N/files?per_page=100&page=1` (rows dicts with str `filename`; `files=[{"path":...}]`). A short page yields a
  files/changedFiles mismatch that `_is_this_goals_design_pr` refuses (distinct, non-None). Filter cheap fields on the list
  row before the per-row calls where safe.
- Never `[]` by accident: list reply with `len >= limit` RAISES GhApiError(other); non-list body (empty output, null, dict)
  RAISES; non-dict row RAISES; only a genuine JSON `[]` returns `[]`.
- Fallback (ONE, same conditions as D1): `gh pr list [--repo R] --head <branch> --state open --limit <limit> --json <same
  fields>`. Non-empty output must be a JSON list of dicts each carrying every key; blank/garbled RAISES.
- Known divergence (documented): `head=owner:` hides fork PRs from another owner. Old list showed them and the identity
  check refused; now a same-branch fork PR is invisible, benign (the real PR is still listed; never reads as merged).

the `len(rows) >= DESIGN_PR_LIMIT` guard (still protects the fallback). `(None, None)` only from a genuine empty list.
The old strings "could not parse ..." / "unexpected ... reply shape" are replaced; tests adjust.
`_is_this_goals_design_pr` unchanged. Removes the `["gh","pr","list",...]` literal from work.py.

### D4. `work.review_gate` (R4)
After the directive check: `gh_api.pr_changes_requested(_pr_api_run(run, rec["worktree"]), rec["pr"], sdlc_dir=sdlc_dir)`.
- ANY failure -> `(False, "could not read PR #N's reviews (...) ... re-queue")` in ALL modes. DELIBERATE FAIL-CLOSED CHANGE:
  changes mode used to fail open on an unreadable combined read. CHANGELOG records it as a behaviour change.
- Non-empty -> park "changes requested by <names>".
- Then the residual ONE `gh pr view N --json reviewDecision` (direct gh call stays; skipped when

  documented behaviour change. `decision == CHANGES_REQUESTED` still parks. Approval logic, `_unresolved_threads`,
  sigma:approve/block unchanged.
