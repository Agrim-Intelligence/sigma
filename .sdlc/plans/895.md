## Design

### D1. `merge_rights` permission over REST (work.py)
- Replace `gh repo view --json viewerPermission` with `gh api repos/{owner}/{repo} --jq .permissions` (the `--jq` makes
  the argv unique among the three reads of that endpoint). New helper `_viewer_permission(run, cwd)`:
  `json.loads(out)`; require a dict; look ONLY at the five known keys (an unknown extra key is ignored, never a
  reason to refuse); map the highest true of admin/maintain/push/triage/pull to ADMIN/MAINTAIN/WRITE/TRIAGE/READ; a
  known key whose value is not a bool, a missing/null/empty/all-false dict, non-JSON, or any exception RAISES, which `merge_rights` already turns into `(False, "could not determine merge rights (...)")`.
  Fail CLOSED is therefore structural. `_CAN_MERGE` and the "<perm> access" wording are unchanged. No GraphQL fallback.
- The `isCrossRepository` read (REST already) is unchanged.

### D2. `protection()` reads classic + rulesets over REST (work.py)
- Drop the `nameWithOwner` read; use `repos/{owner}/{repo}/...` placeholders.
- Classic: `branches/<base>/protection`, parse unchanged. Rules: `repos/{owner}/{repo}/rules/branches/<quote(base, safe="")>?per_page=100`
  (same encoding as `gh_api.branch_rules`, which is not reused because it demands an explicit repo; MEASURED
  2026-10-11: both `sdlc%2F895` and `sdlc/895` return the rules list on this repo). Pure parser `_ruleset_requirements(text)` -> `(contexts:set, reviews:int)`: list of dicts;
  `required_status_checks` -> `parameters.required_status_checks[*].context` (a context counts ONLY when it is a
  non-empty string); `pull_request` ->
  `parameters.required_approving_review_count` (int >= 0, bool rejected). Non-list, non-dict items, missing keys, bad
  types contribute nothing (never raise, never invent a requirement). Each of the two reads sits in its own try: one
  failing leaves the other. Union: checks = classic contexts | rule contexts (by name), reviews = max. Detail string
  keeps today's format. Both unreadable/empty => unchanged `not protected` / `protected but requires no checks`.
- Documented, not derived: bypass actors, `evaluate`-mode rulesets (UNMEASURED), merge queue, deployments/workflows/
  signatures/thread resolution.

### D3. `post_review` comment over REST (gh_api.py + work.py)
- New `gh_api.comment_pr(run, number, body, repo=None, *, fallback_run=None, env=None, sdlc_dir=None, now=None)`:
  `POST issues/N/comments -f body=` via `_rest_write("pr_comment", ..., idempotent=False)`; ONE
  `pr comment N --body` fallback (built here, ratchet-exempt) only on a primary rate limit while `graphql_available`;
  returns the comment URL string (REST: `html_url`, else `...#issuecomment-<id>` from `id`; a body with neither returns
  "" so the caller's existing "ID could not be confirmed" PARK fires); fallback returns gh's stdout.
- `post_review` replaces the `run(... "gh","pr","comment" ...)` call with `comment_pr(_pr_api_run(run, wt), int(pr), body,
  fallback_run=api, sdlc_dir=sdlc_dir)`. The surrounding ambiguous-outcome handling (PARK + marker reconcile) is
  UNCHANGED; no retry, no GraphQL after an ambiguous failure.

### D4. End-to-end cloud merge test (test_work.py)

  cleared (the override beats the env) and sets `CLAUDE_CODE_REMOTE=true`, runs `merge()` with a runner that RAISES for any `gh pr view`, `gh repo view`,

## Stated limitations
- Whether a cloud session token receives `permissions` on `GET repos/{o}/{r}`, the rulesets read through the proxy, the
  comment POST and the merge PUT through the proxy: UNMEASURED live (fakes + one local `gh` measurement of the shapes
  on this repo, 2026-10-11).
- A rule bypass (an admin may skip a ruleset) is not visible to `protection()`; unchanged in kind from classic.
- D3's value in a cloud session: the `sigma:block` comment and the review receipt (changes mode); `require_review:
  approval` still parks there (reviewDecision is unreadable), so D3 alone does not unblock approval mode.
- Existing, unchanged: a definite 4xx on the comment POST leaves the receipt `prepared`, so every re-run parks
  "ambiguous" until the marker is found; recovery is the existing reconcile-review-post lever.
- Unresolved review threads are not enforced in a cloud session (GraphQL-only, fail-open): unchanged, now documented.

## Cost, ceilings, recovery
- merge(): +1 REST rules read per merge, -1 GraphQL (`nameWithOwner`) and -1 GraphQL (`viewerPermission`): +0 net calls,
  all REST core (5,000/h per token, 1 point each), independent of repo size; per-goal, no shared lock. post_review: 1
  REST POST (was 1 GraphQL) + at most 1 CLI fallback.
- Recovery unchanged and idempotent: an ambiguous comment is reconciled by the REST marker read; an undeterminable
  permission returns the `record review` line, and the next `work.py merge` re-reads. A comment failure keeps today's `PARK: remote comment outcome ambiguous` (unchanged behaviour; REST adds no new park path).
