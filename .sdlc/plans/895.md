## Design deltas (short)
- `to_gh_shape`: `state` = `"MERGED"` when `issue["pull_request"]["merged_at"]` is truthy, checked before
  the upper-casing (REST reports a merged PR as `closed`; `gh issue view` says `MERGED`). Closed-unmerged PR
  stays `CLOSED` (stateReason empty) so `closed_state` still refuses it. `number` -> `issue["number"]`
  (int), `title` -> `issue.get("title") or ""`. `_check_fields` already derives from GH_FIELDS.
- Seven sites have a `source`: call `source._read_issue(n, fields)` (already passes `sdlc_dir`, `gql_run`).
  Callers keep their `json.loads(raw)` shape by consuming the dict directly (no re-encode).
- triage:1549 (`run` injected) and brainstorm:178 (`run` or `sources._run_gh`) have no source and no
  `sdlc_dir`: call `gh_api.read_issue(run, n, fields, repo, gql_run=run)` with `repo` taken from the
  existing `repo_args`/config (pass the repo string, not the `--repo` list). No breaker or log is written
  there (no `sdlc_dir`); during a REST outage each such call costs REST + one fallback + a stderr line.
- `reconcile.py` three sites share one local helper only if the diff is smaller; otherwise edit in place.
- Each site keeps its `except Exception` arm unchanged: GhApiError is an Exception, so fail-open
  (`auto_unpark` -> open), refuse (`blockers` -> None, `promote` -> `(None, why)`), skip (`reconcile`),
  continue (`triage:1549`), None (`triage:2015`), raise (`unpark`, `brainstorm`) all behave as today.

## Failures and recovery
- REST outage: each site falls back once (cloud: none, the site's own fail-open/refuse arm runs). Breaker
  opens after 3 failures for 300 s (sdlc_dir sites only); recovers on the first REST success. No retries
  added. Reverting is a revert of one PR; no state format changes (breaker/log files are 2a's).
- Merged PR where REST omits `pull_request`: reads CLOSED, treated unresolved (the safe direction).
- Per-item cost: 1 REST request per view (2+ with comments: 1 + ceil(n/100)) vs 1 GraphQL today, so linear
  in sites touched, same call count. At 10x: reconcile re-reads one per action, 10x actions = 10x REST
  calls (5000/h core budget; 500 reads is 10%). At 100x that is 5000/h, a ceiling: the breaker bounds
  failure spend but not healthy spend. Not measured at scale.
