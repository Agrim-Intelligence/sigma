## Design (gh_api)
- `GhApiError(text, hint=None, status=None, kind="other")`; `_call` fills both via `classify(exc)`.
- `classify(exc) -> (status|None, kind)` over `text = exc.hint or str(exc)`. `.hint` is gh's stderr,
  with no argv. `str(exc)` embeds argv and is only used when there is no hint. In order:
  1. `gh_session.proxy_session_block` / `graphql_unavailable` (on hint and str) -> `proxy` (no fallback).
  2. `HTTP (\d{3})` in `text` decides when present: 429 `rate_limit`; 403 + `/rate.?limit|abuse/i`
     `rate_limit`, else `permission`; 401 `auth`; 404 `not_found`; 422 `invalid`; 5xx `server`; any
     other status (400, 409, 410, ...) `other`.
  3. Only when there is no status: `subprocess.TimeoutExpired` in the `__cause__` chain, or
     `/dial tcp|timeout|timed out|deadline exceeded|connection (refused|reset)|no such host|^EOF$/im`
     -> `transport`; rate-limit wording -> `rate_limit`; else `other`.
  `FALLBACK_KINDS = {"rate_limit","server","transport"}`. Wording INFERRED (gh `gh: <msg> (HTTP n)`
  format, Go net errors, GitHub docs), not captured live; headers invisible so 403-rate is
  text-matched (ceiling: a permission 403 that says "rate limit" falls back once).
- Comments: `view_issue(run, number, repo=None, comments="all"|"none"|int)`. `cap` is removed; it had
  no product caller. The issue GET comes first. Non-dict -> GhApiError.
  `n = issue["comments"]` (an int; a non-int raises GhApiError). `"none"`: 1 request. `"all"`: pages
  1..ceil(n/100). `int k`: only the pages that hold the newest k (`ceil(n/100)` down to
  `ceil((n-k+1)/100)`), at most 2 pages when k <= 100. Each page must be a list, else GhApiError
  (kind other). Tail pages are fetched in ASCENDING order over the computed range; the short-page stop applies to "all" only. Ceiling: "all" costs `1 + ceil(n/100)` requests, so 1000
  comments is 11 requests. Not capped, matching gh's preload-all. A comment posted mid-read can shift
  the tail by one; results are re-sorted by `createdAt`.
- `to_gh_shape(issue, fields)`: requested keys only. `state` upper; `stateReason` upper of
  `state_reason` or None; `author` = `_login(user)`; `closedAt`; `body or ""`; labels/assignees
  pass through; comments = `[{"id": node_id or str(id), "author": {"login": user.login}, "body",
  "createdAt", "authorAssociation"}]`. Comment authors are NOT bot-mapped until step 9 measures them
  (B3). `_login(u)`, used for the ISSUE author only, = `{"login": "app/" + slug}` when
  `u.type == "Bot"` and the login ends `[bot]`, else `{"login": u.login}`. INFERRED from gh's source
  (gh also sets `is_bot`, which no caller reads, so it is not emitted). `node_id` == GraphQL comment id was MEASURED by the reviewer on
  #801 (`IC_kwDOUtULK88AAAABahm5Og`): cite that in the PR. Unknown field -> ValueError.
- Persistence paths: `read_issue(..., sdlc_dir=None)`. When `sdlc_dir` is set, `_state_paths`
  lazily `_load("state")` and calls `state.refuse_symlinks(sdlc_dir, rel)` (`create_parents=False`
  on reads; `True` only right before a write) for
  `state/gh-rest-breaker.json`, `state/gh-fallback.json` and both `.tmp` names. `UnsafeStatePath`
  sets persistence off for this call and prints one stderr `REFUSED` note. Writes then go only through
  `_write_cache`. The lstat->replace window needs concurrent write access inside the checkout, the
  same residual risk state.py documents.
- Breaker `{consecutive, opened_at, last_kind}`, corrupt/missing = closed. `BREAKER_THRESHOLD = 3`.
  Cool-down `SIGMA_GH_BREAKER_COOLDOWN` (default 300; unparseable or negative -> 300). On each
  fallback-class REST failure, `consecutive += 1`, and if `consecutive >= 3` then `opened_at = now`
  (every time, item 5). REST success resets (writes only if non-zero). Open = `opened_at` set and
  `now - opened_at < cooldown`.
- Log `gh-fallback.json`: a JSON list via `_write_cache`, last `FALLBACK_LOG_CAP = 200` entries
  `{ts, op, number, kind, status, fell_back, why}`. Never error text, argv or body. stderr:
  `sigma: gh REST issue #N read failed (<kind>, HTTP <s>); <why>`, once per breaker open (item 8)
  and once per non-breaker fallback.
- `read_issue(run, number, fields, repo=None, *, gql_run=None, env=None, sdlc_dir=None, now=None,
  comment_limit=None)`:
  1. Breaker open and `graphql_available(env)["available"]` -> skip REST, ONE `gql_run`, log `why="breaker open"`.
  2. Else REST: `view_issue(..., comments=("none" if "comments" not in fields else comment_limit or
     "all"))` -> `to_gh_shape`; success resets the breaker.
  3. GhApiError in FALLBACK_KINDS: bump the breaker. If `graphql_available(env)["available"]` (env only, no probe; it returns a dict),
     ONE `gql_run(["issue","view",str(n),*repo_args,"--json",",".join(fields)])`. Malformed JSON
     degrades to `{}` exactly as today's parsers do, then the result is filtered to fields. If the
     call raises, raise GhApiError naming both failures, with `kind` = the REST kind and `.hint` = the
     fallback's hint (else the REST hint). If GraphQL is not available, re-raise the REST error
     (`.hint` kept).
  4. Any other kind: re-raise unchanged, no log, no breaker change.
  `gql_run` defaults to `run`. At most one REST attempt and one fallback per call, no loop. No literal
  `"graphql"` in new code.

## Failures and recovery
| Failure | Behaviour / recovery |
|---|---|
| REST 429/403-rate/5xx/transport | one fallback, logged; 3 in a row opens the breaker; it re-opens on each failed probe |
| GraphQL also exhausted | GhApiError naming both; each site's fail-open/raise posture unchanged |
| cloud session | never falls back; REST error re-raised with `.hint` remediation |
| malformed REST payload | GhApiError(kind other), no fallback; the strict reader raises and its callers park/refuse |
| breaker/log corrupt or unwritable | treated as closed; write failure swallowed; self-heals on next write |
| symlink under `.sdlc/state` | persistence off for the call, `REFUSED` note, read proceeds; nothing written outside |
| crash mid-write (single writer) | tmp + `os.replace`: old or new file |
| concurrent workers | fixed `<name>.tmp` lets two writers interleave, so a torn file is possible: read as corrupt = closed breaker / empty log, self-heals on next write; lost increments delay opening. Not tested, stated |
| hung REST call | `_run_gh` has no timeout; only a runner raising TimeoutExpired yields `transport`. Ceiling |
Scale: each read costs one small file read, plus one write only on failure or reset. A comment read
costs `1 + ceil(n/100)` requests (all) or at most 3 (tail of 100 or fewer). The log is bounded at 200
entries (~30 KB). Liveness: the newest entry's age in `gh-fallback.json` and the stderr-on-open line are
the tell. An open breaker with no new entries after its cool-down means REST recovered.
