## Design
1. GATE. In `skills/sigma-loop/scripts/sources.py` add property
   `GitHubSource.board_active`: False if `not self.project_enabled`; True if `gh_api.graphql_available()["available"]`
   (bare call, env only, no probe, no network); else write ONE stderr line (guarded by `getattr(sys, "_sigma_board_graphql_noticed", False)`, set True after the write, in try/except) and return False. Once-state lives on the `sys` module, NOT a module global and NOT an env var: each consumer loads its own copy of sources.py via
   `spec_from_file_location` (sources.py:177 `_load`, `doctor._load_loop_script`, triage.py:52, status.py `_load_sources`) with no
   `sys.modules` caching, so a module global would print once per copy; an env var would silence child processes and leak. `project_enabled` stays a plain attribute
   (tests assign it); it remains config intent.
   Notice wording (single, fixed): `sigma: GitHub GraphQL is unavailable here (cloud proxy or SIGMA_GH_GRAPHQL=off);
   Projects board calls are skipped this run. sdlc:* labels remain the source of truth.`
2. SWAP the raw reads onto the gate: sources.py 1889 (`_ready_lane`), 3110 (`_archive_card`), 3882
   (`_set_board_status`), 3923 (`_apply_custom_fields`), 5248 (`set_board_phase`: `self.board_active and number`);
   external readers promote.py:618, unpark.py:453, auto_unpark.py:385 (`getattr(source, "board_active", False)` so a
   hand-rolled test stub without the attribute does not AttributeError). Reason for the externals: with the board off,
   `_set_board_status` returns False correctly, and reading raw `project_enabled` would print a FALSE "board move FAILED".
3. ENSURE_BOARD GATE (verified in the worktree: `_ensure_board` ~4131 has no check and goes straight to `_find_project`).
   Put the gate inside it, first line: `if self.project_enabled and not self.board_active: return False` (the
   `project_enabled and` keeps direct calls with config-off byte-identical to today; the three callers 3113/3885/3926 keep
   their own guards). `_write_blocker_promotion` (~4701) is reachable only via `_promote_blockers` <- `_sync_backlog` <-
   `_ensure_board`, so it is covered by this gate; NO separate wrap and NO claim of a closed ungated path. `_board_queue` (~2016) references `board_active` itself: add `if self.project_enabled and not self.board_active: return None`
   before its `_ready_lane()` use (None = label queue, today's fallback; config-off behaviour byte-identical), so the AST rule
   needs no callee heuristic.
4. NOT gated, decided and documented: `_run` and `_graphql` generically (they also carry label transitions, `_swap_labels`,
   `_label_node_ids`, `_issue_node_id`, and `reconcile.py` timeline reads: label writes are not the board, other slices'
   business, named as residual in docs). Human-invoked tools (`doctor.py`, `board_migrate.py`, `board_setup.py`,
   `board_layout.py`) stay ungated because they are explicit operator gestures on their own `run`, they already fail open
   to "could not check" / refuse without the `project` scope, and a silent skip would hide the very failure the human
   invoked them to see. Documented as the deliberate refusal, not left implicit. `loop.py` has no board call of its own;
   the qc phase boundary reaches the board through `phase_report.py:1891` -> `source.set_board_phase`, which the gate covers.
5. DOCTOR. Keep the single existing row `GitHub GraphQL unavailable (cloud proxy)`; rewrite only its `fix` text in
   `doctor._graphql_capability_rows` so it states facts, KEEPING every substring `tests/test_doctor.py` already asserts
   ("board/Projects mirroring", "gh pr merge --auto", "timelineItems (blocker/dependency edges)", "gh issue|pr via GraphQL
   until migrated (#801 slices 2-4)", "detection only; REST migration is in progress, not complete", "SIGMA_GH_GRAPHQL",
   "draft readiness (gh pr ready)", "Unit landing uses REST only"). Add: "board/Projects mirroring is SKIPPED, not failed
   (one notice per run; sdlc:* labels remain the source of truth); the doctor's own board rows and board_migrate /
   board_setup / board_layout are operator-invoked and are not gated (they may report could-not-check)." Exactly what is off
   = board/Projects mirroring (skipped), `gh pr merge --auto` arming, timelineItems blocker edges, GraphQL issue/PR paths
   not yet migrated, draft readiness and merge-queue landing.
5b. DOCTOR QUEUE ROW. `doctor._pick_path_gate_state` (def ~1708, `_ready_lane()` call ~1747) builds a `GitHubSource` and calls `_ready_lane()`, which would return None
   with the gate (printing the stderr notice and a misleading 'LABEL-ONLY (not yet) ... run board_migrate' hint). Before that call,
   check `sources.GitHubSource(...).board_active` (same instance); if false return `board skipped: GraphQL unavailable (labels are the
   source of truth)` and do not call `_ready_lane`. This replaces the earlier claim that the doctor is "not gated": its board
   rows that go through `GitHubSource` follow the gate, the operator tools (`board_migrate`, `board_setup`, `board_layout`) do not.
6. STATUS. `skills/sigma-status/scripts/status.py`: one silent-unless-relevant segment (~8 lines, idiom of
   `_awaiting_merge_segment`): when the config has `discovery.github.project.enabled` true AND `gh_api.graphql_available()`
   is false, append ` | board: skipped (GraphQL unavailable); labels are the source of truth`. Reuse the existing `status._load_sources()` (cross-loads sources.py; status.py ~162 already uses `src.gh_api`), so NO new loader
   (verified; None => ""); fail-open to "" on any error.
7. NOTICE ASYMMETRY. The `sys`-attribute once-state means a long-lived watch daemon prints the notice once ever across all its loaded copies of sources.py, not once per tick (acceptable: the status segment and doctor row repeat the fact). The new test runs `status.py` and `phase_report` consumers under `capsys` to prove they print at most the one notice.
8. DOCS (no home-directory paths). `CHANGELOG.md` `## Unreleased`: new top entry "Board gate when GraphQL is unavailable (#895,
   slice 5; refs #895)": what is skipped, one notice per process, labels unchanged, ungated human tools named, `_swap_labels`
   residual, measured = recording test only, NOT tested live. `docs/cloud-sessions.md`: fix line 10 ("writes (4b/4c) and
   the board remain"), line 192 ("board and project writes" deferred), lines ~575-581 ("the board sites (slice 5)"), and
   line ~32 doctor description; add a short "Board (#895 slice 5)" section: exact list of what is off in cloud (Projects v2
   card moves, custom/priority field writes, archive, backlog seeding, phase field, board-queue pick falls back to label
   queue), the single notice text, still GraphQL (`_swap_labels`, `_label_node_ids`, `_issue_node_id`, reconcile timeline),
   ungated tools, cost O(1), NOT tested live. WRITE-SURFACE UNTOUCHED: the gate string is generated at `tools/readiness/write_surface.py` ~204 and repeated in
   `docs/launch/write-surface.md`/`.json` for every `sources.py` row (label writes included), so a board-only wording change means
   editing generator+json+md together and splitting rows; the string "board writes require project.enabled" stays true (it is a
   necessary, now not sufficient, condition) and the ratchet checks sites, not wording. Leave all three alone; the new condition
   is documented in `docs/cloud-sessions.md` instead.
9. SCALING / FAILURE. Per guarded call: one `os.environ` lookup plus one small dict build (`graphql_available`, probe off),
   so 10x/100x board calls cost 10x/100x of that lookup, no I/O, no growth, no lock. Notice flag is one `sys` attribute per process.
   Failure mode FAIL-OPEN: if `graphql_available` itself raised, the property would propagate; so wrap it in try/except
   inside `board_active` and treat an exception as "available" (today's behaviour). The notice write is try/except too.
   Recovery: unset the env var / `SIGMA_GH_GRAPHQL=on`, next process mirrors again; skipped cards are re-seeded by the
   existing `_sync_backlog` on the next gated board touch (existing mechanism, not new).

Contents of `tests/test_board_gate.py` (each test docstring says whether it is red-before-change or characterisation):
- `test_every_board_call_function_is_gated` (AST over sources.py). Algorithm: (1) board functions B = every `FunctionDef` containing
  a list literal whose first element is the string `"project"`, or a string `"project*"` argv element used with `item-list`/`item-edit`/
  `item-add`/`item-archive`/`field-list`/`field-create`/`link`/`create`/`list`/`view`, or an `"api","graphql"` literal alongside a
  string containing `ProjectV2`/`projectV2`. (2) A function G(f) "is gated" iff its body references the attribute `board_active`
  (or `graphql_available`), OR every `self.<f>(` call site is inside a gated function (recursive, cycle-safe, memoised). (3) For each f in B: gated(f) required; there is NO callee-before-argv rule. (4) f with zero callers and no own reference is
  ungated, so it fails. ALLOWLIST is an empty dict literal in the test; an entry needs a comment naming why. Red only on a NEW
  board-argv function (e.g. one calling `_ensure_board()` then a board argv without referencing `board_active`) that is neither gated nor reached solely through gated callers.
- `test_project_enabled_read_only_inside_board_active` (AST: `Attribute(attr="project_enabled")` loads in `skills/` appear only in `board_active`, the `_ensure_board` first line, and the `__init__` assignment).
- `test_unavailable_graphql_makes_no_board_call` (monkeypatch `CLAUDE_CODE_REMOTE=1`; recording `run` that raises on any argv with first token `project` or `graphql` second on a board query; drive `next_pending`, `claim`, `complete`, `park`, `_set_board_status`, `set_board_phase`, `_ensure_board`; no raise, no board argv).
- `test_one_notice_per_process_across_instances` (delete the `sys` attribute; two instances AND two separate loads of sources.py via its `_load` idiom; exactly one stderr line; also runs the status segment and `phase_report` consumer under `capsys`).
- `test_graphql_available_board_argv_unchanged` (twin with `SIGMA_GH_GRAPHQL=on` and the stock boardfake: board still mirrors, argv non-empty; byte-identity is evidenced ONLY by the existing boardfake suites passing unchanged, no captured fixture is claimed).
- `test_promote_unpark_no_false_board_failed_warning` (board off: no "board move FAILED" text).
- `test_auto_unpark_emits_no_set_status_with_board_off` (board off: `compute_unpark_actions` output contains no `set-status`, so `triage._execute_action` ~2316 never raises on a False return).
- `test_board_active_fails_open_if_probe_raises`.
Plus: in `tests/test_doctor.py` one fix-text row test and `test_pick_path_gate_state_board_skipped_when_graphql_unavailable` (CLAUDE_CODE_REMOTE=1: returns 'board skipped: GraphQL unavailable', no 'board_migrate' text, `_ready_lane` not called); in `tests/test_status.py` one segment test (shown / silent).

## Controls
Documented gesture for all: `env -i PATH=/opt/homebrew/bin:/usr/bin:/bin HOME=$HOME $HOME/.sigma-venv312/bin/python -m pytest tests/test_board_gate.py` (no exported `CLAUDE_CODE_REMOTE`; the tests set their own via monkeypatch). Each break made, named test seen RED, reverted.
- Remove the `board_active` reference from `_set_board_status` -> `test_every_board_call_function_is_gated` fails (this is the "new board call without the gate fails" control) AND `test_unavailable_graphql_makes_no_board_call` fails.
- Add a new method that calls `self._ensure_board()` then a board argv without referencing `board_active` -> structural test fails.
- Remove the `board_active` line from `_board_queue` -> structural test fails.
- Add a new ungated method that calls `self._run(["project", "item-list", ...])` -> `test_every_board_call_function_is_gated` fails (also run it with a method gated only via a caller to see it stay green).
- Add a raw `self.project_enabled` read in a new method -> `test_project_enabled_read_only_inside_board_active` fails.
- Delete the `_ensure_board` first-line gate -> `test_unavailable_graphql_makes_no_board_call` fails (it drives `_ensure_board`).
- Make `_pick_path_gate_state` call `_ready_lane` unconditionally -> the new doctor queue-row test fails.
- Make auto_unpark emit `set-status` unconditionally -> `test_auto_unpark_emits_no_set_status_with_board_off` fails.
- Make the notice flag a module global or per-instance -> `test_one_notice_per_process_across_instances` fails.
- Make `board_active` ignore `graphql_available` (return `project_enabled`) -> `test_unavailable_graphql_makes_no_board_call` fails.
- Revert promote.py:618 to `source.project_enabled` -> `test_promote_unpark_no_false_board_failed_warning` fails (same for unpark / auto_unpark).
- Make `board_active` always return False -> `test_graphql_available_board_argv_unchanged` and the existing `tests/test_github_project.py` fail (proves the byte-identity twin can fail). Run this one BOTH with the `env -i` gesture and with plain `python -m pytest` from the ambient dev shell.
- Change the doctor fix text to drop "SKIPPED, not failed" -> the new doctor row test fails; drop "board/Projects mirroring" -> the pre-existing test fails.
- Make the status segment unconditional -> the silent-case test fails.
- Remove the try/except in `board_active` and make `graphql_available` raise -> fail-open test fails.
- Sensitivity note (AGENTS.md ports rule): all tests are deterministic AST or recording tests, no probabilistic race, nothing collapses.
