## Design
1. `sources.py` `note()` (:3327-3388), verified: loop at :3377 calls `self._run(["issue","comment",...])`, then a REST
   fallback with `-X`. Replace the body with:
   - head unchanged (`hsg.blocks_issue_write` -> `return`).
   - `fell = []`; each attempt: `self._issue_comment(goal, text)` but with the fallback observed. `_issue_comment`
     takes no override, so call `gh_api.comment_issue(self._run, self._n(goal), text, **{**self._write_kw(),
     "fallback_run": lambda a: (fell.append(1), self._run(a))[1]})` (one line; `_write_kw` :1338 supplies repo,
     sdlc_dir). Do not add a parameter to `_issue_comment` (six other callers).
   - `except gh_api.GhApiError as exc`: `if fell or gh_api._write_case(exc) not in ("server_5xx",
     "transport_ambiguous"): raise`; else back off `_NOTE_RETRY_BASE * 2**attempt` and re-POST, up to `_NOTE_RETRIES`
     attempts, then raise the last error. Return None.
   - Classification reads `_write_case`, which looks at `.hint` (gh stderr) and the `__cause__` chain ONLY. Deviation from
     "classify on `.kind`/`.status`": `GhApiError.kind`/`.status` are filled by `classify()` from `str(exc)` when no hint
     exists, and that string embeds argv and so the comment body (a body saying "HTTP 502" must not trigger a retry).
     `_write_case` is the same function `comment_issue`'s own policy uses. Never `str(exc)`.
   - Why `fell`: if the single policy fallback (primary rate limit, non-cloud) itself fails 5xx, that must raise, not loop
     back to REST and trigger a second fallback. `fell` makes "exactly one GraphQL attempt per note()" true.
   - `ValueError` from `_n` on a non-numeric ref propagates (callers catch `Exception`; none passes non-numeric).
2. Table of outcomes (per attempt): 2xx -> return; REST 5xx / transport -> retry REST (<= `_NOTE_RETRIES`) then raise;
   primary rate limit -> `comment_issue` makes ONE `issue comment` fallback (not in cloud: `graphql_available` env gate,
   gh_api.py:255/:793), result or error returned/raised, never retried; 401/403/404/422/secondary limit/proxy/other ->
   raise at once. A `TimeoutExpired` cause is `transport_ambiguous`, which `comment_issue` forbids falling back on.
