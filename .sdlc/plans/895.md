## Design (binding)

### D1. Field whitelist and the converter
`gh_api.PR_FIELDS` is a CLOSED tuple, exactly what the seven sites request and nothing more:
`number, title, body, state, headRefOid, headRefName, mergedAt, closedAt, autoMergeRequest, isCrossRepository,
author, comments`. `to_gh_pr_shape(pr, fields, comments=None)` emits requested keys only; a field outside the
tuple (`mergeable`, `statusCheckRollup`, `reviewDecision`, ...) raises `ValueError` at the top of `view_pr_gh`,
before any call (so a later slice cannot silently get a wrong mapping). Mappings (all DERIVED, UNMEASURED):

| gh field | from REST pull | rule |
|---|---|---|
| number | `number` | int; non-int -> `GhApiError` malformed |
| title | `title` | null -> "" |
| body | `body` | key absent -> `GhApiError` (null -> ""), same rule as the issue converter |
| state | `state` + `merged` / `merged_at` | `merged is True` or truthy `merged_at` -> `MERGED`; else `open` -> `OPEN`, `closed` -> `CLOSED`; anything else or absent -> `GhApiError` malformed (never a guess) |
| headRefOid | `head.sha` | missing/non-str -> `""` (the existing park / no-anchor arms then fire) |
| headRefName | `head.ref` | missing -> "" |
| mergedAt / closedAt | `merged_at` / `closed_at` | passthrough (None allowed) |
| autoMergeRequest | `auto_merge` | key ABSENT -> `GhApiError` (never read as null); null or object passes through, truthiness is what callers read |
| isCrossRepository | `head.repo`, `base.repo` | `head` or `base` not a dict -> `GhApiError`; `head.repo` null (deleted fork) -> TRUE; else `lower(head.repo.full_name) != lower(base.repo.full_name)`; `base.repo` missing -> `GhApiError`. Unknown biases to TRUE or to an error, never to FALSE |
| author | `user.login` | `{"login": <raw REST login>}`; NOT bot-mapped (the issue converter's `app/x` mapping is deliberately not applied) because R3 compares the PR author with comment authors, and both come from REST. Missing `user` -> `{"login": ""}` |
| comments | issue comments (D3) | each `{id, author:{login}, body, createdAt, authorAssociation?}`; `authorAssociation` emitted ONLY when REST sent `author_association` so the `ValueError("a marker comment carries no authorAssociation")` park still fires |

A non-dict pull body raises `GhApiError` (malformed, kind other, no fallback).

### D2. `view_pr_gh` (REST first, one fallback, shared machinery)
`view_pr_gh(run, number, fields, repo=None, *, gql_run=None, env=None, sdlc_dir=None, now=None)`:
`number` is coerced with `int(str(number))` (callers hold `rec["pr"]` as str or int; a non-numeric value raises
`ValueError`, which every caller's broad `except` already treats as "unreadable"). The REST leg is the existing
`view_pr(run, n, repo)` (`GET pulls/{n}`), plus `pr_comments` only when `"comments" in fields`, then
`to_gh_pr_shape`. It runs through `_rest_first("pr_read", n, "PR #n read", "gh pr view", rest, fallback, ...)`: the
SAME breaker, the SAME bounded log, the SAME rules as `read_issue` (fall back only on `rate_limit` / `server` /
`transport`, only while `graphql_available(env)` says so, ONE fallback, never retried). The fallback
`_pr_fallback(gql_run, n, fields, repo, rest_err)` runs ONE `["pr","view",str(n),*repo_args,"--json",",".join(fields)]`
INSIDE `gh_api.py` (EXEMPT from the ratchet), degrades malformed JSON to `{}` like the callers' parsers did, and
filters to `fields`. Shared breaker consequence (stated in docs): issue reads and PR reads open and reset ONE breaker
and share the 200-entry log; a burst of PR failures can open the breaker for issue reads too.
`view_pr` (raw GET) stops being caller-less; the module docstring is updated to say so (only `create_pr` / `merge_pr`
remain caller-less).

### D3. `pr_comments(run, number, repo=None, page_cap=PR_COMMENT_PAGE_CAP)`
`GET issues/{n}/comments?per_page=100&page=k`, ascending (REST default), stop at the first short page. Constant
`PR_COMMENT_PAGE_CAP = 30` (3000 comments). If page `page_cap` comes back FULL, raise `GhApiError(kind="other")`
("PR comment list exceeds the cap"): R3 is fail-closed, truncation would hide a trusted `sigma:block`. Kind `other`
never falls back (so a PR with >3000 comments parks, it is not silently read through `gh`). A non-list page or
non-dict row raises `GhApiError`. Cost: `1 + ceil(n/100)` REST calls per `_comment_directive` against 1 GraphQL call
today (named as a ceiling in the docs: a PR with 1000 comments = 11 calls, 100x = capped at 31).

### D4. `pr_for_branch_gh` (R11, view BY BRANCH)
`pr_for_branch_gh(run, branch, fields, repo, *, gql_run=None, env=None, sdlc_dir=None, now=None)`; `repo` is REQUIRED
(`owner/name`; no placeholder form, a missing/slashless repo raises `ValueError`). REST leg:
`GET repos/R/pulls?head=<owner>:<quote(branch)>&state=all&sort=created&direction=desc&per_page=30`, no paging.
Selection: the first `state=="open"` row, else the first row (newest created). Zero rows -> return `None` (the caller's
"no PR for this branch" arm; `gh pr view` on a branch with no PR is a gh error, which doctor's never-raising runner turned
into a falsy result, i.e. the same arm). Rows are shaped through the same converter (list rows carry `state`,
`merged_at`, `closed_at`, `head.sha`, `head.ref`, `number`; `merged` is absent from list rows, so MERGED comes from
`merged_at` only; `isCrossRepository` / `autoMergeRequest` are not supported in this call and raise `ValueError` if
requested). Fallback = ONE `["pr","view",branch,"--repo",repo,"--json",fields]` inside gh_api via `_rest_first`
(op `pr_branch_read`). Named differences, all UNMEASURED and written into the docs:
 (a) `gh pr view <branch>` resolves across forks; `head=<owner>:<branch>` sees same-owner heads only, so a fork PR on a
     same-named branch becomes invisible (R11 is a diagnostic; invisibility = no alarm, fail-open). No client-side
     scan of all open PRs.
 (b) gh's open-vs-most-recent preference is assumed (open first, else newest); not measured.
 (c) more than 30 PRs for one head: the 30 newest only (ceiling).

### D5. Caller adapters (the convention gap)
`work._run(cwd, argv)` raises `RuntimeError("<argv joined>: <detail>")` with NO `.hint`; `gh_api` wants
`run(args_without_gh)` raising with `.hint`. Two small adapters, each about eight lines, no `["gh", *x]` literal that
the ratchet would count (rule 3 counts `["gh", <non-constant>, ...]`: the adapter builds with `["gh", *args]`, whose
second element is a Starred, so it WOULD count as a rule-3 site: build it as `[binary, *args]` with
`binary = "gh"` assigned once, or reuse an existing wrapper; the implementer prints `scan()` and the number must
not move up):
- `work._pr_api_run(run, cwd)`: returns `def r(args)` calling `run(cwd, [GH, *args])`; on `RuntimeError` it re-raises
  a new `RuntimeError(str(exc))` whose `.hint` is the detail AFTER the `"<argv>: "` prefix (computed as
  `msg[len(prefix):]` when `msg.startswith(prefix)`, else the whole message). Reason: classification must never read
  argv (a repo or branch named `timeout-svc` must not read as transport). Proxy-block text already leads `_run`'s
  detail, so `gh_session.proxy_session_block` still matches on the hint. Non-RuntimeError exceptions pass through
  (`gh_api._call` wraps them). `work.py` gains `gh_api = _load("gh_api")` next to `gh_session`.
- `rebase_brief.pr_description(run, cwd, number)`: same adapter shape (`run(cwd, argv)` convention), gh_api loaded
  lazily and by path from `skills/sigma-loop/scripts/gh_api.py` (the sibling skill ships in the same plugin; inside the
  function so import never fails), any load failure returns `None` (fail-open, as today).
- `doctor._stray_commits_after_merge`: uses the EXISTING `_raising_gh(run)` (doctor's single-arg never-raising `run`
  turned into a raising one with `.hint`), `_load_loop_script("gh_api")`, no `sdlc_dir` (doctor never writes the
  breaker or the log, same as `_list`), `repo=gh_cfg["repo"]`.
