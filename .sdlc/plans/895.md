## Design deltas (baked from the dossier)
1. `_rest_first(op, number, what, rest, fallback, *, env, sdlc_dir, now)` carries the exact breaker,
   `was_open`, `fallback_ok`, log, `newly_open` and stderr text of today's `read_issue`; `read_issue`
   becomes a thin caller. Existing `tests/test_gh_api.py` must pass UNCHANGED (behaviour-preserving).
2. `list_issues_gh(run, fields, *, repo=None, labels=(), state="open", cap=200, sort="created",
   direction="desc", gql_run=None, env=None, sdlc_dir=None, now=None)` -> list of dicts in
   `gh issue list --json` shape (`to_gh_shape` per item; `fields` subset of GH_FIELDS, checked).
   - REST leg: `sources.fetch_issues_rest` through a run wrapped by `_call` so failures are CLASSIFIED
     (existing `list_issues` loses the kind). Each page is validated to be a `list`; a non-list page
     raises `GhApiError(kind="other")`, no fallback (this keeps the sites' dead-looking `isinstance`
     guards honest and keeps test_assign.py:581's warning arm alive).
   - Order: refuses (ValueError, before any call) any sort/direction the fallback argv cannot express.
     Allowed: `created/desc` and `updated/desc`. `created/asc` and `updated/asc` -> ValueError. The
     default is `direction="desc"` (opposite of `fetch_issues_rest`'s asc) because `gh issue list` is
     newest-first and a >cap board must return the NEWEST rows.
   - Fallback argv (only place gh_api builds an `issue list` argv): `["issue","list",*(--repo R),
     *(--label L each),"--state",state,"--json",",".join(fields),"--limit",str(cap)]` plus
     `["--search","sort:updated-desc"]` when sort=="updated". Result must be a JSON list else
     `GhApiError(other)`, no second call. Fallback runs through `gql_run or run` AFTER the
     `graphql_available(env)` gate, inside `_rest_first`; callers cannot hand it a different gate.
   - Log entry: `op: "issue_list"`, `number: None`; `read_issue` log keys stay byte-identical.
3. `GitHubSource._list_issues(fields, labels=(), state="open", cap=None, sort="created", direction="desc")`
   passes `self._run`, `self.repo or None`, `gql_run=self._run`, `sdlc_dir=self.sdlc_dir`, cap default
   `self._BOARD_ITEM_LIMIT`.
4. Per-site direction (STATED, not defaulted silently):
   | site | sort/direction | note |
   |---|---|---|
   | auto_unpark parked/goal_blocked loop | created / desc | as old default |
   | auto_unpark blocking (state all) | created / desc | set membership only |
   | reconcile census | created / desc | `truncated = len>=limit` + `_warn_truncated` kept |
   | assign `_active_members` | created / desc | no label; "newest 50 issues" intent preserved |
   | doctor card, blocked, unreachable, orphan, multi-state | created / desc | cap 200 |
   | doctor `_dependency_marker_scan` | updated / desc | `candidates[:max_issues]` depends on it; replaces `--search sort:updated-desc` on the REST leg |
   No site relies on created-asc today, so none passes asc (and asc is refused anyway).
5. Doctor: `run` takes full argv incl `gh` and NEVER raises (failure = falsy `_RawFailure`). Build the
   raising wrapper ON TOP of existing `_gh_runner(run)` (doctor.py:1228): `_raising_gh(run)` calls
   `_gh_runner(run)(args)`; if the result has `.raw` (is a `_RawFailure`) raise
   `RuntimeError` with `.hint = _failure_text(res)`; else return it. NO new `["gh", *args]` literal, so
   the doctor ratchet lands at 7, total 74. Helper `_list(run, gh_cfg, fields, labels, state, cap, sort,
   sdlc_dir=None)` calls `gh_api.list_issues_gh(wrapped, ..., gql_run=wrapped)` (SAME wrapper for both
   legs) via `_load_loop_script("gh_api")`; returns list or `None` on ANY exception, preserving each
   site's old falsy -> skip arm exactly (None / `[]` / `continue` per the sites table). Repo for site 5
   comes from the existing REQUIRED `--repo R` handling (not `repo_args`).
   Line 2513 `census(run=_gh_runner(run))`: route through the same raising wrapper (one-word change)
   so an outage is not an empty OK census; tested.
6. `doctor.check(...)` gains an optional `sdlc_dir=None` kwarg threaded to `_list`. DOCUMENTED in
   docs/cloud-sessions.md and CHANGELOG: when given, doctor now WRITES `state/gh-rest-breaker.json` and
   `state/gh-fallback.json` (previously doctor was read-only on state). Callers that pass nothing keep
   old behaviour: no breaker, no log.
7. `assign._active_members(..., sdlc_dir=None)` optional kwarg; `resolve_assignment` passes its
   `sdlc_dir`. Default run `sources._run_gh` unchanged. Fix its docstring sentence "REST-search-backed,
   never GraphQL" to what is true (REST list first, one bounded fallback).
8. Fail-open arms are untouched (`except Exception`): GhApiError is an Exception. Sites 1/2 keep
   `complete=False` / `set()` on ANY error (blast radius: a false empty blocking set removes labels).

## Failures and recovery
- REST outage: each site falls back once (cloud: none; the site's own fail-open arm runs). Breaker
  opens after 3 failures for 300 s where `sdlc_dir` exists; closes on the first REST success. Partial
  paging failure (page 3 of 50) discards pages and re-lists ONCE via `gh` -> consistent; if that fails
  too the site fails open (bounded). Sites with no `sdlc_dir` (assign without it, doctor without it)
  have no breaker: each costs REST + one fallback per run during an outage. Revert = one PR revert; no
  state format changes (breaker/log files are 2a's).
- Wrongful-removal guard: auto_unpark sites 1/2 stay `complete=False`/`set()` on any error so a
  failed read can never become an empty blocker set.

## Cost / scale (derived, not measured)
List = `ceil(n/100)` REST requests vs one GraphQL search per call. Doctor cap 200 = at most 2 per site;
multi-state scan 3 labels x 2 pages = up to 6. 5000-cap board reads (auto_unpark, reconcile census) =
up to 50 requests per read at the cap; at 10x boards that is the 5000-cap ceiling, at 100x the cap
truncates (reconcile already warns). REST core budget 5000/h: one full cap-5000 read is ~1%. Doctor
worst case with the default `network_timeout()` 15 s/call: ~45 s per site (2 REST + 1 fallback), ~135 s
multi-state; before ~15 s per site. DERIVED from the timeout, not measured.
