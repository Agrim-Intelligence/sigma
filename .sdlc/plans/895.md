## Design
1. WHY NOT `gh_api.bounded_runner` (read at gh_api.py:1071): it returns stdout only and RAISES `GhApiError` on any non-zero exit,
   timeout or `OSError` (a missing `gh` becomes a `GhApiError`). `cross_repo` needs `(rc, out, err)` with rc 124 on timeout so
   `_classify_failure` still sees the exit code and text; `feature_owner` needs `RuntimeError`; `ledger` needs `""`; today
   `FileNotFoundError` escapes all three. Re-deriving each shape from a `GhApiError` would change behaviour, so a new primitive
   is justified: `gh_api.run_gh(args, timeout=120) -> (rc, out, err)`, the one `["gh", *str args]` spawner;
   `TimeoutExpired` -> `(124, "", "gh: the call timed out after Ns")`; every other exception propagates unchanged.
   `gh_api.gh_argv(args) -> ["gh", *str args]` for seams that hand argv to an injected runner.
2. Wrappers keep names and signatures (tests monkeypatch `_run_gh`). `cross_repo._run_gh(args, timeout=GH_TIMEOUT_SECONDS)`
   returns `run_gh(...)` verbatim; `feature_owner._run_gh` raises `RuntimeError(stderr.strip() or "gh exited N")` on rc != 0,
   else `out.strip()`; `ledger._run_gh` returns `out.strip()` on rc 0 else `""`. TIMEOUT HONESTY: before this change NONE of
   the three had a timeout at all (a hung `gh` blocked forever); now a timeout is RuntimeError in feature_owner and `""` in
   ledger, both already read as "unknown" by their callers.
3. Loaders, cached at module level (a one-element list, like `board_setup._SOURCES`, so the ~1,500-line module is executed once
   per process, not once per call, and every call sees the same module object), lazy, so a partial install breaks the call and
   not the import. `cross_repo` and `feature_owner` reuse their existing `_load(name)` (`_HERE / f"{name}.py"`) through a new
   `_GH_API = []` + `_gh_api()`. `ledger` has no `_load`/`_HERE`, only ad-hoc blocks (managed_settings at ~584 is the
   pattern): add ONE small `_gh_api()` with a `_GH_API = []` cache, same `spec_from_file_location` idiom, NOT fail-open (a load
   error propagates; `actor` already catches everything and falls back to `$USER`).
4. Timeout caps, derived from the callers. `ledger.actor` IS reachable from a hook: `hooks/decision_gate.py` (PreToolUse on
   Edit/Write, no timeout in `hooks/hooks.json`) -> `ledger.safe_append` -> `append` -> `actor` -> `_run_gh`; each hook is a
   fresh process so `_ACTOR_CACHE` does not help. So `ledger._run_gh` passes a SHORT cap, `timeout=15`, to `run_gh` (an edit
   must not stall for two minutes on a dead network; the result `""` just means the `$USER` fallback). The 15 s is a
   judgement, not measured. I grepped `hooks/*` for `feature_owner` and `cross_repo`: no hook calls either (feature_owner's
   callers are `handoff.py`/`promote.py`/loop, cross_repo's the watch loop and `work.py`), so they keep `run_gh`'s 120 s default
   (cross_repo keeps its own 30 s `GH_TIMEOUT_SECONDS`). Watch-loop calls are separately bounded by `SIGMA_WATCH_CALL_TIMEOUT`.
5. `status._github_counts`: in the `src is not None` branch use `src.gh_api.gh_argv` (`sources.gh_api`, sources.py:191) for both
   lambdas; the `src is None` fallback (status.py:174) is untouched.
6. `board_setup.Board.gh` (skills/sigma-init/scripts/board_setup.py:179): load `gh_api` DIRECTLY by path
   (`_LOOP / "gh_api.py"`) through the file's own `_load`, cached in `_GH_API = []`, lazy, NOT through `_sources()` (that
   would execute `sources.py` and all its module-level loads, making every board call depend on sources.py being healthy).
   `argv = _gh_api().gh_argv(args)`; the `--hostname` splice at `argv[2:2]` is kept (`gh_argv` returns a fresh list).
7. `close_pr_gh.rest()`: also reject a body whose `merged` is truthy with `GhApiError` (no hint, so the case is
   `other_unparsed`, no fallback; bodies without a `merged` key still pass). The claim that a real merged PR also answers
   405/422 on PATCH is DERIVED and UNMEASURED; the Control below covers ONLY the 200-with-`merged:true` path. The existing
   `_json` mapping already sends 422 to `invalid_422` and 405 to `other_unparsed` (neither falls back); tests for those two are
   characterisation of existing behaviour. `close_design`'s `_design_pr_state` re-read maps MERGED to "merged by someone else",
   so the guard composes with its caller.
8. Scaling: same single `gh api` spawn per call, no per-item cost; status = 1 `api user` + a fixed N count fetches. The 10x/100x
   label-create cost moves to slice 3c. `_write_priority_label` stays add-then-remove (documented non-atomic).
