# #229 plan — init preflight

## Decisions (recorded; nobody available to ask)

- D1 New stdlib module `skills/agrim-init/scripts/preflight.py`; doctor and work.py load it by path
  (the established cross-skill idiom: `doctor._load_loop_script`, `sdlc_init._legacy`).
- D2 Checks, in order, each `{id, name, ok: True|False|None, detail, fix, meanwhile, blocking}`:
  `git` (is a work tree, has a commit), `remote` (work.remote, default origin; lists other remotes
  when it is missing), `base` (work.base or current branch exists locally AND on the remote via
  `ls-remote`), `gh-installed`, `gh-auth`, `scopes` (repo, workflow, read:org if owner is an org,
  project if a board is enabled). `ok: None` = cannot verify (fine-grained/app token, owner type
  unknown, ls-remote timed out) — printed as `CANNOT VERIFY`, never as OK.
  Dependent checks are SKIPPED (not run, said so) when their prerequisite failed.
- D3 Each failure prints one remediation block per host (Claude Code / Codex / Cursor): exact command,
  where to run it on that host, and what Sigma does meanwhile. `gh` absent -> install instructions,
  never `gh auth login`.
- D4 Init: non-git directory -> REFUSED before writing anything (exit 2). A fresh `git init` with no
  commit is NOT refused (it is the normal first run; existing init tests pin it) -- it is reported. Other failures -> scaffold
  proceeds, report printed, exit 0; no remote / no gh with work on -> a printed DECISION with the
  exact config line and a gesture (`preflight.py local-only <sdlc>` / `use-remote <sdlc> <name>`),
  never flipped silently. Claude Code SKILL.md: ask. Codex/Cursor: relay the block.
- D5 Doctor: rows `git repository`, `git remote`, `base branch pushed`, `gh installed`, `gh auth`,
  `gh token scopes`, `gh project scope` — gated on `work.enabled` or `discovery.source == github`.
  Fix text comes from the failing check. Injected fake `run` keeps working (new `which=` seam).
- D6 work.py start: on `git fetch` failure only, ask preflight whether the remote exists; if not,
  raise the SAME preflight message. Zero added calls on the happy path (test_docs §6e counts).
- D7 Timeout: `SIGMA_WATCH_CALL_TIMEOUT` (read via legacy.getenv), else its default 120 — the bound
  the fleet already uses for one hung git/gh call. (A new SIGMA_PREFLIGHT_TIMEOUT knob was dropped
  in implementation: one more env name to register for no measured need.) Process-group kill on overrun (POSIX killpg, Windows
  taskkill /T). A timeout is `CANNOT VERIFY` with the reason.

- D8 (implementation) `project` scope is required only under github discovery: the template ships
  `project.enabled: true` with `source: local-goals`, where no board is mirrored.
- D9 (implementation) work.py diagnoses a missing remote only on BOTH signals: git's own
  `'<remote>' does not appear to be a git repository` AND the name absent from `git remote`.
- D10 (implementation) tests/conftest.py: guard `subprocess.Popen` against live gh as well (the
  preflight runner needs Popen for the process-group kill), and give child processes an empty
  GH_CONFIG_DIR and no token so a spawned init cannot reach the network.

## Steps (test-first)

1. tests/test_preflight.py: scope parser (classic quoted, classic bare, none, fine-grained, missing
   line, implied read:org), each check with fake runner/which, renders (3 host blocks, no
   `gh auth login` when gh absent), local-only/use-remote gestures, timeout runner kills the tree.
2. preflight.py to green.
3. sdlc_init main(): refuse non-git; print report after scaffold (before the verify report, which
   stays last). Update init tests that scaffold non-git dirs.
4. doctor: preflight rows + `which=` seam; tests incl. gh-absent control.
5. work.py: fetch-failure diagnosis; test with fake runner.
6. SKILL.md (init, doctor), CHANGELOG Unreleased.
7. Acceptance a-d executed with real git/PATH, transcripts in `.sdlc/evidence/229/`; break each guard
   once and see it red.

## Done when

a) non-git: refused with `git init` remediation; b) no remote: decision + config line, and work.py
start prints the same message; c) PATH without gh: install instructions, fallback offered, no `gh
auth login`; d) token without workflow: `gh auth refresh -h github.com -s workflow`; `loop.py verify`
green.
