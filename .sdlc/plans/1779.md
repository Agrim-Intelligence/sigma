## Format spec (the contract the code and tests share)

Constants (module level, declared once):
`QUALITY_VERSION = "iso-iec-25010-2023+sigma-ext/1"`; `CONTAINER_WARN = 20`; `REASON_MIN_WORDS = 3`;
`_SMALL_LANE_REASON = "small lane"`; `_REASON_BLOCKLIST` (a frozenset, one constant);
`_QUALITY_COLUMNS`, `_SCENARIO_FIELDS`, `_STRIDE_COLUMNS`, `_STRIDE_LETTERS`. Lanes come from
`discovery.LANES` and `discovery.DEFAULT_LANE` (never redefined).

Category data (order is the contract, pinned literally by a test): `performance_efficiency`, `compatibility`,
`interaction_capability`, `reliability`, `security`, `maintainability`, `flexibility`, `safety` (origin
`iso-25010-2023`), then `observability`, `data_retention_privacy`, `cost` (origin `sigma-extension`).
Each entry carries `id`, `label`, `origin`, `ask`. `nfr_bank()` returns a fresh deep copy on every call
and `check_quality` reads the category ids from the same tuple (one copy of the names in code).

`nfr-bank` output (stdout, `json.dumps(..., indent=2)`, exit 0, no arguments; any extra argument is a usage
error): `{"version", "categories": [{id,label,origin,ask}...], "scenario_fields": ["Source","Stimulus",
"Environment","Response","Response measure"], "stride": [{"letter","name"}... S,T,R,I,D,E in that order],
"answer_forms": ["scenario","N/A: <reason>","open: D-<n>"]}`.

Main table (under `## Quality requirements`): eight columns, header exactly
`Category | Answer | Source | Stimulus | Environment | Response | Response measure | Evidence`
(case-insensitive after `_norm`). The table is the first pipe-table whose first header cell is `Category`.
Row order is not enforced (presence, uniqueness and spelling are). Row key is the first cell, a bank slug,
case-sensitive.

Answer forms (case-sensitive): `scenario`; `N/A: <reason>`; `open: D-<n>` (regex `^open: D-(\d+)$`).
Anything else is a violation. For `N/A` and `open` rows the five scenario cells must each be `—`; the
Evidence cell of those rows is not checked (D-9).

Reason rule, applied in this fixed order to the text after `N/A:` (after `_norm`):
1. empty -> `N/A without a reason`;
2. lower-cased equals `small lane` -> legal in lane `small`, a violation in `medium` and `large`
   (message `only legal in the small lane`); the 3-word rule is skipped for this literal only;
3. lower-cased (also with trailing `.,;:!` stripped) is in the blocklist -> `placeholder reason` violation;
4. fewer than 3 whitespace-separated words -> `at least 3 words` violation.
Blocklist (default list, one constant): `n/a`, `na`, `none`, `nil`, `tbd`, `todo`, `-`, `—`, `–`, `...`, `?`,
`unknown`, `no`, `later`, `not applicable`, `to be determined`, `not applicable here`, `not yet known`.

Scenario row checks, in order: all five fields non-empty and not `—`; Response measure passes (an ASCII digit
anywhere, or matches `^test:\s*\S`; a bare `test:` fails; form not truth, stated in the docstring once);
Evidence non-empty and every token (split on commas and whitespace) is one of: `agent-proposed`;
`BR-<n>` present as a first-column cell of a table row in `## Blast radius`; `D-<n>` present as a
`- **D-<n>.**` bullet marker in `## Doubts`; `Dossier:<id>` with id in `[A-Za-z0-9_-]+` (not verified);
`file:line` matching `^[\w./-]+:\d+(-\d+)?$` (existence not checked, no filesystem access). `—` or
anything else is a violation naming the token. In effective lane `small`, a scenario row's Evidence must
also contain at least one `BR-<n>` token.

Lane: read from the header lines before the first line starting `## `, regex `\*\*Lane\*\*:\s*(\w+)`. Missing
or not in `discovery.LANES` is a violation (`lane: missing or not one of small, medium, large; proceeding
as medium`) and the rules run as `discovery.DEFAULT_LANE`. `--lane` (or `lane_override`) selects the
effective lane for the rules; the header is still checked for missing/unrecognised (always reported); a
header-versus-flag mismatch is not reported (D-6).

Large lane: the `security` row may not be `N/A` (violation); a STRIDE table is required.
STRIDE table (long form, D-3): the first pipe-table in the section whose first header cell is `Container`;
header exactly `Container | Threat | Mitigation`; one row per (container, threat), Threat one of `S,T,R,I,D,E`;
each container needs all six; Container must equal a first-column cell of the `## Components` table
exactly; a duplicate (container, threat) is a violation; Mitigation non-empty, and `ruled out: <reason>`
applies reason rules 1, 3 and 4 above (no small-lane literal here). The escape row is exactly one row
`— | — | <reason of at least 3 words, not blocklisted>` and must be the only row. A STRIDE table present in
a non-large lane is validated by the same rules (never silently ignored; D-8). Warning (not violation)
when more than `CONTAINER_WARN` distinct containers (20 does not warn, 21 does).

Other checks: any cell over `SENTENCE_CAP` (2000) is a violation, checked before any regex on that row;
a row whose cell count is not the header's is a violation per row (a doubled pipe changes the count);
a wrong main header is ONE violation and stops row checks (no per-row noise, no missing-row lines);
a duplicated `## Quality requirements` heading is a violation (the verb reports it itself, not only via
`REQUIRED_HEADINGS`); a `## Quality requirements` line inside a code fence is not read; missing section or
no `Category` table is one section-level violation plus a `missing row` line for each of the eleven
categories. Small-lane multi-slice warning: effective lane `small` and the slice table (read with the
existing `_parse_table`, throwaway violation list) has more than one data row; one row or no table never warns.

Violation message shape: EVERY line begins `<slug>: ` where slug is one of the eleven bank ids, or the two
reserved prefixes `lane` and `quality_requirements` (section-level, header, unknown or empty category,
cell-count of an unkeyed row). STRIDE lines begin `security: `. Missing row: `observability: missing row`.
Examples: `observability: missing row`, `cost: duplicate row`, `quality_requirements: unknown category
'observabilty'`, `reliability: scenario field Stimulus is empty`, `safety: Response measure 'fast' has no
digit and does not start with 'test:'`, `security: evidence token 'BR-99' is not a row id in ## Blast
radius`. Warnings use the same slug prefixes (`lane: small lane but 2 slice rows`, `security: 21 STRIDE
containers (> 20)`).

JSON result (stdout, `indent=2`, printed only when the artifact was read):
`{"ok": bool, "lane": effective lane, "rows": [{"category": slug, "answer": "scenario"|"na"|"open"|"invalid"}...],
"violations": [str...], "warnings": [str...]}`.
Streams: stderr lines are `goal_design.py quality: warning: <msg>` then `goal_design.py quality: VIOLATION: <msg>`,
mirroring `requirements`. Exit 0 clean (warnings allowed); exit 2 on any violation, a refusal (unreadable,
non-UTF-8, over the 1 MiB cap: message `goal_design.py quality: <msg>`, nothing on stdout), or a usage error
(no artifact, artifact starting `--`, bare trailing `--lane`, `--lane` not in `discovery.LANES`, any other
flag; usage text on stderr, nothing on stdout). A bare trailing `--lane` is handled explicitly because
`_value` returns None for both absent and valueless, exactly the `--plan` precedent in `_requirements_main`.

## Risks and failure modes
- R1 (medium): a bare-token blocklist entry is shadowed by the word-count rule, so deleting it would not
  turn a test red on rejection alone. Mitigation: the tests assert the `placeholder reason` message, and
  three-word fillers are in the list so some entries are only caught by the blocklist.
- R2: `_parse_table` and `_table_groups` duplicate the grouping loop. Accepted (D-12) to keep the sibling's
  behaviour and tests untouched; a later cleanup can unify them.
- R3: the `--lane` override can weaken the rules for whoever types it. The verb is a review aid, the header
  remains the documented source, and slice 3 must not document the flag in the review gesture (note it there).
- R4: the REJECT downstream rests on a reviewing model obeying prose; nothing here gates `mark-designed`. Out of
  scope for this slice and stated in the docstring.
- R5: form is not truth (a meaningless digit passes). Stated once in the docstring; the reviewer judges it.
- R6: `Evidence` tokens and ids are checked against the artifact's own sections only; a wrong but existing id passes.
- Failure modes (all exit 2 with a message, never a traceback or partial stdout): unreadable file, over cap,
  bad encoding, usage error. A partially written artifact yields violations, not a crash. Recovery: run again.
  Host-agnostic: plain Python, no hook, no network, no `gh`, no subprocess, no write.
- Old artifacts without the section read as violations by design (not rewritten); no version marker.
