## Design decisions (each answers a research correction)
1. Kg path: `pathlib.Path(__file__).resolve().parent.parent.parent / "sigma-kg" / "scripts" / "kg.py"` (equivalent to `loop.py:5127`'s `_HERE.parent.parent / ...`; checked to exist). Subprocess of `sys.executable`, never an import.
2. Runner: `_run_text(argv)` = `subprocess.run(argv, capture_output=True, text=True, timeout=60, env=<os.environ minus bounded_run.LOCATION_VARS, GIT_NO_LAZY_FETCH=1>)`. `_run_git` cannot be reused: it returns bytes and times out at `GIT_TIMEOUT = 10`. `source(sdlc_dir, run=None)` uses `run or _run_text` for BOTH the `kg.py freshness` call and the `git diff` call. Tests inject `run`. The at-research ancestor rule keeps using `_run_git` (bytes, 10 s), so the existing `_spy` in `tests/test_reuse.py` is unaffected; `source()` never calls `_run_git`.
3. Helper failure (reason `knowledge graph helper unavailable`, mode grep): `OSError`, `subprocess.TimeoutExpired`, non-zero exit, stdout not valid JSON (`ValueError`), or JSON that is not an object. A missing script exits non-zero from the interpreter, so it needs no extra `is_file` call.
4. Condition table, first failing wins, in the brief's order. Each test is strict on type: `enabled is True`, `built is True`, `holds_code is True` (null and a missing key both fail), `built_at_commit` must be a `str` that `SEARCHED_AT.fullmatch`es (40 or 64 hex; this validation runs BEFORE any git call, and a malformed value reads as `graph has no build commit`), `ancestor is True`, `changed_files` must be an `int` that is not a `bool` and is `<= MAX_DELTA_FILES` (`true` is not a number). Over the limit: `graph is <n> files behind (limit 500)`. A non-number `changed_files` while `ancestor` is true (kg's diff failed): `graph is an unknown number of files behind (limit 500)` (the brief names no text for this shape; recorded as a plan choice).
5. Delta: `git -C <root> diff --name-only --end-of-options <commit>..HEAD` through `run`, `<root>` = `pathlib.Path(sdlc_dir).resolve().parent`; result is `sorted(set(lines))`. If that git call fails (non-zero, `OSError`, timeout), fall back to grep with reason `cannot list the files changed since the graph build` (plan choice; never report graph mode with an empty delta that hides new code).
6. Grep mode: `graph_commit` is `None`, `delta_files` is `[]`. The returned dict has exactly the keys `mode`, `graph_commit`, `reason`, `delta_files`.
7. Form rule: `SOURCE_FORM = re.compile(r"graph@[0-9a-f]{7,64}|grep(?: \(.+\))?")`, matched with `fullmatch` on `parsed["source"]` (already stripped by `parse_reuse`). It lives in `reuse_errors`, directly after the `Searched at:` block and BEFORE the `none:` early return, so it runs for new-format dossiers with or without `--at-research`. Errors: `Source: missing; write **Source:** graph@<commit> or grep (<why>)` (None or empty) and `Source: not graph@<7 to 64 hexadecimal characters> or grep, optionally followed by (<text>)` (anything else). The `_check` gate (`is_new_format`) already makes this apply only to new-format dossiers; a bare `## Reuse` stays legacy.
8. At-research rules live in a new `source_errors(parsed, sdlc_dir, root)` called from `_check` inside `if at_research:` after the Searched-at block. They run only when the Source line passed the form rule, so a malformed line yields one error, not three.
   - Ancestor rule (FR-18), only when the line is `graph@<x>` AND `parsed["searched_at"]` fullmatches `SEARCHED_AT` (else skipped; that error already exists): `git -C <root> rev-parse --verify --end-of-options <x>^{commit}` (x is hex-validated by the form rule first). Non-zero (ambiguous or unknown prefix, or absent from this machine) or `OSError`: the one error `Source: graph commit <x> is not an ancestor of the searched-at commit`. Then `git -C <root> merge-base --is-ancestor --end-of-options <full id> <searched-at>`: exit 0 passes; exit 1 or 128 (searched-at absent) is the same error, never success; `TimeoutExpired` gives `Source: graph commit <x> could not be checked: git did not answer in 10 seconds`. The comparison is with the searched-at commit, never HEAD.
   - Agreement rules (FR-17): call module-level `source(sdlc_dir)` (so tests can monkeypatch it). dossier `grep` and mode `graph`: `Source: the dossier says grep but the knowledge graph is usable (graph@<12 characters>): search the graph, then the <n> changed files` (n = `len(delta_files)`). Dossier `graph@<x>` and mode `grep`: `Source: the dossier says graph but <reason>`. Dossier `graph@<x>`, mode `graph`, and `graph_commit` does not start with `<x>`: `Source: the dossier names graph@<x> but the usable graph was built at <graph_commit[:12]>` (names both).
   - Without `--at-research` neither the ancestor rule nor the comparison runs, and `source()` is not called (no kg subprocess).
9. Repo difference (research TD-1, stated in the docstring, not fixed): `source()` asks about the repo at `parent(sdlc_dir)`; the ancestor rule uses `review_tests._root(sdlc_dir, goal)` (the goal's worktree). They can differ when Research runs against the root checkout's `.sdlc`. Passing `repo_root` through to `kg.py freshness [repo_root]` is out of scope.
10. CLI: `reuse.py source <sdlc_dir>` prints `json.dumps(result, sort_keys=True)` (one line) and returns 0; exactly 2 arguments and no `--at-research`; any other shape prints USAGE, exit 2. `USAGE`/docstring keep `usage: reuse.py check-research ...` first (the test at `tests/test_reuse.py:277` checks the prefix) and add a `reuse.py source <sdlc_dir>` line.
11. Scalability/ceilings to state in the docstring and PR: one extra Python subprocess (~0.043 s measured for `kg.py freshness` on this repo, graph disabled) per `check-research --at-research` call; the delta list is bounded by `MAX_DELTA_FILES = 500` lines. `MAX_DELTA_FILES = 500` is a judgement, not a measurement; past it the graph counts as too stale; the PR records what was and was not timed. Failure modes: kg timeout/crash/garbage degrades to grep with a reason (self-heals on the next run, no state written). The script writes no files and spawns no background process.
