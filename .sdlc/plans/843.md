- DEFAULT D5: the same node id across repos keeps the entry from the fragment with the greater

  kept, not deduplicated, sorted by (type, from, to).

## Output contract (module docstring states all of it)
- `<out>/merged.json`: `{"sysgraph_version":"1.0","merged_from":[{repo,commit,commit_time,file}...sorted by
  repo],"nodes":[...sorted by id],"edges":[...sorted by (type,from,to)]}`; `json.dumps(sort_keys=True,
  indent=2, ensure_ascii=False)+"\n"`; unknown fragment keys are ignored and not copied.
- `<out>/unresolved.json`: `{"unresolved": []}` (skeleton; entries land in a later slice).
- Fixed file names, so "refuse to write outside --out" is structural.
- stdout report, deterministic (no clock, no absolute temp paths):
  `merge: <N> fragment file(s) read; <R> repositor(y|ies) contributed; <S> superseded; <K> skipped corrupt; <V> refused version`,
  then `skipped corrupt: <file>: <reason>` and `refused version: <file>: sysgraph_version "2.0" unsupported major 2 (supported: 1)`,
  then `wrote: <out>/merged.json, <out>/unresolved.json`.
- Exit: 0 ok; 1 no repository contributed (writes nothing); 2 usage or IO.
- Corrupt = unreadable, non-UTF-8, non-JSON, not an object, over the size limit, missing or non-string
  `repo`, missing or invalid `commit_time`/`commit`, `nodes`/`edges` not lists. A bad or unsupported
  version is a separate class: REFUSED.
- Size limit: `default_max_bytes` derived from the machine, `os.sysconf("SC_PAGE_SIZE") *
  os.sysconf("SC_PHYS_PAGES") // 32` with a fixed floor only if sysconf raises (and then it refuses
  loudly rather than guessing); `--max-bytes` overrides. Not a constant copied from a laptop.
- Out-dir safety: `realpath`; refuse if `--out` or either target is a symlink, or if `--out` equals or is
  inside the fragments dir (a rerun would read its own output); missing or non-directory fragments dir is
  exit 2. Defensively skip non-fragment names.
- Atomicity: everything is staged in memory first, so a data error never leaves a partial `--out`; then per
  file same-directory temp + fsync + `os.replace` (shape of `verify_detect._atomic_write_json`), temp
  removed on any exception. Order: `unresolved.json` then `merged.json` (consumers key off merged.json).
  A crash between the two leaves the old merged with a new unresolved; this is stated in the docstring.
- Recovery and rollback: the command is idempotent and rerunnable; a rerun on the same input gives
  byte-identical files; a failed run leaves the previous outputs untouched and no temp file; reverting the
  change is deleting the new file and its table rows, nothing on disk elsewhere depends on it. It writes
  only to a caller-named `--out`, never to the root checkout, so it cannot make `git pull` or `work.py
  start` refuse.

## Steps (test-first; no step commits)
1. Tests skeleton: `-h`/`--help` prints `usage:`, exits 0, creates nothing (also unknown flag exits 2,
   missing fragments dir exits 2). Run, see red (module absent). Then write the module's argv/help shell,
   green.
2. Selection tests (AC-1): per-repo greatest `commit_time` wins; tie on time goes to the greater sha; exact
   tie of both goes to the smaller file name and is reported; PERMUTATION test over all orderings of a
   4-file set (creation order and name order varied, e.g. via renamed copies) must give the identical
   merged bytes and identical chosen file. Red, then implement load + select + `merged_from`, green.
3. Version and corrupt tests (AC-2): unknown major "2.0" refused and named; malformed version strings
   ("1", "01.0", "1.00", "1.0.0", "", non-string, 8+ chars) refused; each corrupt kind in the list above is
   skipped and named by file name; counts in the report; no fall-back to an older same-repo fragment
   (DEFAULT D1); a refused/corrupt NEWEST fragment with a valid older one: older is NOT used; exit 0 when
   another repo contributed, exit 1 and no files when none did. Red, implement, green.
4. Determinism and union tests (AC-3): two runs give byte-identical outputs; node conflict across repos
   (DEFAULT D5); edges sorted; unknown top-level keys not copied. Red, implement, green.
5. Atomic-failure test (AC-3): monkeypatch `os.replace` to raise on the second target; assert previous
   `merged.json`/`unresolved.json` bytes unchanged where they were replaced-or-not as documented, no
   `.tmp` file left in `--out`, and a data error (corrupt-only input) writes nothing. Also a variant where
   the failure hits the first replace. Red, implement, green.
6. Containment tests (AC-4): `--out` equal to or inside the fragments dir refused; `--out` a symlink
   refused; a pre-existing symlink at `merged.json` refused; relative `--out` writes only fixed names; no
   file created outside `--out` (snapshot diff). Size limit: file over `--max-bytes` is skipped as
   corrupt; the default is derived (assert it equals the sysconf formula, not a literal). Static tests:
   AST scan that the module imports none of subprocess/socket/urllib/http; `py_compile`; no `|` in
   annotations. Red, implement, green.
7. Scalability (measured) step: a scratch script in the scratchpad (not committed) generates 1x/10x/100x
   repos (1x = 10 repos x 1,000 nodes, 100x = 1,000 repos), runs the command, records wall time and peak
   RSS (`resource.getrusage`) on this host. Record the numbers, labelled "measured on this host (date,
   python version)", in the module docstring with the stated ceiling: memory is O(repos x fragment size)
   because only the winning fragment per repo is kept; the single-pass sort is O(n log n); the per-file
   cap is machine-derived. If 100x is not measured, the docstring says so in the same sentence.
