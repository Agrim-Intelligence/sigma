## Decisions (every item the dossier asked for)
| Item | Decision | Reason |
|---|---|---|
| Opt-in variable | `SIGMA_REGRESSION_LIVE`; opts in only when stripped, lowercased value is in `{1, true, yes, on}` | spend is bearing, so a typo (`enable`, `2`) must not opt in; allowlist, not the `_truthy` falsy-list. The module docstring carries one line saying why the two differ: the opt-in uses an allowlist of truthy values and the release-gate flag uses the falsy-list, and both are fail-closed (an odd opt-in value means not opted in; an odd gating value means gated) |
| Cap / belt | `--cap-usd` / `SIGMA_REGRESSION_CAP_USD`, `--belt-usd` / `SIGMA_REGRESSION_BELT_USD`, DOLLARS; flag beats env; belt must be <= cap | mirrors bench's `--belt-usd`; a per-run belt above the total cap is incoherent, refused as `no-cap` |
| Number grammar | stripped text must match `^[0-9]+(\.[0-9]{1,6})?$`, then `float`, `math.isfinite`, `> 0` | rejects nan, inf, hex, exponent, signs, bool words, whitespace; huge digit strings overflow to inf and are caught by `isfinite`. Argv note: a negative cap given as a SEPARATE token (`--cap-usd -1`) is read by argparse as a missing value and becomes `bad-usage` (exit 2), not `no-cap`; the `--cap-usd=-1` form reaches the grammar and is `no-cap`. Both are refusals with exit 2; the codes differ and the tests state each |
| Release-gate flag | `--release-gate` and `SIGMA_REGRESSION_RELEASE_GATE` (truthy by the bench `_truthy` falsy-list) | explicit flag only ever ADDS gating (see the opt-in row for why this is a falsy-list while opt-in is an allowlist) |
| Gated | `CI` truthy or `GITHUB_ACTIONS` truthy (bench `_truthy` semantics: anything not in `{"",0,false,no,off}`) or release-gate flag | fail-closed direction: an odd value means gated, an odd opt-in means not opted in |
| Both credentials set | basis `api-key` when ungated (note `both-credentials` in `reason`); gated refuses `subscription-in-gated-mode` whenever `CLAUDE_CODE_OAUTH_TOKEN` is non-blank, even with an API key present | fail closed: the token is reachable by the child; the only gated pass shape is API key and no OAuth token |
| Basis values | `api-key`, `subscription`, `none` | row field `credential_basis`; never a value |
| `--results-dir` | flag; default `<repo root>/.sdlc/eval/results` where repo root = `Path(__file__).resolve().parents[2]`; a flag value is used as given (a relative one resolves against cwd) | DECIDED anchored: cwd-relative would scatter rows into whatever directory the operator happens to be in (a silent half-guarantee for the spend ledger a later slice reads). Hermetic without touching the real tree: the bare-gesture test builds a temp tree `evals/regression/live.py` + `skills/sigma-loop/scripts/scrub.py` (copies) and runs the copy by absolute path from an unrelated temp cwd, so `parents[2]` is the temp tree; `.sdlc/*` stays git-ignored in the real tree |
| Row filename | `live-<UTC YYYYMMDDTHHMMSSZ>-<pid>-<4 hex>.json`; if it exists, regenerate the suffix up to 5 times, then fail the write | unique, sortable, no lock needed. Never-overwrite is BEST EFFORT: it is an `exists()` check followed by `os.replace`, which overwrites, so a collision between the check and the replace is possible in principle; the pid plus 16 random bits make that negligible, and it is not claimed stronger |
| First failing code vs all | all rungs are evaluated every run (independent, cheap); stderr and `code` carry the FIRST; row carries `also_failing` (list of the other codes in ladder order) | one loud line (AC-1) and a complete record |
| After the ladder passes | `REFUSED [not-implemented]`, exit 2, NOT RUN row, reason "no run path exists in this slice" | exiting 0 would read as a pass; documented in the module docstring |
| Bad flags | `parser.error` overridden: `REFUSED [bad-usage]` exit 2, fixed text (never echoes the argument), NOT RUN row to the default dir; `allow_abbrev=False`; `--help` exits 0 before the ladder with no row | a typo is a deliberate, distinguishable result, not argparse's own usage exit |
| Scrubber unavailable | load `<repo root>/skills/sigma-loop/scripts/scrub.py` by path (`importlib.util`, the sibling idiom); if it cannot load, refuse `scrubber-unavailable` (exact-value redaction still applied) | never log through a missing second layer in silence |
| What is scrubbed | the shared scrubber is NEVER run over a whole emitted line. Verified read-only: `scrub.scrub("live.py: REFUSED [no-credential]: neither CLAUDE_CODE_OAUTH_TOKEN nor ...")` returns `REFUSED [no-credential: [REDACTED] CLAUDE_CODE_OAUTH_TOKEN nor ...` (rule `credential-assignment-suffix` matches `credential]:`); the other eight codes and the `row not recorded` line survive. So the line is assembled as fixed prefix `live.py: REFUSED [<code>]: ` + fixed detail text (both constants in the module, never passed through `scrub`) + the VARIABLE part only, which is `echo()`-ed. Variable parts are: the echoed cap/belt text (the sole operator-supplied text) and the exception class name in the `row not recorded` line; row string values are fixed constants plus the same variable part | the fixed text is ours and credential-free by construction (pinned by a test that compares the FULL line to the constant), so scrubbing it can only damage it |
| Echoed text order | variable text is processed in this order: (1) exact-value redaction of the whole held value on the RAW text, (2) `repr`, (3) cut to 40 chars, (4) `scrub.scrub`. Never cut first | a cut prefix of a long credential no longer equals the full value and would leak; redaction before the cut removes it whole |
| Redaction mechanism | `re.sub(re.escape(v), lambda m: "[REDACTED]", text)` per member of the set, longest first. No `str.replace` anywhere in `live.py`. stderr is written with `print(..., file=sys.stderr)`, never `sys.stderr.write` | keeps the write-method AST walker free of an allowlist hole (see Task 5) |
| Defence in depth | after the line is assembled, the EXACT-VALUE redaction pass (never the scrubber) is run once more over each whole emitted stderr line and over the serialised row string before it is written | the 8-char minimum and the distinctive planted shapes mean fixed text cannot be damaged by it, so it is safe on whole lines. DEVIATION from the #810 design ('every log line through the scrubber'): the shared scrubber is not run over whole lines because `credential-assignment-suffix` mangles the fixed `[no-credential]:` prefix. The deviation and its reason are stated in the module docstring and in the CHANGELOG entry |
| Row `reason` and cap echo | `reason` = the fixed detail of the FIRST failing code (the row's `code`); the other failing codes appear only in `also_failing` as bare codes, with no detail. The cap/belt text is echoed (redacted, cut) ONLY when `no-cap` is the first failing code, in both stderr and `reason`; when an earlier rung fails first, no cap text is echoed anywhere. The AC-4 planted test therefore sets `SIGMA_REGRESSION_LIVE=1` and a credential so rungs 1 and 2 pass and `no-cap` is first | one loud line, no echo path other than one the tests drive |
| `commit` | `GITHUB_SHA` if it is 40 hex chars, else `unknown` | no subprocess, so no `git` call |
| Min redaction length | held credential values shorter than 8 characters are NOT redacted globally | a 1-2 char fake would shred all output; tested explicitly |
| Held values | the held set takes BOTH the raw value and the stripped value of each non-blank credential (`CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_API_KEY`), each expanded into the encodings in the Module shape row (`quote`, `quote_plus`, `shlex.quote`, standard and urlsafe base64, padded and unpadded) | a credential with trailing whitespace or a newline would otherwise be matched only in one of its two spellings |

Codes, in ladder order: `no-credential`, `no-opt-in`, `no-cap`, `unsupported-platform`,

## Module shape (`evals/regression/live.py`)
- `CODES`, `EXIT_REFUSED = 2`; `Failure(code, detail)`; `Options` (cap_text, belt_text, release_gate,
  results_dir) parsed by argparse (no required args, no value echoed on error).
- `platform_is_posix()` (`os.name == "posix"`): the seam.
- `evaluate(env, opts, posix)`: PURE; returns `(basis, cap, belt, gated, failures)` with every rung
  evaluated; reads nothing ambient. This is what the in-process platform and ordering tests call.
- `held_credentials(env)`; `redaction_set(values)`: for each value >= 8 chars, the raw value, `quote`,
  `quote_plus`, `shlex.quote`, standard and urlsafe base64 (padded and unpadded), longest first.
- `echo(text, held, scrubber)`: the one place the order lives: exact-value `re.sub` with `[REDACTED]`
  on the raw text, `repr`, cut to 40, then `scrubber.scrub`. Applied ONLY to variable text (see "What is
  scrubbed"), never to a whole line and never to the serialised JSON (where the scrubber's `token=` rule
  could eat a key such as `tokens`).
- `emit_refusal(failure, ...)`: builds `PREFIX + fixed detail + variable part` and `print`s it to stderr.
- Module docstring states: the no-model guarantee, the PROVISIONAL-if-so row schema, the null-cost rule, the opt-in allowlist vs gate falsy-list reason, and the whole-line-scrubber deviation.
- `build_row(...)`, `write_row(results_dir, row)` (the ONLY function that touches the filesystem write
  surface: `mkdir`, temp `write_text`, `os.replace`, `unlink` in `finally`), `main(argv=None, env=None)`.
- stdout is never written on a refusal. On a failed row write: the REFUSED line first, exit stays 2, one
  extra stderr line `live.py: row not recorded (<ExceptionClass>)`, nothing else.

## Failure modes and recovery
- Unwritable or file-shaped results dir, full disk, permission error: the refusal is unchanged (REFUSED
  line, exit 2), one extra stderr line says the row was not recorded; no traceback, nothing partial (temp
  file removed in `finally`, final path appears only through `os.replace`). Recovery: fix the directory and
  rerun; the next refusal records its own row. Nothing retries.
- Scrubber missing: `scrubber-unavailable` refusal, exact-value redaction still applied.
- Crash mid-write: either no row or a whole row, never half of one.
- Concurrency: two runs get distinct filenames (pid plus random suffix); no shared mutable state.

## Scale and safety statement
Per run: one row of roughly 1 KB, O(1) work, no scan of the results directory (existence check on one
name only). Growth: one file per refusal, unbounded over time by design here; at 100 runs a day that is
about 36,500 files a year (about 36 MB). Pruning is named as a LATER slice (with the spend record and
#819's monthly rollup); until then the directory is git-ignored and operator-owned. No locks, no
background process, no network, no subprocess, no consumed quota. Limits are not machine-dependent here
(no resource is spawned); the only constant is the 8-char redaction minimum and the 40-char echo cut, both
documented in the module. Unsupported platforms refuse loudly (`unsupported-platform`) rather than run
weakly; Windows behaviour is untested in this slice (the Windows workflow is dispatch-only).
