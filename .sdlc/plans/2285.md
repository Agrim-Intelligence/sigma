## Decisions on the research's open items
1. Absolute path inside in-flight lines (TD-3): print the lines as they are, as the issue says ("printed as they are"). The brief's own text never contains a path (commands are `reuse.py <verb> ...`, the delta and criteria text are `_one_line`d, the root is never printed). Fixtures for the no-absolute-path test use branches whose names and subjects hold no path. The residual (another goal's branch quoting a home-directory path in a subject or declared row) is documented in the `brief` docstring and said in the PR text as an unmeasured gap, and it is already covered by the printed read-as-data sentence. Not chosen: rewriting `/`-tokens, because it would alter evidence and a mangled path in a URL or a regex would mislead more than the gap does.
2. Ladder wording: third element of `DECISIONS` (not a parallel dict), e.g. `reuse: "the capability exists and does what you need"`. `reuse_errors` and the tests that read `DECISIONS` use `[0]` and `[1]` or the keys only, so they stay green; verified by running the seven reuse test files one at a time.
3. 12,000-character cut: `MAX_BRIEF = 12000`. Fixed parts are built first: head (items 1-7), the `In-flight work:` heading, tail (the two read-as-data sentences, `Then run:` block, the `Plan:` line, the closing sentence, per the issue items 8 to 11). The reserve for the `... <n> more line(s): run reuse.py inflight .sdlc "<goal>"` line is computed with the digit width of the total line count. In-flight lines are then added one at a time while they fit; the remainder is counted and the more-line printed. The tail is therefore never cut. Guard for a head that is itself oversize (huge criteria or delta list): delta names are `_one_line(name, 120)`, the delta list is capped at 50, criterion rows at 100 with `... and <k> more criteria`; if head plus tail still exceeds 12,000 the in-flight block is dropped to the more-line alone. A final `assert`-free fallback truncates nothing else; the length test covers the 50-delta, many-criteria and many-hit cases together.
4. `<goal>` in printed commands: the goal argument one-lined (`_one_line(goal, 80)`) so a hostile goal string cannot inject a line; ordinary goals print as given.
5. `inflight` raising: one line `inflight: could not run (<ExceptionName>)`, same as `_print_inflight`; the brief still prints and exits 0. Cost ceiling (up to 120 seconds, inherited from `inflight`) is stated in the docstring, unmeasured.
6. Determinism: no clock except the injected `now`; sorted lists; no dict-order dependence (explicit tuples).
