# Plan: #234 — Canonical board design: fields and six views, copyable as the init template

**Goal**: #234 · **Research**: `.sdlc/research/234.md` · **Date**: 2026-09-29 · one branch (`sdlc/234`).

## Decisions (made without the owner; recorded here)

- **D1 No real-GitHub mutation from this goal.** Building on board #17, setting milestones and the
  `copyProjectV2` control are OWNER actions: shipped as a script + runbook (`docs/board.md`).
- **D2 One spec.** `skills/sigma-init/scripts/board_spec.py` builds the fields and six views from the
  kit's own vocabulary at call time (`GitHubSource.col`, label names, `discovery.PRIORITIES`,
  `phase_report.PHASE_TOKENS` + `PHASE_BOARD_COLORS`). Nothing is copied.
- **D3 Priority P0..P4**, not the issue's P0..P3 (research: P4 goals would read blank).
- **D4 "Needs a human" filter** is on labels, one qualifier, because the filter language cannot OR
  across fields: `is:open label:"sdlc:parked","sdlc:blocked","sdlc:needs-confirmation"`.
- **D5 Settable vs manual.** name, layout, filter, visible fields go through the API; group-by,
  sort, board column field, roadmap dates/markers and default-view position are printed as exact UI
  steps, per property, only when the board reads different.
- **D6 Ownership.** `fields`/`views` act on the pinned board only when `project.setup_created` names
  it; any other board needs `--number N` (the explicit choice). `verify` is read-only and needs neither.
- **D7 Never delete, never duplicate.** A view is matched by `_match_field`'s rule (exact, else one
  case-variant). Several matches -> that view REFUSED. Views not in the spec are never touched.
  An existing spec view keeps extra columns the user added (spec columns first, extras after).
- **D8 Dry run by default**; `--yes` mutates. Area/Model tier created as TEXT; no writer yet (stated).
