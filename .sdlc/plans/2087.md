# Plan: In a cloud container a plan kept out of git is lost with the container; record done only warns

**Goal**: #2087 · **Lane**: small-to-medium · **Phase**: P3 PLAN · **Date**: 2026-10-29
**Inputs**: issue #2087 (AC-1 to AC-4, recorded unchanged in `.sdlc/acceptance/2087.md`), #2065 (`--land`), #2081 (cloud ledger publish), `AGENTS.md`, `docs/cloud-sessions.md`.
**Not measured**: no real cloud container has run any of this. Everything below is checked against fakes and real local git only, and the docs say so.

## Where the loss happens

`work.py` `_clean_landed_root_records` runs from `finish` after a confirmed merge. For the root copy of the plan, research dossier and acceptance record that is untracked and absent from `<remote>/<base>` it only reports `kept <rel>: not on <remote>/<base> (commit it or it is lost)`. On a laptop the kept file survives in the root checkout. In a container it does not, and a repository that ignores `.sdlc/plans/` on purpose cannot follow the advice.

## Decisions (PROVISIONAL, owner to ratify)

1. **Durable copy home: a comment on the goal's own issue.** The proposal lists a PR-body section, an issue comment, or a file on the ledger branch. The issue comment adds the fewest write surfaces: it goes through `gh_api.comment_issue`, a writer already in the inventory, to an issue the run already writes to, over REST, needing no ledger and no second push. The PR body is already merged and sealed, and a ledger-branch file would be a new writer, a new push and a new lease.
2. **What counts as a cloud run**: `ledger.cloud_session()` (`CLAUDE_CODE_REMOTE` is `true` or `1`), the signal `gh_api` already reads. `SIGMA_GH_GRAPHQL=off` alone is not a cloud session.
3. **Which goals**: github mode with an issue-number stem (`_reads_a_declaration`), because the comment needs an issue. A local goal file keeps today's behaviour.
4. **Which file**: the plan only (the issue's scope). Research and acceptance records keep today's warning; the acceptance criteria are already on the issue and the research dossier is summarised in the phase notes.
5. **Which case**: only `not on <remote>/<base>`. A copy that landed but differs keeps its "differs" line.
6. **Doctor (AC-3)**: a WARN row when git ignores `.sdlc/plans/` AND cloud runs look configured. "Configured" can only be read from the environment the doctor runs in (a laptop doctor cannot see the cloud environment's settings): `CLAUDE_CODE_REMOTE` is `true`/`1`, or `SIGMA_TRUSTED_VERIFY_SHA256` is set (the operator's cloud-environment setup step in `docs/cloud-sessions.md`). Not measured on a real container.

## Steps

1. **Tests first** (one test file for the plan copy, one for the doctor row; listed under Tests), each seen red for the right reason.
2. `work.py`: `_durable_plan_copy(...)` builds idempotent comment(s) (marker with goal and sha256, a fence longer than any backtick run in the plan, parts of at most 60 000 characters, at most 3 parts, the rest truncated and said so), reads existing comments first so a retried `finish` posts nothing twice, posts through `gh_api.comment_issue`, and returns the first comment's URL. `_clean_landed_root_records` calls it only for `plans`, only in a cloud session, and prints `kept <rel>: not on <remote>/<base>; durable copy of the plan: <url>`. On any failure the old line stays, with `; durable copy FAILED: <reason>` appended. The local file is still kept in every case.
3. `doctor.py`: `_plans_ignored_rows(base, cfg, run, env)` wired next to the other advisory rows.
4. Inventory (`docs/launch/write-surface.json` and `.md`) only if `tools/readiness/write_surface.py check` says a writer was added.
5. Docs: `docs/cloud-sessions.md`, `skills/sigma-goal/references/land.md`, doctor docs, `CHANGELOG.md` under Unreleased. Phase-context budget stays green (detail in references).
6. Break each clause of each guard on its own and see its test red; run the control on the documented gesture.

## Plan-review (independent subagent): SOUND-WITH-REFINEMENTS, all taken

1. Egress: a plan is sent to an issue, so secret-shaped strings are redacted first (`scrub_shapes`), and the choice is recorded as PROVISIONAL on the issue.
2. `comment_issue` returns the parsed reply, not a URL: the URL is read from it and a reply without one is `durable copy FAILED`.
3. `_clean_landed_root_records` gained a defaulted `config` parameter (needed for the issue repo and the github-mode test); a caller without it behaves as before.
4. The duplicate-post read trusts only OWNER, MEMBER and COLLABORATOR comments, is an optimisation only, and its cost (`1 + ceil(n/100)` requests) is documented.
5. The write-surface tool needed a `known` entry (it would otherwise label the site "ungated"), plus JSON and `.md` rows.
6. The doctor row is hand-built (`ok` true, level WARN), probes git for a path under the plans directory, and is named and documented for what it observes.
7. Docs avoid the literal direct-`gh` shapes; the changelog uses the existing `## Unreleased` section.
