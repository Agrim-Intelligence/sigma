   - `ensure_hook_path` (the `hooks` verb) REFUSES, writing nothing, when `<toplevel>/<HOOKS_PATH>`

   - New `stale_hook_path(repo_root)` -> `True|False`, raising `HookPathRefused` when git cannot be
     read: local `core.hooksPath` equals `HOOKS_PATH` exactly AND that path, resolved against the

     `git config --local --unset core.hooksPath`; raises `HookPathRefused` on failure.
   - New CLI verb `hooks-repair <repo_root>`: on `cleared` prints ONE line naming what was removed and
     why; on `absent` prints nothing; on failure prints a REFUSED line on stderr carrying the manual
     command and exits 2. USAGE updated.
