# Plan 2086: a killed merge runner is reported with the PR's state and the recovery

Goal: when `loop.py wait-call ... merge` finds the merge runner dead, it reads the goal's PR once and, while the PR is
open and unmerged, says so and names the two gestures (re-register the agent, re-run `work.py merge`) instead of a
bare `FAILED`. The recovery is documented and a test kills a real runner during pending-check polling and walks it.

## Design
- `loop.py` gets `_merge_pr_line(sdlc_dir, goal)`. It runs only for `kind == "merge"`, only on a `failed` receipt, only
  when the work record names a PR. It calls `work.pr_landing_state` ONCE (one REST read; no GraphQL; fail-closed to
  `unknown`). Its answer is one stdout line after the existing `FAILED` line:
  - open: `PR #N is open and unmerged ...` plus both gestures, as absolute, copy-pasteable commands (the same
    quoting `run_receipt.wait_call_gesture` uses), and "do not record the goal failed".
  - merged: `PR #N is already merged: run record done`; do not re-run merge.
  - closed: do not re-run merge; decide by hand.
  - unknown: could not read it; check by hand, do not re-run blindly.
- Exit code stays 1 (not completed). The existing stderr line keeps its text for every state except open, where it
  points at the new landing.md section instead of "do not re-run blindly".
- No change to the receipt, to `merge()` or to `gate()`. Read-only, no lock.
- Residual window (documented, not closed): a kill during the merge call itself can land after the read; the open
  line says "at this read" and landing.md keeps its `record review` rule for that case.
- Proposal item 3 (marker bound to a session id) is NOT built; a PROVISIONAL follow-up note goes on the issue.

## Test list (tests first)
New file `tests/test_merge_runner_killed.py`:
1. Unit, per clause of the guard, each with an injected REST fake and a call counter:
   - open PR: output has `PR #7`, `open and unmerged`, `agent-start`, `--pid`, `work.py`, `merge`; exactly one gh call.
   - merged / closed / unreadable: no `agent-start` advice, no "re-run `work.py merge`" advice; state named.
   - no PR on record: no gh call, no extra line, exit 1.
   - `verify` kind: no gh call. A final (finished) merge receipt: no gh call, exit 0.
   - a still-running live receipt: no gh call, exit 3.
2. End to end (AC-3): a child process runs `work.merge_with_receipt` against a file-backed fake GitHub with a required
   check still pending; the test waits until the child is inside the pending poll, SIGKILLs it, runs `wait-call`
   (reads FAILED + open + gestures), runs the documented gestures (`agent-start --pid`, then merge with the check now
   green), then `record done`. Asserts: one PUT merge in the fake's log, one issue-close write, one `done` record, and
   the second `wait-call` says finished.
3. Docs: landing.md names the recovery (both gestures, "Do not record the goal failed"), land.md and cloud-sessions
   point at it.
4. Controls: break each clause of the guard on its own (kind check, failed-state check, record/PR check, open-state
   check, the open-line gestures) and see the matching test red; run the control on the gesture landing.md prints.
