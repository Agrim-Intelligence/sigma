Decisions (recorded, nobody to ask):
- D1 cost: make the claim true in code. The pass hands its own REST read to `done_refusal`
  (`landing=`), and `_record(..., merged_pr=True)` -> `finish(..., merged=True)` skips both
  `gh pr view` reads (the merge was just confirmed by REST). Docs restate the measured cost: one
  REST `pulls/<n>` read per goal (<=10 per pass), +1 REST read per closed goal only with the
  ledger/journal on; the issue close is `source.complete()`'s own writes, not counted here.
- D2 lock: non-blocking kernel lock (`fcntl.flock` / `msvcrt.locking`) on
  `state/merge-reconcile.lock`; a busy lock skips the pass (the holder does the work). Kernel locks
  release on process death, so nothing goes stale; holder pid written for diagnosis. No lock
  primitive -> refuse loudly and skip. Polite lever: kill the named holder pid; never delete the
  file.
- D3 crash-safety: `_record` clears the awaiting flag right after its ledger terminal entry (before
  unit-completion signal, checkout release, KG hops). Wall-clock budget per pass derived from
  `SIGMA_WATCH_CALL_TIMEOUT` (half of it, default 60 s): no new goal is started after it.
- D4 liveness: `work.awaiting_merge_report()` (age since `record review`, age of the last PR read,
  close failures); doctor row (not OK when a goal waits > 3 d or no pass read it for > 1 d);
  status.py segment; log.py treats `recorded result=review` as in flight and describes it
  `awaiting merge for 3d`.
- D5: `_record` with a REQUESTED `parked`/`failed` clears the flag (a `done` downgraded to parked
  keeps it).
- D6: `finish` refuses (without `--force`) while the record carries `awaiting_merge`.
- D7: reconcile passes `retry_close=True`; a raising `complete()` then records nothing; the flag
  counts `close_failures`; exactly the 3rd consecutive failure parks publicly (once).
- D8: e2e removes `sdlc:in-progress` before the repick so only the local skip can hold it.
- D9: `run_loop` returns a `review` counter; `parked` excludes it.
