## Design of gh_api.py (fixed before the steps)

Capability API (the dossier's contract):
`graphql_available(env=None, cache_dir=None, run=None, now=None, probe=False) -> dict`
returning `{"available": bool, "reason": str, "source": "override|env|cache|probe|default"}`.
Precedence, first hit wins, no I/O before it is needed:
1. Override env `SIGMA_GH_GRAPHQL` = `off`/`0`/`false` -> unavailable, `source=override`; `on`/`1`/`true` ->
   available, `source=override`. Any other value is ignored (and noted in `reason`), never an error.
2. `CLAUDE_CODE_REMOTE` in `{"true","1"}` (case-insensitive) -> unavailable, `source=env`, reason names
   the cloud proxy. Free, no I/O.
3. Cache file `<cache_dir>/gh-capability.json` (`cache_dir` = `<base>/.sdlc/state`), read only if
   `probe` is requested (R4: therefore DEAD CODE IN PRODUCT in slice 1 — doctor always passes
   `probe=False` — built and unit-tested but not exercised by any shipped caller; "wire the probe into a
   real caller" is listed as an explicit follow-up, Step 15, and the docs say so): entry is `{"env_key": <CLAUDE_CODE_REMOTE value or "">, "available": bool,
   "reason": str, "at": <epoch>}`; valid only when `env_key` matches AND `now - at < TTL`
   (`TTL` = 900 s default, constant `CACHE_TTL_SECONDS`; self-heal: an old "unavailable" re-probes).
   Corrupt / unreadable cache = miss, never an error. Cache holds no secrets.
4. One-time probe, only when `probe=True` AND `run` is supplied (never default; `probe=True` with
   `run=None` raises `ValueError`): ONE call `run(["api","graphql","-f","query={viewer{login}}"])` (sources
   convention: NO leading `"gh"`; the timeout is the real wrapper's, tests inject). Success (returns) ->
   available; raised exception `exc` with `gh_session.graphql_unavailable(str(exc))` true -> unavailable;
   any other exception -> `available: True, reason: "probe inconclusive"` (fail-open: a network blip must
   not disable features; stated in the docstring). Result written to the cache (atomic: temp file +
   `os.replace`; cache dir created if missing, any OSError swallowed with the reason noted). NO retry, NO
   loop. No background process.
5. Default: available, `source=default`, reason "no cloud signal".
The module never probes implicitly: `doctor` and every test call with `probe=False` unless a test injects
`run`. Probe cost is O(1); stated in the docstring with the two rate-limit pools (REST `core` 5000/h vs
`graphql` 5000 points/h, REST ~1 point/call measured in #1829).

REST helper ops (all take `run=` per the RUN CONTRACT above, `repo=None` -> `{owner}/{repo}` placeholder,
return parsed JSON, raise `GhApiError` on transport failure or unparseable output; NO retries; ALWAYS
`--method` explicit; label names URL-quoted with `urllib.parse.quote(name, safe="")`).
`GhApiError(Exception)` WRAPS the underlying failure: `str(GhApiError)` is `str(exc)` of the exception
`run` raised, and `.hint` is copied from `exc.hint` when present (else `None`); there is no returncode field
(B3). Callers classify with `gh_session.graphql_unavailable(str(err))`.
Ops: `list_issues` (delegates to the injected `fetch=`, default lazy `sources.fetch_issues_rest`; bounded
`cap`, default 200),
`view_issue` (GET issue + bounded comments pages), `comment_issue`, `add_labels`, `remove_label`
(404 text = no-op, other errors raise), `create_issue` (R5: plain REST create, NO feature-label check. It
BYPASSES the feature-label refusal that lives in `GitHubSource._run`; this is stated in the `gh_api`
docstring and the docs, and migration slice 3 MUST preserve that refusal before any caller moves onto
`create_issue`. Slice 1 adds no new refusals), `close_issue`,
`create_pr`, `view_pr`, `merge_pr` (`PUT /pulls/{n}/merge`, `merge_method`, optional `sha` guard; no
auto-merge exists in REST: documented, not emulated), `list_prs` (not required by acceptance; omit).
Pagination: only `view_issue` comments and `list_issues` paginate; both bounded by an explicit `cap`
argument with `page`-loop (not `--paginate`, which is unbounded). Scalars via `-f`; bodies via
`-f body=...` (argv list, never a shell). Secrets never touched.

gh_session additions (R3: ZERO behaviour change for existing callers): add only
`GRAPHQL_UNAVAILABLE_TEXT = "github graphql is not available from claude code sessions"` (lower-cased
match) as its own marker tuple `_GRAPHQL_UNAVAILABLE_MARKERS`, and `graphql_unavailable(text) -> bool`
(never raises; non-str -> False). `proxy_session_block` and `REMEDIATION` are left UNCHANGED, so
`sources._run_gh`, `work.py`, `doctor` and `preflight` see exactly what they saw before, and no
`GRAPHQL_REMEDIATION` is introduced in slice 1 (wiring the third shape into the callers is a migration
follow-up). Exact 403 wording is from the issue text, unverified against a real proxy; the test pins the
quoted wording and the docs say so.

Ratchet design (`tests/test_no_direct_gh.py`):
- Walk `skills/**/*.py` and `hooks/**/*.py` (repo-relative, posix). Parse with `ast`.
- THE ONE COUNTING RULE (B1; no separate flag, no second number). A "site" is an `ast.List`/`ast.Tuple`
  literal matching exactly one of:
  (1) `["gh", N, <verb>, ...]` with `N` a string constant in `{"issue","pr","project","label"}`;
  (2) `[N, <verb>, ...]` with `N` in that set and `<verb>` a string constant (catches
      `source._run(["issue","view",...])`, sources-convention args without `"gh"`);
  (3) `["gh", X, ...]` where the second element `X` is NOT a string constant (a name, starred
      `*args`, call, f-string...) — the wrapper/variable-noun shape (`["gh", *args]`,
      `["gh", noun, verb]`).
  EXCLUDED, never counted: `["gh","api",...]` (already REST; migration must not raise or fail to lower
  the count), `which("gh")` and any bare `"gh"` constant not the first element of a list/tuple,
  assignments like `BOARD_GH = "gh"`, and `["gh", "repo"|"run"|"auth"|...]` (any other string-constant
  second element). Docstrings/comments are not list literals, so never counted.
  The helper `skills/sigma-loop/scripts/gh_api.py` is exempt by name (EXEMPT = {that path}); the allowlist
  is `BASELINE = {path: max_count}` generated from the current tree by this rule.
- BASELINE DERIVATION (the dossier's 95 is a FLOOR reference only, not the target): the count under this
  rule is expected to be >= 95 (rules 2 and 3 add shapes the dossier's grep did not count, e.g.
  `cross_repo.py:242`, `feature_owner.py:251`, `ledger.py:897`, `status.py:162/167`). The implementer runs
  `count_sites` over the real tree, records the per-file dict and total with date and command in the test
  docstring, and RECONCILES by listing, per file, any site beyond the dossier's count and confirming each
  is a real noun/wrapper site by reading it (not by trusting the number). A total BELOW 95 means the
  scanner misses sites: STOP and fix. Above is fine once every extra is explained.
- Three assertions, three tests, each with a clear message naming the file and what to do:
  (a) no file outside BASELINE/EXEMPT has count > 0 (new file fails);
  (b) no BASELINE file has count > baseline (count up fails);
  (c) no BASELINE file has count < baseline, including 0 (stale entry fails, message: "lower the baseline
      to N or delete the entry — the ratchet only goes down"), so migration slices must shrink it.
- The scanner is a pure function `count_sites(source: str) -> int` so the control can be driven in tests
  with synthetic source strings too (deterministic, not dependent on the repo tree).
- NOT COVERED (B2), named explicitly in the test docstring AND `docs/cloud-sessions.md`, not just "floor":
  `"issue view".split()` and other string-form / shell-string calls; argv built incrementally
  (`args = ["issue"]; args += ["edit", ...]`, `.append`/`.extend`); argv lists whose first element is a
  variable (`[cmd, ...]`); `["gh", *args]`-style wrappers ARE covered by rule 3, but a call site that
  passes ITS arguments to such a wrapper (`_gh("issue", "view")` positional strings, not a list) is NOT;
  noun-less nested constructions; skill prose (`.md`, `.tmpl`; slice 6). The ratchet therefore guarantees
  "no new list-literal gh issue|pr|project|label call", not "no new gh call".
- Controls for each COVERED dynamic shape (B2), as synthetic `count_sites` unit tests with an explicit
  decision each: `["gh", *args]` counts 1; `["gh", noun, "view"]` counts 1; `["gh", "api", ...]` counts 0;
  `which("gh")` and `X = "gh"` count 0; `["gh","repo","view"]`/`["gh","run","list"]`/`["gh","auth","status"]`
  count 0; plus one test per uncovered shape (`"issue view".split()`, `args += [...]`) asserting count 0,
  labeled "documented gap — not detected", so the gap is pinned and a later widening is a conscious edit.
- The test does NOT mutate the tree; the red controls below do it by hand and revert.

## Risks and failure modes (per AGENTS.md properties)

- RELIABILITY: third-shape wording and every proxy REST behaviour are unverified against a real cloud
  session; docs and test names say "from the issue". Doctor's "unavailable" is inferred from env, not
  proven; the reason string says so. Merge/check-state mapping not attempted.
- RESILIENCY: stale "unavailable" cache self-heals via TTL (900 s) and `env_key` mismatch; override env is
  the polite lever; cache write failure never fails the check; corrupt cache = miss.
- SAFETY: probe is opt-in (`probe=True` + injected `run`), single read-only call, no background process,
  no retry, no secret in the cache; slice 1 adds no new network call anywhere by default.
- SCALABILITY: probe O(1); `list_issues`/`view_issue` O(pages) bounded by `cap` (`--paginate` rejected as
  unbounded); ratchet scan is O(files) AST parse of `skills/` + `hooks/` (state the measured wall time in
  the test docstring; if over ~2 s, cache nothing but drop to `-k` free path, do not add a global).
- LIVENESS: doctor names the disabled features, so a degraded mode is visible rather than silent. Status
  line deferred (slice 6) — known gap.
- R-ratchet: the counting rule is the single rule above; uncovered shapes (split() strings, string-form
  calls, `+=`/append-built argv, positional-string wrappers) are named in the docstring and docs and pinned
  by "documented gap" tests; the baseline depends on the rule, so changing it needs regeneration. The stale-entry rule can cause friction for
  unrelated edits that delete a gh call: intended, the message gives the exact fix.
- R-registration: forgetting `LIBRARY_ONLY` would make `test_script_help` fail for gh_api (Step 4 covers it).
- R-conftest: any un-injected `gh` in new tests fails loud; all tests inject. A probe default of `run=None`
  with `probe=True` must raise a clear `ValueError` rather than shelling out (tested).
- R-import cycles: `gh_api` imports `gh_session` eagerly and `sources` only lazily when `list_issues` is
  called without `fetch=` (tests always inject; importing `gh_api` is asserted not to load `sources`, R6);
  `sources` must not import `gh_api` in this slice (asserted by a test that greps `sources.py` for `gh_api`, removed when slice 2 lands).
