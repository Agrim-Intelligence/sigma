## Decisions (resolving the research Open decisions)

1. "Modern shape" is defined by stream KIND, not by field presence. Modern = kind `record` (`token_usage_record.payload.usage`) or `event` (`event_msg` token_count `info.last_token_usage`). Legacy = top-level `token_count` (payload is the usage).
   - Modern: `cached_input_tokens`, `reasoning_output_tokens`, `cache_write_input_tokens` default to 0 when ABSENT. `split_reported` is True when `cached_input_tokens` is present, else False (so a consumer can tell a measured zero from an unreported one).
   - Legacy: all three report 0 and `split_reported` is False. Legacy rows are never rejected for lacking them (keeps `tests/test_phase_report.py:774` and `:993` valid).
   - Any PRESENT new field that is not a non-bool int >= 0 makes `_codex_usage_pair` return `None` (all kinds). The row is then skipped by the existing `continue`, exactly as a bad `input_tokens` is today. Whole-rollout `None` is not introduced.
   - Invariant checks (`cached <= input`, `reasoning <= output`): a present value violating them is malformed, returns `None` (a cached count larger than input would make #1666's `input - cached` negative). Measured to hold on all 1,670 rows (design PC-3/PC-12), so no real row is lost.
2. `_codex_usage_pair(usage, modern=True)` returns a dict or `None`: `{"input_tokens", "cached_input_tokens", "output_tokens", "reasoning_output_tokens", "cache_write_input_tokens", "split_reported"}`. `modern=False` is passed for the legacy kind. Its only callers are inside `find_codex_token_totals`.
3. Per-request row `ts` is `norm_ts(timestamp)` (same normalised epoch form `iter_assistant_turns` gives Claude turns, which `price_turn`/`select_rate` consume). Raw timestamp string is not kept.
4. `cache_write_input_tokens` is per-request only (row key). No `tokens_cache_write_in` total, no event field. #1666 poisons a priced phase if any row has nonzero cache write and no rate.
5. `tokens_cached_in` and `tokens_reasoning_out` are written to the `phase` and `spend` events for Codex-measured phases only, as strings, including "0" (a measured zero). Never written for Claude, unmeasured, or non-Codex phases.
6. Cross-stream refusal stays comparing `[:3]` (tin, tout, count). De-dup fingerprint stays `((input_tokens, output_tokens), (cum_input, cum_output))`, built from the first two fields only, so a `total_token_usage` lacking the new fields still fingerprints. Neither is made stricter (behaviour change for existing partial writes is out of scope).

## Stable downstream contract for #1666 (field names and semantics)

Event fields (kinds `phase` and `spend`, numeric, non-prose, written as strings by `loop.py`/`_record_end_usage`):
- `tokens_in`: unchanged. Sum of Codex `input_tokens`. INCLUDES cached input.
- `tokens_cached_in`: NEW. Sum of `cached_input_tokens`. A SUBSET of `tokens_in`; never added to it. Billable uncached input = `tokens_in - tokens_cached_in`.
- `tokens_out`: unchanged. Sum of `output_tokens`. INCLUDES reasoning.
- `tokens_reasoning_out`: NEW. Sum of `reasoning_output_tokens`. A SUBSET of `tokens_out`; reporting only, never added, never priced separately (price `output_tokens` once, design B-1).

`find_codex_token_totals` return keys: `tokens_in`, `tokens_cached_in`, `tokens_out`, `tokens_reasoning_out`, `models`, optional `unknown_model_turns`, and NEW `requests`: a list of per-request rows
`{"model": str | None, "ts": <norm_ts epoch>, "input_tokens", "cached_input_tokens", "output_tokens", "reasoning_output_tokens", "cache_write_input_tokens", "split_reported": bool}`.
`model` is None for an unknown-model request (#1666 must refuse to price it). Rows are in file order, from the chosen stream only. `requests` flows through `collect_phase_usage` (`**codex_totals`) but is NOT written into any ledger event (scalability: only totals are written; rows are bounded in memory by the rollout, about 200 per phase measured, linear at 100x).

Raw ceiling: `codex_raw_tokens = tokens_in + tokens_out` (`phase_report.py` about `:2020`) is untouched. Never add the new fields.

## Measurement and failure statements

- Reliability: the split is parsed from rollout files that design 1379 PC-3/PC-12 measured (1,670 rows, 8 rollouts: cached <= input, reasoning <= output, cache_write 0 in all). This plan re-measures nothing live and runs no model; all fixtures are offline. The 97.8% cached figure is the design's, not re-measured here.
- Scalability: per-request rows are an in-memory list from a single linear pass of a file already read once; about 200 per phase measured, 20k at 100x, still bounded by the rollout. No rows are written to the ledger, so no unbounded table growth. No new lock or global chokepoint.
- Resiliency: a malformed new field skips that request (existing semantics for a bad input/output) and undercounts the total; a skipped-row count is out of scope, noted as a known limit. A rollout with no valid request still returns `None`. No retry, no state, nothing to re-ship; the budget ceiling is unchanged so recovery behaviour is unchanged.
- Safety: pure parsing, no spawn, no network, no config or secrets, no resource limit. Refusal stays loud for paired-stream mismatch (returns `None`).
- Liveness: no new component. Host-agnostic: Python on Codex's own rollout files, no hook involved.
- Not done here (named, not hidden): pricing the split (#1666), a skipped-row count, `tokens_cache_write_in` total, strictening the cross-stream refusal.
