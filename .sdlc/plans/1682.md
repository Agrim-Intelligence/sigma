# Plan 1682: a failed delete of a merged goal branch is announced, and leftovers are reconciled

Goal: `_delete_remote_branch` stays best-effort but stops being silent; `finish()` finds `sdlc/*` branches whose PR
merged and whose remote ref is still at the merged head, and retries the delete with the same guards, pinned to
the listed head. Acceptance: `.sdlc/acceptance/1682.md` (AC-1 to AC-5). Ask 3 (branches Sigma did not cut) and
recording the merged head on the ledger branch are out of scope; the latter is a PROVISIONAL note on the issue.

## Design
- One delete site only. The inventory pins (`tests/test_no_autonomous_feature_branch_deletion.py`, write-surface)
  allow exactly one REST DELETE in `work.py`; the reconcile calls `_delete_remote_branch`, it never builds a second.
- `_delete_remote_branch` gains: a `feature/` clause (new, own refusal); an optional `expect_sha` lease (re-read the
  ref, refuse unless it still equals the listed sha; refuse when it cannot be read); a failure announcement (stderr
  line naming branch and error, plus a `gate` action-log entry, verdict `failed`); "Reference does not exist" counts
  as already gone (True, silent), any other error does not. A 404 that is not that message (no access) stays a failure.
- In a cloud session (`CLAUDE_CODE_REMOTE` true) the failure line adds that the branch needs a sweep from a host that
  can delete, naming branch and head (the lease sha, else a REST read, else the local branch).
- REST has no conditional delete, so the lease is read-then-delete. The window between the two calls is not removed;
  it is documented, and not measured.
- Reconcile: `merged_leftovers()` is read-only: list refs under the branch prefix (`git/matching-refs`), then for at
  most `RECONCILE_LOOKUPS` (10) branches read the PRs for that head. Eligible = a PR merged at the ref's head sha, no
  open PR on that head, no open PR based on the branch, head repo is this repo. `reconcile_merged_branches()` retries
  the delete on each, stops attempting after the first failure (a token or proxy that rejects one rejects all) and
  lists the rest with their heads. Cost: 1 + 3 per candidate calls, never per PR in history; the cap bounds one
  pass, so 54 leftovers drain over 6 finishes. Calls are REST only. Never raises.
- `finish()` calls it after its own cleanup (not on `--force`). New verb `work.py branches <sdlc_dir> [--delete]` is
  the read-only listing (and the sweep gesture the cloud message names). `/sigma-status` is not touched: a live
  GitHub read does not belong on its one-line summary.

## Tests (first, against local bare repos and a fake `gh` on PATH that refuses any repo but the temp one)
- failed delete prints branch and error, writes the gate entry, returns False, never raises (AC-1); refusal arm unchanged.
- feature/ clause alone; lease clause alone (ref moved), lease unreadable; already-gone is silent True.
- cloud message names branch and head and the sweep; absent outside a cloud session (AC-3).
- reconcile: lists merged-at-head; skips moved head, open PR, open PR based on the branch, foreign head repo,
  unmerged-closed PR; retries with the guards; stops after first failure; cap; finish() integration (AC-2).
- Controls: break each of the four guards, the feature clause, the lease, and each reconcile clause on its own and see red;
  run the documented `work.py branches` gesture.
