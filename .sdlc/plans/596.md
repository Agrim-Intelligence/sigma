# Plan: #596 make the growth-audit CLI test independent of repo size and runner speed

Inputs: issue #596, `.sdlc/research/596.md`, `.sdlc/acceptance/596.md`. Test-only change; `tools/readiness/growth_audit.py` is untouched.

## Design

The unit under test is the audit's logic, not how fast a runner walks this repository. Replace the one whole-repo
CLI test with two:

1. `test_cli_scan_over_a_fixture_tree_keeps_sources_writer_coverage`: builds a small tree (a `sources.py`-shaped
   writer of `.sdlc/journey/<goal>.md` plus a two-function helper cycle), runs the real `growth_audit.py` as a
   subprocess, asserts exit 0 and the same row the old test asserted. Limit 120 s, named a hang guard: the scan of
   that tree is milliseconds, so the limit never decides the result.
2. `test_slow_whole_repository_cli_scan_keeps_sources_writer_coverage`: the one whole-repo CLI scan, marked
   `@pytest.mark.slow` (marker registered in `tests/conftest.py`), limit 600 s, a hang guard derived from the
   measurement (6.5 s here, over 15 s on the slow CI leg; 600 s is about 90x the local figure and 40x the CI lower
   bound) and named in a comment. Same assertion as the old test.

Added guard `tests/test_no_short_whole_repo_scan_timeout.py`: an AST walk over `tests/test_*.py` failing on any
`subprocess.run` with a constant timeout under 60 s whose command or cwd names the repository root. Its own control
test checks the detector on the old shape (flagged), a fixture run (quiet) and a generous limit (quiet).

Not changed: every other assertion in the file (cyclic helpers, LocalSource rows, B6 disposition, store measurements);
the dispositions mechanism `docs/launch/dispositions/*.json` is covered by `tests/test_growth_disp.py` and the
`tests/test_b6_*.py` nodes, none of which is edited.

## Red proof (how it is produced)

The code under test does not change, so the red is the guard, which is a separate unchanged file (red and green bind
to its bytes): with the OLD `tests/test_readiness_growth_audit.py` present the guard node fails with an
AssertionError naming `test_readiness_growth_audit.py:286`; after the edit it passes. Observed with
`red_green.observe` at `COLUMNS=250` before and after. The user-facing failure mode is shown separately with an
injected delay (a `sitecustomize.py` that sleeps 20 s, put first on `PYTHONPATH` of the unchanged pytest
invocation): old file red by `TimeoutExpired`, new file green. Both recorded in the PR.

## Steps

1. Guard file first; red on the old test file (red_green.observe).
2. Edit the test file and register the marker; green.
3. Injection demonstration on old and new files; CI measurement via a throwaway workflow on a scratch branch.
4. Narrow tests, then the configured verify once.
