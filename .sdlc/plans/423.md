# Plan: #423 — managed policy survives deletion of its file

## Design
1. New status `enrolled-policy-missing` (`STATUS_ENROLLED_POLICY_MISSING`), added to
   `REFUSING_STATUSES`. Distinct from `not-adopted` (never enrolled).
2. Enrolment memory = two markers, either one sufficient:
   - `<sdlc_dir>/state/managed-enrolled.json`
   - `<per-checkout git dir>/sigma-managed-enrolled.json` (found by walking up from the sdlc dir's
     parent for `.git`; a `.git` file `gitdir: X` is followed; no subprocess). Absent when not in git.
   Written best-effort (never raises, atomic tmp+replace) by `read()` when it parses a valid file
   with status `ok` or `access-revoked`. Presence-only check: a truncated marker still counts.
3. `is_adopted()` gains a third signal: enrolled. `read()`: file absent AND enrolled ->
   `(STATUS_ENROLLED_POLICY_MISSING, None, None)`; absent and not enrolled -> `not-adopted`
   exactly as today (declared-project_id-only checkouts, fresh clones: unchanged, no outage).
4. `gated_check` reason for the new status names the lever.
5. Lever: `managed_settings.py unenroll <sdlc_dir>` removes both markers (idempotent, local, no
   network, prints what it removed); `managed_settings.py status <sdlc_dir>` prints the status.
   Restoring the file from the policy writer clears the refusal with no command. Refusal affects
   only policy-sensitive gates (merge, pr, journal), never doctor/read paths: not an outage.
6. `ledger.journal_on` already treats REFUSING statuses as OFF: journal goes dark on deletion
   (visible via doctor), same as revoked.
7. Doctor row `managed settings:` reports `enrolled, policy file missing (run unenroll or restore)`
   instead of `absent` (cross-load managed_settings, fail open to `absent`).
8. `tests/test_script_help.py`: drop `managed_settings` from LIBRARY_ONLY (it now has a CLI).
9. Docs: README "Managed settings" section: replace "If the file is absent ... uses the
   repository's own config" with the enrolled/never-enrolled split, the persistence boundary
   (marker locations, host-agnostic, Claude hook `plan_gate.sh` is an accelerator and still reads
   only the file), and the residual risk. `docs/threat-model.md` T6 row gets the same pointer.
   Module docstring updated (five statuses).

## Tests (written first; must be RED on unfixed code)

test; no network, HOME untouched):
- never-enrolled, file absent -> not-adopted, allowed True (control stays green both sides).
- enrol (read a valid ok file), delete only the file -> enrolled-policy-missing, allowed False,
  reason names `unenroll`; same with a declared project_id in config.
- enrol then delete file AND `.sdlc/state` marker -> still refused through the git-dir marker.
- enrol, restore file -> ok, allowed True.
- access-revoked file also enrols.
- invalid-JSON file does not enrol (so a garbage file cannot enrol a checkout).
- lever: `unenroll` via the CLI subprocess (documented gesture) -> not-adopted; idempotent.
- end-to-end seam: `work.effective_review_mode` and `work.effective_hard_plan_gate_locked`
  return a refusal after deletion; `ledger.journal_on` returns False.
- residual pinned honestly: deleting file + both markers -> not-adopted (documented limit).
- unwritable marker location -> read() does not raise.
