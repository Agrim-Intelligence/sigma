# #359 plan — release, pin/rollback, and incident runbook

## Scope and constraints

Ship a release runbook and an evidence-backed statement of the currently usable
pin/rollback gesture.  The public snapshot repository and its `v1.0.0` tag do
not exist yet, so this goal must not create either one or claim that an
unmeasured remote tag works. All plugin probes use isolated temporary `HOME`,
`CLAUDE_CONFIG_DIR`, and `CODEX_HOME`; the real profile's plugin surface is
hashed before and after. No predecessor install, GitHub setting, repository,
tag, or release is changed.

## Definition of done

1. `docs/release.md` gives semantic versioning, a numbered owner release
   checklist, the exact tested pin/rollback result, an incident plan, and the
   stop/repoint/verify procedure required before the private-name takeover.
2. `docs/launch/evidence/pin-rollback-2026-10-02.md` records only commands and
   sanitized outcomes actually observed in isolated profiles, including the
   unavailability of the future `v1.0.0` source.
3. Tests require dated release headings, manifest alignment, the release
   document's decisive sections, and the doctor public-slug relation only when
   the definition is signed.
4. The documented test gesture is deliberately made red by a missing-date
   changelog heading, then restored green; no install/pin claim is based on a
   synthetic CLI.

## Steps

1. Add `tests/test_release_consistency.py` first, including the missing-date
   red control and signed-definition doctor-slug assertion; run it against the
   unchanged tree and retain the red result.
2. Run the three pin-source probes in new isolated profiles: `repo@tag`,
   `repo#tag`, and a local clone/path. Record complete sanitized transcripts,
   profile hashes, and the measured commit SHA. If the future public tag is
   unavailable, document that limitation instead of replacing it with a claim.
3. Add the release runbook, evidence artifact, and the publish-runbook wording
   correction.  Keep all release/tag/create actions owner-attended.
4. Run focused tests, the documented missing-date mutation red/green control,
   an independent review, the required full suite, then commit/PR/CI.
