## Decisions (for plan-review)

- **D1 — the brief is printed by `loop.py`, on the existing HANDOFF path, not by a new verb and not
  by prose.** In the `next` and `next-batch` CLI branches, after `_print_pick`, when the kind is
  `HANDOFF` the CLI prints `_successor_brief(sdlc_dir, argv_tail)` to **stderr**, once per call.
  Stdout stays the bare `HANDOFF` token, byte-identical, because three consumers match it as an
  exact line (`supervise_classify.py:85-88`, `chain.py:1464`, `:1485`). The trigger logic
  (`_session_count_stop`, `_handoff_reason`) is not touched; slice 2's context trigger returns
  through the same `("HANDOFF", reason)`, so its trips print the brief too.
- **D2 — the run's flags come from the call's own argv.** Research found they are persisted nowhere
  (`loop.py:6823-6833` applies them per call; the daemon launches bare `/sigma-loop`,
  `supervise_daemon.py:576-588`). `--feature` and `--label` are the only run-scoping flags; `--skip`,
  `--session-pid`, `--max-concurrent` are per-call and NOT carried. `_cli_scopes` has validated both
  names before the brief runs; they are still quoted.
- **D3 — the resume line reuses init's host-neutral convention** (`init_flow.py:850-856`):
  `/sigma-loop <flags> (Codex/Cursor: <python> <loop.py> next <dir> <flags>)`, built with
  `verify_detect.python_command()` and `verify_detect._q()` (stdlib-only, loaded by path from
  `skills/sigma-init/scripts/verify_detect.py:87-91`, `:131-133`), `<loop.py>` being this file's
  real path, so the line runs as pasted.
- **D4 — live slots are `log.py slots()` verbatim.** Loaded by path
  (`_HERE.parent.parent / "sigma-log" / "scripts" / "log.py"`, the `loop.py:873` precedent; log.py
  imports only the stdlib). It is a constructed Block A, so the brief carries no hand-built status
  line. Any exception becomes one line `live slots: unavailable (<ExcName>); run log.py slots <dir>`.
- **D5 — open decisions from local files only, no network at a stop.** `local` source: the `## `
  headings of `.sdlc/state/review-queue.md`, labelled for what they are —
  `parked goals ever queued (review-queue.md, not pruned): a, b, ...` (at most 10, then `+N more`),
  or `parked goals ever queued: none (review-queue.md)`. The file is append-only and an unparked
  goal stays in it, so the label says "ever queued" rather than implying they are open now.
  `github` source: `parked goals: issues labelled sdlc:parked` (github parks never write the queue,
  `state.py:1214`, `triage.py:394-398`). The four-line heading read is inlined with a comment naming
  its twin `triage._review_queue_names`: loading `triage.py` pulls `work`, `sources`, `ledger`,
  `watch` and four more modules at import (`triage.py:51-59`) for one regex.
- **D6 — the meter's threshold is slice 2's resolver, imported; never a second one here.** Task 0
  waits until #2027 is on main. Recorded on #2027: a pure function beside `_handoff_ceiling`,
  `(config, baseline) -> (threshold | None, origin)`, returning `None` when `handoff.enabled` is
  false. The meter calls it with `baseline` = `--baseline` (or `None`) and prints a real threshold
  and verdict; `threshold=none (<origin>) verdict=unknown` only when the resolver returns `None`
  or the reading is unavailable. If #2027's merged signature differs, the implementer adapts the
  one call site and says so in the PR; it does not add a resolver.
- **D7 — the read-only verb is `loop.py meter <dir> [--baseline TOKENS]`.** Named `meter`, not
  `context`, so it is not confused with the `/sigma-context` skill. It takes a FRESH reading with
  slice 1's `loop_session_model.context_reading()` and never calls `_record_context`,
  `write_session_heartbeat`, `_ensure_watcher`, `_surface_inbox`, a source, or a claim. It is not
  in `_ARMS_CLAIM` (`loop.py:2170`). One stdout line, exit 0; a non-positive or non-integer
  `--baseline` is exit 2 with one stderr line and empty stdout. Format (pinned by tests):
  `meter: context=<N|unavailable (<reason>)> source=<host|unavailable> threshold=<N|none> (<origin>) verdict=<under|over|unknown>`,
  `over` when `context >= threshold`. `--baseline` exists because a supervisor session never picks,
  so it has no heartbeat `first_pick`; it passes the reading from its own first wake.
- **D8 — host-neutral wording; no code reads `CLAUDE_CODE_ENTRYPOINT`.** PC-9 allows the hint for
  wording only; one brief that reads correctly everywhere needs no detection, and a mis-detection
  cannot mis-word it. The docs name the hint as undocumented and unused.
- **D9 — the classifier ignores the brief when probing for a usage limit (in scope).** The daemon
  writes the last 50 lines of the session's final message to the tail it classifies
  (`supervise_daemon.py:530`, `:710-713`). `_LIMIT` and `_RESET_AT` are unanchored and `_LIMIT` is
  checked before `_HOLD`, `_BUDGET` and `_HANDOFF` (`supervise_classify.py:96`, `:153-159` vs
  `:170`). A relayed brief puts slot titles in that tail, and real goal titles say "rate-limited",
  so a hand-off would sleep 1800-3600 s. Fix: a `_BRIEF` pattern matching from a line starting
  `SUCCESSOR BRIEF:` to the next line starting `open decisions:` (`re.S | re.M`, non-greedy), and
  `classify` probes `_LIMIT` and `_RESET_AT` against `_BRIEF.sub("", text)` — the `_ABNORMAL.sub`
  precedent at `supervise_classify.py:197`. Only those two probes change; `_DONE`, `_HOLD`,
  `_BUDGET`, `_HANDOFF` and the crash probe still see the whole text. Both anchors are required:
  a brief cut before its `open decisions:` line strips nothing (today's behaviour), because
  stripping to the end of the text would also hide a real host usage-limit line printed after it.
  The fixed brief text also avoids every earlier pattern (no "limit", "quota", "backlog empty", no
  bare `DONE`/`BUDGET`/`HOLD` line, no line starting `LOOP STOP:`). The brief's own last line
  therefore starts `open decisions:` in every branch of D5.
- **D10 — prose net-shrinks.** The orchestrator ratchet has 22 est-token headroom (32,400 / 32,422,
  measured on `504de5c1`) over SKILL.md, picking.md, stopping.md and five more; slice 2 edits the
  same files. This slice edits only SKILL.md:239-241, stopping.md:29-56 and picking.md:166-169, each
  to fewer words: code now prints what that prose told the model to compose. The host paths and the
  supervisor rules go in `docs/running-the-loop.md` (unmeasured; read by people and supervisor
  sessions). Lines slice 2 owns are untouched: SKILL.md:37, :47-52; picking.md:38, :44, :151-153,
  :172-174; running-the-loop.md:57-60, :80-81; parallelism.md:95-97 (line numbers re-located after
  the Task 0 rebase). The ceiling is not lowered here.
- **D11 — deferred, with a ticket the orchestrator files:** the daemon's relaunch drops
  `--feature`/`--label` (research TD-2). The brief says so in its "who starts it" line.

### The brief (exact shape, pinned by tests)

```
SUCCESSOR BRIEF: this session stops claiming, finishes its live goals, then retires.
resume: start a NEW session (not this conversation) and run: /sigma-loop --feature voice --label run-x (Codex/Cursor: python3 /abs/skills/sigma-loop/scripts/loop.py next .sdlc --feature voice --label run-x)
who starts it: supervise_daemon.py relaunches by itself (without --feature/--label); an attended desktop supervisor session proposes it as a one-click card; otherwise a person or a scheduler starts it.
live slots (finishing in this session; the successor will not pick them):
<log.py slots output, verbatim>
open decisions: <parked goals ever queued (review-queue.md, not pruned): a, b | parked goals ever queued: none (review-queue.md) | parked goals: issues labelled sdlc:parked>
```

With no scope flags the resume line is `... run: /sigma-loop (Codex/Cursor: python3 <loop.py> next .sdlc)`.

## Risks for plan-review

- **Order with slice 2.** Implementation starts only after #2027 merges (Task 0). Both slices edit
  the hand-off prose files; this one only shrinks and touches no line slice 2 owns (D10).
- **The brief is printed at the first HANDOFF, while slots are still live.** Intended: the live slots
  are what the successor must not duplicate, and claims already prevent it. A drained orchestrator
  has the brief in its own context to relay at STOP.
- **The 50-line tail.** If a final message is long enough that the brief's `SUCCESSOR BRIEF:` line
