## Decisions (for plan-review)

- **D1 — the brief is printed by `loop.py`, on the existing HANDOFF path, not by a new verb and not
  by prose.** In the `next` and `next-batch` CLI branches, after `_print_pick`, when the kind is
  `HANDOFF` the CLI prints `_successor_brief(sdlc_dir, argv_tail)` to **stderr**, once per call.
  Stdout stays the bare `HANDOFF` token, byte-identical, because three consumers match it as an
  exact line (`supervise_classify.py:85-88`, `chain.py:1464`, `:1485`). The trigger logic
  (`_session_count_stop`, `_handoff_reason`) is not touched; slice 2 (#2027) adds its context
  trigger through the same `("HANDOFF", reason)` return, so its trips print the brief for free.
- **D2 — the run's flags come from the call's own argv.** Research found they are persisted nowhere
  (`loop.py:6823-6833` applies them per call; the daemon launches bare `/sigma-loop`,
  `supervise_daemon.py:576-588`). `--feature` and `--label` are the only run-scoping flags
  `/sigma-loop` takes; `--skip`, `--session-pid`, `--max-concurrent` are per-call and are NOT
  carried. `_cli_scopes` has already validated both names before the brief runs; they are still
  `shlex.quote`d.
- **D3 — live slots are `log.py slots()` verbatim.** Loaded by path
  (`_HERE.parent.parent / "sigma-log" / "scripts" / "log.py"`, the `loop.py:873` precedent; log.py
  imports only the stdlib). It is a constructed Block A, so the brief carries no hand-built status
  line. Any exception becomes one line `live slots: unavailable (<ExcName>); run log.py slots .sdlc`
  — a brief never costs the stop.
- **D4 — open decisions from local files only, no network at a stop.** `local` source: the `## `
  headings of `.sdlc/state/review-queue.md` (comma-joined, at most 10, then `+N more`), or
  `none recorded in .sdlc/state/review-queue.md`. `github` source: the pointer
  `issues labelled sdlc:parked` (github parks never write the queue, `state.py:1214`,
  `triage.py:394-398`). The four-line heading read is inlined with a comment naming its twin
  `triage._review_queue_names`: loading `triage.py` pulls `work`, `sources`, `ledger`, `watch` and
  four more modules at import (`triage.py:51-59`) for a regex.
- **D5 — the read-only verb is `loop.py meter <dir> [--baseline TOKENS]`.** Named `meter`, not
  `context`, so it is not confused with the `/sigma-context` skill. It takes a FRESH reading with
  slice 1's `loop_session_model.context_reading()` and never calls `_record_context`,
  `write_session_heartbeat`, `_ensure_watcher`, `_surface_inbox`, a source, or a claim. It is not
  in `_ARMS_CLAIM` (`loop.py:2170`) and has 3 argv words, so the claim-arming prologue cannot fire.
  One stdout line, exit 0; a non-positive or non-integer `--baseline` is exit 2 with one stderr
  line. Format (pinned by tests):
  `meter: context=<N|unavailable (<reason>)> source=<host|unavailable> threshold=<N|none> (<origin>) verdict=<under|over|unknown>`.
  `--baseline` exists because a supervisor session never picks, so it has no heartbeat
  `first_pick`; it passes the reading from its own first wake.
- **D6 — one threshold resolver, slice 2's; never a second one here.** The verb's threshold comes
  from #2027's resolver called with `(config, baseline)`. Slice 2 has no plan yet
  (`.sdlc/work/2027` is at `origin/main`). Rule: **whichever of #2027 / #2029 merges second wires
  the meter to the resolver.** If #2027 is on main at implement time, Task 2 step 2.5a calls it; if
  not, step 2.5b prints `threshold=none (no context threshold on this install; goal count only)`
  with `verdict=unknown`, and the orchestrator adds "wire `loop.py meter` to the resolver" to
  #2027's plan. `handoff.enabled: false` prints `threshold=none (handoff disabled)` either way.
- **D7 — host-neutral wording; no code reads `CLAUDE_CODE_ENTRYPOINT`.** PC-9 allows the hint for
  wording only; one brief that reads correctly everywhere needs no detection, and a mis-detection
  cannot mis-word it. The docs name the hint as undocumented and unused.
- **D8 — prose net-shrinks.** The orchestrator ratchet has 22 est-token headroom (32,400 / 32,422)
  over SKILL.md, picking.md, stopping.md and five more, and slice 2 edits the same files. This slice
  edits only SKILL.md:239-241, stopping.md:29-56 and picking.md:166-169, each to fewer words: code
  now prints what that prose told the model to compose. The three host paths and the supervisor
  rules go in `docs/running-the-loop.md` (unmeasured, read by people and supervisor sessions). Lines
  slice 2 owns are untouched: SKILL.md:37, :47-52; picking.md:38, :44, :151-153, :172-174;
  running-the-loop.md:57-60, :80-81; parallelism.md:95-97. The ceiling is not lowered here (slice 2
  needs the headroom).
- **D9 — the fixed brief text is safe for the daemon's classifier.** The model relays the brief in
  its final message, which `supervise_classify.classify` reads; `_DONE`, `_DONE_DEGRADED`,
  `_LIMIT`, `_HOLD` and `_BUDGET` are checked before `_HANDOFF`. The fixed text avoids every one
  (no "limit", "quota", "backlog empty", no bare `DONE`/`BUDGET`/`HOLD` line, no line starting
  `LOOP STOP:`), and a test proves `LOOP STOP: handoff` + brief still classifies as the 60 s
  hand-off relaunch. Free-text slot titles can still contain "rate limit" (research TD-1): that is
  pre-existing for any relayed Block A and is deferred with a ticket, not fixed here.
- **D10 — deferred, with tickets the orchestrator files:** TD-1 (`_LIMIT` unanchored and ahead of
  `_HANDOFF`), TD-2 (the daemon's relaunch drops `--feature`/`--label`).

### The brief (exact shape, pinned by tests)

```
SUCCESSOR BRIEF: this session stops claiming, finishes its live goals, then retires.
resume: start a NEW session (not this conversation) and run the sigma-loop skill: /sigma-loop --feature voice --label run-x
who starts it: supervise_daemon.py relaunches by itself; an attended desktop supervisor session proposes it as a one-click card; otherwise a person or a scheduler starts it.
live slots (finishing in this session; the successor will not pick them):
<log.py slots output, verbatim>
open decisions: <headings | issues labelled sdlc:parked | none recorded in .sdlc/state/review-queue.md>
```

With no scope flags the resume line ends `... skill: /sigma-loop`.
