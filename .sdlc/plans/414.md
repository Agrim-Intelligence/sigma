## Properties (AGENTS.md)
- Reliability: measured only on pytest 9.1.1 / py3.12 (dossier scratch repo: 0 of 5 rows at default width, 5 of 5 at `COLUMNS=1000`). pytest 7 and 8 are UNMEASURED; the real-pytest tests on the CI matrix are the evidence there. 4000 itself is unmeasured; 1000 was, and 100000 did not fail; the value only has to exceed the longest `FAILED <node> - <reason>` line. Side effect, stated rather than hidden: the user's own tests run by `observe` also see `COLUMNS=4000`, so width-dependent output (argparse help wrapping, `shutil.get_terminal_size`, rich/textwrap by terminal size) differs from a developer's shell. Red and green both run through `_run`, so the proof is self-consistent; a test that asserts 80-column wrapping can pass in a shell and fail under the gate. That is why the doc clause states the mechanism and does not claim the proof is width-independent for every test.
- Scalability: per verify, one longer `=` banner (about 1 kB at 1000, about 4 kB at 4000). At 10x or 100x nodes the banner is unchanged; output stays dominated by the node list, as today.
- Resiliency: if a pytest version ignores `COLUMNS`, the failure mode is today's (red not recorded, fail closed, `refusal` still demands a recorded red); the recovery lever is the existing `--no-tests <reason>`. Reds already lost stay lost; no migration.
- Safety: no new limits, processes, network or secrets; the child env is the caller's env plus one variable.
- Liveness: not a long-running component; no change.
- Host-agnostic: the change is in Sigma's Python (`_run`); every host gets it; no hook.
- Root checkout: nothing written there by the change; the plan file is the only file outside the worktree.
