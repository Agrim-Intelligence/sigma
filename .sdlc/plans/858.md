## Rulings (binding for implement)
* R-1 Outcome set is FOUR kinds, not three: `WON`, `LOST_RACE`, `OUTAGE`, `REFUSED`. The issue and acceptance name
  won / lost-race / outage as distinct results; a fourth does not contradict that. It is required because a
  hook decline, a directory/file ref conflict, a case-fold collision, and a permission refusal all print the same
  `[remote rejected] (failed to update ref)` family as a real server-side race (research M-3). Reporting them as
  `LOST_RACE` would make slice 3 skip a goal forever as "someone else has it"; reporting them as `OUTAGE` would make
  it retry. `REFUSED` carries a `detail` string and is never retried as a race. Unknown or garbage output is
  `OUTAGE` (not knowing is never a win and never a lost race), never `WON`.
* R-2 "Already up to date" (porcelain `=`, research M-2) is never `WON`. A re-push of the sha the remote already
  holds exits 0 even under a stale lease. Because every claim commit is unique, a legitimate write can never be
  up-to-date, so `=` is `REFUSED` with detail `up-to-date no-op`. This is also the lost-ack recovery rule: a caller that
  lost an ack re-reads its own ref (slice 3) and compares sha; the primitive never guesses.
* R-3 Every claim commit is unique per write: the message carries `nonce` (random 128-bit hex from `os.urandom`) in
  addition to holder, host, run, acquired_at, renewed_at, lease_seconds. `git commit-tree` is deterministic, so
  without a nonce two attempts with the same second-resolution fields share a sha and both "win" (research M-2).
* R-4 Ref charset (strictly stricter than git and than `sync._ref_value`): a single path component matching
  `[a-z0-9][a-z0-9._-]{0,63}`; no `..`; no trailing `.`; no `.lock` suffix; no `/`. Uppercase is REFUSED (raise), never
  folded, because folding maps two goals to one ref, and the macOS bare remote already treats `Case` and `case` as one
  ref (research M-3, M-5). Non-str input raises. Numeric goal ids pass unchanged. Raises `ValueError("REFUSED: ...")`,
  the `sync._ref_value` convention.
* R-5 Remote argument is validated with the `sync._ref_value` checks COPIED into the new module (non-str, leading `-`,
  whitespace, control characters raise). Do not import `sync` (it pulls in `ledger` and a large surface). A drift-guard
  test imports `sync` by path and asserts every hostile value `sync._ref_value` refuses is also refused here.
* R-6 Every `git push` lives in ONE function, `_push`. The write-surface ratchet counts per function; one function means
  one `git-push` entry and one `git-destructive` entry. `delete` and `create` and `renew` and `reclaim` all call it.
* R-7 The lease flag is built in ONE tiny function, `_lease_flag(ref, expected)`. That is the seam the deliberate-break
  control monkeypatches to `--force`. `expected` is `""` only for create (lease `<ref>:` means "must be absent"); delete
  and reclaim and renew always carry an expected sha, so a double release loses cleanly instead of succeeding on absence
  (research section 6, "delete a missing ref").
* R-8 Classification order: (1) timeout or exit 128 or `Could not read from remote repository` / `does not appear to be
  a git repository` / transport shapes -> `OUTAGE`; (2) `git push --porcelain` per-ref flag: `*` / `+` / `-` -> `WON`
  (but ONLY if the ls-remote tip check below agrees), `=` -> R-2, `!` -> a rejection to be measured; (3) on rejection,
  measure with `ls-remote` (`git ls-remote <remote> <ref>`, `LC_ALL=C`): tip differs from what we leased (or a create
  target now exists) -> `LOST_RACE`; tip equals what we leased -> `REFUSED` (refused for another reason); `ls-remote`
  itself unreadable -> `OUTAGE`. Absent (empty `ls-remote` output with rc 0) and unreadable (non-zero rc) are
  DIFFERENT results, unlike `feature_rebase.remote_tip` which returns `None` for both (research section 4 last note).
  Prose is never matched, except to recognise the transport-failure outage shape, which has no porcelain line at all.
  After a claimed win (`*`/`+`/`-`), the same `ls-remote` check confirms the tip is our sha (or absent for delete); a
  disagreement is `OUTAGE`, never `WON` (the `feature_rebase._pushed` discipline).
* R-9 Git runner is injectable: `run(cwd, argv, env, timeout)`; the default runs `Popen(..., start_new_session=True)`,
  `communicate(timeout=)`, and on timeout `os.killpg` the whole process group (so an `ssh` or `git-remote-*` grandchild is
  not orphaned), with `GIT_TERMINAL_PROMPT=0`, `stdin=DEVNULL`, `LC_ALL=C`. A timeout is `OUTAGE`. On `os.name == "nt"`
  the default runner REFUSES loudly (`RuntimeError("REFUSED: claim_refs is not supported on Windows (process-group
  kill unavailable)")`) rather than proceed with a plain timeout (AGENTS.md SAFETY: no silent half-guarantee).
  `run_with_timeout.py` wraps a Python script, not an arbitrary command, so it is not reused.
* R-10 `lease_seconds` is a REQUIRED argument carried in the claim message; no 30-minute (or any) default constant is
  introduced here (the shipped lease clock is `ledger.lease.ttl_hours: 12`, a different clock, design D-1).
* R-11 `observed_age` is pure: caller owns `seen` (a mapping goal -> `(sha, first_seen)`), clock is injected. It returns
  `(age_seconds, new_seen)` without mutating the input. A changed sha resets the clock; an unchanged sha keeps its
  original `first_seen`; age is clamped to `>= 0` on a backwards clock. Persisting `seen` across processes is slice 3/5;
  the docstring states the limit: `time.monotonic()` does not survive a process, so persistence must use wall time with a
  skew guard (design D-7). No file is written, so no new write surface.
* R-12 `claim_refs.py` is a LIBRARY: no `__main__`, no CLI. Add `"claim_refs"` to `LIBRARY_ONLY` in
  `tests/test_script_help.py`.
* R-13 Hermetic harness rules (apply to both test files): every repo lives under `tmp_path`; remotes are bare repos
  addressed by filesystem path built with `git init -q --bare`; each "clone" is `git init -q` with NO commits (the primitive
  uses `commit-tree` on the built-in empty tree and `push <sha>:<ref>`, verified to work in an empty repo); the git env
  sets `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_SYSTEM` to `os.devnull`, explicit author/committer name/email/date, `LC_ALL=C`.
  The `build_claim` helper also sets identity explicitly (fixed `sigma <sigma@localhost>`), so nothing depends on the host's
  git identity (CI sets one, other hosts may not). A guard test asserts every remote string used is a path under `tmp_path`
  and `GIT_CONFIG_GLOBAL == os.devnull` in the test env.

## Module shape (`claim_refs.py`, stdlib only: subprocess, os, re, time, json not needed)
* Constants: `NAMESPACE = "refs/sigma/claims/"`, `EMPTY_TREE = "4b825dc642cb6eb9a060e54bf8d69288fbee4904"`, kinds
  `WON, LOST_RACE, OUTAGE, REFUSED`.
* `Outcome` - small frozen dataclass or namedtuple: `kind`, `sha` (the sha now at the ref when known, else `""`),
  `detail` (short, no secrets, no remote URL).
* `validate_goal_id(goal)` -> lowercase component or raises; `validate_remote(remote)`; `claim_ref(goal)` -> full ref.
* `build_claim(cwd, holder, host, run, acquired_at, lease_seconds, renewed_at=None, *, runner=None)` -> sha of a
  parentless empty-tree commit via `commit-tree`; message is `key: value` lines; unique per call (R-3);
  `parse_claim(message)` -> dict, tolerant of unknown keys, raises `ValueError` on missing required keys or a non-integer
  `lease_seconds`.
* `_lease_flag(ref, expected)` (R-7); `_push(cwd, remote, ref, expected, sha_or_None, *, runner, timeout)` (R-6, R-8);
  `classify(...)` pure function over `(rc, porcelain, stderr, timed_out, tip_after, tip_known, leased_sha, our_sha)`.
* Verbs: `create(cwd, remote, goal, claim_sha)`, `renew(..., expected, new_sha)`, `reclaim(..., observed_stale_sha, new_sha)`,
  `delete(..., expected)`; each returns `Outcome`.
* Reads: `read_tips(cwd, remote)` via `ls-remote` (cheap; returns `{goal: sha}`, raises an `Outcome`-style outage rather than
  returning `{}` on unreadable); `read_all(cwd, remote)` via namespace fetch, returns `{goal: (sha, parsed_claim)}`.
* `observed_age(seen, goal, sha, now)` (R-11).

## Scalability (10x / 100x) and ceilings (measured on local-path transport; network NOT measured)
* Per-claim push cost is O(total refs on the remote), not O(claim refs): receive-pack advertises every ref, branches and tags
  included. Measured single create push (research section 5): 0.045 s at 10 refs, 0.054 s at 100, 0.152 s at 1000, 0.662 s at
  5000. 10x refs from 100 to 1000 is ~3x per push; 100x (10 to 1000) ~3.4x. Ceiling to state in slice 3's docs: a repo that
  has accumulated thousands of branches pays for it on every claim.
* Namespace fetch (read_all) is linear with a ~25 ms process-start floor: 0.040 / 0.054 / 0.235 / 1.532 s first fetch at
  10 / 100 / 1000 / 5000 refs. `read_tips` (ls-remote) is 4x to 13x cheaper (0.015 / 0.016 / 0.036 / 0.115 s) so a pick-time
  "who holds what" check uses `read_tips`, and `read_all` is used only when claim bodies are needed. This slice re-measures
  10 / 100 / 1000 in the harness; 5000 is cited from research, not re-run.
* Renewals leave one unreachable object per renewal on the remote (300 renewals -> 301 loose objects, ~4 KB each, reclaimed
  by the host's gc; empty tree never written). Bounded by renew cadence x lease; hosted-remote gc policy is UNMEASURED.
* Serialised chokepoint: one ref per goal means two goals never contend; contention is per-goal only, and a lost race costs
  one rejected push. No global lock, no single writer.
* Harness cost: `commit-tree` ~10 ms each dominates (1000 attempts ~10 to 16 s on a 12-core dev host; budget 2 to 4x on a 3
  to 4 core CI runner, so up to ~45 s). The 90-minute CI job cap is not at risk. Worker count is derived from the machine
  (`min(10, cpu_count*2)`), not a laptop constant.
* Unbounded growth: nothing in this slice creates refs outside tests (tmp_path only, removed by pytest). Pruning of orphaned
  claim refs is slice 6 (doctor health, S-12); named here as a deferred ceiling, not solved.

## Resiliency (recovery without a human)
* Lost ack (push succeeded, response lost): caller re-reads its own ref; sha is unique (R-3), so "tip == my sha" proves the
  win and "tip != my sha" proves it lost. The primitive's post-win `ls-remote` confirmation (R-8) already narrows this window;
  residual case returns `OUTAGE` (never WON), and the caller's re-read resolves it.
* Outage (remote unreachable, timeout, exit 128): `OUTAGE` is a distinct outcome so slice 3 can fail closed or retry with a
  bound; the primitive itself never retries. A timeout kills the whole process group (R-9), so a hung `ssh` cannot linger.
* Crash mid-write: `commit-tree` writes only an object; the ref moves in the single push, which is atomic server-side. A crash
  between build and push leaves an unreachable local object, nothing on the remote.
* Restore-from-backup of the remote: a claim ref restored from an old backup is a stale-but-valid claim; the observed-age read
  expires it by age (no change observed for `lease_seconds`), and reclaim is lease-guarded from the observed sha. No re-ship-all
  lever exists or is needed.
* Partial write / reboot: stateless library; `seen` is caller-owned (slice 3/5 persist it).
* Double release / duplicate delete: loses cleanly (expected sha is mandatory on delete).

## Safety
* Nothing spawns a background process, sends data, or consumes quota: the module is only a library; nothing in this slice
  imports or calls it outside tests; it reads no config and so cannot be turned on by accident.
* No secrets: claim messages hold holder, host, run, timestamps, lease seconds, nonce only. `Outcome.detail` never carries a
  remote URL (it can contain credentials) or raw stderr beyond a short classified token.
* Option-injection: remote and ref are validated (R-4, R-5); every git argv uses a `--` boundary where the verb allows and the
  validated values cannot start with `-`.
* Windows: refuses loudly (R-9) rather than weakening the timeout guarantee.
* No `SIGSTOP`/`kill -STOP` text anywhere (the structural guard `tests/test_no_unsupervised_process_pause.py` stays green).

## Liveness
A library has no long-running component; there is nothing to die silently. The one liveness-relevant fact is that the
observed-age read (R-11) is what lets a later slice distinguish a dead holder (sha unchanged for `lease_seconds`) from a
live one that is renewing, using AGE and not error state. Wiring that into doctor rows is slice 6.

## Host-agnostic (no hook dependence)
Pure Python plus git, both available on every host (Claude Code, Cursor, Codex). No Claude Code hook, no `.mdc` text, no
host feature is used or required. The triggers for create/renew/reclaim/delete live in slice 3's Python (`loop.py`), not in a
hook, and a missed trigger costs latency, never data.

## Risks
* Parallel smoke test sensitivity is host- and timing-dependent (research M-1): it can pass with the guard removed on a fast
  runner. Mitigated by making the deterministic tests the system of record and labelling the smoke test.
* A lowercase-only charset limits goal ids (slugs with capitals are refused, not folded). Owner-visible; stated here and tested.
* Only git 2.39.5 was exercised; classification uses porcelain flags plus tip measurement precisely because wording varies by
  git version and locale. A newer git changing porcelain shape would surface as `OUTAGE` (safe), not `WON`.
* The write-surface ratchet only reds once the new file is tracked, so the knock-on JSON edit can be forgotten until commit;
  step 13 and C-5 force the check explicitly.
* 1000 attempts on a 3 to 4 core CI runner may take ~45 s; worker count is machine-derived.
* Timeout default and `timeout` values are caller arguments with a conservative module default; the real value is a slice 3
  decision and is UNMEASURED against a hosted remote.

## Unmeasured (named, not claimed)
Network latency; GitHub-side acceptance and ref limits of `refs/sigma/claims/*`; hosted-remote gc of renewal garbage; behaviour
on git versions other than 2.39.5; the "30-minute lease" attribution (no default introduced here).
