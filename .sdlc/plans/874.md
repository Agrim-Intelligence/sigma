# #874 plan: regression record builder `record.py build` and the `sigma.regression-run/v1` schema

## Goal / done_when
Slice 1 of epic #870 (story #809). Add a new file `evals/regression/record.py` whose verb
`record.py build <run_dir>` writes one JSON record, schema `sigma.regression-run/v1`, from the evidence a
run leaves behind. Covers AC-2 and AC-5. done_when:
1. action-log rows in the record are filtered by `actionlog.INTERNAL_KINDS` (imported by path, never copied);
   a planted `agent_dispatch`, `note` and `file` row never appears anywhere in the record.
2. every stream (plan, research, plan_review_verdict, verify, journal, action_log, review_evidence,
   commit_order, tokens) has `source` and `present`; a run dir with absent streams builds, exit 0, no raise.
3. every phase carries `evidence: "call-existence"`; top-level `caveats` says so.
4. commit order and per-phase tokens are assembled from the run dir and its bare remote.
5. each guard seen red by the documented gesture `record.py build <run_dir>` via subprocess; write-surface
   ratchet green; full suite green by the CONTRIBUTING gesture.

## Decisions (resolving the research doubts)
- D1 run-dir layout (contract for slices 2-5): `<run_dir>/repo/` (a git clone whose `.sdlc/` is the sdlc dir),
  `<run_dir>/remote.git/` (bare), `<run_dir>/gh_state.json` (fake store). Each optional, each reported
  present/absent. Flags override: `--repo`, `--remote`, `--gh-state`, `--out` (default `<run_dir>/record.json`).
- D2 goal: `--goal <stem>`; the `goal` value journal and action-log rows store is `str(goal)` exactly as the
  caller passed it (`ledger.append` writes `"goal": str(goal)`; `phase_report.py` passes the goal arg through),
  i.e. the bare issue number string in github mode (`"874"`) and the slugged stem in local mode, and the
  action-log file is `<that value>.jsonl`. So journal rows are matched on `str(row.get("goal")) == stem`.
  Stem resolution: else the single stem found under `repo/.sdlc/state/log/*.jsonl`; zero or several
  -> stderr refusal, exit 2 (never guess).
- D3 stringly numerics: `_int(v)` returns int for digit strings/ints, else `None`, and the phase entry gets a
  note `non-numeric tokens_in`. Never raises. One test writes events through the real `ledger.append`.
- D4 verify projection (additive-only, small): `exit`, `verify_state`, `at`, `head`, `test_first_passed`
  (from `test_first.passed`). Never `root`, `tail`, `content`.
- D5 the write-surface ratchet: run `check`, then add the entries it names (see step 9).
- D6 commit order: commits of `main` on the remote (oldest first) plus each remote head matching
  `sdlc/*<stem>*` (name sorted); no such head -> that sub-entry `present: false`, reason `no goal branch`.
- D7 `action_log.enabled` off or log file missing: `action_log` and `plan_review_verdict` are
  `present: false`; `phases` still built from the journal (end_present from journal only). Not "NOT EVALUABLE";
  that belongs to slice 2.
- D8 plan/research files: REUSE the real resolver `review_context.phase_doc_file(sdlc_dir, stem, subdir)`
  (loaded by path via `_load_scripts("review_context")`), which tries exact `<stem>.md`/`<slug>.md` then, for a
  purely numeric stem, the `<stem>-*.md` glob by newest mtime. Its glob also matches sibling artifacts
  (`874-controls.md`, `874-retro.md`, `874-code-review.md`, `874-measurements.md`) when no `874.md` exists, and
  an exact `874.md` always wins over the glob. record.py therefore does NOT take the resolver's answer blindly:
  it rejects a result whose name ends in a sibling suffix (`-controls`, `-retro`, `-code-review`,
  `-measurements`, `-plan-review`) and, if the resolver returned one, treats the stream as absent with reason
  `only sibling artifacts found` rather than hashing the wrong file. Tests: numeric stem with slug resolves;
  `874-controls.md` planted as the NEWEST file beside `874.md` still resolves to `874.md`; `874-controls.md`
  alone yields `present: false`.
- D9 the gate file `state/gates/<stem>.json` is a cross-check only: field `gate_file_present` bool inside
  `plan_review_verdict`; its absence never flips `present`.

## Record schema (field names are a contract for slices 2-5)
Top level, keys in this fixed order, written with `json.dumps(..., sort_keys=True, indent=2)` + newline:
- `schema`: "sigma.regression-run/v1"
- `goal`: stem string
- `run`: basename of `run_dir` only (no absolute path)
- `caveats`: list of strings; always contains, verbatim,
  "phase end rows prove phase_report.py end was called, not that the phase did its work (evidence: call-existence)"
  and "journal and action log are off by default; a stream absent here may mean the feature was off"
- `phases`: list sorted by canonical phase order then `phase`, each
  `{phase, evidence: "call-existence", start_present, end_present, attempts, tokens_in, tokens_out, cost_cents, notes}`
  (`attempts` = count of end events; tokens summed over deduplicated END events, cost over deduplicated `spend` events; `null` when none measured).
- `streams`: object; every value has `{source, present, reason?}` plus:
  - `plan`, `research`: `{source: "plans/<name>", present, bytes, sha256}` (repo-relative; absent -> `source` is the pattern tried)
  - `plan_review_verdict`: `{source: "state/log (kind=verdict, phase=plan_review)", present, verdict, route, plan_hash, verified, gate_file_present}` (last row by `ts`)
  - `verify`: `{source: "state/verify/<stem>.json", present, exit, verify_state, at, head, test_first_passed}`
  - `journal`: `{source: "events/*.jsonl", present, files, lines, skipped_malformed, kinds: {kind: count}}`
  - `action_log`: `{source: "state/log/<stem>.jsonl", present, rows: [...INTERNAL only, original field order via sort_keys...], dropped_non_internal: <int>}`
  - `review_evidence`: `{source, present, review_posted: [{pr, head_sha, verdict, evidence_id}], marker_in_store: bool|null}`
  - `commit_order`: `{source: "remote.git", present, main: [{sha, subject}], goal_branches: {name: [{sha, subject}]}}`
  - `tokens`: `{source: "journal phase end (tokens) + spend (cost)", present, by_phase: {phase: {tokens_in, tokens_out, cost_cents}}}`
No build timestamp anywhere; two builds of one dir are byte-identical.

## Functions in record.py (each small, no raise past `main`)
- `_load_scripts(name)`: importlib-by-path from `skills/sigma-loop/scripts/<name>.py`, located via
  `Path(__file__).resolve().parents[2]`. `INTERNAL = actionlog.INTERNAL_KINDS` (the same object, imported).
- `_read_jsonl(path)` -> `(rows, skipped)`: skip malformed/non-dict lines, count them (mirrors `actionlog.read_goal`).
- `_int(v)`; `_sha256(path)`.
- `find_goal(sdlc, goal)`; `phase_doc(sdlc, sub, stem)` (D8).
- `read_action_log(sdlc, stem)`: rows via `_read_jsonl`, keep `kind in INTERNAL`, count the rest, sort by `ts` then original index (stable).
- `read_journal(sdlc)`: union of sorted `events/*.jsonl` (never the prune stamp); keep rows whose `goal == stem` or no goal for counting? -> keep only `str(row.get("goal")) == stem`. Projection of
  `worktree_start` rows: the action log's `worktree` field is an absolute path; `read_action_log` replaces it
  with its basename (`worktree`: `os.path.basename`) and sets no other path-bearing field; any remaining string
  value that is an absolute path is replaced by its basename in a generic `_scrub(row)` pass over all kept rows.
- `read_verify`, `read_plan_review(rows, sdlc, stem)`, `read_review_evidence(journal_rows, gh_state, stem)`.
- `read_commit_order(remote, stem)`: `subprocess.run(["git","--git-dir",remote,"log","--reverse","--format=%H%x09%s", ref], ...)` with a hermetic env built by `_git_env()`: start from `os.environ`, DELETE every key starting `GIT_` (this removes inherited `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_COMMON_DIR`, `GIT_NAMESPACE`, `GIT_CONFIG_*`), then set `GIT_CONFIG_GLOBAL=os.devnull`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_TERMINAL_PROMPT=0`, `timeout=30`, `check=False`; heads from `for-each-ref --format=%(refname:short) refs/heads/`. Failure/missing -> `present: false` with reason.
- `build_phases(journal_rows)` and `build_tokens(...)`: group `phase` start/end and `spend` events by `phase`, `attempt_id`.
  Single-source rule, deduplicated by `attempt_id`: `tokens_in`/`tokens_out` come from phase END events ONLY;
  `cost_cents` comes from `spend` events ONLY. A `spend` event's tokens and an `end` event's cost are ignored,
  so an attempt that has both an end and a spend counts its tokens once and its cost once. Two end events with
  the same `attempt_id` count once (last by `ts`); events lacking `attempt_id` are keyed by their file position
  and noted `no attempt_id`.
- `build_record(run_dir, goal=None, repo=None, remote=None, gh_state=None)` -> dict.
- `write_atomic(path, record)`: temp file in the same dir then `os.replace`.
- `main(argv)`: `build` subcommand only; prints the written path on stdout; refusals on stderr, exit 2; exit 0 on success including absent streams. Module docstring states: read-only against the run dir, only writes the `--out` path, no network, no `gh`, cost linear in journal size (30-day cap) and per-goal log size, one output file overwritten (no growth).

## Scale (10x / 100x)
Cost is one pass over each file: O(journal lines + log rows + commits). 10x journal (a busy month) reads in
tens of ms of JSON parsing; 100x is still linear and memory is rows held once. Measured? No: not benchmarked in
this slice; state "unmeasured" in the docstring. Ceilings: whole journal held in memory (bounded by the 30-day
prune); git log unbounded on a huge remote, mitigated by reading `main` once (not all refs).
