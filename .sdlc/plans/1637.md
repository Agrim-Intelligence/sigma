## Design

**New structure.**
- `quality_delta.run(goal, cwd, *, committed=False, head_only=None, deadline=None, probe, git, runner,
  pid_alive, clock)` -> `Result` holds today's `measure()` body; `measure()` becomes `render(run(...))`, CLI
  text byte-identical, CLI default (dirty goal => unmeasured) unchanged.
- `Result(code, refusal, base_sha, head_sha, unmeasured, no_metrics, budget_seconds, deadline, rows)`; each
  row `MetricRow(name, direction, required, tolerance, base, head, delta, verdict, reason)`, Decimal or None
  values, verdict always RAW better/same/worse/unmeasured.
- `committed=True` (gate only) skips only the dirty-worktree rule: at merge time only the committed, pushed head
  merges, and the scratch worktrees are already built from committed HEAD.
- `head_only=("m1",...)`: ONE scratch at HEAD, only the named metrics, once each, `base=None`.
- Budget (FIX-FIRST 1a, 5): `gate_budget_seconds(cfg)` = `quality.gate_timeout_seconds` if set (<= 3600),
  else `min(1800, sum(timeout x (3 if required else 2)) + 3 x 120)`. 120 s is `_CHECKOUT_ALLOWANCE`, the budget
  share for each of up to three `worktree add` calls: a judgement, unmeasured, and documented as such; each
  checkout keeps its own 600 s ceiling (`_WORKTREE_ADD_TIMEOUT`), clipped to the time left. With `committed`
  and no `deadline`, `run` computes B, reserves `R = min(B // 2, 120 + sum(required timeouts))` for the
  second reading (one checkout + one run per required metric), works to `start + B - R`, and returns
  `Result.deadline = start + B`; so AC-6's second reading never starves because the first checkouts were
  slow. Past its deadline a metric reads `unmeasured (the gate's time budget of N s ran out)`.
- Config: `_ENTRY_KEYS` + `tolerance` (number >= 0, default 0; else refusal `metrics[i]: tolerance ...`);
  `_BLOCK_KEYS` + `gate_timeout_seconds` (0 < n <= 3600). Both read from the MERGE-BASE config.
- `work._quality_ratchet_refusal(sdlc_dir, config, goal, rec, vetted_head, actionlog)` -> "" or PARK detail;
  `work._quality_delta()` is the one loader (`_load("quality_delta")`), the tests' spy.
- Waiver store `<sdlc>/state/gates/quality-waivers/<stem>/<metric>-<head>.json` (same `state/gates/` tree as
  `plan_review_record_path`), create-only via the existing `_create_exclusive` (no new fs-write row);
  `{goal, metric, head, reason, recorded_at}`. `_quality_waiver_valid(sdlc_dir, goal, metric, head)` reads the
  exact path and checks each of the three fields separately (shape of `reviewer._waiver_valid`).
- Verb (FIX-FIRST 2: an OWNER's lever; its usage line and docs say "the loop never runs this") `work.py quality-waive <sdlc> <goal> --metric <name> --reason "<why>"`, dispatched in `main()` beside
  `record-plan-review`. Head = `git rev-parse HEAD` in the recorded worktree, never typed; metric must match
  `quality_delta._NAME`; reason required, <= 500 chars, control chars stripped (as `reviewer.accept_inline`);
  a repeat refuses (exit 2); one action-log `gate` row (gate=`merge`, verdict=`warn`, why `quality ratchet
  waiver recorded: ...`). `finish` removes `quality-waivers/<stem>` inline (existing finish fs-rmtree row).

**Place in `merge()`.** After `vetted_head` is set (work.py ~7031), before the `pending_arm` branches (~7043):
verify, `phase_record_refusal`, `gate()` + BEHIND rebase, review gate, the `off`/`protected` returns have all
run, so it measures only before a real merge/arm, outside `gate()`'s REST wait, on a head no rebase will move.
Not in `reconcile-merges`, `merge_design`, `done_refusal`; no hook. FIX-FIRST 4: `auto_merge: off` (the
shipped default) and unguarded `protected` return before it (~7012-7027): with the gate enabled, both lines
gain the middle clause ` — quality ratchet not run (no merge here)` before their unchanged endings
(`leaving PR #N for a human` / `merging it is yours to make ...`), and the row's `condition` says so.

**Gate logic** (the order is the contract):
1. Off unless `hard_plan_gate_on(_gate_block(config, "quality_ratchet"))` is true. Off means return "" before
   `_quality_delta()` is ever called.
2. `r = qd.run(goal, rec["worktree"], committed=True)`, inside `try`. A raised exception or `code == 2`
   returns PARK `quality ratchet could not measure: <why>`. It never passes silently.
3. `r.no_metrics`: log `pass`, why `quality ratchet: no metrics configured`, and return "".
4. `r.unmeasured` (whole run): PARK when any row is required, or when the metrics are unknown because the run
   stopped before the config was read (fail closed). Otherwise log and return "".
5. `r.head_sha != vetted_head`: every required metric counts as unmeasured, with the reason `measured <sha>
   but the PR head is <sha>`.
6. Per row, `bad = head - base` for `lower` and `base - head` for `higher`; worse-beyond means `bad >
   Decimal(str(tolerance))`, strictly. Required and unmeasured is a park candidate. Required and worse-beyond
   is a re-measure candidate. A non-required row is logged and never parks.
7. Re-measure candidates: `qd.run(..., committed=True, head_only=names, deadline=r.deadline)`. The park stands
   only if the second reading is also worse-beyond against the FIRST base, or is unmeasured. If the second
   reading is not worse, log both readings and do not park (AC-6). A second head sha that differs from the
   first counts as unmeasured.
8. A park candidate with a valid waiver for (goal, metric, measured head) is logged as `waived` and dropped.
   Any mismatch is ignored, and the park stands (AC-5).
9. Every metric gets one action-log `gate` row with only `gate`, `verdict`, `why` (actionlog.py:107):
   gate=`merge`; verdict `pass`, `block` or `warn` (ledger.py:488; `waived` is `warn` with the word in why);
   why ONE line: `quality ratchet: metric=<m> base=<b> head=<h1> head2=<h2|-> tolerance=<t> raw=<v> ->
   pass|park|waived`. Re-using `merge` leaves the three gate vocabularies untouched (BR-12, D-2).
   Worse PARK: `quality ratchet: required metric <m> worse beyond tolerance <t> on two measurements
   (base=<b> head=<h1>, then head=<h2>; head <sha>); fix the regression. An owner may record a waiver (the
   loop never runs this): work.py quality-waive <sdlc> <goal> --metric <m> --reason "<why>". Record with
   --qkind failing_check`. Unmeasured/could-not-measure PARK (required unmeasured, memory floor, live
   scratch owner, timeout, refusal): `quality ratchet could not measure: <m>: <why>; ... --qkind no_evidence`.

**Park kind.** `merge()` returns `PARK: ...`, and the caller runs `loop.py record parked "<text>" --qkind
<kind>`. `gate_hold.GATE_KINDS` is NOT widened. `loop._REASON_CLASS_RULES` gets two needles as its FIRST
rules, in this order: `("quality ratchet could not measure", "no_evidence")`, then `("quality ratchet",
"failing_check")`, so a quoted "rate limit" or "irreversible" cannot reclassify either. With that, `_needle_kind` (the run_loop path) and `_suggest_kind` agree
with the `--qkind` the text names. Callers affected: `merge()`, `finish()`, `main()`, `loop._REASON_CLASS_RULES`;
`measure()`'s CLI and tests see unchanged output.

**Latency and the timeout prose (FIX-FIRST 1).** Gate off: unchanged, 22.5 min. On: + <= 1800 s default
(3600 s explicit max) + fixed git reads <= 2 runs x 8 x 30 s = 480 s + 10 s per memory probe (one per run plus
one per command): 60.5 min worst case by default, 90.5 min at the max, unmeasured on a real project (stated
so in docs/quality-delta.md and docs/configuration.md). A host cut mid-measurement records nothing (scratch
reclaimed by the next run) but a re-run measures from zero, so both orchestrator timeout lines change:
- `skills/sigma-loop/SKILL.md:226-228`: delete `, not after it times out` and `the full worst case,`; after
  `**~1,350,000ms (22.5 minutes)**` add `, plus the quality-ratchet budget and git reads when that gate is
  on (docs/quality-delta.md)`.
- `references/landing.md:188-199`: replace `applies here unchanged: read the literal response, never
  shell-background this and wait on nothing)` with `applies unchanged)`; replace the clause from `on top of the separate,` through `each rebased
  head settle` with `plus the smaller BEHIND poll per rebased head`; change `The safe minimum is that full worst case, **~1,350,000ms (22.5 minutes)**` to `The
  safe minimum is **~1,350,000ms (22.5 minutes)**, plus the quality-ratchet budget and git reads when that
  gate is on (docs/quality-delta.md)`.
  Both files are orchestrator-only (goal-slot does not load them). `python3 evals/phase_context_budget.py`
