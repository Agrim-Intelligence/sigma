## Decisions (for plan-review)

- **D1 — the first-pick baseline lives in the session HEARTBEAT, and the heartbeat writer merges.**
  `write_session_heartbeat` publishes through the existing `state.session_write` (atomic, fsync,
  keeps every key the caller does not pass), so the phase-boundary refresh (`loop.py:3151-3177`) and
  `session_start` (`loop.py:3289`) keep the `context` block without any change of their own (F1,
  M1, M2). The meter's write runs under the same stripe lock those two already hold
  (`_session_locked`, `require_lock=False`), so a phase-boundary read-modify-write cannot drop it.
  The baseline is keyed by the **transcript id**, not by generation: CLI `start` mints a new
  generation on every call (`loop.py:7418-7419`), so a generation key would reset on the very
  restart the acceptance says must keep it, while the transcript id is exactly "this host session".
  Why not the session marker: its mtime is the pid-reuse liveness backstop that only start, claim
  and release may move (`state.py` `session_pid_live` docstring) and a per-`next` write would move
  it; a bare `next` with no `start` has no marker and must not create one (that would register a
  session); and `log.py`/`status.py` already read only `state/heartbeat`. Side effect, intended:
  `next` stops silently dropping `generation` from the heartbeat (research TD-1). No reader reads
  `generation` from the heartbeat (research BR-7, BR-24..BR-26).
- **D2 — transcript roots: the env root first, then the home root, de-duplicated.** Claude:
  `$CLAUDE_CONFIG_DIR/projects`, then `<home>/.claude/projects`; Codex: `$CODEX_HOME/sessions`, then
  `<home>/.codex/sessions`; `resolve()`d and de-duplicated so `_codex_rollout`'s exactly-one-match
  rule still holds when both name the same directory. A strict "env wins" rule (the `coexist.py`
  precedent) would blind ~35 existing tests that set `HOME` and inherit conftest's empty
  `CLAUDE_CONFIG_DIR` (research BR-31, BR-32). Ids are UUIDs matched exactly, so searching two roots
  cannot cross sessions.
- **D3 — the meter is one function, `loop_session_model.context_reading()`,** beside `observed()`,
  built only from existing pieces: `_tail_lines` (256 KiB), `phase_report._session_id` /
  `_codex_session_id`, `find_claude_main_transcript`, `_codex_rollout`, `_codex_usage_pair`, and the
  context formula from `orchestrator_context_report.peak_context`. Two per-line parsers are
  extracted (not copied) out of `iter_assistant_turns` and `find_codex_token_totals` so the meter
  and the existing readers share one line rule each.
- **D4 — the reading.** Claude: the LAST assistant line in the tail, `input_tokens +
  cache_read_input_tokens + cache_creation_input_tokens` (the `peak_context` formula; the last line
  of a progressive message is its complete usage, `dedup_calls`' own rule). Codex: the LAST valid
  request's `input_tokens` only — it already includes cached tokens (F4), so nothing is added. The
  Claude id wins when both are set (same precedence as `loop.py:3102`). Never raises; any failure is
  `{"source": "unavailable"}`. Source `estimate` is never produced (design: never invented).
- **D5 — heartbeat shape (additive):** `"context": {"source": "host"|"unavailable", "tokens": int
  (host only), "session": <transcript id or null>, "first_pick": int|null, "at": <epoch>}`. Counts
  and ids only, never text.
- **D6 — status.py delegates to log.py's tail** (it already cross-loads sibling scripts,
  `status.py:22-90`), deleting its duplicate reader (research TD-2). Tail text:
  `loop heartbeat: 00:01:01 ago, context 84,312 tokens (host)` / `..., context unavailable`; a
  legacy heartbeat with no block prints exactly what it prints today.
- **D7 — re-write definition (FR-8):** a call is a full-context re-write when
  `cache_creation_input_tokens >= 50%` of its context. Buckets by the gap since the previous call:
  `under 5m`, `5m to 1h`, `1h or more` (the two cache lifetimes; a gap exactly on a boundary goes up).
  The first call has no gap and is not bucketed. Per bucket: turns, re-writes, re-write tokens.
  Orchestrator scope only (honours `--since/--until`), JSON key `rewrites_by_gap`.

Deferred (named, not silent): `loop_session_model.observed()` still reads the whole transcript
(research TD-3) — goes to retro `Deferred roots`.

## Risks for plan-review
- R1: D2's two-root search — a reviewer may prefer strict "env wins"; that is ~35 test edits and
  changes behaviour for anyone with a stale `CLAUDE_CONFIG_DIR`. Recommendation: keep D2.
- R2: clearing the Codex ids in conftest goes one step past the acceptance's wording; it is what
  keeps the meter from reading a real `~/.codex` rollout when the suite runs under Codex.
- R3: the meter adds one lock acquisition and a 256 KiB read per `next`/`next-batch` call (not per
  slot). Measured cost goes in the PR (step 8); the lock is the existing per-session stripe, held
  only for one small JSON read+write.
- R4: the Claude transcript format is internal (PC-8): a format change reads `unavailable`, and
  slice 2's goal-count hand-off still bounds the session.
