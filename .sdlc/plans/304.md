# #304 Lifecycle-label self-heal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop normal GitHub loop sessions from issuing rejected label-create writes for labels that
already exist, while preserving lifecycle-label recovery when a label is missing.

**Architecture:** Reuse `GitHubSource._existing_label_names`, the existing bounded REST inventory
helper, at the hot `_ensure_labels` boundary. A complete inventory makes the hot path skip known
labels; an unreadable inventory falls back to the existing create-and-ignore behavior. The
onboarding control’s fake call log provides the end-to-end regression evidence.

**Tech Stack:** Python 3 standard library, pytest, the repository’s stateful fake GitHub client.

**Spec:** GitHub issue #304 and `.sdlc/research/304.md`.

## Global Constraints

- Use REST label inventory only through `_existing_label_names`; do not add GraphQL reads.
- Preserve the existing fallback when label inventory is unreadable or exceeds the bounded page
  limit.
- Preserve the per-source `_labels_ready` cache and existing lifecycle-label colours.
- Do not use `--force`, recolour existing labels, add dependencies, change ledger configuration, or
  create any live GitHub labels as part of acceptance.
- The documented control remains `$HOME/.sigma-venv312/bin/python tools/onboarding_control.py --mode github`.

## Review Focus

1. A fully bootstrapped repository should make no redundant `label create` calls after init.
2. A deleted lifecycle label must still be recreated by the normal self-heal path.
3. An unreadable or incomplete label inventory must retain the safe create-and-classify fallback.
4. Case-only variants of an existing label must not be re-created.
5. The label read must stay bounded by `_LABEL_LIST_MAX_PAGES`.

- [ ] **Step 1: Implement the minimal complete-inventory branch**

```python
existing = self._existing_label_names()
for attr, color in self._LABEL_COLORS:
    name = getattr(self, attr)
    if existing is not None and name.casefold() in existing:
        continue
    try:
        self._run(["label", "create", name, *self._repo_args(), "--color", color])
        if existing is not None:
            existing.add(name.casefold())
    except Exception:
        pass
self._labels_ready = True
```

Keep the existing read-failure behavior by attempting every create when `existing is None`.
