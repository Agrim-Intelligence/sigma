## Decisions

### (a) Contract: local state. No `contract/VERSION` bump and no golden
- The contract covers records that **downstream readers** consume (`contract/README.md` "Overview"). It
  lists nine kinds. It already leaves out the one-writer/one-reader local files under `.sdlc/state/`:
  `state/work/`, `state/review-results/`, `state/review-manifests/` and `state/merge-deliveries/`.
  `state/gates/<stem>.json` is the same shape. Its one writer (`work.record_plan_review`) and its one
  reader (`work._plan_review_refusal`) both live in `work.py`. `.sdlc/state/` is in `RUNTIME_IGNORES`
  (`skills/sigma-setup/scripts/setup.py:51`), so the file is never published or synced.
- The journal mirror reuses the existing `gate` event: `gate="plan_review"` (already in
  `ledger.GATE_KINDS`, `ledger.py:475`) with `verdict` in `pass|warn|block` (in `ledger.VERDICTS`,
  `:478`), plus an optional `why`. All of these are existing `gate` fields (`ledger.py:144`). There is
  **no new kind and no new field**. `plan_hash` stays OUT of the event. Putting it there would be a
  new field, which means a MINOR bump plus a vocabulary/golden regen.
- The new config key: `contract/golden/config.json` has no `gates`, and the template changed in #228
  and #232 without a contract bump (`git log -- contract/VERSION` vs `git log -- config.json.tmpl`).

### (b) Plan hash: one helper, `review_context.plan_sha256(path)`. `publish_generation`'s digest is not used
- Not `publish_generation`'s digest (Research measured it; re-read): it hashes the whole brief, which
  carries only a pointer to the plan (`review_context.py:858`, `:554`); its id mixes in an
  `os.urandom` nonce (`:865-870`); it never runs for plan-review (`:913-914`); and it moves with the
  goal body and north-star.
- The helper, in `skills/sigma-loop/scripts/review_context.py` next to `phase_doc_file`:
  `plan_sha256(path) -> hashlib.sha256(pathlib.Path(path).read_bytes()).hexdigest()`. It hashes raw
  bytes and never decodes or strips. It sits beside `phase_doc_file`, the resolver it pairs with.
  `work.py` reaches both through `_load("review_context")`, as it already does at `work.py:2582`. The
  three sites that must agree on it are the brief (T1), `record_plan_review` (T2) and
  `_plan_review_refusal` (T3). Do **not** name it `content_hash`, because
  `tests/test_mirror.py::test_nothing_under_skills_reads_content_hash` string-matches that name under `skills/`.
- **Two copies of a plan can exist, and one function finds both:**
  `work.plan_copies(sdlc_dir, goal, rec, run) -> (main, branch)`, placed next to
  `_phase_doc_missing_from_branch`. Each value is a `pathlib.Path` or `None`.
  - `main` is `phase_doc_file(sdlc_dir, goal, "plans")`, the main checkout's copy (no git call).
  - `branch` is the goal's worktree copy, resolved by the SAME resolver and the same names:
    `phase_doc_file(<rec["worktree"]>/<sdlc name>, goal, "plans")`, where `<sdlc name>` is
    `Path(sdlc_dir).resolve().name` (the same `rel` `_branch_doc` uses, `review_context.py:369`).
    It counts only when `git ls-files -- <rel>` in the worktree is non-empty (tracked, so it IS on the
    branch) AND `git status --porcelain -- <rel>` is empty (committed and unmodified, so its disk
    bytes are the branch's bytes). `None` when `rec` is `None`, when the worktree has no copy
    (`phase_doc_file` returns `None` on a missing dir, so no git call is made), or when either check
    fails. `run` exceptions propagate.
  - That inference does NOT hold for a file flagged `git update-index --skip-worktree` or
    `--assume-unchanged`: `git status` hides its local edits, so its disk bytes can differ from the
    branch's. Then all three sites hash disk bytes the branch does not hold (fails OPEN). Not guarded:
    the flag is a deliberate local act; stated in §7 and in `plan_copies`' docstring (R-e).
  - Disk bytes are hashed, never `git show` stdout through `_run`: `_run` returns `stdout.strip()`
    (`work.py:1024`), which drops the trailing newline, so that hash could never match a file-bytes hash.
- **Which copy is authoritative:**
  - **Published copy** (what the gate hashes): `branch or main`. The branch's copy is what the PR
    publishes and what its reviewer reads. The main copy is used only when the branch carries none:
    the repo ignores plans, or its ignore rules could not be read (the sibling guard failed open).
  - **Reviewed copy** (what the brief names and hashes, and what `record` checks): `main or branch`.
    This is the same filesystem-first order `brief()` already uses and a test pins
    (`test_a_worktree_plan_still_wins_over_a_different_one_on_the_branch`): Plan writes to the main
    checkout, and corrections land there first (#2237). The branch copy is the #2647 fallback.
  - **Only one copy exists:** both rules pick it. A branch-only plan (B1) is hashed at all three sites.
  - **Both exist:** `record-plan-review` refuses unless the sha matches BOTH copies (Decision 2). So a
    verdict is recorded only for bytes that every existing copy holds, and at `pr` the published copy
    must still hold them. When the copies differ, a re-record refuses and names the reconcile step
    (copy one onto the other). After that, a fresh review satisfies both the record and the gate. The
    gate itself only asks whether the published copy holds the recorded bytes.
  - **Neither exists:** the gate says nothing, unless a record exists (Decision (c)).

### (c) Coverage: the plan `.md` only, and the refusal text says so

  `gates.hard_plan_gate` lets a plan-less goal through, and the registry `condition` and the template

  reviewed plan, so a plan deleted from both copies after its review is not a plan-less goal. Cost:
  one `exists()` on the record path, only on the no-plan path.
- Every refusal ends with the tail
  `… Hashed: <file>. Covers the goal's plan .md only — not <sdlc>/plans/<stem>.slices.json, and not a design PR's .sdlc/design/<n>.md.`

### 1. CLI, verdict vocabulary, `reviewer_route`
- **Gesture:**
  `work.py record-plan-review <sdlc_dir> <goal> --verdict SOUND|SOUND-WITH-REFINEMENTS|FIX-FIRST --plan-sha256 <hex> [--reason "<text>"]`.
- **Verdict words:** the skill's own verdicts, case-insensitive. They map to the journal vocabulary:
  `PLAN_REVIEW_VERDICTS = {"SOUND": "pass", "SOUND-WITH-REFINEMENTS": "warn", "FIX-FIRST": "block"}`.
  The record stores the mapped `pass|warn|block`, so the record and the journal mirror cannot disagree
  on vocabulary. **Approving = `pass` and `warn`.** The CLI takes only the skill's three words (no
  aliases), so there is one vocabulary at the agent-facing edge.
- **`reviewer_route`:** `record_plan_review` calls `reviewer.resolve(sdlc_dir)` itself and stores
  `{mechanism, host, verified}`. No `--resolution <file>`: that re-check (`work.py:611-631`) exists to
  require the `subagent` route, while plan-review accepts every route (`inline` when it says so), so a
  file could only be checked against the same `resolve()` call — an input to forge, proving nothing.
- **Honesty caveat** (docstring, beside `record_subagent_review`'s): the route is what the resolver
  selects here at record time, not proof of which route produced the verdict; the record is
  agent-written (§7).
- **Signature:** `record_plan_review(sdlc_dir, config, goal, verdict, plan_sha256, reason="", run=None)`.
  `run` defaults to `_run`, the house seam (`pr(..., run=None)`). It is used only for `plan_copies`'
  two git calls.
- **Dispatch:** OUTSIDE `_COMMANDS`, next to the review verbs in `main()` (after the
  `reconcile-review-post` block, `work.py:5622-5633`). Plan-review is a portable executor that also runs
  with `work.enabled` off.
  - Errors (`state.ConfigMissing`, `OSError`, `ValueError`, and `RuntimeError`, which is a `git` failure
    from `_run` inside `plan_copies`) print `work: <msg>` to stderr and exit 2.
  - A missing `--verdict` or `--plan-sha256` FLAG prints the usage and exits 2. It is tested as
    `"--plan-sha256" not in argv`, never as `not _flag(...)`: `_flag` returns `""` for BOTH a missing
    flag and an empty value (`work.py:5543-5544`). A present-but-empty value (a `sed` that found no
    line) goes to `record_plan_review`, whose `ValueError` names the brief's `Plan sha256:` line and
    exits 2.
  - A raw newline in `--reason` is refused with `ledger.reject_newline` and exits 2.
  - Success prints the record as sorted-key JSON plus `"path"`, and exits 0.
  - Add the usage to the `--help` dict and to the final usage block.
- **`--reason`** goes to the journal mirror's `why` only (ledger caps and flattens it). It is **not**
  stored in the record, which keeps the record fixed-shape and ≈350 bytes.

### 2. Binding the verdict to the bytes the reviewer saw: the brief carries the sha, and `record` refuses a mismatch
- **The brief carries the sha.** For `--for plan-review` only, `review_context.brief()` appends a
  section with two standalone lines, `Plan file: <pointer>` and `Plan sha256: <hex>`, for the REVIEWED
  copy (Decision (b)):
  - **main copy:** the pointer is its path, `phase_doc_file(...).as_posix()`. No `work` load and no
    git call.
  - **branch copy only:** `_load("work")`, then `rec = work._record(sdlc_dir, goal)` and
    `work.plan_copies(sdlc_dir, goal, rec, work._run)`. The pointer is
    `git -C <project root> show <rec["branch"]>:<rel>`, the same runnable shape `_branch_doc` hands a
    reviewer (`review_context.py:405`). The copy is committed and unmodified, so those bytes are the
    hashed bytes. The pointer **never names the worktree path**: the documented gesture runs
    `reviewer.py check <brief> --scratch "$(pwd)/.sdlc/work/<goal>"` (`sigma-plan-review/SKILL.md:53-54`),
    and `breaker.no_channel` refuses any brief whose text contains that string
    (`breaker.py:145-147`, a plain substring test).
  - **Omitted** when neither copy resolves, or on any exception (the brief is fail-open).
  - The section's text says what the sha is for and asks nothing of the reviewer:
    `This is the file to review. The dispatcher records your verdict against this sha256; the PR gate (gates.plan_review) accepts it only for exactly these bytes.`
  - For plan-review, `brief()` does not inline the plan (`review_context.py:657-662`), and its
    pointer is `"The active plan under .sdlc/plans/"`. In the branch-only case, this `Plan file:` line
    is the only pointer that resolves.
- **`record-plan-review --plan-sha256` is REQUIRED.** It must be 64 hex characters and match every copy
  that exists. It checks, in order:
  1. The reviewed copy (`main or branch`). If there is no match, the command refuses and writes nothing:
     `the plan changed since its review brief was built (<plan> is no longer sha256 <12>…): run a fresh plan-review of the current plan and record that verdict`.
  2. When BOTH copies exist, the branch copy too. If there is no match:
     `the plan on the branch (<rel> on <branch>) differs from the reviewed copy <main>: copy the reviewed plan over <worktree>/<rel> and leave it uncommitted (step 6 commits it), or copy the branch's version back to <main> and review that; then record`.
     This stops a verdict on one copy from being recorded while the branch publishes another.
     The remedy needs no commit during plan-review (running.md:200, "commit … once, at step 6"):
     `plan_copies` ignores a tracked copy with uncommitted edits, so the re-record checks the main
     copy only; `pr` refuses an uncommitted worktree (`work.py:2760`), so by the gate the copy is
     committed and hashed as the branch copy.
- **No copy resolves:** the command refuses with
  `no plan for <goal> in <sdlc>/plans/ or committed on its branch`. A branch copy with uncommitted edits
  does not count, and the message says to copy it into `<sdlc>/plans/` and review that copy (never
  `work.py commit` during plan-review).
- **An empty or invalid value** refuses with a message that says the value is the 64-hex
  `Plan sha256:` line of the plan-review brief. A brief with no such line found no plan.
- **Work on and no work record for the goal under `sdlc_dir` → NO FILE, exit 0** (R-c, revised in
  round 3). This is the work-off branch's behaviour (Decision 4): the verb still validates the sha,
  still writes the journal mirror, keeps no file, returns `"path": null`, and prints a stderr note.
  It must not refuse: `work.enabled` ships `true` (`config.json.tmpl:78-79`,
  `docs/enforcement.md:15-16`), and `/sigma-goal` runs Plan-Review through `sigma-plan-review`
  (`sigma-goal/SKILL.md:52-53`) without ever calling `work.py`, so a refusal would fail every
  `/sigma-goal` and standalone plan-review, even with the gate off. The only reader, `pr`, needs that
  same work record in that same `.sdlc` (`work.py:2756-2758`). So in a goal worktree with a tracked
  config (`/sigma-setup` does not ignore it, `setup.py:51`) nothing lands in the worktree's
  `state/gates/`, which `pr` never reads, and `pr` still refuses: R-c stays closed, failing closed at
  `pr`. With `gates.plan_review` on, the note says so. In the loop, `work.py start` (3a) precedes
  plan-review, so the loop's record is kept.
- **The documented gesture: the brief file is written at DISPATCH time, and the record only reads
  it** (B-new). `sigma-plan-review/SKILL.md:51-52` already writes `/tmp/brief-<goal>.md` before
  dispatch; T5 adds `> "/tmp/brief-$(basename "$goal" .md).md"` to `running.md`'s dispatch gesture
  (`:139-141`) and, identically, to `sigma-loop/SKILL.md`'s copy of it (`:102-103`), the same file. Each record line is `--plan-sha256 "$(sed -n 's/^Plan sha256: //p'
  <that file>)"` and **never rebuilds the brief**: a record-time rebuild hashes the edited plan, so the
  check could never fail (rev 1's running.md block did exactly that).
- **Residual gap:**
  - A dispatcher can still recompute the sha of an edited plan by hand. The check stops honest drift
    (refinements applied before recording, edits during a review), not a determined maker.
  - Nothing proves that the reviewer opened those exact bytes. It was told which file to review.
  - The `pr` refusal never prints the CURRENT plan's full hash, so the easy path is not to copy-paste
    a hash past the review.
  - Raw bytes are compared. A repo with eol conversion (`core.autocrlf`, `.gitattributes eol`) can
    make the main copy and the checked-out branch copy differ on disk. That fails CLOSED, with the
    divergence refusal.

### 3. SOUND-WITH-REFINEMENTS
The skill text says:
1. Record the verdict as returned, BEFORE editing the plan. The sha check refuses afterwards.
2. Refinements carried into Implement without editing the plan file stay inside the approval (note the
   disposition with `loop.py note` as the skill already says).
3. If the plan FILE is edited, the approval no longer covers it and `pr` refuses. Run a fresh

### 4. Where the record lives, and its lifetime
- **Path:** `<sdlc_dir>/state/gates/<goal-stem>.json` in the main checkout, from
  `plan_review_record_path(sdlc_dir, goal)`. This is a copy of `record_path`'s safety: `stem(goal)`, then
  `state.unsafe_goal_reason` → `ValueError`.
- **Shape:** `{"at": "YYYY-MM-DDTHH:MM:SSZ", "goal": "<goal>", "plan": "<rel path>", "plan_hash": "<64hex>", "reviewer_route": {"host","mechanism","verified"}, "verdict": "pass|warn|block"}`.
- **Atomic REPLACE.** Reuse `review_context._atomic_bytes(path, data)` (`review_context.py:761`, mkstemp
  in the same dir, fsync, `os.replace`, temp unlinked in `finally`), with data =
  `json.dumps(sort_keys=True, separators=(",",":")) + "\n"`. It must be overwritable on re-review, so
  create-once `_create_exclusive` is the wrong primitive. `_write_merge_delivery` is not touched; a test
  monkeypatches it (`test_work.py:4696`). The non-atomic `_save` (TD-5) is not copied.
- **Kept only while `work.enabled` is on AND `sdlc_dir` holds the goal's work record**
  (`kept = enabled(config) and bool(rec)`, the same truthiness as `pr()`'s `if not rec`). Nothing
  reads the file without `work.py pr`, and nothing prunes it without `work.py finish` (both are
  `_COMMANDS` verbs that need `work.enabled` and that work record). Otherwise the verb still
  validates and still writes the journal mirror, but keeps no file. It returns `"path": null` and
  `record_plan_review` itself prints one stderr note (the house pattern, e.g. `work.py:842`):
  - work off: `work: no record is kept: work.enabled is off, so no \`work.py pr\` reads one (the journal mirror, when enabled, still has the verdict).`
  - work on, no work record: `work: no record is kept: no work record for <goal> under <sdlc_dir> (the journal mirror, when enabled, still has the verdict).`
    With `_plan_review_on(config)` it adds:
    ` gates.plan_review is on, so \`work.py pr\` will refuse this goal unless the verdict is recorded from the main checkout that ran \`work.py start\`.`

  This avoids a table nothing prunes.
- **Pruned in `finish()`.** Add `plan_review_record_path(sdlc_dir, goal).unlink(missing_ok=True)` next to
  `record_path(...).unlink` (`work.py:5212`). The record then has the work record's lifetime: a parked
  goal keeps both, and a finished goal loses both.
- **10x/100x:**
  - The directory holds one ≈350-byte file per in-flight goal: about 35 KB at 100 goals.
  - `pr()` reads one path directly, with no scan, so its cost does not grow with the number of goals.
  - Leak bound: with work on a record needs a work record (Decision 2), so it leaks exactly where the
    work record does (started, never finished).

### 5. `pr()` placement and refusal wording
- **Placement:** `_plan_review_refusal(sdlc_dir, config, rec, goal, run)`, called in `pr()` right after
  `_hard_plan_gate_refusal` and before `_research_missing_from_branch` (`work.py:2772-2777`), so it runs
  before the push. `_plan_missing_from_branch` has run by then, so a main-checkout plan that is not
  ignored is already on the branch.
- **What it hashes:** the PUBLISHED copy, `branch or main` from `plan_copies(sdlc_dir, goal, rec, run)`
  (Decision (b)). A plan that is only on the branch is found there (B1).
- **Gate off:** `_plan_review_refusal` returns `""` with zero extra calls.
- **No plan in either copy:** it returns `""` when no record exists, so the hard gate owns that case
  and design PRs pass. When a record exists, it refuses (R-d, below).
- **Unreadable plan or record:** FAILS CLOSED. The gate is opt-in, the remedy (re-record) costs one
  command, and the party best placed to make a record unreadable is the one the gate stops. A `git`
  failure inside `plan_copies` propagates. `main()` prints `work: <msg>` and exits 1 (`work.py:5739-5744`),
  and the push, which comes after the gate, never runs.
- **Shape:** it mirrors `_hard_plan_gate_refusal`:
  `gates.plan_review is on and <problem>: <remedy> and re-run (nothing pushed).<tail>`.

**The gesture** named in every remedy (`G`):

```
`work.py record-plan-review <sdlc> <goal> --verdict SOUND|SOUND-WITH-REFINEMENTS|FIX-FIRST --plan-sha256 <the brief's Plan sha256>`
```

**The tail** (`T`):

```
 Hashed: <H>. Covers the goal's plan .md only — not <sdlc>/plans/<stem>.slices.json, and not a design PR's .sdlc/design/<n>.md.
```

`H` = the file actually hashed (posix): the branch copy `<worktree>/<rel>`, or the main-checkout copy
when the branch carries none. `R` = the record path. The remedies name no main-checkout path, because
in the branch-only case there is none.

**Refusal drafts:**
- **No record:**
  `gates.plan_review is on and this goal's plan has no recorded review: run plan-review, record its verdict with G and re-run (nothing pushed).T`
- **Recorded FIX-FIRST:**
  `gates.plan_review is on and this goal's recorded plan review is FIX-FIRST (block): revise the plan, run a fresh plan-review, record its verdict with G and re-run (nothing pushed).T`
- **Hash mismatch:**
  `gates.plan_review is on and the plan changed after its review (the recorded review is of sha256 <recorded[:12]>…, the plan now differs): run a fresh plan-review of the current plan, record its verdict with G and re-run (nothing pushed).T`
- **Malformed record** (not JSON, not a dict, `plan_hash` not 64-hex, or `verdict` not in `pass|warn|block`):
  `gates.plan_review is on and this goal's review record R is unreadable or malformed: run a fresh plan-review, record its verdict with G and re-run (nothing pushed).T`
- **Plan unreadable:**
  `gates.plan_review is on and the plan could not be read (<exc>): make H readable and re-run (nothing pushed).T`
- **Recorded plan gone** (R-d; `H` = `none`):
  `gates.plan_review is on and this goal has a recorded plan review (R) but no plan resolves in <sdlc>/plans/ or committed on its branch: restore the reviewed plan (or delete R if this goal no longer has one) and re-run (nothing pushed).T`

`pr()` refusals exit 0 (the house contract; TD-2 is out of scope). The "red" evidence is the refusal
line plus the branch being absent from the remote.

  duplicate or forged journal event (TD-4). No code gates on the journal event, so enforcement is not
  weakened. This is recorded as a follow-up.

### 7. What this does not claim
- The check runs at `work.py pr`'s push, not before the first edit. Code written before the review is
  caught only at publication.
- **Only `pr`'s push is checked.** Later pushes to an open PR skip it. `work.py rebase` force-pushes
  (`work.py:3232`, `:3281`), and it is reached from `ensure_fresh` (`:3361`, run by `loop.py verify`),
  `_reconcile_behind` (`:3571`) and feature upkeep (`feature_rebase.py:827`). `merge()` never
  re-checks. So a plan edit committed after the last `pr` and published by one of those force-pushes
  is not checked. The documented fix cycle re-runs `work.py pr` after every `commit` (`pr()`'s
  docstring, the blocked-review cycle), and that path IS checked. A re-check in `merge()` is a
  follow-up (DoD 5).
- The record is agent-written: it proves a verdict was recorded for exact bytes, not that an
  independent reviewer produced it. Not org-lockable (#174). Inert with `work.enabled` off. `.md` only.
- A `skip-worktree`/`assume-unchanged` branch copy with local edits fails OPEN (Decision (b), R-e).
- Brief and record run from the main checkout. From a goal worktree (no work record there) the record
  keeps no file and its note names the main checkout, so `pr` still refuses (Decision 2, R-c); a
  brief built there hashes the worktree copy, which the record refuses if it differs.
- It does not fix `_hard_plan_gate_refusal`, which reads only the main checkout (`work.py:3898`). With
  `gates.hard_plan_gate` on, a plan that is only on the branch is refused as "no plan" before this
  gate runs. That is pre-existing, fails closed, and is a follow-up: `plan_copies` is the shared fix.

## Five properties
- **Reliability:** every claim has a test seen red (T6) and an end-to-end run of the gestures the docs
  give (T7); the timing is measured (T3.5); "proceeds" means it reached the push, not a GitHub PR.
- **Scalability:** O(1) path lookups per `pr()`, no scan. Gate on: at most two path-scoped git calls
  (only when the worktree holds a copy), one plan read + sha256, one small JSON read. The brief adds
  nothing when the main copy exists, else one `work` load and two git calls (like `_branch_doc`). The
  gates dir holds in-flight goals only (pruned by `finish`; nothing kept with work off or without a
  work record).
- **Resiliency:** atomic replace (prior record or none, never torn); a torn record, a git failure or a
  gone plan with a record fails closed and names a one-command remedy; a record attempted without the
  main checkout's work record keeps no file and says so, so `pr` fails closed; the gate and the
  writer share one resolver, so every remedy is satisfiable; re-recording is an idempotent
  overwrite; the mirror is fail-open.
- **Safety:** ships OFF; no background process, network call or secret; refuses loudly and names what
  it does not cover; deliberately not lockable rather than silently half-locked (#174).
- **Liveness:** not long-running; the doctor row shows the gate's state, including "ON but not
  enforced" with work off.
- **Host-agnostic:** enforcement lives only in `work.py pr` (Python + git), no hook; every host hits
  the same refusal.
