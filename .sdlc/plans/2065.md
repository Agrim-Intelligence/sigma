## Decision: a one-goal scope on the loop's own picker, then the loop's per-goal steps by reference

`/sigma-goal <N> --land` brackets the run with `loop.py start` and `session-end`, as `/sigma-loop` does.
It selects through `loop.py next .sdlc --land <N> --session-pid "$PPID"`, then runs `/sigma-loop`'s
steps 3 to 6 for that one goal. Those are the same steps a goal slot runs, reached by reference to
`skills/sigma-loop/SKILL.md` and its `references/` (running, progress, filing, landing). No landing
command is copied.

Why the picker and not `loop.py claim`: an unattended run may take N only when `/sigma-loop` would
pick it. `claim` checks the ledger and nothing else (loop.py:7874-7895). `_next_untraced` already
refuses or holds a goal that is:

- parked, in progress, blocked, closed, or without `sdlc:goal`;
- awaiting merge;
- waiting on an open prerequisite;
- held under a live claim lease or the per-goal claim lock, which is what stops two containers
  claiming one issue.

A one-goal scope reuses all of that: one implementation of "may this goal be worked now". It is the
same move `/sigma-goal --feature` made when it started asking `loop.py next --feature`.

Why `/sigma-goal` runs the steps itself rather than starting `/sigma-loop`: the loop's orchestrator
dispatches a goal-slot subagent, which in turn dispatches the phase subagents, and the orchestrator
then refills the slot. `/sigma-goal` is already a one-goal orchestrator that dispatches each phase at
the resolved tier. So it runs the goal slot's steps 3 to 6 directly, one nesting level fewer, and never
step 7 (no refill).

The order is the loop's, unchanged: Review, Retrospective, then verify, commit, PR, post-PR review,
merge and `record`. The landing path is reused as it stands.

## Contract sentence (quoted verbatim in both skills, whitespace-normalised comparison)

> **While a `--land` run is active, no goal other than the one it names may be picked, and no other goal is written to.**

The same paragraph in both skills states one exception directly under the sentence (review finding 5).
With `ledger.enabled` on, the loop's verbs (`next`, `verify`, `record`, `work.py`) keep the ledger
watcher alive (loop.py:7551, 7715, 8037; work.py:9099). The watcher is a separate process whose tick
runs the reconcile sweeps (`reconcile_tick.py`). Its writes are the watcher's, not this run's. The
sentence binds the run.

## Endings (keyed on the last `record` verb; routing from merge line to verb is landing.md's, cited, not copied)

| Last thing that happened | Final state named in the message |
|---|---|
| `record done` succeeded | **merged** |
| `record parked "<reason>"` | **parked**: `record` posts the reason on the issue |
| `record review` | **parked, awaiting merge (not `sdlc:parked`)**: `record review` posts why on the issue |
| `record failed "<reason>"` | **failed**: the reason is in the message and on the issue |
| picker `--land #N not taken (parked)` | **parked**: the pick wrote the hold and its comment on N |
| picker `not taken (not started)`, `BUDGET`, `HANDOFF`, or a refusal | **failed (not started)**: the stderr line is the reason; this run wrote nothing to N |

Not endings:

- `REPAIR:` and `RERUN:` lines, and `HOLD`.
- A `record done` that is REFUSED. Follow the refusal's named next step (landing.md); the ending is
  whichever `record` verb finally lands.

The awaiting-merge state in an ephemeral container (finding 3):

- The merge-reconcile pass reads only local work records (work.py:4997-5012). Once the container is
  gone, no machine will record `done`.
- The documented lever: once the PR has merged, `loop.py record .sdlc <N> done` from any checkout of
  the repository.
  - That checkout has no work record, so `done_refusal` returns None (work.py, `if not rec: return
    None`) and does NOT re-check the merge. The person running it confirms the merge first.
  - Alternatively, `/sigma-unpark`-style human handling. UNMEASURED live.

## Risks

- `_next` is the hot path. Every change is guarded on `land_scope`, and the proceed-chain rewrite is
  order- and short-circuit-identical. The existing golden-call tests guard the unscoped path.
- Cost at 10x and 100x: a scoped pick is one REST issue GET per `next_pending` call, plus one board
  read when a board is active, against a list read of up to 200 issues. It does not grow with the
  backlog. A `--land` container never reconciles other goals; the full loop or the watcher does that.
- Unmeasured live: no real cloud container has run `--land`. Fakes only, and the docs say so.

## Revision 3 changes (round 2 findings; these override the sections above)

1. **The container lever.** Drop the `record done`-from-another-checkout gesture: on shipped config
   the phase-record gate and `verify.enforce` refuse it. What `land.md` documents instead is what
   actually happens to an awaiting-merge goal whose container is gone:
   - **Default-branch base:** the PR body carries `Closes #N` (work.py:4326-4327, when the goal reads
     a declaration). GitHub closes N on merge; the `sdlc:in-progress` label and the ledger `done` are
     left as residue for a person.
   - **`feature/` base:** the keyword is inert and N stays open until a person closes it.
   - In both cases this is UNMEASURED live. The ending names it, so a person knows to look.
2. **Pass-over reasons.** Under the scope, the first pass-over of N ends the pick at once, with no
   re-read (it also saves a GET). Each `skip.add(goal); continue` site becomes "record the reason;
   go to the DONE path".
   - `land_why` is set only from the base read (`extra_labels` empty), so the blocking lane cannot
     overwrite it.
   - New reason: `not assigned to <login>`.
   - Tests assert on the printed `--land #N not taken` line itself.
3. **No "parked" at pick time.** Whether a pick-time hold actually landed on N is not knowable (the
   `Decision` and `Gate` objects carry no landed field). So every pick-time pass-over reports
   **failed (not started)** and names the check. When the check can write a hold to N, the line says
   so: "it may have left a hold and a comment on #N; that comment says what a person must do".
   - Drop the claim "this run wrote nothing to N".
   - An N already carrying `sdlc:needs-label` or `sdlc:needs-unit` reports "not started:
     carries ...". The overlay is cleared by the loop's own sweep: an unscoped `/sigma-loop` pick or
     the ledger watcher, once the person has created the label or declared the unit. `land.md` says
     so.
   - The endings table loses the "picker ... (parked)" row.
4. **Nine sweeps.** `_dag_check_pick` is also skipped: a `refresh-requested` forces a refresh, and the
   refresh posts cycle comments. In `on` mode the hold then falls back to the mirror. `_dag_order_pick`
   only sets ranks, so it stays.
5. **Cost, restated.** A scoped pick costs:
   - one issue GET per `next_pending` call;
   - plus the dependency hold's mirror refresh, which every pick already pays: on a cold checkout two
     REST list reads (open up to 200, closed up to 200), and a forced refetch on a hold;
   - plus the board read (up to 5000 items) when a board is active.
   It does not grow with the backlog beyond what the unscoped pick already reads. The "no backlog
   list read" test is narrowed to `next_pending` with a fresh mirror stubbed.
6. **The board check.** `ready` holds eligible Ready cards only, and `carded` is a set of ints, so
   compare `int(N)`.
   - If N is in `ready`, or not in `carded`: do the label read.
   - If N is carded but not in `ready`: still do the label read, and report "its board card is not in
     the Ready lane" only when that read finds N eligible. Otherwise report the label read's reason.
7. **Chain test seams.**
   - Patch `lp.sources.get_source` to return `GitHubSource(cfg, run=<sources adapter>, sdlc_dir=d)`.
   - Patch `lp.work._run` and `work._run` with the work adapter. These are two adapters over one
     stateful store, because the two runners take different argv shapes.
   - Use a test config without `gates.phase_record`.
   - Patch `subprocess.run` (and `_run_gh`) to raise, so an unpatched seam fails loudly rather than
     reaching GitHub.
8. **`session-end`** passes `--session-generation "$g"` from `start`'s stdout. The prose test requires
   the flag.
9. **The sweep test** patches `loop._dag_first_pick` (and every other sweep) at module level, so the
   process-global `_DAG_PICKED` cannot make it order-dependent.
10. **Second exception under the sentence.** With an active board and `project.archive_done`,
    `record done`'s card archive runs `_ensure_board()`'s backlog sync, which can card other goals.
    It is a board-only write, never in a cloud session (`board_active` is false there). It is named
    beside the watcher.
