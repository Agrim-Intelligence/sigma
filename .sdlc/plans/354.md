## Design

Live arms run `claude -p` only THROUGH the operator isolation launcher (`launcher -- claude ...`), the seam the
landed harness already validates. Sigma cannot prove a launcher contains an agent, and the README says so. What
Sigma owns, enforces and tests:

1. **Isolated profile per run and per attempt.** `HOME`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME` are fresh directories
   under that run's (for A3, that attempt's) own directory. The operator's real plugin directories
   (`<HOME>/.claude/plugins`, plus `<CLAUDE_CONFIG_DIR>/plugins` when the harness environment sets it) are
   content-hashed (symlinks not followed; an absent directory hashes to the stable value `absent`) once as a baseline,
   compared at the top of every run iteration (so a change made during run N is caught before run N+1 starts) and
   once more after the last run's scoring. The baseline is taken before ANY `claude` invocation, including the
   version call, so nothing the harness starts can be absorbed into it. Any change aborts the benchmark. The environment forwards the harness
   environment except the three profile variables and any value containing the hidden root, so an operator-set
   `ANTHROPIC_API_KEY` reaches `claude` and is readable by the agent (stated limit); no environment value is ever
   logged or written to results. The scoring commands receive the same forwarded environment, so agent-authored
   test code can read the key too (stated limit).
2. **Clean plugin export (A1 only).** `git archive <pinned commit> .claude-plugin skills hooks`, read with stdlib
   `tarfile` and written by a loop that refuses links, devices and absolute or `..` paths, into a fresh per-run
   directory; refused if any path has a component named `evals` or `tests`, or a top-level entry outside the three
   trees. `--sigma-commit` is required for the sigma arm (no default, so nothing runs unpinned); the full resolved sha
   is recorded in the results. Loaded with `--plugin-dir <export>`; the repository is never a plugin directory.
   The export omits `docs/`, `tools/`, `contract/`; skill text links to some `docs/` files, nothing else was found
   to need them, and A1's behaviour without them is not measured here (named limit).
3. **Hidden-test root and scoring.** Already refused inside the repository or a task source; add: refused inside the
   scratch root (every arm workdir, profile and plugin export lives there). The hidden root never enters an arm's
   environment. Scoring is done immediately after each run, and the visible and hidden commands both run through the
   launcher with the arm-isolated environment (so agent-authored test code does not execute with the harness's own
   authority or environment). The scoring copy (`<run>/scoring`, which holds the hidden bundle) lives inside the run directory, and after
   scoring the WHOLE run directory (worktree, profile, transcripts, scoring) is removed, so a later arm or attempt cannot read an earlier arm's solution or any hidden
   file, and scratch holds one run at a time (O(1), not O(tasks x arms)). The run directory is also removed in a
   `finally`, so an abort, an exception or Ctrl-C leaves nothing; and the benchmark REFUSES to start when the
   scratch root is not empty (a crash or SIGKILL mid-scoring can leave a copy of the hidden bundle there, and no
   re-run may inherit it; the operator empties it deliberately). The hidden bundle is, by the preregistration's own
   design, copied next to agent-authored code at scoring time, so hidden-test confidentiality at that moment depends
   entirely on launcher containment (named limit; the leak test scans scratch only). Nothing of a run survives except its
   content-free row; capturing transcripts or final messages for the trap-catch metric is a follow-up (a retained
   copy would reopen the leak above, so it needs its own design).
4. **Matched spend (A3)** (defined for one repeat: `--repeats` above 1 with the matched arm is refused, because the
   issue's median-of-repeats rule and the preregistration's one-repeat design differ and the preregistration wins). Snapshot the starting tree (`workdir` at entry) before attempt 1; each attempt runs in a
   fresh copy of it with its own profile and is deleted before the next attempt unless it is the one to score. At
   least one attempt always runs. After each attempt stop when the visible command passes, or cumulative metered
   spend reaches A1's spend for the same task, or the remaining global ceiling is no longer positive (a non-positive
   `--max-budget-usd` is never emitted), or the row's single `deadline` (the preregistration's per-run
   wall-clock limit, shared by all attempts, each attempt's `claude` and visible command bounded by what is left) passes,
   or `--max-attempts` (default 10, a cost-and-time bound) is reached, or an attempt could not be priced (cap
   cannot be applied; the row's cost is then `None`, its reason carries the priced part already spent, and the
   benchmark stops per section 5 with that reason in the `aborted` object).
   Score the first visible-passing attempt, else the last (the analysis reports each A3 row's stop reason, since a
   shared 60-minute deadline can end a long task's row before the spend cap does; the visible result the harness records is its own run
   on the replaced `workdir`; a flaky visible test can differ from the loop's stop decision, a named limit); the chosen tree REPLACES `workdir` (remove, then copy;
   never overlay). The row's cost is the cumulative spend of all attempts; the last attempt may overshoot A1's
   spend by up to one attempt (bounded by the belt), which is recorded, not hidden. `matched` without `sigma`
   earlier in the run is refused before any spend. An A1 run that could not be priced stops the whole benchmark
   (section 6), so A3 never sees an unmetered A1; an A1 row skipped because the spend ceiling was reached has no
   spend, so the A3 row for that task is skipped too, with that reason. Seam: `run_benchmark` binds each live arm
   instance before its `run` (`arm.bind(visible_command, match_usd, guard)`), because `Arm.run(workdir, prompt, env,
   deadline)` carries neither the task's visible command nor A1's spend; `guard` re-checks the plugin hash. The
   exact-type allow-list admits the instance by its class, never by attributes. A3 calls `guard()` before EVERY
   attempt, so a plugin change inside an A3 row stops it before the next attempt (not only at the row's end).
5. **Bounded commands.** Every command the harness launches (the arm's `claude`, the visible command, the hidden
   command) runs in its own process group with a timeout (arm: what is left of the run deadline; scoring commands:
   `--scoring-timeout-seconds`, default 600), and on expiry the WHOLE group is killed, so an agent-spawned child cannot
   keep spending or hang the benchmark (a launcher that re-parents or starts its own session escapes the group kill:
   the same unproven-launcher limit). A timed-out arm run is scored as it stands with its reason recorded; a
   timed-out scoring command counts as a fail. This mirrors the group-kill precedent of the watch loop's runner;
   POSIX only, and a non-POSIX host is refused rather than half-guarded.
6. **Spend safety.** `claude -p` with prompt on stdin, `--session-id <uuid>`, `--model <pinned>`,
   `--permission-mode <value>` (required, owner-chosen, identical for every arm, never defaulted), and
   `--max-budget-usd min(belt, global remaining ceiling)` (for A3, minus what earlier attempts of that run spent).
   Cost per attempt is metered from the profile's own transcript by `evals/bench/meter.py`. A run whose cost is
   `None` cannot be applied to the ceiling, so the benchmark stops (never counts it as zero). A real `claude` can
   overshoot its flag; an arm cost above the remaining ceiling stops the benchmark. Every stop after the first arm
   started (refusal, overshoot, unpriced run, plugin change, any exception including `KeyboardInterrupt`) writes the
   rows so far to the results path with an `aborted` object (reason, task, arm, and `cost_usd_spent`: the in-flight
   run's attempts already paid, which each arm tracks as it goes) and then re-raises; the run directory is removed
   in a `finally` after that write. So money spent is not lost, even mid-row. The first real live run will probably
   stop at the unpriced-run guard until the operator supplies credentials: a `claude` that cannot log in spends
   nothing and meters nothing, and the benchmark stops loudly rather than guess. This
   replaces the landed rule that an overrun writes no report; the existing test is updated and the README says
   a report with `aborted` is partial. There is no resume: a re-run re-pays every arm (named follow-up).
7. **Provenance.** The results carry the resolved sigma commit, the pinned model, the permission mode, the belt and
   `claude --version`, run once at benchmark start through the launcher with an isolated profile (that profile lives under the system
   temp directory and is removed, never under scratch; a dry run
   spawns nothing and reports it as not run). Preregistration holds model and version constant; the
   harness records them but does not itself enforce a single `claude` version across a benchmark.

A results path inside the scratch root is refused (it would survive the run and make the next one refuse as
non-empty). Check order inside validation: the hidden-root-inside-scratch refusal runs BEFORE the non-empty-scratch refusal
(a hidden root inside scratch also makes it non-empty, and the more specific message must win). Run output is
discarded (only return codes are used; `claude --version` is the one captured output, size-limited), so agent-authored
test code that prints endlessly cannot fill memory.

Dry run: `--dry-run` validates everything, exports the plugin once to a temp directory under the system temp
directory (not scratch, so the non-empty rule does not police it; removed afterwards) to check its contents,
spawns nothing and prints each arm's PLANNED isolation facts (labelled planned, not observed), each saying that
launcher containment is not verified by Sigma.

## Test notes
The `## Tests` block names the whole new file because the red-before-green protocol caps selectors at 25 and the
inventory above has more tests than that; the one renamed landed test keeps its own node selector.

A fake `claude` executable on PATH (a Python script written by the test) reads the prompt from stdin, appends one
JSON line per call to a log (argv, cwd, the three profile variables, whether any `attempt.txt` or `solution-*`
file exists under the scratch root outside its own cwd, whether any file under scratch contains the hidden-bundle
sentinel text, plugin-dir listing), writes a priced transcript under `$CLAUDE_CONFIG_DIR/projects/`, and may touch
a path named by a test variable (the real-plugin change). Prices come from a test rate CSV passed with `--rates`;
nothing reads the real rate card, the network, or the real home. Tests set `HOME` to a temp directory so the real
`~/.claude/plugins` is never hashed or touched. The cap test uses cost X per plain attempt and 2.5 X for the sigma
arm, so the cap is 2.5 X and three attempts (cumulative 3 X) is the exact stop.

Message assertions are load-bearing: the repository and scratch refusals assert their own text ("outside the
repository", "outside the scratch root"), because removing either check would otherwise fall through to the later
missing-bundle refusal, which also exits 2 (a control that passes against the bug). The repository test uses an
existing directory inside the checkout (the repository's `docs`). The profile test compares the three variables
with the real `HOME`, every other run's and attempt's values, and each other. The export test checks the directory
contents the fake logs (no `evals`, `tests` or `docs`), not only that the path differs from the repository. The belt
test asserts on the `--max-budget-usd` argv the fake received (the fake ignores the flag). The plugin-hash controls
are separate: remove the post-loop comparison (a one-task benchmark whose only run changes the directory then goes
undetected), remove the loop-top comparison (the between-runs test then sees a second `claude` call), remove the
aborted-rows write. The mid-row exception test monkeypatches the shared bounded-command runner to raise
`KeyboardInterrupt` on its third call (sigma's claude, matched attempt 1's claude, matched attempt 2's claude: the third call whose argv holds `-p`) and expects the first attempt's cost in `aborted`.
The no-predecessor test asserts the parser has no option containing that word and that no `.py` file under
`evals/bench` contains it (prose in docs is out of scope). The leak test scans file CONTENT for the sentinel (a copy
under another name is still found). `_command_passed`/`_hidden_passed` signatures gain launcher and environment
arguments; the landed tests that monkeypatch them accept any arguments.

## Risks and limits
Cost is read from a transcript under the profile's own `CLAUDE_CONFIG_DIR`, which the agent can write if the
launcher does not stop it, and a launcher that remaps HOME can hide it (then cost is `None` and the benchmark
stops); cost is exactly as honest as the launcher. Authentication in an empty profile is untested: `claude -p`
needs credentials the isolated profile lacks, so an unattended run needs an API key in the harness environment
(owner action, outside this goal), readable by the agent. The plugin-hash guard can false-abort if the operator's own
Claude sessions update plugins during a run; it keeps the paid rows, there is no resume. A skill folder named `tests`
or `evals` added later makes A1 fail at export; that is intended. Hashing cost is linear in plugin-directory
size; the real directory's size and one digest time are measured and recorded in the retro, not asserted here. No
real `claude` is run: flag spelling (`--plugin-dir`, `--session-id`, `--max-budget-usd`, `--permission-mode`, prompt
on stdin) is unverified against the real host. At 10x or 100x tasks the harness stays serial by design (one spend
ceiling), and scratch stays one run deep.
