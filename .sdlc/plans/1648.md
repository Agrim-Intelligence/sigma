## Decisions

1. **Module `skills/sigma-loop/scripts/codex_cli.py`**, stdlib only, library (no `__main__`; goes in `tests/test_script_help.py` `LIBRARY_ONLY`). Public API, nothing else is public:
   - `APP_PATH = "/Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex"`, `ENV_BIN = "SIGMA_CODEX_BIN"`.
   - `class CodexCliError(ValueError)` with `.reason` in `("not-found", "override-invalid", "ambiguous")` and `.paths` (tuple of the paths involved). `str(exc)` is operator-ready and names the lever (`set SIGMA_CODEX_BIN=<absolute path>`).
   - `resolve(env=None, which=None, app_path=APP_PATH, platform=None) -> str`: an ABSOLUTE path, never executes the candidate (stat plus `os.access(X_OK)` only). `which=None` means `shutil.which`; `app_path=None` disables the app rung (the injected-stand-in idiom used by the reviewer and tests); `platform=None` means `sys.platform`, and the app rung exists only when it is `"darwin"` (elsewhere the rung is skipped, not an error).
   - `skew(a, b) -> bool | None`: compares the first three dotted integers of two version strings; `True` differ, `False` equal, `None` when either does not parse (callers decide: supervisor refuses on `None`, doctor stays silent).
   - `own_version(root=None) -> str | None`: `version` of `<root>/.claude-plugin/plugin.json`, default root `Path(__file__).resolve().parents[3]` (the RUNNING copy, same idiom as doctor's `_AGENTS_MD`); `None` when unreadable. Never raises.
   Order, each rung exact: (a) `SIGMA_CODEX_BIN` non-empty (empty string counts as unset, matching `legacy.getenv`): must be absolute, a regular file and X_OK, else raise `override-invalid`, NEVER fall through to PATH. A valid override wins without consulting anything else; another copy existing is not ambiguity. (b) PATH hit via `which("codex", path=env PATH)`, made absolute with `os.path.abspath`. (c) the app rung. If both (b) and (c) answer and `os.path.realpath` differs, raise `ambiguous` naming both; same realpath is one copy and returns the PATH spelling. Only one answers: return it. None: `not-found`. Resolution is O(1) stats; deterministic, which the supervisor needs because it re-resolves on every launch.
   **Load by path without bytecode**: `codex_runtime.py` gains `_codex_cli()` that sets `sys.dont_write_bytecode = True`, loads `codex_cli.py` through `spec_from_file_location`, and restores the previous value in a `finally`. It does not rely on the caller having set the flag, because `installed_skill` is also called from tests and doctor-like callers. Plain `import codex_cli` is forbidden (it writes `__pycache__` into the verified Git install and fails `_clean_git_head`).
2. **`SIGMA_CODEX_CMD` vs `SIGMA_CODEX_BIN`, no third name.** Two jobs, both kept: `SIGMA_CODEX_BIN` chooses WHICH binary (inventory call and default launch); `SIGMA_CODEX_CMD` is the full launch argv prefix and decides only the launch argv. Reconciliation of the existing hole: when `SIGMA_CODEX_CMD` is set and its `argv[0]` is exactly the bare word `codex`, the supervisor replaces it with `executable` (the resolver's path); an absolute `argv[0]` is respected as is (the operator named a binary); any other bare name is untouched. Effect: on an app-only machine `SIGMA_CODEX_CMD="codex exec ..."` works with no PATH entry. This is a default-and-flag candidate, not a Block C: documented in `docs/codex-autonomy.md`. `SIGMA_CODEX_BIN` is registered in `legacy.POST_RENAME_ENV` (introduced after the rename; the guard `tests/test_legacy_compat.py::test_every_sigma_env_literal_is_a_name_the_helper_knows` goes red until it is).
3. **Supervisor skew check without weakening the guard.** The running copy's version is supplied by the running copy itself: `codex_runtime.running_version()` returns `codex_cli.own_version()` or raises `ValueError("running Sigma copy has no readable plugin.json version")` (cannot prove no skew, so refuse). `installed_skill(env=None, codex_executable=None, own_version=None)` gains one optional parameter; when not `None`, after `resolve_install` succeeds it compares the enabled inventory entry's `version` with `own_version` via `codex_cli.skew` and raises `ValueError("Sigma version skew: Codex-enabled install is X, the running supervisor is Y; update the older host")` unless `skew(...) is False` (so an unparsable side refuses). ## Fixture facts

Fixture facts the tests rely on. The resolver tests use a tmp dir with executable shell/python fakes (never a real model), `app_path=<tmp fake>` or `None`, `platform="darwin"|"linux"`, and `env={"PATH": <dir>}` so `/Applications` is never read. Value-distinguishing choices:
- Ambiguity: PATH fake and app fake are two files with different content (different realpath); the assertion is on `reason == "ambiguous"` AND that BOTH path strings appear in `text`.
- Same realpath: the app fake is a symlink to the PATH fake; expected `("ok", <PATH spelling>)`.
- Override: `SIGMA_CODEX_BIN` fake, a different PATH fake and a different app fake all exist; expected the override (and not `ambiguous`).
- Invalid override parametrised over relative path, missing file, directory, non-executable file; each with a VALID PATH copy present, so a fall-through is distinguishable (expected `override-invalid`, not the PATH path).
- Executing check: the fake writes a marker file when run; after `resolve` the marker must not exist.
- Skew: unit pairs (`"1.0.15","1.0.15"` False; `"1.0.15","1.0.16"` True; `"1.0.15","1.1.0"` True; `"1.0.15","garbage"` None; `"1.0.15","1.0.15-rc1"` is compared on the first three parts, False).
- Supervisor: `RUNNING_VERSION` from the repo manifest; the skew fixture is `bump(RUNNING_VERSION)` (patch + 1, above the floor so the refusal is the skew one and not "below required version"); the fake CLI is on PATH AND named by `SIGMA_CODEX_BIN` (same file) so current code launches it; assert `rc == 2`, `"version skew" in stderr`, and the fake's `exec` marker file does not exist. Direction coverage is at the `installed_skill` unit (`own_version` greater and smaller than the entry, no floor interplay because `own_version` is free).
- Doctor skew: `installed_plugins_path` always pinned to a tmp file via `_plugins_file(tmp, [_entry("user", "1.0.9")])`, never the real home; Codex entry `_codex_entry("sigmaloop", "1.0.2")`; the check returns a list (no exception) with a row whose name starts `sigma versions:` and `ok is False`. ## Measurement and failure statements

- Reliability: the app path and `codex-cli 0.160.0` were measured on this Mac in research; this plan re-measures them in the Measurement block. The ChatGPT-app layout is one hardcoded string for one product layout: a renamed bundle is not found and falls to `not-found`, whose text names `SIGMA_CODEX_BIN`. A npm shim that execs the app binary looks like a different copy and is refused as ambiguous (lever: `SIGMA_CODEX_BIN`); documented, not hidden. Real two-copy ambiguity has not been observed on any machine, only the planted one.
- Scalability: O(1) (three stats and two realpaths) per call, one call per supervisor launch plus once per doctor run; the figure comes from the `timeit` step, not from reasoning. No table, no cursor, no lock, no chokepoint.
- Resiliency: a bad override, an ambiguity appearing mid-run, or a missing CLI is a loud refusal with the lever named; the supervisor's per-launch revalidation (`current_executable != executable`) turns a mid-run change into the existing "install changed" refusal. Recovery is the operator setting `SIGMA_CODEX_BIN` or updating the older host; nothing to re-ship, no retry state.
- Safety: refuse rather than fall through (override never degrades to PATH); the resolver never executes the candidate; no new spawn in the supervisor; doctor adds at most one `plugin list --json` read in a Claude session, non-cheap, bounded by the existing runner timeout, and only a warning. Nothing consumes quota; no secrets involved. Windows and Linux skip the app rung without error.
- Liveness: no new component. Host-agnostic: plain Python in `sigma-loop/scripts`, no hook; Cursor (no hooks) consumes the same module through the reviewer.
- Not done here (named, not hidden): a `--version` probe or minimum Codex CLI version check (the resolver answers "which binary", not "which version"); resolving the app path from a second bundle name; per-launch skew re-check (covered indirectly by the skill-path comparison); B1/B2 launchers (#1651, #1662, #1671, #1675) consuming `resolve` is their own work.
