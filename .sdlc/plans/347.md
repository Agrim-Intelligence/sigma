## Design
**Tool `tools/readiness/shared_paths.py` (new, stdlib only).**
- `scan --sigma REPO --predecessor-dir DIR --json OUT [--table OUT.md] [--fixture-out OUT.json] [--no-samples]`:
  1. `tree_hash(DIR)` (sha256 over relative path + file sha256, symlinks by target text) BEFORE; read-only scan;
     `tree_hash` AFTER; unequal -> exit 2, nothing written. Version from `.claude-plugin/plugin.json`.
  2. Writers: `growth_audit.scan` with `_row` temporarily relaxed (keeps non-`.sdlc/`-prefixed placeholders), every row
     canonicalised (alias table `<sdlc>`, `<features_dir>`, `<goals_dir>`, `<state>`...; digits and `<x>` -> `*`), rows kept only
     from `skills/` and `hooks/` code, each mapped to a site id `file::function`. One supplementary writer
     (`feature_registry.write_unit`) pinned by name and verified to exist in the tree.
  3. Readers: calls to read/exists/glob/iterdir/stat/`open(r)`/`os.path.*` resolved with `growth_audit._expression_path`
     (the refactor `function_table` is the only change to growth_audit; its `scan` output is unchanged, measured equal).
  4. Shared = a pattern one side writes and both sides touch (wildcard overlap). Directories (a pattern that is a parent of
     another) are listed and not classified.
  5. Class and verdict per two-writer path: `same-format` (equal key sets and schema from a sample each side's own CLI
     wrote), `additive` (one side writes extra keys, same schema), `different-format` (schema id spelling differs, or
     neither key set contains the other), `identical-writer` (no sample, but every writer function on both sides has the
     same AST after docstrings are dropped and brand spellings neutralised), else `unsampled`. One writer -> `one-writer`.
  6. A `different-format` path gets `corruption`: `demonstrated` / `not-demonstrated` / `not-probed` from two probes the
     tool runs against a temporary copy of the predecessor: config cross-`configure` (key loss) and registry fold (Sigma's
     `index.json`, then the predecessor's own `feature_sync.py fold`, then what Sigma reads).
  7. Cross-run: Sigma/predecessor/Sigma and the reverse on one scratch repo with the same command list; any exit code that
     differs from the solo run is listed.
- `check --sigma REPO --fixture F`: scans Sigma's writers only, no predecessor needed. Every Sigma writer site whose pattern
  overlaps a pattern in `F.predecessor_written` needs an entry for that predecessor pattern with `compatible: true` and a
  non-empty reason, or `compatible: false` and a filed `issue` (`#N`), AND the site id must be in the entry's
  `vetted_writers`. So a NEW writer function (or file) on a shared path is refused even when the path already has an entry.
  Exit 2 with one line per violation. Known blind spot: a second write inside an already vetted function is not seen.

**Fixture `tests/fixtures/predecessor_written_paths.json`** (generated by `scan --fixture-out`, then reviewed): predecessor
version, the three digests, `predecessor_written` (sorted `.sdlc/...` patterns only), `entries` (pattern, compatible, reason,
issue, evidence kind, vetted_writers). No predecessor site names.

**Doc `docs/launch/shared-sdlc-paths.md`**: version and why that directory, before/after hashes (values), method, counts per
class, the table (generated), findings with their issue numbers, limits, the gestures to reproduce and to run the control.

**Findings**: the registry `index.json` fold wipe is filed (`launch:blocker`, `readiness`, class B1) through `handoff.py
track --queue queued` after `dedup.py`; not promoted. Unsampled paths: one `launch:next` follow-up.

## Risks / limits stated plainly
- Static scan limits (see the module docstring); samples cover one fixed command list, not work.enabled, ledger, GitHub mode.
- `identical-writer` is weaker evidence than a sample: the same function can call different helpers.
- Key sets, not values or free text, are compared; markdown is compared by heading count only.
- The guard names a writer by `file::function`: a second write inside a vetted function, or a path assembled at run time, is
  not seen.
- Test runtime: two Sigma scans (cached) plus one on a scratch copy, roughly 1 minute measured.
