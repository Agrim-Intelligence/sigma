# Plan: #233 — Loop mirrors Priority and Phase to board fields on every status write

**Goal**: #233 · **Research**: `.sdlc/research/233.md` · **Date**: 2026-09-29 · one branch (`sdlc/233`).

## Decisions (made without the owner; recorded here)

- **D1 Unlabelled = blank, not P3.** The kit's existing rule (`discovery.UNPRIORITISED`, README "the field decides")
  wins over the issue's "P3 when unlabelled": writing P3 would reorder the board queue and make the field-wins mirror
  stamp `priority:P3` labels on every unlabelled goal. An unlabelled card's Priority is left blank ("no priority").
- **D2 Priority keeps #719 semantics.** Field recognised -> it wins (label corrected, loudly); field blank -> filled from
  the label. "Priority matches the label" therefore holds for every card whose field was blank or already agreed.
- **D3 Where each field is written.**
  - Every Status write (`_set_board_status`) also mirrors the moved goal's Priority, from the labels `_sync_backlog`
    already read this run (zero extra reads; skipped when this run never read that goal's labels).
  - Phase is written ONLY at a boundary: `phase_report.py start` -> `GitHubSource.set_board_phase(goal, phase)`,
    which also mirrors Priority from the card's own `labels` (item-list carries them). Status is never written there
    and an uncarded goal is never carded there (that would leave a blank-Status card).
- **D4 Field provisioning** happens on the boundary path only, and only when `project.enabled` AND `project.number`
  is pinned (an explicit operator choice of board). The Status-write path keeps its `created_now`-only rule, so
  `test_an_adopted_board_gets_no_priority_field_from_the_loop` stays true for a loop tick.
  - Absent field -> created ONCE via `createProjectV2Field` (single-select, fixed options: `PHASE_TOKENS` imported
    from `phase_report`, `discovery.PRIORITIES`), every literal JSON-escaped like `_options_mutation`.
  - Present under a case-different name (`phase`, `PRIORITY`) -> adopted, never renamed, never duplicated.
  - Present with extra options -> kept; options are matched exactly then case-insensitively. A missing option is
    NEVER appended from the loop (`gh project field-list` returns no colours/descriptions, and #235's rule is to
    refuse rather than reset them) -> one warning naming the option and `board_setup.py`/by-hand fix. Nothing is
    renamed, recoloured, reordered or dropped, so option ids are preserved by construction.
  - A same-named field that is not single-select -> one warning, skipped.
- **D5 Config.** `project.phase_field` (default `"Phase"`; falsy disables Phase), next to `project.priority_field`.
  Whole path is a no-op (zero gh calls) when `project.enabled` is off, no number is pinned, the source is not
  github, or the goal is not an issue number.
- **D6 Fail-open + one warning.** Every failure on the boundary path is swallowed; the first one per run prints ONE
  `sigma: board Phase/Priority not written ...` line on stderr, later ones are silent. `phase_report.py start` runs the
  write AFTER its marker, ledger event and banner, inside `try/except Exception`, so its exit code and stdout are
  unchanged by any board outcome.
- **D7 Bounded.** Each gh call on the boundary path has a timeout (`BOARD_CALL_TIMEOUT_S`=20) and the whole write a
  deadline (`BOARD_BUDGET_S`=45): a sick `gh` costs at most ~a minute once, never a hung phase.
- **D8 Dedupe.** The card's current Phase (item-list) is compared first: an identical value costs zero writes, so a
  repeated `start` for the same phase writes nothing.

## Cost per boundary (measured against the fake in the tests)

Steady state: 3 reads (`project list`, `field-list`, `item-list`) + at most 1 Phase write + at most 1 Priority write.
First boundary on a board lacking both fields: + 2 GraphQL creates + 1 re-list. `item-list` is one CLI call whose
internal paging grows with the board (100 cards/page up to `_BOARD_ITEM_LIMIT`=5000): at 10x/100x cards it is 10x/100x
GraphQL pages inside that one call — the same read every loop tick already pays in `_ensure_board`; no new O(board)
write, and no O(backlog) REST read (`_sync_backlog` is not run on this path). A pinned number outside the first 100
boards adds 1 `project view` read.
