## Exact edits
1. `cmd_pr`, `sub == "comment"` branch: replace the append-and-silent-return with an id derived as
   1 + the max existing id over every PR's stored comments (legacy bare-string comments and dicts with
   no `id` count as 0, so old state files stay valid and NO state-schema change is needed in
   `_make_world`/`_init_state` or `tools/onboarding_control.py`):
   ```python
   if sub == "comment":
       pr = state["prs"].get(pos[1])
       if pr is not None:
           cid = 1 + max([c.get("id", 0) for p in state["prs"].values()
                          for c in map(_as_comment, p.get("comments", []))] or [0])
           pr.setdefault("comments", []).append({"id": cid, "body": flags.get("body", ""),
                                                 "assoc": os.environ.get("FAKEGH_ASSOC", "OWNER")})
           save_state(state)
           print("https://github.com/%s/pull/%s#issuecomment-%d" % (state["repo"], pos[1], cid)); return
       save_state(state); return
   ```
   `pr_obj` reads only `body`/`assoc`, so the extra `id` key is invisible to `pr view --json comments`.
   The printed form matches `work.py` `post_review`'s `(?:comments?/|issuecomment-)(\d+)`.
2. `cmd_api`: add ONE new branch, inserted directly after the `repos/%s/labels` GET branch and before
   `if endpoint == "repos/%s" % repo:`, matching the endpoint WITH its query string:
   ```python
   m = re.match(r"^repos/%s/issues/(\d+)/comments(?:\?(.*))?$" % re.escape(repo), endpoint)
   if m and method in ("", "GET"):
       q = dict(kv.partition("=")[::2] for kv in (m.group(2) or "").split("&") if kv)
       per_page, page = int(q.get("per_page", "30")), int(q.get("page", "1"))
       pr = state["prs"].get(m.group(1))
       rows = [{"id": c["id"], "body": c["body"]} for c in map(_as_comment, (pr or {}).get("comments", []))
               if c.get("id")]
       emit(rows[(page - 1) * per_page: page * per_page], flags.get("jq"), argv); return
   ```
   Rows without an `id` (legacy) are skipped rather than invented. A page past the end returns `[]`,
   so `_find_evidence_marker`'s stop-on-short-page scan terminates. `re` is already imported in the body.
3. The five `drills.py` replace anchors are NOT touched or moved: the `UNHANDLED_PATH = ...` line, the
   `git(state, "update-ref", base_ref, head_sha)` line, the merge `save_state(state)` + `print("Merged ...`
   block, the `out.append({"number": ...` open-state line, and `if endpoint == "repos/%s/issues" % repo:`.
   The new branch sits BEFORE the last anchor line without editing it; drills' own `$`-anchored,
   query-less comments handler is injected right before that anchor, and the new query-string-aware
   branch (which also accepts the query-less form) runs earlier, which is intended and harmless for
   drills' use (it only POSTs, which the new branch does not match). Verify in step 3 that each anchor
   still occurs exactly once.
4. D-1 (dropped item): the issue's third item, "the matching post", is NOT implemented. Verified:
   `post_review` posts with `gh pr comment`; the only POST to `issues/%d/comments` in `skills/` and
   `tools/` is `comment_issue` in `skills/sigma-loop/scripts/gh_api.py`, which has zero callers. The
   method guard on the new branch (GET only) makes a stray POST fall through to `unhandled`, so the

## Scalability / resiliency / safety
- Fixture-sized: the id is a scan of all stored comments, O(total comments) per `pr comment`; the paged
  read is O(comments on one PR) per call. State is per-test temp JSON, rewritten whole by `save_state`;
  no cross-test growth, nothing to prune. No ceiling matters at fixture scale (tens of comments).
- Failure modes: a missing PR on `pr comment` keeps today's silent no-op; a read for an unknown PR returns
  `[]`; legacy state files without `id` remain valid. Test-only, no network, no host resources consumed.
