# #237 plan — end-to-end onboarding control

## Decisions (recorded; nobody available to ask)
- D1 Script-level control, no model session and no real GitHub (owner run constraints). The
  real-GitHub and live-model halves are an owner runbook plus filed issues, not skipped silently.
- D2 README-parsed, not restated: the init script path, `/agrim-init` flags, `/agrim-loop`
  presence, the confirm gesture and the CLI install lines are read from README.md, so a README that
  drifts turns the control red. The first-run pair is read from the `### Claude Code` block only.
- D3 Everything else comes from init's own printed output: `[ask]` lines answered with the flag
  each names (iteratively, max 3 rounds), the candidate n + id, and the `Next:` loop command.
- D4 The control's own goal has NO frontmatter verify_command, so config `verify.command` is what
  proves it (the demo goal carries its own and cannot catch the trap).
- D5 `loop.py verify`'s exit is recorded, not fatal; `record done` is the gate, so the trap reads
  red AT `record done` (the acceptance's wording), and the evidence assertion still catches a
  failed verify.
- D6 Reuse the bootstrap test's fake gh by `ast` extraction (one fake, not two).
- D7 Assertions are pure functions over observations (`check_local`, `check_github`) so each can
  be broken once in a test against a real run's observations.
- D8 Host install is opt-in (`--install`), isolated profile, real-profile hash before/after;
  `--from-install` runs the scripts from the installed copy.

## Steps / files
1. `tools/onboarding_control.py` (stdlib, POSIX; exits 2 on Windows or missing git/make):
   parse README -> fresh repo (Makefile `test` target checking hello.txt) -> init rounds ->
   README confirm gesture -> file goal (local file / fake-gh issue) -> loop start/next ->
   agent-start -> [work start] -> phase_report start/end -> work -> loop verify -> record done
   (local) or commit/pr/sigma:block merge/sigma:approve merge/record done refused/record review/
   human merge/reconcile (github) -> assertions -> result JSON with per-step durations + gh calls.
2. `tests/test_onboarding_control.py`: both modes green; C1 empty-verify default (scratch copy,
   `write_verify` regressed) red at `record done`; README drift red (confirm verb at the gesture;
   init script / loop line / init line / install line at the parse); every assertion broken once.
3. `docs/onboarding-control.md`: steps, recorded run, what is not covered, owner runbook for real
   GitHub, issues filed per gap.
4. CHANGELOG Unreleased entry; comment on epic #227 linking the doc.
