# #228 plan — init sets a real verify command

## Decisions (recorded; nobody available to ask)

- D1. The template ships `verify: {"command": "", "enforce": false}`. The template cannot know a
  command, so shipping enforce ON with an empty command is the trap itself. Enforce turns ON only
  when a command is confirmed (`verify_detect.py set`). Before this fix the "#2741 enforce ships
  on" state refused every `done`, so it never worked as intended. This keeps its intent (a
  machine-checked done) without the trap.
- D2. `scaffold()` never writes enforce ON. When it creates `config.json`, it records WHY enforce
  is off in `verify._why`: either no candidate was detected, or candidate X was detected but not
  yet confirmed. Confirmation is a separate gesture that every host can run. On Claude Code the
  skill asks the user and then runs it. On Codex and Cursor the scaffolder prints the candidate,
  the exact config line and the exact command.
- D3. `verify_detect.py decline <sdlc>` writes enforce OFF with a reason naming every declined
  candidate.
- D4. The demo goal carries its own `verify_command`, which checks that `sigma-demo.md` exists and
  is non-empty. This is the goal's own done_when, machine-checked, and it passes with or without
  a config command.
- D5. Doctor's row keeps its name. Its fix text gains the one-line gesture, and
  `_any_goal_verify_command` stops counting an empty `verify_command:`. The setup wizard's
  allow-list gains the row (`human_command`). `loop.py record done` says "no verify command
  declared" rather than "run verify first" when no command resolves. `_config_warnings` names
  the gesture.

## Steps

1. New `skills/sigma-init/scripts/verify_detect.py` (stdlib): `detect(repo)` returns ordered
   candidates, each with command, source and why. Sources: pytest (pyproject `[tool.pytest`,
   pytest.ini, setup.cfg `[tool:pytest]`, tox.ini `[pytest]`, conftest.py, or bounded test_*.py
   scan), package.json `scripts.test` (not npm's placeholder; lockfile picks npm/pnpm/yarn),
   go.mod, Cargo.toml, Makefile `test:`, `.github/workflows/*.y*ml` single-line `run:` test step.
   `write_verify(sdlc, cmd|None, why)` rewrites the verify block atomically and never writes
   enforce on with an empty command (it raises instead). CLI: `detect`, `set`, `decline`.
2. `sdlc_init.py`: `scaffold()` records the unconfirmed state on a newly created config.
   `main()` prints the candidate block. An existing config holding the trap gets a loud warning
   with the fix. The demo goal gains `verify_command`.
3. Template: enforce false, `_verify` rewritten. `project.md.tmpl`: the Verify section points at
   config and frontmatter. `SKILL.md`: step 3 replaced with the confirm flow (Claude interactive;
   Codex/Cursor print).
4. `loop.py`: shared `_declared_verify_command`; clearer refusal; warning names the gesture.
5. `doctor.py` fix text and empty-value fix; `setup_wizard._MODES` gains the row; wizard SKILL
   mentions it.
6. Tests: `tests/test_verify_detect.py` (detection, writer, CLI, init integration, e2e
   verify/record done via subprocess with `sys.executable`), plus doctor and wizard additions.
7. Docs: CHANGELOG Unreleased, README config-table row, sigma-setup SKILL step 3 pointer.
