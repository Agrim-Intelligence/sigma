**Definition of done (the issue's five boxes):**
1. `scan` reports every match by location and pattern line number. It exits 1 while any remain, 0 when clean, and 2 on a refusal or any `gh` failure. The known matches are shown by the orchestrator's live read-only run (H1).

3. The dry-run before/after goes only to an `--out` file outside every git work tree, with mode 0600. Stdout gets only counts and the path, `~`-relative. The goal parks with those, awaiting the owner.

## Decisions
**D1-D8, the orchestrator's decisions this plan implements** [F11]:
- **D1 Patterns.** `--patterns FILE` or env `SIGMA_LEAK_PATTERNS`; one Python regex per line; blank and `#` lines skipped; compiled case-insensitive. Refuse (exit 2, one message, no traceback) when neither is given (NO default path, not even under `~`), the file is unreadable, it yields zero patterns, a line fails to compile (its line NUMBER only), or the file resolves inside a git work tree.
- **D2 Output** never contains matched text: a hit is its location plus the pattern's line number, then a counts summary. Exit 0 clean, 1 any hit, 2 refusal, bad input or `gh` failure (a `gh` failure never reads as clean).
- **D3 `scan` surfaces,** all states: issue and PR titles and bodies, conversation comments, review comments, review bodies, release names and bodies, plus EDIT HISTORY read-only via GraphQL as a separate `history` surface, disposition manual (web UI). Truncation is a loud finding. Explicit bounded paging, a page cap that refuses, `gh` through a thin injectable wrapper with a timeout, polite pacing.
- **D4 Self-scan:** `tree` (`git ls-files --cached --others --exclude-standard`, plus commit messages reachable from HEAD) and `text` (a file or stdin).
- **D5 `rewrite`** defaults to dry-run: before/after only to `--out FILE` outside any repo, 0600, never printed; stdout is counts and the path; a machine-readable manifest; `--apply --from FILE` with compare-and-skip, paced, bounded retries; apply is tested offline only.
- **D6 Rewrite rules:** a fixed neutral replacement with no number; the span widened to the whole reference; invariants (a) no pattern left, (b) no new blocker edge (`blocker_scan.py` loaded by path), (c) no added autolink or mention token; an edit failing one becomes manual; only OWNER, MEMBER or COLLABORATOR text is edited.
- **D7** `tools/leak_refs.py`, stdlib only, no `urllib`/`http`/`socket`, the CLI shape of `tools/onboarding_control.py`.
- **D8** `docs/publish-runbook.md` (new) and a CHANGELOG Unreleased bullet; the stale BR-8 comments stay untouched (follow-up).

## RESILIENCY
- **Scan** is read-only and stateless. Any failure, timeout, page cap, budget stop, bad shape or count mismatch (per repository or per item) exits 2 with its code and endpoint; the recovery is a re-run. An unexpected exception is exit 2 `[internal]`, never a clean read.
- **Dry-run** opens its file with `O_EXCL`. A crash leaves it without its manifest line, which apply refuses; the recovery is a new dry-run to a new path.
- **Apply** is idempotent through compare-and-skip: after a crash or a lost ack the re-run skips those edits as `already applied`; an edit another writer changed is skipped as `changed since`, and the owner re-runs the dry-run for it; rate limits get bounded retries, then exit 2, and a re-run resumes. Every edit is judged alone by (a)-(d), so any subset that lands is safe.
- **Hung `gh` or git.** Every call is bounded by `--timeout`, and each page prints a stderr progress line, so a stalled run is told apart from a slow one (LIVENESS).

## SAFETY
- No default patterns path. The patterns file and the dry-run file are both refused inside any git work tree, and the probe fails closed (A4).
- Output names locations only, with no `#N` in them, `_safe` as a second belt over whole lines before any cut, and exception messages never printed.
- The dry-run file is created 0600 and never printed; the issue gets counts and its `~` path only.
- Writes happen only under `--apply --from`, only to text its live GET shows as owned and that passes the invariants, with the text on stdin.
- No background processes; no network except through `gh`.

## Risks
- **R1** The history purge is manual, one revision at a time. Apply ADDS about 60 revisions, and rename events cannot be purged at all, so "rescan zero" needs the owner's web-UI pass and, for renames, the owner's accept-or-delete decision; the dry-run counts both.
- **R2** A patterns file in a format the tool does not expect reads green. H1 must be red, or the goal stops.
- **R3** The name guards read tracked files only, so they run inside the step-10 gate, after the final commit, never before.
- **R4** GitHub may normalise `\r\n` on a write: `verify mismatch` (exit 1), never a lost edit.
- **R5** Loop writers (`sources.append_to_body`, `unpark._append_block`) could race the apply, so the runbook stops them first.
- **R6** A pathological regex in the owner's file can be slow; the stdlib has no regex timeout; documented.
- **R7** A4 refuses a patterns file in a git-managed home directory; the fix is to move the file.
- **R8** The stale BR-8 comments stay; a follow-up will be filed.
- **R9** H2 reads every commit message reachable from HEAD (24 in P3, 0 foreign `owner/repo#N` by a generic regex). A bare-slug mention the real patterns catch turns H2 red: a finding for the owner (a history rewrite before the flip), not a tool defect.
- **R10** The count cross-checks exit 2 when an item or comment is created or deleted during the walk; with loop sessions filing issues that is a re-run, never a clean. A deletion and a creation in one walk cancel out, and review and commit comments have no per-item count; the runbook's two consecutive clean scans are the second pass.
- **R11** The multiset rule sends a second copy of an existing edge to manual although no current consumer counts copies: it costs a manual item, never a phantom edge.
- **R12** (d) is conservative by construction: up to about a third of long-body edits (115 of 335 long bodies hold a `#\d` in their first 557 characters; an upper bound that assumes every hit on line 1) and over half of long-comment edits may go manual. H4 reports the real `cap-shift` count; a manual item costs the owner a hand edit, never a phantom edge.
