## Steps

1. Linux: the workflow was dispatched once from the default branch (Actions run 37187467571, commit
   `c82e3dfa7420e92465a7cf991a1dcf5166403973`). When it ends, read the run's jobs over REST, download the ten
   artifacts into an empty scratch directory under `~/.sigma-ops/`, check the jobs ran that commit, and run
   `flake_census.py aggregate` with `--os linux` and `--meta` for python, runner and the run URL.
2. macOS: ten sequential runs from a detached checkout of the same commit with the verify interpreter
   (`-n 4 -p no:cacheprovider`) through `flake_census.py run`; read its per-run exit codes and `per_run`
   counts before aggregating; `aggregate --os macos`. A run that ended abnormally is deleted and repeated
   with `--start`, never aggregated.
3. `flake_census.py combine ... --sha <the full dispatched commit>` writes
   `docs/launch/evidence/flake-c82e3dfa7420.json` (a new file; `combine` refuses to overwrite).
4. Tests (written before the evidence file is added, so they go red on the tree without it):
   `tests/test_flake_census_evidence.py` reads every `docs/launch/evidence/flake-*.json` and asserts the file
   is one real census: schema, a 40-hex `sha` whose first 12 characters are in the filename, a Linux and a
   macOS section each with `runs` 10 and 10 `per_run` entries, the classification lists present, `totals`
   that sum to `tests` over the five partition classes, `limits` present, `context` naming Python 3.12 for
   Linux, no absolute host path or secret-shaped text anywhere in the file, and at least one evidence file
   exists. Control: delete one `per_run` entry in a scratch copy, set `runs` to 9, change the filename sha,
   and see each go red.
5. `docs/launch/flake-census.md`: replace the opening claim that no result is recorded with a "Recorded
   result" section stating, from the evidence file only, the commit, the run counts per platform, what was
   found (the unstable tests listed by node id, or "none observed in 10 runs on each platform") and the
   limits (ten runs cannot prove zero; Python 3.12 only; Linux single-process and macOS `-n 4`; always-failing
   tests are reported separately and are not flaky). The doc test that pinned "no census result" is changed
   to pin the recorded-result section.
6. Filing: a real flaky defect is grouped into ONE issue, queued (`launch:next`) through `handoff.py track
   --queue queued` after `dedup.py`, never promoted; an always-failing test is reported in the doc and, if a
   real defect, the same one issue. None found means nothing is filed.
7. Early checks, `git add` new files, `loop.py verify` once, commit, PR (body edited to `Refs`), fresh code
   review, five CI legs read and copied, merge, then `record done`, which is the goal's real completion.
