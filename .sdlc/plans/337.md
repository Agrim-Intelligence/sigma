## Design

**`tools/readiness/flake_census.py` (new, stdlib only, conventions of `tools/onboarding_control.py`).**
- `run REPO --runs N --python PY --out DIR [--start K] [-- PYTEST_ARGS...]`: N sequential full-suite runs,
  `PY -m pytest tests/ -q -p no:randomly -p no:rerunfailures --junitxml=DIR/junit-<i>.xml <extra>` with cwd REPO,
  numbered K..K+N-1. Refuses (exit 2) when a target XML already exists, when N < 1, when REPO is not a directory,
  and when the pass-through args retry (`--reruns*`, `--only-rerun`, `--force-flaky`, `-p rerunfailures|flaky`), set the
  junit path, or narrow/reorder/stop the suite (`--lf`, `--ff`, `--nf`, `--sw`, `-x`, `--maxfail`, `-k`, `-m`, `--deselect`,
  `--ignore*`, `--collect-only`, `--pyargs`, and any token that is a `.py` file, contains `::`, or names an
  existing path under REPO). It also injects `-p no:flaky` beside `-p no:rerunfailures`. `per_run` counts remain the
  backstop for any narrowing this list misses, and the doc says so. Exit 0 when every run
  wrote its XML (a failing suite is data, not an error), 1 when a run wrote none, 2 on bad input.
- `aggregate INPUT... --os NAME --json OUT [--meta KEY=VALUE ...]` (INPUT = XML file or directory searched
  recursively for `*.xml`, sorted). One XML file is one run. Node id = `classname::name`, or `name` alone when
  the classname is empty (pytest's collection-error testcase has an empty classname). Outcome: any `failure`
  or `error` child = failed; else `skipped` child = skipped; else passed. A repeated node id inside one file is
  merged (failed beats passed beats skipped) and listed in `duplicate_node_ids`, never silently dropped.
  Output `{"schema": "flake-census/v1", "os", "runs", "flaky", "always_failing", "skipped_only", "missing",
  "totals", "per_run", "duplicate_node_ids", "context"}`. `flaky` = passed in at least one run and failed in at
  least one; `always_failing` = failed in every run it appears in; `skipped_only` = skipped in every run it
  appears in; `mixed_nonpassing` = never passed but has more than one non-pass outcome (failed in some runs, skipped
  in others); `missing` = absent from some run. `clean`, `flaky`, `always_failing`, `skipped_only` and
  `mixed_nonpassing` PARTITION the node set (`totals` proves it: they sum to `tests`); `missing` is an overlay, so a
  node that passed, failed and was absent from a run is in both `flaky` and `missing` by design (stated in the doc and
  tested). `per_run` is the test and failure count of each run, so a run
  that quietly collected nothing is visible. Exit 0 no flaky, 1 flaky, 2 bad input (not XML, no inputs, XML with
  no testcase at all, a testcase with no name, bad `--meta`, or two inputs with byte-identical content: a duplicated file would inflate `runs`, and two real runs
  of this suite never match byte for byte).
- `combine LINUX_JSON MACOS_JSON --sha SHA40 --json OUT`: composes the evidence document
  `{"schema", "sha", "linux", "macos", "limits"}`. Refuses unless each section is `flake-census/v1`, names its
  own OS, and has exactly 10 runs. `limits` is fixed prose: N runs observe, never prove, zero flaky tests; one
  Python version; Linux runs without xdist, macOS with `-n 4`; a skip/pass mix is not classed flaky. Exit codes
  as `aggregate`. The doc says a red Actions job is expected data (the artifact is uploaded on `!cancelled()`), not a
  failed census, and that stray `*.xml` files in a download directory count as runs, which `combine`'s 10-run check
  exposes.
- Every JSON write creates the file exclusively and refuses to replace one (`open("x")`); `--meta` keys are
  `[a-z_]+` and a value that looks like an absolute host path is refused, so evidence cannot carry one.

**`.github/workflows/flake-census.yml` (new).** `on: workflow_dispatch` only (never push, pull_request, schedule);
`permissions: contents: read`; one job, `runs-on: ubuntu-latest`, `timeout-minutes: 60`, `strategy: fail-fast:
false`, `matrix.run: [1..10]`; steps copied from ci.yml (checkout, git identity, setup-python "3.12", `pip install
pytest`), then `python -m pytest tests/ -q -p no:randomly -p no:rerunfailures --junitxml=junit-${{ matrix.run }}.xml`
and `actions/upload-artifact@v4` (`if: ${{ !cancelled() }}`, `name: junit-${{ matrix.run }}`, `if-no-files-found:
error`, `retention-days: 30`). No `gh` call, no token write, no secret.

**`docs/launch/flake-census.md` (new).** What it measures and does not; the three classes plus `skipped_only` and
`missing`; the cost of one Linux dispatch stated as an estimate (10 jobs x about 15 to 21 minutes, so about 150 to
210 Linux runner-minutes) and macOS as local; the two gestures (dispatch and download; local `run`), the
`aggregate` and `combine` commands; the control with its copy-and-run gesture; limits. States that no census
result is recorded by this change.

**`tests/fixtures/flake_census/` (new).** Four hand-made JUnit files: `a` passes 3/3, `b` fails 3/3, `c` passes
twice and fails once, `d` absent from one file (plus a skipped-only node and an `<error>` node).
