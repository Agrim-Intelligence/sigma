## Done

Grandchild of a timed-out drive is dead on return on macOS and Linux CI; the call is bounded by
timeout + grace + reap; Windows refuses loudly; red run recorded.

## Plan-review findings (P4, adversarial; folded in before any edit)

- **Regression created by the fix itself:** a new session takes the model OUT of autowatch's own
  process group, so a group-addressed signal to the tick (Ctrl-C, terminal SIGHUP, a supervisor's
  `killpg`) no longer reaches the model — before, it did. Fix: any exception escaping the wait
  (KeyboardInterrupt, SystemExit from a caller's handler) terminates the group before re-raising;
  and, in the main thread only, SIGTERM/SIGHUP whose handler is still `SIG_DFL` are trapped for the
  duration of the drive, the group is terminated, the previous handler restored, and the signal
  re-delivered to self so the tick still dies by it. A caller's own handler is never replaced.
  Control: a real tick-like subprocess is SIGTERMed mid-drive; its grandchild must be gone.
- `Popen.__exit__` waits unbounded; safe only because the direct child is a session leader (cannot
  `setsid` away) and is SIGKILLed by the group kill. The bounded drain covers an escaped pipe holder.
- Group liveness uses `os.killpg(pgid, 0)` with `pgid = proc.pid` (no `getpgid` race after reap);
  `proc.poll()` each iteration so the direct child's own zombie does not keep the group "alive".
- Tests monkeypatch the grace constant so the SIGTERM-ignoring case stays ~2s.

## Repair cycle 1 — author-blind review REQUEST-CHANGES

1. HIGH: SIGKILL of the tick, or `killpg` of its group, left the model running (the new session put
   it out of reach). Lifeline: a sentinel in its own session holds the read end of a pipe whose
   write end only `_run_drive`'s process holds; it receives the driven group id, and on EOF without
   `done` runs SIGTERM / grace / SIGKILL against that group. No sentinel -> no drive.
2. MEDIUM: a second signal (SIGINT) during termination aborted the escalation. `_terminate_group`
   and the lifeline release run with INT/TERM/HUP blocked via `pthread_sigmask`.
3. LOW-MEDIUM: a caller's own SIGTERM handler disabled the trap. Now trapped unless SIG_IGN or
   non-Python; after the group is terminated the caller's handler is restored and the signal
   re-delivered to it.
4. LOW: trap setup moved inside the `try`, recording each saved handler as it is installed.
Each fix gets a new test seen red against the round-1 code, then a control removing the fix.

## Repair cycle 2 — second author-blind review REQUEST-CHANGES

1. F1: a trappable signal between the model's spawn and the sentinel learning its group orphaned
   the model. The trap HOLDS (records only) through that window and raises right after the
   handoff, inside the try that terminates the group. A signal mask was tried first and rejected:
   children inherit it, so the model started with SIGTERM blocked (caught by the new
   graceful-SIGTERM test). SIGINT is now trapped too, so Ctrl-C is covered by the same hold.
2. F2: a signal in the final cleanup escaped as `_DriveSignalled` and left the raise-once handler
   installed. Cleanup runs under `_SignalsDeferred`; pending signals reach the restored handler.
3. F3: deferral is per-thread; documented as single-threaded only, with the lifeline as backstop.
4. F4: new test that the grandchild's own SIGTERM handler runs (graceful step of the escalation).
5. F5: CHANGELOG states which test passes on main and why.

## Repair cycle 3 — third author-blind review REQUEST-CHANGES

1. A signal between the lifeline swap and its release leaked the write end (sentinel lives on and
   later sweeps a reaped group id). Swap + release now share one `_SignalsDeferred` section, and the
   sentinel gets `done` after any completed termination, not only a normal finish.
2. The mask inside `_terminate_group` guarded nothing a test could see: the raise-once trap already
   absorbs a second signal on whatever thread the kernel picks (Python runs handlers on the main
   thread). Removed; docs no longer claim a single-threaded caveat. The second-signal test is
   guarded by the raise-once property (control: raise on every signal).
3. A signal held during spawn was swallowed when the sentinel was already gone: `_release_hold`
   now runs on that refusal path too.

## Repair cycle 4 — fourth author-blind review REQUEST-CHANGES

Root cause shared by its F1-F4 and by every earlier signal finding: the trap handler RAISED, so
every bytecode boundary in the cleanup was a window for its exception to escape, and a
per-thread mask cannot close those windows in a multithreaded caller. Redesign: the handler only
records (`received.append`); the drive waits in `DRIVE_POLL_SECONDS` slices and terminates the
group when it sees a recorded signal; afterwards handlers are restored and EVERY recorded signal
re-delivered in order (fixes the lost second signal). `_SignalsDeferred`, the hold flag and
`_DriveSignalled` are gone. The sentinel always gets `done` from a live caller (only the caller's
death leaves a bare EOF), guarded by a new test that a normal finish's leftovers survive.
F5: tick-level test that the refusal text reaches the ledger.

## Repair cycle 5 — fifth author-blind review REQUEST-CHANGES

1. A re-delivered signal that raised (KeyboardInterrupt) dropped the ones after it: delivery is now
   a `finally` chain (`_deliver_each`). New test: Ctrl-C then SIGTERM, caller catching
   KeyboardInterrupt, must die by SIGTERM.
2. Documented residuals (low): SIGKILL between a normal finish and `done` lets the sentinel sweep
   the finished model's group; a caller thread with SIGTERM blocked passes that mask to the model
   (graceful step lost, SIGKILL after grace still applies); repeated signals re-delivered once.

## Repair cycle 6 — sixth author-blind review REQUEST-CHANGES

1. A Ctrl-C landing the instant SIGINT's handler was restored (caller catching it) skipped the rest
   of the restore and every re-delivery. Restore is now a `finally` chain ending in delivery.
2. The bounded post-SIGKILL drain had no test: new setsid-escapee-holding-the-pipe test.
3. The pre-spawn signal check had no test: new test that a signal recorded before the spawn
   means no model is ever spawned.
4. `docs/privacy.md` cited the old `autowatch.py:621`; repointed at the model Popen.
