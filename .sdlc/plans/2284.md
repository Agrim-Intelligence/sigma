## Design decisions (each settles a research risk)
1. Risk 1, the sdlc dir token: the command prints the literal `.sdlc`, never the `sdlc_dir` argument, because `brief()` can receive a goal worktree's `.sdlc` and `reviewer.py check` refuses a brief that names that path. Printing `.sdlc` matches the documented gesture, which runs from the main checkout.
2. Risk 2, command form: the brief names scripts bare (`acceptance.py check`, `reviewer.py ...`), so the new text is `reuse.py rerun .sdlc <goal>`, with no `python3` and no path.
3. Risk 3, quoting: the goal goes through `shlex.quote`, so `2284` prints bare and a goal with a space or quote is single-quoted. The test pins both forms.
4. Risk 4, the checker: added lines start with `Re-run` and `A `/`Code`, never `-` or `+`, so the `_LEAK` pattern in `breaker.py` does not match; a test runs `reviewer.py check` on the brief.
5. Risk 5, fail-open: `_has_reuse` calls `_load("reuse").is_new_format(text)` using the existing `_load` in `review_context.py` (no second loader copy) and returns False on any exception, so a broken `reuse.py` leaves the brief byte-identical. It does not look for the heading itself.
6. Gate: `if dossier and phase in _DOSSIER_PHASES and _has_reuse(dossier)`. `plan-review` gets the plain `rerun` line plus the FIX-FIRST sentence; `code-review` and `pr-review` get the `--new-since-research` line plus the duplicate-code sentence. The text is the issue's, word for word, with `<sdlc_dir>` replaced by `.sdlc` and `"<goal>"` by the quoted goal.
7. The builder never runs `reuse.py`; it only prints the command. Cost is one string test on a dossier already in memory, so 10x and 100x goals change nothing; the brief grows by at most two lines.
