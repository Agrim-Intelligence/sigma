## Decisions (settled here, binding for implementation)
- **Documented gesture:** `python3 evals/regression/check.py <record> <properties.json>`. Every behavioural test runs
  exactly that argv as a subprocess (`sys.executable`, no extra flag).
- **Exit codes:** 0 every property PASS (soft NOT EVALUABLE allowed); 1 any FAIL or any hard property whose source stream is
  absent; 2 REFUSAL (printed `check.py: REFUSED: <reason>` on stderr, nothing on stdout) for: missing or unreadable file,
  malformed JSON, record `schema` not `sigma.regression-run/v1`, record without `streams`, malformed property list
  (duplicate id, unknown family, unknown check operator, missing field), and a property naming an agent-writable kind.
  2 is deliberately distinct from 1 so a broken input is never read as a product regression. Unexpected exception: 1 plus one
  `check.py: failed: ...` line, as `record.py` does.
- **Malformed record = exit 2** (a record that is valid JSON but has the wrong schema or no `streams` object). A record that is
  well-formed but has absent streams is NOT malformed; absence is data (the `present` flag).
- **Hard flag:** each property has `"hard": true|false`. Absent source + hard = NOT EVALUABLE and exit 1; absent source + soft
  = NOT EVALUABLE and exit 0. NOT EVALUABLE is printed with that exact word in both cases so output never hides it.
- **How each mutation exits 1 (asserted, not left open):**
  - M1 plan-review verdict dropped: the `plan_review_verdict` stream becomes `present:false`, so the hard property
    `process.plan_review_verdict_approved` prints **NOT EVALUABLE** and exits 1.
  - M2 one phase end dropped (the `review` end, removed from both `phases[]` and the matching `kind=phase,state=end` action-log
    row): the action-log stream is still present, so hard `process.phase_ends_recorded` prints **FAIL** naming `review`.
  - M3 review marker dropped (`marker_in_store:false`, `review_posted` emptied, stream `present:false`): hard
    `process.review_marker_in_store` prints **NOT EVALUABLE** and exits 1.
  Each mutated copy must leave EVERY OTHER property PASS (exactly one thing deleted, exactly one property moves), asserted.
- **Process properties read INTERNAL action-log rows only** (`streams.action_log.rows`), never `phases[]`, so M2 is
  observable. A property carries `kinds` (list); the checker validates each against `INTERNAL_KINDS` loaded through
  `record._load_scripts("actionlog")` (the same object, never a copy). Naming `agent_dispatch`, `note`, `file`,
  `model_choice` or `agent_done` is a REFUSAL (exit 2), tested with a real agent kind taken from `actionlog.AGENT_KINDS`.
- **D-5:** no retro writer. The retro property is `process.phase_ends_recorded` covering all six `phase_gate.REQUIRED`
  phases, including `retro`.
- **D-8:** the three mutations above are the proposal in the design, implemented as stated; owner confirmation is still
  open on #809 and is noted in the PR body, not assumed.
- **Fixture reproducibility:** a new test helper `tests/regression_fixture.py` (new, shim, not a test file; precedent
  `tests/gqlfake.py`) builds a synthetic run directory with a fixed directory name `run` and fixed timestamps, runs
  `record.py build` on it as a subprocess, and exposes pure functions `mutate_drop_verdict`, `mutate_drop_phase_end`,
  `mutate_drop_marker` that transform the green record dict. Committed fixtures are written by that helper through
  `record.write_atomic` (an existing write-surface row). Regenerate-and-compare tests make the committed copies unable to rot.
  Documented regenerate gesture (stated in the helper docstring): `python3 tests/regression_fixture.py evals/regression/fixtures`.
- **Property ids are a contract for slice 4** (the driver feeds real records to `check.py`); they are listed in step 3 and
  never renamed casually.

## Property list (properties.json, new)
Each entry: `id`, `family`, `hard`, `stream` (record stream consulted), `check` (closed operator set), operator arguments,
`why` (one line). Closed operators: `log_row` (an INTERNAL-kind row matching fields exists), `log_phase_ends` (every named phase
has a `phase`/`end` row), `stream_equals` (stream field equals value), `stream_nonempty`, `sum_positive` (tokens or cost > 0),
`subset_of` (commit order), `no_abs_paths`, `kinds_internal`, `caveat_present`.

| id | family | hard | reads |
|---|---|---|---|
| `outcome.goal_merged` | outcome | yes | action_log `merged` row |
| `outcome.verify_exit_zero` | outcome | yes | verify `exit == 0` |
| `outcome.goal_commits_on_main` | outcome | no | commit_order: every goal-branch commit is in main |
| `process.phase_ends_recorded` | process | yes | action_log `phase`/`end` rows for research, plan, plan_review, implement, review, retro |
| `process.plan_review_verdict_approved` | process | yes | plan_review_verdict `present` and `verdict == approve` |
| `process.review_marker_in_store` | process | yes | review_evidence `present` and `marker_in_store is true` |
| `cost.tokens_measured` | cost | no | tokens `present` with at least one measured phase |
| `cost.spend_positive` | cost | no | sum of `by_phase[*].cost_cents` > 0 |
| `quality.test_first_passed` | quality | no | verify `test_first_passed is true` |
| `quality.plan_and_research_present` | quality | no | plan and research streams `present` with a `sha256` |
| `safety.only_internal_kinds` | safety | yes | every action_log row kind in INTERNAL_KINDS |
| `safety.no_absolute_paths` | safety | yes | no string in the record is an absolute path |
| `safety.caveats_present` | safety | yes | record `caveats` carries the call-existence caveat |

Wording constraint: output and `why` text say "phase end row recorded", never "phase completed", because the record's evidence
class is call-existence (research risk "call-existence caveat").

## Risks
- **Guard that cannot fail on the documented gesture:** every behavioural test uses the exact two-argument argv; the control table
  (step 8) is run on the whole file with no flag the docs omit. No test imports `check.py` functions for its pass/fail verdict.
- **M2 unobservable if process properties read the journal side:** pinned by C4 and `test_process_property_ignores_journal_derived_phases`.
- **Mutation 1 and 3 exit 1 via NOT EVALUABLE, not FAIL:** intended and asserted by word; a reader of the PR must not expect "FAIL".
- **Fixture rot and non-determinism:** record.py field changes or a differently named temp dir change the bytes; the helper fixes the
  run dir name `run`, the timestamps, and the goal; regeneration tests catch drift. Any absolute path would also trip
  `safety.no_absolute_paths` on the green record.
- **Hand-built synthetic run is not a live run:** a green record proves the checker's logic, not that Sigma behaves; the CHANGELOG and
  README say so. Slice 4 supplies a real record and may expose property mis-calibration (property ids are the contract).
- **Call-existence overclaim:** PASS on phase ends proves `phase_report.py end` ran only; wording kept to "recorded".
- **Write-surface / inventory surprise:** expected zero new rows; step 9 proves it. A new inventory row would need the exact scanner
  gate wording, not an edit to fit.
- **Scalability:** O(properties x action-log rows), the record held in memory (same ceiling as record.py, unmeasured at 10x/100x
  records); `no_abs_paths` walks every string once. Nothing grows: read-only, no state file.
- **Resiliency:** stateless; a crash leaves nothing to repair. A malformed input is a loud exit 2, never a silent pass.
- **Owner doubt D-8 still open:** the three mutations follow the design's proposal; if the owner changes them, only the mutator
  functions and three fixtures change.
