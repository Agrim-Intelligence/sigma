## Interfaces (fixed before coding)
- `is_sealed(sdlc_dir, stem) -> bool`: `os.path.lexists(seal_path(...))`; an unsafe stem (`SealRefused("bad-files")`) returns False (passthrough decision only; work.py already refuses unsafe stems in `record_path`). Zero git calls, zero pytest.
- `check_tree(root, sdlc_dir, stem, rev="HEAD") -> {"sealed": bool, "problems": [{"path","kind"}]}`, same shape and kinds as `check`, read-only. Reads the COMMITTED tree: `git ls-tree -r -l -z <rev> -- tests/acceptance/<stem>` (via `_git`), mode must be `100644` else `differs`; size from `-l` compared with record `bytes` first (a mismatch is `differs` without reading, bounding memory); then `git cat-file blob <oid>` read as BYTES through `_git_bytes` (text mode or work.py `_run`'s `.strip()` would alter the trailing newline and the sha256) and sha256-compared; extra tree paths are `unexpected` unless the SAME pure name predicate `is_debris_name` (one rule; `is_debris` is rewritten to lstat then call it, so there is no second spelling) says debris: a regular blob `__pycache__/<n>.pyc` directly under a `__pycache__` dir, or any path under `.pytest_cache/`; `__pycache__/sub/x.pyc`, `__pycache__/x.txt` and any non-regular mode are `unexpected`. Mode alignment: `check()` gains an exec-bit test (`mode & 0o111` -> `differs`) so commit and pr report the same set; `remedy` names `chmod 644` for mode-only. CONTRACT CHANGE of the shipped `check()` (a legitimately 0755 sealed file is now `differs` forever): stated in the `check` docstring and the CHANGELOG line; slice 4's `seal()` must write 0644 (noted in the docstring as its obligation; the `chmod 644` remedy is satisfiable because the record hashes bytes only). Filters: NO up-front refusal (an up-front `text=auto`/`autocrlf=input` refusal would wedge every sealed goal in common adopter repos, for which LF blobs are byte-identical to the working file). `check_tree` just runs the sha compare. ONLY on a blob-sha or size mismatch does it consult `git check-attr -z text eol filter ident working-tree-encoding -- <path>` and `git config --get core.autocrlf` and, if any is set, appends the explanation to that `differs` problem (`stored blob differs from the working bytes; text/eol/filter attributes or core.autocrlf may be converting it; lever: set `-text` for the sealed dir in .gitattributes, or park`). Stated limits (also in the registry condition): `check-attr` reads `.gitattributes` from the worktree/index, not `<rev>`, and global attributes (`core.attributesFile`) are consulted by git but a differing global file on another machine is not seen. Tests: `* text=auto` with LF content PASSES (no problem); `* text eol=crlf` (CRLF-converted blob) is `differs` WITH the explanation; `core.autocrlf=input` with LF passes. a symlink or non-tree at the dir path itself is `differs` on that path; absent or corrupt record is `record` (as `check`).
- `source_commit(root, path, sha256, cap=200) -> str|None`: the one lookup behind every `differs`/`missing` remedy. Walks `git log --format='%H %T' -n <cap> -- <path>`-style history, newest first, hashing the blob (`git cat-file blob <c>:<path>`, bytes) only for commits where the blob oid at `<path>` (`git rev-parse <c>:<path>`, via one `git log --raw`/`ls-tree` listing, no per-commit subprocess for unchanged oids) differs from the previous one, and returns the first whose sha256 equals the record's. GLOBAL budget: `remedy` threads one shared counter (`budget=200` blob probes TOTAL per refusal, not per path, passed down from the wrapper); exhausting it reports `not found within the probe budget` for the remaining paths. Cap is a named ceiling, stated in Scalability. Needed because HEAD itself may be the tampered commit (a raw `git commit` caught at `pr`), where `--source=HEAD` rewrites the same bytes, and a file missing at HEAD errors.
- `remedy(problem, root, rec) -> str`: `differs`/`missing` -> if `source_commit` finds `<c>`: `git -C <worktree> restore --source=<c> --staged --worktree -- <path>`; if none: say the sealed bytes were never committed (or are past the cap) and name ONLY the park lever. Same rule on the commit side and the pr side (no `HEAD` assumption anywhere); `unexpected` -> delete `<path>` (`git rm -f` if tracked; restore cannot remove it); mode-only -> `chmod 644 <path>`; `record` -> park the goal.
