## 1. What changes, in one paragraph

`observe()` adds `--junitxml=<TemporaryDirectory>/red_green.xml --junit-prefix=` to its one pytest run. The short summary's `FAILED` lines still decide membership, but the ` - reason` after the node id is no longer read. A node earns an assertion red only when two things hold:
- it is in that `FAILED` set;
- its own unique JUnit `<testcase>` has exactly one outcome child, a `<failure>` whose `message` attribute matches `re.match(r'(?:AssertionError|assert)\b')`.

`<error>` (setup/teardown) and `<skipped>` never credit. Captured output is never read. It appears in the text report and in `<system-out>`/`<system-err>`, never in `message`. `_split_traceback_assertions` and the summary-reason crediting path are deleted. `PROVENANCE` stays `planned-pytest-v1`. Green proof (PASSED/XFAIL/XPASS membership) is unchanged.

## 2. Decisions (and where this deviates from the direction)

- **D-1: JUnit decides the kind, the summary decides membership** (dossier option c). Adopted as directed.
- **D-2: Drop the summary-reason crediting path** (Q-2). That reason depends on width and on `CI` (TD-4). With the path gone, `test_ci_summary_text_cannot_forge_a_red` passes. It is red on the pre-fix code.
- **D-3: Keep `PROVENANCE = 'planned-pytest-v1'`** (Q-1). Bumping it would void every in-flight red fleet-wide (`red_green.py:199,222`).
- **D-4: Fail-closed scopes.**
  - **Per node.** A failed node with no testcase of its own credits nothing: a key two planned nodes share, a key written 0 or ≥2 times, or anything other than exactly one outcome child. ≥2 happens with `record_xml_attribute`, and with pytest's own call failure plus teardown error, which it writes as two testcases (measured, `teardown.py`). **Small addition:** `error` gains `assertion attribution skipped N failed node(s) without exactly one JUnit testcase (...)`. Otherwise a teardown error would silently cost a genuine red. That is a **behaviour change**: the pre-fix parser credited assert-then-teardown-error, and the new code does not (measured both). It fails closed, and it says so.
  - **Whole run (deviation, added).** A testcase whose key no planned node owns means credit nothing for the run, and `error` gains `assertion attribution refused: a JUnit testcase matches no planned node`.
    - *Why:* the directed per-key rule alone is beaten by two renames. The victim renames itself away (`record_xml_attribute("name", "test_elsewhere")`) and the forger renames itself onto the victim. The forger's assertion testcase is then the victim's unique key.
    - *Measured:* mutation M4 (this check removed) credits the RuntimeError victim.
    - *No measured real configuration trips it:* our `--junit-prefix=` overrides an addopts `--junit-prefix=PFX`. `junit_family = xunit1`, `junit_logging = all`, `-x` and an addopts `--junitxml=` keep keys intact (measured, `hostile.py`).
  - **Whole run.** XML missing or unparseable means credit nothing, and `error` gains `assertion attribution unavailable: pytest wrote no readable JUnit XML (is junitxml disabled, e.g. -p no:junitxml in addopts or PYTEST_ADDOPTS?)`. The XML is read only when `returncode == 1` and the FAILED set is non-empty, so green proof never depends on it.

- **D-6: #414** (Q-4). The PR body says `Refs #414` and maps its three done-when items (§6). Closing it is left to the retro or the orchestrator, because it is a separate goal with its own assignee.

## 5. The five properties

- **RELIABILITY.** Every behaviour claimed here was run end to end with real pytest (9.0.2, plus 8.4.1).
  - Red, fix, green, `refusal`: on `flip/`, the installed 1.0.2 gate recorded the 8 reds against pre-fix code. With the fix copied in, the 1.0.2 green `observe` passed and `refusal()` returned `''`.
  - The fixed `red_green.py` itself also credits all 8 listed nodes (measured `gatenew.py`), so the gate keeps working once this ships.
  - Not verified:
    - pytest 7.x: not installed, and installing it needs a download. From the pytest source, `append_failure` writes `reprcrash.message` across 7-9.
    - pytest-xdist in a target's addopts: not installed locally. CI installs it, but the inner runs never pass `-n`.
    - pytest-rerunfailures.
  - In each of those, a missing or odd XML lands in the fail-closed paths. No path credits without a unique testcase whose single outcome is an assertion `<failure>` for a node pytest also listed as FAILED.
- **SCALABILITY.**
  - The XML grows with nodes × failure text; captured output is excluded unless `junit_logging` is set.
  - Measured with a logging test file where half the tests fail: XML 5,672 B vs stdout 9,189 B at 25 nodes, and 55,379 B vs 90,199 B at 250 nodes. Parse took 0.3 ms and 1.1 ms. `_junit_assertions` is O(testcases + nodes) dict work.
  - At 10x/100x nodes (2,500/25,000) the XML stays below the `proc.stdout` already held in memory, about 0.6× by the ratio above. The 2,500-node timing run was aborted on a loaded shared machine, so 10x+ is extrapolated, not measured.
  - Run time with versus without `--junitxml` at 250 nodes, interleaved, 6 pairs: min 1.731 s vs 1.782 s, median 2.215 s vs 2.564 s. That is no overhead measurable above noise.
  - `MAX_SELECTORS = 25` bounds selectors, not nodes. A file selector collects every node in it, which is unchanged.
  - No new chokepoint: one temp dir per `observe()`.
- **RESILIENCY.**
  - Each failure has a stated outcome: missing or unparseable XML, foreign key, non-unique testcase. Each credits nothing and puts the reason in `error`.
  - The next `loop.py verify` re-observes from scratch. Witness rows are append-only, so extra rows are harmless.
  - The temp dir is removed by the context manager on return and on every exception. It leaks into `$TMPDIR` only if the process is SIGKILLed mid-run, and then holds one XML.
  - New failure mode: `TemporaryDirectory()` raising `OSError` (unwritable or full `TMPDIR`) makes `observe()` return `{'passed': False, 'error': ...}`. It fails closed, and it also blocks green until `TMPDIR` is fixed.
- **SAFETY.**
  - No new process: still one collect and one run.
  - The XML lives outside the repo, so the worktree content fingerprint is unchanged. No secrets are involved.
  - Parsing uses stdlib `xml.etree.ElementTree`; `defusedxml` is not a dependency and is not needed here. The XML comes from the pytest process `observe()` launched. Test-controlled text, such as messages, names and captured output, reaches it only as escaped attribute or character data, so a test cannot inject a DOCTYPE or entity. ElementTree resolves no external entities. The bundled expat (2.7.4 under Python 3.13.4 and 2.8.5 under 3.12.15 here; ≥ 2.4.1 is needed) bounds entity expansion.
  - It refuses loudly rather than crediting weakly in every unknown case.
- **LIVENESS.** No long-running component. The reasons go into the persisted verify evidence (D-7). F-2 covers the console gap.
- **Host-agnostic.** Pure Python in `red_green.py`, reached through `loop.py verify` and `work.py pr` on every host. No hook is involved.

## Appendix E: `CHANGELOG.md`, the first bullet under `## Unreleased`

```markdown
- **Planned-test reds are read from pytest's JUnit XML (#956; meets #414's done-when).** Before, `red_green.observe` dropped every red in a run once any test's report carried a `Captured stdout/stderr/log` section, a passing test's included, whenever pytest had trimmed the `FAILED` line's reason. At 80 columns that trim hits node ids over 61 characters, which the research measured as 92% of this repo's 11,187. The gate could then be passed only with `--no-tests`.
  - Its one pytest run now writes `--junitxml` into a temporary directory outside the repository, with `--junit-prefix=`. A node earns an assertion red only when it is on a `FAILED` summary line and its one JUnit testcase holds a single `<failure>` whose message starts `AssertionError` or `assert`.
  - Captured output, terminal width (`COLUMNS`) and `CI` no longer decide a red.
  - The text parser is removed, and with it two false credits it gave: a RuntimeError reported beside an over-72-character test name, and an `AssertionError` line inside a RuntimeError's own message. Its `-s` and CI-summary forgeries go too.
  - Setup and teardown errors never credit. These credit nothing and say why in the verify evidence's `test_first.error`:
    - a failed node without exactly one testcase of its own, including assert-then-teardown-error, which used to count;
    - a testcase no planned node owns (`record_xml_attribute`);
    - a missing or unreadable XML (`-p no:junitxml`).
  - Provenance stays `planned-pytest-v1`, so reds already recorded stay valid.
  - Verified with pytest 9.0.2 and 8.4.1. Not verified: pytest 7.x, and pytest-xdist in a target's addopts.
```
