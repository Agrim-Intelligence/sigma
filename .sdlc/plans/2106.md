# Plan: #2106 — a verify held for a literal `-n N` must not record loop.py's footprint as a cost

Lane: small. Plan-review: one pass (below).

## Cause
`resource_verify.run` returns the literal-count hold from inside its `try`; the `finally` calls
`lease.release`, whose `_finish` measures the lease pid (the caller) into the `verify` ring and `verify_run`.

## Change
1. `resource_lease.discard(lease_id, env=None)`: under admit.lock, unlink the lease file, log a `discard` event
   (id, kind, no peak), record nothing in any ring. False when the lease is unknown or the lock stayed busy.
2. `resource_verify.run`: the literal-hold path discards the lease instead of releasing it. Every path where a
   command ran (including the shed hold) keeps `release`.
3. `docs/configuration.md`: the hold sentence says a hold leaves the learned cost unchanged.
4. `CHANGELOG.md` Unreleased entry; `docs/parallelism.md` if it describes the hold's records.

## Tests (`tests/test_resource_verify_2106.py`, seen red first)
byte-for-byte `observed.json` after a hold (AC-1); six holds of `echo ran -n 2` on a faked 15.7/15.2 GiB machine,
none runs (AC-2); a ran verify still records `verify` and `verify_run` (AC-3); no lease file and no reservation
against the next admit (AC-4); waiting record kept (#1768); `discard` unit tests (event, unknown lease).
Controls: each clause broken alone (see the file docstring).

## Plan-review (self, adversarial)
- Crash between admit and discard leaves the lease; it expires by ttl/stale reclaim, which calls `_finish` with
  `reclaimed` — unchanged and out of scope; the pid is the live caller so it is not reclaimed until it exits.
- An unlink failure inside `discard` must not raise out of the hold path: mirror `_finish` (OSError swallowed).
- Lock busy: `release` returns False and the file stays until ttl; `discard` does the same (documented, bounded
  by `ttl = timeout + 60`).
- Not measured: a real two-worker pytest run; the machine is faked through the lease's own sample seam.
