## Decisions (made, not open)
- **Independence**: stdlib only (`fcntl` guarded, `json`, `os`, `re`, `secrets`, `signal`, `threading`, `time`,
  `datetime`, `decimal`, `contextlib`, `pathlib`). No import of `record.py`, `check.py` or any slice-1 file. No
  `subprocess`, `socket`, `urllib`, no environment read, no credential read. No module-level side effects. Python
  3.10-floor syntax (no `datetime.UTC`, `tomllib`, `ExceptionGroup`). The ledger directory is passed in; no default
  path here (the entrypoint slice picks it).
- **Money**: Decimal. Inputs accepted as `str`, `int` or `Decimal`; `float`, `bool`, NaN, infinity, negative, zero cap,
  zero or negative requested belt, and non-numeric strings are refused with `LedgerRefusal`. Rows carry amounts as
  decimal strings (`"0.40"`, formatted with `format(d, "f")`), never JSON floats, so sums are exact and portable.
- **Row schema** (one JSON object per line, UTF-8, `sort_keys`, compact separators, one `\n` terminator):
  `{"kind":"open","id":"<16 hex>","belt":"<dollars>","t":"<YYYY-MM-DDTHH:MM:SSZ>","pid":<int>}` and
  `{"kind":"settle","id":"<16 hex>","spent":"<dollars>","t":"<...Z>"}` plus optional `"reason":"signal"|"orphan"|"exit"`
  on a settle. `pid` is diagnostic only, never used for correctness. `id` is `secrets.token_hex(8)`.
- **File naming**: `<ledger_dir>/spend-YYYY-MM.jsonl` where YYYY-MM is the UTC month of the `open` row's `t`. Lock file
  `<ledger_dir>/spend.lock`. The `settle` goes to the SAME month file as its `open` (the `Reservation` handle carries
  the month), so a run crossing midnight UTC on the 1st never strands an unsettled open in one file and a settle in
  another. Files `0o600`, directory `0o700` when the module creates it. Old months are never read by `reserve`, never
  deleted by the module (no unlink or replace in the module at all).
- **Lock**: `fcntl.flock(fd, LOCK_EX | LOCK_NB)` polled against a `time.monotonic()` deadline with a 0.05 s sleep;
  `lock_timeout_s` default 5.0 (the critical section is a read plus one fsynced append, milliseconds; derived from that,
  not copied from `feature_judge`'s model-latency figure). Idiom copied, not imported, from
  `skills/sigma-loop/scripts/feature_judge.py`, with ONE deliberate inversion: that code fails OPEN when `fcntl` is
  missing or the lock file cannot be opened; this module fails CLOSED. `fcntl is None` (non-POSIX) raises
  `LedgerRefusal("unsupported-platform")` at first use, import never fails; lock file unopenable raises
  `LedgerRefusal("lock-unavailable")`; timeout returns `NotRun(code="lock-timeout")`; never proceeds unlocked.
  The kernel drops a `flock` on process death, so a dead holder leaves no stale lock.
- **reserve**: under the lock, read the current month file fully, compute `counted`, `belt = min(requested, cap -
  counted)`; if `belt <= 0` return `NotRun(code="budget", counted, cap)` writing nothing; otherwise `os.open(path,
  O_WRONLY|O_APPEND|O_CREAT, 0o600)`, ONE `os.write` of the whole line, `os.fsync(fd)`, close; when the file was just
  created also fsync the directory fd. Only then return `Reservation(id, month, belt)`. If write or fsync raises, no
  handle is returned (`LedgerRefusal("write-failed")`). `reserve(requested_belt, run_id=None, now=None)`: `now` is an
  aware UTC `datetime` so month rollover is tested without a clock patch.
- **settle**: `settle(reservation, spent, reason=None)` appends a `settle` row to the reservation's month file under
  the lock (it need not read the file). Idempotent in effect: the reader ignores a second settle for the same id and
  reports it.
- **Counted spend rule** (reader, one pure function, fully unit-testable): per id, an `open` with no `settle` counts its
  full belt; an `open` with a `settle` counts `spent` as written (an overshoot above the belt counts as `spent`, since
  overshoot is real; a lower `spent` frees budget); an unparseable or missing `spent` counts the full belt. A
  settle can only replace the count of ITS OWN open; an orphan settle (no open) contributes zero and is reported; a
  duplicate settle is ignored and reported. The month's counted spend is the sum.
- **Corrupt line = full cap**: any line that is not valid UTF-8 JSON, is not an object, has an unknown `kind`, a missing
  or ill-typed field, a non-decimal amount, an `open` whose `t` month differs from the file name, a blank interior
  line, or is a torn final line (no newline), sets that month's counted spend to the FULL cap. The next belt is then
  zero, so the result is `NotRun(code="ledger-corrupt")` with a report naming file, line number and reason, never the
  line content. This is the conservative superset of the design ("corrupt trailing line") and the acceptance ("a corrupt
  line"); stated in the docstring with the blast radius (a whole month stops until repaired) and the lever (repair or
  remove the named line by hand, or append a valid `settle` via `settle_orphan`).
- **Belt clamp**: `belt = min(requested_belt, cap - counted)`; `belt <= 0` is `NotRun(code="budget")`. Exact-zero is NOT
  RUN. A `settle` lowering spend frees budget on the next call.
- **Signals, no self-deadlock** (research section 2 hazard): `flock` belongs to the open file description, so a second
  `os.open` of the lock file in the SAME process conflicts with the first. Therefore the handler NEVER takes the lock.
  `reserved(...)` (context manager) installs, only on the main thread, a SIGTERM and SIGHUP handler that only raises
  `LedgerSignal(BaseException)`, in the `bench._unwind_on_signals` idiom, and restores previous handlers in `finally`.
  The exception unwinds out of any locked section (the lock is released in that section's `finally`), and only then does
  the context-manager `__exit__` settle. Cases: signal before the open row is written (nothing to settle); signal after
  the fsync but before `reserve` returned (`reserve` catches `BaseException` AFTER releasing the lock, settles the id at
  full belt with `reason="signal"`, re-raises); signal inside `settle`'s critical section (the lock unwinds, `__exit__`
  retries the settle once; duplicates are tolerated by the reader). On any abnormal exit (`BaseException`, so Ctrl-C is
  covered too, said in the docstring and NOT claimed tested) the unsettled run settles at the FULL belt, fail closed,
  because a killed-but-spending `claude` could outlive `live.py` until the launcher deadline. A normal exit without a
  caller `settle` is treated as abnormal (settle at full belt, `reason="exit"`).
- **Test seam**: a module-level `_hook_in_critical_section = None` called with a stage name inside the locked section,
  so a test can deliver SIGTERM to its own process while the lock is held. Documented as test-only.
- **Operator lever (polite, no CLI)**: `settle_orphan(ledger_dir, month, run_id, spent)` appends a `settle` with
  `reason="orphan"` for a known-dead unsettled `open` so a human need not hand-edit JSON. Ships now; tested once.
- **Docstring (module top, documents the interface)**: purpose; the API (`Ledger`, `Reservation`, `NotRun`,
  `LedgerRefusal`, `LedgerSignal`, `reserve`, `settle`, `reserved`, `settle_orphan`); row schema; file naming; counted
  rule; corrupt rule and lever; clamp; signal behaviour and the same-process lock hazard; non-POSIX refusal; recovery
  table; and the explicit note: "A lost hosted runner is defeated by this local file: the VM's disk is gone and the
  ledger forgets the belt. Job-level reservation belongs to the workflow goal (D-4 of story #810, carried open to
  #819); this module does not and cannot close it." Also states: cap is per ledger home (two machines each believe they
  hold the whole cap); restoring an older month file under-counts; old months are retained, never pruned.
- **Write-surface inventory**: `tools/readiness/write_surface.py` is blind to `open(...)`, `os.open`, `os.write` and
  `os.fsync` (measured in research, section 3) and sees `os.makedirs`/`mkdir`/`os.replace`/`unlink`. So the module
  creates the directory in exactly ONE helper (`_ensure_dir`, `os.makedirs(..., exist_ok=True, mode=0o700)`) and uses no
  replace or unlink. That yields one `fs-write` entry in `docs/launch/write-surface.json`; its exact fields come from
  running `python3 tools/readiness/write_surface.py check . docs/launch/write-surface.json` and reading what it
  demands, not from a hand count. If `docs/launch/write-surface.md` is diffed by a test or regenerated by the repo's
  render gesture, regenerate it; otherwise leave it.
- Lane: **medium** (one stdlib module of about 300 lines, one test file, one inventory entry; the cost is in the real
  subprocess, signal and rollover tests).

## Scale and failure
- Per start the current month file is read in full under the lock; rows are about 100 bytes, two per run. 10x the
  planned volume is about 1,000 lines (100 KB); 100x about 10,000 lines (1 MB), parse cost estimated at milliseconds to
  tens of milliseconds, UNMEASURED until step 9. Growth is bounded by month; old month files are never read again and
  never pruned by the module (about 1 MB per month at 100x; retention is an operator matter).
- Ceiling: the lock serialises ledger access on one machine; the critical section is a read plus one fsynced append
  (fsync dominates, measured in step 9). The one-run-at-a-time ceiling (D-15) is far below it.
- Recovery table: SIGKILL/crash leaves the `open`, counted at full belt next start (over-count persists for the month
  unless `settle_orphan` releases it); torn line or any corrupt line stops the whole month (fail closed, the price);
  dead lock holder needs nothing; lock timeout is NOT RUN, never unlocked; disk full or read-only dir yields no handle
  and a refusal; SIGTERM/SIGHUP/Ctrl-C settle at the full belt after the lock unwinds.
- Residuals stated, not closed: a lost hosted runner (job-level reservation belongs to the workflow goal, #819); a
  `claude` outliving a SIGKILLed parent until the launcher deadline is bounded by the full-belt count; restoring an
  older month file under-counts; two machines hold two independent ledgers; Windows is refused, tested by blocking
  `fcntl`, not on a real Windows host.

## Risks
1. Same-process lock re-entry on signal (highest value; Task C deadlock test, hard timeouts so failure is red not a hang).
2. SIGKILL test flakiness: kill only after the `ready` marker (written after reserve returned), bounded waits, child
   self-exits, Popen cleaned in `finally`.
3. The two-process race is probabilistic and the in-process window is tiny; it is demoted to a labelled smoke test and
   the deterministic held-lock timeout test is the system of record.
4. Local `python3` is 3.9; run pytest with `python3.12`; the module must still avoid post-3.10 syntax (full CI matrix
   includes 3.10, nightly).
