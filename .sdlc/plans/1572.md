# Plan 1572: test_upkeep_agent_1516 fails without a committer identity

Plan sha256: pending

## Goal
The two `wired` tests in `tests/test_upkeep_agent_1516.py` pass on a host with no usable global git identity, through ONE
shared, monkeypatch-scoped identity helper that every HOME-overriding test uses. Production is NOT changed:
`feature_upkeep_resolution.stamp_commit` committing with the inherited identity is correct.

Measured in this re-plan (worktree at `30904edb`, git 2.39.5):
- The documented no-identity gesture (below) gives `2 failed, 29 passed`; the two are
  `test_the_shipped_factory_builds_the_plan_from_config_and_lands_one_atomic_push` and
  `test_the_reviewer_stays_mandatory_even_when_configured_off`, both `level 2 refused (stamp-failed): Committer identity unknown`.
  Log: scratchpad `1572-red.log`.
- Why v1's fix was wrong (plan-review finding 1, verified by hand in a scratch repo): with `HOME=<dir with .gitconfig>` and
  `GIT_CONFIG_GLOBAL=/dev/null`, `git commit` still says `Author identity unknown` -- git reads `GIT_CONFIG_GLOBAL` INSTEAD of
  `$HOME/.gitconfig`. With `GIT_CONFIG_GLOBAL=<identity file>` and an empty HOME the commit succeeds as `t <t@example.com>`.
  So a `.gitconfig` under HOME cannot pass under the very gesture that proves the bug; the identity must come from
  `GIT_CONFIG_GLOBAL`.
- Prior art: `tests/unattended_support.py::hermetic` already does `monkeypatch.setenv("GIT_CONFIG_GLOBAL", <file>)` (plus
  `init.defaultBranch`, `GIT_CONFIG_NOSYSTEM`, and deletes `GIT_EDITOR` etc.). It is NOT reused for `wired`: those extra
  settings would change the environment the upkeep engine's real git runs in, beyond identity. Leave `hermetic` untouched.
- Production builds its git env from `os.environ` (`feature_rebase.pin_env` copies `environ` and appends `GIT_CONFIG_COUNT`
  pairs), so a monkeypatched `GIT_CONFIG_GLOBAL` reaches the committing subprocess.

## Files
- `tests/git_identity_support.py` (new, no tests in it, nothing at import time): the one shared helper
  `scoped_git_identity(root, monkeypatch, name="t", email="t@example.com") -> pathlib.Path`:
  1. writes `root/"git-identity.gitconfig"` containing only `[user]` name/email (creates `root` if needed);
  2. `monkeypatch.setenv("GIT_CONFIG_GLOBAL", str(that file))`;
  3. self-verifies with `git config --global --get user.email` (inherited env, `stdin=DEVNULL`) and raises
     `AssertionError` naming `GIT_CONFIG_GLOBAL` and `git >= 2.32` if the output is not `email` -- SAFETY: refuse loudly
     rather than proceed on a git that silently ignores the variable;
  4. returns the file path.
  It does NOT touch HOME (the caller owns it), does NOT set `GIT_AUTHOR_*`/`GIT_COMMITTER_*`, and does NOT set
  `GIT_CONFIG_NOSYSTEM`/`GIT_CONFIG_SYSTEM`: for `user.*` the global file already outranks system config, so a NOSYSTEM clause
  would have no test that can go red under its own break (decoration); the documented gesture already nulls system config.
- `tests/test_upkeep_agent_1516.py`: in `wired`, after the HOME `setenv`, call
  `git_identity_support.scoped_git_identity(rig.tmp / "git-identity", monkeypatch)`. Keep the HOME override. Add the documented
  no-identity gesture to the module docstring next to the existing one.
- `tests/test_git_identity_1572.py` (new): helper tests, the conftest identity-env scanner, the HOME-override ratchet (below).
- Only if step 5 proves them dependent: further test files, each fixed by the step 6 recipe; named in the PR body.
