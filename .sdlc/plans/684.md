# Plan: #684 the default loop runs and RECORDS every phase; `record done` refuses without them

Inputs: issue #684 (owner decision 2026-10-06: option (a)), `.sdlc/research/684.md`, `.sdlc/acceptance/684.md`.

## Design

One new gate, one new record, one recovery lever, all plain Python so every host and every mode (local-goals, issues, github) goes through it.

**1. Phases reach the action log.** `actionlog.py` gains three INTERNAL kinds (never reachable from `loop.py log`):
- `phase` (`phase`, `state` start|end, `agent_id`, `cost`): written by `phase_report.py start` and `end`, unconditionally of the opt-in journal. `cost` is the same figure the banner printed (`$0.12` or `unavailable`).
- `verdict` (`phase`, `verdict`, `route`, `agent_id`, `plan_hash`): written by `work.py record-plan-review` (phase plan_review, only for a verdict bound to the plan's sha256, as today) and by the new `work.py record-review` (phase review, verdict APPROVE|SEND-BACK|BLOCK). Both resolve `reviewer.resolve` and store its mechanism as `route`.
- `phase_waived` (`phase`, `reason`): written only by the lever below.
`log.py slots` already reads `phase` from any entry, so a finished goal now renders with its newest phase.

**2. The gate** `skills/sigma-loop/scripts/phase_gate.py::phase_record_refusal(sdlc_dir, config, goal)` returns None or the refusal text. It reads the goal's own action-log file (append order, not timestamps) and requires, in order: research end, plan end, plan-review end and an approving plan-review verdict, implement start AFTER that verdict (plan-before-code, the product claim), implement end, review end and an APPROVE review verdict, retro end. Also required: `.sdlc/research/<stem>.md` and `.sdlc/plans/<stem>.md` exist. Independence: when a verdict's route is `subagent` it must carry an `--agent-id`; that id must differ from EVERY other phase row's agent id for the goal (research, plan, implement, and plan-review vs review); when the host's transcript store is readable (`CLAUDE_CODE_SESSION_ID` set and the session dir exists) the id must exist in it, else it is refused; when the store is not readable the id is accepted and the row says `unverified` (a nested caller or a non-Claude host is never stranded). A missing id on either side makes "differs" vacuous; stated in the docs.
Re-run semantics: the LAST `end` row per phase counts; the LAST verdict per phase must be approving; implement's FIRST start must follow the FIRST approving plan-review verdict. Content binding: the last plan-review verdict's `plan_hash` must equal the sha256 of `.sdlc/plans/<stem>.md` at `done` time (an edit after review is refused), and research and plan files must be non-empty. The review verdict binds to no hash (stated: the verify gate already refuses an edit after the green verify). `retro` is the weakest record: a phase `end` row only (stated). A verdict with route `inline` is accepted and shown as inline (the host cannot spawn one; stated, never silent). The refusal names each missing item, the exact command that writes it, and the lever.
- Config: `gates.phase_record.enabled` (the `hard_plan_gate_on` truth table). The scaffold template ships `true`; an ABSENT key is off (an already-adopted repo is not retro-fitted; `/sigma-doctor` reports it). With the gate on and `action_log.enabled` not true the gate REFUSES (it cannot verify; it never passes weakly) and names both levers.
- Wired at the `loop.py record ... done` CLI verb (every mode), inside the same lock as the existing done refusals, and at `work.py merge` (PR modes; parks like the verify gate; slice sub-goals are exempt because they record no phases of their own). `reconcile-merges` is not gated: a PR someone else merged must not strand. `run_loop` (a test-only programmatic driver with no caller under skills/ or hooks/) is not gated; stated in docs/enforcement.md, as is the CLI-only reach.
- Writer side: rows are written with `actionlog.safe_append` (prints one stderr line on a skip); the gate fails CLOSED when a required row is missing, so a dropped write can never read as a pass (test: a kind removed from the vocabulary makes the gate refuse).
- The new `ENFORCEMENT_GATES` row sits in `work.py` and its `function` is the module-level `phase_record_refusal` there (delegating to `phase_gate.py`); `docs/enforcement.md` is regenerated.

**3. The lever (explicit, recorded, visible).** `loop.py waive-phases <sdlc> <goal> research,retro --reason "<text>"` writes a `phase_waived` row per phase and prints a stderr line. Only `research` and `retro` may be waived; plan, plan-review, implement and review never can. `gates.phase_record.enabled: false` turns the whole gate off and is shown in `/sigma-doctor`. Neither deletes anything.

**4. A driver, so orchestrators stop guessing.** `loop.py phases <sdlc> <goal>` prints, per phase, recorded/missing, and the NEXT step with the exact dispatch and recording commands (same text the refusal uses). SKILL.md and running.md say that tier `off` still means one subagent per phase.

**5. Cost.** Expected ceiling stated up front, then measured on the same live task: the prior single-worker run cost $0.875 (loop $0.743 + init $0.132); six dispatched phases with their own cached-context rebuilds are expected to land in the $1.5 to $3 range for that goal, with the $20 run ceiling as the hard stop. The number in the PR body is the measured one, not this estimate. Cheap phases are not collapsed; the lever above is the cost control for trivial goals.

Not changed: `reconcile-merges`, `gates.hard_plan_gate`, `gates.plan_review` (they remain the PR-time checks), the PR review gate.

## Honesty limits (also stated in docs/enforcement.md)
The record proves a phase boundary and a verdict were recorded in order, that a subagent-route verdict names a dispatched agent that exists in the host's transcript store (when readable), and that review and implement were different agents. It does not prove the phase's work was good. A maker can still call the recording verbs; they are forgeable by the maker exactly as `record-plan-review` is today.

## Red proof
`tests/test_phase_record_gate.py` written first; observed red (`red_green.observe`, COLUMNS=250), then green. Controls on the documented gestures: (1) the `record done` command from SKILL.md step 6 against a goal with no phases is REFUSED; (2) the gate neutered (always None) fails the refusal tests; (3) `implement` recorded before the plan-review verdict is refused; (4) a made-up reviewer agent id is refused; (5) lever recorded is visible in `loop.py phases` and in `log.py`.
