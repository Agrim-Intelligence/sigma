## next-step contract (what `next_step.render(sdlc, config, goal)` prints)

Read-only: writes no file, no action-log row, no note, no heartbeat. Exit 0 on success; exit 2 with
`loop.py next-step: <reason>` on stderr for an unsafe goal (`state.unsafe_goal_reason`) or missing args.
Lines, in order:

1. **Route** (from `work.route_of`, `work._legacy_evidence`, `work._record`, `actionlog.enabled_for(...,
   kind="goal_class")` — the same predicates `work.classify` uses, `work.py:1591-1624`):
   - lean: `route: lean/1 profile=<p>`.
   - legacy evidence: `route: legacy — plan-review approved before the lean route; finishes under the 1.0.x
     rules (FR-33); do not classify`.
   - unclassified, and a work record or the action log can hold the route:
     `route: unclassified -> classify it now: python3 "<abs>/loop.py" classify <sdlc> "<goal>"
     trivial|small|standard|heavy --rationale "<why>"` (the hand-off: today no skill text tells the agent to
     run classify; this line plus the pointers is the only prompt besides `work.py start`'s stderr hint).
   - unclassified and neither store can hold it: `route: unclassified — nothing can hold the route (no work
     record; action_log.enabled false); the goal runs on the legacy rules`.
2. **Phases**: `phase_gate.format_status(sdlc, config, goal)` verbatim (reuse; no duplicated phase math).
3. **Step banner** (printed while `implement` has no recorded phase end, any route): the
   `phase_report.py step <sdlc> "<goal>" implement --num <n> --total <m> --phase-model --brief "<what>"`
   command, then the rules moved from implement in <= 5 lines: `--phase-model` only when this phase agent
   runs the step; a separately dispatched step passes `--model <step-tier> --host-model <exact-id>`
   instead; `<sdlc>` is the MAIN checkout's absolute `.sdlc`; brief <= 88 chars; best-effort, never blocks
   a step, writes nothing.
4. **Slices** (printed while `implement` has no recorded end):
   - `work.enabled(config)` false: `slices: work.enabled is off — run the goal as one unit`.
   - no `slices.manifest_path(...)` file, or `slices.parallel(config)[0]` false: `slices: none declared (or
     parallel.enabled off) — run the goal as one unit`.
   - else the wave procedure moved from running.md 3b: the `slices.py plan` command (+ Codex flags
     `--host codex --goal-worktree <absolute-path> --tier <tier-or-off> --effort <effort>` "using the goal
     worktree from `work.py start`). Before every Codex slice dispatch, resolve ..." with the
     `predict.py" host-model codex "<tier-or-off>" <sdlc> --effort "<effort>"` gesture); one wave at a time,
     one subagent per slice; Codex slices sharing a checkout run sequentially; the `loop.py log ...
     agent_dispatch --thread <slice-id> --role slice --phase implement --model <tier>` and `agent-start
     --thread` lines; land the wave logging `agent_done`, then re-run `plan`; never `claude -p`/`codex exec`;
     `dispatch: session` -> print the command for the human, never start it.

Known gap for the PR body (state verbatim): **with `work.enabled` off, `work.py start` never runs, so no
default `standard` classification happens and its stderr hint never prints; the only classify prompt is
next-step's route line, reached only if the agent follows the pointer. With `work.enabled` off AND
`action_log.enabled` false, nothing can hold a route and the goal runs legacy.** Also: the budget proves
bytes, not that an agent runs next-step (`skill_structure.STRUCTURE_ONLY_NOTICE`) — no behavioural claim.

Scalability: next-step reads one goal's action log twice (phase_gate.status, route_of) — O(rows of that
goal), no cross-goal scan. Measure wall time in P5 on a synthetic 50 / 500 / 5000-row log and put the three
numbers in the PR body; unmeasured until then.
