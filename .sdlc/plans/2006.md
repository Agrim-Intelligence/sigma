# #2006 P3 PLAN — Lean goals slice 4: multi-PR goal lifecycle and issue close gates

Epic #2001, unit `lean-goals`, slice 4. Branch `sdlc/2006` off `feature/lean-goals` at `b32b7af`
(slices 1, 2, 3, 9 merged). Inputs: `.sdlc/research/2006.md` (every cited site re-grepped on `b32b7af`
by this run), `.sdlc/design/2000.md` rev 9 (slice row `:1261`, FR-36/37/39/63/65/75/84/85/87, BR-17/18/
19/42/53/54/63/64/68/69, D-41, D-48, D-49, run-the-control rows `:1164-1202`), and the owner's D-41
measurement on #2006 (2026-10-25). Implement, do not redesign. Size: large (design: "large, Opus
(riskiest)"); estimate ~450 production + ~650 test lines, not measured.

## Goal

A lean goal (slice 2's route marker present) whose slice manifest declares two or more slices, with
`work.enabled` on and a GitHub issue, ships as ONE PR PER SLICE: each slice on its own work.py-created
branch; non-final slice PRs write `Refs #N`, the last writes `Closes #N` (default base) and can be
switched back to `Refs` through a new `gh_api.edit_pr_body`; no done path (`work.py merge`'s close, the
merge-reconcile pass, CLI `record done`, the programmatic run driver) closes the issue or records done
while a manifest slice has no merged PR; between slices the goal keeps `sdlc:in-progress`, carries the
informational `sdlc:between-slices` label (seeded, stripped on close/park and by the reconciler, shown by
status and the DAG, read by no picker); the owning machine's next pick continues the goal before
`next_pending`; a slice is done only when its slice-branch PR is merged AND carries a trusted
`sigma:approve`; every slice merged with the issue open records done. Legacy goals and `work.enabled`
off keep one PR / one unit.

## Decisions recorded (interpretations, with reasons)

- **D1 One predicate decides "multi-PR".** `work.multi_pr(sdlc_dir, config, goal)` is True iff
  `route_of(sdlc_dir, goal)` is non-None (lean) AND `enabled(config)` AND `_reads_a_declaration(config,
  goal)` (github mode, numeric stem) AND `len(slices.load(sdlc_dir, goal)) >= 2`. It does not read
  `parallel.enabled` (that switch is concurrency inside one PR). `classify_blocker` is not touched.
  Legacy goals (FR-33), work off (FR-39), local mode and 0/1-slice manifests return False, and every new
  gate stands down on False — that IS the single-PR fallback. A raising `slices.load` (broken manifest)
  with the other three clauses true returns True (fail closed: the gates hold).
- **D2 Slice branch name.** `work.slice_branch(config, goal, slice_id)` =
  `f"{branch_prefix}{stem(goal)}-s{slice_id}"`, the ONE home of the name (5b adds the plan generation
  there). Not `sdlc/<stem>/<id>` (git cannot hold `sdlc/2006` and `sdlc/2006/x` together). Ids are
  refused (ValueError) unless they match `^[A-Za-z0-9][A-Za-z0-9._-]{0,39}$`, contain no `..` and do
  not end `.lock` or `.` (slices.py only strips ids today).
- **D3 `work.py slice <sdlc> <goal>` verb** (new verb in work.py, usage-map line). Picks the first
  manifest slice (manifest order) not done per D5; refuses (exit 2, one line) when `multi_pr` is False,
  the worktree is dirty, or the current slice's PR is open (`pr_landing_state` OPEN: "merge it or record
  review first"). The FIRST slice is cut from the worktree HEAD (`git checkout -B <slice-branch>`,
  keeping the research/plan/acceptance commits `pr()` requires); later slices from `<remote>/<base>`
  after `git fetch <remote> <base>` (the earlier slice merged into it). The work record gets
  `slice=<id>`, `branch=<slice branch>`, `pr` removed, `slices[<id>] = {"branch": ...}` (history), and
  `goal_branch` (first cut only), and fresh `cut_tip` fields via `_cut_tip_fields` on EVERY cut (a
  stale tip would make a later `--onto` rebase replay commits already on the base). Every existing PR verb (`pr`, `gate`, `merge`, `_reconcile_one`,
  `done_refusal`) keeps reading `rec["branch"]`/`rec["pr"]` unchanged. Resume of an open slice PR from
  another machine is 5a, out of scope. All slices done -> prints that and exits 0 with no branch cut.
  A slice whose PR merged WITHOUT a trusted approve is not re-cut: refuse exit 2 naming the PR and
  `loop.py record <sdlc> <goal> parked --qkind needs_decision` (same rule as D8).
- **D4 `pr()` refuses a multi-PR goal with no `rec["slice"]`** and names `work.py slice`: a PR off
  `sdlc/<stem>` could never satisfy FR-65's slice-branch clause, and could not say Refs vs Closes. Lean
  is unreleased (feature branch only), so no in-flight goal is stranded.
- **D5 FR-65 slice state.** `work.slice_done(sdlc_dir, config, goal, slice_id, run)` reads
  `gh_api.pr_for_branch_gh(run, slice_branch(...), ["number","state","mergedAt","headRefName"], repo)`
  and counts the slice done only when (a) the row's `headRefName` equals the slice branch, (b) it is
  merged (`mergedAt` set or state MERGED), and (c) `_comment_directive(dict(rec, pr=<n>), run)[0] ==
  "approve"` — reused, so trust is the existing `authorAssociation in _TRUSTED_ASSOCIATIONS` filter and
  a marker with no association raises (fail closed). `same_author` is not read: a self-authored trusted
  approve already satisfies `merge()` today (#821 warns only), and a solo-account repo must still finish
  a slice. Never reads the local record for state. Cost ≈ 2 REST calls (+ comment pages) per slice per
  evaluation; unmeasured.
- **D6 ONE close-gate predicate, placed where every done path already passes.**
  `work.unmerged_slices(sdlc_dir, config, goal, run, just_merged=None)` -> `[]` when `multi_pr` is
  False, else the manifest slice ids not done per D5 (`just_merged`, the slice `merge()` itself just
  landed after its own review gate, counts as done without a re-read). FAIL CLOSED: a raising
  `slices.load` yields `["<manifest unreadable>"]`; a raising `slice_branch`/`pr_for_branch_gh`/
  `_comment_directive` makes that slice unmerged. Readers:
  1. **`work.done_refusal`**, at its TOP (right after the `enabled` check, before the no-PR early
     return at work.py:5010-5011 — plan-review B1: a freshly cut next slice has no PR and no diff, so
     a check inside the MERGED branch would fail open): non-empty -> refusal starting with the
     constant `work.SLICES_PENDING` (`"slices pending: "`)
     `slice(s) <ids> of goal N have no merged, approved PR (FR-63) — run work.py slice for the next
     slice; done is recorded after the last`. `done_refusal` is the chokepoint the CLI `record done`
     (loop.py:8135), the programmatic driver (loop.py:6837-6841, which then records `review`) and the
     reconcile pass (loop.py:5118) already call — research found the driver as a fourth done path the
     design does not name; one check covers all three, whatever the PR state. It never raises. The
     driver maps a `SLICES_PENDING` refusal to `review` only when the record's current PR is open
     (then `_record_awaiting_merge` works); otherwise it records nothing for that goal (the goal stays
     claimed with its work record, and the continue step resumes it), prints one line, and counts it

  2. **`merge()`** around `_close_issue_the_base_cannot` (work.py:7979): non-empty -> skip the close,

## Definition of done

- A lean, work-on, github goal with a 3-slice manifest: `work.py slice` cuts `sdlc/<n>-sa`, `-sb`,
  `-sc`; `pr()` writes Refs on a and b and Closes on c (default base); no done path closes the issue or
  records done before c merges; after c, the issue closes on every base. Legacy goals, work off, local
  mode and 1-slice manifests behave exactly as on `b32b7af`.
- Slice done only from a merged slice-branch PR with a trusted `sigma:approve`; a slice merged without
  one parks `needs_decision`. Unreadable slice state keeps the issue open and never crashes a landed
  merge.
- Between slices: `sdlc:in-progress` kept, `sdlc:between-slices` present, not pickable, shown in status
  and the DAG, stripped by `complete()`, `park()`, promote demote and the reconciler; a parked
  between-slices goal is never re-claimed; the owning machine's next pick continues the goal first; all
  merged + open issue records done.
- `edit_pr_body` + `switch_pr_to_refs` shipped with the stale-aware bounded re-read; D-41 measurement
  and the unmeasured merge-time behaviour stated in the docstring and PR body.
- All `## Tests` nodes red on `b32b7af`, green after; every run-the-control row executed and recorded;
  Verify set green; phase budget clean.
