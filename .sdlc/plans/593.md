# Plan: #593 benchmark isolation launcher

Inputs: issue #593, `.sdlc/research/593.md`, `.sdlc/acceptance/593.md`. No model run, no spend.

## Design

One stdlib file, `evals/bench/launcher/sigma_bench_launcher.py` (+ `README.md`, `launcher.example.json`). It is a
source the owner installs outside the repo (the harness refuses an in-repo launcher). Config is a JSON file beside
the installed script (owner-written; the harness forwards no flags, strips `SIGMA_BENCH_*`, and drops env values
containing the hidden root, so flags/env cannot carry repo root, hidden root or credential name). Refuses: unknown
keys; missing `deadline_seconds` or `scratch_root`; a bad `credential_var` or one without `claude_path`; a
credential-shaped or profile-variable `extra_env` name; a `scratch_root` inside repo/hidden root; and a `real_home`
unless env `SIGMA_LAUNCHER_TEST_MODE=1` (a wrong value would switch the guard off). `scratch_root` is the
launcher's own scratch: dry-run profile, latch and alert log, and nothing else is ever written by the launcher.
No state persists between runs except the latch (so ordinary plugin updates between benchmarks never trip it).

Invocation: `launcher [--config F] [--dry-run] -- argv...`. Nothing starts before every guard passes:
1. POSIX only. Refuse if the launcher file is inside `repo_root`; if the latch file exists; if `<real home>/.claude`
   does not exist (a guard over a missing profile can never go red); or if any PARENT of the working directory holds
   `CLAUDE.md`, `CLAUDE.local.md`, `.mcp.json` or a `.claude` entry (Claude Code reads instruction files from
   parents and whether it reads a parent's `.claude/` is unmeasured, so the real home as a parent is refused; HOME does
   not stop it; the working directory itself is task content and is not checked). The owner therefore passes a
   harness `--scratch-root` outside the home directory (README's first-run command does).
2. Profile, validated by LOCATION only because the harness reuses a profile between a run and its scoring commands:
   all four of HOME/CLAUDE_CONFIG_DIR/CODEX_HOME/TMPDIR set, absolute, existing, distinct, one common parent, none
   equal to or inside the real home's `.claude`/`.codex` nor the real home itself; the profile and its parent not
   inside `repo_root`/`hidden_root`; `scratch_root` neither inside nor an ancestor of the run directory. `--dry-run`
   (the owner's standalone gesture; the shell sets HOME and TMPDIR but not the others) ignores inherited variables
   and makes a fresh mkdtemp profile under `scratch_root`, removed afterwards. The real home comes from the account
   database (the harness overwrote HOME).
3. `--plugin-dir` (at most one; the `=` form refuses): a directory whose top level is a subset of
   `.claude-plugin skills hooks` holding `.claude-plugin`, no symlinks, no `evals`/`tests` component, not inside
   repo/hidden/real `.claude`/`.codex`, and a sibling of the profile directory (harness mode).
4. Environment built from nothing: PATH LANG LC_ALL LC_CTYPE TZ TERM SHELL USER LOGNAME, config `extra_env` names,
   the four profile variables, and the single named credential variable ONLY when the PATH-resolved realpath of
   argv[0] equals the realpath of config `claude_path`.
5. Hash the real plugin surface (`.claude/plugins`, `.claude/settings.json`, `.codex/config.toml`, `.codex/plugins`).
6. Spawn a supervisor in its own session, passing the before-hashes and the read end of a pipe only the launcher
   holds the write end of. The supervisor runs the command in ITS OWN group (so it survives killing it), enforces
   `deadline_seconds`, and on deadline, normal exit, or pipe EOF (the harness SIGKILLs the launcher's group at its
   own deadline, which no launcher code could survive) it SIGKILLs the command's group, redirects its own
   stdin/stdout/stderr to /dev/null right after starting the command (a lingering stdout would stall the harness's
   `communicate()`; the pipe's write end is non-inheritable and never reaches the supervisor or command), then
   takes the AFTER-hash. The launcher passes stdin through, keeps stdout clean (the harness reads it for `--version`) and
   waits; SIGTERM/SIGHUP/SIGINT close the pipe, wait for the supervisor, and exit 128+n.
7. A difference between before and after hashes: the supervisor writes the latch `<scratch_root>/real-profile-
   changed.txt` (names of changed paths, never contents; every later invocation refuses until the owner deletes it
   after inspecting), appends to the alert log, returns 97, and, outside `--dry-run`, SIGTERMs the launcher's
   parent iff one argument of its `ps` command line has the basename `parent_marker` (default `bench.py`; null
   disables; the pid is the launcher's own getppid captured before the supervisor starts): the
   harness turns SIGTERM into its own `aborted` report that keeps paid rows. It works even when the launcher was
   killed, because the supervisor does it.
8. Every refusal is appended to the alert log (bounded at 1 MiB), because the harness discards stderr and an
   operator would otherwise see only "could not be priced".
Exit codes: command's own; 2 refusal; 97 real profile changed; 124 deadline; 127 cannot start.

## Limits stated in the README, not hidden
Not a sandbox: same uid, so the launched command can WRITE anywhere the owner can (including the real `~/.claude`;
hashing detects four paths and prevents nothing), and read the keychain, system-wide managed settings, the network,
the config file (names the hidden root) and the `ps` environment of the launcher and harness (start the harness under
`env -i`). `~/.claude.json`, `~/.claude/{skills,agents,hooks,CLAUDE.md}` are not hashed. Freshness of profiles is the
harness's (one mkdtemp per run); the launcher checks location only. Hash time counts in the harness's `wall_seconds` and
deadline (matched arm pays it twice per attempt). Rows after a trip are invalid; with `parent_marker` null the
tripping run's scoring is refused and recorded as failed. A launcher `scratch_root` under `$TMPDIR` is refused
(overlaps the version profile's parent). Exit 2 can collide with a command's own, and the launcher's 124 reads as
"claude exit 124" in the harness row. The command's children
(plugin hooks, tools) inherit the credential. Hidden bundle confidentiality at scoring depends on the operator. The
real `CLAUDE_CONFIG_DIR` the owner's shell may export is invisible. `deadline_seconds` should sit just inside the
harness's `--deadline-seconds`; the harness's deadline shrinks for later matched attempts, so it may kill first (the
supervisor still hashes). When a trip stops the harness the report says only "signal SIGTERM" (and none is written if
it fires at the version step): the latch and alert log carry the cause; a change found during a scoring command
aborts before the row is appended. The two hashes cost per invocation is unmeasured on the owner's directories (the
harness measured 332 MB in about 2 s). The env allowlist is unmeasured against a real agent run. Authentication:
`ANTHROPIC_API_KEY` is the documented default recommendation (priced in dollars, matches `--max-budget-usd` and the
meter), `CLAUDE_CODE_OAUTH_TOKEN` the subscription alternative; copying real login state is refused by design; the
owner chooses. Costs: only the measured figures in `docs/launch/evidence/cost-calibration.md`; the pilot is unmeasured.
