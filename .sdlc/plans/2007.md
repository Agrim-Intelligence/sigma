## Goal

A lean multi-PR goal (`work.multi_pr` True) publishes ONE trusted `<!-- sigma:goal-evidence {json} -->`
comment on its issue through `gh_api.comment_issue` when its first slice push carrying an approved plan lands,
and again on any later approving plan-review once a slice has been pushed; the newest trusted publication wins.
A machine that picks the issue without a local work record (or the owner picking it again after an unpark)
reads that evidence only through `sources.trusted_marker_comments` (fail closed), posts one
`<!-- sigma:epoch {json} -->` bump, and `work.py start` then reads plan, acceptance and manifest as RAW bytes
with `git cat-file blob` from the open slice PR head or else `<remote>/<base>`, verifies plan sha256,
acceptance sha256 and the manifest scope fingerprint, imports them plus an `imported: true` gates record bound
to the verified plan sha into `<sdlc>/state/imported/<stem>/` and `state/gates/<stem>.json` (never the tracked
`.sdlc/plans|acceptance`), takes the route and profile from the evidence (no fresh classification), and
`work.py slice` resumes at the first slice without a merged approved PR, checking out and reusing its open PR
branch. A sha/fingerprint mismatch or missing ref refuses naming `loop.py resume <sdlc> <goal> --restart`
(the verb is slice 5b). `loop.py record done` accepts the imported goal evidence for research/plan/plan-review
and live GitHub slice evidence for implement/review.

## Runner decisions applied (binding)

- **Q1** `slices.scope_fingerprint(manifest)` = sha256 of `json.dumps(<list with "status" removed from every
  dict item>, sort_keys=True, separators=(",", ":"), ensure_ascii=False).encode("utf-8")`, over the RAW parsed
  manifest list (not `_normalise`d, so unknown/future fields such as slice 6's `tests` count). Non-list raises
  ValueError. Slice 6 binds it to plan-review; 5a publishes it and verifies an imported manifest against it.
- **Q2** the manifest is imported too (verified by the fingerprint), into the state dir.
- **Restart lever** named in every resume refusal: `loop.py resume <sdlc> <goal> --restart (slice 5b; until it
  ships, park the goal: loop.py record <sdlc> <goal> parked --qkind needs_decision)`.
- **FR-80** shape chosen (smaller correct diff): NO imported action-log rows (no actionlog vocabulary change,
  no agent-id interplay). `phase_gate.status` treats research/plan/plan_review as satisfied by a VERIFIED
  import record, and implement/review (only when their local rows are missing) by a live `work.unmerged_slices`
  read returning `[]` on a multi-PR goal. Unreadable -> not satisfied (fail closed).
- **Scope** publish/resume only for `work.multi_pr` goals; single-PR lean goals are a deferral.
- **FR-90** at the pick, on the one claimed goal, gated (below); unreadable evidence = skip the goal, not park.
- **Raw bytes** every sha is over `subprocess.run(..., capture_output=True)` bytes (no `text=True`, no strip).
- **Epoch marker format fixed now**: `<!-- sigma:epoch {"v":1,"goal":"<n>","epoch":<int>,"reason":"resume"} -->`.
  Current epoch = max `epoch` over trusted epoch AND evidence markers (0 when none). 5a only writes the FR-90
  bump; it never reads the epoch as a fence (5b: D-51 tie-break highest epoch, then earliest comment).

## Decisions recorded (interpretations, with reasons)

- **E1 Evidence marker format (contract, read by 5b/6/7).** One comment:
  `<!-- sigma:goal-evidence {json} -->\nSigma goal evidence for #<n>: plan <path> sha256 <12>…, plan-review
  <verdict>, epoch <e>, generation 1. A machine resuming this goal verifies these against the remote branch.`
  JSON keys (all required): `v` (1), `goal` (stem), `research` (repo-relative dossier path or null), `plan`
  (repo-relative `<sdlc name>/plans/<file>`), `ref` (the slice branch pushed), `plan_sha256`,
  `acceptance_sha256` (hex or null), `verdict` (`pass`|`warn`), `scope_fingerprint` (hex), `epoch` (int >= 1),
  `generation` (int, constant `work.PLAN_GENERATION = 1` until 5b), `profile` (one of `work.PROFILES`).
  Parsed with `re.compile(r"<!-- %s:goal-evidence (\{.*?\}) -->" % legacy.MARKER_PREFIX_RE, re.S)` so the
  retired brand spelling reads too. A JSON payload containing `-->` is refused at write time.
- **E2 One reader, always through the trust filter (FR-93).** `work.newest_evidence(comments, goal)` first calls
  `_load("sources").trusted_marker_comments(comments, goal)` itself (idempotent over an already-filtered
  `fetch_comments_strict` result; raises ValueError on a marker comment with no `authorAssociation`), then
  returns the payload of the LAST matching comment in (createdAt, list position) order plus `"comment": <id>`,
  or None. A trusted evidence marker whose JSON or field types are wrong RAISES ValueError (fail closed: we
  cannot tell what the newest publication says). Identical duplicate posts (TD-7) collapse naturally (same
  payload). `work.current_epoch(comments, goal)` = max epoch over trusted epoch + evidence markers, same filter.
- **E3 Publisher.** `work.publish_goal_evidence(sdlc_dir, config, goal, rec, run)` -> `"published"`,
  `"unchanged"`, or a one-line reason it published nothing. Builds the payload only when: `multi_pr` True;
  the gates record (`plan_review_record_path`) has an approving `verdict`, no `fold`, a hex `plan_hash`
  (D-56: small/folded goals publish nothing); `plan_copies(...)` returns a BRANCH copy whose
  `rc.plan_sha256` equals `plan_hash` (the plan is committed on the pushed branch: R4 control); the worktree's
  `<sdlc name>/plans/<stem>.slices.json` is tracked and clean (`git ls-files`, `git status --porcelain`, the
  `plan_copies` rule) and its fingerprint equals the local manifest's (`slices.raw`) — otherwise the resumer
  could not import it (FR-41's branch-first manifest is slice 6; E4a is what puts it on the branch).
  `acceptance_sha256` (R3) = sha256 of the raw DISK bytes of the WORKTREE copy `<worktree>/<sdlc name>/acceptance/
  <stem>.md` when that copy is tracked and clean (same `ls-files`/`status --porcelain` rule) — the bytes a resumer
  will `cat-file` from the branch, never the main-checkout copy; when the worktree has no such file AND
  `acceptance.resolve(sdlc_dir, goal)` does not exist -> null; when a root/imported record exists but the branch
  copy is missing, untracked or dirty -> publish nothing (reason names the acceptance record; `commit`'s #1474 copy
  puts it there). `epoch` (R5) = `rec.get("epoch") or 1` (the owner has none -> 1; a resumer carries the bumped
  epoch from E5/E6). Idempotence: `digest` = sha256 of the
  canonical payload JSON; when `rec["evidence"]["digest"]` equals it -> `"unchanged"`, no POST. On success
  `rec["evidence"] = {"digest": ..., "at": ...}` and `_save` (mutating the caller's `rec` in place).
  The single GitHub write is `_post_goal_marker(config, goal, body, run, cwd)` ->
  `gh_api.comment_issue(_pr_api_run(run, cwd), int(stem(goal)), body, _issue_repo(config))` — ONE new
  write-surface entry.
