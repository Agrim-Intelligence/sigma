# Plan: #514 — Sigma's registry survives the predecessor's fold

Inputs: issue #514, `.sdlc/research/514.md`, `.sdlc/acceptance/514.md`. Worktree `.sdlc/work/514`, origin/main `0305c6c`.

## Design

Four plan-review rounds converged on this shape. Rejected, with the reason: a "recovered view" inside `read` (touches
`read_index`, `monotonic_violations`, the #314 delta helpers, `migrate.py`); an automatic restore of the tracked sheet
from gated verbs (races, bypasses migrate's holds and `--replace-old-plugin`, churns a tracked file on every verb for
a user who never opted in, mutates in `coexist.gate`); the predecessor's schema id (breaks Sigma's readers and the
cut-over, measured); refusing Sigma's writes (contradicts #314 and does not stop the loss); a shard per unit (a
stale shard would win over a later sheet); `git show HEAD:` as the only source (fails once the emptied sheet is
committed). Sigma cannot stop another program's write, so the fix is: PROTECT (a Sigma-only copy), DETECT LOUDLY,
and give ONE explicit lever; nothing restores the tracked sheet unprompted. That is a mitigation, not the issue's
literal "write in a form the fold leaves alone": stated as such in the docs and the PR.

`feature_registry.py`:
1. `mirror_path(features_dir)` = `<sdlc>/state/backup/index-sigma.json`: bytes of a Sigma-schema `index.json` this
   checkout wrote or observed. Outside `features/` (the predecessor never reads or writes it); not matching the
   `features-*` backup glob; a symlink or non-regular file there is neither read nor written.
2. `_refresh_mirror(features_dir, text, authoritative)`: through the existing `_atomic_write_text` (no new direct
   write site); writes only when the bytes differ AND the sheet on disk still equals `text` (compare-and-write, so
   a stale caller cannot overwrite a newer snapshot; the remaining window is the instant between check and replace).
   A non-authoritative refresh (observation) also requires the sheet's unit names to be a superset of the copy's, so
   a shrunken Sigma sheet (older branch, pull) never destroys the only recovery data; `write_index` (a Sigma write)
   is authoritative and creates `state/backup` as the one-time backup already does. Fail-open, stderr on failure.
3. `recoverable(features_dir)` -> sorted unit names the copy holds and the sheet lacks, ONLY when `index.json`
   declares the predecessor's schema id and the copy is a valid Sigma-schema document (through `parse`, id compared
   exactly, hostile or wrong-typed content ignored); else `[]`. Pure read, never raises.
4. `guard_sheet(sdlc_dir, stream)` (observe; never raises; writes nothing but the copy): Sigma-schema sheet -> refresh
   the copy (non-authoritative; only inside an existing `state/`); predecessor-id sheet with `recoverable` units ->
   one loud stderr line per call (count, names capped, cause, the exact lever). Called from `loop._coexist_notice`
   (after a cheap `index.json` exists check, so a repository without a registry pays one stat) and from the `init`
   paths that already call `coexist.gate`. `coexist.gate` itself is untouched (notice-only). `watch_daemon` never
   calls the gate; stated.
5. `feature_sync.py recover <sdlc_dir>` (the lever; explicit): builds `copy units + sheet units` (sheet wins on a
   shared name), refuses with exit 2 and nothing written when `recoverable` is empty or the sheet changed since it
   was read (compare against the bytes read), and writes through `write_index` (one-time backup hook, legacy-id
   notice, unchanged-bytes rule all apply). Only whole missing units are restored. Prints what it restored and says
   `git diff` is the way to review. Sigma's `fold` also refuses (`FoldRefused`, nothing written, naming `recover`)
   while `recoverable` is non-empty, so a fold can never write the emptied registry as if it were complete. `fold`
   and `repair` are otherwise unchanged.
6. `migrate.py` `_hold_index`: a `recoverable` sheet is not converted (listed as refused with the `recover` command),
   in the dry run too, so `--apply` never turns an emptied sheet into an empty Sigma sheet.
7. `docs/upgrading.md`: covered/not covered and the exact test command. Residuals, plainly: the predecessor still
   rewrites `index.json`; nothing automatic restores it; between its write and Sigma's next gated verb the registry
   is wrong; `read` itself is unchanged, so a bare read before `recover` returns what the file holds; a unit shard
   the predecessor overwrites directly is not covered; the copy covers only sheets this checkout wrote or observed
   (a fresh clone, a linked worktree without its own `state/`, or a sheet emptied before Sigma ran has only git
   history); a truncated, corrupt or deleted sheet is not detected; a partial rewrite that keeps a unit but drops
   its goals is not detected; an unrelated predecessor-id sheet (older branch) whose units are not in the copy
   would be shown the copy's units as recoverable (a refused-by-default lever with a visible diff); restore
   normalises entries like `fold`; a restore bumps `index.json`'s mtime (legacy-delta `repair` then prints a discard
   rather than refusing); while the predecessor keeps running its next fold empties the sheet again and the signal
   returns; the copy is one file the size of the sheet (a measured 1,000-unit sheet in the docs), two small reads
   and no write per gated verb when nothing changed.
No change to `read`, `read_index`, `write_unit`, `feature_propagate.py` (its sibling's own gated verbs observe).

## Test notes
New file. The model of the predecessor's fold is documented as a model of the measured behaviour (rc 0, an empty
registry written under the predecessor's schema id), not the real thing. The real-fold node copies the installed
predecessor scripts to a temporary directory, runs only the copy, asserts the installed scripts' content hash is
unchanged, and SKIPS with a named reason when absent (CI): local evidence; the model carries the red in CI. Every
node also asserts the exact bytes or units restored. The fresh-unit node has a predecessor-schema shard for a new
unit X so its fold writes `{X}`.
Controls that pass on old code or only exist with the fix (kept out of the list; each judged by a mutation I run):
a predecessor-id sheet with units and no copy is left alone and `recover` refuses; a Sigma-schema sheet is never
rewritten by the guard; sheet entries win over the copy on a shared name; a hostile copy (wrong schema, non-unit-name
keys, wrong types, a symlink) is ignored; the guard in a directory with no `state/` creates none and an unwritable
copy location never fails the guard or `write_index`; one copy file however many writes; the compare-and-write seam
(`_refresh_mirror` with older text after the sheet moved on leaves the copy alone); `recover` refuses when the sheet
changed since it was read (same seam); `recover` then Sigma's `fold` leaves a Sigma-schema sheet with
`monotonic_violations` empty; a legacy shard beside a recovered entry is a #314 delta; dry-run migrate writes
nothing; `coexist.gate` output is unchanged.

## Risks
Nothing here rewrites the tracked sheet unprompted; `recover` is an explicit gesture with a reviewable diff. The copy
is machine-local state written for every user (so a predecessor installed later is covered): one file the size of
the sheet. The signal can repeat on every gated verb while the predecessor keeps emptying the sheet; that is the
point (liveness) and the docs say how to stop it (stop the predecessor, then `recover`).
