# #1045 plan: cards for the script-bearing skills (slice 2 of #805, epic #1043)

## Goal / done_when
Add `evals/skills/cards/<skill>.json` for every skill that has a `scripts/*.py|sh` file on disk (19
today; derived, never typed), plus tests scoped to those cards. done_when: for those cards the runner
reports no finding; the `library` stems across cards equal `LIBRARY_ONLY` both ways; each `exercised`
card has a fixture that passes; no card holds a home or absolute path. The real-tree runner stays red
for the prose-only skills until slice 3 and is NOT made a required gate here.

## Files
- new: one `evals/skills/cards/<skill>.json` per script-bearing skill (stem == directory name).
- edit: `tests/test_skill_smoke.py` (new tests only), `evals/README.md` (one short paragraph: cards
  exist for the script skills, the `--help` citation, the real-tree runner is still red for prose skills),

- the generator is a scratch script outside the tree, run once, not committed. Its output is reviewed as JSON.

## Design
- Script entries: the generator globs `skills/*/scripts/*.py|sh` (non-recursive, as the runner does),
  loads `LIBRARY_ONLY` by path from `tests/test_script_help.py` (never parsing text), and writes
  `role: library` for stems in that set, `gesture` otherwise. Counts (skills, files, library) are
  printed by the generator for the PR body and never written into a card or test message. Today:
  152 files, 57 library stems (the design said 38; it has grown), all 57 sit in these skills.
- Kinds, per the runner's rules (an `exercised` card needs a passing gesture fixture; a gesture on an
  exercised card MUST have a fixture):
  - `exercised` only where a real fixture passes from the repo root, read-only, argv list, no shell:
    sigma-velocity (`python3 skills/sigma-velocity/scripts/velocity.py measure . 7`, expect `velocity (last`),
    sigma-model (`predict.py "Rename a variable" .sdlc`, expect nothing beyond exit 0; tier text can vary
    with config), sigma-doctor (`enforcement_table.py` only if a read of it shows no write default),
    sigma-loop (`render.py status --json <facts>`, facts copied from the SLOT/STATUS dicts in
    `tests/test_render.py`, not invented; first guess with raw emoji was REFUSED).
  - BUT on an exercised card EVERY gesture needs a fixture, and a skill like sigma-loop has dozens of
    gestures. The runner has no per-script exemption. So a card may be `exercised` only if each gesture
    entry has a fixture. Decision rule in the generator: if a skill has gestures without a real fixture,
    its card is `pinned` (>=1 verbatim gate) or `described`, never `exercised`. Expect velocity, model
    and probably doctor-only-if-all-4-covered to qualify; sigma-loop will not (62 gestures) and is
    `pinned`. The render.py fixture is therefore not used on the loop card unless a `--help` fixture per
    other gesture is accepted, which is rejected: it duplicates `test_script_help` and mislabels. Record
    the final exercised set as measured, not as promised here.
  - `--help` is never a fixture on an `exercised` card.
  - `pinned`: card carries >=1 gate; gate strings are hand-picked sentences copied verbatim from the
    first 20,000 chars of that SKILL.md (the runner checks it). `described`: no gates, no fixtures.
    A script skill with a gate and no passing fixture is `pinned`; with neither, `described`.
- Artifacts: only paths the SKILL.md itself names. For each, grep the writer
  (`grep -rn '<fragment>' skills/*/scripts hooks`) and READ the writing line before naming a producer;
  paste the grep and the conclusion into the PR body. Settled so far from research:
  - `agent` (SKILL.md tells the agent to write it, no script writes it): `.sdlc/knowledge/align/<UTC-date>.md`,
    `.sdlc/knowledge/audit/<UTC-date>.md`, `.sdlc/design/<n>.md` (`design_goal.py` composes instructions,
    no write), `.sdlc/plans/<goal-stem>.md`.
  - `.sdlc/plans/scope/<slug>.plan.json`: NO confirmed writer. `compile_plan.py` and `scope.py` only read
    it (scope.py writes `.report.json` via `--report`); `assign.py:585` writes a plan file and must be
    read before it is ruled in or out. Unless that read proves it writes this exact file, producer is
    `agent`.
  - script producers (repo-relative, must exist): `.sdlc/knowledge/radar/<UTC-date>.md` only if the
    digest writer is found (otherwise `agent`; `radar.py` appends `ledger.md`, a different file);
    `.sdlc/knowledge/analysis` and `.sdlc/state/kg-refresh.json` to `skills/sigma-kg/scripts/kg.py`;
    `.sdlc/intake/<sha12>.json` to `skills/sigma-prd-intake/scripts/intake.py`; `.sdlc/state/init.json` to
    `skills/sigma-init/scripts/init_flow.py`; `.sdlc/project.md` to `skills/sigma-init/scripts/sdlc_init.py`;
    `.sdlc/state/review-queue.md` to `skills/sigma-loop/scripts/state.py`; `.sdlc/state/log/*.jsonl` to
    `skills/sigma-loop/scripts/actionlog.py`; `.sdlc/features/index.json` to
    `skills/sigma-loop/scripts/feature_registry.py`. Each stays conditional on the confirming read in step 3.
  - A path SKILL.md only reads (config.json, goals, north-star) is not an artifact of that skill; omit it.
- `--help` citation: the schema has no field for it and the runner is not edited (the design needs none:
  D-8 says gesture entries cite `test_script_help`). Cite it in two places only: a paragraph in
  `evals/README.md` and the docstring of the new test file section, naming
  `test_every_script_answers_help_without_side_effects` (covers `*.py`) and
  `test_shell_scripts_have_a_help_handler` (the `.sh` gestures, grep only, not executed).
- New tests in `tests/test_skill_smoke.py`, all scoped by a derived `SCRIPT_SKILLS` set (directories that
  hold a `scripts/*.py|sh`), never by a typed list or count; they never run the whole real-tree runner as
  a gate:
  1. cards exist for exactly `SCRIPT_SKILLS` among those names (every script skill has a card).
  2. library stems across those cards == `LIBRARY_ONLY` (module loaded by path), both directions.
  3. `smoke.check(...)` on the real tree, findings filtered to lines naming a `SCRIPT_SKILLS` skill, are empty.
  4. no card text contains a home-directory prefix, a tilde, a leading `/` path value, or `..` in any path field.
  5. every card with kind `exercised` has a gesture fixture that the runner reports passing (zero findings
     for it, and at least one such card exists is NOT asserted, so removing the last exerciser does not
     redden unrelated code).
  Python 3.9 here (system python): no `match`, no `X | Y` annotations.

## Steps (test-first)
1. Add tests 1-5 to `tests/test_skill_smoke.py` with `cards/` absent; run them and see them red.
2. Write the scratch generator; run it; it writes the `scripts` arrays and `kind: described` with no
   gates/artifacts for all script skills. Tests 1, 2, 3, 4 go green.
3. Per skill (about 5 per sitting): choose gates from SKILL.md, read the writer for each named artifact,
   upgrade `kind` to `pinned`; for the fixture candidates run the argv from the repo root, confirm exit 0 and
   clean `git status`, upgrade to `exercised` only where every gesture has a fixture. Test 5 stays green.
4. README paragraph, test docstring, CHANGELOG bullet. Run `python3 -m pytest tests/test_skill_smoke.py
   tests/test_script_help.py tests/test_skill_structure.py -q`, then the full `tests/`.

## Controls (each guard broken once and seen red, then restored; outputs go in the PR body, not committed)
Run on the documented gesture, `python3 evals/skills/smoke.py` from the repo root (copied from
`evals/README.md`, not retyped), plus the pytest selector for the guard:
- library both ways: add a bogus stem as `library` to one card, red naming the stem; delete one library
  entry, red; restore.
- coverage: temporarily rename one card file, red `no card` for that skill; restore.
- gate: edit one pinned gate string by a character, red `not in kept prefix`; restore.
- producer: point one producer at a nonexistent repo path, red; restore.
- fixture: change `expect` text on an exercised card, red; restore. Change an exercised card's gesture
  to lack its fixture, red; restore.
- paths: put a home-directory path into a card, test 4 red; restore.
- new script: add an empty `.py` under a script skill's `scripts/`, red `in no card entry`; remove it.
Controls are done by editing and `git checkout`/re-write of the card, so leave the worktree as planned.

## Scalability / resiliency / safety
- Cost: one fixture subprocess per exercised card, each under about 0.5 s, sequential; at 100 script
  skills the runner stays linear in files. Measured only for velocity, predict.py and render.py on one
  macOS machine; the full runner time on the real tree is not measured in this slice (slice 4).
- Fixtures are read-only and shell-free; none uses `.sh` (not runnable on Windows).
- `velocity.py measure` on a shallow CI clone gives small counts but exits 0; `expect` is only the fixed
  prefix. Not measured on CI.
- Cards go stale if a script is added; that is the intended red.
