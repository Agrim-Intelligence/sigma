# #612 — trusted invocation receipts and truthful first-run controls: implementation plan

> **For agentic workers:** implement task-by-task under Sigma Loop, with a fresh independent review before publication. This planning pass makes no source edit, commit, PR, or label mutation.

**Goal:** Let an opted-in, independently installed host adapter authorize an autonomous review post or an evidenced phase-end relay, and otherwise defer safely; document the remaining first-run controls without claiming that Sigma can authenticate a host from process environment.

**Architecture:** Sigma owns the challenge, durable action lifecycle, local side-effect gate, and exact rendered payload. A separately installed adapter is the trust boundary: an operator pins its executable path and SHA-256 in Git-local configuration, then Sigma invokes that exact regular file with a versioned JSON ABI. The adapter returns a receipt only after its own host-specific proof; Sigma never treats environment markers, `PATH`, a configuration string, a process tree, or a deterministic test double as host authority.

**Tech stack:** Python standard library; existing `state.py` safe-path helpers and POSIX `fcntl.flock`; canonical JSON; Git-local operator configuration; an external adapter executable. No secret, private key, host session token, or transcript is stored by Sigma.

**Spec inputs:** `.sdlc/acceptance/612.md`, `.sdlc/research/612.md`, and GitHub issue #612. `north_star.py .sdlc` returned `absent` for `.sdlc/context/north-star.md` on 2026-10-09, so no additional project-specific architecture rule applies; the standing Reliability, Scalability, Resiliency, Safety, and Liveness rules in `AGENTS.md` remain binding.

## Scope and non-claims

This replaces the prior plan's under-specified “configured verifier” with a concrete, fail-closed protocol. It does **not** build a pretend host detector or claim that a stock Claude, Codex, or Cursor install can prove UI visibility. Built-in host markers remain usability hints only and cannot authorize a post, merge, host-specific coexistence path, or relay success. Until an operator installs a conforming adapter, all three hosts take the attended/defer path.

The checked-in configuration selects only an adapter identifier and bounded policy. The security root is outside the repository: the operator explicitly sets two Git-local values for the project, `sigma.invocation.adapter.<id>.path` and `sigma.invocation.adapter.<id>.sha256`. At every use Sigma resolves the configured absolute path without `PATH`, requires a regular non-symlink file owned by the current user, hashes its current bytes, and refuses if it differs from the pinned 64-hex digest. The owner of that local Git configuration and executable is trusted to install a real adapter; a same-user adversary able to replace both is already outside this mechanism's threat boundary. Repository config, environment, and tracked files cannot set or replace this root.

## Global constraints

- Add no third-party cryptography dependency. The adapter may use its own host credentials/signature scheme; Sigma authenticates the adapter execution through the operator-pinned path and digest and validates only the strict ABI below.
- Refuse autonomous action on Windows/no `fcntl`, lock timeout, unsafe state path, missing/mismatched pin, malformed/expired/replayed receipt, unknown adapter, adapter timeout, or ambiguous external write. Do not silently downgrade to inline approval.
- All mutable receipt state lives under `.sdlc/state/invocations/`, is bounded to one regular JSON file per action plus a fixed lock stripe, and is written with `O_NOFOLLOW`, component `lstat`, `fsync`, and atomic `os.replace` while holding a stable non-replaced lock file. Never use the fail-open state cursor lock for this security boundary.
- Receipt TTL defaults to 300 seconds, accepts only integer 30–600 seconds, and limits each action to one adapter invocation plus one recovery read; at 10x/100x concurrent requests the fixed 256 lock stripes bound unrelated contention while equal action IDs serialize exactly. Refuse instead of evicting an unexpired record.
- Local phase accounting/action-log boundaries remain local evidence. A relay acknowledgement means the adapter acknowledged exact bytes; it is not a claim that an arbitrary UI displayed them unless that adapter's documented conformance says so.

## Exact adapter ABI and receipt lifecycle

`invocation.py begin` creates a random 256-bit `action_id`, a random 256-bit nonce, and canonical UTF-8 JSON with sorted keys and no insignificant whitespace. The immutable challenge fields are:

```json
{
  "v": 1,
  "kind": "review-post|phase-relay",
  "action_id": "base64url-43-char-random-id",
  "adapter_id": "claude|codex|cursor|operator-id",
  "repo_realpath": "/absolute/real/path",
  "goal": "612",
  "phase": "review|null",
  "pr": 123,
  "head_sha": "40-lowercase-hex|null",
  "brief_sha256": "64-lowercase-hex|null",
  "payload_sha256": "64-lowercase-hex",
  "issued_at": "RFC3339-Z",
  "expires_at": "RFC3339-Z",
  "nonce": "base64url-43-char-random-id"
}
```

For `review-post`, `payload_sha256` is the exact immutable review-evidence file bytes and the adapter receives no PR token or merge authority. For `phase-relay`, it is the SHA-256 of the one rendered Block B UTF-8 byte sequence; the adapter receives those exact bytes base64-encoded in a separate request field and must acknowledge the same digest. Null is permitted only for fields irrelevant to the `kind`; all other types/ranges are exact and extra fields reject.

Sigma sends the adapter exactly one JSON request on stdin, argv `[pinned_path, "verify", "--stdio"]`, with `start_new_session=True`, a 30-second bounded process-group timeout, no shell, inherited environment reduced to locale plus `SIGMA_INVOCATION_V=1`, and no secret. Its one-line canonical JSON response must contain exactly `v`, `action_id`, `adapter_id`, `challenge_sha256`, `receipt_id`, `status`, and `ack_sha256`; `status` is only `accepted` or `deferred`. `accepted` must bind the challenge digest and payload digest; `deferred` performs no autonomous side effect. Any stderr is diagnostic only; extra output, a nonzero exit, timeout, duplicate receipt ID, unknown fields, or non-canonical JSON refuses.

The durable record transitions, all under the action lock, are `issued -> verified -> effect_started -> effect_succeeded` or `issued -> deferred|refused|expired`. Sigma writes `verified` **before** any GitHub/local external action, including the receipt and payload digest but never raw adapter output. A retry of `effect_started` never calls the write again: it first performs the existing deterministic GitHub/read-side idempotency check keyed by action ID; `present` becomes `effect_succeeded`, `absent` becomes `effect_unknown` and parks for attended recovery. A crash after `verified` and before `effect_started` reuses that verified receipt only while unexpired; after expiry it refuses and starts a new action, never replays the prior receipt. A crash after the adapter call but before `verified` is treated as no receipt and must obtain a new challenge; the adapter must therefore treat `(action_id, nonce)` idempotently and return the same receipt or a defer.

## Review focus

- A repo-controlled `review.host`, `CODEX_THREAD_ID`, or `CLAUDECODE` must never turn a deferred run into an autonomous post.
- An adapter binary changed after operator pinning, a symlinked pin, and a path with a substituted inode must all refuse before execution.
- A crash at each lifecycle boundary must make at most one remote write and leave a visible attended-recovery state, not an ambiguous retry.
- A phase-end acknowledgement for a different byte sequence, phase, goal, or expired action must never be recorded as host-visible.
- Simulation controls for Claude/Codex/Cursor must be labelled protocol conformance only; a missing live adapter must remain a safe defer, not a passing “live host” test.

## Task 1 — fail-closed trusted adapter boundary

**Interfaces produced:**

```python
begin(sdlc_dir: str, challenge: dict) -> dict  # immutable issued action
verify(sdlc_dir: str, action_id: str, request_bytes: bytes) -> dict  # verified/deferred/refused
current_receipt(sdlc_dir: str, action_id: str, *, kind: str, bindings: dict) -> dict | None
```

1. Write the new invocation test file first. Parameterize `claude`, `codex`, and `cursor` through a deterministic fake adapter, explicitly named `protocol simulation`, proving each can parse the same ABI but not claiming host capture. Run it red for an absent `invocation.py`.
2. Add failing controls for every trust-root failure: repo config attempting to name a command; environment path/marker changes; relative, symlinked, nonregular, wrong-owner, changed-hash, malformed-local-config, and unknown adapter pins; a `PATH` shadow executable; and a changed inode after open. Assert the adapter is never run.
3. Implement local-pin resolution using `git -C <repo_realpath> config --local --get`, absolute-path validation, `lstat`/`fstat` inode equality, `O_NOFOLLOW`, SHA-256 comparison, and argv execution. Keep trusted values out of `config.json`, logs, challenge, receipt state, and human output.
4. Add red controls for canonical challenge bytes, all schema/type/range/extra-field failures, stale/future timestamps, wrong repo/goal/phase/PR/head/brief/payload digest, non-canonical response, duplicate receipt ID, adapter timeout/nonzero/extra stdout, and accepted-versus-deferred behavior. Deliberately alter one hash comparison to demonstrate a red test, then restore it.
5. Implement version-1 canonical JSON and strict one-line ABI. Store only action/binding/digest/status/timestamps/receipt ID; scrub secret-shaped adapter output. Run the focused suite green.

## Task 2 — durable action state, locking, and crash recovery

**Interfaces consumed/produced:** Task 1 functions plus `claim_effect()` and `finish_effect()` returning one of `execute`, `already-succeeded`, `attended-recovery`, or `refused`.

1. Write red tests for simultaneous verification of one action, 10x and 100x action sets, every crash transition, lock timeout, no-`fcntl`, `ENOLCK`, a symlinked `state`, `invocations`, record, lock, and temp path, and a path/inode swap during lock acquisition. Assert each unsafe or unavailable lock refuses rather than using an unlocked write.
2. Implement a dedicated stable `state/invocations/locks/<two-hex>.lock` lock with `O_NOFOLLOW`, component checks, `fstat`/`lstat` equality after flock, 5-second bounded wait, and `fcntl.LOCK_EX`; no `fcntl` or any lock/open/stat error is a public refusal. Publish action records to a checked same-directory temp regular file, `fsync`, then `os.replace`, and re-check state paths before each reopen.
3. Implement the exact lifecycle and recovery table above. Add a deterministic action marker to the existing review-post body/idempotency reader so ambiguous GitHub completion is read before any retry. `effect_unknown` parks with the action ID and recovery gesture; it never retries a remote write unattended.
4. Prove red/green controls and run `python3 -m pytest tests/test_invocation.py tests/test_work.py -q`.

## Task 5 — adapter registry and honest host coverage

1. Add a small static registry in `invocation.py`: `claude`, `codex`, and `cursor` each require ABI version 1, `review-post` and `phase-relay`, and an operator pin. Unknown IDs refuse. The registry is capability metadata, not a command registry; it has no built-in executable.
2. Add `invocation.py diagnose <sdlc> <adapter-id>` that validates the pin and invokes `describe --stdio`; it reports only `installed-and-conforming`, `defer`, or `refused`, with no auto-fix. The `describe` response must exactly declare the registry capabilities and ABI version.
3. Test each fake host adapter against the identical conformance vectors, labelled simulation; add missing-adapter controls for all three. Do not call them “live integration” in test names or docs. A separately installed host adapter may run the documented `diagnose` gesture as a live conformance check; absence is a safe defer.
