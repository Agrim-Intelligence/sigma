# Plan: #462 committed work records: documented ceiling plus a tested guard

Inputs: issue #462, `.sdlc/research/462.md`, `.sdlc/acceptance/462.md`. Worktree `.sdlc/work/462`.

## Decision
These are tracked project history, read only by goal stem, and deleting them deletes the audit trail,
so there is NO pruner. The 14 scanned rows get `intentionally unbounded`, each with a stated ceiling,
an owner and a reclaim lever that is a human git operation (tracked rows) or `rm` (the three gitignored
local-only rows). Growth is guarded by a small test, `tests/test_b6_462.py`, over `git ls-files`:
- per file: plans and research at most 131,072 B (128 KiB); acceptance at most `acceptance.MAX_BYTES`
  (32,768, imported so there is one source). Justification: the largest tracked file is 89,108 B (plan)
  and 25,656 B (research); the largest pending, not-yet-committed ones are 92,603 B (plan) and 82,252 B
  (research), so 128 KiB clears every real file by 1.4x or more and still stops a 4x runaway; a plan
  that big is also about 32k tokens the reviewer must read whole.
- per goal on average: tracked bytes at most 32,768 B times the distinct goal stems. Measured mean is
  11,645 B tracked (14,318 B counting the pending files), so the ceiling is 2.3x the worst measured mean.
  Projected ceiling at 10x/100x goals: 770 goals about 25 MB, 7,700 goals about 252 MB of working tree;
  at the measured mean 9 MB / 90 MB (packed history about 0.73x of that, raw about 1.9x).
Raising a cap is a reviewed edit of the constants and the doc together; a test fails if they disagree.

## Design
- `docs/launch/b6-committed-work-records.md`: ownership table from each writer, readers traced,
  measurements with commands, what was not measured, 10x/100x, ceilings, owner, reclaim lever (human
  git: `git rm` the files of a retired goal range in a reviewed commit, optionally with a history
  rewrite by a maintainer; Sigma never does either), recovery, public-snapshot unknown, adopters'
  repositories are not covered by the guard. One-line link from `growth-audit.md`.
- `docs/launch/dispositions/462.json`: 14 entries, text copied from the scan, no `unscanned`.
- `tests/test_b6_462.py`: the guard `records_over_ceiling(root)` (git ls-files in `root`; raises when `root` is
  not its own git toplevel, so it can never read an enclosing checkout) and the nodes below. No change to any
  Sigma script, so no new write site and no inventory change.

## Tests
- `tests/test_b6_462.py`

## Test notes
Unparameterized nodes (one assertion family each, so a red proof attributes every node):
`test_covers` (exactly the 14 patterns, no `unscanned`); `test_decisions` (every row starts
`intentionally unbounded`, names its owner/reclaim, tracked rows name the guard); `test_real_tree`
(the guard is clean on this repository, and is not vacuous: it scanned more than zero records);
`test_plan_cap`, `test_research_cap`, `test_acceptance_cap` (scratch git repo with a tracked file at the
cap passes and at cap+1 is reported); `test_mean_cap` (many small goals pass, one goal over the average
ceiling is reported); `test_untracked_not_counted` (an untracked big file is not history);
`test_doc_constants` (the doc states the same cap numbers as the code); `test_no_pruner` (no
`goal_state_prune` family and no Sigma source names plans/research/acceptance as a prune target);
`test_audit` (the exact gesture parsed out of growth-audit.md, run in a scratch copy, shows the 14 rows
out of `unresolved_patterns` and carrying `pruner_or_cap`/`decision`).

## Controls (each broken once, seen red, restored)
1. Guard returns `[]` -> the three cap nodes and mean node red.
2. Drop the research branch of the guard -> `test_research_cap` red.
3. Set the plan cap to 1 -> `test_real_tree` red.
4. Delete `462.json` -> `test_covers` and `test_audit` red, `test_audit` run with the gesture from the doc.
5. Docs gesture: `git add` a 200 KiB `.sdlc/plans/zz-control.md` in the worktree and run the exact
   command the doc prescribes (`python3 -m pytest tests/test_b6_462.py`) -> red; remove, green.
6. Add `plans` to `goal_state_prune.FILE_FAMILIES` -> `test_no_pruner` red.

## Scale / recovery
Guard cost: one `git ls-files` plus one `stat` per record; at 7,700 goals about 23k files, milliseconds
to low tens of ms per test run (not measured at that size). Recovery: nothing to recover, the guard is
read-only; a red test is fixed by trimming the file or a reviewed cap raise. Lost files restore from git.
Partial failure: none, no writes. A maintainer reclaim is one reviewed commit, resumable.

## Definition of done
Nodes red on the old tree by assertion (no 462.json, no doc), green after; controls 1-6 red; growth-audit
gesture on a scratch copy resolves the 14 rows; `test_script_help`, `test_skill_structure`, write-surface
inventory and the secret-literal checks pass; full verify green.
