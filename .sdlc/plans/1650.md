## Decisions on the research's open questions

**F1 - verify deadline and liveness model. DECISION: (b) a held `flock` is the primary liveness for the refusal; pid + deadline is the classifier backstop the acceptance requires.**
- The refusal asks the KERNEL: a non-blocking `flock` on `state/call-runs/<goal>.verify.lock`, held by the verify process for its whole life, with the inode re-check copied from `_try_acquire_claim_lock` (`loop.py:466-505`). The kernel drops it on any death, so a reused pid can never hold a goal refused. That closes R1 for the refusal.
- The receipt keeps `pid`, `started_at`, `timeout_seconds` (the deadline is DERIVED `started_at + timeout_seconds + grace`, never stored, as in #1551) and `run_id`. The shared classifier reads dead pid, past deadline, malformed or nonce mismatch as `failed/not_completed`. `wait-call` uses the classifier only (it must not touch the lock: a read-only probe that takes the lock for a microsecond would make a real verify's own non-blocking acquire read "held" and refuse falsely).
- Deadline value: constant `VERIFY_RECEIPT_SECONDS = 14400` (4 h) in `loop.py`, grace 60 s. NO new config key and NO env var (each needs docs and a registry entry; the lever below makes them unnecessary). A verify that outlives 4 h reads `failed/not_completed` to `wait-call`; the real child is not killed (verify gains no timeout in this goal; D-4/#1571 are deferred). That is a stated limit, not a hidden one.
- **No lock, no refusal (review refinement 6).** `reviewer.pid_alive` returns True unconditionally off POSIX (`reviewer.py:602`), so a receipt-only refusal would lock a goal out for 4 h after any crash. Decision: where `fcntl` is missing or the lock file cannot be opened (`try_lock` returns `UNAVAILABLE`), verify runs EXACTLY as today (still writes its running receipt so `wait-call` works) and prints a loud stderr advisory `concurrency guard unavailable here: a second verify of this goal will NOT be refused`. Only a lock-backed check ever refuses, so there is no self-heal case and no deletion lever to document. This is a stated weaker guarantee, not a silent one.
- Refusal when the lock is HELD: the holder takes the lock BEFORE writing its receipt, so a refusal can see a held lock with a missing, unreadable or stale receipt; the line then reads `holder unknown (receipt not yet written)`. A held lock is refused regardless of what the receipt says (the kernel is the liveness authority).

**F2 - refusal keyed on run id? DECISION: NO. The refusal keys on a live lock plus a live receipt, regardless of `SIGMA_RUN_ID`.** The Codex hazard is the SAME session re-invoking verify after a yield, which has the same run id (or none, and the documented gesture in `landing.md` sets none). A run-id-keyed check would let exactly that through. "Built on the existing run-id check, not beside it" is met by: the receipt records `run` (= `state.run_identity()`), the refusal message names the holder's `run` and `pid`, and the old after-the-fact #498 warning block (`loop.py:5656-5674`, never fires in practice because the writer pid is the verify process that exits right after writing, and no test covers it - research D-1) is DELETED so there is one concurrency check, not two. `state.done_refusal`'s run-id mismatch logic is untouched (that is the evidence-stealing defence, a different job). Plan-review is asked to confirm this reading.

**F3 - refusal exit code. DECISION: a new exit 6, not 4.** Exit 4 already routes to "worktree stale, rebase" in SKILL.md and `landing.md`; a caller seeing 4 would do the wrong thing. Stderr line: `REFUSED exit=6 -- a verify for goal <g> is already running (pid P, run <r>); wait with <gesture>; do not re-run`. The `verify_goal` docstring exit list and the `loop.py` USAGE line gain 6 and `wait-call`.

**F4 - wait-call semantics. DECISION: reviewer precedent. A receipt is "final" (exit 0) when the call COMPLETED and returned, whatever its result; the stored result line is printed so the caller routes on it exactly as on a direct call.**
- `ok` receipt (verify returned any exit code, merge returned any string) -> exit 0; stdout prints the stored result (`result`, capped 500 chars) and `exit=<n>` for verify. Merge's first word (`PR #N merged`, `PARK:`, ...) is therefore still the router. Reason: a red verify and a `PARK:` are answers, not crashes; mapping them to 1 would make a yielded caller re-run a verify that already answered. Landing.md says explicitly "0 means finished, not passed: read the first word / `exit=`".
- `failed` / not-completed (dead pid, past deadline, malformed, runner raised) -> exit 1, stderr names the reason and says what is safe: verify may be re-run; merge `re-run only when the gesture in landing.md says so` (the existing paragraph already distinguishes a cut during gate from a cut during the merge call; wait-call text repeats it: after a failed merge receipt run `loop.py record .sdlc "$goal" review` first, never re-run blindly).
- running at the bound -> exit 3, stdout `RUNNING pid=.. run_id=.. elapsed=..s deadline_in=..s` (same shape as the reviewer).
- missing / unreadable / unsafe goal / another `--run-id` / bad usage -> exit 2 (reviewer's mapping; the acceptance names only 0, 1, 3, so 2 is added and documented). A `wait-call` after `work.py finish` reads missing -> 2, accepted (R7).
- Default `--max-seconds` 20 (`WAIT_DEFAULT_SECONDS`, below the 30.2 s yield); the CLI clamps 1..3600.

## Other decisions
- **Merge deadline**: DERIVED in code from the constants (`work.merge_budget_seconds()`), not the documented 1,350,000: `(BEHIND_REBASES+1) * gate_worst + BEHIND_REBASES * (BEHIND_ATTEMPTS * one_gate + backoff_sum) + RECONCILE_ATTEMPTS * RECONCILE_PAUSE`, where `gate_worst = (PENDING_ATTEMPTS+1) * unknown_backoff_sum + PENDING_ATTEMPTS * PENDING_INTERVAL` and the backoffs are summed from `UNKNOWN_BACKOFF`, `BEHIND_BACKOFF`, `BEHIND_BACKOFF_MAX`. Grace 600 s for untimed `gh`/`git`. Result is about 44 min + grace by the research's arithmetic (DERIVED; D-4 stays open: a hung `gh` can outlive the deadline and the receipt then reads failed while merge lives - stated). `landing.md`'s 22.5 min figure is corrected to point at the derived number rather than hard-code a new one.
- **Merge receipt wraps `main()` only**, not `merge()`: unit tests call `work.merge(d, cfg, goal, run=fake, sleep=NOSLEEP)` 773+ times and must see no new files. The wrapper is `work.merge_with_receipt(sdlc_dir, config, goal, **kw)`, used by `_COMMANDS["merge"]`'s CLI call. It returns the inner string unchanged, so the first-word contract (`main` prints it to stdout, `:8376-8378`) is byte-identical. The launch hint goes to stderr only. No concurrency refusal for merge (not in the acceptance; a second merge is idempotent by the documented contract and the nonce keeps receipts honest). **Refinement 10**: before writing its running receipt, `merge_with_receipt` reads the existing merge receipt through the shared classifier; if it classifies `running` (live pid, unexpired) it prints one stderr line `a merge for goal <g> already has a live receipt (pid P); proceeding (merge is idempotent)` and still proceeds.
- **Receipt location**: `<sdlc>/state/call-runs/<goal>.verify.json`, `<goal>.merge.json`, `<goal>.verify.lock`. NOT in `state/verify/` (frozen contract kind, `contract/README.md:34`). Reviewer keeps `state/reviewer-runs/` (no behaviour change, no path migration).
- **sdlc path (R5, refinement 9)**: guard and receipts are keyed on the sdlc dir the caller GIVES. `work.py` exposes no cheap main-checkout canonicaliser (grepped `work.py`, `loop.py`, `state.py`: no helper), so canonicalising is NOT done; instead it is a NAMED LIMIT: a verify run with a worktree-relative `.sdlc` locks a different `state/` than the loop's main-checkout `.sdlc`, so the two are not mutually refused. The loop always passes the main checkout's dir and `landing.md` says so; the printed gesture carries the resolved absolute dir so `wait-call` reads the same files as the writer. Both writers and `wait-call` use `pathlib.Path(sdlc_dir).resolve()` of the directory they were GIVEN, and the printed gesture carries that absolute path, so a relative `.sdlc` typed in a worktree prints the worktree's absolute dir and wait-call reads the same files. (The loop always passes the main checkout's `.sdlc`; a test covers the relative-path-with-chdir case.) The gesture also uses the absolute `loop.py` path (`Path(__file__).resolve().with_name("loop.py")`), so it works from any cwd.
- **Order in `verify_goal`** (R6): unsafe goal -> config/acceptance -> NO-COMMAND -> enforce-needs-record, THEN lock + refuse + running receipt, THEN `work.ensure_fresh` (may auto-rebase), then the child. STALE (exit 4) and every later return finalises the receipt via a wrapper with try/finally. **`guard.finish` is a no-op unless `begin()` won the lock (refinement 3)**: a refused second verify and every pre-begin early return (exit 2 unsafe goal / invalid acceptance, exit 3 NO-COMMAND, exit 4 enforce-needs-record) leave the holder's receipt byte-identical and create no receipt and no lock file.
- **finish vs a live merge (refinement 7)**: `work.finish` is reachable (`record done` / merge-reconcile, `work.py:7096-7120`) while `merge()` is still in its post-land steps, which would delete the receipt and drop the final write (`run_receipt.finish` then sees FileNotFound and does not resurrect), so `wait-call` would exit 2 after a SUCCESSFUL merge. Fix, both halves: (1) `finish` skips (does not delete) a call-run receipt whose state classifies `running` with a live pid; prune clears it later once final or dead; (2) the `wait-call` exit-2 `missing` text says `no receipt: it was never written, or work.py finish already cleared it. Check the PR / goal status before acting; do not re-run blindly`.
- **D-6**: `phase_gate.py:155` calls reviewer's private `_wait_gesture`; add a public alias `wait_gesture` in reviewer.py and switch phase_gate to it (2 lines). `_wait_gesture` stays as a re-export.
- Out of scope, named: the already-merged short-circuit (design slice 1), #1673, #1571, D-3 (non-atomic evidence write), D-4 (untimed `work._run`), pruning of `reviewer-runs/` beyond today's `finish` (existing, unchanged).
