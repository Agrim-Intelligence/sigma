## Design decisions (each answers a research finding)
1. Order inside `check_plan(sdlc_dir, goal, plan=None)` (R2): (a) legacy first: `dossier_text` empty, or no `## Reuse`, or not `is_new_format`, returns `([], ["legacy goal (<why>); plan inputs not checked"])` whether or not a plan exists (FR-25 and AC-4 allow no exception; `red_green.py check-tests` already refuses a missing plan). (b) Only for a new-format goal: plan path, `phase_doc_file` when `plan` is None; absent gives the one error `no plan for goal <goal>`. (c) Plan text over `MAX_CHARS` gives one error `plan: over 1048576 characters; nothing checked` (a cap on parsing, like the dossier's; the read itself is unbounded, stated in the docstring). (d) Rule 0. (e) Rules 1 to 4. (f) Rules 5 to 10. The issue lists "No plan file" before "Legacy goal" but as a list, not a precedence; this reading is recorded with `loop.py note` at Task 8 as the ground rules ask.
2. Rule 0: `errors = list(check_research(sdlc_dir, goal)[0])` first and unchanged; its warnings are carried through. When enforcement is on and there is no acceptance record, `check_research` reports its own `no recorded acceptance criteria ... record them before Research` and rule 10 adds its own line; both are kept (rule 0 says unchanged), documented in the docstring. With enforcement off and no record, the result holds exactly two warnings, in this order: `check_research`'s own `no recorded acceptance criteria for goal <goal>; one row per criterion was not checked`, then rule 10's `no recorded acceptance criteria for goal <goal>` (the issue's "one warning" is rule 10's own line). Tests assert that exact pair and, enforced, the exact two-error list (`check_research`'s `...; record them before Research` line, then rule 10's).
3. Plan `## Reuse` (rules 1 to 4): lines come from `_section_lines(text, "Reuse")`; `None` is `## Reuse: section missing`. Bullets use their own regex `- (RU-[0-9]+):(?:[ \t](.*))?$` over those lines, which accepts an empty remainder (research TD-2: `parse_reuse` would count them as queries); the text is stripped and an empty one gives `RU-<n>: bullet text is empty`. A research row id with no bullet gives `RU-<n>: no bullet in the plan's ## Reuse for this research row`. A bullet for an id the dossier does not have is not an error, and a repeated bullet id is not an error either (rule 2 asks for one bullet per row, not exactly one; no rule refuses either, so none is invented). The plan's `|` lines are joined under a first line `## Reuse` (`parse_reuse` reads `_section_lines(text, "Reuse")`, so the block must start with that heading) and given to `parse_reuse` so the existing `_table` code is the only table parser; `table_errors(parsed, root)` supplies the row rules (a departure from the issue's naming `reuse_errors`, recorded at Task 8.3); each row id that is also a dossier row id gets `RU-<n>: id collides with a row of the research dossier`. `root` is `review_tests._root(sdlc_dir, goal)`. Rule 4 (R5): a plan `none:` line always needs a non-empty reason (`## Reuse: none: needs a reason`); it is allowed only when the dossier's parsed `none` is not None and it has no rows (a new-format dossier always carries `**Source:**`/`**Searched at:**` lines, so "the single `none:` line" is read through `parse_reuse`, not literally), and it never excuses a missing bullet when the dossier has rows: rule 2 still names every such id. A plan `none:` line with a rows-bearing dossier gets exactly those per-id errors and no error of its own. With a `none:` dossier the plan's section may be exactly that one line; anything else there is judged by rules 1 to 3 (no RU rows exist to cite, so the section need only exist).
4. Plan `## Test map` (rules 5 to 9): `_section_lines(text, "Test map")`, fence-aware, `None` gives `## Test map: section missing`. Bullets use `- (AC-[0-9]+):(?:[ \t](.*))?$` (an empty remainder is accepted), and an empty or blank value gives `AC-<n>: value is empty; map a test or write UNTESTABLE: <why>`; a bullet outside the section is never seen. Rule 6 is two checks: every criterion id has exactly one bullet (`AC-<n>: no bullet in ## Test map` / `AC-<n>: more than one bullet`) and no bullet for an unknown id (`AC-<n>: not an acceptance criterion of goal <goal>`).
5. Values (rule 7), in `review_tests.check`'s order so the two readers look the same: `review_tests._NONE.match` first gives `AC-<n>: NONE is refused; map a test or write UNTESTABLE: <why>` (anchored `^NONE\b`, case-insensitive: `NONE`, `none`, `None: x` are refused); then `review_tests._UNTESTABLE.match` with `group(1).strip() == ""` gives `AC-<n>: UNTESTABLE needs a reason`, a non-empty reason passes. The two patterns are anchored on different first words and cannot both match, so their order is not a clause and has no control. Otherwise a test list.
6. Coverage (rule 8): `red_green.none_reason(plan)` is called first (docs-only form). Else `red_green.selectors(plan, runners)`; a `ValueError` (covers the `_rejected` subclass and the lone `none:` form) means coverage is not judged: no test-map error is returned for the broken `## Tests` (the existing `check-tests` speaks), and one warning `## Test map: coverage not judged (<the ValueError text, first line>)` is returned so the skip is visible (F2); the id and value checks still run. A value is first matched whole against the entries (so a runner bullet `pytest: file > suite > test` whose name holds a comma matches exactly), then split on commas and each part stripped. A part is covered when it equals an entry, or an entry has no `::` and the part starts with `entry + "::"`. An entry for which the loaded `red_green.parse_runner(entry)` is truthy (a runner bullet; the function is public) is exact-match only, never a file prefix. Uncovered part: `AC-<n>: <test> is not covered by a ## Tests entry`.
7. Docs-only (rule 9): when `none_reason(plan)` is not None, `## Test map` may be exactly one `none: <reason>` line with a non-empty reason (empty reason: `## Test map: none: needs a reason`); per-criterion bullets are then not required. A `none:` Test map with a code `## Tests` adds no special error: rule 6 already names every criterion id as having no bullet (F1).
8. Runners: `state.test_runners(state.load_config(sdlc_dir))`; `state.ConfigMissing` (a goal worktree's `.sdlc` has no config.json) is read as `{}`, never an error and no warning. Any other config error also reads as `{}` for the runner map only; runner bullets then fail `selectors` with a `ValueError`, which is the coverage-not-judged warning of design 6 (F2), so a corrupt config is visible, but only when the plan's `## Tests` names a runner bullet; with a pytest-only `## Tests` a corrupt config stays silent for coverage (while `_enforced` reads it as on), a limit the docstring names. `_enforced` keeps its own fail-closed read for rule 10.
9. Criteria (rule 10): `review_tests.criteria(sdlc_dir, goal)`; `OSError` or `ValueError` gives, with `_enforced` on, one error `no recorded acceptance criteria for goal <goal>` (after `check_research`'s own line, so the enforced result is exactly those two errors); off, one warning of the same text, and rules 6 to 8 are skipped (rules 1 to 5 and 9's none-line still run).
10. Every error starts with the id it is about (`RU-3`, `AC-2`) or the section name (`## Reuse`, `## Test map`) and names the rule. The command line prints at most `MAX_SHOWN_ERRORS` (50) and a count, reusing the constant and the same loop shape as `check-research`.
11. CLI: `reuse.py check-plan <sdlc_dir> <goal>` (exactly two arguments after the verb; any other shape prints `USAGE`, exit 2). Warnings then errors go to stderr prefixed `reuse.py: `; errors exit 2; else stdout `reuse.py: ## Reuse and ## Test map in <plan> are complete (<n> rows cited, <k> criteria mapped)` and exit 0. `<plan>` is the path as resolved; `<n>` is the number of RU bullets read; `<k>` the number of criteria mapped (0 for docs-only). A legacy goal exits 0, prints the warning to stderr, nothing to stdout, in the same shape as `check-research`. `USAGE` keeps `usage: reuse.py check-research ` first because `tests/test_reuse.py` asserts the prefix.
12. Scalability and ceilings (stated in the docstring, measured at Task 6): cost is one `check_research` call (its own measured 0.47 s ceiling on 1 MiB) plus two section scans of at most 1 MiB of plan text and one criteria read, linear in plan size and in rows; the unbounded parts are the dossier and plan file reads themselves (read before the cap, as `check-research` does), not timed against a 1 MiB plan until Task 8.5 times the real shapes. Reference numbers are the module docstring's own (Apple M4 Pro, Python 3.12, measured for `check_research`): at most 0.47 s for the two parsers on any 1 MiB shape, 0.9 s for 1 MiB of 4,096-character evidence rows, and a 244 MB Python-allocation peak on 1 MiB of `|` rows. `check_plan` can pay that peak twice, once inside `check_research` and once if the plan itself is 1 MiB of `|` rows through `parse_reuse`; the memory ceiling is therefore about twice 244 MB, an inference from those numbers, not measured for `check_plan`. No file is written, no process is started beyond what `check_research` already starts (git for the Searched-at check). Nothing persists, so a crash mid-run leaves nothing to recover; a re-run is idempotent. The dossier is read twice (once by `dossier_text`, once inside `check_research`), and each read may fall back to a `git show` of the branch's copy; the docstring's ceilings line says so (F3).
13. Legacy text (R8): define three reasons once, `LEGACY_WHY_NO_DOSSIER = "no research dossier"`, `LEGACY_WHY_NO_SECTION = "the research dossier has no ## Reuse section"`, `LEGACY_WHY_OLD_SECTION = "## Reuse was not written from reuse.py brief"`, and rebuild `LEGACY_NO_DOSSIER` etc. as `"legacy goal (%s); nothing checked" % why`, so the check-research strings stay byte-identical (`tests/test_reuse.py` lines 29-31 guard that; run it). `check_plan` builds `"legacy goal (%s); plan inputs not checked" % why`. The legacy tests assert the exact strings, e.g. `legacy goal (no research dossier); plan inputs not checked`.
