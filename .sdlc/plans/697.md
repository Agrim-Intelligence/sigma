# Plan: #697 launch hardening 1/2

Inputs: issue #697, `.sdlc/research/697.md`, the owner decision of 2026-10-06 in the severity-review notes.

## Design
**(a) Trust-filter comment markers (#650 item 5).**
- `sources.py`: `TRUSTED_ASSOCIATIONS = ("OWNER","MEMBER","COLLABORATOR")` and one helper `untrusted_marker(comment, goal)` that returns True (and prints one stderr line naming commenter and association) when a comment carries a `sigma:`-brand marker (`legacy.MARKER_PREFIX_RE + ":"`) and its `authorAssociation` is not in the set. A marker comment with no `authorAssociation` key raises `ValueError` in the strict path.
- `fetch_comments` keeps returning every comment, now with `"association"` (empty string when gh omitted it).
- `backlog_check._fetch_scrubbed_comments` neutralises marker text in comments whose association is not trusted (replacing the `sigma:` brand token), so the dismissed-finding scan and `auto_unpark._is_exempt` (keep-parked) never see it, while the blocker-phrase scan still reads the prose. One fetch, as before.
- One shared helper in `sources.py`, `defuse_untrusted(comment_dicts, goal)`, handles BOTH brand spellings (`sigma` and the retired one, via `legacy.MARKER_PREFIX_RE`) and the replacement token cannot itself match `legacy.has_marker`. `unpark.brief` (a second dismissed-finding reader through `_filter_dismissal_comments`) uses it on its raw gh comments too.
- `GitHubSource.fetch_comments_strict` drops untrusted marker comments from its returned `comments` list (non-marker comments untouched), so decompose-filed, design-filed, feature-ownership, scope-expansion, feature-label flags and the acceptance dedupe are all covered at one seam. A comment with a marker and no `authorAssociation` raises (all callers already treat a strict-read raise as park or skip).
**(b)** `loop.py spend`: a negative count refuses with exit 2 and a stated message before any write. `state.add_tokens` and the `amount` in `state.record_phase_end` (third `run_tokens` writer) raise `ValueError` for a negative value; `phase_report` only passes non-negative priced tokens.
**(c)** `work.merge`: both `gh pr merge` calls (arm and direct) gain `--match-head-commit <sha>` where `<sha>` is `normalise_ci_rollup(final_data)["head_sha"].strip()`, the head `gate()` verified equal to the worktree. `gate()` already parks when that head is empty, so there is no unguarded path. `merge_design` and `skills/sigma-rebase/scripts/verify_merge.py` have no vetted head and are untouched: follow-ups.
**(d)** `_unresolved_threads` pages `reviewThreads(first:100, after:$cursor)` on `pageInfo{hasNextPage endCursor}` up to a bound of 50 pages (cursor passed as `-f after=<cursor>`, omitted on page 1). A read error on a later page returns the unresolved count already seen (never discards it); hitting the bound counts one extra unresolved thread so the merge is blocked, with one stderr line.
**(e)** `channel_notify._real_post` bypasses proxies (`ProxyHandler({})`) only when the URL host is `127.0.0.1`, `::1` or `localhost`; with `allow_remote_webhook: true` and a remote host the default opener (and so the operator's egress proxy) is kept.

## Limits stated
The trust set is GitHub's own association (MEMBER can be broader than write access); it is not a substitute for branch protection. A bot token with NONE association has its own loop-authored idempotency markers ignored (a duplicate flag comment, or a second decomposition/design filing); recorded as a known gap in `docs/enforcement.md`. Reviews and issue bodies are out of scope.
