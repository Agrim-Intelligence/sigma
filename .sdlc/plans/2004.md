## Interfaces (fixed before coding)
- `classify_file(path, generated_globs=(), header="")` -> one of `CLASSES`.
  Precedence: sensitive (risk-detect `SENSITIVE_GLOBS`, copied as `SENSITIVE_GLOBS` here, pinned equal by a test) > generated (configured glob OR header marker in `header`) > tests (test PATH only) > docs (`*.md`, `*.rst`, `*.txt`, `docs/`, `.sdlc/`) > handwritten.
- `classify_files([(path, n|"binary")], generated_globs, headers)` -> `{"files": {class: n}, "lines": {class: n}}`; every class key always present.
- `measure(top, remote, base, cfg)` -> that dict plus `"cap"`, `"over_cap"`; None when anything cannot be measured.
  It runs its OWN `git diff --numstat -z -M <merge-base> HEAD` (the PR is committed and clean at `pr`) and classifies a rename by its NEW path (not `zones._diff_counts`, which keys renames on the old path: `tests/x.py` -> `src/x.py` would otherwise stay "tests"). Deleted or unreadable-at-HEAD files have no header, so they fall to handwritten unless a configured glob matches.
- Header reads are bounded in count AND bytes: at most 500 files, one `git cat-file --batch-check` to learn sizes, then one `--batch` for blobs of at most 64 KiB, of which only the first 5 lines are read; a larger/absent blob or any file past 500 has no header -> handwritten (fails toward scrutiny).
- Sensitive globs mirror risk-detect.sh INCLUDING its exclusions: `.sdlc/**` and `docs/**` are never sensitive (they are docs). Project overrides in `.sdlc/risk-detect.conf` are NOT read (they need a shell opt-in); defaults only, stated in the docs.
- Cap counts handwritten + sensitive lines only (generated, tests and docs are excluded); default 400 from `work.slice_pr_soft_cap`; a non-int, bool or <1 value reads as the default; the check is strictly greater-than; advisory only.
- `pr()` placement: computed once the PR number is known, BEFORE the receipt block; `rec["size"]` is set and saved there so the receipt-pending early return still carries it; the note is appended only to the final success return `PR #N`, and only when over the cap, so the existing `== "PR #9"` assertions stay valid.
