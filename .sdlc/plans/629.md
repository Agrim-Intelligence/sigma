# Plan: #629 redact unquoted env-style secrets in scrub()

Inputs: issue #629, `.sdlc/research/629.md`, `.sdlc/acceptance/629.md`.

## Design

In `skills/sigma-loop/scripts/scrub.py` add two REDACTOR-ONLY entries to `_SECRET_PATTERN_SPECS` before the existing `credential-assignment` (left byte-identical): `credential-assignment-suffix` (below) and `authorization-header` (everything after the separator to end of line, since scheme words are open-ended). Both run BEFORE the gate-shaped `SHAPE_RULES` entries (post-PR review: the shape rule `credential-assignment` stops at an escaped quote and leaves a tail the suffix rule cannot then repair). Both are excluded from `COMMIT_SHAPE_RULES`, because the commit gate and `exposure_scan` share that table and the wide rules roughly double tracked-tree hits on ordinary code (measured 125 -> 253 hit lines). The suffix rule:

- Drop the leading and trailing `\b` (the key is matched as a suffix of the name; the prefix `GITHUB_` stays in the
  text untouched, so the key name is preserved).
- Add key names `auth`, `credential(s)`, `passphrase`, `access[_-]?key` to the existing list.
- Value: a quoted value is taken to its closing quote (escape-aware) or end of line when unterminated, so spaces
  inside no longer leave a tail; an unquoted value is a run of non-space characters, min 4 as today.
- No new leading character class, no nested quantifiers: each key occurrence costs O(1) plus the run it consumes, so
  total work is linear in the input. Stdlib `re` only.
- After the separator an optional scheme word (`Token`, `ApiKey`, `Bearer`, `Basic`, `Digest`) is consumed with the
  value, so an `Authorization` header with a `Token <v>` scheme leaves no tail. `secret_key_base` is a key name.
- Stated limits (pinned or documented): an UNQUOTED value containing spaces is cut at the first space; JSON key
  quoting is still mangled by the replacement (pre-existing; no secret survives); a `PWD` or `oauth` assignment
  is redacted (over-redaction accepted); `gh_auth=""` (empty quoted) is left alone; a key with a trailing suffix
  (`token_file`, `DB_PASSWORD_FILE`) is not matched.
- The commit gate (`commit_secret_hits`) and `exposure_scan` are kept identical (measured: same hit list on the tracked tree before and after, pinned by a test). Gate-side gap (env-style names are not caught at commit time) is out of scope; follow-up. `leak_scan` does not use this rule (it takes only
  labelled `[REDACTED:name]` entries), so it is unaffected.
- Fail toward redaction: an `auth` key with a plain-word value is redacted; accepted over-redaction. A key with a trailing suffix
  (`token_file=`) is NOT matched (stated limit; `tokens=4096`-style metrics must survive).

Not changed: `tools/leak_scan.py`, `tools/build_public_tree.py`, `SHAPE_RULES`. If the tracked-tree scan flags
existing text, fix that text or narrow, not the gate.
