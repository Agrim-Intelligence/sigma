  without `re.I`, so every arm below is case-sensitive and matches lowercase Python keywords only; capitalised
  prose ("Return 0 on success", "Import of a file...", "Class of error...") can never match a keyword arm. Arms:
  `\bdef\s+\w+\s*\(`, `\basync\s+def\s+\w+\s*\(`, `\bclass\s+\w+\s*[:(]` (anywhere in the line);
  line-start imports `^\s*import\s+[\w.]+(?:\s+as\s+\w+)?(?:\s*,\s*[\w.]+(?:\s+as\s+\w+)?)*\s*$` (covers
  `import os, sys`) and `^\s*from\s+[\w.]+\s+import\s+\S`; line-start return with an operator or bracket
  `^\s*return\b[^\n]*[=<>()\[\]]`; plain bare returns `^\s*return(?:\s+\w+(?:\.\w+)*)?\s*$` (covers `return`,
  `return result`, `return None`); a one-line compound `\b(?:if|elif|else|for|while)\b[^\n]*:\s*return\b`
  (covers `if x: return y`); a statement chained after a semicolon `;\s*(?:import|return)\s+\w` (covers

## Output contract grammar and caps
```
=== FILE: <relpath> ===
<python source lines>
=== END FILE ===
```
Grammar edges (each decided, each tested):
- Line endings: `\r\n` is normalised to `\n` before anything else; a CRLF-written block validates like an LF one.
- Marker lines tolerate TRAILING spaces and tabs (they are rstripped) and reject leading whitespace: an indented
  `=== FILE:` is body text, not a header.
- A `=== FILE:` header while a block is open is a finding ("block not terminated before next header"); the open
  block is discarded and the new header opens a fresh block, so later problems are still reported.
- A stray code fence (a line starting with three backticks or three tildes) OUTSIDE a block is a finding. Inside a
  block a fence is just source and will fail `ast.parse`.
- Only blocks and blank lines may appear outside a block; any other text there is a finding. An unterminated
  block at end of input is a finding.
- `<relpath>` is exactly `tests/acceptance/<stem>/<name>.py` where `tests` is the literal directory, `<stem>` is
  the caller-supplied goal stem (must match `[A-Za-z0-9_-]+`, else a finding) and `<name>` is constrained next.
  Forward slashes only; no `..`, no leading `/`, no NUL, no backslash, no nested subdirectory; `.py` only
  (case-sensitive: `.PY`, `.pyi`, `.txt` rejected). The `tests/acceptance` directory does not exist in the tree
  today (verified), hence the placeholder spelling.
- `<name>` must be pytest-collectable and, within one call, collision-free. Collection in this repo uses default
  import mode and `tests/` has no `__init__.py`, so a test module's basename must be unique across the whole
  collection. Rule: `<name>` must equal `test_acc_<s>_<suffix>` where `<s>` is the stem with every character
  outside `[A-Za-z0-9]` replaced by `_` and `<suffix>` matches `[A-Za-z0-9_]+`. `helper.py` is rejected (not
  collected by pytest's default `test_*.py` pattern); `test_x.py` without the `test_acc_<s>_` prefix is rejected;
  a prefix for a different stem is rejected. CAVEAT, stated honestly: the sanitising is not injective, so the
  stems `a-b` and `a_b` both yield `<s> = a_b` and their files can share a basename ACROSS two calls (or two
  goals); the validator sees one stem per call and cannot detect that. Within a call, duplicates are rejected
  (below). Cross-goal collision is therefore not prevented by this validator; it is a residual gap named for the
  sealing slices, which write the files. Existing top-level tests are named `test_<topic>.py` (verified: no
  `test_acc_*` file exists), so a clash with an existing top-level file is impossible today; a guard test asserts
  that no `tests/test_acc_*.py` exists outside the `acceptance` subdirectory.
- Duplicate names are rejected, compared case-folded (the directory is fixed by the stem, so duplicate path and
  duplicate basename coincide).
- Each block must `ast.parse` cleanly; define at least one MODULE-LEVEL `def`/`async def` named `test_*` (nested
  functions, class methods and strings do not count); and have no repo-internal import at module top: any
  `Import`/`ImportFrom` in the module body (including inside top-level `if`/`try`/`with`) is a finding unless its
  root is `pytest` or in `sys.stdlib_module_names`; a relative import is a finding. Imports inside function bodies
  are allowed (the breaker imports the code under test inside the test body). Allow-listing stdlib plus pytest
  fails closed with no repo scan.
- Fail closed without `sys.stdlib_module_names` (Python 3.9, the host): `validate_output` does not raise; when the
  attribute is missing and a block has a module-top import whose root is not `pytest`, it returns the finding
  "cannot classify imports on this Python (no sys.stdlib_module_names)". Blocks with no such import validate
  normally, so nothing is silently half-checked and nothing crashes.
- `validate_output(text, stem) -> (ok, findings)`, findings a list of strings, ALL returned. `text` may be `str` or
  `bytes` (strict UTF-8 decode; failure is a finding). Empty or whitespace-only output is a finding. Pure
  function: validates strings, writes nothing, never executes the text.
- Caps, DERIVED: `_MAX_CRITERIA = 7` (pinned to `acceptance.criteria`'s upper bound by a test that feeds 8
  bullets), `_MAX_BLOCKS = 2 * _MAX_CRITERIA` = 14 (at most two files per criterion), `_MAX_BLOCK_BYTES = 32768`
  (same order as the acceptance record's own 32 KiB limit), `_MAX_TOTAL_BYTES = _MAX_BLOCKS * _MAX_BLOCK_BYTES`
  = 448 KiB. An over-cap block is a finding and is NOT parsed. `ast.parse` can raise `SyntaxError`, `ValueError`
  (NUL), `RecursionError`, `MemoryError`; all four become findings. The caps are a derivation, not a
  measurement, and the code comment says so.

## Red/green rule for these tests (verified against the harness)

heading and the next `## ` heading be exactly one backticked selector bullet, 1 to 25 of them; hence all notes
live under the separate `## Test notes` heading, never inside `## Tests`. It counts a red only when pytest

red_green hashes each planned test file, so any edit after the red run invalidates the proof and the red must be
re-observed. Green-before guards (see Test notes) are deliberately not listed in `## Tests`, since a test that
passes on base can never have an assertion red.

## Five properties for the validator
- Scalability: per-block cost is linear in bytes (`ast.parse`) and in block count. At 10x and 100x input the caps
  (14 blocks, 32 KiB each, 448 KiB total) bound the work before parsing; over-cap input is refused unparsed, so
  the ceiling is a number. `scrub`/`criterion_verdicts` stay linear per criterion (research measured scrub at
  0.13 ms per 1000 lines; larger inputs unmeasured), and the new `_LEAK` arms are anchored or bounded with no
  nested unbounded quantifier over the same characters, but their worst case on adversarial one-line input is
  NOT measured. No unbounded growth: no table, cursor or cache beyond the one `_load` module cache.
- Resiliency: pure and idempotent; nothing is written, so no partial write or lost ack. Re-running is the
  recovery. Malformed breaker output is a returned finding (caller re-asks or parks), never an exception that
  kills the loop, including on a Python without `sys.stdlib_module_names`.
- Safety: no lock, no background process, no network, no file or quota use, no secrets. It parses, never
  executes, breaker-authored text (`ast.parse` only; no `compile`/`exec`/import). Where a guarantee cannot hold
  (third-party import, path outside the directory, oversized block, unclassifiable imports) it refuses loudly.
- Liveness: no long-running component is added; nothing can die silently.
- Reliability: no performance claim beyond the research measurements above; the caps are derived, not measured;
  the prose-versus-code regex sample is a 14-versus-11 line planning sample, not a corpus.
- Host-agnostic: pure Python in Sigma's own module; no hook or host-specific trigger.
