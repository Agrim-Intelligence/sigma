# Plan: #2028 Compaction safety net: daemon sets the compact window; rules and live slots re-injected after compaction
**Goal**: #2028 · **Lane**: medium · **Research**: `.sdlc/research/2028.md` · **Design**: `.sdlc/design/2024.md` §3 (FR-5, FR-6; BR-9, BR-10, BR-17) · **Date**: 2026-10-24 · **Revision**: 2 (plan-review FIX-FIRST, items 1–9 applied)

## Decisions (for the plan reviewer)
- **D-A. The window rule (revised, review item 1).** `compact_window.window(cfg)` reads
  `handoff.after_context_tokens` (call it `a`) from the config the launcher already has.
  - **`a` absent, 0, a bool, a non-int or negative → set nothing.** The host's own threshold is
    the safety net: about 967k on a native 1M window, or the 200k boundary (model-config docs).
    This decision is the orchestrator's, recorded on the issue. It replaces revision 1's 500k
    default and removes the collision with slice 2's derived threshold.
  - **`a` set → `candidate = max(2*a, PHASE_SUBAGENT_FLOOR)`.** It is set only if
    `candidate < 900_000`, so never later than the host's own ~967k point (review item 2).
    Otherwise nothing is set and the reason is logged.
    - `candidate > a` holds by construction for every positive int `a` (both `2a > a` and
      `max(...) >= 2a`). So that clause is asserted in the property test, not coded as a dead
      branch.
    - The `100_000` lower bound of the documented range is implied by the floor, which is
      above it.
  - **Why the floor exists: the variable is inherited.** The sub-agents doc says: "If you set
    CLAUDE_CODE_AUTO_COMPACT_WINDOW, the subagent uses that variable's window instead". It also
    reaches every nested `claude -p`. A window sized for the orchestrator would therefore compact
    phase subagents mid-phase.
  - **`PHASE_SUBAGENT_FLOOR = 420_000`, measured.**
    - Source: every subagent transcript on this machine modified in the last 30 days,
      `~/.claude/projects/*/*/subagents/agent-*.jsonl`, 6,906 files.
    - Script: `python3 -I .sdlc/research/2028-subpeaks.py`. For each assistant turn it takes
      `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`.
    - First-turn context: median 62,520, p90 67,268, p99 75,534, max 83,855. This matches the
      ~71k start.
    - Peak context: median 111,638, p90 225,111, **p99 411,359**, max 905,845. 60.1% of
      subagents peak at 100k or more, and 14.3% at 200k or more.
    - The floor is the p99 peak rounded up to 420k, so at most about 1% of subagents would
      compact earlier than they would today.
    - Ceiling, stated in the module: this is one machine and one month, mostly Sigma phase
      subagents. Re-measure with the same script when the phase mix changes.
  - **Consequence:** a value is set only for `a < 450_000`. For `a <= 210_000` it is 420,000; for
    `210_000 < a < 450_000` it is `2a`. The 2× headroom still covers the drain: a pick is the
    only check, and live slots finish after HANDOFF (measured 603,142 tokens over 3 goals,
    `loop.py:337-344`). The number is provisional, like slice 2's D-1.
- **D-B. Operator-set detection (review item 4).** `compact_window.operator_set` returns true on
  any of these:
  - (a) the key is present in the parent env (`setdefault` semantics, an empty value included);
  - (b) `--autocompact` appears in the launch command string;
  - (c) `autoCompactWindow` or `CLAUDE_CODE_AUTO_COMPACT_WINDOW` appears in the text of
    `$CLAUDE_CONFIG_DIR|~/.claude/settings.json`, `<repo>/.claude/settings.json` or
    `<repo>/.claude/settings.local.json`;
  - (d) the same substring appears in a file-based managed settings file:
    `/Library/Application Support/ClaudeCode/managed-settings.json` (macOS) or
    `/etc/claude-code/managed-settings.json` (Linux).

  The paths are module constants so tests can repoint them. All of this is needed because the
  env var outranks `/autocompact`, `--autocompact` and `autoCompactWindow` (model-config docs).

  **Undetectable, stated in the docstring and docs:** MDM / OS policy, server-managed settings,
  and an embedding host's `managedSettings`.
- **D-C. One shared module.** It is a new `skills/sigma-loop/scripts/compact_window.py` used by
  both launchers, so it cannot conflict with slices 1 and 2. It only mutates the child dict it is
  handed, never `os.environ`.
- **D-D. The key is read, not added.** Slice 2 owns the template and docs. `handoff.enabled` is
  not consulted.
- **D-E. Compact tier gating.** The tier fires on `source == "compact"` in any **adopted** repo
  (`.sdlc/config.json` exists). It needs no `session_start.enabled` and ignores `SIGMA_RUN_ID`
  (FR-6). The cost is about 600 tokens after a compaction.
  - It sits after the coexist notice and before the first SIGMA_RUN_ID-gated tier.
  - **Stated consequence (review item 6):** because only one additionalContext is emitted per
    invocation, an interactive compaction **skips** these later tiers for that one start: the
    upkeep lines and sweep start, north-star, dag, wizard, stop-file, watcher-staleness, loop
    liveness, session model and kg. Each is still reached at the next startup or resume, and
    `/sigma-doctor` reports them.
  - Every other source (`startup|resume|clear|fork`, missing or malformed input) falls through to
    today's code unchanged.
- **D-F. Bounded stdin read (review item 3).** The preamble is
  `HOOK_INPUT=""; [ -t 0 ] || IFS= read -r -d '' -t 2 HOOK_INPUT || true`.
  - The explicit `HOOK_INPUT=""` comes first because bash 3.2's `read` leaves the variable unset
    on the timeout path, and `set -u` would then kill the hook.
  - Behaviour: a tty is skipped, EOF returns at once, and a pipe that is never closed costs at
    most 2 s.
  - Checked on bash 3.2.57 and 5.3.15: the payload is read on EOF (rc 1, value set), and an open
    pipe returns after the timeout.
- **D-G. Cheap pre-check, then one copy of the rules (review item 6).**
  - **No Python runs unless the payload names compaction:** `case "$HOOK_INPUT" in *compact*)`
    gates the tier. Python then parses the JSON and requires `source == "compact"` exactly.
  - The policy text moves into one exported `SIGMA_POLICY_BRIEF`, read by both the opt-in brief
    and the compact tier.
  - The compact tier adds one line: this session was just compacted; if it runs the loop, the
    slots below are in flight, must not be re-dispatched, and the sigma-loop skill should be
    re-read before the next pick. The reason is that skill bodies are re-injected capped at
    5,000 tokens and `SKILL.md` is 19,137 bytes.
  - `log.py slots` runs with `timeout=5`. Measured 0.30 s warm and 1.29 s cold. On failure the
    brief is still emitted, with `Live slots unavailable (<why>)`.
- **D-H. The daemon log line (review item 7).** `apply` runs on `child_env` right after `:620`.
  The one `supervisor.log` line (the value and its source, or "left to the operator", or "not
  set: <why>") is written **after `state.mkdir` at `:628`** (the review cited `:626`; on this branch the mkdir is line 628), through `_append` in the same
  OSError guard style. It goes to the log only, never stdout.
- **D-I. A non-Claude autowatch command receives the key (review item 5).** If
  `SIGMA_AUTOWATCH_CMD` or `drive_cmd` runs a non-Claude CLI, the key still reaches that process.
  This is harmless: it is one inert env var that only Claude Code reads. Nested `claude -p` calls
  under it inherit it, as D-A intends.
- **Not done (skipped):**
  - a `compact` matcher split in `hooks.json` (the timeout stays 20);
  - an opt-out key for the compact tier;
  - `feature_judge.py` and `feature_upkeep_review.py` (short single calls);
  - Codex re-injection: Codex has no hook, and slice 2's hand-off is the load-bearing control.
