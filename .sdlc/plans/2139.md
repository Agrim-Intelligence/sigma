# #2139 plan: a blocked goal leaves `sdlc:blocked` once its explicit blockers close, and the chain asks about, frees and names a blocked member instead of stopping `claimed`

## Goal / done_when
The auto-unpark sweep holds a blocked-only goal that names an explicit blocker only on explicit (confident)
findings; the chain plan answers, read-only, whether the sweep would lift a blocked member and asks up front when
it would not; a run cycle that freed a member is `running` (exit 0); a root held only by the label stops
`decision` naming `/sigma-unpark #N`. done_when (the acceptance record, `.sdlc/acceptance/2139.md`):

1. A goal carrying `sdlc:goal` + `sdlc:blocked` that names at least one explicit blocker is lifted once every explicit
   blocker has closed, even when a weak word (needs, after, requires, waiting on) beside an unrelated open issue is in
   its title, body or comments; a goal naming only weak refs is still held by an open weak ref; the parked path is
   unchanged; `resolved[n]` and the audit comment name only refs that really closed.
2. The chain plan answers, read-only, whether the sweep would lift a blocked member with no open recorded wait: yes ->
   the forecast treats it as workable and asks nothing; no -> the sheet asks up front (release it into the chain, or
   keep it blocked and the chain stops before it); an old record without the new fields still works.
3. A cycle whose sweep just lifted a member and whose pick is then empty exits 0, state `running`, naming the freed
   member, and the next cycle claims it; a blocked member whose sweep was skipped by the interval gets one forced sweep.
4. A root held only by the label stops with reason `decision` naming the member and `/sigma-unpark #N`, never
   `claimed`; the forecast and the run give the same stop.
5. Each clause has a test seen red when that clause alone was broken, then green; `docs/chain.md`,
   `docs/label-model.md` and `CHANGELOG.md` (under `## Unreleased`) describe the change and what was not measured.

Out of scope (owner): part 3 of the issue, the sweep running only on a pick (split to #2140), and the
`compute_blocking_actions` note carried there. Lane: medium. Research: `.sdlc/research/2139.md` (BR-, TD-, D- ids
below are the dossier's).

## Decisions taken (defaulted and recorded; nobody will answer)
- **D-1 taken, a deviation from "reuse the park id".** The question is a SIBLING `blocked:<n>` (kind `blocked`), built
  and enacted by the park machinery (`chain_asks.released` / a new `kept_blocked` / `view`, `chain_enact`'s release
  loop through `unpark.resolve(..., "unpark")`). Not the literal `park:<n>`: that id routes the member into
  `kept_parked`, whose option text "keep it parked" and stop words "is parked and you answered to keep it parked"
  (`chain_forecast.py:153-157`) are false for a goal that is not parked. Options `[keep it blocked, release it]`; the
  first is recommended and `--defaults` takes it (nothing starts unasked); kind `blocked` is in `UNGROUPED`; asked
  right after the park questions. `blocked` is not an `unpark.QUESTIONS` kind, so `answer` records it locally with no
  GitHub write (`chain.py:1227-1243`), exactly like `park:<n>`.
- **D-2 DEFERRED (owner scope).** `compute_blocking_actions` is NOT changed: it still derives `sdlc:blocking` (and the
  rank raise) from weak findings. TA7 is dropped. The docs say so honestly: they no longer claim weak words never
  derive `sdlc:blocking`. Retro files it as a follow-up (or links the note already carried by the split issue, if
  Retro finds that is its tracked home).
- **D-3 taken, one refinement.** The plan checks only members with `blocked` true, no `waits_on`, not in any
  `externals[].needed_by`, verdict `armed` or `assigned-elsewhere`, AND not `in_progress` (refinement: a member
  somebody is working on reads `claimed`; asking about it changes nothing).
- **D-4 taken.** Before an empty pick is stopped on a label-held root, those roots (at most `1 + MAX_OTHER_ROOTS` = 7)
  are re-read once through the BASE runner (`run.base`, bypassing `chain_reads.CycleReads`, whose cache predates the
  pick); a label already gone (the pick's own sweep lifted it) reads as freed. A failed read is "still labelled".
- **D-5 taken.** The forced sweep stamps the interval file as any applying sweep does; no new parameter. The double
  sweep per cycle (chain key vs pick key) is TD-2, deferred.
- **D-6 taken.** `MAX_SWEEP_CHECKS = 20` is a module constant in `chain.py` (beside `label_drain.MAX_PARKED_BRIEFS`,
  also 20), NOT a config key (`tests/test_chain_docs.py` pins every `chain.<key>` to the docs). Past it the member's
  fields stay absent (the old behaviour; the run's decision stop covers it) and the numbers go to the record's
  `sweep_not_checked` (written only when non-empty) and one sheet line. The plan stays complete.
- **D-7 taken, with the owner's "one forced sweep" made literal.** `_default_sweep(sdlc_dir, config, run, force=False)`
  returns `_Swept`, a `frozenset` subclass carrying `skipped` (`None` or the sweep's own `"interval"`). The run calls
  the sweep a second time, `sweep(sdlc_dir, config, run, force=True)`, only when `skipped == "interval"`, never when
  the mode is off (the off path returns `skipped None`), at most once per cycle, and only for a TRIGGER: an open member
  of the cycle's read that carries the label, is not in progress, has no open wait (no record wait in the open set and
  no label-drain `waiting_on`), is not answered `keep it blocked`, and is not already in the run block's `forced`
  list. The triggering members are added to `forced` (local record, optional key), so each member gets one forced
  sweep per run; a later lift is the normal interval sweep's (at most 10 minutes by default).
- **D-8 taken.** The forecast marker of an unanswered or unchecked blocked row stays `not workable` / "carries the
  blocked label" (`tests/test_chain_unblock_fix.py:43-47`, `tests/test_chain_forecast.py:355-367` stay unedited);
  only the stop reason changes (to `decision`).
- **D-9 taken.** Members answered `keep it blocked` join the run's pick skip, so a later sweep lift does not let the run

## Cost at 10x and 100x (SCALABILITY)
- B, per checked member (read from the code, counted on the fake at implement time and quoted in the PR body): one
  issue GET, the comment read (`gh_api.read_issue`: one issue GET plus at most 3 comment pages, here at most 20
  comments), and one GET per distinct referenced issue not already read in this plan (one memo shared by every
  member): about 3 to 5 + r GETs. Bound: 20 checks per plan, so at most about 100 + R GETs, R the distinct refs. A
  plan with no blocked member makes zero added calls. 10x members (to the 100-member map bound, 50 live) and 100x
  (refused by `chain.max_members` before this runs) cost the same ceiling; past it members are listed, not read.
- C: the freed branch adds no call. The forced sweep is one ordinary sweep (2 label lists, comment reads served by the
  persisted cache while `updated_at` is unchanged, 1 GET per distinct ref), at most once per cycle and once per
  member per run (`forced`, at most the member count, 100). The D-4 read is at most 7 GETs, only on a cycle that would
  stop on a label-held root.
- A: zero added calls (the any-state test is pure regex over text already read).

## Failure modes and recovery (RESILIENCY, SAFETY)
- B read fails (issue, comments, a ref, a refused non-GET): `unread` or, for a ref, "reads open" (the sweep's own
  rule): the answer is `False` and the sheet asks. Never a false yes. Any exception in the check: `unread`.
- Sweep off: `sweep-off`, asked. Over the bound: field absent, listed; the run stops `decision` on it.
- Run sweep or forced sweep raises: fail open (empty `_Swept`, no force); the stop is computed as before, with the
  label-held branch and the D-4 read. D-4 read fails: still labelled, `decision` (never a false freed).
- A freed member the next cycle still cannot claim: that cycle stops with its real reason; a lift happens once, so at
  most one extra `running` cycle per lift.
- Old record / record without `forced`: works (Task 5). Record write failure: the existing exit-1 path.
