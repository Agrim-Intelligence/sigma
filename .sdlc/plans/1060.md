## Design
- Job `regression-control`: `if: pull_request || schedule || workflow_dispatch` (not push: PR gate plus nightly, per the issue). ubuntu-latest, python 3.12 (a launch-supported cell), `timeout-minutes: 30`, `permissions: contents read` inherited. Steps: checkout with `fetch-depth: 2`; git identity (some gated tests make real commits); setup-python; `pip install pytest`.
- PR step: `git diff --name-only HEAD^1 HEAD > "$RUNNER_TEMP/changed-files.txt"` (HEAD is the PR merge commit, `HEAD^1` the base tip) then `python3 evals/regression/control.py run --changed-files "$RUNNER_TEMP/changed-files.txt"`. `control.py` already selects rows whose anchor file or gate argv entry is in the list, or any `evals/regression/` file; an empty selection runs nothing and exits 0.
- Nightly/dispatch step: `python3 evals/regression/control.py run` (all rows). No `--strict` (layer1-control is pending until #812, strict would be permanently red); no `--record` (CI must not write the matrix).
- Both steps print `SECONDS` wall time so the number is in the job log. The real CI number is read back from `gh api repos/.../actions/runs/<id>/jobs` after the PR's own run; if the PR run selects zero rows that number is the zero-row cost, stated as such.
- Not a required check: the ruleset requires only `test`; making `regression-control` required is an owner ruling (reported, not done).
- Ceilings: serial, ~80 s for all rows locally (control.py docstring); PR job pays checkout and setup (~tens of s) even when zero rows are selected. A selector miss (a gate file renamed but not matching argv) means a PR escapes the control until the nightly: bounded to one day; the existing anchor tests in the fast suite catch anchor renames on every PR.
- Recovery: the control removes its own temp tree in `finally`; a cancelled job leaves only the runner's disposable disk.
