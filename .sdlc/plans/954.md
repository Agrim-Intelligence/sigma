**Code**: goal worktree `.sdlc/work/954` (branch `sdlc/954`, HEAD `5f25b99`, release 1.0.5). Line numbers below are from that HEAD.

## 1. What changes, in one paragraph

Every registry shard (`.sdlc/features/units/<u>.json`) and page (`.sdlc/features/<u>.md`) write records a **provenance chain** in gitignored `.sdlc/state/features/provenance/`. The chain is an ordered list of git SHA-1 blob ids. Each id is a content state of that file, and each consecutive pair is one Sigma write: the pre-image the write replaced, then the bytes it wrote. The writer reads the pre-image and updates the chain under a per-path lock. It does both **before** the chokepoint's own `os.replace`, which runs inside that lock (D8).

`work._dirty_root_refusal` stays exactly as it is when the root is clean, and when any dirty line is not a registry file. When every tracked dirty line is a registry shard or page, it makes **one** extra call: `git status --porcelain=v2 --untracked-files=no -- <sdlc>/features`. Every path it compares is derived from **one resolved `.sdlc`** (`Path(sdlc_dir).resolve()`, the resolution `project_root` already does), so the documented gesture `work.py start .sdlc "$goal"` (relative, passed raw by `main`) gets the same answer as an absolute path (D7). It then exempts a path only when all of these hold:
- the line is a worktree-only modification (`.M`), with no worktree mode change;
- the current bytes are a Sigma post-image;
- the committed (HEAD) version sits **earlier in the same unbroken chain**.

Anything else still refuses. That covers a human hand-edit, an edit Sigma then wrote over, a staged file, `index.json`, `rebase-acks/`, and any unproven write. The refusal names each path and gives §15's commit gesture. It no longer advises `git stash`.

## 2. Design decisions, and where this deviates from the dossier (each justified)

The dossier's recommendation is kept: content-hash provenance at the two write chokepoints, recorded before `os.replace` in `.sdlc/state/`, and exemption only when both the working-tree bytes and HEAD are Sigma-trusted. Six refinements were found while stress-testing it, and two more (D7, D8) came out of the plan review.

### 2a. Writer rule — `with feature_provenance.recorded(features_dir, target, tmp): os.replace(tmp, target)`

`recorded` is a context manager (D8). The chokepoint's own `os.replace` is the body.
1. If `record_path(features_dir, target)` is None, `yield` with no lock and no record; the caller's replace still runs. `record_path` goes through `_key` (D7). It returns None when the target is not `units/<x>.json` or `<x>.md` directly under the normalised features directory, when `<sdlc>/state` is absent, or when a link is on the record path.
2. Take the per-path lock `<record>.lock`. It is an exclusive `flock`, bounded at 10 s with a 5 ms poll, and fails open. This is the `feature_sync._acquire` idiom, written locally (see §9 Decisions).
3. Read `W = blob_id(tmp bytes)`, which are the exact disk bytes including Windows text-mode newlines. Read `P = blob_id(target bytes)`, or None if the target is absent.
4. Compute the new chain:
   - absent P gives `[W]`;
   - a P in the chain gives `chain[:last(P)+1] + [W]`, unless W already equals that new tip;
   - any other P gives `[P, W]`.
   If the length is over `CAP = 256`, the result is `[chain[0]] + chain[-(CAP-1):]`.
5. Write the record atomically (temp file in the same directory, then `os.replace`). On any failure, write **one stderr line naming the record** and **never raise**. The write itself must not fail: fail-open for the write, fail-closed for trust.
6. `yield`. The caller's `os.replace(tmp, target)` runs here, under the lock. Its failure propagates through the context manager unchanged, so the caller's existing cleanup and re-raise still hold.
7. Release the lock in `finally`.

Record schema: `{"schema": "sigma/feature-provenance@1", "chain": ["<40-hex>", ...]}`. Any other shape reads as an empty chain. A record larger than 64 KiB reads as corrupt.

### 2b. Reader rule — `feature_provenance.proven(features_dir, target, head_oid, compact=False) -> bool`

0. Find the record through `_key` (D7), so the reader names the same record file as the writer whatever spelling either was handed. `head_oid` is the v2 `hH`.
1. Read D from `target`: it must be a regular, non-symlink file of at most 16 MiB.
2. **Then** read the chain. Reading the bytes first is what closes the AC-4 window (§4).
3. Return True only if `head_oid` is 40-hex and some `i < j` has `chain[i] == head_oid` and `chain[j] == blob_id(D)`.
4. If True and `compact`, try the lock non-blocking. If it is held, or there is no `fcntl`, skip. Otherwise re-read the chain under the lock, find H's last index `i` that is before D's last index, and store `chain[i:]`. Never raise.

### 2c. Checker — `work._dirty_root_refusal(base_root, s, run, sdlc_dir=None)`

Existing order is kept: v1 `git status --porcelain`, then `git rev-parse --abbrev-ref HEAD` only when there are tracked lines, and fail-open on either error. Then:
0. **Resolve once (D7).** `sdlc = pathlib.Path(sdlc_dir).resolve()`; `features_dir = registry_dir(sdlc)`; `features_rel = features_dir.relative_to(base_root).as_posix()` (`.sdlc/features`). Both `base_root` (`project_root`, `work.py:1179`) and `features_dir` now carry the same resolved prefix. Nothing below touches the raw `sdlc_dir` again. This is one `realpath` and no new git call.
1. Collect `paths`, the tracked v1 lines parsed **defensively for BR-9**. If `ln[2] == " "`, the path is `ln[3:]`. Else if `ln[1] == " "`, the path is `ln[2:]`: this is line 1 with its leading space stripped. Any misparse fails closed at step 4.
2. Leave the registry branch **without** another call (and refuse as today) if any of these holds: `sdlc_dir` is None, `.sdlc/features/` is not adopted (`work._adopted(sdlc)`, one `stat`), or **any** path is not a registry shard or page. A registry shard or page is a path P where `base_root/P` equals `unit_path(features_dir, stem)` or `doc_path(features_dir, stem)`, built by the registry's own builders from the step-0 `features_dir` and never a literal. A builder's `ValueError` (an illegal name) means "not a registry file".
3. Make one v2 call: `git status --porcelain=v2 --untracked-files=no -- <features_rel>`. If it raises, refuse. That is today's behaviour for this dirt, never a new failure mode.
4. A v2 entry is exempt only when all of these hold: it is kind `1`; XY is `.M`; `mI == mW`; it is a registry file per step 2; and `_feature_provenance().proven(features_dir, base_root/P, hH, compact=True)` returns True. Allow the start if every v1 path is in the exempt set and no v2 entry is non-exempt. Otherwise refuse, listing the unproven paths.
   - **No separate `hH == hI` or `mH == mI` check.** X = `.` means index = HEAD, so both hold by git's definition. Measured: `.M` prints `<h> <h>`, while `M.` prints `hH != hI` (scratch repo, 2026-10-10). A check that another check implies can never be seen red on its own.
   - **No `sub == N...` check.** A submodule entry is a directory, and `proven` refuses anything but a regular file.
   - Lines of kind `2` (rename/copy) and `u` (unmerged) are non-exempt by construction: the parser only builds candidates from kind `1`.
5. The refusal text (`_dirty_root_message`) lists at most 10 paths, then "and N more". When registry paths are among them, it says they could not be proved to be Sigma's own write (§15). It gives the gesture verbatim: `git -C <root> add <features_rel> && git -C <root> commit -m "registry: record unit membership"`. It says: look with `git -C <root> diff`, then commit or move to a branch (never `reset --hard` / `clean -f`), then re-run. It contains **no `stash`**. It keeps the words `REFUSED` and `tracked` (`tests/test_work.py:7112`).
   New module-level helpers take the `_dirty_root_` prefix (test 9 scans them). None may end in `_refusal`, `_gate`, `_hold` or `_guard`, or contain `blocked_by`, because `enforcement_table.problems()` would flag it.

## 4. Concurrency: what holds, and the honest limits (AC-4)

- **No global chokepoint.** There is one leaf lock per registry file. Lock order is always unit lock (`amend`), then the provenance lock, and never the reverse, so it cannot deadlock. `_sync_doc` holds no unit lock and takes only the page's provenance lock.
- **Writer B against checker A in one root.** B updates the chain *before* the replace. A reads the bytes *before* the chain. Whenever A sees B's new bytes, the chain A reads afterwards already holds them. Whenever A sees the old bytes, they are still in the chain, because a Sigma write only appends or truncates *after* its own pre-image. Concurrent v1/v2 drift is covered by requiring every v1 path to be exempt in v2, and every v2 entry to be exempt.
- **Deterministic seam controls** (in process, per AGENTS.md "a port across a performance boundary…"):
  - Test 14 wraps `os.replace`, filtered to the shard target. It runs A's check *after* the real replace, and also before it. Mutant M5 (the record stored after `recorded`'s `yield`, i.e. after the caller's replace) goes red.
  - Test 15 wraps `pathlib.Path.read_text`, filtered to the record path and fired once. After A reads the chain, it runs B's full write. Mutant M6 (chain read before the bytes) goes red.
  - Test 16 is the multi-process run. It is **labelled SMOKE in its docstring**: probabilistic, and not the system of record.
- **Fail-open limits, stated:**
  - With no `fcntl` (Windows), an unlockable filesystem, or a holder wedged for 10 s or more, the record's read-modify-write is unserialised. It can lose a chain entry. The cost is a **spurious refusal**, never a hidden edit, because entries are only ever Sigma post-images or pre-images read from disk. Compaction is skipped there. Test 16 skips with that reason when `fcntl` is None.
  - A human edit landing inside the ~1 ms window between the locked pre-image read and the replace can still be overwritten. That is the pre-existing atomic-replace race, unchanged by this fix.

## 6. Failure modes and recovery (RESILIENCY)

| Failure | What happens | Recovery |
|---|---|---|
| Crash between the record update and `os.replace`, or the caller's `os.replace` raising inside `recorded` | The chain holds a W that never landed. The disk is still P, which is still proven (test 20). | The next write sees P as the tip's predecessor, truncates, and appends. Self-heals. |
| Crash mid record write | The temp file and replace are atomic, so the old record is intact. At most one `*.tmp` is left per crash. | None needed. |
| Record missing or corrupt (deleted `state/`, fresh clone, upgrade from ≤ 1.0.5 with dirt already present) | An empty chain trusts nothing, so the start refuses, naming the path and the commit gesture. | One human commit. The next Sigma write reseeds `[P, W]`, and later starts are exempt (test 19). **Polite lever**: the §15 gesture, printed in the refusal. |

## 7. Tasks

### Why the tests are written first, in one go

`verify.enforce` is true in this repo, and the installed `red_green.py` credits a red only when it is:
- an **assertion** failure (not an ImportError, TypeError or collection error);
- observed by `loop.py verify` **before** the green run;
- bound to the **whole test-file bytes** ("changed tests need red again").

So both test files are written complete in Task 1, then seen red once against the unchanged code. Implementation then proceeds step by step, each step turning a named subset green with plain `pytest`. That is the same red→green cycle at step granularity, without re-recording reds.

Every test reaches the code through APIs that exist *before* the fix, so old code fails by assertion rather than by error:
- `work.start`, and `work.main` with the documented argv (test 23);
- `work._dirty_root_refusal`, through the signature-adaptive `World.check()`;
- `feature_registry.write_unit`;
- `feature_sync.amend`;
- `feature_doc.sync`;
- the global `os.replace` and `pathlib.Path.read_text`;
- `feature_provenance` only through `registry_root.module("feature_provenance")`, which returns None when the file is absent. Test 24 asserts `prov is not None, "feature_provenance.py is missing"`, and test 9 scans it only if present. This is the `tests/test_shared_sdlc_paths.py::_tool` precedent: against a tree without the module, the test fails on an AssertionError, not an ImportError.

Pins wrap expected-success calls in `try/except Exception as e: assert False, f"...{e}"` so their control reds are credited as assertions.

### Output discipline — what the installed `red_green.py` will and will not credit (measured)

`red_green.observe` runs only the planned nodes, as `pytest -q -rA --tb=short --color=no`, and parses stdout. Three facts about that parse decide whether a red is ever recorded. Each was measured on 2026-10-10 against the installed 1.0.2 `red_green.py`, with its own `_split_traceback_assertions` run over real pytest 9.0.2 output, at the 80 columns pytest uses for a piped stdout here (`COLUMNS=0` falls back to 80):
1. **Every node id is at least 74 characters**, so the `FAILED <node>` summary line has no room for ` - AssertionError…` and carries no reason. Every red therefore comes from traceback attribution (`red_green.py:106-131`).
2. **Any `Captured stdout|stderr|log` section anywhere in the run voids every traceback-attributed red in that run** (`:106-112`). Under `-rA`, a *passing* node that wrote output prints such a section in `PASSES`. Measured: one passing node writing one stderr line left the credited set empty, although a sibling had failed by assertion.
3. **Failure blocks are split on separators of at least three underscores** (`:113`). Pytest shrinks the `___ name ___` separator as the function name grows. Measured: a 72-character name gets `___`, and a 73-character name gets `__`. Below three, every failure merges into one block, and a non-assertion failure is **credited as an assertion** whenever a sibling failed by assertion. Measured: a `TypeError` node was credited.

So, for every planned node:
- **Names are at most 72 characters** (every name in `## Tests` is; Revision 2 renamed five). No `parametrize`, since `[id]` would lengthen the separator title.
- **Nothing reaches pytest's capture.** Each test takes `capfd` (FD-level, so inherited child output is caught too; `capsys` would miss it) and runs its whole body inside `with registry_root.drained(capfd) as out:`. The context manager calls `capfd.readouterr()` in `finally`, so output is consumed on pass, on assertion failure, and on error. This happens before pytest's call phase closes the fixture and would otherwise flush unread output into a report section (pytest 9 `CaptureFixture.close` → `pop_outerr_to_orig`). Measured: a body that wrote to stderr, ran a child that wrote to stderr, and then failed an assertion left no `Captured` section, and its red was credited. Tests that assert on output call `out.take()` right after the action.
- **The sources this covers, named:** test 21's fail-open stderr line (asserted, not just swallowed); `work.main`'s printed result (test 23, asserted); `_sync_registry`'s `sigma: feature registry sync skipped` at `work.py:1934`; `feature_registry._note` and `feature_doc`'s legacy-marker line; and `git` itself.
- **`World` is built inside the body, under `drained`, never in a pytest fixture.** Setup-phase output gets its own `Captured … setup` section, which a body-level `readouterr` cannot reach.
- **Every subprocess captures its own output.** That covers the fixture's `git init/commit/push`, the §15 gesture run through the shell, and test 16's writer processes (`stdout=PIPE, stderr=PIPE`, joined with a timeout inside the body, killed on timeout). Child output reaches the report only inside an assertion message. No child may outlive the body.
- Tests never `print`.

## 9. Decisions on the dossier's open items

- **TD-1 (stash advice): fixed now.** The refusal and agent-rules-detail are changed, and tests 8 and 9 cover it.
- **TD-2 (`amend` folds human edits and drops out-of-schema fields): deferred, follow-up F-1.** This design already stops the *fold* from being hidden. The chain resets with the human's bytes as anchor, H is no longer in it, and the next start refuses and names the shard (test 5). Dropping out-of-schema fields is a pre-existing silent loss that the guard neither causes nor can see. Fixing it needs `write_unit` to know HEAD (git) or to refuse untrusted pre-images, and the second would refuse every fresh clone. That is a design question, not a cheap fix.

## Risks

- **Verify cost.** Recording reds and the green takes three `loop.py verify` runs: R-OLD, R-WEAK, and the final green. Each runs the full suite first. This is the price of `red_green.py`'s assertion-only, file-bound reds. A test-file change after Task 1 costs two more (R-OLD and R-WEAK again); the Task 1.4 dry run is there so that none is spent on a run that would credit nothing.
- **`red_green.py` attribution (F-6).** One stray `Captured` section, or one name over 72 characters, silently costs every red in a run, or credits an error as an assertion. Mitigated by `drained(capfd)`, the 72-character rule, and the dry run. The width was measured at 80 columns (`COLUMNS=0` here); a verify run under a narrower `COLUMNS` (40-79) would shrink separators further. The dry run runs in the same environment as verify, so it would show that.
- **Selector headroom.** 24 of `red_green.MAX_SELECTORS = 25` are used, which leaves one spare.
- **Platform limits.** #954 is **not** fixed under `core.autocrlf` or clean filters (Git for Windows' default), on SHA-256 repos, or with `.sdlc` below the git toplevel. Those cases fail closed to today's refusal (F-4). Pre-upgrade dirt refuses once.
- **Existing tests that may need narrowing.** Tests enumerating `state/features/`, and the `os.replace` spy in `test_feature_doc.py`, may need narrowing. Task 3 runs them and fixes them only on evidence.
- **The smoke test.** It is probabilistic by nature. The deterministic seams (14, 15) are the system of record.
