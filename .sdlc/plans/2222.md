Lane: large. One goal, one PR, eleven ordered tasks (S1..S6 of the research, with S2, S4 and S6 split so each task is one test cycle). Inputs: goal body, `.sdlc/acceptance/2222.md` (read-only, never edited by this plan or by Implement), `.sdlc/research/2222.md`. ## Decisions
Each binds Implement. A deviation is a plan deviation and goes back to plan-review.

- **D1 Baseline (Q1).** `record` stores `criteria_sha256` (sha256 of the normalised ORIGINAL `## Done when` block, the exact bytes from the heading line to the last item) in the record front matter at first record, and also in the ledger `acceptance` event. The guard checks BOTH: (a) the stored hash equals the hash of the current original block, and (b) the original criteria list in the baseline copy is an exact, ordered prefix of the combined list in the new record, and the baseline's `criteria_sha256` equals the new one. Baseline copy = the earliest committed blob of `.sdlc/acceptance/<g>.md` on the goal branch history (`git log --reverse`, read through the existing `_branch_doc` seam in `review_context.py`), or `<remote>/<base>` if the file already landed. Before any commit exists the baseline is the record's own stored hash plus the ledger witness. Rejected: hash only (an agent rewrites block and hash together, so it is tamper-evident at best); issue-body-at-record-time only (the issue is editable and fetched over the network); storing a full text copy elsewhere under `.sdlc/` (a second file in the root checkout, which AGENTS.md forbids unless the branch copy carries it). **Residual, stated honestly:** the hash is tamper-evident, not tamper-proof. An actor who rewrites the root record, its `criteria_sha256`, the ledger entry and the goal branch history before the first push, and also edits the issue, defeats every witness. After the first commit the git history is the witness and a rewrite shows as non-fast-forward. Host branch protection is the only hard stop, as AGENTS.md already says for feature branches.
- **D2 Cap vs append (Q2).** The original block keeps the 3 to 7 rule and the 1024-character limit untouched (`criteria()` semantics for `## Done when` do not change). Added criteria live in a separate `## Added criteria` section after it, so the original block stays byte-identical and the prefix check is a block-equality test. **Ceiling: at most 10 added criteria per goal** (17 in total), each at most 1024 characters including its suffix. SCALABILITY: 17 x 1024 is under 18 KiB, inside the existing 32 KiB `MAX_BYTES`, and review briefs carry the record verbatim, so the brief grows by at most 10 lines. Ten is a named ceiling, not unbounded growth: a goal that needs more than 10 added criteria is a new goal, and `extend` refuses with that sentence. `breaker._MAX_CRITERIA` (7) keeps reading only the original block (D-2 stays one constant, imported from `acceptance.py`, not duplicated).
- **D3 Reason format (Q3).** Each added criterion is `- [ ] <text> (added: <slice>; reason: <why>)`, visible in rendered markdown. `acceptance.added(text)` returns `[{text, slice, reason}]`; a line missing the suffix yields `reason: None`. `extend` refuses to write one. A hand-written reasonless line is still parsed (so review can see and block it) and `work.py pr` refuses it. Rejected: an HTML comment (invisible in review).
- **D4 Issue-vs-record divergence, failure direction.** The guard's real protection is local (D1) and does not depend on the network. The divergence check compares the issue's current criteria with the record's ORIGINAL block. Divergence parks the goal for a person with the stated reason, in every phase. **Source fetch failure: fail CLOSED at `work.py pr`** (the point where work leaves the machine; the hold is retried by the next tick, so recovery needs no human) **and fail OPEN at `work.py commit`** (local, offline work stays possible; the local clauses still run). Both print which way they went. Local-file goals have no issue: the divergence check is skipped and says so. Rejected: fail-open everywhere (an agent working offline would never be compared); fail-closed at commit (an outage would stop all local work).
- **D5 `goal_readiness` default `warn`.** `warn` prints the missing sections and proceeds; it never parks and never blocks. Default `warn` because Sigma is installed across whole organisations and a default `require` would park every existing goal on upgrade (a fleet outage, RESILIENCY). `require` parks with a stated reason; `off` does nothing. Required sections default: `Done when`, plus `Verification command` only when the repo has a configured verify command ("where one is known"). Rejected: default `require` (mass parking), default `off` (the feature would be invisible).
- **D6 Prefix clause is unconditional.** The new guard in `work.py commit` and `work.py pr` runs whether or not `verify.enforce` is on. The existing presence check at `work.py:4839` stays enforce-gated and is NOT widened (research D-3). Rejected: gating on enforce (the goal says every phase and every actor).
- **D7 Doctor open-goals read is bounded.** The doctor row reads at most **50** open goals' bodies (the same REST list the label drain already pages), prints `N of M checked` and `50+ unchecked` beyond that. 100x growth costs no more than 50 reads per doctor run. No GraphQL.
- **D8 The promote seam is GitHub-only.** `promote.py:130 _github` is the only promote path, so `goal_readiness` at promote applies to GitHub goals only. Local-file goals get only the pick-time check. Documented in `docs/configuration.md`.
- **D9 No bypass surface.** No flag, environment variable or config key reaches the guard. `prefix_refusal(...)` takes no override argument, `acceptance.py` and `work.py` gain no `--force`, `--skip`, `--allow`, `--no-guard` flag and read no env var in the guard path. A structural test (T2) asserts this, and its control adds a `--force` flag and sees it go red. `goal_readiness` is a separate, non-security setting about goal bodies, and it can never loosen the append-only guard.
- **D10 Normalisation.** `## Acceptance criteria` is read as an alias; `record` writes `## Done when` only. After `record`, the original block never changes. A body with both headings uses `## Done when` (canonical wins) and the alias block is ignored with a printed note, never merged.

## Risks
1. **Baseline strength (D1).** Hash plus ordered prefix is tamper-evident, not tamper-proof; the pre-first-commit window and a history rewrite are residuals. Mitigated by the ledger witness, the issue comparison at `pr`, and the git history after the first commit.
2. **Blast radius of a gate every goal passes through.** A false positive in `commit` or `pr` stops every goal in the fleet. Mitigated: old records without `criteria_sha256` use the branch-copy baseline only and never refuse for the missing hash; a guard error that is not a clear mismatch refuses with its reason, never a traceback; the new tests cover legacy records.
3. **Performance-boundary port (AGENTS.md).** The guard is in-process Python, not a probabilistic concurrency control, so the sensitivity-collapse rule does not apply; the one concurrency seam (`os.link` create-only, `extend` write) keeps a deterministic in-process test (`test_acceptance_atomic_create_failure_...` exists; an equivalent for `extend` is in T8). No `kill -STOP`, no background process is added.
4. **Divergence check turns an issue edit into a park.** A person who edits the issue's criteria mid-run parks the goal. Intended, but noisy; the park reason names the one gesture (`/sigma-unpark` after the person decides, or `extend`).
5. **Cap interplay.** `breaker.py` and `seal_tests.py` read criteria; they must keep reading only the original block. Verified in T1 by a test that a record with ten added criteria leaves `breaker`'s count at the original.
6. **Doc and test pins.** Many pins read `docs/` and templates; each new doc line may redden an old pin. Each task runs the pin files it touches.

- No `acceptance.py` verb that edits or removes a criterion, and none will be added; correcting a wrong criterion is a person editing the goal and re-recording through `/sigma-unpark`, outside the agent's reach.
