# Plan: #493 — narrow the macOS support claim to what CI proves (3.12)

Inputs: issue #493, `.sdlc/research/493.md`, `.sdlc/acceptance/493.md`. Worktree `.sdlc/work/493`, origin/main `53f8120`.

## Design
Make the launch definition claim only cells CI runs, and add a guard that derives the CI cells from the workflow.
- `docs/launch/definition.md` and `definition.json`: macOS supported on Python 3.12 only; Linux 3.10-3.13. The macOS cells on
  3.10, 3.11 and 3.13 are stated as untested (not unsupported): prose in "Supported cells" plus a JSON `untested` list.
  Status stays `proposed`; `signed_by`/`signed_on` stay null. The CI matrix is not touched.
- `CONTRIBUTING.md`: "supports Python 3.10 and newer" becomes a floor ("requires 3.10 or newer") plus the CI sentence.
- `CHANGELOG.md`: one Unreleased entry (the #330 entry is history and stays).
- New `tests/test_launch_ci_cells.py`: parses `.github/workflows/ci.yml` for its (os, python) cells and fails when
  (a) a `supported` entry of definition.json or a `supported` row of any docs table is not a CI cell,
  (b) a doc sentence "<Linux|Ubuntu|macOS> with Python <versions>" (README, CONTRIBUTING, docs/*.md, docs/launch/*.md,
  excluding evidence logs) names a version CI does not run for that OS,
  (c) the cells CI runs on Linux but not on macOS are not stated as untested in both the page and the JSON.
  Controls on synthetic text assert each branch fails on a deliberately broken input, and that the parser reads
  the real workflow (cell count equals the number of `- os:` lines, so a format change cannot silently empty it).
- Documented gesture: `python -m pytest tests/test_launch_ci_cells.py -q`, written into "How to change this page".
