## Files (all NEW; no existing file is edited)
Under `evals/golden/T2/` (created by this goal):
- `repo/<helper>.py`: shared helper with a latent defect on an input class the visible tests do not exercise. Docstring
  states the real contract (the promise the defect breaks) and does not enumerate hidden cases.
- `repo/<caller_a>.py`, `repo/<caller_b>.py`: two sibling callers, each importing the helper by top-level module name and
  each doing independent work with its result.
- `repo/test_<name>.py`: visible tests, green on repo/, never touching the defective input class.
- `reference/`: the COMPLETE fixed tree (not an overlay): all repo/ files, with ONLY the helper changed; the visible test
  and both callers byte-identical to repo/.
- `allowed_paths.json`: JSON list with only the helper file name.
- `rubric.json`: `{"criteria": [...]}`, plain-language criteria: the root cause is fixed in the helper; both callers
  behave correctly; the unrequested single-call-site patch is not accepted as the fix.
- `hidden/files/test_<name>_hidden.py`: one test per caller on the defective input class; no import of or call to the helper
  by name in any assertion path (callers only).
- `hidden/naive/<caller_a>.py` (the call site the prompt names): repo/ copy with the proposed call-site-only change.
- `hidden/verify.json`: the T1 argv above.
- `task.json`: per D1/D2; `visible_command` is `["python","-m","pytest","-q","-p","no:cacheprovider","."]`; `prompt` quotes the
  symptom in the named caller and proposes the call-site change explicitly, with no mention of the sibling or the helper
  as cause; `hidden_sha256` written LAST (see step 5).
- Constraints on every task file: stdlib-only; task `.py` writes no files (no open-for-write, write_text, mkdir, rmtree,
  subprocess, git, gh); no token-like strings; no e-mail addresses; no home-directory paths; no `#` followed by 4+ digits;
  no retired-name prefix in any file or path; no conftest or pytest config (CI's `pytest tests/` must never collect these).

## Steps (leave the worktree uncommitted; `work.py commit` is the only commit; the planner stages nothing)
1. IMPLEMENT subagent authors repo/ per the structure above. Verify: run the visible suite in a scratch copy of repo/
   (outside the worktree, copy only): all pass.
2. Author reference/ (helper fix only). Verify: `diff -r repo reference` shows only the helper file differs; visible suite
   passes in a scratch copy of reference/.
3. Author hidden/files test and hidden/verify.json. Verify by hand in scratch copies, with the hidden dir copied to
   `.sigma-hidden/` at the tree root: on repo/ expect exit 1 with assertion failures (NOT collection error exit 2); on
   reference/ expect exit 0; both tests fail on repo/ (one per caller).
4. Author hidden/naive/<caller_a>.py. Verify: scratch copy of repo/ with naive overlaid and hidden tests run: exit 1; the
   named caller's test passes and the sibling's test fails (that is the property, check both statuses).
5. Write allowed_paths.json, rubric.json, task.json with placeholder `hidden_sha256`. Then, from inside `evals/golden/T2`,
   compute sha256 hex of every regular file under `hidden/` (keys relative to `hidden/`, all three groups: `verify.json`,
   `files/...`, `naive/...`) and write them into task.json. Regenerate after ANY hidden edit; do this step last.
6. Run the documented gesture exactly: `python3 evals/golden/verify.py`, then `python3 evals/golden/verify.py --only T2`.
   Expect `ok T2`, exit 0. Record wall time (`time`) as the measurement below.
7. Run the guards in the goal worktree: `python3 tools/readiness/write_surface.py check`,
   `python3 tools/readiness/exposure_scan.py tracked`, `python3 tools/rename_check.py`, and pytest of
   `tests/test_third_party_imports.py`, `tests/test_doc_links.py`, `tests/test_golden_verify.py` (use `git add -N` on the
   new files only if a guard reads tracked files; do not stage for real). If a guard demands registration, add the minimal
   entry and say so in the PR; otherwise add none.
8. Run the controls below, revert each break, then rerun step 6 green and confirm no stray `__pycache__`, `.pyc` or
   `.DS_Store` remains under the task directory.
9. Full suite `python -m pytest tests -q -n 4 -p no:cacheprovider`; then `loop.py verify` for the goal.

## Risks
- Hash drift: any hidden edit after hashing is `RED hidden-sha256`; hash last.
- Collection error (exit 2 from pytest) would make `hidden-on-start` pass for the wrong reason; step 3 requires seeing
  assertion failures.
- Third-party-import guard scans every non-test `.py` incl. callers and naive/reference copies; keep imports stdlib or
  sibling top-level modules.
- Leakage: hidden tests live in the repo (accepted design doubt D-2; an executor must hide them).
- Independence: if the PR cannot state an independent author, the task is not accepted as a trap (D5).
- The worktree is cut before the T1 PR merged; `golden: N task(s)` may report only T2 here. Not an error.

## Scale / resiliency / safety
Cost is linear in tasks: per task three pytest runs (start, reference, naive) plus process spawns. At 10x and 100x tasks
the serial run grows 10x and 100x; the measured single-task-set wall time above is the baseline (extrapolation is
arithmetic, not measured). Ceiling is the serial run with a 120 s per-run timeout in verify.py. No network, no model, no
background process, no persistent state; recovery from a bad task is deleting or fixing the task directory and rehashing.
