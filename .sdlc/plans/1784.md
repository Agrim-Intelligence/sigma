## What is and is not measured

- **Nothing is measured yet.** The scaffold writes one file of about 1 KB; no loop, lock, network or background process. At 10x and 100x repositories the cost is flat (one file per run, one exclusive create). Growth: none (one file, never rewritten). Wall time of the scaffold gesture is measured once in Task 9 on `/usr/bin/python3` (3.9.6) and the venv 3.12 and recorded in the PR body; until then no speed claim is made.
- **Windows (D-15) is unmeasured and not claimed.** `open(dest, "x")` maps to `O_EXCL` on Windows, paths use `pathlib`, the slice-1 resolver already refuses drive-letter and UNC values, and the scaffold refuses any backslash. Tested on this macOS host only; `docs/architecture-doc.md` "Honest limits" already says "not measured on Windows" and the new section must not contradict it.
- **The real-host run** (`/sigma-vision --architecture-doc` inside Claude Code in a fresh adopter repo) is UNMEASURED and cannot be shown from a subagent. The measurable substitute is the documented gesture run as a subprocess on a temp repo (Task 9).
- **Recovery:** every failure mode is "run it again". Validate fully before any `mkdir`; exclusive create means a rerun never overwrites; a write error removes the one file this run created, so no partial file is ever left.
