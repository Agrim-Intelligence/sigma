# Plan: #502 — exact paired test that fits 15 tasks

Inputs: issue #502, `.sdlc/research/502.md`, `.sdlc/acceptance/502.md`. Worktree `.sdlc/work/502`, origin/main `53f8120`.

## Design

Replace the "Go threshold" of `docs/bench/preregistration.md` with a rule on the discordant tasks of each paired
comparison (A1 vs A2, A1 vs A3), computed by a stdlib-only script whose published tables a test pins.

**Rule (per comparison; W = A1 pass and the other arm fail, L = the reverse, D = W + L, ties ignored):**
- Null: Sigma is no better than the arm (P(win | discordant) <= 1/2). One-sided exact binomial tail
  `P(Bin(D, 1/2) >= W) <= alpha`, compared as exact fractions. Recommended alpha 0.05 (owner decision).
- Paired verdict GO if that holds for W; paired NO-GO if the same test holds for L (Sigma significantly worse);
  otherwise INCONCLUSIVE. D <= 4 is always INCONCLUSIVE at alpha 0.05 (4 of 4 has p = 0.0625).
- Overall: GO needs both paired verdicts GO and A1's trap catch rate above A2's (unchanged condition). NO-GO if any
  paired verdict is NO-GO (precedence over GO). Everything else is INCONCLUSIVE, which is never a win and permits no
  comparative claim. GO is an intersection-union test (size <= alpha, no correction, any dependence between arms);
  a false NO-GO is a union, bounded by 2 alpha.
- Margin: 0 tasks (the rule tests superiority; there is no non-inferiority margin). Owner decision, with the
  alternatives and their cost recorded: non-inferiority margins of 1, 2, 3 tasks (6.7, 13.3, 20 points) need net wins
  >= 6, 6, 4 at alpha 0.05 on the unconditional W - L statistic, so a margin below 20 points costs superiority-grade
  evidence; a margin floor on the sign test never binds below 5 tasks.
- The document states, from the tables, that error control is exact but power is low: with 15 tasks a true +20 point
  advantage (40% of tasks discordant) passes with probability 0.176 and +30 with 0.410, +40 with 0.783; a true tie
  passes with at most 0.030; the tasks needed for P(GO) >= 0.8 are tabulated. No non-inferiority claim is available.
  What an INCONCLUSIVE result supports: the descriptive counts (W, L, T per arm), nothing comparative.
- Assumption stated in the document: the probabilities assume independent, identically distributed tasks with fixed
  (pw, pl, tie); the exact conditional size guarantee holds for that model and for per-task symmetry; heterogeneous
  tasks can change power in either direction and the script cannot check this.

## Test notes
`test_probabilities_match_brute_force_enumeration` enumerates all 3^n win/loss/tie sequences for n <= 7 with a
separately written classifier (a loop over `math.comb`, not the script's functions) and compares exact fractions.
The published-tables test runs the exact command from the document (`--check docs/bench/preregistration.md`) as a
subprocess; the drift test runs the same command on a copy with one digit of one table changed and requires exit 1.
Reviewers are asked to recompute the operating characteristics without the script.

## Risks
Script runtime about 7 s (exact fractions); the tables are computed once per test via a module-level cache.
Statistical risk: the document's conclusion is "low power"; it must not read as a rule that looks stronger than it is.
