# Plan: #458 — bounded prune of per-goal state records

Inputs: issue #458, `.sdlc/research/458.md`, `.sdlc/acceptance/458.md`. Worktree `.sdlc/work/458`.

## Design
- New `skills/sigma-loop/scripts/goal_state_prune.py` (stdlib only). The pruner removes, per goal stem: `state/{verify,landing,propagation,escalation}/<stem>.json`, `state/unit-tracking/<stem>.attempt`, `state/phase/<stem>.json`. Regular, non-symlink files only; parent dirs that are symlinks are skipped; `unlink(missing_ok=True)`; nothing recursive. Unsafe stems (`state.unsafe_goal_reason`) are refused.
- `sweep(sdlc_dir, limit=200, now=None, dry_run=False, agent_alive=None)`: candidate stems = file names in those dirs plus `state/agents/` dirs. A stem is pruned only if ALL hold (revised after code review: `tools/onboarding_control.py` and the contract's downstream ingester read `state/verify` AFTER `record done`, so nothing is removed at `done`): its action log's newest row among `actionlog.INTERNAL_KINDS` is `recorded` with `result == "done"` (a reopened goal appends `claimed`, so it is skipped); that row and every file to be removed are older than a 7-day window (CLI `--min-age-days`; keeps post-`done` readers working and a late re-created marker waits it out); no `state/work/<stem>.json` record; no alive agent marker. For agents, the `state/agents/<stem>/` directory is removed only if no thread marker is alive. Also removes `state/run_stop/*.json` older than 30 days. `limit` (default 200) caps the GOALS PRUNED per call, never the goals examined, so permanently kept stems (work record, slack-keyed dirs) cannot starve prunable ones; the scan is one stat or one bounded (256 KB) log-tail read per stem still owning a file (cheap work-record/agent stats run before the log read; measured 5,500 stems 1.22 s dry-run). Oldest first. Returns `{"removed": [...], "kept": {reason: n}}`; never raises.
- There is NO in-line prune at `done` (`prune_goal` dropped): the sweep alone applies the work-record rule: while `state/work/<stem>.json` exists everything is kept, and the sweep removes the files after `work.finish` ran. Just before removing a stem the sweep re-reads the newest log row and re-checks the agent markers. Agent directories are emptied non-recursively then `rmdir`ed; a directory re-populated meanwhile is kept. Slack-keyed `agents/<key>/` dirs have no log row, so they are never terminal-pruned: disposition says already bounded by `slack_commands_listen.finish_claim -> agent_end` (existing test, control run) and a crashed key dir is retained.
- The sweep needs `action_log.enabled` (shipped on); with it off nothing is pruned (documented, tested). A kill during `_signal_unit_completion` (up to 450 s) skips that one sweep; the next `record done` runs it.
- Hooks: `loop.py _record`, last step, outcome `done` only: `goal_state_prune.sweep` (fail-open, stderr note); it never reaches the goal that just finished. Operator lever and docs gesture: `python3 skills/sigma-loop/scripts/goal_state_prune.py sweep .sdlc [--dry-run] [--limit N]`.
- Recovery: crash mid-prune leaves a subset; the log row proving `done` is untouched, so the next sweep finishes (idempotent). Restore-from-backup restores files with fresh mtime, so they wait out the 7-day window then are pruned again. No process pausing, no human.
- The 7-day window is an UNMEASURED policy default (operator-tunable `--min-age-days`), chosen because readers run after `done`: `tools/onboarding_control.py` (minutes) and the frozen `verify` kind in `contract/README.md` (ingester cadence not measured); `contract/README.md` gets a one-line retention note. Coupling to #457: the action log is the only terminal signal, so log-less stems (log off, pre-log legacy goals, logs #457 later prunes at 90 days) are kept: fail-safe, unbounded for those stems, stated in the doc and filed as a follow-up. Trigger: the sweep runs only from `record done`; a machine that records no further `done` uses the CLI lever, named in the doc as the answer. Tests also pin the `state/` symlink refusal and `agent_alive` raising -> kept.
- Documented decisions (no code): work, withheld, goal-review (reasons, ceilings, levers in `docs/launch/b6-per-goal-state.md`). Disposition file `docs/launch/dispositions/458.json` covering all 29 patterns.

## Test notes

Cases (adds from plan review: action log disabled keeps everything; slack-key dir with no log row kept; kept stems older than the prunable one do not starve it under `--limit 1`; a work record keeps files and the sweep removes them after `finish`; `record done` keeps its own evidence and sweeps an older goal; deterministic in-process controls for the reopen re-read and the agent re-check; a marker recreated late on a done goal is swept after the window): terminal goal's every family removed; live (claimed last row) kept; parked, failed, awaiting-merge (`recorded review`) kept; reopened (done then claimed) kept; work record present kept; alive agent marker kept, dead removed; inside the 7-day window kept; symlinked file/dir never followed with target intact; unsafe/odd names untouched; non-owned neighbours (`state/log`, `state/witness`, sibling files) untouched; dry-run removes nothing; `--limit`; partial prune heals on rerun; run_stop old removed / fresh kept; `loop.py record <g> done` leaves that goal's own evidence untouched (inside the window).
