   `python3 S/release_dependents.py <sdlc_dir> <goal> [<goal>...] [--all] [--apply]` (dry run unless `--apply`, the sweep CLI's posture; `--all` = no named goal, every open blocked goal, for the watcher and the doctor read).

2. `S/auto_unpark.py`: one new kwarg `use_map=True` on `compute_unpark_actions`, guarding the `_map_still_waiting` skip (546-552). The release path passes `use_map=False`: the map may nominate candidates, never say "still open" (trap 1: right after N closes the map still stores N open for up to `ttl_minutes`).
3. Filters applied by the verb to the decision's output (traps 2 and 3, D-2):
   - only issues carrying `goal_blocked_label` and NOT `parked_label` are ever passed in (a parked goal is never resumed, even one with a `sigma:waiting-on-dependency` note; that stays with the full sweep and `/sigma-unpark`);
   - each `swap-label` action is rebuilt as `add=[]`, `remove=[goal_blocked_label]` with `detail` REGENERATED by `triage._swap_detail(add, remove)` (auto_unpark.py:615 builds `detail` from the unfiltered sets; a stale detail would tell the audit trail the wrong labels; `triage._execute_action` accepts a remove-only swap, triage.py:2339), and dropped if `goal_blocked_label` was not in its remove list. `in_progress_label` is never removed, `goal_label` is never added (a blocked goal keeps membership; a legacy blocked goal that lacks `sdlc:goal` is therefore released into NO pool: it stays unpickable, and the docs say so rather than the verb silently adding a label the sweep would add). The board `set-status ready` card move is kept (without it a board-authoritative repo gets a correctly labelled, unpickable card: #1393);
   - the closed goal N must itself read closed live before anything is written, by the verb's own strict read `source._read_issue(N, ["state","stateReason"])` (raises on failure) and the same PR-aware rule as `auto_unpark._ref_is_open`; unreadable or open means nothing is released (covers a lagging read right after the close: the watcher catches it). This read is the verb's own clause: `compute_unpark_actions` only reads N when a candidate's TEXT names it (`_holding_findings` -> `_ref_is_open`, auto_unpark.py:466-486), and a map-nominated candidate may not;
   - STRICT READS (plan-review 1; auto_unpark.py:160-175 and backlog_check.py:468-512 and sources.fetch_comments:939-971 all fail open to `[]`, so a wrapper over them cannot tell "no comments" from "read failed", and a comment outage would hide the `sigma:keep-parked` marker `_is_exempt` reads (:555), a declared gate (:559) and comment-only blockers): the verb passes `compute_unpark_actions` a `reads=` object `_StrictComments(auto_unpark._CommentReads)` (defined in `release_dependents.py`, reused by the doctor scan) whose `get` calls `source.fetch_comments_strict(n)` (sources.py:4247; raises on any transport or malformed read, and only returns comments after `trusted_marker_comments`), then re-applies exactly what `_fetch_scrubbed_comments` applies: drop every comment whose `authorAssociation` is not in `sources.TRUSTED_ASSOCIATIONS` (the #709 rule, one stderr line each) and `scrub.scrub()` each kept body. On an exception it records the goal in `reads.failed` and returns `[]`; after `compute_unpark_actions` returns, every action (swap and card move) whose issue is in `failed` is DROPPED and the goal counted `incomplete`. (`compute_unpark_actions` has no try around `reads.get`, so the wrapper must not re-raise: one bad goal may not cost the others.) The persisted `_CommentReads` cache is reused only for hits keyed on `updatedAt`; a failed read stores nothing;
   - EVERY read leg is audited the same way, none is allowed to fail open: the listing (`source._list_issues` raises `GhApiError`: the whole result is `incomplete`, nothing released), each candidate's `source._read_issue(n, [...])` (raise -> that goal incomplete), N's state (raise or open -> nothing released at all), each comment read (above), and each ref's state (`_ref_is_open` reads unreadable as OPEN, the safe direction, so a ref-state failure keeps the goal blocked and releases nothing). ## Scale (AGENTS.md SCALABILITY; arithmetic from the code, NOT measured)

- Scoped release, map path: 0 list calls; per candidate 1 issue read + 1 comment read + 1 state read per distinct ref (memoised) + 1 swap + 1 note; plus 1 N state read and at most 1 N label strip. About 3D+4 REST calls for D dependents, UNBOUNDED in D by itself: the hook and the duty cap it by deadline (a derived number of seconds, `SIGMA_WATCH_CALL_TIMEOUT / 2` for the hook, the shared tick deadline for the duty), so at D=30 the worst case is about 94 calls, arithmetic not measured, of which only as many as fit the deadline run and the rest are `not_checked`. Cost scales with D (dependents of one goal), not with the backlog.
- Scoped release, listing path: at most 2 list calls (cap 101 over 100-row pages) + the same per-candidate cost, candidates limited by the `#N` prefilter. Ceiling: 100 blocked goals read. At 10x (1000 blocked goals in a fleet) the verb still reads 100 and reports "1+ not checked"; the 900 rest are covered only by the watcher `--all` pass (same 100 ceiling) and the doctor, so the ceiling is named: past 100 simultaneously blocked goals the OLDEST are unreachable by listing until newer ones clear. At 100x this is a stated limit, not a solved one; the mitigation is the fresh map (no ceiling, reverse edges) which `discovery.dag.mode` shadow/on provides, and the recorded follow-up (paged oldest-first listing) goes to retro's deferred list.
- `--all` / watcher: per run at most 2 list calls + per goal 1 comment read (persist cache keyed on `updatedAt`, `_CommentReads`) + memoised ref reads, hard-bounded by the SHARED tick deadline (`tick_start + SIGMA_WATCH_CALL_TIMEOUT * 0.9`, earlier duties' spend already deducted; it can be starved to zero and says so) and throttled to once per `interval_minutes`. Worst case bound per tick = what is left of that deadline; REST quota gated by `rest_deferral`.
- Doctor: 1 list call (cap 101) + the 10 most recently updated of the rows read (their strict comment reads) + their refs' `closedAt` reads; bound in the row name (`oldest of N read`).
- Per-goal per-close hook cost in `record done`: one fail-open pass inside a call that already does dozens of REST calls; unmeasured, stated as such in docs.

| list, issue read, comment read (strict reader), ref-state or N-state read fails | releases nothing for the affected goal (all goals when list or N state fails); the goal's actions are dropped after `compute_unpark_actions`; stderr line; result `incomplete` | idempotent; next watcher tick or the doctor row retries; no write was made |
| closed goal reads open (lag) | nothing released | watcher `--all` within one interval |
| crash between swap and note | label already removed (the release), audit note missing | re-run is a no-op for the goal (no longer blocked); documented as cosmetic |
| `record done` hook raises | swallowed, one stderr line, `complete()` already landed | watcher duty releases within `interval_minutes` |
| closed outside Sigma (keyword close, by hand) | no hook fires | watcher duty `--all`, bounded latency one interval (default 10 min, provisional) |
| watcher dead | state file age grows | doctor row reports age or "never run" (age is the tell) |
| tick budget spent by earlier duties (merge-reconcile, dag refresh) | duty starts nothing, state `deferred`, `starved_ticks` + 1 | next tick; the doctor row shows `starved_ticks` |
| process-group kill mid-duty | state file left at `started` or the last finished goal (written per goal) | next tick re-runs idempotently; doctor shows age |
| crash after `work.merge` closes N, before `record done` | dependents stay blocked | live watcher `--all` pass; cloud fleets have no watcher (stated in cloud-sessions.md) |
| hook and watcher race on the same goal | label swap idempotent; the audit note may post twice | cosmetic, stated |
| REST quota low | unattended callers defer (`rest_deferral`), CLI does not | next tick |
| label collision (blocked == goal_blocked) | refused, nothing read or written | operator fixes labels per doctor |
| GraphQL refused (cloud) | `_swap_labels` REST fallback; cloud end-to-end UNMEASURED | said in cloud-sessions.md in the same sentence |
| legacy blocked goal lacking `sdlc:goal` | released into no pool (label removed, none added) | stated in docs; `/sigma-doctor` label rows |
| 17 closed issues still carrying `sdlc:blocked` | untouched (harmless; BR-17 deferred note) | out of scope |
Safety: nothing here spawns a process, sends data, or consumes quota beyond reads and one label write per released goal; `mode: off` disables the unattended paths entirely; no SIGSTOP; no files in the root checkout beyond the gitignored `state/` file.
