# Plan 1856: the writes-nothing outcomes test stamps fixtures from the clock its subprocess reads

Goal: `tests/test_outcomes.py::test_a_run_writes_nothing_anywhere` passes on any date. Today it fails on pristine
main: `World` stamps commits and log entries from the constant `NOW` (1792195200, 2026-10-17T00:00:00Z), but the
run goes through `_run_copy`, a subprocess where `outcomes.main(now=None)` falls back to `time.time()`. One day past
`NOW` the oldest of the 10 mature goals (29d) leaves the 30d window and the report prints `unmeasured: 9 mature ...`.

## Design (test-only; no production flag)
- `outcomes.main` already takes `now=`; only the CLI path reads the real clock, and the in-process tests already
  inject `NOW`. A CLI clock flag would add a production surface for a test defect, so none is added.
- `World.__init__(..., now=NOW)` stores `self.now`; `commit()` and `log()` stamp `self.now - ago * DAY` instead of
  `NOW`. Default unchanged, so every in-process test (which passes `now=NOW` to `outcomes.main`) is byte-identical.
- Split `_run_copy`'s env into `_copy_env(home)`; add `_child_now(home)`: runs `sys.executable -c "import time;
  print(time.time())"` with that env and returns the float, i.e. the clock the `_run_copy` child will read.
- `test_a_run_writes_nothing_anywhere`: create `scripts`/`home` first, `now = _child_now(home)`, build both
  Worlds with `now=now`. Fixtures for a subprocess run are stamped from the subprocess's clock, not a constant.
- New file `tests/test_outcomes_late_clock_1856.py` (the red-green witness binds the test FILE's bytes; the fix lives
  in `test_outcomes.py`, an external helper to it, so red at base and green after share one file identity):
  writes `<tmp>/clock/sitecustomize.py` (`time.time = lambda: LATE`, LATE = NOW + 40 days), sets PYTHONPATH to it via
  monkeypatch, asserts a `-c` child prints LATE (the shim really moved the clock), then `mkdir <tmp>/late` and calls
  `test_outcomes.test_a_run_writes_nothing_anywhere(<tmp>/late)` through `import test_outcomes as T` (attribute
  access, so pytest does not collect the function twice; the `from test_applier import` pattern already exists).
