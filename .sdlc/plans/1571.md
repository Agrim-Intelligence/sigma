## Design

**Mechanism: three concurrent serial runs, no per-run xdist.** `check()` keeps its three shuffled runs and submits
them to a bounded `concurrent.futures.ThreadPoolExecutor` (subprocess waits; the GIL is not held).
- Each run keeps one unbroken, seeded order. xdist splits that order across workers, so an interacting pair can
  land on different workers, and `--dist load` is not reproducible from a seed: it would weaken order dependence,
  the one control the module exists for.
- The flake runs use bare `python3` (no xdist there); probing xdist from the verify venv then running system
  Python with `-n` gives exit 4 and `absent` every time (research risk 3).
- **Orchestrator decision (review 2 #9):** ship the bounded-concurrency mechanism; per-run xdist and the
  flake-interpreter question go to a follow-up filed in Step D. Done-when 3 allows "or the PR says why not".

**Interpreter: unchanged (`python3`).** `red_green.py` and `_collect` use the same bare `python3`; changing only
the flake runs would make observation and flake disagree. Named in the PR, folded into the xdist follow-up.

**`flake_check.py`** (adds `import concurrent.futures`, `functools`, `math`, `os`, `threading`; every use is an
attribute lookup at call time, e.g. `concurrent.futures.ThreadPoolExecutor(...)`, `os.cpu_count()`,
`random.Random(seed)`, `subprocess.Popen(...)`, never `from x import y`, so tests pin them on the shared modules):
- `_workers(runs, cpus=None, load1=None)`: `free = cpus - math.ceil(load1)`, result `max(1, min(runs, free))`.
  Defaults apply only when the argument `is None` (0.0 is a real load): `cpus` is `len(os.sched_getaffinity(0))`
  where it exists (Linux; honours cgroup/taskset), else `os.cpu_count()`; `load1` is `os.getloadavg()[0]`; each
  read inside `try/except (OSError, AttributeError)`. A `None` cpu count counts as 1; a missing load average gives
  1 (fail toward the old behaviour). **Honest consequence:** at this host's normal load (load1 15.9-24 on 12
  cores) the bound is 1 and the feature is a no-op here; it reaches 3 only at load1 <= 9, and load1 is sampled
  right after the proving command's own `-n 4`, overstating by up to about 4. Named in the PR.
- `check(..., workers=None)`: `None` means `_workers(runs)`; an explicit value is clamped to
  `max(1, min(int(workers), _workers(runs)))` (a caller can only LOWER it). No env knob
  (`tests/test_legacy_compat.py` pins every `SIGMA_*` literal).
- Orders are drawn in the calling thread, in index order, before the first `submit` (`random.Random` is not
  thread-safe; a seed must give the same orders at any worker count). Results are read back
  `[f.result() for f in futures]` and stored at `results[i]`; `as_completed` is not used.
- **Interrupt and child tracking (RESILIENCY).** No `with` executor (its exit is `shutdown(wait=True)`, blocking a
  Ctrl-C until every sibling run ends, about 8 min each):
  ```
  live = _Live()
  ex = concurrent.futures.ThreadPoolExecutor(max_workers=w)
  try:
      futures = [ex.submit(runner, root, argv_i) for i ...]
      results = [f.result() for f in futures]
  except BaseException:
      ex.shutdown(wait=False, cancel_futures=True)   # 3.9+
      live.close()
      raise
  ex.shutdown(wait=True)
  ```
  `_Live` (per check, never module-global): `closing` bool, a set, one `threading.Lock`.
  `register(p) -> bool` (under the lock: `False` if `closing`, else add); `discard(p)`; `close(grace=5.0)`: under
  the lock set `closing = True` and copy the set; outside it `terminate()` EVERY child first, then one deadline
  `time.monotonic() + grace`, each child `wait(timeout=max(0, deadline - time.monotonic()))`, on
  `subprocess.TimeoutExpired` `kill()` then `wait()`. Worst case one grace plus kills, for any `w`.
  `_run(cwd, argv, live=None)` keeps its two-positional shape and `(code, output)` return (`_collect`, loop.py
  :5386, :5473): `if live is not None and live.closing: return (-15, "")`; `p = subprocess.Popen(argv, cwd=cwd,
  stdout=PIPE, stderr=PIPE, text=True)`; `if live is not None and not live.register(p): p.terminate(); p.wait();
  return (-15, "")` (closes the Popen-after-close race); `communicate()` with `except BaseException: p.kill();
  p.wait(); raise`, and `live.discard(p)` in `finally`. With `run=None`, `check()` uses
  `functools.partial(_run, live=live)`. Children stay in the caller's process group, so a terminal Ctrl-C still
  reaches them. **SIGTERM:** nothing in loop.py handles it, so the parent dies with no cleanup as today and up to
  `w` runs are orphaned (today one); no prediction about how they die (CPython ignores SIGPIPE; block-buffered
  output may keep one alive up to about 8 min); lifetime measured in Step C.
- Per-run argv: `python3 -m pytest -q -p no:cacheprovider -p no:xdist --basetemp=<own> *order` (no shared
  `lastfailed`; no workers inside a run). The per-run record stays `{"exit", "failed"}`; `check()` adds
  `workers` (the number used) on every path that ran tests. Inside the existing `flake` evidence dict: no new
  writer, file or module.
- `_judge(results) -> (verdict, disagreement)`, extracted verbatim from the end of `check()`, rebuilding the
  observations from `results`: (1) any unmeasured run -> `absent`; (2) `len(set(observations)) == 1` over
  `(exit == 0, tuple(failed))` -> `verified`; (3) else `unverified` with the union of failed ids.
- **Collisions.** Two copies of the same tests can now collide on shared paths; that shows as `unverified` ->
  verify exit 5 (loop.py :5870), safe-failing. The #1550 measurement is the collision check (ship gate below).
- Pre-existing, not fixed: `mkdtemp(prefix="sigma-flake-%d-")` basetemps never removed (:148); follow-up in Step D.
- Docstring: ceiling text unchanged; one short paragraph (concurrency changes wall time, not runs or orders; a test
  unsafe to run twice at once shows `unverified`; an interrupt cancels and terminates).

**Scope label (`loop.py`).** `_planned_scope(sdlc_dir, goal, root) -> (selectors, node_ids) | None` (today's
`_planned_tests` body, :5351); `_planned_tests` becomes a wrapper returning `node_ids` (`_changed_tests` :5377
