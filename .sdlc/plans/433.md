## What is wrong, for a reader with no context
`python3 tools/leak_scan.py` is the publish gate (rule `key-body`: "a private key body whose header was stripped").
Today it needs 3+ adjacent whole lines of 40+ base64 chars with upper+lower+digit, so it misses a real EC P-256 SEC1 body
(lines of 64, 64, 36 chars), an Ed25519 PKCS8 key (ONE 64-char line), and a truncated RSA paste (BEGIN + `Comment:` + 2
lines), in the shapes (a) BEGIN + armor + body, no END, (b) prose naming the header + blank + body, (c) the body alone. It
also exempts a body whenever the single line above is `-----BEGIN CERTIFICATE-----` / `...PUBLIC KEY-----` (so a PRIVATE
body under one is clean) and flags real public PGP/SSH2/CSR/CRL/PKCS7 blocks. Reproduction and shapes: the issue.

## Decisions
**D1 Shape (c) for one-line keys: a structural DER recogniser at the START OF A LINE (departs from "whole-line only").**
A lone 64-char mixed base64 line is 48 random bytes, identical to a sha384 digest: no line-count rule reaches an Ed25519 key
(dossier section 0). The recogniser decodes the first 18 bytes (24 base64 chars) of a token that starts with `M` (0x30,
SEQUENCE) and accepts `SEQUENCE{ INTEGER 0|1, ...}` followed by exactly the four (version, next tag) pairs that exist: PKCS8 v1
(0, SEQUENCE), PKCS1/DSA (0, INTEGER), SEC1 (1, OCTET STRING), PKCS8 v2 (1, SEQUENCE); plus OpenSSH's constant `openssh-key-v1`
in base64. The decoded first byte must be exactly 0x30 (`M` also spans 0x31-0x33; a planted 0x31 SET header is clean, red
without the check). Public/non-key DER is not read as private for the kinds planted and run: SPKI, certificate, CSR, DH params,
PKCS7, PKCS12, an ECDSA signature, and explicit EC PARAMETERS (re-measured): those open `02 01 01 30 <len> 06 07 2a8648ce3d01`
and mimic PKCS8 v2, so `_der_private` returns False when `head[i:i+4] == 02 01 01 30` and `head[i+5:i+13] == 06 07 2a 86 48 ce
3d 01` (OID arc `1.2.840.10045.1.1`; a real PKCS8 v2 EC key has `3d 02 01` there; both `openssl ecparam -param_enc explicit`
outputs, prime256v1 and secp384r1, go clean; the 7 python-ecdsa `test_curves.py` FPs review #1 found over 99,772 files under
/opt/homebrew are gone). A measurement over those kinds, not a proof: any other public DER opening `02 01 00|01 30|02|04` stays
a possible FP. The orchestrator's 2x3 pair grid is tightened to the 4 real pairs (no count changed). Three widenings, each
measured, over the orchestrator's "whole line, nothing else": (i) token floor 24 chars (18 bytes), not 40, because a key
re-wrapped at 32/36/39 is otherwise clean (harness C01 x3); floor 16 measured identical to 32 on the tree (0 over 798 files), the
corpus (17 over 97), the 99,772 homebrew files (50) and the 71 repos' 36,745 git-tracked files (47), but its only gain is a key
wrapped at 16-23 and 18 bytes are the least that decode the explicit-ECParameters test, so 24 (re-measured: a P-256/Ed25519/RSA
first line re-wrapped at 24, 28, 31 is a finding, at 16, 20, 23 clean; the pre-review floor 32 missed 24-31); (ii) the token may
follow indentation and up to two runs of 1-3 symbols (`"`, `# `, `> `, `// `, ` * `, `- "`, `["`) and anything may follow it
(harness C18, C19, C22 x5, D05); (iii) the token alphabet also takes `-` and `_` (base64url, C11). Evidence: key-body findings
added vs a3c913c = 0 on this tree (798 files), 0 extra on the 97-file corpus, 13 NEW on 71 sibling repos from this recogniser,
same counts over their whole working trees (128,828 decodable text files <= 4 MB, 1.63 GB, `repos_final.txt`) and their
git-tracked files (36,745, `cmpoldg.py`, reproduced by review #2): key-body 39 -> 47 = 15 extra (those 13 + 2 SAML XML
certificates) and 7 gone. The 13 are all real private keys (decoded structure bytes: PKCS8 EC/RSA, PKCS1 in Java string
literals, YAML `- ` items, a JSON array, XML `<PrivateKeyPem>`), 0 FPs in that sample; whole-line-only finds 2 of them.
Rejected: "token mode" (a DER header anywhere on a line): 4 fabricated literals in this repo's tests would need fragmenting
(F1); whole-line-only (floor 40, no prefix, no base64url): leaves 13 harness attempts open (C01 x3, C10, C11, C18, C19, C22 x5,
D05) and 11 of the 13 real keys unseen. The DER line is never exempted by D2.
**D2 Exemption = the whole non-private BEGIN..END span, and only for the line-count trigger.** A span is a STANDALONE
`-----BEGIN <label>-----` line (4 or 5 dashes, optional space, so `---- BEGIN SSH2 PUBLIC KEY ----` works), label 1-64 chars with
no dash (bounded: the natural lazy `(.*?)` is quadratic, D7), whose upper-cased label contains neither PRIVATE nor SECRET (so
`PGP SECRET KEY BLOCK`, `ENCRYPTED PRIVATE KEY`, `OPENSSH PRIVATE KEY` never exempt; lower-case spellings alike), then only
blank, `Key: value`, base64 (`[A-Za-z0-9+/=]+`) or `...`/`U+2026` lines, then `-----END <same label>-----`. A run is exempt iff
its first line is inside such a span. Measured: with the exemption disabled the 97-file corpus gives 456 findings (422 new) and
the largest sibling repo (git-tracked) 71 (41 new); the literal "END right after the run" reading gives 19 CA-bundle findings (dossier 0a).
Blacklist (PRIVATE/SECRET), not a label whitelist: a whitelist would flag any public label nobody listed; a private body under an
odd label is still caught by its DER first line. The existing certificate-body test uses a PKCS1 header (`MIIEpAIBAAKCAQEA`), so
it is re-fixtured (Step 2) and its old fixture becomes the red control "a private body wearing a certificate header AND a
matching END is flagged". The issue's "documented limit" shrinks to what has no DER start: a private slice lacking its first
line, inside a matching public span, stays green (run, pinned). Elided certificates (`...` inside) stay exempt (old adjacency
exempted them); prose inside a span breaks it (measured: flagged).
**D3 Blocks.** A BLOCK is adjacent whole lines of 40+ chars (`=` padding; outer spaces/tabs/CR ignored). It counts when it has 3+
lines with at most ONE lacking upper, lower or digit, or exactly 2 lines (both mixed) followed directly by a 28-39 char whole
line (the tail). Floors 40 and 28 are the dossier's width sweep (q36 +3 FP, tail 24 adds nothing observable). Tolerance: 0
non-mixed lines reopens harness C08 (a 12-line body with one digit-less line); 1 costs 2 findings in the 71 repos' 36,745 tracked
files (`saml-entity-descriptor.xml` x2: public certificate bodies in XML, a class the old rule flags in 6 sibling files) and 0
anywhere else. Tolerance 1 for 3+ lines, 0 for the 2+tail case (tol2=0 vs 1: identical counts on corpus and 71 repos; a 2-line
block has one line less evidence). A real key line lacks a digit with P about 2e-5.
**D4 Header anchor (closes (a) and (b) for Ed25519 and truncated RSA).** A block that did NOT already count is a finding when,

enough IF every line of the anchored block is mixed (re-measured): a header constant (`PRIVATE_KEY_HEADER = "-----BEGIN ..."`),
a blank line and then an 80-slash separator or a 40-hex SHA-1 were findings in the first plan and are green now, while every

Algorithm (equivalent code is enough; the seams and the one-finding-per-block rule are the contract):
```
def _private_label(label): return "PRIVATE" in label.upper() or "SECRET" in label.upper()

def _der_private(tok):                      # tok: the b or k group
    if tok.startswith(_OPENSSH_KEY): return True
    if tok[0] != "M": return False          # cheap prefilter: 0x30..0x33 are all "M"
    head = base64.urlsafe_b64decode(tok[:24])                 # 18 bytes, no padding, never raises
    if head[0] != 0x30: return False        # exactly SEQUENCE
    if head[1] < 0x80: i = 2
    elif head[1] in (0x81, 0x82, 0x83): i = 2 + (head[1] & 0x7F)
    else: return False
    if head[i:i+4] == b"\x02\x01\x01\x30" and head[i+5:i+13] == b"\x06\x07\x2a\x86\x48\xce\x3d\x01": return False   # explicit ECParameters
    return head[i] == 0x02 and head[i + 1] == 0x01 and (head[i + 2], head[i + 3]) in _DER_PRIVATE   # seam spelling

def _public_spans(text):                    # [(first_offset, end_offset)], ascending, non-overlapping
    spans = []
    for m in _PEM_BEGIN_LINE.finditer(text):
        if _private_label(m.group(1)): continue
        first = pos = m.end() + 1
        while pos <= len(text):
            eol = text.find("\n", pos); eol = len(text) if eol < 0 else eol
            if _SPAN_LINE.fullmatch(text, pos, eol): pos = eol + 1; continue
            end = _PEM_END_LINE.fullmatch(text, pos, eol)
            if end and end.group(1) == m.group(1): spans.append((first, pos))
            break                           # any other line (a BEGIN line is one) ends this scan
    return spans

def _anchored(text, first):                 # first = offset of the block's first line
    pos = first
    for _ in range(_GAP + 1):
        if pos == 0: return False
        start = text.rfind("\n", 0, pos - 1) + 1              # the line above is text[start:pos-1]
        if any(_private_label(h.group(1)) for h in _PEM_BEGIN.finditer(text, start, pos - 1)): return True
        if not _BLANK_OR_ARMOR.fullmatch(text, start, pos - 1): return False
        pos = start
    return False

def _key_bodies(text):
    cands, out = [], []
    for m in _BODY_LINE.finditer(text):
        tok = m.group("b") or m.group("k")
        if m.group("b"): cands.append(m)
        if _der_private(tok): out.append(m.start())          # a DER line is a finding wherever it sits
    blocks = []                             # adjacent = next.start() == prev.end() + 1 (group b ends AT the "\n")
    for m in cands:
        if blocks and m.start() == blocks[-1][-1].end() + 1: blocks[-1].append(m)
        else: blocks.append([m])            # NOTE: an empty cands list must not append an empty block
    spans = None
    for blk in blocks:
        n = len(blk); bad = (#lines of blk lacking [A-Z], [a-z] or \d)      # for EVERY n, a single line included
        counted = (n >= 3 and bad <= 1) or (n == 2 and bad == 0 and _B64_TAIL.match(text, blk[-1].end() + 1))
        if counted:
            spans = _public_spans(text) if spans is None else spans      # lazily, once per file
            i = bisect.bisect_right(spans, (blk[0].start(), len(text) + 1)) - 1
            counted = i < 0 or not spans[i][0] <= blk[0].start() < spans[i][1]
        if counted or (bad == 0 and _anchored(text, blk[0].start())): out.append(blk[0].start())   # anchor: all lines mixed
    return sorted(set(out))
```

Complexity: n = file bytes (<= `MAX_BYTES` 4 MB), c = candidate lines. `_BODY_LINE`: O(n), tried only at line starts (both
alternatives fail fast; leading-whitespace backtracking is linear per line, measured on a 4 MB space/tab line). Blocks O(c). Spans:
lazily once, O(n): each scan stops at the next non-conforming line and a BEGIN line is one, so scans are disjoint. Anchor: <= 9
lines per non-counted block, each line reachable from ONE block. DER: a decode (about 1 us) only for tokens starting `M`. At 10x
(40 MB, past `MAX_BYTES`, n/a) the cost is linear in bytes because no line regex has two adjacent quantifiers over one class and
none is `.*?` before `$`; backed by the D7 fuzz (worst 0.322 s at 1M), not by inspection; worst measured 4 MB file about 1.2 s
key-body / 2.7 s `scan_text` (D7). Do not scan the flood with an unanchored `.*?`/`$` regex (50 s CPU at 128 KB, 199 s at 256
KB); a new line regex is not accepted until it passes the same fuzz.
