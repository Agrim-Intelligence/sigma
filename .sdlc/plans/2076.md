# Plan #2076: a cloud run's claim, keep-alive and outcome reach the team ledger, and no machine releases a claim it cannot confirm is dead

Plan sha256: pending

Lane: large in surface (ledger, sync, loop, contract, docs) but one mechanism. Plan-Review runs in full.

## What is measured about today's tree (read, not run live)

- `ledger._held_full` folds `claimed` and the four terminal kinds only. `lease-renew` is not a kind (`KINDS`), so a renewal could not even be written.
- `loop._claim`, `loop._record` and `loop._release` call `ledger.safe_append` and stop. Publishing is the watcher's job, or the typed-verb path `sync.publish_after_write`. In a fresh container there is no `.sdlc/ledger` worktree and no watcher, so the entry stays in a plain directory.
- `ledger._host_token` is `sha256(hostname)[:8]`. Cloud containers share a hostname.
- `sync._run_git` has no timeout. `PUSH_ATTEMPTS = 5`, no backoff, no jitter.
- `_auto_reclaim_stale_claims` reads `ledger.read_all` (this machine's copy) and releases when the lease is aged and no local worker marker exists.

## Design

1. **Kind and reader (AC-3, closes #616).** `lease-renew` joins `KINDS` (not `SHARED_KINDS`: it must not fill TEAM.md). `_held_full` extends a held claim's timestamp for a `lease-renew` whose actor equals the holder's actor, whose writer host equals the claim's writer host (an unknown host on the claim side reads as compatible: pre-#540 writers carry none), and whose `run_id` is compatible (equal, or absent on either side: `note`, `agent-start` and `verify` carry no `--session-pid`, so a strict rule would make the keep-alive useless in the `--land` flow). A renewal dated more than 15 minutes ahead of the reader's clock is not believed (a skewed clock cannot extend a lease indefinitely), and a renewal never moves a timestamp backwards. Any other renewal and any unknown kind is ignored and never raises. Residual, stated: containers that an operator forces onto one `ledger.host_alias` AND that carry no run id cannot be told apart by a renewal; the per-container salt in item 5 removes that case.
2. **Writer (AC-3).** `ledger.renew_lease(sdlc_dir, config, goal)` appends one `lease-renew` for a goal this process's actor, machine and run hold, at most once per `ttl/3`. A per-goal marker under `.sdlc/state/` (name sanitised through `_safe_name`) holds the epoch before which nothing is due, so the common call costs one `stat` and the ledger is read at most once per `ttl/3` per goal. TTL off writes nothing. `loop.py` calls it from `note`, `agent-start`, `agent-beat` and `verify`, fail-open.
3. **Publish without a daemon (AC-1, AC-2).** `sync.publish_entry(sdlc_dir, config, what)` returns the one stderr line to print, or None when there is nothing to say. Off when `ledger.enabled` is not true or `ledger.publish_on_write` is false. On a laptop a live watcher keeps its tick (silent defer, as `publish_after_write`). **In a cloud session it never defers and the loop never starts the watcher** (`_ensure_watcher` returns early there): a container can be gone before the next tick, and a daemon in an ephemeral container is the opposite of this goal. When `.sdlc/ledger` is not a worktree it calls `sync.init` (plumbing only), makes sure the path is excluded from the code checkout's status through `.git/info/exclude` when the repository does not ignore it, then `sync.publish`. Every git call runs through a bounded runner: a wall-clock deadline (`SIGMA_LEDGER_PUBLISH_DEADLINE`, default 90 s) shared by the whole step, `GIT_TERMINAL_PROMPT=0`, stdin closed, its own process group, SIGTERM then SIGKILL on overrun so git removes its own lock, and a `rebase --abort` after a timeout. Failure prints `ledger: NOT published (<why>) ...` where `<why>` has URL credentials scrubbed and is capped; the run continues. **Call placement:** never inside `_claim`, which runs under the per-goal claim lock. `_claim`, `_record`, `_release` and the renew calls only mark "an entry is pending"; the CLI entry point flushes ONE publish in a `finally` after the verb returns, so `next-batch` pays once, not once per goal, and no lock is held across the network.
4. **Concurrent pushers (AC-4).** `_push_with_retry` gets injectable `sleep`/`clock` with defaults of no sleep, so every existing stub-driven test is unchanged. Real git (no injected runner) gets exponential backoff with full jitter and a deadline; the ledger publish raises attempts. Evidence: a deterministic in-process control at the seam (a push that is rejected k times: attempts bounded, delays jittered and capped, deadline honoured), and a real-git multi-clone race as a labelled smoke test. If the race cannot be made red against today's tree, the plan says so in the PR rather than claiming it.
5. **Host token (AC-5).** In a cloud session (`CLAUDE_CODE_REMOTE` true or 1) the token is salted with a per-container id: random, persisted once per container (exclusive create, format validated on read) in the temp directory, else a deterministic fallback from the boot id and the init start time (weaker on a shared kernel; stated). With `ledger.host_alias` set, the alias stays and four hex digits of the container id are appended, so the alias still never exposes a host name and containers still differ. A laptop's token is byte-identical to today's.
6. **Reclaim (AC-6).** `_auto_reclaim_stale_claims`: when the stale claim's writer host differs from this machine's token, `sync.confirm_expired(sdlc_dir, config, goal)` runs a bounded fetch of the ledger branch and reads the entries FROM the fetched remote ref (read-only; no rebase, no worktree move, no contention with a watcher's index lock). It releases only if that fresh read still shows the claim open and expired. A failed fetch, a missing branch or an unreadable ref releases nothing and prints why. A claim with no host (pre-#540) reads as local, unchanged.
7. **GraphQL off (AC-7).** No GraphQL on any of these paths (git and REST). Proven by a test that refuses every GraphQL-shaped call across claim, renew, publish and outcome.
8. **Contract.** `contract/VERSION` 1.4.0 to 1.5.0 (MINOR, approved on #393), `vocabulary.json` regenerated, README, golden `entries.jsonl` line. Rollout order, written in the CHANGELOG: a reader that validates entries against contract 1.4 must accept 1.5 before a writer upgrades, because an entry kind it does not know can stall a closed-vocabulary consumer.

PROVISIONAL (owner to ratify), each the conservative option: renewals extend even past the lapse if no release intervened; the cloud id lives in the temp directory; the default deadline is 90 s; the cloud session never starts the ledger watcher.

## Tests (red first, then green)

- `tests/test_ledger_lease_renew.py`: reader (holder extends; other actor, other host, other run do not; unknown kind does not raise; backwards ts ignored); the 13-hour fixture; writer throttle; TTL off.
- `tests/test_ledger_cloud_claims.py`: host token (cloud unique per container, laptop unchanged, alias wins); reclaim confirm (remote writer needs a fresh read; read failure does not release; a renewal on origin stops the release; local writer unchanged); GraphQL-off end to end.
- `tests/test_ledger_publish_entry.py` (real git; one deterministic control at the retry seam): fresh clone, no worktree, claim published to a bare origin with code HEAD, index and status unchanged; refused push prints NOT published and continues; deadline bound; AC-4 with several clones pushing at once.
- Controls: AC-5 and AC-6 clause by clause, run with the gesture the docs give; AC-3 reader clauses one at a time.
