Goal: the review brief carries the goal's test-trust facts; with `review.test_review` on, the
author-blind reviewer maps every acceptance criterion to the test(s) that prove it, and a criterion
with no test, or a diff-revert survivor on a changed line, turns the approval into a block.
Research: `.sdlc/research/1964.md`. Revisions 1 (8b5b56da…) and 2 (4f52583d…) got FIX-FIRST; dispositions at the end.

## Decisions
- **Module name `review_tests.py`** (revision 4, round-3 refinement 2). A production script named
  `test_*.py` matches `tamper_scan._TEST_PATH`, so `production_changed` would call a change to it
  test-only and the survivor clause would never judge it; flake_check would collect it as a changed
  test, and diff_revert would copy it into the reverted tree whenever pytest collects ids from it.
  (Revision 5 only rewords one line that named the gesture's path from `.sdlc/plans/`, where
  `${CLAUDE_SKILL_DIR}` cannot resolve, and this bullet's order of harms - round 4's R2.) AC-2/3/5 of the create-only acceptance record name
  `test_review.py`; this is a recorded divergence of the name only. Round 3's other refinements are
  carried as noted on the issue (loop.py note), unchanged by this revision.
- **#535 criterion ids.** A bullet starting `AC-<n>:` keeps that id; every other bullet gets
  `AC-<position>` (1-based). That is #535's AC-2 rule for bullets without ids. If the result holds
  a duplicate id (first bullet `AC-2: x`, second bullet unprefixed and so also `AC-2`; or two
  explicit `AC-2`), the check reports `duplicate criterion id AC-2` as a blocking finding instead of
  guessing. EARS lint stays
  #535's; not built here.
- **#568 mutation.** Not duplicated. The survivor clause reads `diff_revert` (whole-diff revert,
  mutmut-free, already wired into verify). #568's per-mutant survivors would feed the same section;
  kill-rate floors stay #568's.
- **"Survivor on a changed line".** A diff-revert survivor whose own test function (first decorator
  to `end_lineno`) overlaps a `git diff -U0 <fork> -- <file>` new-side hunk, or that lives in a file
  absent at the fork. Recorded at verify as `diff_revert.changed_survivors`, with
  `production_changed`. A path is production unless it matches `tamper_scan._TEST_PATH` or lives
  under the sdlc directory (`.sdlc/` - plan, research, acceptance and changelog-fragment records are
  tracked there and are never code). Docs count as production: a test may read them. When nothing
  production changed the list is empty and `production_changed` is false: nothing was reverted, so
  survival proves nothing. A `-U0` hunk `+N,0` (a pure deletion) touches line N (line 1 when N is 0),
  so a test whose assertion was deleted is caught. `git diff` runs with `--no-color --no-ext-diff`.
- **One key gates the whole new behaviour.** `review.test_review` (absent or false = off; the init
  template ships `false`). Off: the brief still carries the facts (AC-1 is unconditional and purely
  informational) and nothing else changes - no TEST-MAP instruction, no new blocking rule, no
  refusal. On: the brief adds the TEST-MAP instruction, SKILL.md's blocking rule applies, and the
  approval seams enforce it. Reason: the gate has never run end to end against a real host
  (RELIABILITY) and its false-block rate is unmeasured, so it does not flip fleet-wide; the doc
  names it UNMEASURED and the owner turns it on per repo.
- **Approving verdicts.** Every review verdict except `block` / `BLOCK` / `SEND-BACK` is checked:
  `approve`, `APPROVE` and `unblock` (unblock clears a loop block and lets the merge proceed,
  work.py:6216).
- **What a block does.** PR seam (`_write_review_result`, all three routes): an approving verdict
  the check blocks is WRITTEN AS `block`, its reason the check's findings followed by the reviewer's
  text, and a stderr line says so. The goal then goes through the ordinary block -> fix -> fresh
  generation -> `unblock` cycle. `post_review` closes the one gap that leaves: asked to post
  `approve`/`unblock` with evidence whose stored result is `block`, it posts the `block` with the
  stored reason instead of returning its mismatch line and posting nothing (which, under
  `require_review: changes`, let the merge through). Only that downgrade direction is added; every
  other mismatch is refused as before. Local seam (`work.py record-review`): refuses
  (exit 2) naming the findings and the lever: record `--verdict SEND-BACK`, fix, re-review.
- **Reviewer levers.** `UNTESTABLE: <why>` (a criterion no test can prove, e.g. a DOC line) and
  `SURVIVOR-OK <test id>: <why>`. Both need a non-empty reason, are written only by the reviewer,
  and are echoed in the check output.
- **Missing evidence never reads PASS.** The check's last line is one of `TEST-REVIEW: block`,
  `TEST-REVIEW: pass`, or `TEST-REVIEW: partial - survivor clause not judged (<reason>)` - the last
  when the evidence file is absent/unreadable, the `diff_revert` verdict is `absent`, or the
  evidence predates `changed_survivors`. `partial` does not refuse (diff_revert is absent for real,
  common reasons: >50 tests, no base ref, a timeout); it is printed into the stored reason so the
  owner sees the clause was not judged.
- **Test existence.** Tree: the goal's work-record worktree, else the project root. An id
  `path::[Class::]name[params]` exists when the file exists there and the AST holds that top-level
  function, or that method inside that class. An id with no `::` exists when the file exists (a
  non-pytest suite; the clause degrades to file existence and the doc says so).
- **Map parsing.** `TEST-MAP AC-<n>: ...` lines anywhere in the text (they are asked for first, so
  the 32 KiB receipt cap keeps them), tolerating the same markdown decoration the verdict regex
  does (leading bullets, `>`, `*`, `_`, backticks). An inherited test method (defined on a base
  class) reads nonexistent; the reviewer maps the defining class's id, and the doc says so. Two lines for one id that differ: blocking `conflicting
  TEST-MAP lines for AC-n`. A line for an id the record does not have: ignored and listed.
- **Paths in the brief.** Relative to the project root only; an unreadable-evidence reason is the
  exception's class name, never its text (it can carry an absolute scratch path and trip
  `reviewer.py check`). An unsafe goal (`state.evidence_path` ValueError) reads `unreachable`.
- **No receipt fallback.** `work.py record-review` takes the reviewer's text only from
  `--review-output <file>`, required when the key is on and the verdict approves. It is
  agent-supplied, exactly like the verdict word beside it; the doc says so.
- **Criterion text in the brief.** With the key on, the facts block lists every recorded criterion
  beside its derived id, so the reviewer numbers exactly as the check does (code-review briefs do
  not otherwise inline the record). With it off, one line gives the ids and count only.
- **`partial` on the local seam** has no field on the verdict row; it is printed to stderr.
- **Freshness** is not re-checked here: the evidence is the last `loop.py verify`.
  `state.done_refusal` already refuses a tree changed since then. Stated in the doc.

## Task 1 — review_tests.py (AC-2, AC-3, AC-5)
Cases, all through the documented gesture `python3 skills/sigma-loop/scripts/review_tests.py check
<sdlc> <goal> --review <file>` unless noted:
- ids: positional; explicit `AC-2:` kept; duplicate id -> exit 1 naming it.
- exit 1 naming AC-n for: (a) no line, (b) `NONE`, (c) only nonexistent tests (a missing file; a
  present file without that def; a class method id that does not exist), (d) `UNTESTABLE:` with an
  empty reason, (e) two conflicting lines.
- exit 1 naming the test for a `changed_survivors` entry; `SURVIVOR-OK <id>: <why>` clears it; an
  empty SURVIVOR-OK reason does not.
- exit 0 `TEST-REVIEW: pass` when every criterion maps to an existing test and the survivor list is
  empty with a measured verdict; `UNTESTABLE: <why>` counts as mapped.
- exit 0 `TEST-REVIEW: partial - survivor clause not judged (...)` for: no evidence file, diff_revert
  `absent`, evidence without `changed_survivors`.
- acceptance missing -> exit 1. Usage error -> exit 2.
- `refusal()` (direct call): None with the key absent or false; the findings with it true; a refusal
  on an unreadable config.
