# #112 Hook-wizard interpreter isolation implementation plan

> Execution: Codex native implementation using Superpowers planning/TDD, followed by a fresh independent review agent.

**Goal:** Hook-wizard tests run the interpreter that launched pytest even when the host's `python3` is broken.

**Architecture:** Give the real shell hook a temporary, interpreter-only `python3` symlink to `sys.executable`, ahead of fixture tools and system utilities. Retain the hermetic environment and direct missing-interpreter control.

**Tech stack:** Python stdlib, pytest, real Bash hook subprocess.

**Spec:** https://github.com/Agrim-Intelligence/sigma/issues/112

## Global constraints

- Preserve hook production behavior and non-adopted-repository silence.
- Never inherit the developer's PATH or SIGMA_RUN_ID; retain the isolated plugin inventories.
- No root commands, Xcode changes, skips, or new runtime dependencies.
- Constant work per hook invocation: one temporary directory and symlink, cleaned on success or exception. No persistent state or daemon.
- This is a POSIX shell-test fixture; it does not claim a measured Windows hook run.

## Review focus

1. Broken fallback python must not suppress meaningful wizard or policy output.
2. Fixture graphify must still resolve ahead of any machine-installed graphify.
3. A supervised variable in pytest's environment must stay out of the hook unless explicitly supplied.
4. Non-adopted project directories must stay clean after helper cleanup.
5. The separate missing-python control must still deliberately omit the interpreter shim.
